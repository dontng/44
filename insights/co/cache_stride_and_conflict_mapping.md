# 组相联 Cache 的跨步映射与无冲突遍历推导

> 关联真题：2023-43  
> 核心痛点：为什么二维数组按列遍历（跨行跳跃）时，虽然破坏了空间局部性，但在特定条件下 Cache 命中率依然能高达 87.5%？到底怎么严密证明它“没有发生冲突置换”？

---

## 一、 认知摩擦点：“空间局部性差”不等于“命中率必然雪崩”

在常规直觉中：
- 按行遍历（行优先）：内存连续读写，1 个 32B 块容纳 8 个 int，第 1 个缺失，后 7 个命中，命中率 7/8 = 87.5%；
- 按列遍历（列优先）：每次跨过整整一行，访问地址剧烈跳跃，按直觉命中率应该直接跌到 0%（每次都冷缺失）。

但在 2023-43 题中，官方答案与严密推导得出的结论却是：**调换遍历顺序后，Cache 命中率仍然为 87.5%！**

很多考生只靠一句“因为数组总大小小于 Cache 容量”来背答案，但在大题中如果只写这句话，无法解释**组相联 Cache 中可能发生的组内冲突置换（Conflict Miss）**。

---

## 二、 物理不变量与严密映射推演

### 硬件参数基准
- 数组尺寸：`int a[24][64]`（行优先存放，共 24 行、64 列）；
- 每个元素：`sizeof(int) = 4B`；
- 每行跨度：$64 \times 4\text{ B} = 256\text{ B}$；
- 主存块大小：$B = 32\text{ B}$；
- Cache 架构：数据区容量 $C = 8\text{ KB}$，采用 **4 路组相联**（每组 4 个 Cache 行）；
- Cache 总组数：
  $$G = \frac{8192\text{ B}}{4 \times 32\text{ B}} = 64\text{ 组} \quad (\text{组号范围 } 0 \sim 63)$$

### 为什么按列跳跃不会发生组内冲突？

我们跟踪内层循环沿列遍历的过程（$j$ 固定为 0，依次访问 $i=0, 1, 2, \dots, 23$ 的元素 `a[i][0]`）：

1. **相邻两行在内存中的地址差**：
   $$\Delta \text{Addr} = 256\text{ B}$$
2. **相邻两行在主存块编号上的差距**：
   $$\Delta \text{Block} = \frac{256\text{ B}}{32\text{ B}} = 8\text{ 块}$$
3. **映射到 Cache 组号的步进差值**：
   $$\Delta \text{Set} = 8 \bmod 64 = 8\text{ 组}$$

这意味着，连续 24 行的首元素所在主存块，映射到的 Cache 组号呈现**周期为 8 的严格循环跳跃**：
- 第 0 行 $\to$ 组 0
- 第 1 行 $\to$ 组 8
- 第 2 行 $\to$ 组 16
- 第 3 行 $\to$ 组 24
- 第 4 行 $\to$ 组 32
- 第 5 行 $\to$ 组 40
- 第 6 行 $\to$ 组 48
- 第 7 行 $\to$ 组 56
- 第 8 行 $\to$ 组 $64 \equiv 0$ （回绕到第 0 组）
- ...

### 组内容量压测：
- 24 行数据以步长 8 散列在全 Cache 的 64 个组中，**实际仅仅命中了其中的 8 个特定组**；
- 这 24 行均匀分配在这 8 个组里，每一个组分担的物理块数为：
  $$\frac{24\text{ 行}}{8\text{ 组}} = 3\text{ 块/组}$$
- **判定核心**：我们的 Cache 是 **4 路组相联**，意味着**每个组最多可以容纳 4 个主存块**！
- 因为：
  $$3\text{ 块} < 4\text{ 路}$$
  **每一个被用到的组，其负载都严格小于组相联路数上限！**

---

## 三、 全局命中率最终推导闭环

1. **当 $j=0$ 时（遍历第 0 列）**：
   - 依次访问 `a[0][0], a[1][0], ..., a[23][0]`；
   - 24 次访问共载入 24 个主存块，由于每组只塞入 3 块（$< 4$ 路），**全过程没有任何一个块被淘汰置换**，这 24 个块全部稳稳驻留在 Cache 中；
2. **当 $j=1$ 到 $j=7$ 时（遍历后续各列）**：
   - `a[i][1]` 到 `a[i][7]` 与 `a[i][0]` 在内存中物理相邻，它们**完全处于前面已经被调入 Cache 的同一个 32B 主存块中**！
   - 因为前序块没有被踢出，后续这 7 次访问**次次直接命中 Cache**！
3. **命中率计算**：
   - 每个 32B 块依然是首次访问冷缺失 1 次，随后 7 次访问全部命中；
   - 命中率依旧为：
     $$\text{Hit Rate} = \frac{7}{8} = \mathbf{87.5\%}$$

这就是为什么在满足“数据总量小于 Cache 且各组冲突块数小于组相联度”时，按列遍历依然能保持和按行遍历相同的高命中率。
