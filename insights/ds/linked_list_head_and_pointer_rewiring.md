# 链表头结点（哨兵）与半成品指针改链时序

> 关联真题：`2021-01`、`2023-02`（见 [Sprint40 Day 03](../../sprint40/day03.md)）  
> 核心痛点：
> 1. 带头结点链表里“删除第一个元素”为什么不是删 `h`，为什么要先 `h->next = q->next`？
> 2. 双链表插入只改完 `next` 还没改 `prev` 时，为什么 `s->next->prev` 不是 `s` 自己，而是 `p`？

---

## 一、 带头结点链表删除首元结点（2021-01）

### 1. 认知摩擦点：“第一个元素”不是 `h`
审题必须先盯死**带头结点**还是**不带头结点**：

| 链表类型 | `h` 指向谁 | “第一个元素”是谁 | 删除第一个元素时 |
| :--- | :--- | :--- | :--- |
| **带头结点**（2021-01） | 头结点（哨兵，不存业务数据） | **`h->next`** | 删 `h->next`，**永远不删 `h`** |
| **不带头结点** | 第一个数据元素本身 | **`h`** | 删 `h`，且必须修改 `h = h->next` |

### 2. 为什么必须有第二步 `h->next = q->next;`？
设原带头结点的单循环链表为 `h -> A -> B -> C -> h`，要删除第一个元素 `A`：
1. `q = h->next;`：只用临时指针 `q` 抓住 `A`，链表的任何指针都还没改。
2. `h->next = q->next;`：把 `h` 的后继跨过 `A` 直接连向 `B`（**保住后半段不断链**）。如果跳过这步直接 `free(q)`，`A` 销毁后 `B` 的地址随之丢失，整条链表断裂。
3. **单结点边界（原链表只有 `A`，且尾指针 `p` 指向 `A`）**：
   - 此时 `q->next` 指向 `h` 本身，第二步 `h->next = q->next;` 恰好执行了 `h->next = h;`，把空表还原成合法的**空单循环链表**；
   - 第三步 `if (p == q) p = h;` 把尾指针 `p` 拉回头结点，防止 `free(q)` 后 `p` 变成悬空指针；
4. `free(q);`：安全释放 `A`。

## 二、 双链表半成品状态下的指针追踪（2023-02）

### 1. 认知摩擦点：把“半成品”当成“完整双链表”
题干在非尾结点 `p` 后插入新结点 `s`（设原 `p` 的后继为 `B`），已执行：
```c
s->next = p->next;
p->next = s;
```
此时容易凭直觉误以为“往右走一步再往左走一步 `s->next->prev` 一定是 `s` 自己”。

### 2. 逐条检查此刻的真实指针状态
前两句**只改了 `next` 方向，一条 `prev` 链都没动过**，`B->prev` 里存的依然是旧前驱 **`p`**：

```text
next 方向（已接好）：  p ──▶ s ──▶ B
prev 方向（未修改）：  p ◀──────── B   （s->prev 未赋值，B->prev 仍是 p）
```

此时执行 C 选项两句（注意 `=` 是**赋值**，不是判等）：
1. **`s->prev = s->next->prev;`**
   - `s->next` 是 `B`，`B->prev` 此刻是旧值 **`p`**；
   - 所以这句等价于 **`s->prev = p;`**，把 `s` 的前驱连向 `p`。
2. **`s->next->prev = s;`**
   - 等价于 **`B->prev = s;`**，把 `B` 的前驱从 `p` 改指到 `s`。
   - **只有在这两句都执行完之后**，`s->next->prev` 才真正变成 `s` 自己。

### 3. 闭环判据（做任何链表改链题通用）
> **永远不要凭“最终完成态”的对称性去猜中间某一行代码的值。**  
> 每写/读一行指针赋值，只看**执行到这一行之前，每个结点的 `next` 和 `prev` 实际存着谁的地址**；谁的指针还没被改写，它就一定还指着原来的旧结点。
