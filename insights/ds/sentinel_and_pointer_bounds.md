# 哨兵机制与 C 指针越界边界辨析

> 核心痛点：
> 1. 顺序查找里 `a[0]` 为什么要存 `key` 而不是存数组长度 `n`？
> 2. 把 `key` 放进 `a[0]` 是为了利用栈/堆缓存局部性吗？
> 3. 代码里没有叫 `sentinel` 的变量，怎么一眼认出哪里用了哨兵？
> 4. `a[-1]` 当哨兵为什么合法？什么情况下 `[-1]` 才算违法越界？此时数组地址还是 `&a[0]` 吗？

---

## 一、 哨兵的本质：用 1 个边界槽位，砍掉循环里每轮的越界判断

没有哨兵时，循环每推进 1 步都要同时做 **2 次条件判断**：
- **边界条件**：下标有没有越界（如 `i < n` / `i >= 1`）？
- **业务条件**：当前元素是不是目标（如 `a[i] == key`）？

加上哨兵后，人为在边界放一个**必然触发业务条件终止**的值，把“边界条件”吸收到“业务条件”里，循环内部就只剩 **1 次条件判断**。

### 对比一览：无哨兵 vs `a[0]` 存长度 vs `a[0]` 存哨兵（`key`）

| 写法 | `a[0]` 里放什么 | 循环每轮判断几次 | 是否属于哨兵 |
| :--- | :--- | :--- | :--- |
| **普通顺序查找** (`a[0..n-1]`) | 真实数据 | **2 次**（`i < n` + `a[i] == key`） | 否 |
| **长度域写法**（如串长 `S[0]`） | 元素个数 `n` | **2 次**（`i <= a[0]` + `a[i] == key`） | **否**（只是把 `length` 变量借存在 `a[0]`，没省掉越界判断） |
| **哨兵顺序查找** (`a[1..n]`) | **`key` 本身** | **1 次**（只有 `a[i] != key`，删掉 `i >= 1`） | **是** |

> **考研 ASL 易错点**：
> - 查找成功时，有无哨兵的平均查找长度都是 $\frac{n+1}{2}$；
> - **查找失败**时，有哨兵版最后还要和 `a[0]` 比较一次相等才退出，所以关键字比较次数是 **$n+1$ 次**；无哨兵版只比较 **$n$ 次**关键字（但多做了 $n+1$ 次下标越界判断）。

### 为什么不是为了“缓存局部性”？
- `key` 作为标量，进循环前就被编译器加载到 **CPU 寄存器**（比 L1 Cache 更快）；
- 从 `i = n` 往 `1` 扫描的过程中，循环中途根本不读 `a[0]`，直到最后 `i = 0` 才读一次 `a[0]` 停下来；
- 哨兵提速靠的不是访存局部性，而是**把每轮循环的条件分支指令减半**（现代工程中因破坏只读性/线程安全且 CPU 分支预测准确率高，顺序查找反而少用）。

## 二、 代码里没有 `sentinel` 关键字，怎么一眼认出哨兵？

同时满足以下 **3 个结构特征**，就是哨兵：
1. **边界多占 1 个不存业务数据的位置**（如数组空出 `a[0]` 或 `a[n]`，链表多建头结点）；
2. **往该位置塞入能触发循环终止的值**（循环见什么停，哨兵就放什么）：
   - 顺序查找：`a[0] = key`（`a[i] != key` 见 `key` 停）
   - 直接插入排序：`a[0] = a[i]`（`a[j] > a[0]` 见自己停）
   - 归并排序：两段末尾放 `+∞`（较小的一侧先走，遇 `+∞` 停）
   - C 字符串：末尾放 `'\0'`（`s[i] != '\0'` 见 `'\0'` 停）
3. **紧接着的循环里“故意没写”防越界或判空判断**（最核心识别标志）。

## 三、 `a[-1]` 哨兵是怎么做到的？合法与违法的唯一边界

### 1. 合法实现：多申请 1 格 + 指针右移 1 位
```c
int raw[6];          // 真正申请 6 个格子：假设地址 0x100 ~ 0x114
int *a = raw + 1;    // 指针 a 指向 raw[1]（地址 0x104）

a[-1] = key;         // *(a - 1) = *(0x104 - 4) = *0x100 = raw[0]（合法！）
int i = n - 1;
while (a[i] != key) i--;
return i;            // 没找到自然返回 -1，找到返回 0..n-1
```
*(动态分配 `int *raw = malloc((n + 1) * sizeof(int));` 时，释放必须 `free(raw)`，不能 `free(a)`。Java 不支持指针偏移；Python 的 `a[-1]` 指最后一个元素，含义不同。)*

### 2. 合法 vs 违法的唯一判据
在 C/C++ 中，`p[i]` 只是地址计算 `*(p + i)`。**合法与否不看下标正负，只看算出来的地址是否落在自己申请的内存块内**：
- **合法 `a[-1]`**：`a = raw + 1`，`a[-1]` 落在 `raw[0]`（`0x100`），属于已分配内存。
- **违法 `b[-1]`**：只定义了 `int b[5]`（`0x104 ~ 0x114`）却写 `b[-1] = 99`，踩到 `0x100`（隔壁变量或未映射页），属于未定义行为。
- **为什么违法时有时不报错？** C/C++ 默认不做数组边界检查，操作系统 MMU 只按页（通常 4KB）保护；踩到同页隔壁变量表面能读写但不报错，实际已破坏数据。编译加 `-fsanitize=address`（ASan）可立刻捕获此类越界。

### 3. 有了 `a[-1]`，指针/数组地址还是 `[0]` 吗？
**依然是 `[0]`**，永远不会变成 `-1`：
- 真实数组 `raw` 的首地址是 `&raw[0]`（`0x100`）；
- 指针 `a` 存的地址永远是 `&a[0]`（`0x104`，即 `&raw[1]`）；
- `a[-1]` 只是从 `a` 往回退 1 格算出来的地址（`0x100`）。
