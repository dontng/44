# 3.1_存储器概述

3.1 如果只是"分类 + 指标 + 层次图"，那它只值五分钟。但换个身份看——3.1 其实是**这一整章为什么存在的答案**。我看到的 3.1 是这样的：

## 3.1 的底色：内存墙

Patterson & Hennessy 在《计算机组成与设计》里，把"局部性"列进体系结构的**八大设计思想**，和"抽象""流水线"并列。这个待遇不是随便给的：处理器性能曾经每年涨 50% 上下，而 DRAM 延迟每年只改善 7% 左右——Wulf 和 McKee 1995 年给这道裂缝起了名字，叫 **内存墙**。

翻译成大白话：**计算是便宜的，访存是贵的。** 现代 CPU 一个周期不到 1ns，从 DRAM 取一个数却要 ~100ns，几百个周期干等。Cache、乱序执行、预取——硬件一半的聪明才智都花在"等内存"上。所以存储系统不是 CPU 的附属，它是整个体系结构的中心矛盾。这解释了为什么 408 计组把这一章养得这么肥：**这是全科目里"工程妥协"味道最浓的一章。**

## 层次结构的本质：不是抽屉，是递归的 Cache

课本画"寄存器 → Cache → 主存 → 辅存"，容易让人误以为是四格抽屉。真实的理解是：**每一层都是下一层的 Cache。**

- 寄存器是 Cache 的 Cache；
- TLB 是页表的 Cache；
- 页是磁盘的 Cache。

也就是说，3.1 的层次图不是一张静态示意图，它是**全章的目录**：它提前预告了 3.5 和 3.6 是同一套机关（映射、替换、写策略对每一层都成立），只是上演的位置不同。

## 物理决定了一切

为什么分层恰好是"SRAM / DRAM / 磁盘"这个顺序？这不是工程师的选择，是物理的选择：

- **SRAM**：双稳态触发器，稳定，但一比特要 6 个晶体管——贵；
- **DRAM**：一个电容存一比特，密度高、便宜，但电荷会漏（所以要刷新），而且读是**破坏性读出**（读完了电荷没了，得回写）——这就是"存取周期 > 存取时间"的物理根源，不是考试规定；
- **磁盘**：机械臂寻道是毫秒级。

每往下一层，速度掉一个数量级、容量涨一个数量级——这张表不是设计出来的，是物理常数表。**理解了它，3.2 里 DRAM 刷新的所有细节都自动有了解释。**

## 命题人视角：3.1 的坑

作为分析命题的助手，3.1 的考点我看就三类，而且都有陷阱：

1. **透明性**：Cache 由硬件管理，对所有程序员透明；虚拟存储由 OS 管理，对**应用程序员**透明、对系统程序员可见。408 最爱在"对谁透明"上做文章——这是 3.1 里最容易被当废话跳过、又最常考的点。
2. **单位**：存储容量是 2 的幂（64KB = 2^16），传输速率是 10 的幂。同一个"K"在两个语境里含义不同，专门有人栽在这上面。
3. **指标换算**：存取时间 / 存取周期 / 带宽，主存带宽 = 数据宽度 × 频率。这个账本 3.1 立起来，3.3 扩展芯片、3.5 算平均访问时间全都要回来用它。

## 我的一句话总结

全章 3.1–3.6 就两个词：**用钱换速度。** 3.1 立原则（分层、局部性、指标），3.2/3.3 造便宜的层，3.4 造最便宜的层，3.5/3.6 装"看起来快"的机关。工业界也没闲着：JEDEC 定 DDR 标准、NVMe 让 SSD 直连 PCIe、HBM 把内存叠到 GPU 旁边——每一次迭代都是在内存墙上凿新洞。

所以 3.1 不是绪论废话，它是**带着命题意图的纲领**：后面每一节的考题，都能在 3.1 找到"为什么考它"的理由。

要不要接着聊透明性这个坑？还是直接钻平均访问时间公式——3.5 和 3.6 所有计算题的骨架。
