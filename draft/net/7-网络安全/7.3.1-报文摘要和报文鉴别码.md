# 7.3.1 报文摘要和报文鉴别码

在网络通信中，仅有加密并不等同于安全。加密只能防止信息泄露（保证机密性），却不能证明收到的数据未被黑客篡改（无法保证完整性），也不能证明消息确实由真正的发件人发出（无法提供报文鉴别）。

---

## 一、密码学单向散列函数与报文摘要

### 1. 报文摘要（Message Digest）的定义
**密码学散列函数（Cryptographic Hash Function）** 能够将任意长度的输入报文 $M$，变换为一个**固定长度**的较短输出比特串，该输出被称为输入报文的 **报文摘要（Message Digest）** 或 **散列值（Hash Value）**：

$$h = H(M)$$

```text
       任意长度的输入明文 M (可以是 1 字节，也可以是 10 GB 镜像文件)
                     │
                     ▼
             +---------------+
             | 密码散列函数  |  H(M)
             +---------------+
                     │
                     ▼
       固定长度的输出摘要 h (例如 MD5 输出 128 位，SHA-256 输出 256 位)
       (相当于该数据独一无二的“数字指纹”)
```

### 2. 密码学安全散列函数的四大硬性数学特性
普通校验和（如 CRC、IP 首部检验和）只能防范偶然的信道物理比特翻转，不能抵御恶意攻击。合法的密码学散列函数必须严格满足以下特性：

1. **单向性（One-Way Property / 抗原像性）**：
   - 给定报文 $M$，计算散列值 $H(M)$ 在计算上极快；
   - 但**反过来**，给定一个散列值 $h$，要逆向推导寻找满足 $H(M) = h$ 的原始输入 $M$ 在计算上是不可行的（数学上的单向性保证）；
2. **弱抗碰撞性（Weak Collision Resistance / 抗第二原像性）**：
   - 给定一个已知的原始报文 $M$，要寻找另一个**内容不同的报文 $M'$（$M' \ne M$）**，使得它们的散列值相同（$H(M') = H(M)$），在计算上是不可行的；
3. **强抗碰撞性（Strong Collision Resistance）**：
   - 攻击者要凭空发现**任意两个内容不同的报文 $M$ 和 $M'$（$M \ne M'$）**，使得它们产生相同的散列值（$H(M) = H(M')$），在计算上是不可行的（防范生日攻击 Birthday Attack）；
4. **雪崩效应（Avalanche Effect）**：
   - 原始报文中只要哪怕发生了 1 个比特的微小改变，输出的报文摘要中至少有超过一半的比特位会发生随机性的巨大变动，使攻击者无法通过对比散列值推测篡改规律。

### 3. 常见散列算法对比：MD5 与 SHA 家族

| 算法名称 | 摘要输出长度 | 内部处理分组 | 安全现状与规范 |
|---|:---:|:---:|---|
| **MD5** | **128 位** (16 字节) | 512 位 | 由 Rivest 设计。王小云院士团队攻破其抗碰撞性，已被证实容易构造碰撞冲突，**严禁用于高安全场景**。 |
| **SHA-1** | **160 位** (20 字节) | 512 位 | 美国 NIST 早期标准。2017 年已被攻破理论碰撞实例，现已被主流安全协议全面淘汰。 |
| **SHA-256**<br>*(SHA-2 家族)* | **256 位** (32 字节) | 512 位 | **当前国际通用标准**。输出长度长、数学结构抗碰撞性极强，广泛应用于 TLS 证书、比特币区块链与现代操作系统签名。 |
| **SHA-512** | **512 位** (64 字节) | 1024 位 | 针对 64 位 CPU 架构深度优化的超长安全散列标准。 |

## 二、为什么单纯的报文摘要无法防止恶意篡改？

一个常见的误区是：发送方把明文 $M$ 和它的摘要 $H(M)$ 一起发送给接收方，接收方重新计算摘要并比对，就能防止数据被篡改。

```text
【中间人攻击推演 (中间人攻击下单纯散列的彻底失效)】:
 发送方 (Alice)                                                接收方 (Bob)
      │                                                             │
      ├─ 发送 [ 明文 M, 摘要 H(M) ] ───X (被中间人黑客截获!)        │
                                       │                            │
                                       ▼                            │
                       [ 中间人修改数据为篡改文本 M' ]               │
                       [ 中间人利用公开算法重新计算: H(M') ]         │
                                       │                            │
                                       ├─ 转发伪造包 [ M', H(M') ] ─>│
                                                                    ▼
                                                       Bob 收到 [ M', H(M') ]
                                                       Bob 计算 H(M') 并比对:
                                                       "计算值 == 接收值! 校验通过!"
                                                       (Bob 惨遭欺骗，接受了假数据!)
```

- **失效根源**：散列函数 $H$ 是完全公开的数学算法。中间人截获报文篡改内容后，可以轻易使用同一个公开函数重新计算一个全新的匹配摘要并替换原摘要。
- **核心结论**：**单纯的散列函数只能提供完整性检验，无法提供真实性鉴别。要想保证完整性与真实性，计算散列时必须引入秘密密钥**！

## 三、基于密钥的散列：报文鉴别码（MAC / HMAC）

为了彻底解决上述篡改漏洞，密码学引入了 **报文鉴别码（MAC，Message Authentication Code）**。

### 1. 核心工作原理
通信双方预先通过某种方式共享一个秘密密钥 $K_{shared}$：
- 发送方将**原始报文 $M$** 与 **共享密钥 $K_{shared}$** 联合输入鉴别算法，生成一段短小的鉴别标签（即 MAC 值）：
  $$\text{MAC} = C_{K_{shared}}(M)$$
- 发送方将明文报文 $M$ 与 MAC 一同发送给接收方：$[M, \; \text{MAC}]$；
- 接收方收到后，使用本地持有的完全相同的共享密钥 $K_{shared}$ 对收到的 $M$ 重新计算 $\text{MAC}'$；
- **比对判定**：若 $\text{MAC}' == \text{MAC}$，证明该报文在传输过程中**绝对未被篡改**，且**确实出自知晓该秘密密钥的合法发送方之手**！

```text
       发送方 (Alice)                                                接收方 (Bob)
            │                                                             │
     明文 M │                                                      明文 M │
            ├───────────────┐                                             ├───────────────┐
            │               │                                             │               │
            ▼               ▼                                             ▼               ▼
      [ 原样发送 ]    +-----------+                                 [ 提取明文 M ]  +-----------+
            │         | MAC 计算  | <── 共享密钥 K                        │         | MAC 计算  | <── 共享密钥 K
            │         +-----------+                                       │         +-----------+
            │               │                                             │               │
            │               ▼ 生成 MAC 标签                               │               ▼ 计算 MAC'
            ├──────── [ M, MAC ] ────────────────────────────────────────>┤
            │                                                             │ (比对 MAC' 与 MAC)
            │                                                             ▼
            │                                                   若一致: 完整性与身份确凿!
```

### 2. HMAC（基于散列函数的报文鉴别码，RFC 2104）
在现代网络协议（如 IPsec AH、TLS 记录层）中，最著名的 MAC 构造方案是 **HMAC（Hash-based MAC）**。
HMAC 利用标准密码散列函数（如 SHA-256）结合密钥构造，数学定义为：

$$\text{HMAC}_K(M) = H\Big((K \oplus opad) \;\parallel\; H\big((K \oplus ipad) \;\parallel\; M\big)\Big)$$

- 其中 $ipad$（内部填充常数）与 $opad$（外部填充常数）为固定的填充常数比特串，$\parallel$ 表示字符串拼接；
- **设计精妙之处**：经过了内外两次散列嵌套，彻底免疫了普通散列函数容易遭受的“长度扩展攻击（Length Extension Attack）”，保证了极端数学环境下的强安全性。
