# 7.6 访问控制

访问控制（Access Control）是网络系统安全防御的核心机制，负责根据实体身份和系统安全策略，明确限定主体（Subject，如用户、进程）对客体（Object，如文件、网络端口、数据库、系统设备）的访问操作权限，防止未授权的数据泄露或越权破坏。

---

## 一、访问控制的核心要素与基本模型

访问控制体系建立在三大核心概念之上：

$$\text{访问控制三要素} = (\text{主体 Subject}, \; \text{客体 Object}, \; \text{控制策略 Policy})$$

```text
       [ 主体 Subject ] ──(发起访问请求)──> [ 访问控制执行实体 / 引用监控器 ] ──> [ 客体 Object ]
       (用户、客户端进程)                   (检查访问权限与安全策略规则)            (资源、文件、端口)
                                                          │
                                                    [ 允许 / 拒绝 ]
```

1. **主体（Subject）**：发出访问操作请求的主动实体（如登录用户、正在运行的服务进程）；
2. **客体（Object）**：包含信息的被动受保护实体（如服务器数据文件、网络服务端口、系统设备）；
3. **操作（Operation）**：主体对客体执行的具体动作（如读、写、执行、删除、转发）。

---

## 二、经典访问控制策略模型对比

根据权限决定的控制主体与管理模式，经典访问控制模型分为三大流派：

| 访问控制模型类别 | 权限决定权归属 | 核心工作机制 | 典型适用场景 |
|---|---|---|---|
| **自主访问控制**<br>(DAC, Discretionary) | **客体拥有者自主决定** | 资源的所有者对该资源拥有完全处置权，可自主决定将该资源的读写执行权限授予或转授给其他任意用户。 | 普通操作系统文件权限系统（如 UNIX 的 `chmod`，文件属主可自由更改其他用户的 rwx 权限）。 |
| **强制访问控制**<br>(MAC, Mandatory) | **系统管理员统一强制设定** | 系统为每个主体分配“安全许可级别”，为每个客体贴上“敏感度安全标签”。主体能否访问客体完全由系统内核强制依照格模型（如 Bell-LaPadula 保密模型）规则裁决，任何普通用户无权更改权限。 | 国防军工保密系统、高安全等级操作系统（如 SELinux）。 |
| **基于角色的访问控制**<br>(RBAC, Role-Based) | **根据系统业务岗位角色集中绑定** | 不直接给单个用户分配具体权限，而是**将权限与“角色（Role）”绑定，再为用户分配角色**。用户离开岗位或换岗时，只需收回或更换角色，无需重配底层资源。 | 大型企业内部管理系统、云服务 IAM 权限系统。 |

---

## 三、访问控制的底层数据结构实现

在操作系统和网络防火墙内核中，访问控制通常依赖以下两种经典数据结构维护：

```text
       【访问控制矩阵 (Access Control Matrix)】
                   文件 F1        文件 F2        网络端口 80
       Alice   |   Read/Write |   Read       |   Connect
       Bob     |   Read       |   No Access  |   Listen
       
            │ 垂直按列拆分 (以客体为中心)              │ 水平按行拆分 (以主体为中心)
            ▼                                         ▼
   【访问控制列表 (ACL)】                     【权能列表 (Capability List)】
   - 挂在客体身上                             - 挂在主体身上 (令牌模式)
   - 文件 F1: [Alice: RW, Bob: R]             - Alice: [F1: RW, F2: R, Port80: Connect]
```

### 1. 访问控制列表（ACL，Access Control List）
- **组织形式**：以**受保护客体**为中心。每个客体维护一个访问项列表，明确列出允许访问本客体的各个主体及其对应权限；
- **网络中的典型应用**：路由器与交换机上的 **IP 访问控制列表（ACL）**。网络管理员在路由器接口上配置规则清单，根据数据包的五元组逐条匹配并执行 `permit`（允许放行）或 `deny`（拒绝丢弃）。

### 2. 权能列表（Capability List）
- **组织形式**：以**访问主体**为中心。每个用户或进程持有一张“凭证清单”（类似于通行证或数字令牌），清单中列明了该主体合法被允许访问的所有客体及权限范围；
- **应用场景**：现代 Web API 中的 JWT（JSON Web Token）或 OAuth 2.0 授权令牌。
