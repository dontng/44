# 7.9 常见的网络攻击及其防范

随着计算机网络深入社会各个领域，网络攻击手段呈现出复杂化与系统化趋势。理解常见网络攻击的底层运作机理，是构建端到端网络防御纵深的关键前提。

---

## 一、拒绝服务攻击（DoS 与 DDoS）

### 1. 攻击机理与分布式演进
- **拒绝服务攻击（DoS，Denial of Service）**：攻击者利用协议漏洞或海量伪造请求，耗尽目标服务器或网络路由器的特定系统资源（如 CPU、内存、TCP 半开连接表、网络带宽），致使合法用户无法获得正常响应；
- **分布式拒绝服务攻击（DDoS，Distributed DoS）**：攻击者利用恶意木马控制全球成千上万台僵尸主机（Botnet / 肉鸡），在同一时刻统一步调向受害目标服务器发起饱和式洪泛攻击。

### 2. 常见攻击形态与底层机制
1. **TCP SYN 洪泛攻击（SYN Flood）**：
   - **底层协议机理**：利用 TCP 三次握手机制中服务端的资源分配缺陷；
   - 攻击者向服务器连续发送海量伪造源 IP 的 `SYN = 1` 报文段；
   - 服务器收到后，分配传输控制块（TCB）与半连接队列资源，并回送 `SYN+ACK`，进入 `SYN-RCVD` 状态等待客户端确认；
   - 由于源 IP 全是虚假的，服务器永远收不到第三次握手的 ACK；服务器的**半连接队列（SYN Queue）被迅速占满**，导致合法用户的正常 TCP 连接请求被全部丢弃；
   - **防范机制**：启用 **SYN Cookie 机制**。服务端在收到 SYN 时不立即分配半连接内存，而是根据双方 IP、端口与时间戳计算出一个加密哈希值填入初始序号（seq）；仅当收到合法的第三次握手 ACK 且哈希校验通过后，才正式为该连接分配系统内存资源。
2. **Smurf 攻击（ICMP 广播放大攻击）**：
   - 攻击者向中间广播网络的广播地址发送 ICMP Echo Request（ping 请求），并将该报文的**源 IP 地址恶意伪造为受害者目标主机的 IP**；
   - 广播网络内的成百上千台主机收到该请求后，同时向该伪造源 IP（受害者）发送 ICMP Echo Reply 应答，数十倍放大的海量流量直接冲垮受害者的网络出口带宽；
   - **防范机制**：配置网络边界路由器，严禁将外部定向广播转发至本地网段（禁用 Directed Broadcast），并禁止主机响应对广播地址的 ICMP 请求。

## 二、地址欺骗类攻击

### 1. ARP 欺骗（ARP Spoofing / 中间人截获）
- **漏洞根源**：传统 ARP 协议是完全无状态、无认证的。任何主机在未收到请求的情况下均可主动广播“免费 ARP”，且接收端会无条件用最新收到的 ARP 报文覆盖本地 ARP 缓存表项；
- **攻击过程**：
  - 黑客向局域网受害者主机发送伪造的 ARP 应答：“默认网关的 IP 是 192.168.1.1，其 MAC 地址是黑客的 MAC”；
  - 受害者主机受骗，将其 ARP 表中网关的 MAC 地址篡改为黑客网卡的 MAC；
  - 随后受害者发往外网的所有数据帧全部被交换机导流送入黑客电脑，黑客轻松实现嗅探监听或篡改（中间人攻击）；
- **防范机制**：静态绑定 IP 与 MAC 地址；在交换机上部署 **DAI（动态 ARP 检查，Dynamic ARP Inspection）**，通过结合 DHCP Snooping 绑定表丢弃非法伪造的 ARP 报文。

### 2. IP 欺骗（IP Spoofing）
- **机理**：攻击者直接在原始套接字中伪造 IP 首部中的“源 IP 地址”，以绕过基于源 IP 的访问控制列表（ACL）或隐藏真实攻击来源；
- **防范机制**：在路由器边界启用 **URPF（单播逆向路径转发检查）**。路由器收到数据包时，检查该数据包入接口是否与到达该源 IP 的路由转发表出接口匹配；若不匹配，判定为伪造源 IP 直接丢弃。

## 三、网络攻击分类与纵深防御矩阵

| 攻击类型 | 核心攻击机理 | 受攻击协议层次 | 工业级针对性防范措施 |
|---|---|:---:|---|
| **SYN Flood** | 伪造源 IP 耗尽服务端 TCP 半连接队列 | 运输层 (TCP) | 启用 SYN Cookie，缩短半连接超时，部署 DDoS 高防清洗网关 |
| **ARP 欺骗** | 滥用无状态 ARP 应答篡改本地缓存 | 数据链路层 | 交换机启用 DAI（动态 ARP 检查），静态绑定关键网关 MAC |
| **DNS 劫持/投毒** | 抢先伪造不安全的 UDP 53 解析响应 | 应用层 (DNS) | 部署 DNSSEC（DNS 数字签名扩展），使用 DoH（基于 HTTPS 的 DNS） |
| **重放攻击** | 录制截获的合法鉴别报文原样重新注入 | 运输层 / 应用层 | 鉴别协议强制加入动态不重数（Nonce）或严格时钟同步时间戳 |
| **中间人攻击** | 伪造通信对端公钥介入通信双向窃听 | 运输层 / 应用层 | 强制部署基于第三方权威 CA 认证的数字证书体系（X.509） |
