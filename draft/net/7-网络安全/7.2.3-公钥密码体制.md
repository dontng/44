# 7.2.3 公钥密码体制

公钥密码体制（Public Key Cryptosystem，又称非对称密码体制或双钥密码体制）是现代密码学史上最伟大的里程碑，由 Diffie 与 Hellman 于 1976 年首次提出，彻底解决了对称密钥密码在密钥分发与数字签名上的根本困境。

---

## 一、公钥密码体制的基本工作模型

在公钥密码体制中，加密密钥与解密密钥是**成对生成的非对称密钥对**：
1. **公钥（Public Key，记为 $PK$）**：**公开透明**，可以向全球任何人发布（如公开发布在服务器或数字证书中）；
2. **私钥（Private Key / Secret Key，记为 $SK$）**：**绝对保密**，仅由密钥的拥有者一人在本地安全硬件或受保护内存中秘密持有，绝不向网络传输。

```text
       发送方 (Alice)                                                接收方 (Bob)
            │                                                             │
            │ 想要给 Bob 发送机密消息 X                                   │ 生成密钥对: (PK_B, SK_B)
            │                                                             │ 将公钥 PK_B 全网公开发布!
            │ 1. 获取 Bob 的公开密钥 PK_B                                 │
            ▼                                                             │
      [ 执行加密运算 ]                                                    │
      密文 Y = E_{PK_B}(X)                                                │
            │                                                             │
            ├────────────── 2. 将密文 Y 发送给 Bob ──────────────────────>│
            │                                                             ▼
            │                                                       [ 执行解密运算 ]
            │                                                       明文 X = D_{SK_B}(Y)
            │                                                       (全网仅 Bob 拥有的私钥 SK_B 能解密!)
```

### 核心数学逻辑与单向陷门函数
- 任意用户均可使用 Bob 的公钥 $PK_B$ 将明文加密为密文：$Y = E_{PK_B}(X)$；
- **全网只有 Bob 本人持有对应的私钥 $SK_B$，有且仅有 Bob 能够成功解密**：$X = D_{SK_B}(Y)$；
- **单向陷门函数特性**：
  - 由私钥 $SK$ 计算公钥 $PK$ 在数学上极其容易；
  - 但已知公钥 $PK$ 和密文 $Y$，要在不知道私钥 $SK$ 的前提下反向推导出明文 $X$ 或私钥 $SK$，在计算复杂度上等价于求解极难的数学难题（如大整数素因子分解、离散对数问题），在多项式时间内是不可计算的。

## 二、经典公钥密码算法：RSA 算法数学机制

RSA 算法由 Rivest、Shamir 和 Adleman 于 1977 年提出，是目前应用最广泛的公钥密码算法，其安全性完全建立在**大整数素因子分解的数学极度困难性**之上。

### 1. RSA 密钥生成五步数学推演
1. **选取素数**：随机挑选两个互不相同的大素数 $p$ 和 $q$（保密）；
2. **计算模数**：计算模数 $n = p \times q$。其二进制长度即为 RSA 密钥长度（如 2048 位）。**模数 $n$ 作为公钥的一部分向全网公开**；
3. **计算欧拉函数**：计算 $\phi(n) = (p - 1)(q - 1)$（保密）；
4. **选取公钥指数 $e$**：随机挑选一个整数 $e$，满足 $1 < e < \phi(n)$，且 $e$ 与 $\phi(n)$ 互素（即 $\gcd(e, \phi(n)) = 1$）。工程中常固定选取 $e = 65537$；
5. **计算私钥指数 $d$**：利用扩展欧几里得算法，求解 $e$ 模 $\phi(n)$ 的乘法逆元 $d$，满足：
   $$e \times d \equiv 1 \pmod{\phi(n)}$$

- **最终密钥对输出**：
  $$\text{公钥 (Public Key)} = (e, n)$$
  $$\text{私钥 (Private Key)} = (d, n)$$
  *(参数 $p, q, \phi(n)$ 必须全部销毁或严格保密！)*

### 2. RSA 加密与解密运算
- **加密过程**：将明文编码为整数 $m$（$0 \le m < n$），利用公钥 $(e, n)$ 执行模幂运算：
  $$c = m^e \pmod{n}$$
- **解密过程**：接收方利用私钥 $(d, n)$ 对密文 $c$ 执行模幂运算：
  $$m = c^d \pmod{n}$$
- **数学证明依托**：根据欧拉定理与费马小定理，$(m^e)^d \equiv m^{ed} \equiv m^{k\phi(n)+1} \equiv m \pmod{n}$，保证了加解密变换的精确可逆性。

## 三、对称密码体制 vs 公钥密码体制全面对比

| 评估维度 | 对称密钥密码体制 (Symmetric) | 公钥密码体制 (Asymmetric) |
|---|---|---|
| **密钥特征** | 加密密钥与解密密钥**完全相同** ($K_E = K_D$) | 加密公钥与解密私钥**成对分离** ($PK \ne SK$) |
| **保密要求** | 双方必须秘密共享该密钥，严禁外泄 | **公钥全网公开**，私钥由拥有者一人本地绝对保密 |
| **密钥分发** | 极度困难（依赖物理信道或预设安全通道） | **极其容易**（公钥可公开广播或写入证书分发） |
| **全网密钥数量** | $N$ 个实体需两两通信，需维护 $\frac{N(N-1)}{2} = \mathbf{O(N^2)}$ 个密钥 | $N$ 个实体每人仅持有一对密钥，全网仅需 $\mathbf{2N}$ 个密钥 |
| **加解密运算速度** | **极快**（硬件/软件高吞吐，适合海量流数据） | **极慢**（涉及大数模幂乘法，比对称加密慢数千倍） |
| **附加功能支持** | 仅支持机密性，无法提供不可抵赖的数字签名 | 天然支持**机密性**与**数字签名（抗抵赖）** |
| **典型代表算法** | DES, 3DES, **AES** | **RSA**, ECC (椭圆曲线密码), ElGamal |

## 四、混合密码系统（Hybrid Cryptosystem）：工程最佳实践

在现代网络安全协议（如 HTTPS/TLS、IPsec、SSH）的工业落地中，既不可能单独使用难以分发密钥的对称加密，也不可能完全依赖计算缓慢的公钥加密。实际系统全面采用 **混合密码系统（Hybrid Cryptosystem）**：

```text
       发送端 (Alice)                                                接收端 (Bob)
            │                                                             │
            │ 1. 临时生成一个真随机的【对称会话密钥 (Session Key Ks)】      │
            │                                                             │
            │ 2. 用 Bob 的【公钥 PK_B】加密该会话密钥 Ks:                  │
            │    Enc_Ks = E_{PK_B}(Ks)  (数据量极小，公钥加密开销可忽略!) │
            │                                                             │
            │ 3. 用【会话密钥 Ks】对海量业务明文数据进行快速对称加密 (AES):│
            │    Ciphertext = E_{Ks}(海量数据)                            │
            │                                                             │
            ├──────────── 4. 将 [ Enc_Ks + Ciphertext ] 发送给 Bob ──────>│
            │                                                             │
            │                                                             ▼
            │                                                       5. Bob 用自己的【私钥 SK_B】
            │                                                          解密获取会话密钥 Ks:
            │                                                          Ks = D_{SK_B}(Enc_Ks)
            │                                                             │
            │                                                             ▼
            │                                                       6. Bob 用提取出的【Ks】
            │                                                          高速解密海量业务数据:
            │                                                          数据 = D_{Ks}(Ciphertext)
```

- **设计哲学**：
  - **公钥加密用于安全信道建立**：仅加密微小的对称会话密钥（通常仅 128 位或 256 位），完美解决对称密钥的线上安全分发难题；
  - **对称加密用于真正数据吞吐**：使用协商好的会话密钥快速加密大容量的应用层传输数据，充分发挥对称算法极高的吞吐性能。
