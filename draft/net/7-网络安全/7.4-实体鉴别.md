# 7.4 实体鉴别

实体鉴别（Entity Authentication，又称身份认证）是指在网络通信中，一个通信实体向另一个实体证明自己的真实身份，确认通信对端不是冒名顶替的攻击者。

---

## 一、实体鉴别与报文鉴别的本质界限

必须严正区分**报文鉴别**与**实体鉴别**的职责范围：

| 评估维度 | 报文鉴别 (Message Authentication) | 实体鉴别 (Entity Authentication) |
|---|---|---|
| **鉴别对象** | **单个孤立报文**（静态数据） | **正在进行实时通信的实体/活人**（动态会话） |
| **防范的重点** | 防止报文内容被篡改、插入或伪造 | 防止非法攻击者**冒名顶替通信实体身份**发起会话 |
| **时间上下文** | 不关心时效性，一封邮件或一个文件可事后鉴别 | **强时效性**，必须证明对端实体**当前正在实时存活在线** |
| **重放攻击威胁**| 无法防范重放（旧的合法报文依然拥有合法签名） | **核心防范目标就是抵御重放攻击（Replay Attacks）** |

---

## 二、重放攻击的机理与防范策略

### 1. 简单口令鉴别的致命缺陷
最简单的鉴别方案是客户端向服务端发送密码明文或口令的加密散列值。
- **重放攻击（Replay Attack）**：
  - 攻击者 Mallory 潜伏在信道中，即使他无法破译该加密口令，但他可以**将该报文原封不动地录制下来**；
  - 稍后，Mallory 假冒 Alice 的身份，把录制好的加密口令重新向服务器发送一遍；
  - 服务器比对后发现口令密文完全匹配，误以为是 Alice 再次登录，Mallory 成功窃取会话权限！
- **核心结论**：**静态凭证在网络中传输，无论是否加密，都无法抵御重放攻击**。

### 2. 防重放攻击的两大核心技术
为了确保鉴别交互发生在“此时此刻”，鉴别报文中必须注入动态可变的**时变参数**：

```text
+---------------------------------------------------------------------------------+
|                              防范重放攻击的两大技术手段                         |
+---------------------------------------------------------------------------------+
| 1. 时间戳机制 (Timestamp)     : 报文携带发送方的实时绝对时间 (依赖全网严格时钟同步)|
| 2. 不重数机制 (Nonce / 挑战码): 接收方随机生成的仅使用一次的伪随机数 (无时钟依赖)  |
+---------------------------------------------------------------------------------+
```

1. **时间戳（Timestamp）**：
   - 发送方在鉴别报文中附加当前的绝对时间 $T$；
   - 接收方收到后检查当前时间 $T_{now}$，若 $|T_{now} - T| > \Delta t$（允许的最大网络时延容限），则判定报文过期直接丢弃；
   - **局限性**：对全网分布式节点之间的时钟同步精度要求极高（依赖高精度 NTP 协议），否则时钟偏差容易引发误判或重放漏洞。
2. **不重数 / 随机数（Nonce，Number used once）**：
   - 接收方每次动态生成一个不可预测的、**仅在本次握手中使用一次的随机大整数（挑战码 Nonce）**；
   - 发送方必须使用自己的秘密密钥对该 Nonce 进行加密计算或签名并返回；
   - 接收方通过验证对端对 Nonce 的计算结果，确认对端既知晓秘密密钥、且当前正在线实时响应。**现代安全协议（如 TLS、Kerberos）全面优先采用 Nonce 机制**。

## 三、经典挑战-应答鉴别机制（Challenge-Response）

**挑战-应答机制**是现代实体鉴别的经典范式。

### 1. 基于对称密钥的挑战-应答鉴别

通信双方预先共享一个秘密密钥 $K_{AB}$：

```text
       发送方 (Alice)                                                接收方 (Bob)
            │                                                             │
            ├─ 1. 发送声明: "我是 Alice，请求建立连接" ───────────────────>│
            │                                                             │
            │                                                             ▼
            │                                                       2. Bob 生成一个真随机
            │                                                          不重数 Nonce R_B
            │                                                             │
            │<─ 3. 发送挑战码 R_B ────────────────────────────────────────┤
            │                                                             │
            ▼                                                             │
      4. Alice 使用共享密钥 K_AB                                           │
         对该挑战码加密:                                                  │
         Ticket = E_{K_AB}(R_B)                                           │
            │                                                             │
            ├─ 5. 回送加密应答 Ticket ───────────────────────────────────>│
            │                                                             │
            │                                                             ▼
            │                                                       6. Bob 用自己的 K_AB
            │                                                          解密该应答:
            │                                                          R' = D_{K_AB}(Ticket)
            │                                                             │
            │                                                             ▼
            │                                                       7. 若 R' == R_B:
            │                                                          证明对端确实是 Alice!
```

- **抗重放分析**：由于 $R_B$ 是 Bob 随机动态生成的，下一次握手时 $R_B$ 必然不同；攻击者即使截获了本次的 `Ticket`，在下次连接中重放也将无法匹配新的随机数，重放攻击彻底失效。

### 2. 基于公钥密码与数字签名的双向实体鉴别
若使用公钥体系，Alice 使用自己的**私钥 $SK_A$** 对 Bob 发来的随机数 $R_B$ 进行数字签名；Bob 使用 Alice 的**公钥 $PK_A$** 验签。
同理，Alice 也可向 Bob 发送随机数 $R_A$ 要求 Bob 用私钥 $SK_B$ 签名，从而实现**双向实体互认（Mutual Authentication）**。
