# 7.2.1 密码学相关基本概念

密码学是网络安全技术的数学基石，通过对信息进行变换，以保护信息的机密性、完整性并实现实体鉴别。

---

## 一、密码系统的基本数学模型

一个通用的密码通信系统可以用五元组形式化描述：

$$\text{Cryptosystem} = (M, C, K, E, D)$$

```text
               明文 X                                                密文 Y                                                明文 X
               (Plaintext)                                           (Ciphertext)                                          (Plaintext)
                    │                                                     ▲                                                     ▲
                    ▼                                                     │                                                     │
           +-----------------+                                   +-----------------+                                   +-----------------+
           | 加密算法 E_K1   | ─────────────────────────────────>| 不安全物理信道  | ─────────────────────────────────>| 解密算法 D_K2   |
           +-----------------+                                   +-----------------+                                   +-----------------+
                    ▲                                                                                                           ▲
                    │                                                                                                           │
               加密密钥 K1                                                                                                 解密密钥 K2
```

1. **明文（Plaintext，$X$ 或 $M$）**：
   - 处于原始未加密状态的信息，任何人均可直接阅读与理解；
2. **密文（Ciphertext，$Y$ 或 $C$）**：
   - 明文经过加密变换后生成的隐藏形式数据，对无密钥的观察者呈现为伪随机字符流；
3. **密钥（Key，$K$）**：
   - 控制加密算法与解密算法执行具体变换的参数；
4. **加密算法（Encryption Algorithm，$E$）**：
   - 将明文和加密密钥转换为密文的数学变换函数：$Y = E_{K_1}(X)$；
5. **解密算法（Decryption Algorithm，$D$）**：
   - 将密文和解密密钥还原为原始明文的数学变换函数：$X = D_{K_2}(Y) = D_{K_2}(E_{K_1}(X))$。

## 二、柯克霍夫原则（Kerckhoffs's Principle）

现代密码学设计的根本铁律是 **柯克霍夫原则（Kerckhoffs's Principle）**：

> **“密码系统的安全性必须完全依赖于对密钥（Key）的保密，而绝不能依赖于对加密算法（Algorithm）本身的保密。”**

- **为什么不能靠保密算法？**
  - **难以长期守秘**：算法会被编译为硬件芯片或软件二进制程序，通过逆向工程、固件提取或代码泄露，算法细节极易曝光；一旦算法公开，整个系统将全盘崩溃且无法补救；
  - **无法经受全球同行审查**：公开的算法（如 AES、RSA）经过了全球密码学家数十年的联合数学攻防检验，已被证明没有已知的数学缺陷；而私有保密算法往往存在设计者未察觉的致命漏洞；
  - **更换代价不同**：密钥可以随时动态随机生成并在线更换；而一旦算法被破解，更换算法需要全网所有设备重构或升级硬件，成本极高。

## 三、密码分析与攻击模型分类

密码分析学（Cryptanalysis）研究如何在不知道秘密密钥的前提下破译密文或推导密钥。根据攻击者所能掌握的信息程度，密码攻击模型从弱到强分为四类：

| 攻击模型类别 | 攻击者掌握的信息前提 | 破解难度与场景 |
|---|---|---|
| **唯密文攻击**<br>(Ciphertext-Only Attack) | 攻击者仅截获并掌握**若干密文 $Y$**，知道加密算法，但不知道对应的明文。 | 攻击难度最高。现代强密码系统必须在此模型下保证计算上安全。 |
| **已知明文攻击**<br>(Known-Plaintext Attack) | 攻击者不仅掌握截获的密文 $Y$，还掌握**若干组已配对的明文-密文对 $(X_i, Y_i)$**。 | 常见于协议首部（如固定格式的报文头）或已知标准格式文件的加密场景。 |
| **选择明文攻击**<br>(Chosen-Plaintext Attack) | 攻击者能够**挑选任意自己构造的明文 $X$**，并能通过加密机获取其对应的密文 $Y$。 | 攻击能力较强。公钥密码系统（任何人都能用公钥加密）天然处于选择明文攻击环境下。 |
| **选择密文攻击**<br>(Chosen-Ciphertext Attack) | 攻击者能够**挑选任意密文 $Y$**，并能通过解密机获取其解密后的明文 $X$（但解密机拒绝解密目标目标密文）。 | 攻击者能力最强。用于检验密码系统在面对恶意篡改密文反馈时的鲁棒性。 |

## 四、无条件安全 vs 计算上安全

- **无条件安全（Unconditionally Secure / 绝对安全）**：
  - 无论攻击者掌握多少截获的密文，无论拥有多大算力或多长时间，都绝不可能解密出明文（密文不包含任何关于明文的统计信息）；
  - **唯一已被数学证明的无条件安全密码**：**一次一密（One-Time Pad，OTP）**。其要求密钥完全真随机生成、长度与明文完全等长、且每个密钥只使用一次后立即彻底销毁。由于海量真随机密钥的安全分发极其困难，在工程中除极高密级专线外难以普适使用。
- **计算上安全（Computationally Secure）**：
  - 现代密码体制普遍采用的标准。若满足以下条件之一，即认为计算上安全：
    1. 破译密码所需的计算代价超过了该信息本身的潜在商业/战略价值；
    2. 破译密码所需的计算时间远超过了该信息的有效生命周期。
