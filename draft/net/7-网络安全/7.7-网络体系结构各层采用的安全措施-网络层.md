# 7.7 网络体系结构各层采用的安全措施-网络层

网络层负责将 IP 数据报从源主机跨越多个异构网络路由转发至目的主机。在网络层实施安全机制的最大优势是：**对高层所有应用进程完全透明**，无需对 Web、邮件或自定义应用做任何代码修改，即可为全网所有端到端流量提供无缝的机密性、完整性与身份鉴别。

---

## 一、IPsec 协议族架构总览

**IP 安全协议族（IPsec，IP Security，RFC 4301）** 并不是单一的孤立协议，而是一整套构建在网络层的模块化安全框架。

```text
+=================================================================================+
|                              IPsec 协议族三大核心支柱                           |
+=================================================================================+
  │
  ├─ 1. 【鉴别首部协议 AH (Authentication Header，协议号 51)】:
  │      - 提供: 数据完整性校验 + 源身份鉴别 + 抗重放保护
  │      - 【绝对不提供数据加密 (不保证机密性，数据仍为明文!)】
  │
  ├─ 2. 【封装安全载荷协议 ESP (Encapsulating Security Payload，协议号 50)】:
  │      - 提供: 【数据加密 (机密性)】 + 数据完整性校验 + 源身份鉴别 + 抗重放
  │      - (现代 IPsec VPN 事实上的绝对主流协议)
  │
  └─ 3. 【因特网密钥交换协议 IKE (Internet Key Exchange)】:
         - 基于 Diffie-Hellman 与公钥/预共享密钥，在通信前自动协商加密算法并生成会话密钥
```

---

## 二、AH 与 ESP 协议机制深度对比

| 对比维度 | 鉴别首部协议 (AH，协议号 51) | 封装安全载荷协议 (ESP，协议号 50) |
|---|---|---|
| **机密性 (数据加密)** | **无**（数据载荷完全以明文形式在网络裸奔） | **有**（使用 AES/3DES 对数据载荷进行对称加密） |
| **完整性与身份鉴别** | **有**（利用 HMAC-SHA 计算 ICV 鉴别值） | **有**（同样利用 HMAC-SHA 对载荷与 ESP 首部提供完整性） |
| **抗重放保护** | **有**（内置 32 位防重放序列号） | **有**（内置 32 位防重放序列号） |
| **与 NAT 的兼容性** | **与 NAT 绝对水火不容**！因为 AH 校验范围覆盖了外部 IP 首部中的源目 IP，NAT 一旦修改 IP，AH 校验立即失败报废。 | **良好**（通过 ESP-in-UDP 封装技术可安全穿透 NAT 网关）。 |

## 三、IPsec 的两大工作模式：传输模式 vs 隧道模式

两种模式决定了加密与认证的范围以及具体网络部署场景：

```text
【1. 传输模式 (Transport Mode)】:
    原始 IP 数据报:  [ 原始 IP 首部 (20B) ] [ 传输层首部 (TCP/UDP) + 数据 ]
                            │
                            ▼ (插入 ESP 首部与尾部)
    传输模式数据报:  [ 原始 IP 首部 ] [ ESP 首部 ] [ 加密的 TCP/UDP 首部 + 数据 ] [ ESP 尾部 ] [ 鉴别值 ICV ]
                     (仅主机到主机端到端保护，不隐藏原始源/目的 IP 地址!)

-----------------------------------------------------------------------------

【2. 隧道模式 (Tunnel Mode)】:
    原始 IP 数据报:  [ 原始内层 IP 首部 ] [ 传输层首部 + 数据 ]
                            │
                            ▼ (将整个原始 IP 数据报作为载荷整体加密打包!)
    隧道模式数据报:  [ 全新外层 IP 首部 ] [ ESP 首部 ] [ 加密的原始 IP 首部 + 载荷 ] [ ESP 尾部 ] [ 鉴别值 ICV ]
                     (网关到网关隧道保护，彻底隐藏内部真实主机的源目 IP!)
```

### 1. 传输模式（Transport Mode）
- **封装结构**：在原始 IP 首部与传输层协议首部之间直接插入 IPsec 首部（AH 或 ESP）；
- **保护范围**：仅保护 IP 数据报的**高层载荷（传输层及以上数据）**，**不保护原始 IP 首部本身**；
- **典型应用**：**两台终端主机之间的端到端安全通信**（Host-to-Host）。两端主机操作系统必须均原生支持 IPsec。

### 2. 隧道模式（Tunnel Mode）
- **封装结构**：
  - 将**整个原始 IP 数据报（包括原始内层 IP 首部与数据载荷）整体打包作为载荷**；
  - 对这整个原始数据报执行加密和认证；
  - 在最前端**附加一个全新的、由边界路由器生成的“外层 IP 首部”**：
    - 外层源 IP：入口 VPN 网关的公网 IP；
    - 外层目的 IP：出口 VPN 网关的公网 IP。
- **保护范围**：不仅全面保护了传输层及应用层数据，而且**将内部子网主机的真实私网 IP 地址完全隐藏加密**，防止外部监听者获知通信主机的拓扑；
- **典型应用**：**站点到站点虚拟专用网（Site-to-Site VPN / 网关到网关网状互联）**。内部普通主机无需安装任何安全软件，所有加解密全权由企业边界 VPN 路由器在后台透明代劳。

## 四、安全关联（SA，Security Association）

IPsec 是面向连接逻辑的安全框架。在两个 IPsec 实体正式传输数据之前，必须先在双方之间协商并建立一条单向逻辑连接，称为 **安全关联（SA）**。

```text
+---------------------------------------------------------------------------------+
|                              安全关联 SA 的三大核心属性                         |
+---------------------------------------------------------------------------------+
| 1. 单向性 (Simplex)          : 一条 SA 仅保护单个方向的流量。通信双方全双工双向  |
|                                通信必须至少独立建立 2 条 SA (出站 SA 与 入站 SA)|
| 2. 安全参数索引 (SPI)        : 32 位无符号整数，用于在目的节点唯一标识特定 SA   |
| 3. SA 唯一定义三元组         : (安全参数索引 SPI, 目的 IP 地址, 安全协议号 AH/ESP)|
+---------------------------------------------------------------------------------+
```

- **SA 保存的状态内容**：通信双方协商选定的具体加密算法（如 AES-CBC）、鉴别散列算法（如 HMAC-SHA256）、共享的密钥串、当前防重放序列号计数器以及生存期（Lifetime）。
