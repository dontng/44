# 7.3.2 数字签名

数字签名（Digital Signature）是密码学中模拟现实世界纸质手写签名与印章的计算机技术。在公钥密码体制的支持下，数字签名能够同时实现**报文鉴别（身份验证）**、**报文完整性检验**以及**不可抵赖性（抗否认）**。

---

## 一、数字签名的三大核心特性

一个合法的数字签名体制必须满足以下三项严格的技术特性：

```text
+---------------------------------------------------------------------------------+
|                              数字签名三大法律与技术特性                         |
+---------------------------------------------------------------------------------+
| 1. 报文鉴别 (Authentication) : 接收方能够确凿核实发送方的签名身份真实有效       |
| 2. 报文完整 (Integrity)      : 签名后报文内容若发生哪怕 1 比特的篡改，签名即失效|
| 3. 不可抵赖 (Non-Repudiation): 发送方事后无法否认该报文出自自己之手;           |
|                                接收方也绝对无法伪造出能够验证通过的签名报文     |
+---------------------------------------------------------------------------------+
```

- **与手写签名的本质差异**：
  - 现实生活中的手写签名是“与人绑定、但与内容无关的”（同一份笔迹签名可以签在不同的合同上，有被复印假冒的风险）；
  - **计算机中的数字签名是“既与签名人私钥绑定、又与报文的具体每个比特内容强绑定的”**！即使同一个人签名，只要报文改动了一个字，生成的数字签名就会截然不同。

---

## 二、基于公钥密码体制的数字签名实现机制

数字签名的本质数学基础是**公钥密码体制（如 RSA）加解密运算的对称可逆性**：
- **普通机密加密**：用接收方的**公钥**加密，接收方的**私钥**解密（实现机密性）；
- **数字签名过程**：用发送方的**私钥**加密（签名），全网任何人用发送方的**公钥**解密（验签）！

### 1. 朴素数字签名（对整篇报文直接签名）
- 发送方 Alice 使用自己的私钥 $SK_A$ 对明文 $M$ 执行变换生成签名 $S$：
  $$S = D_{SK_A}(M)$$
- Alice 将原始报文与签名一起发出：$[M, \; S]$；
- 接收方 Bob 使用 Alice 的公钥 $PK_A$ 对签名 $S$ 执行运算验证：
  $$M' = E_{PK_A}(S) = E_{PK_A}(D_{SK_A}(M)) = M$$
- 若 $M' == M$，则签名验证成功。
- **工程致命缺陷**：公钥密码（如 RSA）的模幂计算极其繁重缓慢。如果传输的是 1 GB 的大文件，对整篇数据直接进行公钥加密计算会导致 CPU 彻底瘫痪，完全不具备实用性。

## 三、现代实用数字签名：报文摘要结合公钥签名

在实际工程（如 TLS 握手、软件发布包校验、区块链交易）中，数字签名全面采用 **“先计算摘要，再对摘要进行私钥签名”** 的标准两步法：

```text
       发送方 (Alice)                                                接收方 (Bob)
            │                                                             │
            │ 拥有明文 M                                                  │
            │                                                             │
            ├─ 1. 计算散列摘要: h = H(M)                                  │
            │     (将海量数据压缩为固定 256 位指纹)                       │
            │                                                             │
            ├─ 2. 用【Alice 自己的私钥 SK_A】对摘要签名:                  │
            │     Signature S = D_{SK_A}(h)                               │
            │     (仅对 256 位执行公钥运算，毫秒级瞬间完成!)              │
            │                                                             │
            ├──────────── 3. 发送 [ 明文 M, 签名 S ] ────────────────────>│
            │                                                             │
            │                                                             ▼
            │                                                       4. Bob 独立计算明文的
            │                                                          散列摘要:
            │                                                          h1 = H(M)
            │                                                             │
            │                                                             ▼
            │                                                       5. Bob 用【Alice 的公钥 PK_A】
            │                                                          解密验签还原摘要:
            │                                                          h2 = E_{PK_A}(S)
            │                                                             │
            │                                                             ▼
            │                                                       6. 比对 h1 与 h2:
            │                                                          若 h1 == h2:
            │                                                          证明 Alice 亲笔签名且未篡改!
```

### 1. 签名与验签的时序闭环
1. **签名端（Alice）**：
   - 使用标准散列函数（如 SHA-256）对任意长度的明文 $M$ 进行散列，得到固定长度的摘要 $h = H(M)$；
   - 使用自己的**私钥 $SK_A$** 对摘要 $h$ 进行加密计算，生成数字签名 $S$；
   - 将原报文 $M$ 和数字签名 $S$ 捆绑发出。
2. **验签端（Bob）**：
   - 收到报文后，使用完全相同的散列函数对明文 $M$ 独立计算一份摘要 $h_1 = H(M)$；
   - 使用 Alice 的**公钥 $PK_A$** 对收到的签名 $S$ 执行解密运算，还原出 Alice 签名时的原始摘要 $h_2 = E_{PK_A}(S)$；
   - **比对判定**：
     - 若 $h_1 == h_2$：表明签名合法通过。这确凿证明了两件事：
       1. **真实性与不可抵赖**：该报文必定来自 Alice 本人，因为全网除了 Alice 没有任何人拥有对应的私钥 $SK_A$；
       2. **完整性**：报文在网络传输中绝对未被修改过，因为任何哪怕 1 位的改动都会导致 $h_1$ 发生雪崩巨变，使 $h_1 \ne h_2$。

## 四、报文鉴别码（MAC）vs 数字签名（Digital Signature）本质对比

| 对比维度 | 报文鉴别码 (MAC / HMAC) | 数字签名 (Digital Signature) |
|---|---|---|
| **底层核心机制** | **对称密钥体系** + 密码散列函数 | **公钥密钥体系** + 密码散列函数 |
| **密钥使用方式** | 双方共享同一个秘密密钥 $K$ | 签名方使用**私钥 $SK$**，验签方使用**公钥 $PK$** |
| **防篡改与完整性**| **支持**（无法在不知晓密钥下修改 MAC） | **支持**（篡改导致验签摘要不匹配） |
| **身份真实性鉴别**| 仅在**通信双方之间**可信 | **全网公信**（任何人只要持有公钥均可独立核验） |
| **抗抵赖性 (不可否认)**| **不支持**！双方均持有相同密钥，接收方无法向第三方仲裁机构证明不是自己伪造的。 | **绝对支持**！私钥仅发送方一人持有，具备极强的法律效力抗抵赖性。 |
| **计算执行开销** | **极低**（纯对称哈希运算，毫秒微秒级） | **较高**（涉及非对称模幂或大数乘法运算） |
| **典型适用场景** | 内部网络高速报文完整性鉴别（如 IPsec ESP/AH） | 软件防篡改发布、数字证书鉴权、比特币防双花交易 |
