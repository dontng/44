# 1.6.4 计算机网络体系结构中的专用术语

在深入学习计算机网络各层协议之前，必须严格厘清体系结构中所使用的一组高度抽象的基础学术概念与专用术语。这些术语界定了实体、协议、服务以及层级交互的标准语义。

---

## 一、实体、对等实体与协议

### 1. 实体（Entity）与对等实体（Peer Entities）
- **实体（Entity）**：任何可发送或接收信息的硬件或软件进程。在计算机网络分层模型中，实体通常指某个特定层次中活动的具体软件模块、硬件芯片或系统进程。
- **对等实体（Peer Entities）**：在不同系统的**同一层次**中进行通信交互的实体。
  例如：主机 A 的运输层 TCP 模块与主机 B 的运输层 TCP 模块互为对等实体；路由器 A 的 OSPF 路由进程与路由器 B 的 OSPF 进程互为对等实体。

### 2. 协议（Protocol）
- **定义**：为了进行网络中的对等实体数据交换而建立的规则、标准或约定的集合。
- **协议的三要素（极其核心的判定准则）**：
  1. **语法（Syntax）**：通信数据与控制信息的结构与格式。规定了传输的数据在二进制比特流中各字段的具体排布次序、字段长度及数据类型（即“怎么讲”、“格式是什么”）。
  2. **语义（Semantics）**：发出何种控制信息、完成何种动作以及做出何种响应。规定了首部中特定标志位或字段取值的具体含义（即“讲什么”、“含义是什么”）。
  3. **同步 / 时序（Timing）**：事件实现顺序的详细说明，包括通信双方动作应答的先后时序约束与速度匹配（即“何时讲”、“先后次序是什么”）。

```text
               主机 A (系统 1)                               主机 B (系统 2)
  ┌─────────────────────────────────────┐       ┌─────────────────────────────────────┐
  │ 第 n+1 层实体                        │       │ 第 n+1 层实体                        │
  └──────────────────┬──────────────────┘       └──────────────────▲──────────────────┘
            服务 (向下请求)    ▲ 服务 (向上提供)           服务 (向下请求)    ▲ 服务 (向上提供)
                     │        │                          │        │
  ┌──────────────────▼────────┴─────────┐  对等协议通信  ┌────────▼────────┴─────────┐
  │ 第 n 层实体                          │ < - - - - - > │ 第 n 层实体                          │
  └─────────────────────────────────────┘ (逻辑上的水平交互)└─────────────────────────────────────┘
```

## 二、协议与服务的本质区别与关联

“协议”与“服务”是分层体系结构中最容易混淆但具有根本区别的一对核心概念：

| 比较维度 | 协议（Protocol） | 服务（Service） |
|---|---|---|
| **交互方向** | **水平方向（Horizontal）** | **垂直方向（Vertical）** |
| **交互对象** | 不同机器上的**对等实体之间** | 同一节点内**相邻上下两层之间** |
| **透明性** | 对上层是**完全透明（不可见）**的 | 对上层是**直接可见且可调用**的 |
| **实现与本质** | 是控制两个对等实体进行逻辑通信的规则集合 | 是下层实体通过层间接口向相邻上层实体提供的功能能力集合 |

- **深度辨析**：
  - 本层的协议是本层为实现自身功能而与对端实体达成的约定；只要对上层提供的服务接口不变，本层协议的内部替换（例如将路由协议 RIP 替换为 OSPF）对上层实体完全透明无感；
  - 只有在第 $n$ 层协议的有效支撑下，第 $n$ 层才能向第 $n+1$ 层提供服务；
  - 第 $n$ 层实体不仅使用了相邻下层（第 $n-1$ 层）所提供的服务，还借助本层的对等协议，在此基础上叠加新能力，最终向相邻上层（第 $n+1$ 层）提供更高级的服务。

## 三、服务访问点（SAP）与接口数据单元

在垂直层级交互中，相邻层之间通过标准化的概念模型进行信息交换：

```text
  第 n+1 层实体
        │
        ▼ (通过 SAP 服务访问点调用服务)
  ───[ SAP ]────────────────────────────── (层间逻辑接口边界)
        │
  第 n 层实体
```

### 1. 服务访问点（Service Access Point, SAP）
- **定义**：同一系统内相邻两层的实体进行交互（即第 $n$ 层向第 $n+1$ 层提供服务）的**逻辑接口物理或逻辑标识**。
- **典型层级的服务访问点实例**：
  - **物理层的 SAP**：物理接口的引脚与插座（如 RJ-45 接口的电气触点）；
  - **数据链路层的 SAP**：逻辑链路控制子层（LLC）的 SAP，或直接表现为网络适配器的 **MAC 地址**；
  - **网络层的 SAP**：**IP 地址** 或 网络协议类型字段（标识上层是 TCP 还是 UDP）；
  - **运输层的 SAP**：**端口号（Port Number）**（应用进程与网络协议栈的交付边界）；
  - **应用层的 SAP**：用户界面或应用程序名。

### 2. SDU、PCI 与 PDU 的数学与结构关系
- **服务数据单元（SDU, Service Data Unit）**：
  相邻上层实体为完成某一任务而递交给相邻下层实体的**原始数据载荷**。第 $n$ 层的 SDU 即为第 $n$ 层需要传输的净荷（Payload）。
- **协议控制信息（PCI, Protocol Control Information）**：
  第 $n$ 层对等实体为了协调本层协议操作而添加的**本层专属控制首部或尾部**。
- **协议数据单元（PDU, Protocol Data Unit）**：
  第 $n$ 层对等实体之间通过网络实际交换的**完整数据块**。
- **三者结构关系公式**：
  $$n\text{-PDU} = n\text{-PCI} + n\text{-SDU}$$
  同时，在垂直层级传递时，本层生成的完整 PDU，将作为相邻下层的 SDU 直接交付：
  $$(n-1)\text{-SDU} = n\text{-PDU}$$

```text
  第 n 层:       ┌───────────┐
                 │  n-SDU    │ (来自上层的数据)
                 └─────┬─────┘
                       ▼
                 ┌───────────┬───────────┐
                 │  n-PCI    │  n-SDU    │  =  n-PDU (第 n 层的协议数据单元)
                 └───────────┴───────────┘
                       │
                       ▼ 整体下传作为下一层载荷
  第 n-1 层:     ┌───────────────────────┐
                 │       (n-1)-SDU       │
                 └───────────┬───────────┘
                             ▼
                 ┌───────────┬───────────────────────┐
                 │ (n-1)-PCI │       (n-1)-SDU       │  =  (n-1)-PDU
                 └───────────┴───────────────────────┘
```

## 四、网络服务的核心分类维度

计算机网络所提供的服务可以从多个维度进行分类划分：

### 1. 面向连接服务 vs 无连接服务
- **面向连接服务（Connection-Oriented Service）**：
  - 通信过程严格划分为三个独立阶段：**建立连接 $\to$ 传输数据 $\to$ 释放连接**；
  - 数据传输期间，通信双方建立并维护专有的状态记录（如 TCP 的三次握手与四次挥手）；
  - 能够提供可靠的保序传输保证；通信结束后必须显式拆除连接。
  - *典型实例*：运输层的 **TCP 协议**。
- **无连接服务（Connectionless Service）**：
  - 通信前**无需预先建立连接**；数据随时可以直接组装并独立发出；
  - 每一个数据单元都携带完整的目的地址信息，被网络独立路由转发（尽力而为交付）；
  - 传输可能发生乱序、丢失或重复，通信双方在网络底层不维持状态记录。
  - *典型实例*：网际层的 **IP 协议**、运输层的 **UDP 协议**。

### 2. 可靠服务 vs 不可靠服务
- **可靠服务（Reliable Service）**：
  - 网络系统具有内在的检错、确认和重传机制，能够向上层绝对保证数据的正确性、完整性和顺序性（“不丢、不错、不重、不乱”）。
  - *典型实例*：TCP 协议。
- **不可靠服务（Unreliable / Best-Effort Service）**：
  - 网络系统不保证数据一定能够送达，也不保证送达顺序，一旦发生差错或拥塞，数据可能直接被丢弃且网络层不负责重发（重发由高层应用或高层传输协议按需实现）。
  - *典型实例*：IP 协议、以太网 MAC 帧传输。

### 3. 有应答服务 vs 无应答服务
- **有应答服务（Acknowledged Service）**：
  - 接收端在正确收到每个数据单元后，必须向发送端显式返回一个确认应答（ACK）。若发送端在规定时间内未收到应答，将自动触发重传。
  - *典型实例*：停止-等待协议、TCP 确认机制。
- **无应答服务（Unacknowledged Service）**：
  - 接收端收到数据后不返回任何确认应答。若数据在传输过程中发生损坏或丢失，发送端无从知晓。
  - *典型实例*：普通的以太网数据帧传输、UDP 数据报传输。
