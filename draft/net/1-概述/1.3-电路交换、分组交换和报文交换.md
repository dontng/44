# 1.3 电路交换、分组交换和报文交换

网络核心（Network Core）的主要功能是通过网络交换技术实现数据的跨节点传递。在计算机网络演进过程中，先后出现了**电路交换**、**报文交换**与**分组交换**三种截然不同的数据交换方式。

---

## 一、电路交换（Circuit Switching）

电路交换是传统电信电话网络（PSTN）的核心工作模式。

```text
  [ 发送端 A ] ───(1. 呼叫建立物理通路)───> [ 交换机 1 ] ───> [ 交换机 2 ] ───> [ 接收端 B ]
  [ 发送端 A ] <───(2. 专用独占信道传输数据: 比特流直通，零中间排队!)──────> [ 接收端 B ]
  [ 发送端 A ] ───(3. 释放拆除连接连接)───> [ 交换机 1 ] ───> [ 交换机 2 ] ───> [ 接收端 B ]
```

### 1. 三个必经阶段
1. **建立连接（呼叫建立）**：在发送数据前，必须通过信令在发送端与接收端之间寻找一条物理路径，并为该通信**静态预留专用的传输信道与频带资源**；
2. **数据传输**：在连接期间，该物理通路被通信双方**独占使用**，传输全程如同通过一根直通铜线，数据无排队延迟；
3. **释放连接（拆除链路）**：通信结束后，释放信道资源，供其他用户重新申请使用。

### 2. 电路交换的本质优缺点
- **优点**：
  - **传输时延极小且恒定**：一旦通路建立，中间节点无缓冲排队；
  - **独占物理带宽**：通信双方完全不受网络中其他用户流量的干扰，实时性强。
- **致命缺点（为什么不适合计算机通信？）**：
  - **建立连接耗时极长**：计算机网络交互通常是极短的突发请求，建立连接的时间往往远超数据传输本身；
  - **信道利用率极其低下**：计算机通信具有高度的**突发性（Bursty）**（例如用户浏览网页时大部分时间在阅读，信道处于空闲状态）。电路交换采用专占信道，空闲时信道资源被白白闲置，严禁其他节点复用。

## 二、报文交换（Message Switching）

报文交换（又称存储-转发交换）是电报通信的早期产物。
- **工作机制**：
  - 通信双方在发送数据前**无需预先建立连接**；
  - 发送端将用户的完整数据（如整篇电报长文）作为一个整体，加上源地址和目的地址封装为一个完整的**报文（Message）**；
  - 报文以“存储-转发（Store-and-Forward）”的方式在中间交换节点之间逐跳转发：中间节点必须**先完整接收并缓存整个报文**，经过校验和查表路由后，再寻找下一跳空闲链路整体转发出去。
- **缺点**：报文长度没有上限约束。中间节点必须配备巨大的磁盘/内存缓冲空间；若传输中途发生 1 位比特差错，整个长报文必须全盘重传；排队延迟极大。**现已基本被淘汰**。

---

## 三、分组交换（Packet Switching，因特网的灵魂）

为了兼顾“无连接高效动态复用”与“极短时延和极小缓存开销”，因特网全面确立了 **分组交换（Packet Switching）** 架构。

```text
  原始长报文: [              海量应用层连续数据 (如 10 MB 文件)              ]
                     │
                     ▼ (在源端主机被切分成固定长度的短数据块，并附加首部)
  分组 1: [ 首部 H ] [ 数据块 1 ] ──> 独立发送
  分组 2: [ 首部 H ] [ 数据块 2 ] ──> 独立发送
  分组 3: [ 首部 H ] [ 数据块 3 ] ──> 独立发送
```

### 1. 分组交换的核心工作时序
1. **源端分包（Packetizing）**：发送端将较长的报文划分成一个个长度较小、受严格上限约束（如 1500 字节）的数据段，并在每个数据段前加上包含目的地址等控制信息的**首部（Header）**，构造成**分组（Packet，又称包）**；
2. **存储-转发（Store-and-Forward）**：
   - 路由器收到分组后，先将其存入快速内存缓存中；
   - 路由器仅需检查首部中的目的 IP 地址，查转发表确定下一跳；
   - 随后立即将该小分组通过出端口转发出去；
3. **目的端重组**：各个分组在网络中可能走不同路径甚至乱序到达，目的端主机根据首部中的序号重新拼接还原出原始长报文。

### 2. 为什么分组交换优于报文交换？
- **并行流水线传输（Pipeline）**：因为每个分组极短，当一个节点正在转发前一个分组时，前序节点可以同时向其发送后续分组，实现了端到端链路的**高度流水线并行化**，总端到端传输时延远小于报文交换；
- **交换机内存要求极低**：节点只需微小的半导体 RAM 缓存即可容纳若干小分组，实现极速硬件查表转发；
- **差错重传代价极小**：传输中发生差错时，只需重传发生差错的那一个几百字节的小分组，无需重传整个大报文。

## 四、电路交换、报文交换与分组交换全景对比

```text
  [电路交换]                 [报文交换]                 [分组交换 (流水线重叠!)]
  呼叫建立时延                源节点发送整报文           源节点切片流水发送
  │                           │                          │ p1 │ p2 │ p3 │
  ▼                           ▼                          ▼    ▼    ▼
  专有链路直通传输            节点 A 接收整报文并暂存    节点 A 并行流水转发
  │                           │                          │ p1 │ p2 │ p3 │
  ▼                           ▼                          ▼    ▼    ▼
  拆除释放时延                节点 B 接收整报文并暂存    节点 B 并行流水转发
                              │                          │ p1 │ p2 │ p3 │
                              ▼                          ▼    ▼    ▼
                              目的节点完整接收           目的节点接收重组
```

| 评估维度 | 电路交换 (Circuit Switching) | 报文交换 (Message Switching) | 分组交换 (Packet Switching) |
|---|---|---|---|
| **建立连接** | **必须建立**（经历建立、传输、释放三阶段） | **无连接** | **无连接**（数据报模式） |
| **信道分配机制** | **静态预留独占**（信道空闲时禁止复用） | **动态分时复用**（按报文排队抢占） | **统计多路复用（Statistical Multiplexing）** |
| **中间节点缓冲** | **零缓冲**（数据物理直通） | **大容量外存/磁盘**（需缓存整份长报文） | **极小快速高速 RAM**（仅需缓存单个短分组） |
| **传输时延** | 建立连接时延大；传输中**节点排队时延为零** | **时延极大且波动剧烈**（排队逐跳串行等待） | **时延极小**（流水线重叠转发，响应迅速） |
| **差错重传开销** | 链路层无检错（交由端系统） | 发生差错必须**全报文重传** | 仅需**单独重传出错的分组** |
| **突发数据适应** | **极差**（严重浪费网络物理带宽） | 较好 | **极优**（因特网弹性自适应架构基石） |
