# 1.6.1 常见的三种计算机网络体系结构

计算机网络体系结构（Network Architecture）是计算机网络的各层及其协议的集合，是网络在功能结构和交互规则上的精确定义。当前计算机网络领域最核心的三种参考体系结构为：**OSI 七层参考模型**、**TCP/IP 四层体系结构**以及**五层原理体系结构**。

---

### 1. 体系结构的提出背景
- **OSI / RM（Open Systems Interconnection Reference Model）**：国际标准化组织（ISO）在 1980 年代提出的开放系统互连参考模型，旨在建立一个全球完全统一的计算机网络开放标准。
- **TCP/IP 体系结构**：由美国国防部高级研究计划局（DARPA）为 ARPANET 设计，伴随 Unix 操作系统的广泛推广与学术界/工业界的实践迭代，最终成为全球互联网通用的**事实工业标准（De Facto Standard）**。
- **五层原理体系结构**：学术界和教材（如谢希仁《计算机网络》、Tanenbaum《计算机网络》）为阐述网络底层通信细节而采用的折中教学模型。由于 TCP/IP 体系结构对底层（网络接口层）缺乏细致分层，而 OSI 的物理层和数据链路层在教学上极具理论价值，因而将 TCP/IP 顶层与 OSI 底层有机结合，形成了五层教学模型。

## 二、OSI 七层参考模型功能详解

OSI 模型自底向上定义了清晰的七个抽象层级：

| 层级 | 层名称 | 英文 | 核心职责与传输实体 | 典型功能与协议机制 |
|:---:|---|---|---|---|
| **7** | **应用层** | Application Layer | 为用户的应用程序提供网络服务接口 | 定义应用程序间通信的规则与语义，直接面向业务应用（如 HTTP, FTP, DNS, SMTP） |
| **6** | **表示层** | Presentation Layer | 处理两个通信系统间信息交换的表示方式 | 负责**数据格式转换、数据加密/解密、数据压缩/解压缩**，确保异构系统能正确解析语义 |
| **5** | **会话层** | Session Layer | 管理不同机器上进程之间的会话建立与维护 | 建立、管理和终止**会话进程（Session）**，支持插入同步点（Checkpoints）以实现断点续传 |
| **4** | **运输层** | Transport Layer | 提供端到端（进程到进程）的可靠/不可靠通信 | 负责进程级通信寻址（端口号）、端到端差错控制、流量控制与拥塞控制（TCP, UDP） |
| **3** | **网络层** | Network Layer | 负责将分组从源节点经中间路径路由转发到宿节点 | 提供逻辑地址寻址（IP 地址）、分组路由选择（路由算法）、拥塞控制与异构网络互联 |
| **2** | **数据链路层**| Data Link Layer | 将网络层交下的 IP 数据报组装成帧并在相邻节点间无差错传输 | 节点间成帧、硬件地址寻址（MAC）、物理信道差错检测与纠正、介质访问控制（CSMA/CD） |
| **1** | **物理层** | Physical Layer | 在物理传输介质上传输原始比特流 | 定义机械、电气、功能和规程特性，完成比特流与物理信号（光电脉冲）之间的转换 |

## 三、各层数据交换单元的专有名词（PDU / 数据单元）

在不同的协议层级中，流经该层的数据单位具有极其严格的标准称谓：

| 层次 | 协议数据单元（PDU）称谓 | 英文规范简称 | 组成构成 |
|:---:|---|---|---|
| **应用层** | **应用协议数据单元 / 报文** | **APDU (Message)** | 应用层产生的纯数据载荷或带有应用协议头的报文 |
| **表示层** | **表示协议数据单元** | **PPDU** | 经表示层格式编码/加密后的数据单元 |
| **会话层** | **会话协议数据单元** | **SPDU** | 包含会话同步信息的数据单元 |
| **运输层** | **报文段 / 用户数据报** | **TPDU (Segment / Datagram)** | TCP 中称为**报文段（Segment）**；UDP 中称为**用户数据报（Datagram）** |
| **网络层** | **IP 数据报 / 分组** | **Packet / IP Datagram** | 加上 IP 首部的网络层传输单位，通用称谓为**分组（Packet）** |
| **数据链路层** | **帧** | **Frame** | 包含帧首部（MAC 地址等）、数据载荷及帧尾部（CRC 校验）的单元 |
| **物理层** | **比特** | **Bit** | 物理介质上传输的单个 $0$ 或 $1$ 信号 |

## 四、TCP/IP 四层体系结构及其工业胜利原因

### 1. TCP/IP 四层架构组成
1. **应用层**：包含所有高层协议（HTTP, DNS, FTP, SMTP, SSH 等），将 OSI 的表示层和会话层功能全部收归应用程序内部自行实现。
2. **运输层**：提供通用的端到端传输服务，主要包括面向连接的可靠传输协议 **TCP** 和无连接的尽力而为传输协议 **UDP**。
3. **网际层（IP 层）**：核心是 **IP 协议**。网际层不提供可靠传输保证，向上仅提供**灵活简捷、无连接、尽力而为（Best-Effort）交付**的数据报服务，从而使网络核心路由器无需维持复杂的状态信息。
4. **网络接口层**：负责利用具体的物理网络硬件（如以太网、Wi-Fi、光纤信道）传输上一层的 IP 数据报。TCP/IP 并没有对底层制定专有协议，而是允许接入几乎所有现存的物理链路技术（“沙漏模型”）。

```text
                    【TCP/IP 的“沙漏”模型】
      HTTP     FTP     DNS     SMTP     SSH     RTP ...  (丰富的应用)
         \      │       │       │       /
          \     ▼       ▼       ▼      /
           ┌────────────────────────┐
           │       TCP  /  UDP      │                  (通用运输层)
           ├────────────────────────┤
           │      网际层 (IP)       │  <── 瓶颈核心 (统一互联一切)
           ├────────────────────────┤
           │     网络接口层         │
           └────────────────────────┘
          /     │       │       │      \
     以太网   Wi-Fi    光纤    蜂窝4G/5G  点对点专线 ...  (多元的物理技术)
```

### 2. 为什么 OSI 七层模型在工业竞争中失败？
尽管 OSI 参考模型在概念结构上极其完整严密，但在实际商业竞争中彻底败给 TCP/IP，工程界常将其归结为以下核心缺陷：
- **专家主导与脱离工程实际**：OSI 标准制定周期极其漫长，缺乏实用软件实现配合；而 TCP/IP 伴随开源软件与实际网络运行同步演进（“Running Code and Rough Consensus”）。
- **层次划分重叠与冗余**：OSI 的表示层和会话层在大多数网络应用中显得多余，而流量控制、差错控制和寻址功能在数据链路层、网络层和运输层均被重复实现，协议开销过大。
- **协议实现极其复杂低效**：OSI 协议栈占用内存大、执行效率低，难以在当时受限的硬件计算能力下高效运行。
- **核心哲学分歧（端到端原则）**：
  - OSI 倾向于在网络内部实现极其复杂的控制与保证机制；
  - TCP/IP 贯彻了**端到端原则（End-to-End Principle）**，坚持将智能与复杂状态控制推向**网络边缘的主机**，而让**网络核心（路由器）保持极简**，仅负责无连接的高速分组转发。这种设计极大地降低了核心网部署成本，具备惊人的网络互联弹性与横向扩展能力。
