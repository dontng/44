# 5.1.1 进程间基于网络的通信


## 一、为什么网络层之上必须设立运输层？

在计算机网络体系结构中，网络层（IP 协议）提供了将 IP 数据报从源主机跨越多个异构网络路由投递至目的主机的能力。

然而，仅有网络层无法直接满足现代多任务分布式操作系统的通信需求：
1. **通信的真正主体是进程，而不是物理主机**：
   - 一台运行现代多任务操作系统的主机，往往同时并发运行着数十甚至上百个网络应用（如浏览器 HTTP 客户端、微信客户端、SSH 终端、邮件拉取进程等）；
   - IP 协议的数据报首部中只包含源 IP 地址和目的 IP 地址，只能将报文送达目标物理网卡和主机操作系统；
   - 一旦报文抵达目的主机，操作系统若仅凭 IP 首部，无法获知该数据究竟应提交给哪一个正在等待接收的应用进程。
2. **底层不可靠网络的屏蔽与功能增强**：
   - 网络层（IP 协议）提供的是“尽最大努力交付（Best-Effort）”的无连接、不可靠数据报服务，可能发生分组丢失、乱序、重复及拥塞；
   - 不同的上层应用对通信质量的要求截然不同：文件传输（FTP）和网页浏览（HTTP）要求绝对无差错且保序；实时语音和视频会议则对传输时延极度敏感，但能容忍极少量的丢包；
   - 运输层作为操作系统的核心协议栈组件，向上屏蔽了底层物理通信网络的异构细节与不可靠性，根据应用需求提供差异化的端到端逻辑通信服务。

```text
+=================================================================================+
|  应用层 (Application Layer)  : [进程 P1] [进程 P2] [进程 P3] ... [进程 Pn]      |
+=================================================================================+
                                        ▲
                       端到端通信       │ 运输层提供的
                    (进程到进程逻辑通信)│ 进程间逻辑通道
                                        ▼
+=================================================================================+
|  运输层 (Transport Layer)    : 提供端口寻址、复用分用、可靠/不可靠传输控制      |
+=================================================================================+
                                        ▲
                       主机到主机通信   │ 网络层提供的
                    (物理节点间路由互联)│ 主机间数据报投递
                                        ▼
+=================================================================================+
|  网络层 (Network Layer)      : IP 协议 (仅识别主机 IP 地址)                     |
+=================================================================================+
```

## 二、主机到主机 vs 进程到进程（端到端通信的本质）

计算机网络体系严格区分网络层与运输层的服务边界：

| 评估维度 | 网络层 (Host-to-Host) | 运输层 (Process-to-Process / End-to-End) |
|---|---|---|
| **通信服务对象** | **两台主机之间**的物理/逻辑连通 | **两台主机上的两个具体应用进程之间** |
| **寻址识别标识** | **IP 地址** (32 位 IPv4 / 128 位 IPv6) | **端口号 (Port Number)** (16 位整数) |
| **设备涉及范围** | 源主机、沿途所有路由器、目的主机 | **仅存在于两端的主机操作系统内部** (路由器不感知运输层) |
| **差错检测范围** | 仅校验网络层首部 (IPv4 检验和已在 IPv6 废除) | 覆盖**运输层首部 + 应用层数据载荷** (端到端全校验) |
| **通信逻辑信道** | 尽最大努力交付的不可靠分组信道 | 可靠的全双工字节流信道 (TCP) 或不可靠的数据报信道 (UDP) |

- **“端到端（End-to-End）”的物理真实含义**：
  - 沿途的所有中间交换节点（如以太网交换机、路由器）其最高处理层级仅到数据链路层或网络层；
  - 只有通信两端的终端设备（主机、服务器、手机）的操作系统内核中才完整运行运输层协议栈；
  - 运输层为应用层呈现的，仿佛是一条直接横跨在两个通信进程之间的、排他的“逻辑通信信道（Logical Channel）”。

## 三、网络通信端点抽象：套接字（Socket）

在操作系统内核中，进程本身是由进程标识符（PID）唯一标识的。但不同操作系统的 PID 分配机制不同，且进程是动态创建和销毁的，不能直接用 PID 进行跨网络的全局寻址。

为了统一描述跨网络的进程间通信，计算机网络与操作系统引入了**套接字（Socket）**抽象：

### 1. 套接字的构成
在 TCP/IP 体系中，一个网络通信端点由 **IP 地址** 与 **端口号** 联合绑定唯一确定：
$$\text{套接字 (Socket)} = (\text{IP 地址} : \text{端口号})$$

### 2. 端到端通信五元组（5-Tuple）
在互联网中，任意一条全双工连接（如 TCP 连接）在网络中必须由一个唯一的**五元组**全局标识：
$$\text{连接标识} = \{\text{源 IP}, \text{源端口}, \text{目的 IP}, \text{目的端口}, \text{传输层协议类型 (TCP/UDP)}\}$$
- 只要五元组中有一个元素不同，操作系统即可将其精确区分为不同的通信会话，从而允许多个网络客户端同时并发访问同一台 Web 服务器的同一个 80 端口而互不干扰。
