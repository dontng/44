# 5.1.2 TCP-IP体系结构运输层中的两个重要协议


## 一、运输层两大核心协议的设计分工

在 TCP/IP 体系结构中，运输层定义了两个地位截然不同、功能高度互补的协议：
1. **用户数据报协议（UDP，User Datagram Protocol，RFC 768）**；
2. **传输控制协议（TCP，Transmission Control Protocol，RFC 793）**。

网络层统一采用单一的 IP 协议，而运输层之所以提供两个截然相反的协议，根源在于**网络应用对可靠性、传输时延与控制开销的多样化诉求**。

```text
+=================================================================================+
|  应用层 (Application Layer)                                                     |
|    - DNS, TFTP, SNMP, DHCP, 实时音视频     - HTTP, HTTPS, FTP, SMTP, POP3, SSH  |
+=========================================+=======================================+
                    │                                         │
                    ▼ (追求极简、低时延)                      ▼ (追求可靠、保序、无差错)
+=========================================+=======================================+
|  【用户数据报协议 UDP】                 |  【传输控制协议 TCP】                 |
|    - 无连接 (Connectionless)            |    - 面向连接 (Connection-Oriented)   |
|    - 不可靠 (尽最大努力交付)            |    - 可靠交付 (无差错、不丢失、不重复)|
|    - 面向报文 (保留应用层边界)          |    - 面向字节流 (流式传输，无记录边界)|
|    - 无拥塞控制，开销极小 (8 字节首部)  |    - 流量控制 + 拥塞控制 (20 字节首部)|
+=========================================+=======================================+
                                        ▲
                                        │ 统一封装于 IP 数据报载荷
                                        ▼
+=================================================================================+
|  网络层 (Network Layer) : IP 协议 (协议字段: UDP=17, TCP=6)                     |
+=================================================================================+
```

## 二、UDP 与 TCP 的根本服务哲学剖析

### 1. 用户数据报协议（UDP）
- **极简主义哲学**：UDP 几乎只是在 IP 协议之上增加了两项最基本的增值服务——**端口寻址（复用与分用）** 以及 **端到端差错检测（UDP 校验和）**。
- **核心机制特征**：
  1. **无连接**：发送数据之前无需经过握手建立连接，数据传输完毕也无需释放连接，直接将报文送交下层网卡发送，零握手时延；
  2. **不可靠**：不保证数据报一定送达目的端，不保证数据报按发送顺序到达，也不维护任何重传机制；
  3. **面向报文**：应用层交给 UDP 多长的报文，UDP 照样封装发送，保留应用层报文边界，既不合并也不拆分；
  4. **无拥塞控制与流量控制**：主机网络协议栈不限制 UDP 发送速率。网络发生严重拥塞时，UDP 仍以原速率向网络注入数据包（这对实时音视频非常关键，因为宁可丢掉几帧，也不能为了重传而引入数秒的缓冲时延）；
  5. **开销极低**：首部仅固定为 **8 字节**，网络吞吐效率极高。

### 2. 传输控制协议（TCP）
- **完美可靠主义哲学**：在底层完全不可靠的 IP 网络之上，通过极其严密的控制算法，向应用层提供绝对可靠、保序、无差错、无重复的端到端数据传输。
- **核心机制特征**：
  1. **面向连接**：数据通信前必须通过“三次握手”建立逻辑连接，传输结束必须通过“四次挥手”释放连接并回收系统资源；
  2. **每一条 TCP 连接只能是点对点的（一对一通信）**：不支持一对多（多播/广播）通信；
  3. **可靠交付**：通过序号机制、累计确认机制、超时重传定时器以及快速重传算法，保证传输数据无差错、不丢失、不重复且按序到达；
  4. **全双工通信（Full-Duplex）**：连接两端均设有发送缓存与接收缓存，双方可同时双向独立发送数据；
  5. **面向字节流（Byte Stream）**：TCP 不感知应用层报文的逻辑边界。TCP 将应用层数据视为一连串无结构的 8 位字节序列，根据当前接收窗口大小与拥塞窗口大小，自主将字节流动态分块封装为不同长度的 TCP 报文段发送；
  6. **内置流量控制与拥塞控制**：通过滑动窗口协议动态防止接收方缓冲区溢出；通过慢开始、拥塞避免、快重传、快恢复四阶段状态机动态防止网络核心路由器拥塞崩溃；
  7. **开销较大**：最小首部为 **20 字节**，加上选项最大可达 60 字节，协议状态机复杂，内存与 CPU 资源开销显著高于 UDP。

## 三、常见应用层协议的传输层协议绑定关系

常见应用层协议根据其业务特征，与下层传输层协议的绑定关系如下：

| 应用层协议 | 英文全称 | 传输层协议 | 默认端口号 | 选用传输层协议的工程底层原因 |
|---|---|:---:|:---:|---|
| **DNS** | 域名系统 | **UDP** *(主)* / TCP | 53 | 域名解析查询仅需单次请求/应答交互，UDP 避免了三次握手时延；仅在区域传送（主从同步）或报文大于 512B 时使用 TCP |
| **DHCP** | 动态主机配置协议 | **UDP** | 67 (服务端) / 68 (客户端) | 主机尚未配置 IP 地址，无法建立 TCP 连接；需借助 UDP 广播收发报文 |
| **TFTP** | 简单文件传送协议 | **UDP** | 69 | 运行于系统引导（PXE/ROM）环境，代码体积受限，UDP 极简且在应用层自行实现停止-等待可靠性 |
| **SNMP** | 简单网络管理协议 | **UDP** | 161 (Agent) / 162 (Trap) | 网络故障或严重拥塞时，必须避免 TCP 繁琐的握手重传开销，确保警报报文能以最高概率发出 |
| **RTP / RTSP** | 实时传输协议 | **UDP** | 动态分配 | 实时音视频通信，强时延敏感弱丢包敏感，无法承受 TCP 超时重传引入的卡顿延迟 |
| **HTTP / HTTPS** | 超文本传输协议 | **TCP** | 80 (HTTP) / 443 (HTTPS) | 网页数据、样式表与脚本要求内容 100% 准确完整，绝不允许数据比特丢失或乱序 |
| **FTP** | 文件传送协议 | **TCP** | 21 (控制) / 20 (数据) | 大文件传输要求数据绝对完整保序，必须依靠 TCP 的强可靠性交付 |
| **SMTP / POP3 / IMAP** | 电子邮件传输协议 | **TCP** | 25 (SMTP) / 110 (POP3) | 电子邮件正文与附件属于严肃文本与二进制数据，不能承受任何数据丢失 |
| **SSH / Telnet** | 远程登录协议 | **TCP** | 22 (SSH) / 23 (Telnet) | 远程终端管理指令与输出必须绝对精准保序执行 |
| **BGP** | 边界网关协议 | **TCP** | 179 | 跨自治系统路由器间交换路由表庞大且关键，利用 TCP 长连接提供点对点可靠性 |
