# 5.3.8 TCP的选择确认


## 一、传统累计确认的缺陷与重传代价

在标准的 TCP 协议中，确认机制是**累计确认（Cumulative Acknowledgment）**：
- 确认号（ack）指示的是**期望收到的下一个连续字节序号**，代表该序号之前的所有字节均已完整收齐；
- **痛点场景（跳跃丢包）**：
  - 假设发送方连续发送了 5 个报文段（序号依次为 $1 \sim 1000$、$1001 \sim 2000$、$2001 \sim 3000$、$3001 \sim 4000$、$4001 \sim 5000$）；
  - 其中第二个报文段（$1001 \sim 2000$）在网络中丢失，但其余 4 个报文段全部完好无损地到达接收方；
  - **接收端状态**：虽然接收方缓存中已经完整保存了 $2001 \sim 5000$ 这 3000 个字节的数据，但由于前面存在 $1001 \sim 2000$ 的空洞，接收方回送的 ACK 中**确认号只能死死填为 1001**；
  - **发送端困境**：发送方只知道 1001 丢失了，无法获知后面的 $2001 \sim 5000$ 是否已经被接收端保存。
- **两难妥协**：
  - 若发送方仅重传 $1001 \sim 2000$，每收到一个确认再重传下一个，恢复速度极慢；
  - 若发送方像 GBN 一样盲目重传 1001 之后的所有报文段，则造成了巨大的网络带宽浪费，重复发送了接收方早已拥有的数据。

---

## 二、选择确认（SACK）的核心思想

为了解决上述问题，RFC 2018 引入了 **选择确认机制（SACK，Selective Acknowledgment）**：
- **基本思路**：
  - 正常的确认号（ack）依然保持累计确认的语义不变（依然报告缺失的第一个字节序号）；
  - 同时，在 TCP 首部的 **可变选项（Options）** 字段中，额外通告若干个由不连续块组成的**已正确接收的数据块的左右边界**；
- **发送端收益**：
  - 发送方收到带有 SACK 选项的报文后，能够精确获知哪些数据段已经安全抵达接收方缓冲区，哪些数据段在网络中丢失；
  - 发送方**仅精准重传真正缺失的那些数据段（空洞部分）**，极大节省了网络带宽，显著加速了长肥网络下的丢包恢复。

```text
 字节序号流:  [ 1 ~ 1000 ]  [ 1001 ~ 2000 ]  [ 2001 ~ 3000 ]  [ 3001 ~ 4000 ]  [ 4001 ~ 5000 ]
 接收状态  :   已收到确认       【丢失!】        已缓存暂存        已缓存暂存        已缓存暂存
 
 SACK 回送 :  ACK 确认号 = 1001 (常规累计确认)
             首部 SACK 选项: [ 左边界 = 2001, 右边界 = 5001 ]
 
 发送端动作:  【精准仅重传 1001 ~ 2000】，不重复发送 2001 ~ 5000!
```

## 三、SACK 选项的微观格式与边界记录

### 1. 左右边界的定义规范
每个未按序到达的孤立数据块由一对边界描述：
- **左边界（Left Edge）**：该不连续数据块中**第一个字节的序号**；
- **右边界（Right Edge）**：该不连续数据块中**最后一个字节的序号加 1**（即该数据块之后紧跟的第一个未收到字节序号）。
- *例如*：收到了字节 $2001 \sim 3000$，则左边界填入 2001，右边界填入 3001。

### 2. SACK 块数量的数学极限（机制深度剖析）
TCP 首部的选项字段最大长度为 **40 字节**：
- **SACK 选项的首部开销**：
  - 选项类型字段（Kind = 5）：占 1 字节；
  - 选项长度字段（Length）：占 1 字节；
  - 选项自身固定开销共占 **2 字节**。
- **剩余可用空间**：$40 - 2 = \mathbf{38 \text{ 字节}}$。
- **单个 SACK 块的开销**：
  - 每个边界是一个 32 位的序号，占 4 字节；
  - 一个 SACK 块包含一个左边界和一个右边界，共占用 $4 + 4 = \mathbf{8 \text{ 字节}}$。
- **最多可容纳的 SACK 块数量推导**：
  $$\text{最大 SACK 块数} = \left\lfloor \frac{38}{8} \right\rfloor = \mathbf{4 \text{ 块}} \quad (4 \times 8 = 32 \le 38)$$
- **携带时间戳选项时的特殊情况**：
  - 若 TCP 连接同时启用了常用的**时间戳选项（Timestamp Option，占 10 字节）**；
  - 则剩余给 SACK 的空间为 $40 - 10 - 2 = 28$ 字节；
  - 此时最多只能容纳：$\left\lfloor \frac{28}{8} \right\rfloor = \mathbf{3 \text{ 块}}$ SACK 块。
