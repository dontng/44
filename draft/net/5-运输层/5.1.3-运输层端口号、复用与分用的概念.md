# 5.1.3 运输层端口号、复用与分用的概念

> **408 考纲地位**：**运输层核心寻址机制与数据分流模型（选择题必考送分/细节题）**。深入考查：**端口号（Port Number）的硬件无关性与软件抽象**、**16 位端口号的三大划分区间（熟知端口 0~1023、登记端口 1024~49151、短暂/动态端口 49152~65535）**、**发送端复用（Multiplexing）与接收端分用（Demultiplexing）的微观时序**、**无连接分用（UDP 二元组匹配）vs 面向连接分用（TCP 四元组匹配）的本质区别**。

---

## 一、端口号的概念与软件寻址抽象

### 1. 为什么不能直接使用操作系统进程号（PID）？
在单机操作系统中，每个运行的程序由操作系统分配一个唯一的**进程标识符（PID）**：
- **痛点一：操作系统异构性**：Linux、Windows、macOS 以及各类嵌入式 RTOS 的进程号管理机制各不相同（如 Windows 的 PID 格式与 Linux 的整数范围不同）；
- **痛点二：动态随机性**：主机重启或服务进程重新启动后，操作系统分配给该服务的 PID 会发生变化。远端客户端不可能事先预测服务端的实时 PID；
- **解决方案**：TCP/IP 体系引入了与具体操作系统实现无关的**软件抽象概念——协议端口号（Protocol Port Number，简称为端口）**。

### 2. 端口的本质
- 端口是一个 16 位的无符号整数（取值范围为 $0 \sim 65535$）；
- 端口在操作系统内核中表现为**与特定网络通信缓冲区绑定的抽象接口**；
- 应用进程通过系统调用（如 `bind`、`listen`）将自身与某个特定的端口号绑定。凡是发往该端口号的网络报文，操作系统内核均自动投递给该进程的接收队列。

## 二、端口号的分类与划分区间（408 必背标准）

根据 IANA（因特网号分配机构）标准，16 位端口号（共 65536 个）划分为三大区间：

```text
  0               1023 1024             49151 49152             65535
  +-------------------+-----------------------+---------------------+
  |   熟知端口号      |      登记端口号       |   短暂/动态端口号   |
  | (Well-Known Ports)|  (Registered Ports)   | (Ephemeral / Private|
  +-------------------+-----------------------+---------------------+
```

| 端口类别 | 取值范围 | 分配主体与使用规则 | 408 考点核心代表端口 |
|---|:---:|---|---|
| **熟知端口号**<br>*(系统端口)* | **`0 ~ 1023`** | 由 IANA 统一严格分配给因特网核心通用基础服务。在通用操作系统中，绑定这些端口通常需要超级用户（root/Administrator）权限。 | - **FTP**：21 (控制连接), 20 (数据连接)<br>- **SSH**：22<br>- **Telnet**：23<br>- **SMTP**：25<br>- **DNS**：53<br>- **DHCP**：67 (服务端), 68 (客户端)<br>- **TFTP**：69<br>- **HTTP**：80<br>- **POP3**：110<br>- **SNMP**：161<br>- **HTTPS**：443 |
| **登记端口号** | **`1024 ~ 49151`** | 为没有熟知端口号的第三方网络应用程序使用。必须在 IANA 按照规范登记以防止冲突。 | - **Tomcat**：8080<br>- **MySQL**：3306<br>- **Microsoft RDP**：3389 |
| **短暂端口号**<br>*(客户端动态端口)* | **`49152 ~ 65535`** | 留给客户进程选择暂时使用。当客户端发起网络请求时，操作系统从该区间内**动态挑选一个未被占用的端口号**分配给客户进程；通信结束、连接关闭后，操作系统将该端口号释放回收。 | 浏览器、微信等客户端在发起向外请求时操作系统随机分配的源端口号 |

## 三、发送端复用与接收端分用

**复用（Multiplexing）** 与 **分用（Demultiplexing）** 是运输层的核心基础功能。

```text
       【发送端：复用 Multiplexing】                 【接收端：分用 Demultiplexing】
       
    [进程 A]   [进程 B]   [进程 C]                [进程 A]   [进程 B]   [进程 C]
   (Port 80)  (Port 21)  (Port 25)              (Port 80)  (Port 21)  (Port 25)
       │          │          │                      ▲          ▲          ▲
       └────┬─────┴─────┬────┘                      └───┬──────┴──────┬───┘
            ▼           ▼                               │             │
       +-----------------------+                    +-----------------------+
       |   运输层协议 (TCP/UDP) |                    |   运输层协议 (TCP/UDP) |
       | (统一添加源/目的端口号) |                    | (读取目的端口号精准投递)|
       +-----------------------+                    +-----------------------+
                   │                                            ▲
                   ▼                                            │
       +-----------------------+                    +-----------------------+
       |       网 络 层        |                    |       网 络 层        |
       |  (统一封装为 IP 数据报)|                   |  (协议号: TCP=6/UDP=17)|
       +-----------------------+                    +-----------------------+
```

### 1. 发送端的复用（Multiplexing）
- 概念：同一台主机上的**多个不同应用层进程**，可以同时利用**同一个运输层协议（如 TCP 或 UDP）**向网络发送数据；
- 实现方式：运输层在接收到各进程的数据后，在其头部封装统一的运输层首部，填入分配给该进程的“源端口号”和远端服务器的“目的端口号”，然后统一交给网络层 IP 协议封装发送。

### 2. 接收端的分用（Demultiplexing）
- 概念：运输层从网络层剥离出 IP 首部并接收到传输层报文段后，**根据报文首部中的端口标识，将数据准确交付给目的主机上对应的应用进程**；
- 分用分为两级：
  - **网络层分用**：目的主机网络层根据 IP 首部中的“协议（Protocol）”字段（TCP 为 6，UDP 为 17），将数据交付给对应的 TCP 或 UDP 协议栈实体；
  - **运输层分用**：运输层实体根据报文首部中的“目的端口号”将数据交付给对应的具体应用进程。

---

## 四、UDP 分用 vs TCP 分用的底层机制差异（高频考点）

408 经常考查操作系统内核在执行分用时依据的报文字段差异：

### 1. 无连接的 UDP 分用（仅依据目的端口号）
- 一个 UDP 套接字在操作系统中由一个**二元组**标识：
  $$\text{UDP 套接字} = (\text{目的 IP 地址}, \text{目的端口号})$$
- **分用规则**：当主机收到一个 UDP 用户数据报时，操作系统仅检查其**目的端口号**。只要目的端口号相同，无论该报文来自哪个源 IP 地址、哪个源端口号，操作系统都会将其无差别地投递给绑定该目的端口的同一个应用进程。

### 2. 面向连接的 TCP 分用（必须依据四元组）
- 一个 TCP 套接字在操作系统中严格由一个**四元组**标识：
  $$\text{TCP 连接} = (\text{源 IP 地址}, \text{源端口号}, \text{目的 IP 地址}, \text{目的端口号})$$
- **分用规则**：
  - 当主机收到一个 TCP 报文段时，操作系统必须同时比对**源 IP、源端口、目的 IP、目的端口**全部四个字段；
  - 即使两个 TCP 报文段发往同一个目的 IP 和同一个目的端口（例如 Web 服务器的 80 端口），只要它们的源 IP 或源端口不同，操作系统就会将它们分用至**不同的独立套接字（Socket）实体**进行处理；
  - 这正是单一 Web 服务器（单一 80 端口）能够同时与数万个并发客户端建立互相独立、互不干扰的 TCP 连接的底层机制保证。
