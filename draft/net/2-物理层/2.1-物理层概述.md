# 2.1 物理层概述

物理层（Physical Layer）位于 OSI 参考模型与 TCP/IP 体系结构的最底层，也是整个网络体系结构中**唯一直接与传输媒体接触的一层**。它的核心任务是：**透明地传送比特流（Bit Stream）**，确定与传输媒体的接口有关的一些特性，并尽可能屏蔽掉物理设备、传输媒体和通信手段的差异。

---

## 一、物理层解决的核心问题与服务边界

### 1. 物理层 vs 传输媒体（最基础的经典辨析陷阱）
- **传输媒体（Transmission Media）不属于物理层！**
  - 双绞线、同轴电缆、光纤、无线电磁波属于“物理层之下”的物理媒介（有时被称为第 0 层）。
  - **物理层的任务是规定“与传输媒体相连的接口规范”**，即网卡接口、网线水晶头、光模块金手指的协议标准，而不是规定传输介质本身的材料和物理结构。

### 2. “透明传输”在物理层的含义
- 物理层传送数据的基本单位是**比特（bit）**。
- 物理层对所传送的比特流的内容、格式和含义**完全不知情，也毫不关心**。无论是网络层 IP 包、控制信令还是随机噪声，物理层只负责忠实地将其转换成信号发出，并在对端尽可能无失真地还原为 0 和 1。这种“数据内容不被物理层解释和约束”的特性称为**透明传输**。

---

## 二、物理层四大接口特性（408 概念题核心考察阵地）

物理层协议通常称为物理层接口标准（如 EIA-232、RS-449、RJ-45 等）。这些标准严格规定了以下四大特性，408 经常给出某个工程细节，考查其属于哪一种特性归属：

```text
+---------------------------------------------------------------------------------+
|                                物理层四大特性全景                                 |
+---------------------------------------------------------------------------------+
| 1. 机械特性 (Mechanical)  | 接头的形状、引脚数量、排列方式、物理尺寸 (长什么样)     |
| 2. 电气特性 (Electrical)  | 信号线上的电压范围、阻抗匹配、传输速率与传输距离限制     |
| 3. 功能特性 (Functional)  | 某一引脚/电平所代表的具体含义 (干什么用: 数据/控制/地线) |
| 4. 规程特性 (Procedural)  | 不同功能事件出现的先后顺序、状态时序关系 (按什么顺序发生)|
+---------------------------------------------------------------------------------+
```

### 1. 机械特性（Mechanical Characteristics）
- **定义**：指明接口所用接线器的**形状、尺寸、引脚数目、排列方式**以及固定和锁定装置等。
- **典型实例**：
  - RJ-45 水晶头有 8 根引脚（Pin）；
  - RS-232 接口采用 DB-9 或 DB-25 针形/孔形连接器；
  - 规定插头不能插反、防呆卡扣的设计尺寸。

### 2. 电气特性（Electrical Characteristics）
- **定义**：指明在接口电缆的各条信号线上出现的**电压范围、阻抗匹配、传输速率上限和最大传输距离**。
- **典型实例**：
  - 规定正逻辑电平：$+3\text{V} \sim +15\text{V}$ 表示逻辑 `0`，$-3\text{V} \sim -15\text{V}$ 表示逻辑 `1`；
  - 规定 10BASE-T 双绞线最大传输距离为 100 米；
  - 规定特性阻抗为 100 欧姆。
- **易错陷阱**：“某一电平代表什么逻辑意义”属于电气还是功能？
  - **电压的数值范围（如 $-5\text{V}$ 到 $+5\text{V}$）属于电气特性**；
  - **这一脚是作为数据传输还是作为握手控制，属于功能特性**。

### 3. 功能特性（Functional Characteristics）
- **定义**：指明某条线上出现的某一电平的**电压表示何种物理意义**，即**每一个引脚的具体用途**。
- **典型实例**：
  - EIA-232 接口中：第 2 脚为接收数据（RxD），第 3 脚为发送数据（TxD），第 5 脚为信号地（GND），第 7 脚为请求发送（RTS）；
  - RJ-45 中：1、2 脚用于发送数据，3、6 脚用于接收数据；
  - 指明某个引脚是数据线、控制线、定时线还是地线。

### 4. 规程特性（Procedural Characteristics / 过程特性）
- **定义**：指明在各条物理线路上进行通信时，**不同功能的事件出现的先后顺序**，即通信协议的**操作步骤和时间顺序关系（时序）**。
- **典型实例**：
  - DTE（数据终端设备，如 PC）与 DCE（数据通信设备，如 Modem）建立连接时的时序：
    1. DTE 先将数据终端就绪（DTR）线置为有效电平；
    2. DCE 检测到后将数据准备好（DSR）线置为有效；
    3. DTE 发出请求发送（RTS），DCE 回复允许发送（CTS）；
    4. 双方开始在数据线上收发比特流；
    5. 通信结束后依次撤除信号线电平。

## 三、408 典型命题陷阱与秒杀对比表

| 题目描述的情境 | 正确的特性归属 | 常见错误判断与归因 |
|---|:---:|---|
| “规定网线插头的几何尺寸为 $11.68\,\text{mm} \times 6.6\,\text{mm}$” | **机械特性** | 容易误选为物理介质特性 |
| “规定接口信号线上传输的最大脉冲频率为 $100\,\text{MHz}$” | **电气特性** | 容易误选为功能特性；传输速率/频率是电信号参数 |
| “规定第 4 号引脚用于发送 RTS 请求信号” | **功能特性** | 容易因提到“引脚编号”误选机械特性；此处强调的是该引脚的**用途与意义** |
| “规定发送数据前必须先置 RTS 有效，收到 CTS 确认后方可发送” | **规程特性** | 容易误选为功能特性；此处强调的是动作发生的**先后时间顺序** |
| “双绞线分为 UTP 和 STP 两类” | **不属于物理层** | **属于传输媒体**；物理层只规范接口，不属于 OSI 七层模型层内 |

## 四、物理层的两大核心支撑技术桥梁

物理层并非孤立存在，它向下将抽象比特转化为信号投射入信道，向上为数据链路层提供无差异的服务。本章后续各节的承接逻辑如下：

1. **物理介质与信道特性（2.2 ~ 2.3）**：
   - 导向（双绞线/光纤）与非导向（微波/无线）；
   - 串行传输与并行传输（为什么现代高速网络全面转向高速串行？）；
   - 同步传输（字符/位同步）与异步传输（起止位开销）。
2. **信号调制与编码（2.4）**：
   - 计算机内部是方波数字脉冲，信道若只能传模拟波，需**调制（AM/FM/PM/QAM）**；
   - 若信道支持基带传输，需**数字基带编码（曼彻斯特/差分曼彻斯特/NRZ）**。
3. **传输能力数学极限（2.5）**：
   - 奈氏准则（无噪声低通信道极限波特率 $B = 2W$）与香农公式（带噪信道极限比特率 $C = W \log_2(1 + S/N)$）的统一与综合求解。
4. **介质共享与复用（2.6）**：
   - FDM、TDM、STDM、WDM、CDMA 的数学原理与码片正交解码计算。
