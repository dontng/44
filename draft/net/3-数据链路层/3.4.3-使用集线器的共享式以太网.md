# 3.4.3 使用集线器的共享式以太网

---

## 1. 物理演进：从同轴电缆总线到双绞线星形集线器

在以太网演进史上，集线器（Hub）的引入解决了总线式以太网在工程维护上的致命缺陷。

### 1.1 物理总线（10BASE5 / 10BASE2）的维护困境

1. **单点故障引发全网崩溃**：
   高频基带电信号在传输介质中传播时，必须在总线两端连接与线缆特性阻抗匹配的终端电阻（如 $50\ \Omega$）吸收能量，消除信号反射。若电缆任意一处发生折断、虚焊或接头松动，断口处的阻抗失配将引发全反射波，导致反射电压与正常信号叠加形成严重驻波，**整条总线上的全部节点瞬间全部瘫痪**；
2. **故障定位成本极高**：
   同轴电缆串联经过所有办公室，网络管理员必须使用仪器沿物理线缆逐段排查故障点，恢复周期长。

### 1.2 双绞线星形拓扑的工程优势

1990 年 IEEE 802.3i 制定了 10BASE-T 标准，采用无屏蔽双绞线（UTP）和中心集线器（Hub）：
- **物理星形布线**：每个节点通过独立双绞线点对点连接到中心集线器端口；
- **物理容错隔离**：若某根双绞线发生断裂或接口松脱，集线器内部逻辑可自动旁路（Partition）该故障端口，**其他端口之间的通信完全不受影响**；
- **逻辑总线本质**：由于早期硬件成本限制，集线器内部在电气上依然是将所有端口的收发线路直接短接，**通信机制依然遵循单一共享总线规则**。

## 2. 集线器（Hub）的微观工作机理与物理层属性

### 2.1 硬件本质：多端口中继器（Multiport Repeater）

集线器在 OSI 体系结构中严格归属于 **物理层（第 1 层，L1）**：

```
                    +---------------------------------------+
                    |         集线器 Hub (物理层 L1)         |
                    |                                       |
                    |   [ 模拟放大与波形整形电路 ]           |
                    |                 |                     |
                    |                 v (内部电气短接广播)   |
                    |    +------------+------------+        |
                    +----+------------+------------+--------+
                         |            |            |
                      端口 1        端口 2       端口 3
                         |            |            |
                      [ 主机 A ]    [ 主机 B ]   [ 主机 C ]
```

1. **信号整形与再生**：端口 1 接收到输入电信号后，集线器内部电路对衰减失真的模拟波形进行整形与放大，恢复时钟相位；
2. **电气广播转发**：集线器不具备数据链路层帧解析能力，无法读取帧首部的 MAC 地址。它将整形后的信号**无差别同步复制并分发至除输入端口外的所有其他端口**。

### 2.2 集线器的物理与性能边界

| 属性维度 | 集线器（Hub）的表现 | 物理机制动因 |
| :--- | :--- | :--- |
| **冲突域（Collision Domain）** | **所有端口同处于 1 个冲突域** | 内部电气线路短接，若任意两个端口同时有信号输入，电平在内部直接叠加相撞，引发全网冲突。 |
| **广播域（Broadcast Domain）** | **所有端口同处于 1 个广播域** | 物理层设备无法识别广播 MAC 地址，所有电信号无条件全端口泛洪。 |
| **工作双工模式** | **仅支持半双工（Half-Duplex）** | 必须依赖 CSMA/CD“边发边听”检测冲突；若工作在全双工模式，收发电路独立将导致无法检测总线电平冲突。 |
| **信道带宽分配** | **所有连接节点共享总物理带宽** | 若标称速率为 $10\text{ Mbps}$，全网并发理论吞吐量上限严格为 $10\text{ Mbps}$，各节点平均分摊可用带宽。 |
| **端口速率匹配** | **所有端口速率必须严格一致** | 集线器无帧存储转发缓冲区与内部时钟速率适配电路，无法混接不同速率的端口（如 10M 与 100M）。 |

## 3. 集线器（Hub）与交换机（Switch）的本质对比

| 对比维度 | 集线器（Hub） | 交换机（Switch） |
| :--- | :--- | :--- |
| **OSI 工作层次** | **物理层（L1）** | **数据链路层（L2）** |
| **转发机制** | 纯电信号整形放大、全端口无差别广播 | 存储转发、基于 MAC 地址自学习实现定向单播转发 |
| **片上缓冲区** | **无**（纯比特位流直通放大） | **有**（各端口具备独立的收发 FIFO 缓冲区） |
| **冲突域隔离能力** | **不隔离**（全网 1 个冲突域） | **隔离**（**每个端口独立为一个冲突域**） |
| **广播域隔离能力** | **不隔离**（全网 1 个广播域） | **不隔离**（默认全网 1 个广播域，依赖 VLAN 隔离） |
| **双工支持** | 仅半双工（必须执行 CSMA/CD） | **支持全双工**（无碰撞，淘汰 CSMA/CD） |
| **带宽特性** | 共享带宽（总容量上限为 $C$） | **独占带宽**（每个端口独享标称速率 $C$） |
| **跨速率适配** | 不支持（全网必须同频） | 支持（端口缓冲区可自适应桥接不同速率链路） |

## 4. 典型问题分析

### 题目：集线器级联网络通信行为与性能推导

某局域网拓扑由两台集线器级联构成：
- 集线器 Hub-A（8 个端口）连接主机 H1~H6；
- 集线器 Hub-B（8 个端口）连接主机 H7~H10；
- Hub-A 的端口 8 与 Hub-B 的端口 8 采用双绞线直连级联；
- 两台集线器标称端口速率均为 $10\text{ Mbps}$。

```
[ H1~H6 ]                         [ H7~H10 ]
   \                                   /
  +-+---+-----------------------------+---+--+
  |              Hub-A                | Port8|
  +-----------------------------------+---+--+
                                          | (级联双绞线)
  +-----------------------------------+---+--+
  |              Hub-B                | Port8|
  +-+---+-----------------------------+---+--+
```

**问题**：
1. 计算全网包含的冲突域数量与广播域数量；
2. 某一时刻主机 H1 向主机 H2 发送一个单播以太网帧：
   - 分析主机 H7 的网卡收发器是否会接收到该帧的物理电信号；
   - 此时主机 H7 能否同时向主机 H8 发送数据帧？为什么？
3. 在所有主机均有通信需求的高负荷场景下，全网的理论最大总吞吐量是多少？各主机的平均带宽是多少？
4. 若将两台集线器替换为两台 $10\text{ Mbps}$ 全双工以太网交换机，重新计算全网的冲突域数量及理论最大并发吞吐量。

---

### 推导过程

#### 1. 冲突域与广播域数量判定
- 集线器属于物理层设备，其级联线缆将两台设备的内部总线直接并联；
- 全网在电气上构成单一共享介质；
- **冲突域数量**：**1 个**；
- **广播域数量**：**1 个**。

#### 2. 通信微观行为推导
- **主机 H7 是否收到电信号**：
  - **必定收到**。Hub-A 无法解析帧头中的目的 MAC 地址，收到 H1 的信号后向所有端口复制，信号经级联线灌入 Hub-B，Hub-B 再次向其所有端口广播，故 H7 的物理层收发器必定接收到该完整电信号（H7 的网卡在 MAC 过滤阶段发现目的 MAC 不匹配后才在硬件层丢弃）；
- **主机 H7 能否并发发送**：
  - **绝对不能**。全网同处于一个冲突域，H1 发送期间总线处于繁忙状态；H7 发送前执行 CSMA/CD 载波监听，必定检测到信道繁忙并被迫推迟；若 H7 强行发送，两路信号发生物理碰撞，两组通信均被破坏。

#### 3. 集线器网络吞吐量推导
- 整个网络共享 $10\text{ Mbps}$ 的总信道容量；
- **全网理论最大总吞吐量**：严格为 **$10\text{ Mbps}$**；
- 10 台主机平分信道总带宽，平均可用带宽为：
  $$\text{平均带宽} = \frac{10\text{ Mbps}}{10} = \mathbf{1\text{ Mbps}}$$

#### 4. 替换为交换机后的指标对比
若替换为两台 $10\text{ Mbps}$ 以太网交换机：
- **冲突域数量**：
  - 交换机每个端口独立为一个冲突域；
  - Switch-A 连接 6 台主机（6 个端口） + Switch-B 连接 4 台主机（4 个端口） + 级联互连链路端口（1 个链路冲突域） = **共 11 个冲突域**；
- **全网理论最大并发吞吐量**：
  - 交换机支持多对端口并行独立通信；
  - 10 台主机可建立最多 5 对并发会话（如 H1-H2, H3-H4, H5-H6, H7-H8, H9-H10）；
  - 半双工并发总吞吐量可达 $5 \times 10\text{ Mbps} = 50\text{ Mbps}$；在全双工模式下理论吞吐量最高可达 **$100\text{ Mbps}$**。
