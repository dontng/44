# 3.2.3-（3）可靠传输的实现机制-回退N帧协议

> **本节在 408 中的定位**：回退 N 帧协议（Go-Back-N ARQ，GBN）是流水线协议（Pipelined Protocol）的经典模型。408 统考历年对 GBN 的考查强度极高，核心命题点集中在**“累计确认（Cumulative ACK）的抗丢包机制”**、**“接收窗口 $W_R=1$ 导致失序帧无情丢弃的连锁雪崩”**、**“发送窗口上限 $W_T \le 2^n - 1$ 的严格数学防歧义证明”**，以及**带误码率/不带误码率的信道利用率与重传开销计算**。

---

## 一、第一性原理与设计动因：为什么需要 GBN？

### 1. 突破停止-等待的信道闲置枷锁
在停止-等待协议中，发送方发完一帧必须停下来等待 RTT 时间。为消除这一漫长等待，**流水线（Pipelining）机制允许发送方在未收到任何 ACK 的情况下，连续向信道注入多个数据帧**。

### 2. GBN 的极端设计哲学：以发送端的重传代价，换取接收端的绝对极简
在早期的网络硬件中，网络适配器（网卡）的片上高速缓存（SRAM）极其昂贵且容量极其有限。
- **GBN 的妥协方案**：
  - **接收端极简**：接收窗口大小固定为 **$W_R = 1$**！这意味着接收端不需要任何复杂的乱序重组缓存区。只要来的帧不是我眼巴巴等待的“下一个按序帧”，哪怕它后面所有帧都完好无损，接收端也**毫不留情地一律丢弃**！
  - **发送端承担代价**：发送端必须维护发送窗口 $W_T$，保存所有已发送但未确认的帧副本。一旦中间某个帧在信道中丢失，发送端**必须回退到该帧，将其后所有已经发送出去的帧全部重发一遍（Go Back N）**。

---

## 二、微观机制：滑动窗口、累计确认与状态机推演

### 1. 发送窗口与接收窗口的微观结构
设序号位数为 $n$，序号空间为 $0 \sim 2^n - 1$。
- **发送窗口 $W_T$（$1 < W_T \le 2^n - 1$）**：
  - 维护三个边界指针：
    - `send_base`：最早未确认的帧序号；
    - `next_seq_num`：下一个待发送的可用序号；
    - 窗口大小限制：`next_seq_num - send_base < W_T`。
- **接收窗口 $W_R = 1$**：
  - 仅维护一个变量 `expected_seq_num`（期待接收的下一个按序帧序号）。

```
发送窗口形态 (假设 W_T = 4):
          send_base                    next_seq_num
              v                             v
[ 0 | 1 ]   [ 2       3       4       5 ]   [ 6 | 7 | 0 ... ]
+-------+   +---------------------------+   +---------------+
 已发送且     已发送但等待 ACK 的帧           允许发送但       超出窗口
 已被确认     (需保存在重传缓冲区中)          尚未发送的帧     绝对禁止发送
```

### 2. 累计确认（Cumulative ACK）的微观交互
GBN 采用累计确认：
- 接收方回复 $ACK = n$，其明确的协议语义是：**“序号为 $n$ 以及 $n$ 之前的所有帧均已正确接收，我现在期待序号为 $n+1$ 的帧！”**
- **天然的抗 ACK 丢失特性**：
  - 若发送方发了帧 0, 1, 2；
  - 途中 $ACK\ 0$ 和 $ACK\ 1$ 因信道噪声丢失，但 $ACK\ 2$ 成功抵达发送方；
  - 发送方收到 $ACK\ 2$ 后，直接判定：**帧 0、帧 1、帧 2 全部安全到达！** 发送窗口底座 `send_base` 直接向前滑动到 3。无需任何重传！

### 3. 出错重传连锁雪崩时序剖析
```
发送方 (W_T = 4)                                     接收方 (W_R = 1, expected = 0)
  | --- 帧 0 -----------------------------------------> | (收到 0，交付上层，发 ACK 0, expected=1)
  | --- 帧 1 (丢失/出错) ------------> ×                 |
  | --- 帧 2 -----------------------------------------> | (期望 1 却收到 2: 丢弃! 补发 ACK 0)
  | --- 帧 3 -----------------------------------------> | (期望 1 却收到 3: 丢弃! 补发 ACK 0)
  |                                                     |
  | [帧 1 的超时定时器爆炸 !]                            |
  | 此时即使帧 2、帧 3 已完好到达网卡，也全被扔了！       |
  | 发送方必须执行 Go-Back-N：                           |
  | --- 帧 1 (重发) ----------------------------------> | (收到 1，交付上层，发 ACK 1, expected=2)
  | --- 帧 2 (重发) ----------------------------------> | (收到 2，交付上层，发 ACK 2, expected=3)
  | --- 帧 3 (重发) ----------------------------------> | (收到 3，交付上层，发 ACK 3, expected=4)
```

## 三、为什么 GBN 发送窗口上限必须满足 $W_T \le 2^n - 1$？（408 核心证明）

这是 408 选择题中错误率最高的高频概念考点。

### 1. 反证法：若取 $W_T = 2^n$ 会发生什么灾难？
设序号位数 $n = 3$，序号空间大小为 $2^3 = 8$，序号集合为 $\{0, 1, 2, 3, 4, 5, 6, 7\}$。
假设我们贪心令 $W_T = 8$：
1. 发送方一次性发送全部 8 个帧：`帧 0, 帧 1, 帧 2, 帧 3, 帧 4, 帧 5, 帧 6, 帧 7`；
2. 接收方（$W_R=1$）完美收齐这 8 个帧，全部交付上层，并将期待序号 `expected_seq_num` 推进回绕为 **`0`**（新一轮的帧 0）；
3. 接收方向发送方回复 `ACK 7`；
4. **灾难发生**：信道出现故障，`ACK 7` 在途中丢失！
5. 发送方的定时器超时，发送方执行重传：**重新发送上一轮未被确认的 `旧帧 0`**；
6. 接收方收到这个 `帧 0`，查看自己当前期待的序号：**`expected_seq_num == 0`**！
7. **致命歧义诞生**：
   - 接收方**根本无法区分**：这到底是“发送方上一轮没收到 ACK 而重发的旧帧 0”，还是“发送方已经收到 ACK 后发来的全新一轮的第 8 个新数据帧 0”？！
   - 接收方将其误当成新帧再次交付上层，**导致整个数据流发生严重的数据翻倍与重叠！**

### 2. 结论与数学约束
为了彻底消除这种“新旧帧回绕重叠”的歧义，发送窗口内的所有帧，加上未确认时可能发生混淆的空隙，必须严格小于序号空间总容量：
$$W_T + W_R \le 2^n$$
因为 GBN 中 $W_R = 1$，代入即得：
$$W_T + 1 \le 2^n \implies W_T \le 2^n - 1$$

## 四、408 核心数学公式：GBN 信道利用率与实际吞吐率

### 1. 理想无差错条件下的利用率
设数据帧长为 $L_f$，数据率 $C$，发送时延 $T_f = L_f / C$；单向传播时延 $T_p$，往返时间 $RTT \approx 2T_p$；忽略 ACK 发送时延。
一个往返周期内最多可发送 $W_T$ 个帧。
- **若 $W_T$ 足够大**，发送窗口持续发送的时间能够完全覆盖整个往返等待时间（即 $W_T \cdot T_f \ge T_f + 2T_p$）：
  $$U_{\text{GBN}} = 100\%$$
- **若 $W_T$ 较小**，窗口发完后信道仍需空等 ACK：
  $$U_{\text{GBN}} = \frac{W_T \cdot T_f}{T_f + 2T_p} = \frac{W_T}{1 + 2 \cdot \frac{T_p}{T_f}} = \frac{W_T}{1 + 2a}$$

### 2. 存在误码率 $p$ 条件下的重传开销模型
若信道传输帧的出错概率为 $p$：
- 一旦某帧出错，接收方丢弃该帧及后续所有 $W_T - 1$ 个已发帧；
- 发送方超时后，平均需要重传整整 $W_T$ 个帧；
- 平均传输一个正确帧所需发送的平均帧数：
  $$\bar{N} = 1 + \frac{p \cdot W_T}{1 - p}$$
- **推论**：在**高误码率信道**（如无线电磁干扰严重）下，GBN 的性能会发生灾难性暴跌，甚至不如停止-等待协议！

## 五、408 统考真题级计算演练与全参数推导

### 【题型模型：GBN 窗口设计、序号位数与实际吞吐率综合大题】

**【考题背景】**
两台主机 A 和 B 之间建立一条速率为 $10\text{ Mbps}$ 的点对点通信链路，物理长度为 $2000\text{ km}$。
- 电磁波在链路中的传播速率为 $2 \times 10^8\text{ m/s}$；
- 数据帧长固定为 $1250\text{ 字节}$，确认帧 ACK 极短，忽略其传输时延；
- 双方采用 GBN 协议进行可靠通信，信道无差错。

**【试求解】**：
1. 计算单向传播时延 $T_p$ 与单帧发送时延 $T_f$；
2. 若要求链路的信道利用率达到 $100\%$，发送窗口 $W_T$ 至少应设为多大？
3. 承接第 2 问，此时帧首部的序号字段至少需要多少位（bit）二进制？
4. 若帧首部序号字段仅分配了 3 位二进制，且令 $W_T$ 达到 GBN 协议允许的最大值，求此时的信道利用率及主机的实际数据发送速率。

---

### 【草稿纸执行第一步：换算基本物理参数】
- $C = 10\text{ Mbps} = 10^7\text{ bps}$；
- $D = 2000\text{ km} = 2 \times 10^6\text{ m}$；
- $V = 2 \times 10^8\text{ m/s}$；
- 帧长 $L_f = 1250 \times 8\text{ bit} = 10000\text{ bit} = 10^4\text{ bit}$。

---

### 【严密推导过程】

#### 第 1 问：基础时延计算
1. 单向传播时延：
   $$T_p = \frac{D}{V} = \frac{2 \times 10^6\text{ m}}{2 \times 10^8\text{ m/s}} = 0.01\text{ s} = 10\text{ ms}$$
2. 单帧发送时延：
   $$T_f = \frac{L_f}{C} = \frac{10000\text{ bit}}{10^7\text{ bps}} = 10^{-3}\text{ s} = 1\text{ ms}$$
3. 往返周期：$T_{\text{cycle}} = T_f + 2T_p = 1\text{ ms} + 2 \times 10\text{ ms} = 21\text{ ms}$。

#### 第 2 问：实现 100% 利用率的最小发送窗口 $W_T$
要使信道利用率达到 $100\%$，发送方发送窗口连续发送帧的时间必须覆盖整个往返周期：
$$W_T \times T_f \ge T_{\text{cycle}} \implies W_T \ge \frac{T_{\text{cycle}}}{T_f} = \frac{21\text{ ms}}{1\text{ ms}} = 21$$
故发送窗口 $W_T$ 至少为 **21**。

#### 第 3 问：所需最小序号位数推导
- GBN 协议中，发送窗口与序号位数 $n$ 的关系为：$W_T \le 2^n - 1$。
- 将 $W_T = 21$ 代入：
  $$2^n - 1 \ge 21 \implies 2^n \ge 22$$
- 检验 2 的幂次：
  - $2^4 = 16 < 22$（不足）
  - $2^5 = 32 \ge 22$（满足）
- 因此，序号字段至少需要 **5 位** 二进制。

#### 第 4 问：序号字段为 3 位时的性能计算
1. 若序号字段为 $n = 3$ 位：
   - 序号空间大小为 $2^3 = 8$；
   - GBN 协议允许的最大发送窗口：$W_{T,\max} = 2^3 - 1 = 7$。
2. 此时一个往返周期内最多只能发送 7 个帧：
   $$U = \frac{W_T \times T_f}{T_{\text{cycle}}} = \frac{7 \times 1\text{ ms}}{21\text{ ms}} = \frac{7}{21} = \frac{1}{3} \approx 33.33\%$$
3. 实际数据发送速率（有效吞吐量）：
   $$\text{Throughput} = U \times C = 33.33\% \times 10\text{ Mbps} \approx 3.33\text{ Mbps}$$

## 六、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：把 GBN 的最大窗口算成 $2^n$**
> - **408 丢分重灾区**：题目说“3 位序号，GBN 最大发送窗口是多少？”。大量考生脱口而出写 $2^3 = 8$。
> - **记住扣分点**：GBN 必须减 1！$W_T \le 2^n - 1$！3 位序号最大窗口只能是 **7**；4 位序号最大窗口只能是 **15**！

> [!CAUTION]
> **陷阱 2：以为收到失序帧会触发 NAK 或直接断开**
> - 在标准 GBN 中，接收端收到失序帧的处理动作只有两个：**① 丢弃该失序帧；② 重复发送上一张已按序收到的最高有效帧的 ACK（即重复 ACK）**。接收端绝不会报错断开，也不会把失序帧暂存在缓冲区中。

### 2. 考场核心记忆桩
- **“GBN 窗口减去一，接收窗口只有一”**：$W_T \le 2^n - 1, W_R = 1$。
- **“一人犯错全家连坐，累计确认不怕丢包”**：形象理解 GBN 出错回退全部与 ACK 累计确认的本质。
