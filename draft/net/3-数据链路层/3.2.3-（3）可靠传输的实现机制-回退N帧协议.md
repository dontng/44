# 3.2.3-（3）可靠传输的实现机制-回退N帧协议

停止-等待协议通过限制信道中只飞一个帧保证了正确性，但其低下的信道利用率无法适应高速或长距离网络。**流水线协议（Pipelined Protocol）**允许发送端在未收到确认前连续发送多个数据帧。**回退N帧协议（Go-Back-N, GBN）**是流水线可靠传输协议的经典模型。

---

## 一、设计思想：发送端重传代价换取接收端极简

在网络早期硬件设计中，网络适配器的片上高速缓存（SRAM）容量极度受限且价格高昂。GBN 协议采用了极度倾斜的软硬件资源权衡方案：
- **接收端极简（$W_R = 1$）**：
  接收端的接收窗口大小严格固定为 $1$。接收端不设乱序接收缓冲区，只严格按顺序接收下一个期待的帧；任何失序到达的帧（即便其数据完全无误）均被**直接丢弃**；
- **发送端承担代价（$W_T > 1$）**：
  发送端必须维护容量为 $W_T$ 的发送缓冲区，保存所有已发送但未收到确认的帧副本。一旦信道中某个中间帧丢失，由于接收端丢弃了其后所有失序帧，发送端超时后必须**回退到丢失的帧，将其后所有已发出的帧全部重新发送一遍（Go-Back-N）**。

---

## 二、滑动窗口与累计确认机制

### 1. 发送窗口与接收窗口结构
设帧序号字段的位宽为 $n$ 位，则序号空间大小为 $2^n$，序号取值范围为 $[0, 2^n - 1]$。

```text
发送窗口结构 (设 W_T = 4):
           send_base                     next_seq_num
               │                              │
               ▼                              ▼
  [ 0   1 ]    [ 2       3        4       5 ]   [ 6   7   0 ... ]
┌───────────┐ ┌─────────────────────────────┐ ┌─────────────────┐
  已发送并已     已发送但尚未收到确认的帧        允许发送但尚未      超出窗口范围
  收到确认的帧   (必须缓存在重传队列中)          发送的数据帧        绝对禁止发送
```

- **发送窗口界限**：由最早未确认帧序号 `send_base` 与下一个可用序号 `next_seq_num` 标识，满足 `next_seq_num - send_base < W_T`；
- **接收窗口界限**：仅维护一个期待序号 `expected_seq_num`（$W_R = 1$）。

---

### 2. 累计确认（Cumulative ACK）的协议语义与抗丢包能力
GBN 协议采用累计确认机制：
- 接收端回复确认报文 $\text{ACK } n$，其语义为：**“序号为 $n$ 以及 $n$ 之前的所有数据帧均已按序正确接收，期待接收序号为 $n+1$ 的帧”**；
- **抗 ACK 丢失特性**：
  若发送端连续发送了帧 0、帧 1、帧 2，传输途中 $\text{ACK } 0$ 与 $\text{ACK } 1$ 因干扰丢失，但 $\text{ACK } 2$ 成功抵达发送端。发送端收到 $\text{ACK } 2$ 后，判定帧 0、1、2 全部安全接收，`send_base` 直接向前推进至 3。中间确认帧的丢失不会引发任何重传。

---

### 3. 出错重传与连锁丢弃的时序流转

```text
发送端 (W_T = 4)                                     接收端 (W_R = 1, expected = 0)
  │ ─── 帧 0 ─────────────────────────────────────────> │ (收到 0，递交上层，回复 ACK 0, expected=1)
  │ ─── 帧 1 (信道损坏/丢失) ─────────> ╳                │
  │ ─── 帧 2 ─────────────────────────────────────────> │ (期望 1 却收到 2: 失序丢弃! 补发 ACK 0)
  │ ─── 帧 3 ─────────────────────────────────────────> │ (期望 1 却收到 3: 失序丢弃! 补发 ACK 0)
  │                                                     │
  │ [帧 1 的超时定时器触发 !]                            │
  │ 触发 Go-Back-N，发送窗口从帧 1 开始全部重传:          │
  │ ─── 帧 1 (重传) ──────────────────────────────────> │ (收到 1，递交上层，回复 ACK 1, expected=2)
  │ ─── 帧 2 (重传) ──────────────────────────────────> │ (收到 2，递交上层，回复 ACK 2, expected=3)
  │ ─── 帧 3 (重传) ──────────────────────────────────> │ (收到 3，递交上层，回复 ACK 3, expected=4)
```

## 三、发送窗口上限 $W_T \le 2^n - 1$ 的数学证明

在采用 $n$ 位二进制序号的系统里，GBN 的发送窗口大小必须严格满足：
$$W_T \le 2^n - 1$$

### 1. 反证法推演：若 $W_T = 2^n$ 产生的致命歧义
设序号位宽 $n = 3$，序号空间为 $2^3 = 8$，序号集合为 $\{0, 1, 2, 3, 4, 5, 6, 7\}$。若将发送窗口设为 $W_T = 8$：
1. 发送端在初始窗口内一次性发满全部 8 个帧：`帧 0 ~ 帧 7`；
2. 接收端（$W_R = 1$）按序收齐了全部 8 个帧并递交给上层，接收窗口按模 8 回绕，`expected_seq_num` 重新变为 **`0`**（期待新一轮的第 0 号帧）；
3. 接收端向发送端回复 $\text{ACK } 7$；
4. **异常发生**：该 $\text{ACK } 7$ 在回传途中丢失；
5. 发送端重传定时器超时，触发重传：发送端从最早未确认的帧开始重传，**再次发送上一轮未被确认的“旧帧 0”**；
6. 接收端收到该数据帧，读取其首部序号为 `0`，而本地 `expected_seq_num` 正好等于 `0`：
   - **致命歧义**：接收端无法判断该帧是**发送端因未收到 ACK 7 而重传的上一轮旧帧 0**，还是**发送端已顺利收到 ACK 7 后发送的新一轮全新帧 0**；
   - 接收端将其当作新数据交付上层，直接造成数据重复错误。

### 2. 数学约束准则
为了彻底避免序号回绕产生的新旧帧混淆，发送窗口与接收窗口大小之和必须严格小于或等于序号空间大小：
$$W_T + W_R \le 2^n$$
由于 GBN 协议中接收窗口固定为 $W_R = 1$，代入可得：
$$W_T + 1 \le 2^n \implies W_T \le 2^n - 1$$

## 四、GBN 性能分析与信道利用率计算模型

设数据帧长度为 $L_f$，信道传输速率为 $C$，单帧发送时延为 $T_f = L_f / C$；单向传播时延为 $T_p$，往返时间 $RTT \approx 2T_p$；忽略微小的 ACK 发送时延与处理时延。
一个完整的发送周期耗时：$T_{\text{cycle}} = T_f + 2T_p$。

1. **发送窗口受限情况（$W_T \times T_f < T_{\text{cycle}}$）**：
   发送端发送完 $W_T$ 个帧后，信道必须暂停发送，等待第一个帧的 ACK 返回：
   $$U = \frac{W_T \times T_f}{T_{\text{cycle}}} = \frac{W_T \times T_f}{T_f + 2T_p} = \frac{W_T}{1 + 2 \cdot \frac{T_p}{T_f}} = \frac{W_T}{1 + 2a}$$
2. **发送窗口充足情况（$W_T \times T_f \ge T_{\text{cycle}}$）**：
   发送端在第一个帧的 ACK 返回前始终有新帧可以发送，数据流完全流水化：
   $$U = 100\%$$

## 五、综合参数设计与吞吐量推导演练

### 场景参数
- 链路特征：长度 $D = 2000\,\text{km}$ 的直连点对点通信线路；
- 传输带宽：$C = 10\,\text{Mb/s} = 10^7\,\text{b/s}$；
- 介质电磁波传播速度：$V = 2.0 \times 10^8\,\text{m/s}$；
- 数据帧长固定为 $L_f = 1250\,\text{字节} = 10000\,\text{bit}$；
- 忽略 ACK 发送时延，信道处于无差错稳定传输状态。

### 1. 基础时延分量计算
1. **单向传播时延**：
   $$T_p = \frac{D}{V} = \frac{2 \times 10^6\,\text{m}}{2.0 \times 10^8\,\text{m/s}} = 0.01\,\text{s} = 10\,\text{ms}$$
2. **单帧发送时延**：
   $$T_f = \frac{L_f}{C} = \frac{10000\,\text{bit}}{10^7\,\text{b/s}} = 0.001\,\text{s} = 1\,\text{ms}$$
3. **往返周期总耗时**：
   $$T_{\text{cycle}} = T_f + 2T_p = 1\,\text{ms} + 2 \times 10\,\text{ms} = 21\,\text{ms}$$

### 2. 满载传输（100% 利用率）的最小发送窗口
要使信道在无差错下达到 $100\%$ 利用率，发送端必须在确认返回前连续发送满整个周期：
$$W_T \times T_f \ge T_{\text{cycle}} \implies W_T \ge \frac{T_{\text{cycle}}}{T_f} = \frac{21\,\text{ms}}{1\,\text{ms}} = 21$$
因此，临界发送窗口大小为 $W_T = 21$。

### 3. 支持该窗口所需的最小序号编码位宽
根据 GBN 窗口约束：
$$W_T \le 2^n - 1 \implies 2^n - 1 \ge 21 \implies 2^n \ge 22$$
由于 $2^4 = 16 < 22$ 且 $2^5 = 32 \ge 22$，序号字段长度至少需要 **5 位** 二进制。

### 4. 序号位宽受限（$n = 3$）时的网络性能分析
若协议首部仅分配了 $n = 3$ 位二进制作为序号：
1. **允许的最大发送窗口**：
   $$W_{T,\max} = 2^3 - 1 = 7$$
2. **此时的信道利用率**：
   $$U = \frac{W_T \times T_f}{T_{\text{cycle}}} = \frac{7 \times 1\,\text{ms}}{21\,\text{ms}} = \frac{7}{21} = \frac{1}{3} \approx 33.33\%$$
3. **实际有效数据吞吐量**：
   $$\text{Throughput} = U \times C = \frac{1}{3} \times 10\,\text{Mb/s} \approx 3.33\,\text{Mb/s}$$
