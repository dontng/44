# 3.2.3 （3）可靠传输的实现机制-回退N帧协议

**回退 N 帧协议（Go-Back-N，GBN）** 是一种流水线 ARQ 协议：发送方可以连续发出最多 $W_T$ 个帧而不等待 ACK，但一旦检测到某帧出错，必须**从出错帧开始，重传该帧及其后所有已发的帧**。

## 一、滑动窗口机制

- **发送窗口（$W_T$）**：发送方可以连续发送而无需等待 ACK 的最大帧数，$1 < W_T \leq 2^n - 1$（n 为序号位数）；
- **接收窗口（$W_R$）**：GBN 中接收窗口固定为 **1**，即接收方只接受**按序到达**的帧，失序帧一律丢弃。

序号空间大小为 $2^n$，GBN 要求 $W_T \leq 2^n - 1$（不能用 $2^n$，原因见下文）。

## 二、GBN 工作过程

```
发送方连续发：  0  1  2  3  4  5  ...
              ←——W_T=4——→
假设帧 2 出错：
  接收方发 ACK1（对帧 0、1 的累积确认），丢弃帧 2、3、3...
  发送方超时后，从帧 2 开始重传：  2  3  4  5  ...
```

### 累积确认（Cumulative ACK）
GBN 使用**累积确认**：ACK n 表示序号 n 及之前的所有帧都已正确收到，期待收到 n+1。

## 三、为什么 $W_T \leq 2^n - 1$ 而不是 $2^n$？

设 n=3，序号空间 0-7（8 个）。若 $W_T = 8$，发送方发完 0~7 后，接收方全部收到并发出 ACK 0~7，但若所有 ACK 都丢失，发送方超时重传从帧 0 开始；而接收方已经期待帧 8（即序号 0 的新帧），会误将重传的旧帧 0 当作新帧 0 接受——**产生歧义**。因此 $W_T \leq 2^n - 1 = 7$。

## 四、信道利用率

设 $a = T_p / T_f$（传播时延与帧发送时间之比）：

$$\eta_{GBN} = \begin{cases} 1 & W_T \geq 2a+1 \\ \dfrac{W_T}{2a+1} & W_T < 2a+1 \end{cases}$$

（假设无误码，仅考虑流水线填充效率）

若有误码率 p（帧出错概率），则：
$$\eta_{GBN} = \frac{(1-p) \cdot W_T}{2a+1} \quad（W_T < 2a+1 \text{ 时}）$$

## 五、GBN 小结

| 参数 | GBN |
|---|---|
| 发送窗口 $W_T$ | $1 < W_T \leq 2^n - 1$ |
| 接收窗口 $W_R$ | 1（只接受按序帧） |
| 出错重传范围 | 出错帧 + 其后所有帧（"回退 N"的含义） |
| ACK 类型 | 累积确认 |
| 失序帧处理 | 丢弃 |
| 接收方缓冲 | 不需要（$W_R=1$，不缓冲失序帧） |

**记忆要点**：GBN 接收窗口 = 1，出错代价大（要把出错帧后面的全部重发），但接收方实现简单（无需缓冲）。
