# 3.2.1 封装成帧和透明传输

## 一、封装成帧（Framing）

**封装成帧**是指数据链路层在网络层交下来的数据报前后分别加上**帧头**和**帧尾**，构成一个完整的帧。接收方通过帧头/帧尾中的定界标志，准确判断帧的起止边界，从比特流中提取出完整的帧。

帧头和帧尾中包含许多控制信息，其中**帧定界符**是实现帧同步的关键字段。

### MTU（最大传输单元）

每种数据链路层协议都规定了帧的最大数据长度，称为 **MTU（Maximum Transmission Unit）**。以太网的 MTU 为 1500 字节。网络层在封装 IP 数据报时，若数据报超过链路 MTU，需进行**分片**。

## 二、帧定界的实现方法

### 方法一：字节计数法

在帧头中加入一个**长度字段**，指明帧内数据的字节数。缺点：若该字段本身因误码而出错，后续帧边界全部错位，难以恢复同步。

### 方法二：字节填充法（字符填充法）

使用特殊的控制字符作为帧定界符，如：
- **SOH**（Start Of Header，0x01）标记帧头起始；
- **EOT**（End Of Transmission，0x04）标记帧尾。

**问题**：若帧的数据部分恰好出现与定界符相同的字节，接收方会误认为帧结束。

**透明传输解决方案（字节填充/转义）**：发送方在数据中每个与定界符相同的字节前插入一个**转义字符 ESC**（0x1B）；接收方遇到 ESC 则删去并将下一字节作为数据处理。若数据中出现 ESC 本身，则在其前再插入一个 ESC（双写转义）。

| 原始数据 | 填充后（发送） |
|---|---|
| `...SOH...` | `...ESC SOH...` |
| `...EOT...` | `...ESC EOT...` |
| `...ESC...` | `...ESC ESC...` |

### 方法三：比特填充法（零比特填充）

HDLC 协议使用标志字段 `01111110`（0x7E）作为帧的起止定界符。

**问题**：若数据中出现连续 6 个 1，接收方误认为帧边界。

**解决（透明传输）**：
- **发送方**：对数据部分扫描，每遇到连续 5 个 1，自动在其后**插入一个 0**；
- **接收方**：对数据部分扫描，每遇到连续 5 个 1 后跟着一个 0，**删去该 0**（还原数据）；若 5 个 1 后跟的是 1，则认为是帧定界符。

**示例**：
```
原始数据：  ... 0 1 1 1 1 1 1 0 ...
填充后：    ... 0 1 1 1 1 1 0 1 0 ...
                        ↑ 插入的 0
```

## 三、透明传输的含义（考点）

**透明传输**是指数据链路层对上层（网络层）来说是"透明的"——无论数据内容是什么（包括和定界符一样的比特组合），都能被正确封装和传输，上层不需要关心底层如何处理帧边界问题。

> 易错点：透明传输≠无损传输（仍可能有比特差错）；透明的意思是"数据内容对链路层是透明的，链路层不解释数据含义，只负责正确定界和传送"。

## 四、考点速记

| 方法 | 插入/删除单位 | 代表协议 |
|---|---|---|
| 字节填充 | 字节（ESC） | PPP |
| 比特填充 | 比特（0） | HDLC |

计算题常考：给出原始比特串，写出比特填充后的内容；或给出接收到的含填充的比特串，还原原始数据。
