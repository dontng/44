# 3.9.3-（2）802.11 无线局域网的数据链路层-CSMA/CA 协议的基本工作原理

802.11 的 CSMA/CA 协议通过多层规避机制降低碰撞发生的概率，并在发生不可避免的碰撞时提供可靠的链路恢复机制。其核心机制包括：**帧间间隔（IFS）分级**、**退避计数器及其遇忙冻结机制**、**网络分配向量（NAV）虚拟载波监听**以及**RTS / CTS 信道预约机制**。

---

## 一、帧间间隔（IFS）的分级机制

802.11 规定：所有站点在检测到物理信道变为空闲之后，绝对不能立即发射信号，必须强制等待一段特定的静默时间，称为**帧间间隔（IFS，Inter-Frame Space）**。

帧间间隔的长短决定了不同类型数据帧占用信道的优先级：**等待时间越短，抢占信道的优先级越高**。802.11 中最常用的三种帧间间隔满足严格的不等式关系：

$$\mathbf{\text{SIFS} < \text{PIFS} < \text{DIFS}}$$

```
优先级: [ 最高优先级 ] ====================================> [ 普通优先级 ]
时间长度:   SIFS (最短)            PIFS (中等)                DIFS (最长)
典型应用: ACK, CTS 响应帧        AP 点协调集中轮询        普通数据帧, RTS 预约帧
```

### 1. 短帧间间隔（SIFS，Short IFS）
- **特点**：时间最短，优先级最高（典型取值为 $10 \sim 16\ \mu\text{s}$）。
- **作用**：用于已经建立连接的一对节点之间的快速响应，确保当前通信事务不被外界打断。
- **典型应用帧**：
  - **ACK 确认帧**；
  - **CTS（清除发送）控制帧**；
  - 分片传输中的后续分片数据帧。

### 2. 点协调帧间间隔（PIFS，Point Coordination IFS）
- **特点**：时间居中（$\text{PIFS} = \text{SIFS} + 1\ \text{SlotTime}$）。
- **作用**：用于 AP 在点协调功能（PCF，免争用服务）下集中轮询各个站点，优先级高于普通分布式竞争站点。

### 3. 分布式协调帧间间隔（DIFS，Distributed IFS）
- **特点**：时间最长，优先级为普通争用级别（$\text{DIFS} = \text{SIFS} + 2 \times \text{SlotTime}$）。
- **作用**：用于分布式协调功能（DCF）下的普通信道争用。
- **典型应用帧**：
  - 所有的**普通数据帧（Data Frame）**；
  - 信道预约的**请求发送帧（RTS Frame）**。

## 二、CSMA/CA 基础时序与退避计数器“冻结”机制

在分布式协调功能（DCF）的基本模式下，单播数据传输的时序流程如下：

```
发送端:
          | 数据产生，检测信道若忙...
          +-------------------------------+~~~~~~ 等待信道由忙变闲 ~~~~~~+
                                                                         |
                                                                         |<-- DIFS -->|<- 退避倒计时 (Backoff) ->|
                                                                         +------------+--------------------------+========================+
                                                                         | 强制等待   | 信道空闲一个时隙减 1      | 倒计时归零!            |
                                                                         | DIFS 时间  | 若信道变忙则【冻结】!     | 发送数据帧 (Data)      |
                                                                         +------------+--------------------------+========================+
                                                                                                                                          |
接收端:                                                                                                                                   |
                                                                                                                                          v
                                                                                                                   |<-- SIFS -->|
                                                                                                                   +------------+=========+
                                                                                                                   | 校验无误   | 发送    |
                                                                                                                   | 仅等 SIFS  | ACK 帧  |
                                                                                                                   +------------+=========+
```

### 1. 发送端基本时序流程
1. 站点准备发送数据时，首先监听物理信道：
   - 若信道在最初监听时就处于空闲状态，且持续保持空闲满 **DIFS** 时间，该站点可以立即发送数据帧（无需退避）；
   - 若最初监听时信道正忙，该站点必须持续监听，直到信道变为空闲；
2. 当信道变为空闲后，站点必须首先等待一个 **DIFS** 时间；
3. DIFS 等待期满后，信道若依然空闲，站点启动**随机退避算法**。

### 2. 退避计数器与“冻结（Freeze）”机制
与有线以太网发生碰撞后才退避不同，802.11 在信道由忙变闲后，为了防止多个等待的站点同时抢发导致严重碰撞，强制执行退避：
1. **产生退避时隙数**：
   - 站点在争用窗口 $[0, CW - 1]$ 内均匀随机选择一个整数 $r$（$CW$ 为争用窗口大小，初始为 $CW_{\min}$，发生重传时成倍翻倍）；
   - 退避时间计算为 $r \times \text{SlotTime}$（$\text{SlotTime}$ 为物理层定义的固定时隙时间）。
2. **退避倒计时规则**：
   - 站点在退避期间持续监听信道；
   - **信道每保持空闲一个完整的时隙时间，退避计数器就减 1**；
3. **遇忙冻结机制**：
   - 在倒计时过程中，如果信道被其他站点抢先占用（信道变忙），**站点的退避计数器立即暂停倒计时并保持当前剩余数值，即“冻结”**；
   - 站点静默等待，直到占用信道的传输结束、信道重新变为空闲；
   - 站点再次等待满一个 DIFS 时间后，**从原先冻结的剩余数值继续向下倒计时**，而无需重新生成退避计数值；
   - 这种机制保证了先前已经等待了较长时间的站点在下一轮竞争中拥有更小的剩余退避值，从而更具竞争优势，保证了信道分配的相对公平性。
4. **归零发送**：
   - 当退避计数器减至 0 时，站点立即启动发射数据帧。

### 3. 接收端 ACK 确认
- 接收端在完整接收数据帧并经 CRC 校验无误后，等待一个很短的 **SIFS** 即可发送 ACK 确认帧；
- 由于 $\text{SIFS} < \text{DIFS}$，其他任何想要发数据的站点此时都至少还在等待 DIFS，因此接收端的 ACK 帧能够无碰撞地抢占信道发回给发送端。

## 三、网络分配向量（NAV）与 RTS / CTS 信道预约机制

为了解决隐藏终端引起的严重碰撞问题，802.11 提供了可选的 RTS / CTS 握手机制，该机制结合了**虚拟载波监听**技术。

### 1. 虚拟载波监听与网络分配向量（NAV）
- **物理载波监听**：通过网卡物理层检测无线信道中的射频信号能量；
- **虚拟载波监听**：
  - 802.11 的 MAC 帧首部包含一个 2 字节的 **Duration（持续时间）** 字段；
  - 发送端在发送帧时，会将完成本次完整通信事务（包括后续的数据传输、ACK 确认以及相关的 SIFS 间隔）所需的总微秒数填入该字段；
  - 空间中监听到该帧的所有其他站点，读取该持续时间字段后，会在本地维护一个递减计时器，称为**网络分配向量（NAV，Network Allocation Vector）**；
  - **在 NAV 递减到 0 之前，站点在逻辑上判定信道为忙碌状态，在此期间主动关闭发射电路、禁止争用信道**。

### 2. RTS / CTS 握手流程与隐藏终端的解决

```
[ 隐藏站点 A ]                                 [ 接入点 B (AP) ]                                [ 隐藏站点 C ]
  (准备发数据给 B)                                                                               (听不到 A, 听得到 B)
       |                                                |                                                |
       | --- RTS 帧 (包含持续时间 D1) -----------------> |                                                |
       |                                                |                                                |
       |                                                | (B 收到 RTS, 等 SIFS)                          |
       |                                                |                                                |
       | <========== CTS 帧 (广播包含持续时间 D2) =======|======== CTS 帧 (广播包含持续时间 D2) =========> |
       |                                                |                                                |
       | (A 收到 CTS: 预约成功!)                         |                                                | (C 听到来自 B 的 CTS 帧)
       | (等待 SIFS)                                    |                                                | (C 读取 Duration D2)
       |                                                |                                                | 【C 设置 NAV 计时器】
       | --- 发送真实数据帧 (Data) --------------------> |                                                | 【C 在整个传输期静默】
       |                                                |                                                |
       |                                                | (B 校验无误, 等 SIFS)                          |
       | <---------- ACK 确认帧 ------------------------ |                                                |
       |                                                |                                                | (NAV 归零, C 解除静默)
```

1. **发送 RTS（请求发送）**：
   - 站点 A 在发送真实长数据帧前，先发送一个短小的 RTS 控制帧，内含本次传输所需时长 $D_1$；
2. **回复 CTS（清除发送）**：
   - 接入点 B 收到 RTS 后，等待一个 SIFS，向四周广播回复一个短小的 CTS 控制帧，内含剩余所需时长 $D_2$；
   - 站点 A 收到 CTS 确认预约成功；
3. **隐藏终端消除机制**：
   - 处于 A 覆盖范围外的隐藏终端 C 无法听到 A 发出的 RTS；
   - 但 **AP（B）发出的 CTS 广播能够覆盖站点 C**；
   - 站点 C 收到来自 B 的 CTS 帧后，读取其中的 Duration 字段，更新自身的 NAV 计时器；
   - 在 A 向 B 发送数据帧及 B 回复 ACK 的整个期间，**站点 C 处于 NAV 静默保护状态，绝不会发射信号**，从而彻底避免了在 AP（B）处发生碰撞。

### 3. RTS 门限（RTS Threshold）
RTS 和 CTS 帧本身包含头部开销和信道占用时间。对于短数据包（如仅数十字节的控制报文），先握手再发数据反而会导致信道开销大于收益。因此，802.11 引入了 **RTS 门限** 参数：
- 只有当待发送的数据帧长度超过 RTS 门限时，才启动 RTS / CTS 握手流程；
- 小于 RTS 门限的数据帧，直接采用基础的 DCF 流程发送。
