# 3.6 以太网的 MAC 帧格式

> **本节在 408 中的定位**：以太网 MAC 帧格式是整个计算机网络体系中出现频率最高、考查粒度最细的报文字段模型。408 统考历年对本节的考查贯穿选择题与综合大题，核心考核点包括：**“Ethernet V2 帧微观字节位图（目的 MAC 6B、源 MAC 6B、类型 2B、数据 46~1500B、FCS 4B）”**、**“上层分用协议代码（`0800` IPv4、`0806` ARP、`86DD` IPv6）的抓包逆向”**、**“数据载荷 46 字节最小填充计算与 IP 首部总长度反算”**，以及**“物理层前导码（8B）与帧间隙（IFG）在传输信道上的开销折算”**。

---

## 一、第一性原理与设计动因：为什么 MAC 帧这样布局？

### 1. 字段排列的微观硬件逻辑
在物理线路上，比特流是按序逐位从网卡芯片飞出的。
- **为什么“目的 MAC”必须排在最开头（Byte 0~5）？**
  网卡在接收到信号时，必须在最短时间内做出“是接收还是丢弃”的硬件裁决。把目的 MAC 放在最前面，网卡接收完前 6 字节即可在直通交换机或网卡 ASIC 芯片中完成硬件地址比对与过滤，**无需等待整帧接收**！
- **为什么“源 MAC”排在第二（Byte 6~11）？**
  供交换机进行**自学习（Self-Learning）**记录源端口映射，并供对端回复响应报文。
- **为什么“类型/长度”排在第三（Byte 12~13）？**
  数据链路层接收完帧后，必须知道将内部有效载荷剥除后递交给操作系统网络层的哪个协议模块（是交给 IP 协议栈，还是交给 ARP 处理模块？），这个分用字段必须紧随帧头。
- **为什么“FCS 校验”必须放在帧尾（最后 4 字节）？**
  发送端网卡硬件是一边从内存 DMA 读取数据向物理线路上发射比特，一边通过片上移位寄存器（LFSR）硬件动态计算 CRC-32 校验码。当数据全部发射完毕的瞬间，校验码刚好计算完成，**顺势追加在帧的最后发送出去**，无需二次遍历内存！

## 二、Ethernet V2 MAC 帧微观全景位图与字段拆解

### 1. Ethernet V2 标准帧格式（RFC 894 / 事实工业标准）

```
 物理层前导码 (在线路上发送, 不计入 MAC 帧长):
 +-------------------------------------------+-------------------+
 |         前导码 Preamble (7 字节)          | 帧前定界符 SFD(1B)|
 | 10101010 10101010 ... 10101010 (共 56 bit)| 10101011 (8 bit)  |
 +-------------------------------------------+-------------------+
   (用于接收方时钟同步与位定界)                 (最后两位 11 宣告帧开始)

 数据链路层 MAC 帧实体 (严格计入帧长: 64 ~ 1518 字节):
 字节偏移:
  0               6               12     14                           N-4       N
 +---------------+---------------+------+----------------------------+---------+
 | 目的 MAC 地址 |  源 MAC 地址  | 类型 |    数据载荷 (IP 数据报)    |   FCS   |
 |   (6 字节)    |   (6 字节)    | (2B) |     (46 ~ 1500 字节)       | (4 字节)|
 +---------------+---------------+------+----------------------------+---------+
 |<---------- 帧头 (14 字节) ---------->|                            | 帧尾(4B)|
```

### 2. 各字段深度解析与 408 核心考点

| 字段名称 | 字节长度 | 标准范围/十六进制值 | 408 考场深层考点与微观机制 |
| :--- | :---: | :---: | :--- |
| **目的 MAC 地址** | 6 字节 | 48 位物理地址 | 接收方网卡硬件比对对象（单播、组播或 `FF-FF-FF-FF-FF-FF` 广播）。 |
| **源 MAC 地址** | 6 字节 | 48 位物理地址 | 发送方网卡硬件烧录地址，供交换机自学习建立 CAM 转发表。 |
| **类型 (Type)** | 2 字节 | $\ge \text{0x0600}$ ($1536$) | **上层协议分用标识符**（408 抓包题必背十六进制代码）：<br>• `0x0800`：上层是 **IPv4 数据报**；<br>• `0x0806`：上层是 **ARP 地址解析协议报文**；<br>• `0x86DD`：上层是 **IPv6 数据报**；<br>• `0x8100`：后跟 **802.1Q VLAN Tag 标签**。 |
| **数据载荷 (Data)**| 可变 | **46 ~ 1500 字节** | **核心计算陷阱点**：<br>• **MTU 上限**：1500 字节（网络层 IP 分片基准）；<br>• **下限约束**：受 64 字节最小帧长限制，$64 - 18 = 46\text{ 字节}$。不足 46B 必须硬件填充 0。 |
| **FCS 校验序列** | 4 字节 | CRC-32 校验和 | 覆盖范围：**从目的 MAC 的第 1 字节开始，到数据/填充字段的最后 1 字节为止**（不包括物理层前导码！）。 |

### 3. Ethernet V2 与 IEEE 802.3 帧格式的区分（类型 vs 长度）
- 历史上施乐/DEC/Intel 制定了 Ethernet V2，而 IEEE 制定了 802.3 标准；
- **区分黄金准则**：看第 12、13 字节的值：
  - 若值 $\ge \text{0x0600}$（十进制 1536） $\implies$ 为 **Ethernet V2 帧**，该字段解释为**协议类型（Type）**；
  - 若值 $\le 1500$（十进制） $\implies$ 为 **IEEE 802.3 帧**，该字段解释为**数据载荷长度（Length）**。

## 三、物理信道上的实际线速传输开销（408 物理层扩展计算）

在 408 综合计算题中，常要求计算“主机在物理信道上线速发送帧时的有效吞吐率与实际传输时间”，此时绝不能只算 MAC 帧自身！

```
线路上一个以太网帧的完整物理时空占用:
+-------------------+-----------------------------+-------------------+
| 前导码 + SFD (8B) |    以太网 MAC 帧 (64~1518B)  |  帧间最小间隙 IFG |
| (56bit + 8bit)    | (目的MAC+源MAC+类型+数据+FCS)| (96 bit 时间 = 12B)|
+-------------------+-----------------------------+-------------------+
|<---------------------- 物理线路上实际占用的总时间/总比特 --------------------->|
```

1. **物理层前导码（Preamble）与 SFD**：
   - 7 字节前导码（`10101010...`）：高低交替方波，用于接收端 PHY 芯片的锁相环（PLL）电路与发送端**时钟同步（Clock Synchronization）**；
   - 1 字节帧开始定界符（SFD，`10101011`）：最后连续两个比特 `11` 打破交替节奏，宣告**“下一比特就是目的 MAC 地址的第 1 位！”**
2. **帧间最小间隔（IFG / IPG，Inter-Frame Gap）**：
   - 规定为 **96 个比特时间（Bit Time）**（在 $10\text{ Mbps}$ 下为 $9.6\ \mu\text{s}$，在 $100\text{ Mbps}$ 下为 $0.96\ \mu\text{s}$，在 $1\text{ Gbps}$ 下为 $0.096\ \mu\text{s}$）；
   - 折合字节开销：$\frac{96}{8} = \mathbf{12\text{ 字节}}$；
   - **设计目的**：给接收端网卡腾出清理片上接收缓冲区、重置电路状态的纳秒级恢复时间。

## 四、408 统考真题级 Wireshark 抓包十六进制逆向演练

### 【题型模型：十六进制十六进二逆向解码与上层协议首部剥离】

**【考题背景】**
网络管理员利用抓包分析软件在以太网线路上截获到了一个数据链路层数据帧，其完整十六进制报文（去除物理层前导码）前 40 字节如下所示：
```text
00 1A 2B 3C 4D 5E 00 11 22 33 44 55 08 00 45 00
00 28 00 01 00 00 40 06 7C CD C0 A8 01 02 C0 A8
01 03 04 01 00 50 00 00
```
（注：该帧总捕获长度为 64 字节，后有 24 字节全 0 填充及 4 字节 FCS）。

**【试推导并严密回答以下问题】**：
1. 写出该帧的**目的 MAC 地址**与**源 MAC 地址**；
2. 分析该帧承载的上层网络层协议是什么？由报文中哪个字段判定？
3. 根据封装在 MAC 帧内部的 IPv4 数据报首部，计算该 IP 数据报的**总长度（Total Length）**是多少字节？该帧在数据链路层是否进行了填充（Padding）？若进行了填充，填充了多少字节的 0？
4. 分析并指出该 IP 数据报所承载的**传输层协议类型**是什么？

---

### 【草稿纸执行第一步：画出 14 字节以太网帧头与 IP 首部偏移对照标尺】
```
字节偏移:
00 ~ 05 : 00 1A 2B 3C 4D 5E       ===> 目的 MAC (6 字节)
06 ~ 11 : 00 11 22 33 44 55       ===> 源 MAC (6 字节)
12 ~ 13 : 08 00                   ===> 类型 Type (0x0800 = IPv4 数据报)
-------------------------------------------------------------
14 ~ 33 : 45 00 00 28 00 01 ...   ===> IPv4 首部开始 (固定 20 字节)
  - 14: 45 => 版本 4, 首部长度 5*4 = 20 字节
  - 16~17: 00 28 => IP 总长度 Total Length
  - 23: 06 => 协议 Protocol (0x06 = TCP)
```

---

### 【严密推导过程】

#### 第 1 问：MAC 物理地址逆向提取
- 目的 MAC（前 6 字节）：`00-1A-2B-3C-4D-5E`；
- 源 MAC（第 6 到 11 字节）：`00-11-22-33-44-55`。

#### 第 2 问：网络层协议类型判定
- 第 12、13 字节为 `08 00`，十六进制数值为 `0x0800`；
- 标准协议代码 `0x0800` 明确指明：上层承载的协议为 **IPv4 数据报**。

#### 第 3 问：IP 数据报总长度与数据链路层填充推导
1. 观察进入 IP 首部后的偏移：
   - 字节 14 为 `45`：前半字节 `4` 表示 IPv4，后半字节 `5` 表示首部长度（IHL）为 $5 \times 4\text{ B} = 20\text{ 字节}$；
   - 字节 16、17 为总长度字段：十六进制 `00 28`；
   - 换算为十进制：
     $$\text{Total Length} = 0 \times 16^2 + 2 \times 16^1 + 8 \times 16^0 = 32 + 8 = \mathbf{40\text{ 字节}}$$
2. **数据链路层填充判定**：
   - 该 IP 数据报总长度仅为 **40 字节**；
   - 但以太网数据链路层的最小数据载荷限制为 **46 字节**（以确保整帧达到 64 字节）；
   - $40\text{ 字节} < 46\text{ 字节}$，因此数据链路层在发送时**必须进行了填充（Padding）**！
   - **填充的零字节数**：
     $$\text{Padding} = 46\text{ B} - 40\text{ B} = \mathbf{6\text{ 字节}}$$
   - 接收端网络层解封装时，根据 IP 首部中的总长度 `40` 字节，自动将末尾的 6 字节填充 0 丢弃。

#### 第 4 问：传输层协议逆向分析
- IP 首部的协议字段位于 IP 首部的第 9 字节（整个捕获帧的第 23 字节偏移）；
- 读取该字节数值为 `06`（十六进制 `0x06`）；
- 标准传输层协议号 `0x06` 对应 **TCP 协议**（若为 `0x11` 则为 UDP，若为 `0x01` 则为 ICMP）。

## 五、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：计算整帧大小时遗漏 18 字节固定开销**
> - **408 经典计算失误**：题目说“上层 IP 数据报长 1000 字节，求以太网 MAC 帧长”。很多考生直接写 1000 字节。
> - **铁律警示**：MAC 帧长 = 数据长 + 帧头（14B） + 帧尾 FCS（4B） = $1000 + 18 = \mathbf{1018\text{ 字节}}$！固定开销 **18 字节** 必须刻入骨髓！

> [!CAUTION]
> **陷阱 2：把物理层前导码（8B）算入 MAC 帧长**
> - **审题核心**：
>   - 问“以太网 MAC 帧长”：取值范围严格为 **64 ~ 1518 字节**（绝不包含前导码）；
>   - 问“线路上发送该帧所占用的总物理比特/时间”：必须额外加上 **8 字节前导码**（甚至题目要求加上 12 字节 IFG）！

### 2. 考场核心记忆桩
- **“六目六源二类型，头十四尾四校验，固定开销十八整”**：MAC 帧头尾尺寸口诀。
- **“零八零零是网络，零八零六是 ARP，四十六到千五百”**：类型与数据范围秒杀桩。
