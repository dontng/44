# 3.4.2 （3）共享式以太网的退避算法和信道利用率

## 一、截断二进制指数退避算法（Truncated Binary Exponential Backoff）

当检测到冲突后，发送方停止发送，并按照**截断二进制指数退避**算法决定等待多长时间后重试：

### 算法规则

设这是第 **k** 次冲突（k = 1, 2, 3, …）：

1. 从集合 $\{0, 1, 2, \ldots, 2^{\min(k,10)} - 1\}$ 中**随机选取**一个整数 $r$；
2. 等待 $r$ 个**争用期（时隙，51.2 μs）**后重新监听并尝试发送；
3. 若第 **16 次**冲突后仍失败，**放弃发送**，向上层报告错误。

### 示例

| 冲突次数 k | 随机范围 | 最大等待时隙 |
|---|---|---|
| 1 | {0, 1} | 1 |
| 2 | {0, 1, 2, 3} | 3 |
| 3 | {0, 1, …, 7} | 7 |
| 10 | {0, 1, …, 1023} | 1023 |
| 11～15 | {0, 1, …, 1023} | 1023（上限截断） |
| 16 | — | 放弃，报错 |

### 设计思想

- **指数增长退避范围**：随冲突次数增加，等待时间的随机范围指数扩大，使冲突严重时各站点自动"分散"，降低再次冲突概率；
- **截断（Truncated）**：退避范围上限截断在 1023（即 $2^{10}-1$），防止等待时间过长；
- **最多 16 次**：限制重试次数，避免无限等待，16 次失败说明网络极度拥塞，交由上层处理。

> 考点：k 次冲突随机选 r ∈ {0, …, min(2^k, 1024)-1}；放弃阈值为 **16 次**。注意"第10次及以后上限都是1023"。

## 二、以太网信道利用率

### 理论分析

在**无冲突**情况下，发送方的信道利用率为 100%。但冲突会浪费信道时间，实际有效吞吐量低于理论带宽。

设：
- $T_0$：帧发送时间（帧长 / 数据率）
- $\tau$：端到端单向传播时延
- $a = \tau / T_0$：传播时延与帧发送时间之比

理想（无冲突）信道利用率上界：

$$\eta_{max} \approx \frac{T_0}{T_0 + \tau} = \frac{1}{1 + a}$$

（发送完一帧后，至少还需等 $\tau$ 时间确认无冲突，才能开始下一帧）

### 实践规律

- 以太网轻负载时效率较高；
- 当站点数增多、负载加重时，冲突频率升高，有效吞吐量显著下降；
- 实际以太网在负载约 30%～40% 时信道利用率最佳，更高负载反而因大量冲突导致吞吐量下降；
- 这正是以太网**适合轻到中等负载**，不适合高负载长距离链路的原因，也是交换式以太网兴起的动力。

## 三、信道利用率公式（考试常考）

对于 **停止等待型**（每帧发完等确认，类似 SW-ARQ）：

$$\eta = \frac{T_0}{T_0 + 2\tau} = \frac{1}{1 + 2a}$$

这与 SW-ARQ 的效率公式一致，$a = \tau/T_0$，$a$ 越大（传播时延相对帧发送时间越长），效率越低。

> 考点：计算题常给出帧长、数据率、传播距离，要求算信道利用率。步骤：① 算 $T_0$（帧长/速率）→ ② 算 $\tau$（距离/光速）→ ③ 算 $a = \tau/T_0$ → ④ 代入 $\eta = 1/(1+2a)$。
