# 3.4.5-（1）在数据链路层扩展以太网-网桥的主要结构和基本工作原理

> **本节在 408 中的定位**：网桥（Bridge）是局域网由“单一冲突域的物理层共享”跨越到“多冲突域的数据链路层隔离”的关键技术分水岭，是以太网交换机（多端口网桥）的前身。408 统考对网桥的考查极具实战性，核心命题点集中在：**“网桥根据 MAC 地址表进行过滤（Filtering）、转发（Forwarding）与盲目泛洪（Flooding）的微观判决逻辑”**、**“网桥为什么能够隔离冲突域但无法隔离广播域”**，以及**“透明网桥与源路由网桥的设计哲学分歧”**。

---

## 一、第一性原理与设计动因：为什么需要网桥？

### 1. 终结物理层扩展的“冲突域雪崩”
在前一小节（3.4.4）中我们看到，使用集线器（Hub）将多个网段相连，会导致冲突域急剧扩大，全网主机共同争用一个信道，吞吐率急剧暴跌。
- **根本矛盾**：
  在实际局域网中，绝大多数局域网通信发生在“同一个工作组内部”（例如财务科内部传账单、研发部内部传代码）。
  如果研发部的代码通信必须穿透集线器广播给财务科，导致财务科的电脑也无法发报，这在工程上是极度荒谬的！
- **网桥的破局哲学：建立“海关门禁”**
  在两个网段之间架设一台智能设备——**网桥（Bridge）**：
  - 如果网段 1 内部的 A 发给 B，网桥把这封信在门口拦下（**过滤丢弃**），绝不放行给网段 2，网段 2 此时可以同时自由通信；
  - 只有当网段 1 的 A 确实要发给网段 2 的 C 时，网桥才将帧放行过去（**精准转发**）！

```
          [ 网段 1 (冲突域 1) ]                  [ 网段 2 (冲突域 2) ]
        [ Host A ]    [ Host B ]              [ Host C ]    [ Host D ]
            \            /                        \            /
         ====+==========+==== (总线 1)         ====+==========+==== (总线 2)
                     |                                     |
                     +-------------[ 网 桥 ]---------------+
                                (端口 1)   (端口 2)
                                 - 隔离两个冲突域!
                                 - A 与 B 通信，C 与 D 可同时并发通信!
```

## 二、微观结构：网桥的硬件组成与转发表查找机制

### 1. 网桥的核心硬件架构

```
+-------------------------------------------------------------------------------+
|                           网桥内部结构 (数据链路层 L2)                           |
|                                                                               |
|   +-----------------------+               +-------------------------------+   |
|   | 端口 1 接口与缓冲队列  |               | 端口 2 接口与缓冲队列          |   |
|   |  - 独立 MAC 控制器    |               |  - 独立 MAC 控制器            |   |
|   |  - 独立收发 FIFO 队列 |               |  - 独立收发 FIFO 队列         |   |
|   +-----------+-----------+               +---------------+---------------+   |
|               |                                           |                   |
|               +-------------> [ 转 发 引 擎 ] <------------+                   |
|                               (查表判决与过滤)                                 |
|                                      |                                        |
|                         [ 转发表 / MAC 地址映射表 ]                           |
|                         +-----------------------+                             |
|                         |  MAC 地址  | 出口端口  |                             |
|                         |------------+----------|                             |
|                         |   MAC_A    |  Port 1  |                             |
|                         |   MAC_C    |  Port 2  |                             |
|                         +-----------------------+                             |
+-------------------------------------------------------------------------------+
```

- **存储转发（Store-and-Forward）机制**：
  网桥收到一个帧后，先完整接收存入缓冲区，进行 CRC 校验。如果帧受损（残帧或 CRC 错），直接丢弃；若校验正确，提取帧头中的**目的 MAC 地址**，在转发表中查找。

### 2. 帧处理的三大判决分支（408 核心流程图）

当网桥从端口 $X$ 接收到一个校验正确的以太网数据帧，其目的 MAC 为 $\text{MAC}_{\text{dst}}$ 时，网桥严格执行以下三步判决：

```
                      从端口 X 收到数据帧
                               |
                               v
                     在转发表中查找 MAC_dst
                               |
             +-----------------+-----------------+
             | 查到了对应端口 Y                  | 表中未找到 MAC_dst
             v                                   v
       Y 是否等于 X ?                       【盲目泛洪 (Flooding)】
       /          \                         向除了端口 X 之外的所有其他
     是            否                       有效端口复制广播该帧！
     v              v
【过滤 (Filter)】  【单播转发 (Forward)】
直接丢弃该帧!       将该帧仅从端口 Y 发出!
(因为目的与源在     (精准投递到目标网段)
 同一网段，对端
 已经在线路上收到了)
```

1. **同端口过滤（Filtering）**：
   若查表发现出口端口 $Y == X$（入端口和出端口相同），说明目标主机与发送主机在同一个网段。当发送主机在总线上发信号时，目标主机早就在同网段总线上自行接收了，网桥**直接把该帧从缓冲区扔掉**，防止垃圾通信量外溢污染其他网段！
2. **跨端口精准转发（Forwarding）**：
   若查表发现出口端口 $Y \neq X$，网桥将该帧放入端口 $Y$ 的发送队列，按照端口 $Y$ 的介质访问控制规则发出；
3. **未知单播泛洪（Flooding）**：
   若转发表中根本查不到 $\text{MAC}_{\text{dst}}$，网桥不知道目标在哪，为了保证数据不丢，网桥采取保守策略：**向除了入端口 $X$ 以外的所有其他端口盲目复制广播（泛洪）**！

## 三、透明网桥 vs 源路由网桥（408 概念辨析）

在 IEEE 802 标准化进程中，曾存在两种截然不同的网桥设计哲学：

| 对比维度 | **透明网桥（Transparent Bridge，IEEE 802.1D）** | **源路由网桥（Source Routing Bridge，IEEE 802.5）** |
| :--- | :--- | :--- |
| **标准与起源** | 以太网标准（主流，现代交换机的鼻祖） | 令牌环网标准（IBM 主推，现已基本淘汰） |
| **对主机的透明性** | **完全透明**！主机完全不知道网桥的存在，发帧时只管写最终目的 MAC。 | **不透明**！源主机发帧时，必须在帧头里明确写入到达目的地的完整路由路径！ |
| **路由决策者** | **网桥自己**（通过自学习算法动态学习建立转发表） | **源主机自己**（源主机在发数据前，先发探索帧探测最佳路由） |
| **转发表维护** | 逆向自学习、逆向学习源 MAC 地址、老化定时器刷新 | 网桥不做自学习，网桥只看帧头中包含的明确端口指引顺序转发 |

## 四、408 统考真题级场景分析与转发/过滤演算

### 【题型模型：网桥多端口网络中的过滤与转发状态跟踪】

**【考题背景】**
某网络拓扑如下图所示，双端口网桥 B1 连接网段 1 和网段 2：
- 网段 1 上连接主机 H1（`MAC_1`）和主机 H2（`MAC_2`）；
- 网段 2 上连接主机 H3（`MAC_3`）和主机 H4（`MAC_4`）；
- 网桥 B1 的端口 1 连网段 1，端口 2 连网段 2。
当前网桥 B1 的转发表中已经稳定学习到如下表项：
```
+-------------+----------+
|  MAC 地址   |   端口   |
+-------------+----------+
|    MAC_1    |    1     |
|    MAC_3    |    2     |
+-------------+----------+
```

```
[ H1: MAC_1 ]       [ H2: MAC_2 ]          [ H3: MAC_3 ]       [ H4: MAC_4 ]
      \                  /                       \                  /
    ===+================+=== 网段 1            ===+================+=== 网段 2
               |                                           |
               +---------------[ 网桥 B1 ]-----------------+
                            (端口 1)   (端口 2)
```

**【试跟踪推导以下连续事件中，网桥 B1 的处理动作与各网段的流量情况】**：
1. **事件 1**：主机 H1 向主机 H2 发送一个单播帧（目的 MAC 为 `MAC_2`）；
2. **事件 2**：主机 H3 向主机 H1 发送一个单播帧（目的 MAC 为 `MAC_1`）；
3. **事件 3**：主机 H2 向网络发送一个广播帧（目的 MAC 为 `FF-FF-FF-FF-FF-FF`）。

---

### 【严密推导过程】

#### 事件 1 推导：未知单播帧的泛洪与网段影响
1. H1 发出目的为 `MAC_2` 的单播帧，该信号在网段 1 广播；
2. 主机 H2 直接在网段 1 上接收到该帧；
3. 网桥 B1 从端口 1 接收到该帧：
   - 提取目的 MAC 为 `MAC_2`；
   - 查转发表：表中**没有 `MAC_2` 的条目**（未知单播）；
   - **网桥 B1 执行动作**：**向除端口 1 以外的所有端口泛洪**，即从端口 2 发出该帧！
4. 结果：该帧外溢到网段 2，网段 2 上的 H3 和 H4 均收到该帧并在网卡层因 MAC 不匹配而丢弃。

#### 事件 2 推导：已知单播帧的跨端口精准转发
1. H3 发出目的为 `MAC_1` 的单播帧，该信号在网段 2 扩散；
2. 网桥 B1 从端口 2 接收到该帧：
   - 提取目的 MAC 为 `MAC_1`；
   - 查转发表：表中记录 `MAC_1` 对应端口为 **1**；
   - 比较入端口与出端口：入端口为 2，出端口为 1（$1 \neq 2$）；
   - **网桥 B1 执行动作**：**精准转发**，将该帧放入端口 1 的发送队列并从端口 1 发出！
3. 网段 1 上的主机 H1 顺利接收该帧；网段 2 上的 H4 没有参与通信。

#### 事件 3 推导：广播帧的无条件穿透
1. H2 发出广播帧（目的为全 F）；
2. 网段 1 上的 H1 接收到该广播帧；
3. 网桥 B1 从端口 1 收到该广播帧：
   - 目的 MAC 为广播地址，**网桥绝不隔离广播域**！
   - **网桥 B1 执行动作**：无条件将广播帧**从端口 2 转发出去**！
4. 网段 2 上的 H3 和 H4 均接收并处理该广播帧。

## 五、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：以为“过滤”是指把坏帧给丢了**
> - **408 专业术语陷阱**：在网桥理论中，“过滤（Filtering）”具有专门的协议定义：**指当入端口与转发表中的目标出端口完全相同时，网桥主动放弃转发、丢弃该帧的动作！** 其目的是“阻止同网段内部通信流量泄漏到其他网段”。

> [!CAUTION]
> **陷阱 2：误以为网桥查不到 MAC 地址时会“丢弃”**
> - **大题极高频错误**：很多考生做大题写“转发表中没有目的 MAC，网桥不知道发给谁，所以丢弃”——**大错特错！**
> - 查不到目的 MAC 时，网桥绝不能随便丢弃，必须执行**“泛洪（Flooding）”**，除接收端口外全部转发，直到目标主机回复响应时被网桥自学习记录！

### 2. 考场核心记忆桩
- **“同端口则过滤，异端口则转发，找不到就泛洪，全一广播全放行”**：网桥转发表处理的四路判决口诀。
- **“网桥隔断冲突域，广播穿透拦不住”**：数据链路层设备隔离冲突域，绝不隔离广播域。
