# 3.4.5-（1）在数据链路层扩展以太网-网桥的主要结构和基本工作原理

---

## 1. 动因与架构转变：从物理层共享到链路层隔离

使用物理层设备（集线器、中继器）扩展以太网会导致全网合并为一个庞大的碰撞域，引发信道吞吐量急剧恶化。

在实际局域网中，绝大多数局域网通信发生在工作组内部（例如同一部门主机之间的数据交换）：
- 若依赖物理层扩展，部门内部的通信信号会盲目广播扩散至全网其他部门，导致其他部门即使没有对外通信需求，信道也被迫占用并面临碰撞风险；
- **网桥（Bridge）的核心设计思想**：工作在**数据链路层（第 2 层）**，根据 MAC 帧的目的物理地址对收到的帧进行**转发与过滤**，将局部通信流量严格限制在本地网段内部，实现不同网段之间的并发通信。

```text
          [ 网段 1 (碰撞域 1) ]                  [ 网段 2 (碰撞域 2) ]
        [ Host A ]    [ Host B ]              [ Host C ]    [ Host D ]
            \            /                        \            /
         ====+==========+==== (总线 1)         ====+==========+==== (总线 2)
                     │                                     │
                     └─────────────[ 网 桥 ]───────────────┘
                                (端口 1)   (端口 2)
                                 - 隔离两个碰撞域
                                 - A 与 B 通信，C 与 D 可并发独立通信
```

---

## 2. 网桥的工作过程与帧处理规则

网桥每个端口均配置独立的帧缓冲区：
1. **完整帧接收与差错检验**：端口接收完整的以太网帧存入缓冲区，计算 CRC。若帧长度小于 64 字节（残帧）或 CRC 校验出错，网桥**直接丢弃**该帧；
2. **查表决策**：校验通过后，读取目的 MAC 地址并在转发表（MAC 地址表）中查找对应的出口端口。

```text
                      从端口 X 收到合法数据帧
                                 │
                                 ▼
                     在转发表中检索目的 MAC 地址
                                 │
              ┌──────────────────┴──────────────────┐
              │ 命中了表项，对应出口端口为 Y         │ 表中未找到目的 MAC
              ▼                                     ▼
         Y 是否等于 X ?                         【泛洪转发 (Flooding)】
         /          \                           向除端口 X 之外的所有其他
       是            否                         有效端口复制并转发该帧
       ▼              ▼
【过滤 (Filter)】  【单播转发 (Forward)】
直接丢弃该帧!       将该帧仅从端口 Y 发送出去
(目的主机与源主机   (跨网段精准单播投递)
 处于同一网段，本地
 已在总线上直接接收)
```

1. **同端口过滤（Filtering）**：
   若查表得到的目标出端口 $Y = X$（即入端口与出端口完全相同），表明目标主机与发送主机处于同一个物理网段。源主机在总线上发送时，目标主机已在本地线路上直接接收，网桥在内部**直接丢弃**该帧，阻断无用流量向其他网段外溢；
2. **跨端口单播转发（Forwarding）**：
   若查表得到的目标出端口 $Y \neq X$，网桥将该帧放入端口 $Y$ 的发送队列，由端口 $Y$ 独立发出；
3. **未知单播泛洪（Flooding）**：
   若转发表中未找到目的 MAC 地址，网桥无法确定目标位置，采取保全策略：**向除入端口 $X$ 外的所有其他端口复制转发**。

## 3. 透明网桥与源路由网桥的设计对比

| 对比维度 | **透明网桥（Transparent Bridge，IEEE 802.1D）** | **源路由网桥（Source Routing Bridge，IEEE 802.5）** |
| :--- | :--- | :--- |
| **应用背景** | 以太网标准体系（主流架构，以太网交换机的前身） | 令牌环网体系（早期历史技术） |
| **主机的透明性** | **完全透明**：终端主机完全不知道网桥的存在，发帧时仅填写最终目的 MAC 地址。 | **不透明**：源主机发帧时，必须在帧首部中明确指定帧经过的所有网桥和网段路径。 |
| **路由决策主体** | **网桥自身**：依靠转发表自学习与动态更新机制决策。 | **源主机自身**：源主机在正式传输前主动发送探索帧（Discovery Frame）探测最优路径。 |
| **网桥硬件开销** | 需维护庞大的 MAC 转发表及老化定时器。 | 网桥无需转发表，仅按帧头中携带的路由信息逐跳转发。 |
