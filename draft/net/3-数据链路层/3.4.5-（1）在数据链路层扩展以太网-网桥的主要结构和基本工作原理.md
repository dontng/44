# 3.4.5-（1）在数据链路层扩展以太网-网桥的主要结构和基本工作原理

---

## 1. 动因与架构转变：从物理层共享到链路层隔离

使用物理层设备（集线器、中继器）扩展以太网会导致全网合并为一个庞大的冲突域，引发信道吞吐率雪崩。

### 1.1 局域网流量的局部性原理

在实际局域网环境中，绝大部分网络通信发生在工作组内部（例如同一部门主机之间的数据交换）。
- 若依赖物理层扩展，部门内部的通信信号会盲目广播扩散至全网其他部门，导致其他部门即使没有对外通信需求，信道也被迫占用并面临碰撞风险；
- **网桥（Bridge）的核心设计思想**：在不同网段之间建立数据链路层边界，通过识别 MAC 帧地址进行**智能过滤与定向转发**，将局部通信流量严格限制在本地网段内部，实现不同网段之间的并发通信。

```
          [ 网段 1 (冲突域 1) ]                  [ 网段 2 (冲突域 2) ]
        [ Host A ]    [ Host B ]              [ Host C ]    [ Host D ]
            \            /                        \            /
         ====+==========+==== (总线 1)         ====+==========+==== (总线 2)
                     |                                     |
                     +-------------[ 网 桥 ]---------------+
                                (端口 1)   (端口 2)
                                 - 隔离两个冲突域
                                 - A 与 B 通信，C 与 D 可并发独立通信
```

## 2. 网桥的硬件结构与核心工作流程

网桥在 OSI 体系结构中归属于 **数据链路层（第 2 层，L2）** 设备：

```
+-------------------------------------------------------------------------------+
|                           网桥内部结构 (数据链路层 L2)                           |
|                                                                               |
|   +-----------------------+               +-------------------------------+   |
|   | 端口 1 接口与缓冲队列  |               | 端口 2 接口与缓冲队列          |   |
|   |  - 独立 MAC 控制器    |               |  - 独立 MAC 控制器            |   |
|   |  - 独立收发 FIFO 队列 |               |  - 独立收发 FIFO 队列         |   |
|   +-----------+-----------+               +---------------+---------------+   |
|               |                                           |                   |
|               +-------------> [ 转 发 引 擎 ] <------------+                   |
|                               (查表判决与过滤)                                 |
|                                      |                                        |
|                         [ 转发表 / MAC 地址映射表 ]                           |
|                         +-----------------------+                             |
|                         |  MAC 地址  | 出口端口  |                             |
|                         |------------+----------|                             |
|                         |   MAC_A    |  Port 1  |                             |
|                         |   MAC_C    |  Port 2  |                             |
|                         +-----------------------+                             |
+-------------------------------------------------------------------------------+
```

### 2.1 存储转发（Store-and-Forward）机制

网桥每个端口均配置独立的 MAC 控制器与 FIFO 缓冲区：
1. **完整帧接收与 CRC 校验**：端口接收完整的以太网帧并存入缓冲区，硬件计算 FCS；若帧长度小于 64 字节（残帧）或 CRC 校验出错，网桥**直接丢弃**，防止损坏帧跨网段扩散；
2. **查表决策**：校验通过后，解析目的 MAC 地址并在转发表中检索出端口。

### 2.2 帧处理的三大判决分支

当网桥从入端口 $X$ 接收到一个校验无误的数据帧（目的 MAC 记为 $\text{MAC}_{\text{dst}}$）时，执行以下判决：

```
                      从入端口 X 收到合法数据帧
                                 |
                                 v
                       在转发表中检索 MAC_dst
                                 |
              +------------------+------------------+
              | 命中了表项，对应出口端口为 Y         | 表中未检索到 MAC_dst
              v                                     v
         Y 是否等于 X ?                         【泛洪转发 (Flooding)】
         /          \                           向除端口 X 之外的所有其他
       是            否                         有效端口复制并转发该帧
       v              v
【过滤 (Filter)】  【精准转发 (Forward)】
直接丢弃该帧!       将该帧送入端口 Y 发送队列并发出
(目的节点与源节点   (跨网段精准单播投递)
 处于同一网段，本地
 已在总线上直接接收)
```

1. **同端口过滤（Filtering）**：
   若查表得到的目标出端口 $Y = X$（即入端口与出端口完全相同），表明目标主机与源主机处于同一个物理网段。源主机在总线上发送时，目标主机已在本地线路上直接接收，网桥在内部**直接丢弃**该帧，阻断无用流量向其他网段外溢；
2. **跨端口精准转发（Forwarding）**：
   若查表得到的目标出端口 $Y \neq X$，网桥将该帧放入端口 $Y$ 的发送队列，由端口 $Y$ 的 MAC 控制器独立执行介质访问控制后发出；
3. **未知单播泛洪（Flooding）**：
   若转发表中未命中 $\text{MAC}_{\text{dst}}$，网桥无法确定目标位置，采取保全策略：**向除入端口 $X$ 外的所有其他端口复制转发**。

## 3. 透明网桥与源路由网桥的设计对比

| 对比维度 | **透明网桥（Transparent Bridge，IEEE 802.1D）** | **源路由网桥（Source Routing Bridge，IEEE 802.5）** |
| :--- | :--- | :--- |
| **应用背景** | 以太网标准体系（主流架构，交换机的前身） | 令牌环网体系（Token Ring，早期历史技术） |
| **主机的透明性** | **完全透明**：终端主机无需感知网桥存在，发帧时仅填写最终目的 MAC 地址。 | **不透明**：源主机发帧时，必须在帧首部中明确指定帧经过的所有网桥和网段路径。 |
| **路由决策主体** | **网桥自身**：依靠转发表自学习与动态更新机制决策。 | **源主机自身**：源主机在正式传输前主动发送探索帧（Discovery Frame）探测最优路径。 |
| **网桥硬件开销** | 需维护庞大的 MAC 转发表及老化定时器。 | 网桥无需转发表，仅按帧头中携带的路由信息逐跳转发。 |

## 4. 典型问题分析

### 题目：双端口网桥转发表状态与转发/过滤行为推导

某网络拓扑中，双端口网桥 B1 连接网段 LAN-1 与 LAN-2：
- LAN-1 上挂接主机 H1（MAC 地址 `MAC_1`）与 H2（MAC 地址 `MAC_2`）；
- LAN-2 上挂接主机 H3（MAC 地址 `MAC_3`）与 H4（MAC 地址 `MAC_4`）；
- 网桥 B1 的端口 1 连接 LAN-1，端口 2 连接 LAN-2。
当前网桥 B1 的转发表中已包含以下表项：

```
+-------------+----------+
|  MAC 地址   | 出口端口 |
+-------------+----------+
|    MAC_1    |    1     |
|    MAC_3    |    2     |
+-------------+----------+
```

```
[ H1: MAC_1 ]       [ H2: MAC_2 ]          [ H3: MAC_3 ]       [ H4: MAC_4 ]
      \                  /                       \                  /
    ===+================+=== LAN-1             ===+================+=== LAN-2
               |                                           |
               +---------------[ 网桥 B1 ]-----------------+
                            (端口 1)   (端口 2)
```

**问题**：
推导下列三个独立通信事件发生时，网桥 B1 的具体动作及各网段的流量传播情况：
1. 主机 H1 向主机 H2 发送一个单播帧（目的 MAC 为 `MAC_2`）；
2. 主机 H3 向主机 H1 发送一个单播帧（目的 MAC 为 `MAC_1`）；
3. 主机 H2 发送一个广播帧（目的 MAC 为 `FF-FF-FF-FF-FF-FF`）。

---

### 推导过程

#### 1. 事件 1（H1 发往 H2，目的 MAC 为 `MAC_2`）
1. H1 发出的信号在 LAN-1 总线上扩散，H2 在本地线路上直接接收到该信号；
2. 网桥 B1 从端口 1 接收该帧：
   - 提取目的 MAC 为 `MAC_2`；
   - 检索转发表：表中未找到 `MAC_2` 的对应记录（未知单播）；
   - **网桥动作**：执行**泛洪（Flooding）**，将该帧从除入端口以外的所有端口（端口 2）复制转发至 LAN-2；
3. LAN-2 上的主机 H3 与 H4 均收到该帧，因目的 MAC 不匹配在网卡层丢弃。

#### 2. 事件 2（H3 发往 H1，目的 MAC 为 `MAC_1`）
1. H3 发出的信号在 LAN-2 总线上扩散；
2. 网桥 B1 从端口 2 接收该帧：
   - 提取目的 MAC 为 `MAC_1`；
   - 检索转发表：命中记录 `MAC_1 -> 端口 1`；
   - 比较端口：入端口为 2，目标出端口为 1（$1 \neq 2$）；
   - **网桥动作**：执行**精准单播转发**，将该帧放入端口 1 的发送队列并向 LAN-1 发出；
3. LAN-1 上的主机 H1 顺利接收该帧；LAN-2 上的 H4 不受跨网段通信干扰。

#### 3. 事件 3（H2 发送广播帧）
1. H2 发出的信号在 LAN-1 上扩散，H1 接收并处理；
2. 网桥 B1 从端口 1 接收该广播帧：
   - 目的 MAC 为广播地址（全 1）；
   - **网桥动作**：数据链路层设备无法隔离广播域，网桥无条件将该帧**从端口 2 复制并转发**至 LAN-2；
3. LAN-2 上的主机 H3 与 H4 均接收并处理该广播帧。
