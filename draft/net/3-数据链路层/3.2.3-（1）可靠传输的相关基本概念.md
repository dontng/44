# 3.2.3-（1）可靠传输的相关基本概念

---

## 1. 为什么需要可靠传输机制

物理信道提供的比特传输服务是不可靠的，存在比特翻转、信号衰减和缓冲区溢出导致的丢帧。

### 1.1 自动重传请求（ARQ）的基本思想

差错检验技术（如 CRC）只能发现受损的帧并将其丢弃，无法凭空找回丢失的数据。
- **自动重传请求（ARQ, Automatic Repeat reQuest）**：
  发送端在发出数据帧后必须暂时保留该帧的副本，并启动一个重传定时器；接收端收到正确的帧后向发送端回复一个**确认（ACK）**；如果发送端在定时器超时之前没有收到确认，就自动重新发送该帧。

### 1.2 链路层可靠传输与传输层（TCP）可靠传输的分工

传输层的 TCP 协议已经提供了端到端的可靠传输保证，为什么有些数据链路层依然需要提供可靠传输？
- **极低误码率链路（如有线光纤与双绞线）**：
  通信质量非常好，极少发生差错。若在每一跳链路层都实现复杂的确认重传机制，会徒增网络设备的芯片处理开销与传输延迟。因此现代有线以太网在链路层不提供可靠传输，偶发的丢帧交由端到端的 TCP 协议负责重传；
- **高误码率链路（如无线信道、卫星通信）**：
  无线信道容易受到空间衰落和多径干扰，误码率很高。如果链路层不纠错，大量数据包在无线链路上丢失，端到端 TCP 经过极长的往返时延（RTT）超时后才会重传，并且 TCP 会将丢包误判为网络拥塞而大幅降低传输速率，导致整体吞吐量严重下降。此时在无线链路层实现本地快速重传，可以就近修复差错，避免触发上层降速。

---

## 2. ARQ 协议的三大基本要素

要实现自动重传请求，必须依靠三个核心机制的相互配合：

### 2.1 确认机制（ACK / NAK）

接收端通过反向信道告知发送端数据的接收情况：
- **肯定确认（ACK）**：
  - **逐帧确认**：接收端每正确接收一个特定序号的帧，就回复一个对应的 ACK；
  - **累计确认（Cumulative ACK）**：接收端回复一个确认号 $n$，表示**序号为 $n$ 以及 $n$ 以前的所有数据帧均已正确接收，期待接收序号为 $n+1$ 的帧**。累计确认具备天然的抗 ACK 丢失能力（若前面的某个 ACK 在半路丢失，只要后面的 ACK 成功送达，就能隐式覆盖确认）；
- **否认确认（NAK）**：显式通知发送方某个序号的帧未正确收到，请求立即重发；
- **捎带确认（Piggybacking）**：在双向通信中，接收端把要回复的确认信息顺便放在自己发往对方的数据帧首部中带过去，无需单独占用信道发送一个专门的确认控制帧。

### 2.2 超时重传与重传定时器

若数据帧在传输中丢失，或者确认帧在返回途中丢失，发送方和接收方就会陷入无限等待的死锁状态。
- 发送方必须维护一个**重传定时器（Retransmission Timer）**；
- 发送端每发送一个帧就启动定时器。若在定时器超时前收到了确认，就关闭定时器；若直到超时仍未收到确认，发送方就自动重新发送该帧。
- **重传时间的选择**：重传时间一般应当略大于“一个数据帧的往返时间（RTT）加上节点处理时间”，既不能太短（避免产生不必要的重复重传），也不能太长（避免信道过长时间闲置）。

### 2.3 帧序号机制

为了防止确认帧在网络中延迟到达引发的重传混乱，数据帧和确认帧都必须进行**编号（Sequence Number）**：
- 如果没有序号，当接收方收到一个重传的帧时，无法分辨它是因前一个确认丢失而重发的旧帧，还是发送方发出的下一个新帧；
- 序号使得接收方能够明确识别出重复帧并将其果断丢弃，同时补发确认。
