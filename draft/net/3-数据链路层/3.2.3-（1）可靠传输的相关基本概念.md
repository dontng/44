# 3.2.3 （1）可靠传输的相关基本概念

## 一、为什么需要可靠传输？

物理信道存在噪声，导致帧可能出现：
- **帧出错（比特差错）**：某些比特翻转，CRC 可以检测出来；
- **帧丢失**：整个帧消失（如噪声过强导致帧无法识别），接收方根本感知不到；
- **帧乱序**：帧到达顺序与发送顺序不同（在多路径网络中）。

仅靠差错检测（CRC）只能"发现"出错的帧并丢弃，但无法自动恢复——如果丢掉了就永久丢失了。**可靠传输**通过自动重传机制保证所有帧最终都能被正确接收。

## 二、并非所有链路都需要可靠传输

| 链路类型 | 是否实现可靠传输 | 原因 |
|---|---|---|
| 以太网（有线） | **否** | 误码率极低，差错处理交给上层（TCP） |
| Wi-Fi（802.11） | **是** | 无线信道误码率高，帧级重传更高效 |
| PPP | 否（基本版） | 依赖上层保证 |
| 卫星链路 | 是 | 传播时延大、误码率高 |

> 考点：有线以太网**不提供可靠传输**，这是高频选择题考点，不要与 TCP 可靠传输混淆。

## 三、ARQ（Automatic Repeat Request，自动重传请求）

ARQ 是实现可靠传输的核心机制，包含三个要素：

### 1. 确认（ACK）与否认（NAK）
- **ACK（Acknowledgement）**：接收方成功收到帧后，向发送方返回确认。
- **NAK（Negative Acknowledgement）**：接收方检测到帧出错，向发送方请求重传（部分协议使用，部分协议用超时隐式代替 NAK）。

### 2. 序号（Sequence Number）
帧必须编号，原因：
- 发送方重传时，接收方需知道这是重传帧还是新帧（避免重复接收）；
- 接收方发出的 ACK 需指明确认的是哪一帧。

序号位数 n 决定序号空间大小 2ⁿ，具体分配给发送/接收窗口的方案因协议而异（见 3.2.3(2)(3)(4)）。

### 3. 超时重传（Timeout & Retransmission）
发送方发出帧后启动定时器，若在规定时间内未收到 ACK，则**超时重传**该帧。定时器时间 = 估计的往返时延（RTT）+ 一定余量。

## 四、流水线（Pipelining）概念

停止等待（SW）每次只发一帧等一个 ACK，效率低下；**流水线**允许发送方连续发出多个帧而不等待每帧的确认，发送窗口大小决定最多有多少帧在"飞行中（in-flight）"。

后续 GBN 和 SR 协议都是流水线 ARQ 的具体实现，核心差异在于出错时**重传哪些帧**和**接收窗口大小**。

## 五、可靠传输的层次关系

```
应用层
运输层   ← TCP 提供端到端可靠传输（跨越多个链路和路由器）
网络层
数据链路层 ← 部分协议提供逐跳可靠传输（仅本段链路）
物理层
```

数据链路层的可靠传输和 TCP 的可靠传输是**不同层次、独立工作**的，二者可以同时存在。即使数据链路层已保证逐跳可靠，TCP 仍需端到端确认，因为路由器可能因拥塞丢弃分组。
