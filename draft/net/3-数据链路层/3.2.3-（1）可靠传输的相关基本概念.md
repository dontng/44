# 3.2.3-（1）可靠传输的相关基本概念

> **本节在 408 中的定位**：本节是滑动窗口与 ARQ 可靠传输协议簇的“理论基石”。408 统考历年对可靠传输的考查，不仅要求会计算信道利用率、吞吐率、窗口上限，更要求深刻理解**“确认机制（累计确认 vs 选择确认）”、“超时重传定时器设计”与“序号回绕与死锁防范”**的本质原理。本节打通后续停止-等待（SW）、回退N帧（GBN）、选择重传（SR）的所有核心概念脉络。

---

## 一、第一性原理与设计动因：为什么需要 ARQ 可靠传输？

### 1. 物理不可靠向逻辑可靠的跃迁
物理世界中，信道传输不可避免地面临三大约束：
1. **比特翻转（Bit Error）**：虽然 CRC 检错率高达 $99.999999\%$，但检测出错误后，硬件只能做一件事——**直接把受损帧扔进垃圾桶**；
2. **帧丢失（Frame Loss）**：噪声导致帧头定界符完全变形，接收方根本不知道有帧到达；或者交换机/路由器排队缓冲区溢出（Buffer Overflow）导致丢包；
3. **延迟与重复（Duplicate Frames）**：ACK 确认帧由于信道拥堵超时到达，导致发送方误以为数据丢失而触发重传，造成接收方收到多份一模一样的数据帧。

> **ARQ（Automatic Repeat reQuest，自动重传请求）的本质**：
> 接收方不具备无中生有的纠错能力，当数据缺失或损坏时，**通过反向信道向发送方请求重新发送，利用时间换取正确性**。

### 2. 逐跳可靠（Hop-by-Hop）vs 端到端可靠（End-to-End）
408 极高频的经典设问：“既然传输层 TCP 已经提供了端到端的可靠传输，为什么无线链路层（如 802.11）还要多此一举实现链路层可靠传输？”

```
[源主机] ==========(有线)==========> [路由器 R1] =====(高误码率无线)=====> [路由器 R2] ==========(有线)==========> [目的主机]
   |                                                                                                          |
   |<---------------------------------- TCP 端到端可靠传输 (RTT = 100ms) ----------------------------------->|
                                                  |<--- 链路层 ARQ (RTT = 2ms) --->|
```

- **代价权衡（Cost of Recovery）**：
  - 若无线信道误码率高达 $10\%$，且链路层不重传；则平均每发 10 个包就有 1 个丢失。
  - 这个丢失只能等整条路径走完全程（端到端 RTT 约 $100\text{ ms}$）后，由 TCP 超时重传。TCP 一旦超时，还会误以为网络发生严重拥塞，主动触发**拥塞窗口腰斩（减半）**，导致整个网络吞吐量断崖式暴跌！
  - **链路层就地解决（Local Recovery）**：无线网卡在 $2\text{ ms}$ 内通过链路层 ACK 迅速重传补救，TCP 根本感知不到偶发丢包，系统吞吐量维持峰值。
- **结论**：**高误码率链路必须在链路层实现局部可靠传输；极低误码率链路（如有线光纤）则链路层完全免除确认重传，由上层兜底。**

## 二、ARQ 协议的三大支柱机制微观拆解

### 1. 确认机制（ACK / NAK）
- **ACK（Positive Acknowledgement，肯定确认）**：
  - **逐个确认（Individual ACK）**：收到哪一帧，就明确回复确认哪一帧（SR 协议使用）；
  - **累计确认（Cumulative ACK）**：回复 $ACK=n$，代表**“序号为 $n$ 及以前的所有帧已全部正确接收，期待接收序号为 $n+1$ 的帧”**（TCP、GBN 协议使用）。累计确认具有天然的“抗 ACK 丢失”能力（若 ACK 1 丢了但 ACK 2 到达，则隐式确认了帧 1）。
- **NAK（Negative Acknowledgement，否认确认）**：
  - 显式通知发送方“某号帧损坏或未收到，请立即重发”。工程上并非所有系统都用 NAK，超时机制可隐式代替 NAK。
- **捎带确认（Piggybacking）**：
  - 在全双工通信中，接收方将自己的 ACK 控制信息嵌入到反向发送给对方的有效数据帧首部中，**无需单独发送纯 ACK 小帧**，极大地节省了信道开销。

### 2. 超时重传与定时器机制（Timeout & Retransmission）
- **往返时延（RTT，Round-Trip Time）**：从发送数据开始，到收到接收方的 ACK 为止所经历的全程时间。
- **重传定时器（RTO，Retransmission Time-Out）**：
  - 发送端每发送一个需要确认的帧，必须启动一个定时器；
  - **定时器设计黄金准则**：$RTO > RTT$。若 $RTO \le RTT$，在正常 ACK 还没来得及飞回来时定时器就提前爆炸，引发灾难性的**“假死重传（Spurious Retransmission）”**。

```
发送方                        接收方
  | --- 数据帧 0 (发) -------> |
  | (启动定时器 RTO)           |
  |                           | (帧 0 正确到达，发 ACK 0)
  | <------ ACK 0 (回) ------- |
  | (在 RTO 内收到 ACK 0)       |
  | (停止定时器，发下一帧)       |
```

### 3. 序号机制（Sequence Number）
- 必须给帧编号的根本原因：**防止“重复帧”被当作“新帧”交付给上层**。
  - *场景*：接收方已收到帧 0 并递交上层，但回复的 ACK 0 在信道中丢失；
  - 发送方超时重传帧 0；
  - 若帧没有编号，接收方会误以为这是一个新的数据帧，再次递交上层，造成**数据翻倍重复**；
  - 若有编号，接收方识别出当前收到的是“已经接收过的帧 0”，直接丢弃重复数据，并**重新补发一个 ACK 0** 给对端。
- **序号空间大小**：设序号采用 $n$ 位二进制表示，则序号范围为 $0 \sim 2^n - 1$，空间大小为 $N = 2^n$。

## 三、408 性能核心指标公式与数学模型推导

在 408 计算大题中，任何可靠传输协议的效率分析，都可以抽象为以下精确物理时间模型：

```
时间轴分解：
|<- 发送时延 T_data ->|
+---------------------+
|   发送数据帧的时间    |~~~~~~~~~~~~~~~~ 传播时延 T_prop ~~~~~~~~~~~~~~~~> [接收端接收完毕]
+---------------------+                                                     | 处理时延 T_proc
                                                                            v
<~~~~~~~~~~~~~~~~ 传播时延 T_prop ~~~~~~~~~~~~~~~~+-------------------------+
                                                  |   发送确认帧时间 T_ack   |
                                                  +-------------------------+
|<---------------------------- 一个往返周期 T_cycle --------------------------->|
```

### 1. 物理参数标准定义
- **数据帧发送时延（传输时延）**：$T_{\text{data}} = \frac{L_{\text{data}}}{C}$（$L_{\text{data}}$ 为数据帧长，$C$ 为信道传输速率/带宽）；
- **单向信号传播时延**：$T_{\text{prop}} = \frac{D}{V}$（$D$ 为物理距离，$V$ 为电磁波波速，铜线/光纤取 $2 \times 10^8\text{ m/s}$，无线电取 $3 \times 10^8\text{ m/s}$）；
- **确认帧发送时延**：$T_{\text{ack}} = \frac{L_{\text{ack}}}{C}$（ACK 帧通常极短，考题中若注明“忽略 ACK 发送时延”，则 $T_{\text{ack}} \approx 0$）；
- **节点处理时延**：$T_{\text{proc}}$（硬件检错耗时，通常忽略不计）。

### 2. 一个完整的交互周期（Round-Trip Cycle）
$$T_{\text{cycle}} = T_{\text{data}} + T_{\text{prop}} + T_{\text{proc}} + T_{\text{ack}} + T_{\text{prop}} \approx T_{\text{data}} + 2 \cdot T_{\text{prop}} + T_{\text{ack}}$$

### 3. 信道利用率（Channel Utilization，$U$）与有效数据率（Throughput）
- **信道利用率 $U$**：发送有效数据所占用的时间与总周期时间的比值。
  $$U = \frac{W_{\text{send}} \times T_{\text{data}}}{T_{\text{cycle}}}$$
  （其中 $W_{\text{send}}$ 为一个往返周期内发送方能够连续发送的数据帧个数）。
- **信道吞吐率（有效吞吐量）**：
  $$\text{Throughput} = U \times C = \frac{W_{\text{send}} \times L_{\text{data}}}{T_{\text{cycle}}}$$

## 四、408 统考真题级计算演练

### 【题型模型：卫星信道可靠传输参数与信道利用率临界推导】

**【考题背景】**
两台主机之间建立一条全双工卫星通信链路。
- 卫星信道带宽（传输速率）$C = 1\text{ Mbps}$；
- 单向传播时延 $T_{\text{prop}} = 250\text{ ms}$；
- 数据帧长固定为 $L_{\text{data}} = 1000\text{ 字节}$；
- 确认帧长固定为 $L_{\text{ack}} = 40\text{ 字节}$；
- 忽略节点处理时延与排队时延，信道误码率为 0。

**【试求解】**：
1. 若采用停止-等待协议（SW，发送窗口 $W=1$），求该通信链路的信道利用率与实际吞吐率；
2. 若要求信道利用率达到 $100\%$，发送方在一个往返周期内至少需要连续发送多少个数据帧？
3. 若采用滑动窗口协议，帧首部序号字段至少需要多少位二进制才能支撑 $100\%$ 的信道利用率？

---

### 【草稿纸执行第一步：统一单位并计算基本时间分量】
- 带宽 $C = 1\text{ Mbps} = 10^6\text{ bps}$；
- 数据帧发送时延：$T_{\text{data}} = \frac{1000 \times 8\text{ b}}{10^6\text{ bps}} = \frac{8000}{10^6} = 8\text{ ms}$；
- 确认帧发送时延：$T_{\text{ack}} = \frac{40 \times 8\text{ b}}{10^6\text{ bps}} = \frac{320}{10^6} = 0.32\text{ ms}$；
- 往返传播时延：$2 \times T_{\text{prop}} = 2 \times 250\text{ ms} = 500\text{ ms}$。

---

### 【严密推导过程】

#### 第 1 问：停止-等待协议利用率计算
1. 一个完整发送确认周期：
   $$T_{\text{cycle}} = T_{\text{data}} + 2 \times T_{\text{prop}} + T_{\text{ack}} = 8\text{ ms} + 500\text{ ms} + 0.32\text{ ms} = 508.32\text{ ms}$$
2. 信道利用率 $U_{\text{SW}}$：
   $$U_{\text{SW}} = \frac{T_{\text{data}}}{T_{\text{cycle}}} = \frac{8\text{ ms}}{508.32\text{ ms}} \approx 1.57\%$$
3. 实际吞吐率：
   $$\text{Throughput} = U_{\text{SW}} \times C = 1.57\% \times 1\text{ Mbps} = 15.7\text{ kbps}$$
   *结论分析*：停止等待协议在大时延卫星信道上，高达 $98.43\%$ 的时间信道全在闲置等待，利用率极低！

#### 第 2 问：达到 100% 利用率的临界窗口大小推导
要使信道利用率达到 $100\%$，发送方发送数据的动作必须在整个往返周期内**连续不断、毫无空隙**。
设在一个周期内发送的数据帧数为 $W$：
$$W \times T_{\text{data}} \ge T_{\text{cycle}} \implies W \ge \frac{T_{\text{cycle}}}{T_{\text{data}}} = \frac{508.32\text{ ms}}{8\text{ ms}} = 63.54$$
因为发送的帧数必须为整数，故向上取整：
$$W_{\min} = \lceil 63.54 \rceil = 64\text{ 帧}$$
即：发送方至少需要有连续发送 **64 个帧** 的能力。

#### 第 3 问：所需最小序号位数推导
- 不同的 ARQ 协议对序号空间 $2^n$ 与发送窗口 $W$ 的约束不同：
  - **若采用 GBN 协议**：GBN 的发送窗口满足 $W_{\text{GBN}} \le 2^n - 1$。
    $$2^n - 1 \ge 64 \implies 2^n \ge 65 \implies n \ge 7\text{ 位}$$
  - **若采用 SR 协议**：SR 的发送窗口满足 $W_{\text{SR}} \le 2^{n-1}$。
    $$2^{n-1} \ge 64 \implies n - 1 \ge 6 \implies n \ge 7\text{ 位}$$
- 综上，无论采用 GBN 还是 SR 协议，序号字段至少需要 **7 位** 二进制。

## 五、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：求发送时延时把“字节（Byte）”忘了乘 8 转为“比特（bit）”**
> - **考场第一死因**：$L = 1000\text{ B}$，算 $T = 1000 / 10^6$。直接差了 8 倍！带宽单位永远是 $\text{bps}$（bit per second），帧长单位通常是 $\text{Byte}$，**计算第一步必须：Byte $\times 8$！**

> [!CAUTION]
> **陷阱 2：周期公式漏算往返传播时延（算成了单程 $T_{\text{prop}}$）**
> - 数据发过去需要 $T_{\text{prop}}$，ACK 飞回来还需要 $T_{\text{prop}}$。除非题目明文说“单程已包含往返”，否则总时延必定是 **$2 \times T_{\text{prop}}$**！

### 2. 考场核心记忆桩
- **“字节乘八化比特，单程双倍算往返”**：做时延计算题的保命符。
- **“停等大时延必惨淡，流水线满跑看窗口”**：信道利用率的微观本质。
