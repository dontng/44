# 3.3 点对点协议PPP

**PPP（Point-to-Point Protocol，点对点协议）** 是目前使用最广泛的点对点数据链路层协议，用于家庭用户通过拨号（ADSL/PPPoE）接入互联网，也用于路由器之间的串行链路。

## 一、PPP 协议的组成

PPP 由三个组件构成：

| 组件 | 全称 | 作用 |
|---|---|---|
| **LCP** | Link Control Protocol（链路控制协议） | 建立、配置、测试、关闭数据链路连接 |
| **NCP** | Network Control Protocol（网络控制协议） | 为不同网络层协议（IP、IPX 等）协商参数（如 IP 地址分配） |
| **认证协议** | PAP / CHAP | 可选的身份验证（如 ISP 验证用户名密码） |

## 二、PPP 帧格式（考点）

```
+--------+----------+---------+----------+----------+--------+
|  Flag  |  Address |  Control|  Protocol|   Data   |  FCS   |
|  0x7E  |  0xFF    |  0x03   |  2 字节  | 可变长度 |  2/4B  |
+--------+----------+---------+----------+----------+--------+
  1 字节   1 字节    1 字节    2 字节                 2/4 字节
```

- **Flag**：`0x7E`（即 `01111110`），帧定界符，标记帧的起止；
- **Address**：固定为 `0xFF`（全 1 广播地址），PPP 点对点链路只有两端，无需真正寻址；
- **Control**：固定为 `0x03`（无编号帧），PPP 不提供可靠传输（无序号、无重传）；
- **Protocol**：标识 Data 字段携带的上层协议类型：
  - `0x0021` = IP 数据报
  - `0xC021` = LCP 报文
  - `0x8021` = NCP（IPCP）报文
- **Data**：上层协议数据，长度可变（默认最大 1500 字节）；
- **FCS**：帧校验序列，默认 2 字节（也可协商为 4 字节），CRC 差错检测。

## 三、透明传输——字节填充（转义）

PPP 使用**字节填充**实现透明传输。当 Data 字段中出现与帧定界符或特殊控制字符相同的字节时，进行如下转义：

| 原始字节 | 填充后（发送） |
|---|---|
| `7E`（Flag） | `7D 5E` |
| `7D`（Escape） | `7D 5D` |

规则：在需转义的字节前插入转义字符 `0x7D`，并将原字节与 `0x20` 做 XOR（即第 6 位取反）：`7E → 7D 5E`，`7D → 7D 5D`。

接收方遇到 `7D` 则删去并将下一字节与 `0x20` XOR 还原。

## 四、PPP 的特点（考点对比）

| 特性 | PPP |
|---|---|
| 是否可靠 | **否**（无序号、无重传，不保证有序无丢失） |
| 支持多协议 | **是**（通过 Protocol 字段区分 IP/IPX 等） |
| 全双工 | 是 |
| 认证 | 可选（PAP 明文 / CHAP 挑战握手） |
| 适用链路 | 点对点（拨号、ADSL、路由器串口） |

> 考点：PPP 帧的 Address 字段为 `0xFF`，Control 字段为 `0x03`——这两个字段固定，是选择题常考的"PPP 帧中哪个字段是固定的"。PPP **不提供可靠传输**，可靠性由上层 TCP 保证。

## 五、PPPoE

**PPPoE（PPP over Ethernet）** 是将 PPP 帧封装在以太网帧中传输的技术，用于 ADSL 宽带接入：用户电脑→（以太网）→ADSL Modem→（PPP）→ISP 接入服务器。理解 PPPoE = PPP + Ethernet 封装即可，考试很少深入考查其帧格式细节。
