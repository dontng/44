# 3.3 点对点协议 PPP

---

## 1. PPP 协议的基本概念与组成

点对点协议（Point-to-Point Protocol，PPP）是目前使用最广泛的数据链路层协议，广泛用于广域网点对点通信以及用户宽带拨号接入（如 PPPoE）。

### 1.1 点对点通信与广播信道的根本区别

- **无须介质争用**：点对点链路仅有两个端点，信道由双方独占，不存在并发碰撞与冲突仲裁问题；
- **无须物理寻址**：发出的信号对端是唯一的接收者，因此无需在链路层区分目标物理设备；
- **需要动态配置与多协议封装**：同一条物理链路可能需要承载 IPv4、IPv6 等多种不同的网络层数据报，且通信前需要动态协商网络层参数（如 IP 地址分配）。

### 1.2 PPP 协议的三大组成部分

PPP 协议是一个综合性的协议族，由三大部分组成：
1. **链路控制协议 LCP（Link Control Protocol）**：
   用于建立、配置、测试和释放数据链路连接；
2. **网络控制协议 NCP（Network Control Protocol）**：
   针对不同的网络层协议设立的子协议集合（例如用于配置 IPv4 的 IPCP、用于配置 IPv6 的 IPv6CP），用于协商网络层参数；
3. **帧封装与成帧规程**：
   定义如何把网络层 IP 数据报封装成 PPP 帧，并规定同步或异步链路下的透明传输方法。

## 2. PPP 帧格式与字段解析

```text
 字节偏移:
    0          1          2          3          4 ...               ... N-2      N
 +----------+----------+----------+----------+----------------------+----------+----------+
 |  标志 F  |  地址 A  |  控制 C  |  协议    |       信息部分       |   FCS    |  标志 F  |
 |  (0x7E)  |  (0xFF)  |  (0x03)  | (2 字节) |   (IP 数据报等载荷)   | (2 字节) |  (0x7E)  |
 +----------+----------+----------+----------+----------------------+----------+----------+
   1 字节     1 字节     1 字节     2 字节          不超过 MTU 长度     2 字节     1 字节
                                              (默认最大 1500 字节)
```

### 2.1 字段含义与固定值成因

1. **标志字段 F（Flag，1 字节）**：
   固定为十六进制 `0x7E`（二进制 `01111110`），用于帧的开始与结束定界；
2. **地址字段 A（Address，1 字节）**：
   固定为十六进制 `0xFF`。因为点对点链路对端是唯一的，根本不需要物理寻址，该字段仅为兼容早期 HDLC 规范保留，并无实际寻址功能；
3. **控制字段 C（Control，1 字节）**：
   固定为十六进制 `0x03`。在 HDLC 中表示无编号信息（UI）帧；
4. **协议字段（Protocol，2 字节）**：
   用于指明信息部分承载的是何种上层报文：
   - `0x0021`：信息部分是 **IP 数据报**；
   - `0x8021`：信息部分是 **IPCP 报文**（NCP 协议族）；
   - `0xC021`：信息部分是 **LCP 报文**；
   - `0xC023`：信息部分是 **PAP 认证报文**；
   - `0xC223`：信息部分是 **CHAP 认证报文**；
5. **信息部分（Information）**：
   承载上层数据，长度可变，不超过 MTU（默认通常为 1500 字节）；
6. **帧检验序列 FCS（2 字节）**：
   使用 CRC 进行差错检验，用于发现传输比特差错。

### 2.2 为什么 PPP 协议是不可靠传输协议？

在 408 统考中，这是一个高频核心概念：
- **PPP 具备检错能力**：接收端硬件通过 FCS 计算 CRC，一旦发现错误帧，**直接丢弃**；
- **PPP 不提供确认与重传**：PPP 帧的控制字段固定为 `0x03`，帧首部**没有发送序号，没有确认号，发送方也没有重传定时器**；
- **结论**：**PPP 是一个典型的提供无差错检测服务、但不提供确认重传的不可靠数据链路层协议**。

## 3. PPP 透明传输的双重实现机制

当信息部分出现与标志字段 `0x7E` 相同的内容时，PPP 区分物理信道类型采用两种不同的透明传输手段：

### 3.1 异步传输（面向字节）：字节填充法

当物理信道采用异步传输（以字节为单位）时，PPP 采用字节填充：
- 定义转义字节为 `0x7D`（二进制 `01111101`）；
- **填充规则**：
  1. 信息中若出现 `0x7E`，将其替换为 2 字节序列：`0x7D 0x5E`；
  2. 信息中若出现 `0x7D`，将其替换为 2 字节序列：`0x7D 0x5D`；
  3. 信息中若出现数值小于 `0x20` 的 ASCII 控制字符，在字符前插入 `0x7D`，同时改变该字符的数值；
- **接收端还原**：接收端每读到 `0x7D`，就将其丢弃，并将紧随其后的字节异或 `0x20` 恢复原值。

### 3.2 同步传输（面向比特）：零比特填充法

当物理信道采用同步传输（面向比特流连续对齐）时，PPP 采用标准的零比特填充法：
- 发送端硬件扫描比特流，**只要连续出现 5 个 1，必须立即在其后插入一个 0**；
- 接收端硬件扫描比特流，**只要连续出现 5 个 1 且后跟 0，硬件自动将该 0 剔除**，恢复原始数据。

## 4. 安全认证机制：PAP 与 CHAP

在拨号接入时，PPP 支持两种身份认证子协议：
1. **PAP（口令认证协议，Password Authentication Protocol）**：
   - **两次握手**；
   - 被认证方直接将用户名和密码以**明文形式**在信道中发送给认证方，安全性差；
2. **CHAP（质询握手认证协议，Challenge Handshake Authentication Protocol）**：
   - **三次握手**；
   - 认证方首先向被认证方发送一个随机的“质询码”；
   - 被认证方将密码和质询码通过单向散列算法（如 MD5）计算出摘要发回认证方；
   - **真实密码从不在网络中传输**，安全性高，且能有效防范重放攻击。
