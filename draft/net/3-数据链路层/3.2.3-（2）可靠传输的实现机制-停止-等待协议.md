# 3.2.3-（2）可靠传输的实现机制-停止-等待协议

> **本节在 408 中的定位**：停止-等待协议（Stop-and-Wait ARQ）是滑动窗口协议的特化极限（$W_S=1, W_R=1$）。408 统考中对本节的考查聚焦于**“时序状态机异常转移（丢数据、丢ACK、迟到ACK）”**、**“参数 $a = T_p / T_f$ 对信道利用率的数学决定性”**与**“1 比特交替编号的严密逻辑证明”**。必须能徒手推演每一种异常时序并快速给出精确到小数点的利用率与有效吞吐率。

---

## 一、第一性原理与设计动因：为什么需要 1 比特交替编号？

### 1. 停止-等待协议的微观状态流转
停止-等待协议的核心规则：**发送方每次只允许在信道中飞 1 个数据帧；在收到接收方对该帧的明确 ACK 之前，绝对不发送下一个新数据帧。**

### 2. 为什么无序号的停止等待必然导致“死锁与重复”？（思维实验反推）
设想一种“不编号”的原始停止-等待协议：
- **场景 1：数据帧丢失**
  发送方发送帧后等待，若数据在途中丢失，接收方一无所知；发送方必须引入**超时定时器（Timer）**，超时未收到 ACK 则重传该帧。
- **场景 2：ACK 丢失或延迟到达（无序号的致命死锁/数据重复）**
  1. 发送方发送第 1 个数据帧 $D$；
  2. 接收方正确接收 $D$，递交上层，并向发送方回复确认帧 $ACK$；
  3. 但该 $ACK$ 在信道中发生严重延迟或丢失，发送方的重传定时器超时；
  4. 发送方**重新发送数据帧 $D$**；
  5. 接收方收到此帧：**此时如果帧上没有编号，接收方根本分不清这是“一个新的不同数据帧”，还是“由于 ACK 丢失而重传的旧数据帧”！**
  6. 接收方将重复的帧再次递交上层应用，**导致上层数据严重错误重复！**

```
【ACK 迟到引起的幽灵确认错位】
发送方                                      接收方
  | --------- 帧 0 -------------------------> | (正确接收帧 0，发 ACK 0)
  |                                           |
  | (超时未收到 ACK 0，定时器触发)              |
  | --------- 帧 0 (重传) -------------------> | (收到重复帧 0，丢弃数据，补发 ACK 0)
  | <======== ACK 0 (迟到的第1个ACK到达) ====== |
  | (误以为是重传的 ACK，立刻发帧 1 !)          |
  | --------- 帧 1 -------------------------> |
  | <======== ACK 0 (补发的第2个ACK到达) ====== |
  | (发送方看到 ACK 0，误以为是对帧 1 的确认！)  | ===> 严重逻辑混乱！
```

### 3. 1 比特序号（0 和 1 交替）如何彻底根治此问题？
- 发送方的数据帧交替打上标签：`0, 1, 0, 1, 0, 1 ...`；
- 确认帧明确指出自己确认的是哪一个帧：`ACK 0, ACK 1, ...`（或下一期待帧 `ACK 1, ACK 0, ...`）；
- **接收方判决逻辑**：若当前期待的是帧 1，却收到了帧 0，证明“对端没收到我之前的 ACK 0 而重发了旧帧”，接收方**果断丢弃该数据，并再次补发 ACK 0**，绝不递交上层；
- **1 比特足够性证明**：在停止-等待协议中，信道中最多只有前后相邻的两个状态在交替，因此模 2 编号（0 和 1）在数学上完全充分。

## 二、三种异常场景的微观时序图拆解

### 1. 场景 A：数据帧在途中丢失或校验出错
```
发送方                               接收方
  | --- 帧 0 ------------------------> × (CRC 校验失败丢弃，或物理损坏)
  | [启动定时器]
  | ... (静默等待)
  | [定时器超时爆炸 !]
  | --- 帧 0 (超时重发) -------------> | (正确接收帧 0，递交上层)
  | <---------------------- ACK 0 ---- |
  | (收到 ACK 0，关闭定时器，发帧 1)
```

### 2. 场景 B：确认帧 ACK 途中丢失
```
发送方                               接收方
  | --- 帧 0 ------------------------> | (正确接收帧 0，递交上层)
  |                                   | --- ACK 0 -----> × (途中丢失)
  | [定时器超时爆炸 !]
  | --- 帧 0 (超时重发) -------------> | (检测到仍是帧 0: 重复帧!)
  |                                   |  [动作: 丢弃帧 0，重发 ACK 0]
  | <---------------------- ACK 0 ---- |
  | (收到 ACK 0，发新帧 1)
```

### 3. 场景 C：确认帧 ACK 迟到（滞后到达）
```
发送方                               接收方
  | --- 帧 0 ------------------------> | (接收帧 0)
  |                                   | ~~~~~~~~~ 慢速信道 ~~~~~~~~~> ACK 0
  | [定时器超时 !]
  | --- 帧 0 (重传) ------>            |
  | <------------------- ACK 0 (迟到) -| (收到迟到的 ACK 0)
  | (发送方发新帧 1)                   |
  | --- 帧 1 ------------------------> |
  |                                   | (收到重发的帧 0，丢弃并补发 ACK 0)
  | <------------------- ACK 0 (补发) -|
  | (发送方收到了旧的 ACK 0: 直接忽略丢弃!)
```

## 三、408 核心数学推导：信道利用率与参数 $a$ 的本质关系

### 1. 严格数学模型推导
定义：
- $L$：数据帧长度（bit）；
- $C$：信道数据率/带宽（bps）；
- $T_f$：数据帧发送时延（$T_f = L / C$）；
- $T_p$：单向信号传播时延（$T_p = D / V$）；
- $L_a$：确认帧长度（bit）；$T_a$：确认帧发送时延（$T_a = L_a / C$）；
- $T_{\text{proc}}$：节点处理时延（通常略去）。

一个完整无差错周期所耗费的总物理时间：
$$T_{\text{cycle}} = T_f + T_p + T_{\text{proc}} + T_a + T_p \approx T_f + 2T_p + T_a$$

**信道利用率（Channel Utilization，$U$）**：
$$U = \frac{T_f}{T_{\text{cycle}}} = \frac{T_f}{T_f + 2T_p + T_a}$$

### 2. 关键无量纲参数 $a$ 的引入
在 408 理论分析中，常忽略极小的确认帧发送时延 $T_a \approx 0$。
定义 **单向传播时延与发送时延之比**：
$$a = \frac{T_p}{T_f}$$
分子分母同除以 $T_f$，得到 408 经典黄金简化公式：
$$U = \frac{1}{1 + 2 \cdot \frac{T_p}{T_f}} = \frac{1}{1 + 2a}$$

> **物理意义深刻剖析**：
> - **$a \ll 1$（即 $T_p \ll T_f$）**：帧很长、距离很短、速率不高。数据发送时间占绝对统治地位，信号一眨眼就到了，$2a \to 0$，$U \to 100\%$。此时停止-等待协议非常高效！
> - **$a \gg 1$（即 $T_p \gg T_f$）**：信道速率极高（$T_f$ 极短）或传输距离极远（$T_p$ 极大，如卫星通信）。发送数据只花了极短瞬间，剩下的绝大部分时间信道全在“空等电波往返飞行”，$U \to 0$。此时停止-等待协议性能彻底崩溃！

## 四、408 统考真题级计算演练与全参数推导

### 【题型模型：停止-等待协议下的信道利用率与有效吞吐率综合计算】

**【考题背景】**
主机 A 和主机 B 之间通过一条长度为 $1000\text{ km}$ 的直连光纤链路通信。
- 链路传输速率 $C = 100\text{ Mbps}$；
- 光纤中光信号传播速率 $V = 2.0 \times 10^8\text{ m/s}$；
- 数据帧总长度为 $1250\text{ 字节}$（含首尾开销）；
- 确认帧 ACK 长度为 $50\text{ 字节}$；
- 双方采用停止-等待协议通信，忽略节点处理时延；
- 假设在无误码理想状态下运行。

**【试求解】**：
1. 计算单向传播时延 $T_p$ 和数据帧发送时延 $T_f$；
2. 计算无量纲参数 $a$；
3. 计算该链路的信道利用率 $U$（分别用精确公式与忽略 $T_a$ 的近似公式计算，并对比误差）；
4. 计算主机 A 发送数据的有效吞吐率（$\text{Throughput}$，以 $\text{Mbps}$ 为单位）。

---

### 【草稿纸执行第一步：统一单位并列出四项基础时延】
- $D = 1000\text{ km} = 10^6\text{ m}$；
- $V = 2 \times 10^8\text{ m/s}$；
- $C = 100\text{ Mbps} = 10^8\text{ bps}$；
- 数据帧长：$L_f = 1250 \times 8\text{ bit} = 10000\text{ bit} = 10^4\text{ bit}$；
- ACK 帧长：$L_a = 50 \times 8\text{ bit} = 400\text{ bit}$。

---

### 【严密推导过程】

#### 第 1 问：基础时延计算
1. **单向传播时延**：
   $$T_p = \frac{D}{V} = \frac{10^6\text{ m}}{2 \times 10^8\text{ m/s}} = 5 \times 10^{-3}\text{ s} = 5\text{ ms}$$
2. **数据帧发送时延**：
   $$T_f = \frac{L_f}{C} = \frac{10000\text{ bit}}{10^8\text{ bps}} = 10^{-4}\text{ s} = 0.1\text{ ms}$$
3. **确认帧发送时延**：
   $$T_a = \frac{L_a}{C} = \frac{400\text{ bit}}{10^8\text{ bps}} = 4 \times 10^{-6}\text{ s} = 0.004\text{ ms}$$

#### 第 2 问：无量纲参数 $a$
$$a = \frac{T_p}{T_f} = \frac{5\text{ ms}}{0.1\text{ ms}} = 50$$
（此场景中传播时延是发送时延的 50 倍，典型的 $a \gg 1$ 场景！预判利用率将极其低下）。

#### 第 3 问：信道利用率计算
1. **精确计算（考虑 $T_a$）**：
   $$T_{\text{cycle}} = T_f + 2T_p + T_a = 0.1\text{ ms} + 2 \times 5\text{ ms} + 0.004\text{ ms} = 10.104\text{ ms}$$
   $$U_{\text{exact}} = \frac{T_f}{T_{\text{cycle}}} = \frac{0.1}{10.104} \approx 0.009897 \approx 0.99\%$$
2. **近似公式计算（忽略 $T_a$）**：
   $$U_{\text{approx}} = \frac{1}{1 + 2a} = \frac{1}{1 + 2 \times 50} = \frac{1}{101} \approx 0.009901 \approx 0.99\%$$
   *分析*：两者几乎完全一致，在 408 大题中若 ACK 很短，忽略 $T_a$ 完全成立。

#### 第 4 问：有效吞吐率计算
$$\text{Throughput} = U \times C = 0.0099 \times 100\text{ Mbps} = 0.99\text{ Mbps}$$
*惊人结论*：一条高达 $100\text{ Mbps}$ 物理带宽的高速光纤，仅仅因为采用了停止-等待协议，实际跑出来的数据传输率竟然不足 **$1\text{ Mbps}$**（只有可怜的 $0.99\text{ Mbps}$），$99\%$ 以上的昂贵带宽全部被浪费在空等确认帧的飞行上！

## 五、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：混淆“信道利用率”与“信道吞吐率”**
> - **信道利用率**是一个百分比（无量纲，如 $0.99\%$）；
> - **信道吞吐率**是有物理单位的绝对数据率（如 $0.99\text{ Mbps}$ 或 $123.75\text{ KB/s}$）。考场审题必须看清题目问的是“利用率”还是“吞吐量/吞吐率”！

> [!CAUTION]
> **陷阱 2：误以为停止-等待协议不需要序号**
> - “只传 1 个帧还要什么编号？”——**大错特错！** 如果没有序号，ACK 丢失重传时，接收方必然将重传帧当成新帧再次交付上层；ACK 迟到时会引发后续所有帧的确认错位。因此，**停止-等待协议必须有序号，最少需要 1 位（0 和 1）！**

### 2. 考场核心记忆桩
- **“停等效率一除一加两倍a”**：$U = 1 / (1 + 2a)$，其中 $a = T_p / T_f$。
- **“大带宽长距离用停等，光纤当成自行车”**：形象记忆高时延带宽积下停等协议的悲剧。
