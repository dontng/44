# 3.2.3-（2）可靠传输的实现机制-停止-等待协议

停止-等待协议（Stop-and-Wait ARQ）是滑动窗口协议的特化极限形式（发送窗口 $W_S = 1$，接收窗口 $W_R = 1$）。其基本规则为：**发送端每发送一个数据帧后便停止发送，启动重传定时器并等待接收端的确认（ACK）；只有在收到确认后，才允许发送下一个数据帧**。

---

## 一、为什么停止-等待协议必须使用 1 比特交替编号

直觉上，既然发送端在任意时刻信道中最多只允许存在一个未确认的数据帧，似乎不需要给数据帧进行编号。然而，通过严密的时序分析可以证明：**无序号的停止-等待协议在信道发生故障时必然导致死锁或数据重复交付**。

### 1. 无序号假设下的逻辑崩溃
设想发送端发送的数据帧和接收端回复的 ACK 均不携带任何序号：
- **故障情境：ACK 丢失或延迟到达**
  1. 发送端发送数据帧 $D_0$；
  2. 接收端正确接收 $D_0$，将其递交给上层协议，并向发送端发送确认帧 $\text{ACK}$；
  3. 该 $\text{ACK}$ 帧在传输介质中丢失，或者由于信道慢速导致其传输时延超过了发送端的重传超时时间（RTO）；
  4. 发送端的重传定时器超时，触发自动重传，**重新发送了一份完全相同的数据帧 $D_0$**；
  5. 接收端收到重传的 $D_0$：**由于帧没有编号，接收端无法分辨这是发送端因为丢失 ACK 而重发的前一个旧帧，还是发送端发送的下一个新帧**；
  6. 接收端将该重复帧再次交付给上层应用，导致上层数据发生静默重复，破坏了数据传输的正确性。

```text
ACK 延迟到达引起的错位混淆：
发送端                                         接收端
  │ ───────── 数据帧 0 ─────────────────────────> │ (正确接收帧 0，递交上层，回复 ACK 0)
  │                                              │
  │ (超时未收到 ACK 0，定时器触发)                 │
  │ ───────── 数据帧 0 (重传) ───────────────────> │ (接收端识别出是重复帧 0，丢弃数据，补发 ACK 0)
  │ <════════ ACK 0 (迟到的第 1 个 ACK 到达) ═════ │
  │ (误以为该 ACK 是对重发帧的确认，发送新帧 1)     │
  │ ───────── 数据帧 1 ─────────────────────────> │
  │ <════════ ACK 0 (补发的第 2 个 ACK 到达) ═════ │
  │ (发送端若不加序号区分，将把旧 ACK 0 误判为帧 1 的确认！)
```

### 2. 1 比特交替编号（0 与 1）的充分性
- **数据帧交替编号**：发送端依次为数据帧打上 `0` 和 `1` 的模 2 循环标签（即 `0, 1, 0, 1, ...`）；
- **确认帧对等编号**：确认帧明确携带对应的确认号（如 $\text{ACK } 0$ 与 $\text{ACK } 1$），表示对特定序号数据帧的接收确认；
- **接收端的判决机制**：若接收端当前期待接收帧 1，却收到了帧 0，接收端立即判定该帧属于旧的重传帧，**果断丢弃该数据载荷，但必须向对端重新补发 $\text{ACK } 0$**（通知发送端前一帧已被收到，促使其推进发送窗口）；
- **充分性证明**：在停止-等待协议中，由于发送端每次只发 1 帧，任意时刻信道中至多只存在“当前帧”与“紧邻的前一帧”两种交互状态，因此采用 1 位二进制数（可表示 0 和 1 两种状态）在数学上完全充分。

## 二、三种典型异常场景的时序状态流转

在实际通信中，停止-等待协议通过超时定时器与 1 比特交替编号协同处理三类异常：

### 1. 场景 A：数据帧在信道中丢失或损坏

```text
发送端                               接收端
  │ ─── 帧 0 ────────────────────────> ╳ (CRC 校验失败被直接丢弃，或物理中断)
  │ [启动定时器]
  │ ... (静默等待)
  │ [定时器超时 !]
  │ ─── 帧 0 (超时自动重传) ─────────> │ (正确接收帧 0，递交上层)
  │ <────────────────────── ACK 0 ─── │ (回复 ACK 0)
  │ (收到 ACK 0，关闭定时器，发新帧 1)
```

---

### 2. 场景 B：确认帧 ACK 途中丢失

```text
发送端                               接收端
  │ ─── 帧 0 ────────────────────────> │ (正确接收帧 0，递交上层)
  │                                   │ ─── ACK 0 ─────> ╳ (确认帧在途中丢失)
  │ [定时器超时 !]
  │ ─── 帧 0 (超时重传) ─────────────> │ (检测到仍为帧 0: 判定为重复帧!)
  │                                   │ [动作: 丢弃数据帧 0，重新补发 ACK 0]
  │ <────────────────────── ACK 0 ─── │
  │ (收到补发的 ACK 0，发送新帧 1)
```

---

### 3. 场景 C：确认帧 ACK 迟到（传输滞后）

```text
发送端                               接收端
  │ ─── 帧 0 ────────────────────────> │ (正确接收帧 0，回复 ACK 0)
  │                                   │ ~~~~~~~~~ 慢速传输 ~~~~~~~~~> ACK 0
  │ [定时器超时 !]
  │ ─── 帧 0 (重传) ───────>          │
  │ <─────────────────── ACK 0 (迟到) ─│ (发送端收到迟到的 ACK 0)
  │ (发送端启动发送新帧 1)             │
  │ ─── 帧 1 ────────────────────────> │
  │                                   │ (接收端收到重发的帧 0: 丢弃并补发 ACK 0)
  │ <─────────────────── ACK 0 (补发) ─│
  │ (发送端此时期待 ACK 1，收到旧的 ACK 0: 直接忽略抛弃，不影响帧 1 的定时器)
```

## 三、性能分析与无量纲参数 $a$ 的数学模型

### 1. 严格信道利用率公式推导
定义基本时间物理分量：
- $L_f$：数据帧长度（$\text{bit}$）；
- $C$：信道数据传输速率（$\text{b/s}$）；
- $T_f$：数据帧发送时延（$T_f = L_f / C$）；
- $D$：链路物理距离（$\text{m}$）；$V$：信号在介质中的传播速度（$\text{m/s}$）；
- $T_p$：单向信号传播时延（$T_p = D / V$）；
- $L_a$：确认帧长度（$\text{bit}$）；$T_a$：确认帧发送时延（$T_a = L_a / C$）；
- $T_{\text{proc}}$：节点软硬件处理时延（通常极微小，忽略不计）。

在无差错状态下，发送端完成一帧发送并收到确认的完整周期时间：
$$T_{\text{cycle}} = T_f + T_p + T_{\text{proc}} + T_a + T_p \approx T_f + 2T_p + T_a$$

**信道利用率（Channel Utilization, $U$）**定义为有效发送数据占用的时间与总周期时间之比：
$$U = \frac{T_f}{T_{\text{cycle}}} = \frac{T_f}{T_f + 2T_p + T_a}$$

---

### 2. 无量纲参数 $a$ 的引入与物理本质
在实际网络中，确认帧 ACK 长度通常极短（数十字节），其发送时延 $T_a \ll 2T_p$。忽略 $T_a$ 后：
$$U \approx \frac{T_f}{T_f + 2T_p}$$

定义**单向传播时延与发送时延之比**为无量纲参数 $a$：
$$a = \frac{T_p}{T_f}$$

将分子分母同除以 $T_f$，可得简化的理论信道利用率公式：
$$U = \frac{1}{1 + 2a}$$

**参数 $a$ 对网络性能的物理支配作用**：
- **$a \ll 1$（$T_p \ll T_f$）**：
  帧长极长、传输距离极短或信道速率较低。数据帧发送耗时占据了主导地位，信号很快送达且确认很快返回，$2a \to 0$，$U \to 100\%$。在此类信道中，停止-等待协议非常高效且实现简单；
- **$a \gg 1$（$T_p \gg T_f$）**：
  信道物理速率极高（$T_f$ 极短）或传输距离极远（$T_p$ 极大，如长途光纤、卫星通信）。数据发送仅耗费极短时间，剩余的绝大部分时间信道完全处于空等电磁波往返飞行的闲置状态，$U \to 0$。停止-等待协议在此类高时延带宽积信道中性能崩溃，必须使用流水线协议（滑动窗口协议）。

## 四、长途高速链路性能推导演练

### 场景参数
- 链路类型：两主机直连的单模光纤链路，长度 $D = 1000\,\text{km} = 10^6\,\text{m}$；
- 传输带宽：$C = 100\,\text{Mb/s} = 10^8\,\text{b/s}$；
- 光纤光速：$V = 2.0 \times 10^8\,\text{m/s}$；
- 数据帧总长：$L_f = 1250\,\text{字节} = 10000\,\text{bit}$；
- 确认帧总长：$L_a = 50\,\text{字节} = 400\,\text{bit}$；
- 双方采用停止-等待协议通信，忽略节点处理时延，信道处于无差错稳定传输状态。

### 1. 基础时延分量计算
1. **单向传播时延**：
   $$T_p = \frac{D}{V} = \frac{10^6\,\text{m}}{2.0 \times 10^8\,\text{m/s}} = 0.005\,\text{s} = 5\,\text{ms}$$
2. **数据帧发送时延**：
   $$T_f = \frac{L_f}{C} = \frac{10000\,\text{bit}}{10^8\,\text{b/s}} = 0.0001\,\text{s} = 0.1\,\text{ms}$$
3. **确认帧发送时延**：
   $$T_a = \frac{L_a}{C} = \frac{400\,\text{bit}}{10^8\,\text{b/s}} = 0.000004\,\text{s} = 0.004\,\text{ms}$$

### 2. 参数 $a$ 计算
$$a = \frac{T_p}{T_f} = \frac{5\,\text{ms}}{0.1\,\text{ms}} = 50$$
（传播时延是发送时延的 50 倍，属于典型的 $a \gg 1$ 场景）。

### 3. 信道利用率计算与误差比对
1. **考虑 $T_a$ 的精确信道利用率**：
   $$T_{\text{cycle}} = T_f + 2T_p + T_a = 0.1\,\text{ms} + 2 \times 5\,\text{ms} + 0.004\,\text{ms} = 10.104\,\text{ms}$$
   $$U_{\text{exact}} = \frac{T_f}{T_{\text{cycle}}} = \frac{0.1\,\text{ms}}{10.104\,\text{ms}} \approx 0.9897\%$$
2. **忽略 $T_a$ 的理论近似利用率**：
   $$U_{\text{approx}} = \frac{1}{1 + 2a} = \frac{1}{1 + 2 \times 50} = \frac{1}{101} \approx 0.9901\%$$
- *结论*：确认帧极短时，两者相对误差仅约 $0.04\%$，在工程分析中 $U = \frac{1}{1+2a}$ 具有极高的准确度。

### 4. 实际有效吞吐量推导
$$\text{Throughput} = U_{\text{exact}} \times C \approx 0.9897\% \times 100\,\text{Mb/s} \approx 0.9897\,\text{Mb/s}$$
- *物理分析*：尽管物理信道具备 $100\,\text{Mb/s}$ 的极高带宽，但在该物理距离下使用停止-等待协议，信道超过 $99\%$ 的时间处于空等确认返回的闲置状态，实际有效吞吐量不足 $1\,\text{Mb/s}$。这从数学上证明了在高速、长距离网络中采用流水线滑动窗口机制的必然性。
