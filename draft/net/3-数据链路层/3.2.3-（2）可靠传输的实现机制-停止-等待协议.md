# 3.2.3-（2）可靠传输的实现机制-停止-等待协议

---

## 1. 停止-等待协议的基本原理

停止-等待协议（Stop-and-Wait ARQ）是最简单的可靠传输协议，可以看作是滑动窗口大小为 1 的特殊情况（发送窗口 $W_T = 1$，接收窗口 $W_R = 1$）。

### 1.1 基本工作流程

1. 发送端每次只能发送 1 个数据帧；
2. 发送端发出该帧后，必须暂时保留其副本，启动重传定时器，并**停止发送，等待接收端的确认**；
3. 接收端收到无差错的帧后，递交上层，并向发送端回复一个确认帧（ACK）；
4. 发送端只有在收到对应的 ACK 之后，才能清除该帧的副本，并发送下一个数据帧。

---

## 2. 为什么停止-等待协议必须使用 1 比特序号

直觉上，既然信道中同一时刻最多只有一个未确认的帧在传输，似乎不需要给数据帧进行编号。然而，严密的逻辑推导表明：**如果不加编号，在确认帧发生丢失或延迟到达时，必然导致数据重复交付或死锁**。

### 2.1 确认帧丢失或延迟到达引发的混乱

设想数据帧和确认帧均不携带序号：
1. 发送端发送数据帧 $D_0$；
2. 接收端正确收到 $D_0$，将其交给上层，并回复 $\text{ACK}$；
3. 这个 $\text{ACK}$ 在信道中丢失，或者因信道拥塞迟到了，导致发送端的重传定时器超时；
4. 发送端超时重传，**再次发送了一份完全相同的帧 $D_0$**；
5. 接收端收到重传的 $D_0$：**由于帧没有序号，接收端根本无法判断这是因为上一个 ACK 丢失而重发的旧帧，还是发送端发出的下一个新帧！**
6. 接收端会把这份数据再次交给上层应用，导致上层收到两份重复的数据。

### 2.2 1 比特交替编号的充分性

为了解决重复交付问题，发送端和接收端采用 1 位二进制数进行交替编号（即 `0` 和 `1`）：
- **数据帧交替编号**：数据帧依次标为 0 和 1（`0, 1, 0, 1, ...`）；
- **确认帧携带序号**：确认帧明确指出是对帧 0 还是帧 1 的确认（如 $\text{ACK } 0$ 和 $\text{ACK } 1$）；
- **接收端的判决规则**：
  - 若接收端期待接收帧 1，却收到了帧 0：接收端立即判断出该帧是一个重复帧，**果断丢弃该帧的数据部分，但必须向发送方重新发送 $\text{ACK } 0$**（通知发送方前一帧已收到，促使发送方推进到下一帧）；
- **充分性**：在停止-等待协议中，任意时刻信道中至多只存在“当前帧”与“相邻的前一帧”两种状态，因此只需 1 个比特（0 和 1 两个状态）便完全足以消除歧义。

## 3. 三种异常情况的处理过程

```text
1. 数据帧丢失或出错:
   发送端                         接收端
     │ ─── 帧 0 ───────────────> ╳ (中途丢失或 CRC 校验失败被丢弃)
     │ [启动定时器]
     │ [定时器超时 !]
     │ ─── 帧 0 (重传) ────────> │ (正确收到帧 0，回复 ACK 0)
     │ <───────────── ACK 0 ─── │

2. 确认帧 ACK 丢失:
   发送端                         接收端
     │ ─── 帧 0 ───────────────> │ (正确收到帧 0)
     │                           │ ─── ACK 0 ───> ╳ (ACK 在途中丢失)
     │ [定时器超时 !]
     │ ─── 帧 0 (重传) ────────> │ (发现是重复的帧 0，丢弃数据，补发 ACK 0)
     │ <───────────── ACK 0 ─── │ (发送端收到补发的 ACK 0，继续发送新帧 1)

3. 确认帧 ACK 迟到:
   发送端                         接收端
     │ ─── 帧 0 ───────────────> │ (正确收到帧 0，回复 ACK 0)
     │ [定时器超时 !]             │
     │ ─── 帧 0 (重传) ────────> │ (发现是重复的帧 0，丢弃数据，补发 ACK 0)
     │ <─────── 迟到的 ACK 0 ─── │ (旧的 ACK 0 终于到达，发送端误以为是重传的确认，发送帧 1)
     │ ─── 帧 1 ───────────────> │
     │ <─────── 补发的 ACK 0 ─── │ (发送端通过确认号识别出这是过时的 ACK 0，将其忽略)
```

## 4. 信道利用率与参数 $a$

### 4.1 信道利用率公式推导

设：
- $T_D$：数据帧的发送时延（$T_D = \frac{L}{C}$，其中 $L$ 为帧长，$C$ 为数据传输速率）；
- $RTT$：往返传播时延（$RTT \approx 2 \times T_P$，其中 $T_P$ 为单向传播时延）；
- $T_A$：确认帧的发送时延（通常确认帧很短，可忽略不计）。

在无差错的情况下，发送端发送一个数据帧并收到确认所需要的总时间（发送周期）为：
$$T_{\text{cycle}} = T_D + RTT + T_A \approx T_D + 2T_P$$

**信道利用率（$U$）**为有效发送数据占用的时间与总周期时间之比：
$$U = \frac{T_D}{T_D + 2T_P + T_A} \approx \frac{T_D}{T_D + 2T_P}$$

### 4.2 参数 $a$ 的物理意义

定义**单向传播时延与数据帧发送时延之比**为参数 $a$：
$$a = \frac{T_P}{T_D}$$

将分子分母同除以 $T_D$，可得：
$$U = \frac{1}{1 + 2a}$$

- **当 $a \ll 1$ 时**（即 $T_P \ll T_D$）：数据帧很长或传播距离很短，发送时延占绝对主导地位，$U \to 100\%$，此时停止-等待协议的效率很高；
- **当 $a \gg 1$ 时**（即 $T_P \gg T_D$）：传输距离很远（如卫星通信）或信道速率极高（$T_D$ 极短），发送一帧只需极短时间，绝大部分时间都在空等电磁波在信道中往返飞行，$U \to 0$。停止-等待协议在此类信道中效率极低，必须采用流水线协议（滑动窗口协议）。
