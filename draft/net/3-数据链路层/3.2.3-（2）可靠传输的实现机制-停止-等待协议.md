# 3.2.3 （2）可靠传输的实现机制-停止-等待协议

**停止-等待协议（Stop-and-Wait，SW）** 是最简单的 ARQ 协议：发送方每次只发送**一帧**，发完后停下来等待接收方的确认（ACK），收到 ACK 后再发下一帧。

## 一、基本工作过程

### 情况1：正常传输
```
发送方          接收方
  |------ 帧0 ------>|
  |<----- ACK0 ------|
  |------ 帧1 ------>|
  |<----- ACK1 ------|
```

### 情况2：帧丢失（或出错被丢弃）
```
发送方          接收方
  |------ 帧0 -----> ×  （帧丢失）
  |   （等待超时）
  |------ 帧0 ------>|   （超时重传）
  |<----- ACK0 ------|
```

### 情况3：ACK 丢失
```
发送方          接收方
  |------ 帧0 ------>|
  |       ACK0 -----> ×  （ACK 丢失）
  |   （等待超时）
  |------ 帧0 ------>|   （超时重传）
  |<----- ACK0 ------|
```
接收方收到重复的帧 0，需靠**序号**识别并丢弃重复帧，但仍要重发 ACK0。

## 二、序号

SW 协议只需要 **1 位序号**（即序号 0 和 1 交替），因为同一时刻只有一帧在传输，接收方只需区分"新帧"和"重传帧"。

## 三、信道利用率（效率）公式

设：
- $T_f$：帧的发送时间（= 帧长 / 数据率）
- $T_p$：单向传播时延
- $T_a$：ACK 的发送时间（通常 ACK 很短，近似为 0）

$$\eta = \frac{T_f}{T_f + 2T_p + T_a} \approx \frac{T_f}{T_f + 2T_p}$$

定义 $a = T_p / T_f$（传播时延与帧发送时间之比），则：

$$\eta = \frac{1}{1 + 2a}$$

**结论**：
- $a \ll 1$（传播时延远小于帧发送时间）→ $\eta \approx 1$，效率高（如短距离高速局域网）；
- $a \gg 1$（传播时延远大于帧发送时间）→ $\eta \approx 0$，效率极低（如卫星链路）。

## 四、SW 协议的适用场景

| 场景 | 效率 | 适合 SW？ |
|---|---|---|
| 短距离局域网（RTT 极小） | 高 | 可以 |
| 卫星链路（RTT 约 500 ms） | 极低 | 不适合，应用 GBN/SR |
| 高速长链路（带宽时延积大） | 很低 | 不适合 |

## 五、考点速记

- SW 协议序号只需 **1 bit（0/1 交替）**；
- 效率公式 $\eta = \frac{1}{1+2a}$，其中 $a = T_p / T_f$；
- 出错/超时则**重传同一帧**，接收方靠序号识别重复帧；
- SW 是 GBN/SR 的基础，理解透了后者自然清晰。
