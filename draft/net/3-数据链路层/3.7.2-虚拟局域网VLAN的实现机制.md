# 3.7.2 虚拟局域网 VLAN 的实现机制

虚拟局域网技术必须解决一个关键问题：当一个 VLAN 跨越多台物理交换机时，交换机之间如何识别互联链路上所传输的数据帧到底属于哪一个 VLAN？IEEE 802.1Q 标准为此定义了带标签的以太网帧格式（VLAN 标记）以及交换机端口对数据帧的收发处理规则。

---

## 一、为什么需要 IEEE 802.1Q 标签？

### 1. 跨交换机级联时的“标识缺失”问题
在单台交换机内部划分基于端口的 VLAN 很容易，交换机只需要在内部转发表中记录每个物理端口对应的 VLAN 编号即可。
然而，在多台交换机互联的大型网络中：

```
       [ 交换机 SW1 ] =============================== [ 交换机 SW2 ]
      (端口 1 属于 VLAN 10)                           (端口 1 属于 VLAN 10)
      (端口 2 属于 VLAN 20)                           (端口 2 属于 VLAN 20)
```

如果两台交换机之间仅使用一根普通的以太网双绞线互联：
- 当 SW1 的端口 1（VLAN 10）接收到主机发出的标准以太网帧并转发给 SW2 时，由于标准以太网帧头中只有目的 MAC、源 MAC 和类型字段，**SW2 收到后根本无法分辨该帧最初属于 VLAN 10 还是 VLAN 20**。
- 若要彻底解决该问题，最简单的物理方法是在 SW1 和 SW2 之间为每个 VLAN 专门拉一条独立的物理线缆。但若网络中存在几十甚至上百个 VLAN，将导致级联线缆和物理端口的大量浪费，完全不具备工程可行性。

### 2. 单链路复用与 802.1Q 标记帧
IEEE 802.1Q 标准给出了优雅的解决方案：
1. 两台交换机之间只需要一条高速互联链路（称为**干道链路 Trunk Link**）；
2. 当数据帧离开第一台交换机进入干道链路时，交换机在以太网帧中**插入一个 4 字节的 VLAN 标记（VLAN Tag）**，标明该帧所属的 VLAN 编号；
3. 第二台交换机从干道链路接收到该帧后，读取其中的 VLAN 标记，即可准确知道该帧属于哪个 VLAN，进而只向属于该 VLAN 的端口转发；
4. 当交换机最终将数据帧发送给终端用户主机时，**剥除这 4 字节标记**，还原为标准以太网帧，因为普通终端计算机的网卡通常无法识别带 VLAN 标记的帧。

---

## 二、IEEE 802.1Q 帧格式

IEEE 802.1Q 标记帧在标准以太网 MAC 帧（Ethernet V2）的**“源 MAC 地址”字段与“类型”字段之间**，插入了 **4 字节（32 bit）** 的 VLAN 标记（VLAN Tag）：

```
 标准以太网 MAC 帧 (Ethernet V2):
 +---------------+---------------+------+--------------------------+---------+
 | 目的 MAC (6B) |  源 MAC (6B)  | 类型 |   数据载荷 (46~1500B)    | FCS (4B)|
 +---------------+---------------+------+--------------------------+---------+
                                    |
                                    v 插入 4 字节 802.1Q 标记 (VLAN Tag)
 802.1Q 标记帧 (Tagged Frame):
 +---------------+---------------+-----------+------+--------------------------+---------+
 | 目的 MAC (6B) |  源 MAC (6B)  |  VLAN Tag | 类型 |   数据载荷 (42~1500B)    | FCS (4B)|
 |               |               |  (4 字节) | (2B) |                          | (4 字节)|
 +---------------+---------------+-----------+------+--------------------------+---------+
                                 |<-- 4B --->|
```

### 1. 4 字节 VLAN 标记（VLAN Tag）的字段拆解

4 字节的 VLAN 标记由两个主要字段组成：**标签协议标识符（TPID）** 和 **标签控制信息（TCI）**。

```
 字节偏移:
     0                       1                       2                       3
 +-----------------------+-----------------------+-----------------------+-----------------------+
 |             TPID (16 bit)                     |  PRI (3b) | CFI (1b)  |       VID (12 bit)    |
 |          固定为 0x8100                        | 优先级 0~7|  0=以太网 |   VLAN ID (0 ~ 4095)  |
 +-----------------------+-----------------------+-----------+-----------+-----------------------+
 |<---------- 标签协议标识符 (2 字节) ---------->|<---------------- TCI (2 字节) ---------------->|
```

| 字段名称 | 长度 | 取值与作用解析 |
| :--- | :---: | :--- |
| **TPID（标签协议标识符）** | **16 bit (2 字节)** | 固定取值为十六进制 **`0x8100`**。当设备读取到源 MAC 地址后的两个字节为 `0x8100` 时，即表明该帧是一个带有 802.1Q 标记的以太网帧，而不是普通的以太网帧。 |
| **PRI（优先级）** | **3 bit** | 对应 IEEE 802.1p 标准，用于服务质量（QoS）。3 位二进制可表示 $0 \sim 7$ 共 8 个优先级等级，用于在网络拥塞时优先转发高优先级的流量（如语音通话或控制信令）。 |
| **CFI / DEI（规范格式指示符）** | **1 bit** | Canonical Format Indicator。在标准以太网中该位固定为 **`0`**（表明 MAC 地址为规范格式）；在非以太网（如令牌环网）中为 `1`。在后续标准中该位也被扩展定义为丢弃资格指示符（DEI）。 |
| **VID（VLAN 标识符）** | **12 bit** | **唯一标识该数据帧所属的 VLAN 编号**。12 位二进制可表示 $2^{12} = 4096$ 个取值（$0 \sim 4095$）。<br>• `VID = 0`：保留不用，表示帧中不携带 VLAN ID，仅携带优先级；<br>• `VID = 4095`（全 1）：系统保留，不可分配；<br>• **有效可用 VID 范围**：**$1 \sim 4094$**（全网实际可用的 VLAN 数量最多为 4094 个）。 |

### 2. 标记帧对最大帧长限制的影响
- 标准以太网 MAC 帧的最大长度为 $1518\text{ 字节}$（$6 + 6 + 2 + 1500 + 4 = 1518\text{ B}$）；
- 插入 4 字节 802.1Q 标记后，**802.1Q 标记帧的最大长度变更为 $1522\text{ 字节}$**；
- 遵循 IEEE 802.1Q 标准的以太网设备必须能够接收并处理最大长度为 $1522\text{ 字节}$ 的数据帧，并在插入或剥离 VLAN 标记后重新计算帧尾的 FCS（校验和）。

## 三、交换机端口类型与数据帧处理规则

为了保证既能与普通终端主机互联，又能与其他交换机级联传输标记帧，交换机通常定义了不同的端口工作模式。其中最基础、最核心的两种类型为 **Access 端口（接入端口）** 和 **Trunk 端口（干道端口）**。

### 1. 核心概念：PVID（端口默认 VLAN ID）
交换机的每个物理端口都拥有一个默认的 VLAN 属性，称为 **PVID（Port VLAN ID）**。
- 无论端口配置为 Access 模式还是 Trunk 模式，都必然包含且仅包含一个 PVID；
- 当端口接收到未携带任何标记的普通以太网帧（Untagged 帧）时，交换机以该端口的 PVID 作为该帧所属的 VLAN 归属。

### 2. Access 端口（接入端口）
- **连接对象**：用于连接**终端设备**（如个人计算机、打印机、普通服务器等），这些设备通常无法识别 802.1Q 标记帧。
- **端口归属**：一个 Access 端口**只能属于一个唯一的 VLAN**，其 PVID 即为其所属的 VLAN ID。
- **数据帧处理规则**：
  - **接收方向（从外部进入交换机）**：
    - 接收到未标记帧（Untagged）：交换机为该帧打上本端口的 PVID 标记，并在交换机内部转发；
    - 接收到带标记帧（Tagged）：若帧内的 VID 等于该端口的 PVID，则接收该帧；若 VID 不等于该端口的 PVID，则直接丢弃。
  - **发送方向（从交换机发往外部设备）**：
    - 交换机将数据帧向 Access 端口发送时，**必须先剥除 4 字节的 VLAN 标记**，将其还原为标准的普通以太网帧后再发送给终端设备。

### 3. Trunk 端口（干道端口）
- **连接对象**：用于**交换机与交换机之间**、或**交换机与路由器之间**的互联链路，用于同时承载多个不同 VLAN 的流量。
- **端口归属**：Trunk 端口可以**同时允许多个不同的 VLAN 通过**（配置有允许通过的 VLAN 列表），并且拥有一个 PVID（通常默认为 VLAN 1）。
- **数据帧处理规则**：
  - **接收方向（从外部进入交换机）**：
    - 接收到带标记帧（Tagged）：检查帧内的 VID 是否在允许通过的列表中。若在列表中，则顺利接收并转发；若不在列表中，则丢弃；
    - 接收到未标记帧（Untagged）：交换机为该帧打上本 Trunk 端口的 PVID 标记；若该 PVID 处于允许通过列表中，则接收并转发，否则丢弃。
  - **发送方向（从交换机发往外部设备）**：
    - 检查该帧的 VID 是否在允许通过的列表中，若不在则禁止发送；
    - 若在允许列表中：
      - **若帧的 VID 等于该 Trunk 端口的 PVID**：交换机将**剥除该帧的 4 字节 VLAN 标记**，作为无标记的普通以太网帧发出；
      - **若帧的 VID 不等于该 Trunk 端口的 PVID**：交换机**完整保留该帧的 4 字节 VLAN 标记**，直接发出。

## 四、Access 端口与 Trunk 端口数据帧处理对照表

| 处理阶段 | Access 端口 | Trunk 端口 |
| :--- | :--- | :--- |
| **常见连接设备** | 终端主机（PC、服务器） | 交换机、路由器 |
| **允许通过的 VLAN** | 仅 1 个（即该端口的 PVID） | 允许多个（管理员配置的允许列表） |
| **入站收帧：收到未标记帧 (Untagged)** | 打上本端口的 PVID 标记接收 | 打上本端口的 PVID 标记，若 PVID 在允许列表中则接收，否则丢弃 |
| **入站收帧：收到带标记帧 (Tagged)** | 若 VID == PVID 则接收，否则丢弃 | 若 VID 在允许列表中则接收，否则丢弃 |
| **出站发帧：发送给外部介质** | **一律剥除 VLAN 标记**，还原为标准无标记帧发出 | • 若 VID == 本端口 PVID：**剥除标记**发出；<br>• 若 VID != 本端口 PVID：**保留标记**发出 |
