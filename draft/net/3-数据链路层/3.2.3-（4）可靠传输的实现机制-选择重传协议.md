# 3.2.3-（4）可靠传输的实现机制-选择重传协议

> **本节在 408 中的定位**：选择重传协议（Selective Repeat ARQ，SR）是滑动窗口协议家族中机制最完备、效率最高、硬件实现最复杂的终极形态。408 统考对 SR 的考查难度常年位列全章之巅，核心命题刀刃在于**“发送窗口与接收窗口的数学约束 $W_T + W_R \le 2^n$（对称情况下 $W_T = W_R \le 2^{n-1}$）的微观反例证伪”**、**“逐个确认（Individual ACK）与独立重传定时器阵列”**、**“接收方滑动窗口向前推进的时机”**，以及**SW、GBN、SR 三大协议的横向横评与计算判决**。

---

## 一、第一性原理与设计动因：为什么需要选择重传（SR）？

### 1. GBN 在大时延高误码网络中的“雪崩式崩溃”
在回退 N 帧（GBN）协议中，只要有一个帧（例如帧 2）丢失，即使后续紧随的帧 3、帧 4、...、帧 100 全部毫发无损地抵达接收方网卡，接收方也必须将它们统统当成垃圾扔掉。发送方超时后必须将帧 2 到 100 全部重新在线路上狂飙一遍。
- **致命瓶颈**：随着信道带宽时延积（BDP）的扩大，信道中“在途（in-flight）”的帧越来越多，GBN 这种“一人犯错、全家重发”的连坐机制，会导致实际吞吐率断崖式跌至近乎于零。

### 2. SR 的解题哲学：精确手术刀式重传
- **接收端付出硬件代价**：接收端不再是 $W_R = 1$ 的简陋状态，而是开辟了一个大小为 $W_R > 1$ 的**高速乱序接收缓冲区（Out-of-Order Buffer）**；
- **允许乱序暂存**：若帧 2 丢失，后续正确到达的帧 3、帧 4 不再被丢弃，而是**直接存入接收缓冲区并立即向发送端单独回复 $ACK\ 3$、$ACK\ 4$**；
- **发送端精准补发**：发送端为**每一个发出去的未确认帧配备独立的定时器**。只有帧 2 的定时器超时，发送端**仅重发受损的帧 2 一个孤本**，帧 3、4 绝不重发！
- **按序批量交付**：一旦补发的帧 2 顺利抵达接收端，接收缓冲区拼齐了完整的连续拼图（2, 3, 4），接收端**一口气将它们按序批量交付给上层网络层**，接收窗口整体大幅向前滑动！

## 二、微观机制：双向滑动窗口与逐个确认时序推演

### 1. 双窗口的微观时空状态
设序号位数为 $n$，序号空间为 $0 \sim 2^n - 1$。
- **发送窗口 $W_T$**：
  - 记录已发送但等待单独 ACK 的帧；
  - 收到失序帧的 ACK（如收到 ACK 3 但 ACK 2 没来），标记帧 3 为“已确认”，但**发送窗口的底座不能前移**，必须等最底部的帧 2 确认后才能滑动。
- **接收窗口 $W_R$**：
  - 记录允许接收并缓存的序号区间；
  - 只有当**最底部的按序帧（窗口下沿）被成功接收**，接收窗口才会向前滑动。

```
接收窗口滑动时序 (假设 W_R = 4):
当前接收窗口: [ 2 (缺失) ] [ 3 (已缓存) ] [ 4 (已缓存) ] [ 5 (空闲) ]
                             ^              ^
                             收到数据并暂存  收到数据并暂存
此时接收窗口下沿卡在 2，不能滑动！
当帧 2 补发到达:
接收端瞬间凑齐 2, 3, 4!
===> 将 2, 3, 4 一起递交上层应用!
===> 接收窗口下沿直接从 2 狂飙跳跃到 5!
全新接收窗口: [ 5 ] [ 6 ] [ 7 ] [ 0 ]
```

### 2. SR 协议完整微观时序图剖析
```
发送方 (W_T = 4)                                     接收方 (W_R = 4)
  | --- 帧 0 -----------------------------------------> | (收到 0，递交，发 ACK 0，窗口滑移)
  | --- 帧 1 (途中丢失!) ------------> ×                 |
  | --- 帧 2 -----------------------------------------> | (收到 2: 乱序! 缓存 2，发 ACK 2)
  | --- 帧 3 -----------------------------------------> | (收到 3: 乱序! 缓存 3，发 ACK 3)
  |                                                     |
  | <---------------------- ACK 0 --------------------- | (发送方确认 0，窗口滑移)
  | <---------------------- ACK 2 --------------------- | (发送方标记 2 已收到，窗口不滑)
  | <---------------------- ACK 3 --------------------- | (发送方标记 3 已收到，窗口不滑)
  |                                                     |
  | [仅 帧 1 的定时器超时 !]                             | (只有 1 的定时器爆炸，2/3 不超时)
  | --- 帧 1 (单帧重发) -----------------------------> | (收到 1! 拼齐 1, 2, 3!)
  |                                                     |  [动作: 1, 2, 3 批量递交上层]
  |                                                     |  [动作: 接收窗口大幅向前滑动 3 格]
  | <---------------------- ACK 1 --------------------- |
  | (发送方收到 ACK 1，窗口底座一口气向前滑动到 4!)
```

## 三、为什么 SR 必须满足 $W_T + W_R \le 2^n$（$W_T \le 2^{n-1}$）？（408 终极反例证明）

这是 408 统考历年难度极高、极易误选的理论核心。

### 1. 经典数学约束推导
设序号空间大小为 $N = 2^n$。在最恶劣的情况下：
1. 发送方发满了整个发送窗口的所有数据帧：$[0, 1, \dots, W_T - 1]$；
2. 接收方**全部正确接收**了这 $W_T$ 个帧，并将自己的接收窗口向前完全滑动了 $W_T$ 个位置；
3. 接收方的全新接收窗口范围变为：$[W_T, W_T + 1, \dots, W_T + W_R - 1]$；
4. **信道发生极端故障**：接收方发回的所有 $W_T$ 个 ACK 帧**全部在信道中灰飞烟灭**；
5. 发送方定时器超时，重新发送上一轮未被确认的旧数据帧，其中包含最小的旧序号：**`0`**；
6. 此时，旧帧 `0` 飞到了接收方网卡。

### 2. 歧义诞生的充要条件
接收方为了**绝对不会把重发的旧帧 0 误当成新帧 0 接收**，接收方当前的全新接收窗口区间 $[W_T, W_T + W_R - 1]$ 中，**绝对不能包含经过模 $2^n$ 回绕后的序号 0**！
这意味着：从 0 开始跨越整个原窗口和新窗口的总跨度，不能超过序号空间总量 $2^n$：
$$W_T + W_R \le 2^n$$

### 3. 对称窗口下的黄金推论（$W_T = W_R$）
工程上为了收发双方地位对称、缓冲区利用最优，通常令发送窗口与接收窗口相等：$W_T = W_R$。
代入不等式：
$$W_T + W_T \le 2^n \implies 2 W_T \le 2^n \implies W_T \le 2^{n-1}$$
**黄金铁律**：**在选择重传协议中，发送窗口和接收窗口的最大尺寸，绝对不能超过序号空间容量的一半（即 $2^{n-1}$）！**

### 4. 具象反例（假定 $n=3$，$2^n = 8$，令 $W_T = W_R = 5 > 4$ 会发生什么？）
- 序号空间：`0, 1, 2, 3, 4, 5, 6, 7`；
- 发送方发送：`0, 1, 2, 3, 4`（共 5 帧）；
- 接收方全收到，回复 ACK，接收窗口向前滑动 5 格，新接收窗口变为：`[5, 6, 7, 0, 1]`；
- 所有 ACK 全丢，发送方超时重传旧帧 `0`；
- 接收方查看当前窗口：**`[5, 6, 7, 0, 1]` 里面赫然包含 `0`！**
- 接收方**无法分辨**这是旧帧 0 还是回绕后的新帧 0，直接当成新数据收下，**系统发生不可挽回的数据错乱！**

## 四、408 三大可靠传输协议（SW / GBN / SR）横向全维横评

| 维度 / 协议 | 停止-等待 (Stop-and-Wait) | 回退 N 帧 (Go-Back-N) | 选择重传 (Selective Repeat) |
| :--- | :--- | :--- | :--- |
| **发送窗口 $W_T$** | $W_T = 1$ | $1 < W_T \le 2^n - 1$ | $W_T \le 2^{n-1}$（通常取 $2^{n-1}$） |
| **接收窗口 $W_R$** | $W_R = 1$ | $W_R = 1$（极简） | $W_R \le 2^{n-1}$（通常 $W_R = W_T$） |
| **核心约束关系** | 无需约束（1 bit 序号） | $W_T + W_R \le 2^n \implies W_T \le 2^n - 1$ | $W_T + W_R \le 2^n \implies W_T \le 2^{n-1}$ |
| **重传范围** | 仅超时帧 | **超时帧及其后所有已发帧（连坐）** | **仅重传出错/超时的单帧（精准）** |
| **接收端缓冲区** | 无需乱序缓存 | 无需乱序缓存（来错就丢） | **必须有乱序缓存队列** |
| **ACK 确认机制** | 独立确认 | **累计确认（Cumulative ACK）** | **逐个/选择确认（Individual ACK）** |
| **定时器数量** | 1 个 | 1 个（绑定最早未确认帧） | **每个未确认帧各 1 个（定时器阵列）** |
| **高误码信道利用率** | 极低 | 极低（重传雪崩） | **最高（仅重发坏帧）** |

## 五、408 统考真题级计算演练与窗口极限推导

### 【题型模型：滑动窗口协议选型、序号位数字节与信道性能极值推导】

**【考题背景】**
两台主机通过一条全双工链路相连。
- 链路带宽 $C = 100\text{ Mbps}$；
- 单向传播时延 $T_p = 10\text{ ms}$；
- 数据帧长固定为 $L_f = 2500\text{ 字节}$；
- 确认帧 ACK 极短，忽略其发送时延；
- 链路误码率极低，可视为无差错传输。

**【试求解】**：
1. 计算单帧发送时延 $T_f$ 与信道往返时间 $RTT$；
2. 若采用选择重传协议（SR），且要求信道利用率达到 $100\%$，求发送窗口 $W_T$ 的理论最小值；
3. 承接第 2 问，若令 $W_T = W_R = W_{T,\min}$，协议帧首部中的序号字段至少需要多少位（bit）二进制？
4. 若帧首部序号字段仅有 4 位二进制：
   - 在保证协议正常工作的前提下，SR 协议允许的最大发送窗口 $W_{T,\max}$ 是多少？
   - 此时该链路能达到的最大信道利用率是多少？

---

### 【草稿纸执行第一步：单位换算与时间分量】
- $C = 100\text{ Mbps} = 10^8\text{ bps}$；
- $L_f = 2500 \times 8\text{ bit} = 20000\text{ bit} = 2 \times 10^4\text{ bit}$；
- 单向传播时延 $T_p = 10\text{ ms} = 0.01\text{ s}$；
- 往返传播时延 $2T_p = 20\text{ ms}$。

---

### 【严密推导过程】

#### 第 1 问：单帧发送时延与 RTT
1. 单帧发送时延：
   $$T_f = \frac{L_f}{C} = \frac{2 \times 10^4\text{ bit}}{10^8\text{ bps}} = 2 \times 10^{-4}\text{ s} = 0.2\text{ ms}$$
2. 信道往返时间（无 ACK 发送时延）：
   $$RTT = 2 \times T_p = 20\text{ ms}$$
3. 发送一个帧并收到其确认的总周期：
   $$T_{\text{cycle}} = T_f + RTT = 0.2\text{ ms} + 20\text{ ms} = 20.2\text{ ms}$$

#### 第 2 问：达到 100% 利用率的最小发送窗口
要使发送端毫无停歇地连续发送（利用率 $100\%$）：
$$W_T \times T_f \ge T_{\text{cycle}} \implies W_T \ge \frac{T_{\text{cycle}}}{T_f} = \frac{20.2\text{ ms}}{0.2\text{ ms}} = 101$$
因此，发送窗口 $W_T$ 至少为 **101**。

#### 第 3 问：所需最小序号位数计算
- 在 SR 协议中，窗口大小与序号位数 $n$ 的关系为：$W_T + W_R \le 2^n$；
- 当 $W_T = W_R = 101$ 时：
  $$W_T \le 2^{n-1} \implies 2^{n-1} \ge 101$$
- 检验 2 的幂次：
  - $2^6 = 64 < 101$
  - $2^7 = 128 \ge 101$
  - 得：$n - 1 \ge 7 \implies n \ge 8\text{ 位}$。
- 故帧首部序号字段至少需要 **8 位**（整整 1 个字节）。

#### 第 4 问：4 位序号下的极值性能推导
1. 序号位数 $n = 4$ 位，序号空间总量为 $2^4 = 16$；
2. SR 协议的最大发送窗口为序号空间的一半：
   $$W_{T,\max} = 2^{4-1} = 2^3 = 8$$
3. 此时一个往返周期内最多只能发送 8 个帧：
   $$U = \frac{W_T \times T_f}{T_{\text{cycle}}} = \frac{8 \times 0.2\text{ ms}}{20.2\text{ ms}} = \frac{1.6}{20.2} \approx 7.92\%$$
   *结论分析*：仅有 4 位序号限制时，SR 协议受制于发送窗口上限，信道利用率只有可怜的 $7.92\%$。

## 六、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：混淆 GBN 与 SR 的最大窗口公式**
> - **408 头号经典考点**：
>   - GBN：$W_T \le 2^n - 1$（减 1 是因为接收窗口为 1）；
>   - SR：$W_T \le 2^{n-1}$（除以 2 是因为接收窗口也分走了一半空间）。
>   - 考场一见 $n$ 位序号：问 GBN 最大窗口写 $2^n-1$，问 SR 最大窗口写 $2^{n-1}$，绝不能张冠李戴！

> [!CAUTION]
> **陷阱 2：误以为 SR 协议接收窗口必须严格等于发送窗口**
> - 理论上只需满足 **$W_T + W_R \le 2^n$ 且 $W_R \le W_T$** 即可，并不强制要求 $W_T = W_R$。例如 $n=3$（总空间 8），取 $W_T = 5, W_R = 3$ 是完全合法且不会发生歧义的！但在 408 统考没有特别指明时，默认按对称窗口 $W_T = W_R = 2^{n-1}$ 计算。

### 2. 考场核心记忆桩
- **“GBN 减去一，SR 砍一半”**：最大发送窗口的秒杀判定。
- **“GBN 累积确认怕错帧，SR 单独确认要缓存”**：两类流水线协议的微观本质。
