# 3.2.3-（4）可靠传输的实现机制-选择重传协议

在回退N帧（GBN）协议中，由于接收端不设乱序缓冲区（$W_R = 1$），一旦中间某个帧受损丢失，其后所有正确到达的帧均被丢弃，造成重传雪崩。**选择重传协议（Selective Repeat, SR）**通过在接收端引入乱序接收缓冲区，实现仅针对出错单帧的“精准选择性重传”，是流水线滑动窗口协议的最高演进形态。

---

## 一、设计思想：乱序缓存与精准重传

为了克服 GBN 在长距离、高速或高误码网络中的带宽回退浪费，SR 协议进行了硬件与算法层面的全面重构：
1. **接收端开辟乱序缓冲区（$W_R > 1$）**：
   接收端不再将失序帧无情丢弃。若某帧丢失，其后到达的正确数据帧将被暂存在接收窗口的缓冲区中，并向发送端回复**针对该特定序号的逐个肯定确认（Individual ACK）**；
2. **发送端维护独立定时器阵列**：
   发送端为每一个发出的未确认帧维护独立的重传定时器。仅当某个特定帧的定时器超时时，发送端**仅重传该受损帧单个孤本**，其余已收到确认的帧绝不重发；
3. **按序批量提交与窗口大幅滑动**：
   一旦缺失的帧补发到达，接收端将该帧与缓冲区中后续已缓存的连续帧**拼齐后一次性按序批量交付给上层网络层**，接收窗口整体向前滑动。

---

## 二、双向滑动窗口与状态流转

### 1. 发送窗口与接收窗口的工作状态
设帧序号字段的位宽为 $n$ 位，序号空间大小为 $2^n$。

```text
接收窗口滑动机制 (设 W_R = 4):
当前接收窗口: [ 2 (缺失) ] [ 3 (已暂存) ] [ 4 (已暂存) ] [ 5 (空闲) ]
                             │              │
                             ▼ 收到并缓存   ▼ 收到并缓存
此时窗口下沿受阻于帧 2，窗口绝对不能向前滑动！

当帧 2 补发到达:
接收端瞬间凑齐连续帧 [ 2, 3, 4 ] !
───> 将帧 2、3、4 批量按序交付给上层协议；
───> 接收窗口下沿从 2 直接跃迁推进到 5；
全新接收窗口变为: [ 5 ] [ 6 ] [ 7 ] [ 0 ]
```

- **发送窗口 $W_T$**：
  - 收到失序帧的 ACK（如收到 ACK 3 但 ACK 2 尚未返回），仅在窗口内标记帧 3 为“已确认”，**发送窗口下沿不能移动**；
  - 只有当窗口下沿对应的最早未确认帧（帧 2）收到 ACK 时，发送窗口才能向前滑动；
- **接收窗口 $W_R$**：
  - 只有当窗口下沿所等待的数据帧正确到达时，接收窗口才能向前滑动。

### 2. SR 协议完整时序流转过程

```text
发送端 (W_T = 4)                                     接收端 (W_R = 4)
  │ ─── 帧 0 ─────────────────────────────────────────> │ (收到 0，递交上层，回复 ACK 0，窗口滑移)
  │ ─── 帧 1 (信道丢失) ──────────────> ╳               │
  │ ─── 帧 2 ─────────────────────────────────────────> │ (收到 2: 乱序! 缓存 2，回复 ACK 2)
  │ ─── 帧 3 ─────────────────────────────────────────> │ (收到 3: 乱序! 缓存 3，回复 ACK 3)
  │                                                     │
  │ <────────────────────── ACK 0 ───────────────────── │ (发送端收到 ACK 0，窗口向前滑动 1 格)
  │ <────────────────────── ACK 2 ───────────────────── │ (发送端标记帧 2 已确认，窗口不滑)
  │ <────────────────────── ACK 3 ───────────────────── │ (发送端标记帧 3 已确认，窗口不滑)
  │                                                     │
  │ [仅 帧 1 的定时器超时 !]                            │ (仅帧 1 触发超时，帧 2/3 不超时)
  │ ─── 帧 1 (单帧补发) ─────────────────────────────> │ (收到 1! 拼齐 1, 2, 3)
  │                                                     │ [动作: 1, 2, 3 批量交付上层]
  │                                                     │ [动作: 接收窗口底座向前推进 3 格]
  │ <────────────────────── ACK 1 ───────────────────── │
  │ (发送端收到 ACK 1，窗口底座一口气滑过 1, 2, 3，推进到 4)
```

## 三、窗口尺寸极值约束：为什么必须满足 $W_T + W_R \le 2^n$？

在 SR 协议中，为了防止序号回绕产生新旧帧无法辨别的致命歧义，窗口尺寸必须满足严格的数学约束：
$$W_T + W_R \le 2^n$$

### 1. 产生歧义的物理情境
设序号空间大小为 $2^n$：
1. 发送端发满了当前发送窗口的所有数据帧：$[0, 1, \dots, W_T - 1]$；
2. 接收端**全部正确接收**了这 $W_T$ 个帧，将其交付上层，并将接收窗口整体向前推进了 $W_T$ 个位置；
3. 接收端全新的接收窗口范围变为：$[W_T, W_T + 1, \dots, W_T + W_R - 1]$；
4. **极端信道故障**：接收端为这 $W_T$ 个帧发回的全部 ACK 确认帧**在反向信道中全部丢失**；
5. 发送端定时器超时，重新发送上一轮未被确认的旧数据帧，其中包括序号最小的旧帧 `0`；
6. 此时，旧帧 `0` 抵达接收端网卡。

### 2. 避免新旧帧混淆的充要条件
接收端为了**绝对不会把重发的旧帧 0 误判为下一轮的新帧 0 接收**，接收端当前的新窗口区间 $[W_T, W_T + W_R - 1]$ 在模 $2^n$ 意义下，**绝对不能跨越回绕包含序号 0**！
因此，从原窗口起点 0 开始，跨越原发送窗口跨度（$W_T$）与新接收窗口跨度（$W_R$）的总和，不能超过整个序号空间的总容量：
$$W_T + W_R \le 2^n$$

### 3. 对称窗口下的黄金推论（$W_T = W_R$）
工程实现中，为使收发双方地位对称且缓冲区利用率最高，通常令发送窗口与接收窗口大小相等：$W_T = W_R$。
代入上述约束：
$$W_T + W_T \le 2^n \implies 2W_T \le 2^n \implies W_T \le 2^{n-1}$$
**结论**：在对称选择重传协议中，**发送窗口和接收窗口的最大尺寸，均不得超过序号空间容量的一半（$2^{n-1}$）**。

#### 具象反例推演（若 $n=3$，$2^n=8$，错误令 $W_T = W_R = 5 > 4$）
- 序号空间为 $\{0, 1, 2, 3, 4, 5, 6, 7\}$；
- 发送端发送帧 `0, 1, 2, 3, 4`；
- 接收端全收到，回复 ACK，接收窗口向前滑动 5 格，新接收窗口变为 `[5, 6, 7, 0, 1]`；
- 所有 ACK 途中丢失，发送端超时重传旧帧 `0`；
- 接收端检查当前接收窗口：`[5, 6, 7, 0, 1]` 中赫然包含 `0`！
- 接收端无法分辨该帧是发送端重发的旧帧 0，还是已经收到 ACK 后发送的新一轮第 8 个帧 0，将其当作新数据接收，系统发生严重的数据破坏。

## 四、三大可靠传输协议（SW / GBN / SR）横向全维对比

| 对比维度 | 停止-等待协议 (SW) | 回退N帧协议 (GBN) | 选择重传协议 (SR) |
|---|---|---|---|
| **发送窗口尺寸 $W_T$** | $W_T = 1$ | $1 < W_T \le 2^n - 1$ | $W_T \le 2^{n-1}$（对称时） |
| **接收窗口尺寸 $W_R$** | $W_R = 1$ | $W_R = 1$（极简无缓存） | $W_R \le 2^{n-1}$（通常 $W_R = W_T$） |
| **窗口核心数学约束** | $W_T = 1, W_R = 1$ | $W_T + W_R \le 2^n \implies W_T \le 2^n - 1$ | $W_T + W_R \le 2^n \implies W_T \le 2^{n-1}$ |
| **重传影响范围** | 仅超时帧 | **超时帧及其后所有已发帧（批量回退）** | **仅重传出错或超时的孤立单帧（精准重传）** |
| **接收端乱序缓存** | 无需缓存 | 无需缓存（失序即弃） | **必须具备乱序接收缓冲区** |
| **确认机制语义** | 逐帧确认 | **累计确认（Cumulative ACK）** | **选择性逐帧确认（Individual ACK）** |
| **定时器硬件成本** | 仅需 1 个 | 仅需 1 个（绑定最早未确认帧） | **每个未确认帧独立维护 1 个（定时器阵列）** |
| **高误码/大时延信道适应性** | 极低 | 低（重传开销雪崩） | **最高（有效利用率最佳）** |

## 五、综合窗口极限与性能推导演练

### 场景参数
- 链路特征：直连全双工点对点通信线路；
- 物理传输带宽：$C = 100\,\text{Mb/s} = 10^8\,\text{b/s}$；
- 单向传播时延：$T_p = 10\,\text{ms} = 0.01\,\text{s}$；
- 数据帧总长度：$L_f = 2500\,\text{字节} = 20000\,\text{bit}$；
- 确认帧 ACK 极短，忽略其发送时延；
- 链路处于无差错稳定传输状态。

### 1. 基础时延分量计算
1. **单帧发送时延**：
   $$T_f = \frac{L_f}{C} = \frac{20000\,\text{bit}}{10^8\,\text{b/s}} = 0.0002\,\text{s} = 0.2\,\text{ms}$$
2. **往返传播时延**：
   $$RTT = 2 \times T_p = 2 \times 10\,\text{ms} = 20\,\text{ms}$$
3. **一个完整的发送与确认周期耗时**：
   $$T_{\text{cycle}} = T_f + RTT = 0.2\,\text{ms} + 20\,\text{ms} = 20.2\,\text{ms}$$

### 2. 满载传输（100% 利用率）的最小发送窗口
要使发送端数据流连续流水化传输而不停歇空等：
$$W_T \times T_f \ge T_{\text{cycle}} \implies W_T \ge \frac{T_{\text{cycle}}}{T_f} = \frac{20.2\,\text{ms}}{0.2\,\text{ms}} = 101$$
因此，达到 100% 利用率所需的最小发送窗口为 $W_{T,\min} = 101$。

### 3. 支持该窗口所需的最小序号编码位宽
在对称 SR 协议中，$W_T \le 2^{n-1}$：
$$2^{n-1} \ge 101$$
检验 2 的幂次：
- $2^6 = 64 < 101$；
- $2^7 = 128 \ge 101$；
解得：
$$n - 1 \ge 7 \implies n \ge 8\,\text{位}$$
因此，帧首部的序号字段至少需要 **8 位** 二进制（即整整 1 字节）。

### 4. 序号位宽受限（$n = 4$）时的极值性能分析
若协议首部仅分配了 $n = 4$ 位二进制作为序号：
1. **SR 协议允许的最大发送窗口**：
   $$W_{T,\max} = 2^{4-1} = 2^3 = 8$$
2. **此时能够达到的最大信道利用率**：
   $$U = \frac{W_{T,\max} \times T_f}{T_{\text{cycle}}} = \frac{8 \times 0.2\,\text{ms}}{20.2\,\text{ms}} = \frac{1.6}{20.2} \approx 7.92\%$$
3. **实际有效数据吞吐量**：
   $$\text{Throughput} = U \times C \approx 7.92\% \times 100\,\text{Mb/s} \approx 7.92\,\text{Mb/s}$$
- *物理分析*：受制于 4 位序号空间的严格数学约束，发送窗口无法开大，导致高速信道超过 $92\%$ 的带宽处于闲置等待状态。
