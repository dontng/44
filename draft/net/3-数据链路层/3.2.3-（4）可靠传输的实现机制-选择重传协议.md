# 3.2.3-（4）可靠传输的实现机制-选择重传协议

---

## 1. 选择重传协议（SR）的设计思想

在回退N帧（GBN）协议中，由于接收端不设乱序缓冲区（$W_R = 1$），一旦中间某个帧在信道中丢失，其后所有正确到达的帧也都会被无情丢弃，造成发送端必须从出错的帧开始批量重传，浪费了大量信道带宽。

为了进一步提高信道利用率，**选择重传协议（Selective Repeat, SR）**进行了两项重大改进：
1. **接收端设置乱序缓冲区（接收窗口 $W_R > 1$）**：
   接收端不再盲目丢弃失序帧。若某一帧丢失，其后到达的正确帧将被暂存进接收窗口的缓冲区中，并向发送方回复**逐帧单独确认（Individual ACK）**；
2. **发送端仅重传出错的单帧**：
   发送端为每一个发出的未确认帧维护独立的重传定时器。仅当某个特定帧超时未收到确认时，发送端**只重传该超时帧本身**，其余已经收到确认的帧绝不重发；
3. **按序连续交付与窗口向前滑动**：
   一旦缺失的那个帧被成功补发到达，接收端将该帧与缓冲区中先前暂存的连续帧**拼齐后一次性按序交付给上层网络层**，接收窗口随之向前滑动。

---

## 2. 滑动窗口与确认机制

### 2.1 接收窗口的工作过程

设接收窗口大小为 $W_R$：
- 接收窗口表示当前允许接收并缓存的帧的序号范围；
- 当收到一个落在接收窗口范围内的正确帧时：
  - 若该帧恰好是窗口下界所期待的那个帧：接收端将其接收，并连同其后已经在缓冲区中连续就绪的所有帧一起交付给上层，然后接收窗口向前滑动；
  - 若该帧不是窗口下界所期待的帧（即失序到达）：接收端先将其存入缓冲区，向发送端回复针对该帧的单独确认，但**接收窗口下界不能移动**。

### 2.2 逐帧单独确认（Individual ACK）

与 GBN 的累计确认不同，SR 协议采用**逐帧单独确认**：
- 确认帧明确指出是对某一个特定序号数据帧的确认；
- 发送端收到对某一帧的确认后，仅在发送窗口中标记该帧为“已确认”；
- 只有当发送窗口下界所对应的最早未确认帧收到确认时，发送窗口才能向前滑动。

## 3. 出错重传过程时序图

```text
发送端 (设 W_T = 4)                                   接收端 (设 W_R = 4)
  │ ─── 帧 0 ─────────────────────────────────────────> │ (收到 0，递交上层，回复 ACK 0，窗口滑动)
  │ ─── 帧 1 (信道丢失) ──────────────> ╳               │
  │ ─── 帧 2 ─────────────────────────────────────────> │ (收到 2: 失序! 暂存 2，回复 ACK 2)
  │ ─── 帧 3 ─────────────────────────────────────────> │ (收到 3: 失序! 暂存 3，回复 ACK 3)
  │                                                     │
  │ <────────────────────── ACK 0 ───────────────────── │ (收到 ACK 0，发送窗口向前滑动 1 格)
  │ <────────────────────── ACK 2 ───────────────────── │ (标记帧 2 已确认，窗口下沿不能移动)
  │ <────────────────────── ACK 3 ───────────────────── │ (标记帧 3 已确认，窗口下沿不能移动)
  │                                                     │
  │ [仅 帧 1 的重传定时器超时 !]                         │ (仅帧 1 超时，帧 2 和帧 3 不重传)
  │ ─── 帧 1 (单帧重发) ─────────────────────────────> │ (收到 1! 拼齐 1, 2, 3，全部递交上层)
  │ <────────────────────── ACK 1 ───────────────────── │ (接收窗口向前大幅滑动)
  │ (收到 ACK 1，发送窗口向前大幅滑动)                   │
```

## 4. 窗口大小的数学约束与反证推导

若用 $n$ 个比特表示帧序号，序号空间大小为 $2^n$。在选择重传协议中，为了避免新旧帧混淆，发送窗口 $W_T$ 与接收窗口 $W_R$ 必须满足：

$$W_T + W_R \le 2^n$$

在最常见且效率最高的**对称窗口配置（即 $W_T = W_R$）**下：

$$W_T \le 2^{n-1}, \quad W_R \le 2^{n-1}$$

即**发送窗口和接收窗口的最大尺寸不能超过序号空间大小的一半（$2^{n-1}$）**。

### 反证推导：为什么窗口大小不能超过 $2^{n-1}$？

假设 $n = 3$，序号空间为 $[0, 7]$（共 8 个序号，$2^{n-1} = 4$）。
若违反该规则，设发送窗口和接收窗口大小均为 $W_T = W_R = 5$（大于 4）：
1. 发送端依次发送了序号为 $0, 1, 2, 3, 4$ 的 5 个帧；
2. 接收端全部正确接收了这 5 个帧，交给上层，并向发送端发回了 5 个确认帧。此时接收窗口向前滑动 5 格，**新的接收窗口变为 $[5, 6, 7, 0, 1]$**；
3. **故障情境**：这 5 个确认帧在反向信道中全部丢失；
4. 发送端为帧 0 设定的定时器超时，重新发出了**上一轮的旧帧 0**；
5. 接收端收到这个旧的帧 0：
   - 接收端检查自己的当前接收窗口 $[5, 6, 7, 0, 1]$；
   - 接收端发现序号 `0` 恰好**落在当前接收窗口的有效范围内**！
   - 接收端无法分辨这个帧 0 是发送端重发的旧帧 0，还是已经收到确认后发出的新一轮新帧 0！
   - 接收端将其当作新数据接收并暂存，系统发生严重的数据重复与乱序破坏。
- **结论**：为了保证“当前接收窗口”与“可能发生重传的发送窗口”所涉及的序号集合永远不产生任何交叠，窗口大小严格不能超过序号空间的一半，即 $W_T = W_R \le 2^{n-1}$。

## 5. 三大可靠传输协议（SW / GBN / SR）对比总结

| 协议类型 | 发送窗口大小 $W_T$ | 接收窗口大小 $W_R$ | 核心窗口约束 | 重传范围 | 确认方式 | 接收端乱序缓存 |
| :--- | :---: | :---: | :--- | :--- | :--- | :---: |
| **停止-等待 (SW)** | $W_T = 1$ | $W_R = 1$ | $W_T = 1, W_R = 1$ | 仅当前超时帧 | 逐帧确认 | 无需缓存 |
| **回退N帧 (GBN)** | $1 < W_T \le 2^n - 1$ | $W_R = 1$ | $W_T \le 2^n - 1$ | **超时帧及其后所有已发帧** | **累计确认** | 无需缓存（失序即弃） |
| **选择重传 (SR)** | $W_T \le 2^{n-1}$ | $W_R \le 2^{n-1}$ | $W_T + W_R \le 2^n$ | **仅重传超时的单个出错帧** | **逐帧单独确认** | **必须具备乱序缓冲区** |
