# 3.4.5-（2）在数据链路层扩展以太网-透明网桥的自学习和转发帧的过程以及生成树协议 STP

---

## 1. 为什么需要自学习算法与生成树协议？

### 1.1 为什么需要动态自学习？

在大型局域网中，设备随时可能移动、接入或下线，人工静态配置转发表工作量极大且极易出错：
- **自学习（Self-Learning）的核心逻辑**：网桥“即插即用”，通过被动监听每个端口上进入的数据帧，自动在内存中建立 MAC 地址与端口的映射关系；
- **基本假设**：若一个帧从端口 $P$ 传来，且该帧的**源 MAC 地址**为 $S$，则网桥记住：**以后发往目的 MAC 为 $S$ 的帧，只需从端口 $P$ 转发出去即可**。

### 1.2 物理环路带来的灾难

为了提高可靠性，网络管理员常常在网桥之间引入冗余线路，形成物理闭合环路：

```text
          [ 主机 A 发送一个广播帧 ]
                     │
       ┌─────────────┴─────────────┐
       ▼                           ▼
   [ 网桥 B1 ] ═════════════════ [ 网桥 B2 ]
       │                           │
       └─────────────┬─────────────┘
                     ▼
               [ 闭合物理环路 ]
```

若没有防环机制，物理环路将引发三大网络灾难：
1. **广播风暴（Broadcast Storm）**：
   以太网帧首部**没有生存时间（TTL）字段**。广播帧在环路中将无限循环复制扩散，在几毫秒内信道被完全塞死，全网瘫痪；
2. **转发表震荡（MAC 地址漂移）**：
   同一个广播帧在环路上双向乱窜，网桥 B1 刚从端口 1 记录 `A -> 端口 1`，下一刻又从端口 2 收到同一广播帧并改写为 `A -> 端口 2`。转发表频繁被错误覆写，导致单播数据完全无法正确定向；
3. **主机重复接收数据帧**：目的主机会持续接收到指数倍增的重复帧副本。

## 2. 透明网桥自学习与转发的执行规则

网桥对每个合法入站帧的处理严格遵循两条并行逻辑：

```text
+---------------------------------------------------------------------------------------------------+
|  收到入站数据帧 (包含: 入端口 InPort, 源 MAC 字段 SrcMAC, 目的 MAC 字段 DstMAC)                     |
+---------------------------------------------------------------------------------------------------+
       │                                                                            │
       │ 【自学习写表逻辑：严格基于 源 MAC 地址】                                    │ 【查表转发逻辑：严格基于 目的 MAC 地址】
       ▼                                                                            ▼
  检查转发表中是否存在条目 (SrcMAC)                                            在转发表中检索条目 (DstMAC)
  - 若无：新增表项 [SrcMAC -> InPort, 启动老化计时]                             - 命中表项 且 映射出端口 == InPort:
  - 若有：更新端口映射并【重置老化定时器】                                           【过滤丢弃】(同网段已本地接收)
  (注：自学习绝不看目的 MAC 地址!)                                             - 命中表项 且 映射出端口 != InPort:
                                                                                   【单播转发】(由该映射端口发出)
                                                                                - 未命中表项 (未知单播) 或 目的为广播/组播:
                                                                                   【泛洪转发】(向除 InPort 外所有端口复制广播)
```

### 2.1 表项老化时间（Aging Time）

- 转发表中的动态表项均绑定独立的老化计时器（通常默认设置约为几分钟）；
- 每次收到匹配源 MAC 的新帧，计时器重新刷新；
- 若某主机下线或换线，超过老化时间未发送帧，对应条目自动被从转发表中删除，防止向过期的陈旧端口盲发数据。

## 3. 生成树协议 STP（IEEE 802.1D）基本原理

生成树协议（Spanning Tree Protocol，STP）在保留物理冗余连线的前提下，通过算法在逻辑上**阻塞（Block）特定冗余端口**，将有环的图结构动态修剪为无环的树状拓扑。当活跃链路发生物理故障时，被阻塞的备用端口自动恢复转发。

### 3.1 核心算法四步状态机

网桥之间周期性交换 **网桥协议数据单元（BPDU）**，执行分布式计算：

1. **选举全网唯一的根网桥（Root Bridge）**：
   - 比较全网网桥的 **网桥 ID（Bridge ID = 优先级 + MAC 地址）**；
   - 具有全网最小 Bridge ID 的网桥当选为根网桥（树根）；
2. **在每个非根网桥上选举唯一的根端口（Root Port，RP）**：
   - 非根网桥上到达根网桥**累计路径开销最小**的端口被选为根端口（处于转发状态）；
3. **在每个网段（链路）上选举唯一的指定端口（Designated Port，DP）**：
   - 连接该网段的网桥中，到根网桥开销最小的网桥端口为指定端口（处于转发状态）。根网桥的所有端口均为指定端口；
4. **阻塞所有剩余的备用端口（Blocked Port）**：
   - 未被选为根端口或指定端口的端口被置于阻塞（Blocking）状态：**只接收 BPDU，不转发任何数据帧，也不学习 MAC 地址**，从而在逻辑上切断环路。
