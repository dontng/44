# 3.4.5-（2）在数据链路层扩展以太网-透明网桥的自学习和转发帧的过程以及生成树协议 STP

---

## 1. 自学习算法与环路成因的第一性原理

透明网桥（Transparent Bridge，IEEE 802.1D）的核心价值在于“即插即用（Plug and Play）”。

### 1.1 为什么需要动态自学习？

大型局域网中存在大量移动设备与拓扑变更，人工静态配置转发表成本过高且无法适应拓扑漂移。
- **逆向自学习（Backward Learning）机制**：网桥不需要探针主动扫描全网，而是被动监听每个接口上收到的数据帧；
- **核心逻辑**：若某一数据帧从端口 $P$ 到达，且该帧的**源 MAC 地址**为 $S$，则网桥确信：**未来发往目的 MAC 为 $S$ 的数据帧，只需从端口 $P$ 转发即可**。

### 1.2 物理冗余与广播风暴的必然冲突

为防止单条线缆或单一网桥故障导致网络分区，网络工程中常在网桥之间引入冗余连接，形成物理闭合环路：

```
          [ 主机 A 发送广播帧 ]
                   |
       +-----------+-----------+
       |                       |
       v (Port 1 入站)          v (Port 1 入站)
   [ 网桥 B1 ] ============= [ 网桥 B2 ]
       | (Port 2 泛洪)          | (Port 2 泛洪)
       +-----------+-----------+
                   |
             [ 闭合物理环路 ]
```

若没有防环机制，物理环路将引发三大网络灾难：
1. **广播风暴（Broadcast Storm）**：
   以太网 MAC 帧**没有像 IP 报文那样的 TTL（生存时间）递减机制**，广播帧在两台网桥之间顺时针与逆时针无休止循环复制，信道在数毫秒内被完全饱和死锁；
2. **转发表震荡 / MAC 漂移（MAC Table Thrashing / Flapping）**：
   同一个广播帧在环路中双向乱窜，网桥刚从端口 1 记录 `A -> 端口 1`，下一微秒又从端口 2 收到同一主机 A 的回环帧并改写为 `A -> 端口 2`，转发表频繁颠簸，单播转发全盘紊乱；
3. **多副本帧重复接收（Multiple Frame Copies）**：
   目的主机持续接收到指数倍增的重复数据帧副本。

## 2. 自学习与转发处理的双轨解耦流水线

网桥对每个合法入站帧的处理严格解耦为两条并行逻辑链：

```
+---------------------------------------------------------------------------------------------------+
|  收到入站数据帧 (包含: 入端口 InPort, 源 MAC 字段 SrcMAC, 目的 MAC 字段 DstMAC)                     |
+---------------------------------------------------------------------------------------------------+
       |                                                                            |
       | 【左轨：自学习写表逻辑 (严格基于源 MAC)】                                    | 【右轨：查表转发逻辑 (严格基于目的 MAC)】
       v                                                                            v
  检查转发表中是否存在条目 (SrcMAC)                                            在转发表中检索条目 (DstMAC)
  - 若无：新增表项 [SrcMAC -> InPort, 启动老化计时]                             - 命中表项 且 映射出端口 == InPort:
  - 若有：更新端口映射并【重置老化定时器】                                           【过滤丢弃】(同网段已本地接收)
  (注：自学习绝不看目的 MAC 地址!)                                             - 命中表项 且 映射出端口 != InPort:
                                                                                   【精准单播转发】(由该端口发送)
                                                                                - 未命中表项 (未知单播) 或 目的为广播/组播:
                                                                                   【泛洪转发】(向除 InPort 外所有端口复制广播)
```

### 2.1 表项老化机制（Aging Timer）

- 转发表中的动态学习条目均绑定独立的老化计时器（默认通常为 300 秒）；
- 每次收到匹配源 MAC 的新帧，计时器重新刷新为 300 秒；
- 若某主机下线或移至其他网络，超过 300 秒未发送帧，对应条目自动超时删除，避免向陈旧端口错误转发。

## 3. 生成树协议 STP（IEEE 802.1D）基本原理

生成树协议（Spanning Tree Protocol，STP）在保留物理冗余拓扑的前提下，通过算法在逻辑上**阻塞（Block）特定端口**，将有环的图结构动态修剪为无环的树状拓扑。当活跃链路发生故障时，阻塞端口自动被激活恢复通信。

### 3.1 核心算法四步状态机

网桥之间周期性交换 **BPDU（Bridge Protocol Data Unit，网桥协议数据单元）**，执行分布式运算：

1. **选举全网唯一的根网桥（Root Bridge）**：
   - 比较全网网桥的 **网桥 ID（Bridge ID = 2 字节优先级 + 6 字节 MAC 地址）**；
   - 具有全网最小 Bridge ID 的网桥当选为根网桥（树根）；
2. **在每个非根网桥上选举唯一的根端口（Root Port，RP）**：
   - 非根网桥上到达根网桥**累计路径开销（Path Cost）最小**的端口当选为根端口（处于转发状态）；
3. **在每个网段（链路）上选举唯一的指定端口（Designated Port，DP）**：
   - 连接该网段的网桥中，到根网桥开销最小的网桥端口为指定端口（处于转发状态）。根网桥的所有端口均为指定端口；
4. **阻塞所有剩余的备用端口（Alternate / Blocked Port）**：
   - 未被选为根端口或指定端口的端口被置于阻塞（Blocking）状态：**只接收并处理 BPDU，不转发任何数据帧，也不学习 MAC 地址**，从而在逻辑上切断环路。

## 4. 典型问题分析

### 题目：多网桥级联网络中的自学习与转发表动态演进

如下图所示网络拓扑中，网桥 B1 与 B2 将 LAN-1、LAN-2、LAN-3 互联：
- LAN-1 连接主机 A（`MAC_A`）与主机 B（`MAC_B`）；
- LAN-2 连接主机 C（`MAC_C`）；
- LAN-3 连接主机 D（`MAC_D`）与主机 E（`MAC_E`）；
- 网桥 B1 的端口 1 接 LAN-1，端口 2 接 LAN-2；
- 网桥 B2 的端口 1 接 LAN-2，端口 2 接 LAN-3；
- **初始条件**：网桥 B1 与 B2 的转发表**均为空**。

```
[ A ]       [ B ]                    [ C ]                    [ D ]       [ E ]
  \           /                        |                        \           /
===+=========+=== LAN-1              ===+=== LAN-2            ===+=========+=== LAN-3
         |                              |     |                          |
         +-------[ 网桥 B1 ]------------+     +--------[ 网桥 B2 ]-------+
              (Port 1) (Port 2)                    (Port 1) (Port 2)
```

**问题**：
网络依次发生以下三个通信事件，推导每个事件发生后网桥 B1 与 B2 的转发表更新情况及帧的传输过滤过程：
1. **事件 1**：主机 A 向主机 B 发送一个单播帧；
2. **事件 2**：主机 C 向主机 A 发送一个单播帧；
3. **事件 3**：主机 D 向主机 C 发送一个单播帧。

---

### 推导过程

#### 1. 事件 1：A 向 B 发送数据（`Src = MAC_A, Dst = MAC_B`）
1. **LAN-1 上的传输**：A 的信号在 LAN-1 扩散，主机 B 直接接收到该帧；网桥 B1 的端口 1 收到该帧；
2. **网桥 B1 处理**：
   - **自学习（看源 MAC）**：帧自端口 1 入站，源为 `MAC_A`，新增表项：`MAC_A -> 端口 1`；
   - **查表转发（看目的 MAC）**：检索 `MAC_B`，当前表中无记录（未知单播）；
   - **决策**：执行**泛洪**，将帧从端口 2 复制发出至 LAN-2；
3. **LAN-2 上的传输**：主机 C 收到后丢弃；网桥 B2 的端口 1 收到该帧；
4. **网桥 B2 处理**：
   - **自学习（看源 MAC）**：帧自端口 1 入站，源为 `MAC_A`，新增表项：`MAC_A -> 端口 1`；
   - **查表转发（看目的 MAC）**：检索 `MAC_B`，表中无记录；
   - **决策**：执行**泛洪**，将帧从端口 2 复制发出至 LAN-3；
5. **LAN-3 上的传输**：主机 D 与 E 收到后因 MAC 不匹配丢弃。
- **事件 1 结束后转发表状态**：
  - B1 转发表：`{ MAC_A: 端口 1 }`
  - B2 转发表：`{ MAC_A: 端口 1 }`

#### 2. 事件 2：C 向 A 发送数据（`Src = MAC_C, Dst = MAC_A`）
1. **LAN-2 上的传输**：C 发出数据，B1 的端口 2 与 B2 的端口 1 同时收到该帧；
2. **网桥 B1 处理**：
   - **自学习**：记录源 `MAC_C` 来自端口 2，新增表项：`MAC_C -> 端口 2`；
   - **查表转发**：检索目的 `MAC_A`，命中记录 `MAC_A -> 端口 1`；
   - **决策**：入端口为 2，目标出端口为 1（$1 \neq 2$），执行**精准单播转发**，将帧从端口 1 注入 LAN-1；主机 A 成功接收；
3. **网桥 B2 处理**：
   - **自学习**：记录源 `MAC_C` 来自端口 1，新增表项：`MAC_C -> 端口 1`；
   - **查表转发**：检索目的 `MAC_A`，命中记录 `MAC_A -> 端口 1`；
   - **决策**：入端口为 1，目标出端口亦为 1（**入端口 == 出端口**），执行**【过滤（Filtering）】**，直接在内部丢弃该帧，不向 LAN-3 转发；
- **事件 2 结束后转发表状态**：
  - B1 转发表：`{ MAC_A: 端口 1, MAC_C: 端口 2 }`
  - B2 转发表：`{ MAC_A: 端口 1, MAC_C: 端口 1 }`

#### 3. 事件 3：D 向 C 发送数据（`Src = MAC_D, Dst = MAC_C`）
1. **LAN-3 上的传输**：D 发出数据，主机 E 丢弃；B2 的端口 2 收到该帧；
2. **网桥 B2 处理**：
   - **自学习**：记录源 `MAC_D` 来自端口 2，新增表项：`MAC_D -> 端口 2`；
   - **查表转发**：检索目的 `MAC_C`，命中记录 `MAC_C -> 端口 1`；
   - **决策**：入端口为 2，目标出端口为 1（$1 \neq 2$），执行**精准转发**，将帧从端口 1 发送至 LAN-2；主机 C 顺利接收；
3. **网桥 B1 处理**：
   - B1 的端口 2 从 LAN-2 收到该帧；
   - **自学习**：记录源 `MAC_D` 来自端口 2，新增表项：`MAC_D -> 端口 2`；
   - **查表转发**：检索目的 `MAC_C`，命中记录 `MAC_C -> 端口 2`；
   - **决策**：入端口为 2，目标出端口亦为 2（**入端口 == 出端口**），执行**【过滤（Filtering）】**，内部丢弃，不向 LAN-1 转发；
- **事件 3 结束后转发表最终状态**：
  - B1 转发表：`{ MAC_A: 端口 1, MAC_C: 端口 2, MAC_D: 端口 2 }`
  - B2 转发表：`{ MAC_A: 端口 1, MAC_C: 端口 1, MAC_D: 端口 2 }`
