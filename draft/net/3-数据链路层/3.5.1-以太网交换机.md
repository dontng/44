# 3.5.1 以太网交换机

> **本节在 408 中的定位**：以太网交换机（Ethernet Switch）是数据链路层的核心设备实体。408 统考对交换机的考查极为具体且微观，核心考核点包括：**“交换机的本质是多端口硬件网桥”**、**“两大转发方式（存储转发 vs 直通交换，以及折中的无碎片交换）的微观时延与检错特性对比”**、**“CAM 硬件内容寻址内存查表机制”**，以及**“交换机自协商与跨速率缓存适配”**。

---

## 一、第一性原理与设计动因：为什么需要 ASIC 交换机？

### 1. 传统软件网桥的算力瓶颈
早期的网桥是由一台拥有多个网卡的通用微型计算机充当的，网卡收到数据帧后产生 CPU 中断，由操作系统 CPU 运行软件查表程序进行转发。
- **瓶颈**：随着网络端口由 2 个扩展到 24 个、速率由 10M 暴涨至 100M/1000M，通用 CPU 的软件查表速度完全跟不上端口的线速比特流，缓冲区迅速被挤爆丢包。

### 2. 硬件交换机（ASIC）的破局
以太网交换机将原本跑在 CPU 上的网桥自学习、MAC 表查找、CRC 校验逻辑，全部固化烧录在**专用集成电路（ASIC，Application-Specific Integrated Circuit）芯片**中。
- **硬件 CAM（Content Addressable Memory，内容寻址寄存器）**：
  软件查表需要二分查找或哈希计算（耗费数百个 CPU 指令周期）；而交换机采用硬件 CAM，只需把 48 位的目的 MAC 作为电信号输入，硬件电路**在单个时钟周期（几个纳秒）内直接并行比对所有表项，瞬间输出目标出口端口号**！
- 从而真正实现了**线速转发（Wire-Speed Forwarding）**。

---

## 二、微观机制：两大交换转发模式的深度解构

408 选择题对交换机转发方式的考查极为高频，主要对比**存储转发（Store-and-Forward）**与**直通交换（Cut-Through）**：

```
以太网帧结构流向:
[ 前导码 8B ] [ 目的 MAC 6B ] [ 源 MAC 6B ] [ 类型 2B ] [ 数据 46~1500B ] [ FCS 4B ]
   =======> 直通交换 (Cut-Through): 读满前 6 字节目的 MAC，立刻开始向出端口发射!
   ===================================================> 存储转发 (Store-and-Forward): 全部收齐, 验完 FCS, 再转发!
```

### 1. 存储转发方式（Store-and-Forward）
- **微观流程**：
  1. 交换机将整张帧（从目的 MAC 一直到最后的 4 字节 FCS）全部完整存入入端口 FIFO 缓冲区；
  2. 硬件计算并比对 FCS 校验序列；
  3. **若 CRC 出错或属于碰撞残帧（$< 64\text{ B}$）**：硬件**直接静默丢弃**；
  4. 若完全无误，查 CAM 表将帧推入出端口发送队列。
- **优缺点分析**：
  - **优点**：可靠性极高，杜绝坏帧在网络中蔓延；支持输入与输出端口速率不同（如 100M 端口收帧，1000M 端口发帧）。
  - **缺点**：转发时延较大，且**时延随帧长线性增长**（必须等完整帧全部接收完毕）。

### 2. 直通交换方式（Cut-Through）
- **微观流程**：
  1. 交换机硬件一边接收数据，一边读取帧头；
  2. 一旦读完**前 6 个字节的目的 MAC 地址**，硬件不再等待后续数据，**立即启动 CAM 硬件查表并在出端口开始同步向外发射该帧**！
  3. 此时帧的尾部甚至还在原主机的网卡里没有发出来，帧的头部已经在交换机出端口飞向目标主机了！
- **优缺点分析**：
  - **优点**：**转发时延极小且固定**（仅需 6 字节的处理时间），几乎等于光电在线缆中的物理延迟；
  - **缺点**：**完全不具备差错检测能力！** 哪怕后续数据被电磁脉冲严重损坏、哪怕是一个只有 20 字节的残帧碎片，直通交换机也会盲目将其转发出去，浪费下游信道带宽；且两端端口速率必须完全一致。

### 3. 折中方案：无碎片直通转发（Fragment-Free / Modified Cut-Through）
- **设计折中**：针对直通交换转发碰撞残帧的致命缺陷，交换机强行读满**前 64 字节（最小帧长）**后才开始转发；
- 能够过滤掉网络中绝大多数因为碰撞产生的残帧（因为碰撞碎片必小于 64B），同时时延远小于存储转发。

## 三、两大转发模式的全维技术特性对照矩阵

| 对比维度 | 存储转发 (Store-and-Forward) | 直通交换 (Cut-Through) |
| :--- | :--- | :--- |
| **开始转发的时机** | 完整收齐整帧并完成 FCS 校验后 | **仅接收完前 6 字节目的 MAC 后** |
| **最小处理时延** | $\ge \frac{L_{\text{frame}}}{C}$（与帧长成正比） | $\approx \frac{6\text{ B}}{C}$（极短且固定，几微秒） |
| **CRC 差错检测能力**| **有**（能识别并丢弃坏帧与残帧） | **无**（无法检错，坏帧照常穿透转发） |
| **是否支持异构端口速率**| **支持**（10M/100M/1000M 自由转换） | **不支持**（输入与输出速率必须严格一致） |
| **工业现代普及度** | **现代主流交换机 99% 采用** | 仅用于超高频金融量化交易等极端低时延网络 |

## 四、408 统考真题级情景逆向与时延计算演练

### 【题型模型：存储转发与直通交换微观时延计算与对比】

**【考题背景】**
主机 A 通过一台以太网交换机 S 向主机 B 发送一个长度为 $1518\text{ 字节}$ 的以太网 MAC 帧。
- 交换机的端口速率均为 $C = 100\text{ Mbps}$；
- 主机 A 到交换机 S 的物理链路长度为 $100\text{ m}$，交换机 S 到主机 B 的物理链路长度也为 $100\text{ m}$；
- 信号在线缆中的传播速率为 $V = 2 \times 10^8\text{ m/s}$；
- 假设交换机硬件查表与处理时延为微小的固定值 $T_{\text{proc}} = 1\ \mu\text{s}$。

**【试推导并求解】**：
1. 信号在单段 $100\text{ m}$ 链路上的单向物理传播时延 $T_p$ 是多少微秒？
2. 主机 A 将该 $1518\text{ 字节}$ 的数据帧完全推入物理链路所需的发送时延 $T_{\text{tx}}$ 是多少微秒？
3. 若交换机采用**存储转发（Store-and-Forward）**方式，求从主机 A 开始发送该帧的第一个比特，到主机 B 完整接收该帧最后一个比特所需的**总时延 $T_{\text{total, store}}$**；
4. 若交换机采用**直通交换（Cut-Through）**方式（读取完前 6 字节目的 MAC 并经历 $T_{\text{proc}}$ 后立即转发），求主机 B 完整接收该帧所需的**总时延 $T_{\text{total, cut}}$**。

---

### 【草稿纸执行第一步：换算基础物理时间分量】
- 帧长 $L = 1518 \times 8\text{ bit} = 12144\text{ bit}$；
- 速率 $C = 100\text{ Mbps} = 10^8\text{ bps}$；
- 链路长度 $D = 100\text{ m}$；
- 光速 $V = 2 \times 10^8\text{ m/s}$。

---

### 【严密推导过程】

#### 第 1 问：单向传播时延计算
$$T_p = \frac{D}{V} = \frac{100\text{ m}}{2 \times 10^8\text{ m/s}} = 0.5 \times 10^{-6}\text{ s} = \mathbf{0.5\ \mu\text{s}}$$

#### 第 2 问：单节点完整帧发送时延计算
$$T_{\text{tx}} = \frac{L}{C} = \frac{12144\text{ bit}}{10^8\text{ bps}} = 121.44 \times 10^{-6}\text{ s} = \mathbf{121.44\ \mu\text{s}}$$

#### 第 3 问：存储转发总时延推导
在存储转发模式下，交换机必须先**完整收齐整帧**，才能开始向主机 B 转发：
1. 主机 A 发送整帧耗时：$T_{\text{tx}} = 121.44\ \mu\text{s}$；
2. 最后一个比特从 A 传播到交换机 S 耗时：$T_p = 0.5\ \mu\text{s}$；
3. 交换机内部查表与校验处理耗时：$T_{\text{proc}} = 1\ \mu\text{s}$；
4. 交换机 S 向主机 B 发送整帧耗时：$T_{\text{tx}} = 121.44\ \mu\text{s}$；
5. 最后一个比特从 S 传播到主机 B 耗时：$T_p = 0.5\ \mu\text{s}$。
- **总时延为**：
  $$T_{\text{total, store}} = T_{\text{tx}} + T_p + T_{\text{proc}} + T_{\text{tx}} + T_p$$
  $$T_{\text{total, store}} = 121.44 + 0.5 + 1 + 121.44 + 0.5 = \mathbf{244.88\ \mu\text{s}}$$

#### 第 4 问：直通交换总时延推导
在直通交换模式下，交换机无需等待整帧接收，流水线高度重叠：
1. 目的 MAC 长度为 $6\text{ 字节} = 48\text{ bit}$；
2. 交换机接收前 6 字节所需的时间：
   $$T_{\text{header}} = \frac{48\text{ bit}}{10^8\text{ bps}} = 0.48\ \mu\text{s}$$
3. 第 6 字节到达交换机并经硬件处理耗时：$T_p + T_{\text{proc}} = 0.5 + 1 = 1.5\ \mu\text{s}$；
4. 此时（时刻 $t = T_{\text{header}} + T_p + T_{\text{proc}} = 0.48 + 0.5 + 1 = 1.98\ \mu\text{s}$），交换机出端口已经开始向主机 B 发送帧头！
5. 主机 A 持续发送剩余比特，信号以流水线形式无缝穿过交换机到达主机 B；
6. 帧的**最后一个比特**从 A 发出需要 $T_{\text{tx}} = 121.44\ \mu\text{s}$，经 A 到 S 的传播（$T_p$）、交换机硬件流水穿透（可忽略或计 $T_{\text{proc}}$）、S 到 B 的传播（$T_p$）抵达主机 B：
   $$T_{\text{total, cut}} \approx T_{\text{tx}} + 2T_p + T_{\text{proc}} + T_{\text{header}}$$
   $$T_{\text{total, cut}} = 121.44 + 2 \times 0.5 + 1 + 0.48 = \mathbf{123.92\ \mu\text{s}}$$
- *惊人对比*：直通交换比存储转发节省了整整一个帧发送时延（约 $121\ \mu\text{s}$），总时延几乎被**砍掉了一半**！

## 五、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：以为直通交换完全不经过缓冲区**
> - 直通交换虽然不暂存整帧，但**必须有微型的移位寄存器缓存前 6 字节**，因为不把 6 字节读齐，硬件根本不知道目的 MAC 是多少，也就无法决定从哪个端口送出去！

> [!CAUTION]
> **陷阱 2：误以为直通交换机支持 10M 到 100M 的速率转换**
> - **408 经典常识题**：如果入端口是 10M，出端口是 100M，直通转发意味着出端口以 100M 往外吐数据，但入端口还在以 10M 慢慢喂数据，出端口会立刻发生**下溢（Buffer Underflow）饥饿**！因此直通交换**严格不支持异构速率端口转换**！

### 2. 考场核心记忆桩
- **“存转发验全帧查错，直通发六字节开溜”**：两类转发方式的极速秒杀桩。
- **“坏帧穿透直通换，速率异构必存储”**：交换模式功能特性的本质对比。
