# 3.5.1 以太网交换机

---

## 1. 交换机的硬件本质与转发原理

以太网交换机（Ethernet Switch）本质上是一个**多端口硬件网桥**，工作在 OSI 体系结构的 **数据链路层（第 2 层，L2）**。

### 1.1 从软件网桥到 ASIC 硬件交换机

1. **软件网桥的性能瓶颈**：
   早期网桥通常基于通用微型计算机配合多块网卡运行软件协议栈实现。数据帧的接收触发 CPU 中断，由操作系统执行内存拷贝、软件哈希查表以及转发判决。当端口数量扩展至数十个、速率达到百兆或千兆时，通用 CPU 算力与内存总线带宽成为严峻瓶颈，极易造成队列堆积与丢包；
2. **ASIC 硬件流水线与 CAM**：
   现代以太网交换机将帧解析、MAC 转发表检索、CRC-32 校验与交叉开关切换全部固化于**专用集成电路（ASIC）**芯片中；
   - **内容寻址内存（CAM，Content Addressable Memory）**：
     传统 RAM 依据“地址”检索“数据”；而 CAM 依据输入的“数据（48 位目的 MAC 地址）”进行并行硬件比较，在单个时钟周期（纳秒级）内直接匹配出对应的“出口端口号”，实现了与物理端口速率匹配的**线速转发（Wire-Speed Forwarding）**。

---

## 2. 交换机两大核心转发方式对比

交换机依据内部启动转发的时间节点，分为两种基本转发工作模式：

```
以太网帧结构流向:
[ 目的 MAC 6B ] [ 源 MAC 6B ] [ 类型 2B ] [ 数据 46~1500B ] [ FCS 4B ]
   =======> 直通交换 (Cut-Through): 读满前 6 字节目的 MAC，立即启动硬件转发
   ===================================================> 存储转发 (Store-and-Forward): 全部收齐，计算校验 FCS，再转发
```

### 2.1 存储转发（Store-and-Forward）

1. **处理流程**：
   - 交换机将整帧完整接收并存入端口缓冲区；
   - 硬件计算 CRC 校验码并与尾部 FCS 字段比对；
   - 若发现校验错误或帧长小于 64 字节（残帧），硬件**直接丢弃**该帧；
   - 仅当整帧校验无误后，查表并将其推入目标出口端口发送队列。
2. **特性评价**：
   - **优点**：可靠性高，防止受损残帧与误码帧在网络中蔓延；支持输入与输出端口速率不同（通过内部缓冲区实现跨速率与时钟适配）；
   - **缺点**：转发时延较大，且**时延大小与数据帧长度严格成正比**（必须等待整帧完全接收）。

### 2.2 直通交换（Cut-Through）

1. **处理流程**：
   - 交换机硬件一边接收数据比特流，一边解析头部字段；
   - 一旦读完**前 6 字节的目的 MAC 地址**，硬件不再等待后续载荷与尾部，立即执行 CAM 查表并在目标出口端口同步向外发送该帧；
   - 帧头在交换机出端口向目标节点发射时，帧的尾部甚至尚未完全从源主机网卡发出。
2. **特性评价**：
   - **优点**：转发时延极小且固定（仅需读取 6 字节的时间加上 ASIC 微秒级门电路延迟），不随帧长变化；
   - **缺点**：**不具备差错检测能力**。即使后续传输遭遇突发误码或该帧原本是碰撞残帧，直通交换机也会原样向后转发，浪费下游网络带宽；且**输入端口与输出端口速率必须严格一致**（若入端口慢、出端口快，出端口将因数据供给不足发生欠载饥饿中断）。

### 2.3 折中机制：无碎片交换（Fragment-Free）

针对直通交换盲目转发碰撞残帧的缺陷，部分交换机提供折中方案：
- 交换机固定接收并缓存**前 64 字节（以太网最小帧长）**后再启动转发；
- 能够有效拦截和丢弃由于碰撞产生的残帧碎片（碎片长度均小于 64 字节），同时避免了全帧缓存带来的大时延。

## 3. 技术特性综合对照

| 对比维度 | 存储转发 (Store-and-Forward) | 直通交换 (Cut-Through) | 无碎片交换 (Fragment-Free) |
| :--- | :--- | :--- | :--- |
| **转发启动时机** | 完整接收整帧并完成 FCS 校验后 | **仅接收完前 6 字节目的 MAC 后** | 接收满前 64 字节后 |
| **转发处理时延** | 较大，随帧长线性增长 | **极小且固定（微秒级）** | 介于两者之间，固定较小 |
| **CRC 差错检测** | **具备**（错误帧直接丢弃） | **不具备**（损坏帧照常透传） | 仅能检出小于 64 字节的残帧 |
| **异构速率转换** | **支持**（10M/100M/1000M 自由桥接） | **不支持**（收发端口速率必须相同）| 不支持（通常要求同速） |
| **应用场景** | 绝大多数通用现代局域网交换机 | 极端追求低时延的高性能计算、量化交易 | 部分特定厂商设备 |
