# 3.2 数据链路层的三个重要问题

---

## 1. 三大核心问题的内在因果逻辑

数据链路层协议虽然形态各异（如以太网、PPP、HDLC 等），但它们都必须围绕三个最基本的问题展开设计：**封装成帧**、**透明传输**与**差错检测**。

这三个问题体现了层层递进的工程因果链：

```text
物理层比特流 (无边界、易失真)
         │
         ▼
1. 封装成帧 (Framing)    ───> 确立数据的起始与结束边界，确定每次传输的基本数据单元
         │
         ▼
2. 透明传输 (Transparency) ──> 确保数据部分出现的任何特殊比特组合不会被误判为帧边界控制信息
         │
         ▼
3. 差错检测 (Detection)  ───> 发现信号在传输过程中发生的比特差错，赋予接收方识别坏帧的能力
```

### 1.1 为什么必须先封装成帧？

网络层下发的是一个完整的 IP 数据报，而物理层只是一连串连续的高低电平比特流。
- 如果不添加首部和尾部来标明一帧的开始与结束，接收方就无法知道从哪里截取一段数据算作一个完整的包，也无法确定校验码应该覆盖哪一段比特。因此，**封装成帧是数据链路层工作的前提**。

### 1.2 为什么必须解决透明传输？

一旦使用特定的控制字符或比特组合作为帧定界符（如首尾标志 `01111110`），就会产生新的矛盾：
- 上层传输的数据往往是任意的二进制数据（如压缩包、图像、加密数据）。在这些数据中，随机出现与定界符完全相同的内容是完全正常的；
- 如果直接发送，接收方在扫描到该内容时就会误以为帧已经提前结束，导致严重的帧截断错误；
- 因此，协议必须设计专门的**转义或填充手段**，保证无论上层传送什么内容，都能原封不动、无歧义地通过链路层，这就是**透明传输**。

### 1.3 为什么必须进行差错检测？

即使帧边界确定且数据透明，由于物理传输介质存在热噪声、脉冲干扰等物理缺陷，比特在传输过程中依然可能发生翻转（`0` 变 `1` 或 `1` 变 `0`，即**比特差错**）。
- 接收端必须通过数学校验码（如 CRC）及时检验出收到的帧是否已经受损，以便将损坏的帧及时丢弃，防止错误的数据扩散到网络层破坏上层运行。

## 2. “检错丢弃”与“可靠传输”的区别

在计算机网络分层体系中，有一个极其关键的概念界限：**“无比特差错”并不等同于“可靠传输（无传输差错）”**。

1. **比特差错（Bit Error）**：
   数据在传输中个别位发生翻转。数据链路层的 CRC 检验码能够以极高概率发现比特差错。当发现帧出错时，数据链路层的常规动作是**直接将该错误帧丢弃**；
2. **传输差错（Transmission Error）**：
   在网络系统层面，由于错误帧被丢弃、网络设备拥塞等原因，会产生更大维度的差错：
   - **帧丢失**：发送方发送了帧，但在半路上损坏被接收方直接丢弃，接收方根本不知道曾有这个帧；
   - **帧重复**：发送方因为没有及时收到确认而重新发送，接收方收到了两份相同的帧；
   - **帧失序**：后发送的帧反而先到达，先发送的帧后到达。
3. **结论**：
   - 差错检测技术（如 CRC）**只能发现比特差错并丢弃坏帧，它本身并不提供重传机制**；
   - 要消除帧丢失、帧重复和帧失序，必须依赖确认（ACK）、超时定时器和重传机制，即**可靠传输协议**。

---

## 3. 分层权衡：为什么有线局域网不提供可靠传输？

在早期广域网中，物理链路多为电话线和微波，通信质量差、误码率极高。如果链路层不纠错，大量错误累积到端到端由 TCP 重传，开销极大，因此早期的链路层协议（如 HDLC）通常在链路层实现可靠传输。

然而，在现代计算机网络中：
1. **有线通信质量极高**：双绞线与光纤的物理误码率极低（通常低于 $10^{-10}$），传输中极少发生误码丢帧；
2. **端到端原则（End-to-End Argument）**：无论底层怎么保证可靠，传输层（TCP）为了防止路由器故障丢包，依然必须在端到端实现可靠传输机制；
3. **工程效率权衡**：如果在有线以太网的每一跳链路层都维护复杂的确认、序号与重传定时器，会大大增加网络适配器芯片的硬件开销并引入额外的传输延迟。
4. **结论**：
   - **现代有线以太网和 PPP 协议只提供“无差错接收”（通过 CRC 检错，错则丢弃），不提供“可靠传输”（不确认、不重传）**；
   - 只有在误码率极高、丢包代价极其严重的信道环境（如 802.11 无线局域网 Wi-Fi）中，数据链路层才保留确认与重传机制。
