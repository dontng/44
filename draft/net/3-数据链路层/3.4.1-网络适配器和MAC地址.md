# 3.4.1 网络适配器和 MAC 地址

---

## 1. 体系结构动因：双重编址的必然性

在 TCP/IP 体系结构中，网络层采用 IP 地址，而数据链路层采用 MAC 地址。这种看似冗余的双重编址机制是由计算机网络的物理分工与路由扩展性决定的：

### 1.1 若全局仅用 MAC 地址：扁平地址与路由表爆炸

1. **扁平化结构无拓扑信息**：MAC 地址是由 IEEE 组织随机向各硬件制造商分配的（前 24 位为厂商标识符 OUI，后 24 位为设备流水号）。MAC 地址不包含任何地理、拓扑或网络归属信息；
2. **无法进行路由聚合（Prefix Aggregation）**：如果全球路由器直接依据 MAC 地址选路，由于缺乏层次结构，路由器无法使用类似 CIDR 前缀的方式聚合路由，全球互联网所有路由器的路由表必须平铺存储全球每一块网卡的独立条目，引发内存爆炸与路由收敛瘫痪。

### 1.2 若局域网仅用 IP 地址：协议解耦与硬件开销

1. **动态性与多协议兼容**：IP 地址与节点的物理位置强绑定，随拓扑变更而动态分配（如 DHCP）；而局域网底层不仅承载 IPv4，还可以同时并发承载 IPv6 等多种网络层协议；
2. **硬件流水线处理效率**：网卡（NIC）芯片必须在物理层与数据链路层以硬件时钟速度完成帧过滤与 CRC 校验。固化在硬件 ROM 中的物理地址使网卡完全脱离上层复杂的软件协议栈，无需解析上层数据报即可直接完成帧的收发决策。

**分工原则**：**IP 地址用于跨越异构网络的全局拓扑寻址与分层路由，MAC 地址用于同一局域网网段内直接相邻节点间的物理点对点投递。**

---

## 2. 网络适配器（网卡 NIC）硬件结构与工作流程

网络适配器（Network Interface Card，NIC）是计算机连接物理通信介质的桥梁，跨越了物理层与数据链路层：

```
+-----------------------------------------------------------------------------------+
|  主机系统内部 (CPU, 主存, PCIe 系统总线, 操作系统网络协议栈)                        |
+-----------------------------------------------------------------------------------+
       ^                                                 ^
       | DMA 直接内存访问                                 | 中断请求 (IRQ)
+------v-------------------------------------------------v--------------------------+
|  网络适配器 (NIC) 硬件逻辑                                                         |
|                                                                                   |
|  [ 固化 ROM / EEPROM ]  <--- 存储出厂烧录的 48 位 MAC 地址 (Burned-In Address)    |
|  [ 片上 RAM 缓冲区 ]    <--- 发送 FIFO / 接收 FIFO 缓冲区                         |
|                                                                                   |
|  [ MAC 控制器芯片 (链路层) ]                                                       |
|    - 封装/解析以太网帧首尾、硬件流水线校验 CRC-32 (FCS)                            |
|    - 硬件地址过滤器 (MAC Filter)：比对目的 MAC 是否匹配                            |
|    - 介质访问控制：CSMA/CD 碰撞监听、随机退避时钟                                  |
|                                                                                   |
|  [ PHY 物理层芯片 (物理层) ]                                                       |
|    - 曼彻斯特 / 4B/5B / PAM-5 编解码器                                            |
|    - 模拟前端驱动器 (Transceiver)：差分信号收发、电缆接口匹配                      |
+-----------------------------------------------------------------------------------+
                                   | 物理传输介质 (双绞线 / 光纤)
```

### 2.1 正常模式下的帧接收过滤逻辑

当物理介质上的信号经 PHY 芯片解调为比特流送入 MAC 控制器时，网卡硬件执行以下判决：
1. **CRC 校验**：若帧校验序列（FCS）计算不符，说明传输过程中发生误码，网卡硬件**直接静默丢弃**该帧，不产生主机中断；
2. **目的 MAC 比对**：
   - 目的 MAC 与本网卡固化 MAC 匹配 $\to$ **接收**；
   - 目的 MAC 为广播地址（全 1） $\to$ **接收**；
   - 目的 MAC 为本地已注册的组播/多播地址 $\to$ **接收**；
   - 目的 MAC 与本机无关 $\to$ **硬件电路直接过滤丢弃**，不消耗主机系统总线带宽与 CPU 周期；
3. **数据交付**：通过 DMA 将有效帧载荷搬移到主机内存缓冲区，并向操作系统触发中断。

### 2.2 混杂模式（Promiscuous Mode）

当网络诊断或抓包工具（如 Wireshark、tcpdump）工作时，网卡驱动程序可将网卡置于**混杂模式**：
- 网卡关闭硬件地址过滤逻辑，只要 CRC 校验正确的帧，无论其目的 MAC 地址为何，一律无差别接收并上送操作系统分析。

## 3. MAC 地址的微观格式与判定规则

IEEE 802 标准规定局域网硬件地址（MAC-48 / EUI-48）长度为 **48 位（6 字节）**：

```
   字节 1        字节 2        字节 3        字节 4        字节 5        字节 6
+-------------+-------------+-------------+-------------+-------------+-------------+
|   Byte 0    |   Byte 1    |   Byte 2    |   Byte 3    |   Byte 4    |   Byte 5    |
+-------------+-------------+-------------+-------------+-------------+-------------+
|<----------- OUI (组织唯一标识符) --------->|<------------ 厂商扩展标识符 ------------->|
  (前 24 位由 IEEE 统一分配给设备制造商)        (后 24 位由设备厂商自行分配管理)
```

### 3.1 首字节关键控制比特的定义

以太网在物理介质上传输数据时，采用**低位先发（LSB First，最低有效位最先发送）**的串行传输规范。因此，首字节的最低两位在协议中具有全局控制语义：

```
首字节 (8 bit) 内部结构:
  b7   b6   b5   b4   b3   b2   b1   b0
+----+----+----+----+----+----+----+----+
|    |    |    |    |    |    | G/L| I/G|
+----+----+----+----+----+----+----+----+
                                 ^    ^
                                 |    +--- I/G 位 (Individual / Group): 0 = 单播, 1 = 组播/广播
                                 +-------- G/L 位 (Global / Local): 0 = 全球管理, 1 = 本地管理
```

1. **I/G 位（Individual / Group，第 1 字节最低位 b0）**：
   - **`0`：单播地址（Individual / Unicast）**，标识局域网内唯一的单台主机网络接口；
   - **`1`：组播地址（Group / Multicast）**，标识一组特定的主机接口；
   - **全 1 广播地址**：`FF-FF-FF-FF-FF-FF`（其第 1 字节为 `0xFF`，b0 为 1，属于组播地址的全集特例）。
2. **G/L 位（Global / Local，第 1 字节次低位 b1）**：
   - **`0`：全球管理（Globally Unique）**，由 IEEE 严格分配厂商代码，全球唯一；
   - **`1`：本地管理（Locally Administered）**，由网络管理员或虚拟化软件（如虚拟机虚拟网卡）在本地配置，仅在局部网段内有效。

### 3.2 十六进制速查规律

在以太网地址的书写中，首字节由两位十六进制字符组成，记为 $H_1 H_2$：
- $H_2$ 对应的正是低 4 位（$b3, b2, b1, b0$）；
- 因此，$b0$ 的取值取决于 $H_2$ 的数值奇偶性：
  - 若 $H_2 \in \{0, 2, 4, 6, 8, \text{A}, \text{C}, \text{E}\}$（偶数）$\implies b0 = 0 \implies$ **单播地址**；
  - 若 $H_2 \in \{1, 3, 5, 7, 9, \text{B}, \text{D}, \text{F}\}$（奇数）$\implies b0 = 1 \implies$ **组播/广播地址**。

## 4. 典型问题分析

### 题目：MAC 地址属性解析与网卡过滤判决

某主机连接在共享式以太网中，该主机网卡的物理 MAC 地址为 `00-1B-44-11-22-33`，且处于非混杂工作模式。网络分析仪在同一碰撞域线路上捕获到以下 4 个数据帧的目的 MAC 地址：
1. 帧 A：`00-50-56-C0-00-08`
2. 帧 B：`01-00-5E-00-00-FB`
3. 帧 C：`02-1B-44-11-22-33`
4. 帧 D：`FF-FF-FF-FF-FF-FF`

**问题**：
1. 判定上述 4 个 MAC 地址分别属于单播、组播还是广播地址；
2. 分析帧 A 与帧 C 的地址在分配管理属性（全球管理 vs 本地管理）上的差异；
3. 说明该主机网卡在接收到上述 4 个帧时的硬件处理行为。

---

### 推导过程

#### 1. 单播 / 组播 / 广播属性推导
分析每个地址的第 1 个字节：
- **帧 A（`00-...`）**：
  - 第 1 字节为十六进制 `00`，展开为二进制 `0000 0000`；
  - 最低位 $b0 = 0$，判定为**单播地址**。
- **帧 B（`01-...`）**：
  - 第 1 字节为十六进制 `01`，展开为二进制 `0000 0001`；
  - 最低位 $b0 = 1$（且非 48 位全 1），判定为**组播地址**（此为 IPv4 组播映射标准地址）。
- **帧 C（`02-...`）**：
  - 第 1 字节为十六进制 `02`，展开为二进制 `0000 0010`；
  - 最低位 $b0 = 0$，判定为**单播地址**。
- **帧 D（`FF-...`）**：
  - 48 位全部为 1，判定为**广播地址**。

#### 2. 全球管理与本地管理属性推导
观察第 1 字节次低位 $b1$（G/L 位）：
- **帧 A 的第 1 字节为 `0x00`（`0000 0000`）**：
  - $b1 = 0 \implies$ **全球管理地址**，属于由 IEEE 认证厂商烧录在网卡 ROM 中的唯一物理硬件地址。
- **帧 C 的第 1 字节为 `0x02`（`0000 0010`）**：
  - $b1 = 1 \implies$ **本地管理地址**，属于由虚拟化软件或系统管理员手工分配的局部地址。

#### 3. 主机网卡接收判决推导
主机工作在非混杂模式，自身物理地址为 `00-1B-44-11-22-33`：
- **帧 A**：属于发往其他节点的单播帧，硬件地址过滤器比对不匹配，**硬件直接丢弃**；
- **帧 B**：属于组播帧，若主机未加入对应的 IP 组播组，网卡硬件直接丢弃；
- **帧 C**：虽然除首字节外与本机相同，但由于次低位为 1，与本机真实 MAC（`00` 开头）并不匹配，**硬件直接丢弃**；
- **帧 D**：属于全局广播帧，网卡**接收并上送操作系统**协议栈处理。
