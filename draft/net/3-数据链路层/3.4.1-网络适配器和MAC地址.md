# 3.4.1 网络适配器和 MAC 地址

---

## 1. 为什么有了 IP 地址还需要 MAC 地址？

在 TCP/IP 体系结构中，网络层使用 IP 地址，而数据链路层使用 MAC 地址（硬件地址 / 物理地址）。这种双重编址机制是由网络体系的分层原则与路由扩展性决定的：

### 1.1 若全球只使用 MAC 地址（扁平地址的灾难）

1. **MAC 地址是扁平地址**：MAC 地址是由 IEEE 组织向硬件制造商分配的（前 24 位为厂商代码 OUI，后 24 位为厂家自定义流水号），不包含任何地理或网络拓扑信息；
2. **无法进行路由聚合**：若全球路由器直接依据 MAC 地址选路，由于没有前缀层次结构，全球路由表中必须平铺存储数十亿个独立的 MAC 条目，导致路由器内存耗尽、路由收敛崩溃。

### 1.2 若局域网只使用 IP 地址（软硬件耦合与多协议的障碍）

1. **IP 地址具有动态性**：IP 地址与网络物理位置绑定，主机移动位置或重新拨号后 IP 地址会发生变化；且局域网底层不仅承载 IP 协议，还可以并发承载 IPv6 等多种不同网络层协议；
2. **硬件分工解耦**：网络适配器（网卡）硬件芯片必须脱离操作系统繁琐的软件协议栈，依靠固化在芯片内部的硬件物理地址，独立完成帧过滤与 CRC 差错检验。

**分工原则**：**IP 地址用于全网范围内的全局寻址和路由选择（标识逻辑主机位置），MAC 地址用于同一局域网网段内部直接相连的相邻节点之间的物理帧投递。**

---

## 2. 网络适配器（网卡）的功能与工作机制

网络适配器（Network Interface Card，NIC）是计算机与通信介质之间的物理接口，跨越了物理层与数据链路层：

### 2.1 网卡的核心功能

1. **数据封装与解封装**：将主机送来的 IP 数据报加上首部和尾部封装成帧，或将接收到的正确帧剥去首尾交给主机；
2. **差错检验**：发送时自动生成 CRC-32 校验码，接收时自动计算并验证 CRC，发现错帧直接丢弃；
3. **介质访问控制**：在共享信道中执行 CSMA/CD 碰撞检测与退避；
4. **硬件地址过滤**：硬件自动比对接收到的帧的目的 MAC 地址。

### 2.2 网卡的帧接收过滤逻辑与混杂模式

当物理信道上有电信号传入时，网卡硬件执行以下判决：
1. **CRC 校验**：若 CRC 检验出错，网卡**直接丢弃**该帧；
2. **目的 MAC 比对**：
   - 若目的 MAC 是 **本网卡的物理 MAC 地址** $\to$ **接收**；
   - 若目的 MAC 是 **广播地址（全 1）** $\to$ **接收**；
   - 若目的 MAC 是 **本机加入的多播组地址** $\to$ **接收**；
   - 若目的 MAC 是其他主机的单播地址 $\to$ **硬件直接过滤丢弃**，不产生中断，不惊扰主机 CPU；
3. **混杂模式（Promiscuous Mode）**：
   当使用抓包软件（如 Wireshark）时，驱动程序可将网卡设置为“混杂模式”。此时网卡关闭硬件过滤功能，**无差别接收信道上流过的所有数据帧并上交给操作系统**。

## 3. MAC 地址的格式与特殊比特语义

IEEE 802 标准规定以太网物理硬件地址（MAC-48）长度为 **48 位（6 个字节）**，通常表示为 6 组十六进制数（例如 `00-1A-2B-3C-4D-5E`）：

```text
  第 1 字节      第 2 字节      第 3 字节      第 4 字节      第 5 字节      第 6 字节
+-------------+-------------+-------------+-------------+-------------+-------------+
|    Byte 0   |    Byte 1   |    Byte 2   |    Byte 3   |    Byte 4   |    Byte 5   |
+-------------+-------------+-------------+-------------+-------------+-------------+
|<----------- OUI (组织唯一标识符) --------->|<------------- 厂商自定义扩展编号 ---------->|
  (前 24 位由 IEEE 统一分配给设备制造商)        (后 24 位由厂商自由分配，保证产品不重)
```

### 3.1 第 1 字节的关键比特位

由于以太网在物理上传输时采用**最低有效位先发（LSB First）**的规则，第 1 个字节的最低 2 个比特具有特殊的全球协议语义：

```text
第 1 个字节 (8 bit) 内部结构:
  b7   b6   b5   b4   b3   b2   b1   b0
+----+----+----+----+----+----+----+----+
|    |    |    |    |    |    | G/L| I/G|
+----+----+----+----+----+----+----+----+
                                 │    │
                                 │    └─── I/G 位 (单播 / 多播位): 0 = 单播地址, 1 = 组播/广播地址
                                 └──────── G/L 位 (全球 / 本地位): 0 = 全球管理, 1 = 本地管理
```

1. **I/G 位（Individual / Group，第 1 字节最低位 b0）**：
   - **`0`：单播地址（Unicast）**，指向唯一的单台主机网卡；
   - **`1`：组播/多播地址（Multicast）**，指向一组主机；
   - **广播地址（Broadcast）**：48 位全为 1（`FF-FF-FF-FF-FF-FF`），第 1 字节为 `0xFF`，其最低位为 1，属于组播地址的一个全集特例；
2. **G/L 位（Global / Local，第 1 字节次低位 b1）**：
   - **`0`：全球管理**，由 IEEE 严格分配认证的全球唯一物理硬件地址；
   - **`1`：本地管理**，由网络管理员或虚拟机软件手工配置的本地地址。
