# 3.9.3 （1）802.11无线局域网的数据链路层-使用CSMA-CA协议（而不使用CSMA-CD）

802.11 无线局域网在数据链路层采用 **CSMA/CA（带冲突避免的载波监听多路访问）** 协议，而不是有线以太网的 CSMA/CD。这是无线通信物理特性决定的。

## 一、为什么无线信道不能使用 CSMA/CD？（必考理论题）

CSMA/CD 的核心是“边发边听，冲突停发”。在无线局域网中无法实现这一机制，原因有二：

### 1. 硬件无法实现边发边听（信号强度落差悬殊）
- 在无线信道中，天线发射信号的能量远大于从远端接收到的微弱信号（发射功率可能是接收功率的数百万倍）。
- 若站点在发射的同时开启接收机试图监听信道，自身的发射信号会彻底淹没任何外界传入的信号，**在硬件上无法有效检测到碰撞**。

### 2. 隐藏终端问题与暴露终端问题（无线环境特殊性）

#### （1）隐藏终端问题（Hidden Terminal Problem）
- **现象**：终端 A 与 C 相隔较远，互相不在对方的无线覆盖范围内（互为隐藏终端），但它们都在 AP（B）的覆盖范围内。
- **后果**：A 监听信道觉得空闲，C 也监听信道觉得空闲，二者同时向 B 发送数据。两个信号在 B 处剧烈碰撞损毁。**传统的载波监听（CS）彻底失效**。

#### （2）暴露终端问题（Exposed Terminal Problem）
- **现象**：B 正在向 A 发送数据，处于 B 信号范围内的 C 监听信道感知到忙碌，于是推迟向 D 发送数据；然而实际上 D 处于 B 的范围之外，C 向 D 发送根本不会干扰 B 向 A 的通信。
- **后果**：造成不必要的等待，降低信道利用率。

## 二、从“冲突检测（CD）”走向“冲突避免（CA）”

既然无法在发送中途检测冲突并停止，802.11 采取了如下对策：
1. **尽量避免碰撞（Collision Avoidance）**：通过预约信道、帧间间隔、随机退避等机制，把冲突概率降到最低。
2. **引入确认重传（ACK）机制**：有线以太网无差错即默认成功；而无线信道不可靠且无法中途感知碰撞，因此**每个单播数据帧都必须等待接收方回复 ACK**，超时未收到 ACK 则判定丢失或碰撞，启动重传。
