# 3.9.3-（1）802.11 无线局域网的数据链路层-使用 CSMA/CA 协议（而不使用 CSMA/CD）

在有线局域网中，共享总线以太网普遍采用 CSMA/CD（载波监听多址接入/碰撞检测）协议来实现信道分配。然而，当进入无线局域网环境时，由于无线信道的物理传播特性和无线网卡的硬件限制，CSMA/CD 协议无法正常工作，802.11 必须改用 **CSMA/CA（载波监听多址接入/碰撞避免）** 协议。

---

## 一、为什么无线局域网不能使用 CSMA/CD？

CSMA/CD 的核心运行逻辑是**“边发送边监听”**：站点在发射信号的同时，通过检测信道上的电平变化来判断是否发生了信号碰撞。如果在发送期间检测到碰撞，立即停止发送并执行退避算法。

在无线通信环境中，这种机制遇到了两大不可克服的物理与工程障碍：

### 1. 硬件限制：发射信号强度远超接收微弱信号（无法“边发边听”）
- 在有线同轴电缆或双绞线中，电磁波在闭合金属导体中传输，信号衰减相对较慢，发射信号电平与发生碰撞时的叠加电平处于同一数量级，硬件电路很容易通过简单的电压比较器检测出碰撞。
- 在无线通信中，发射天线发出的射频信号功率通常在数十至数百毫瓦（$\text{mW}$）级别；而经自由空间扩散和墙体反射后到达本地天线的远端微弱信号可能仅有皮瓦（$\text{pW}$，即 $10^{-12}\text{ W}$）级别。
- **本地发射功率比远端接收功率高出数万甚至数十万倍**！
- 如果无线网卡在发射强功率无线电波的同时试图接收微弱的外部信号，本地强信号会直接使接收端的高灵敏度低噪声放大器（LNA）进入过载饱和状态。在工程实现上，无线网卡很难在发送数据的同时精确检测出信道中是否发生了信号碰撞。

### 2. 空间拓扑限制：碰撞发生在接收端而非发射端
有线局域网是封闭的总线结构，总线上任何一处发生碰撞，碰撞脉冲都会沿着导线传向两端的所有站点；
而在无线环境中，电磁波在三维自由空间中全向发散，信号强度随距离快速衰减，导致站点的载波监听能力受到覆盖半径的限制。**信道是否发生碰撞，取决于“接收端天线处的信号叠加情况”，而不是“发送端天线处的监听情况”**。

## 二、无线信道特有的两大空间问题

由于无线电波的有限覆盖半径，无线网络中存在两类经典的局部拓扑问题：

### 1. 隐藏终端问题（Hidden Terminal Problem）

```
[ 站点 A ] ----------------> [ 站点 B (AP) ] <---------------- [ 站点 C ]
 (A 覆盖范围)                  (B 处于重叠区)                   (C 覆盖范围)
   |<--- A 无法监听到 C --->|                          |<--- C 无法监听到 A --->|
```

- **现象描述**：
  1. 站点 A 准备向中心节点 B 发送数据帧，发送前执行物理载波监听。由于 A 处于 C 的无线覆盖范围之外，A 测得信道为空闲；
  2. 此时，站点 C 也恰好准备向中心节点 B 发送数据帧。C 执行载波监听，同样测得信道为空闲；
  3. 站点 A 和站点 C 几乎同时启动数据发送；
  4. 两个信号在中心节点 B 处同时到达并发生严重叠加碰撞，导致 B 无法正确接收两者的任何数据；
  5. 站点 A 和 C 彼此听不到对方的信号，在发送过程中根本不知道在目的地 B 处已经发生了碰撞，依然会完整发送完整个长数据帧。
- **本质**：A 和 C 互为**隐藏终端**。由于发送端无法监听到彼此，导致**载波监听机制部分失效**，在接收端引发碰撞。

### 2. 暴露终端问题（Exposed Terminal Problem）

```
[ 站点 A ] <---------------- [ 站点 B ]              [ 站点 C ] ----------------> [ 站点 D ]
(A 接收 B)                    (B 发送给 A)            (C 准备发给 D)               (D 接收 C)
                                |<--- C 能够监听到 B --->|
```

- **现象描述**：
  1. 站点 B 正在向站点 A 发送数据；
  2. 此时，站点 C 准备向站点 D 发送数据；
  3. 站点 C 在发送前执行载波监听，由于 C 处于 B 的信号覆盖范围内，C 检测到信道忙碌，从而被迫推迟发送；
  4. 然而在实际物理拓扑中，站点 D 处于站点 B 的覆盖范围之外，B 的发送并不会干扰到 D 接收 C 的信号；同时 A 也处于 C 的覆盖范围之外，C 的发送也不会干扰到 A 接收 B 的信号；
  5. 此时 C 向 D 的通信完全可以安全并行进行。
- **本质**：站点 C 成为**暴露终端**。载波监听检测到的信道忙碌并不代表目的端也会发生冲突，导致**站点不必要地等待推迟**，降低了无线频谱的空间复用率。

## 三、从 CSMA/CD 到 CSMA/CA 的设计转变

既然无线局域网无法实现“碰撞检测（CD）”，协议设计便转向了**“碰撞避免（CA，Collision Avoidance）”**。CSMA/CA 协议通过以下三大核心机制来保证数据传输的正确性：

1. **碰撞避免机制**：
   - 站点在检测到信道空闲后，并不立即发送数据，而是强制等待一段**帧间间隔（IFS）**；
   - 随后进入**随机退避阶段**，各并发站点在时间轴上错开启动发送的时刻，尽量降低多个站点同时发帧产生碰撞的概率。
2. **虚拟载波监听与信道预约（RTS / CTS 机制）**：
   - 引入短小的控制帧提前在空间中预约信道，通过持续时间字段（Duration）通知周围所有站点保持静默，以此化解隐藏终端引发的严重碰撞。
3. **数据链路层的逐帧显式确认与重传（ACK）**：
   - 有线以太网在链路层只检错不确认（依靠上层传输层 TCP 处理丢包）；
   - 无线局域网误码率和碰撞概率高，**CSMA/CA 规定接收端每正确接收一个单播数据帧，必须立即回复一个确认帧（ACK）**；
   - 发送端若在超时时间内未收到 ACK，则判定发送失败，启动链路层重传。

## 四、CSMA/CD 与 CSMA/CA 的核心对比

| 比较维度 | 有线以太网：CSMA/CD | 无线局域网：CSMA/CA |
| :--- | :--- | :--- |
| **全称与核心思想** | 载波监听多址接入 / **碰撞检测**（边发边听） | 载波监听多址接入 / **碰撞避免**（协议规避） |
| **物理传输介质** | 封闭金属导线（双绞线、同轴电缆） | 开放自由空间（无线电磁波） |
| **硬件能否边发边听** | **能够实现**（通过电路电压比较判定） | **无法实现**（发射强功率压制接收微弱信号） |
| **碰撞感知方式** | 发送过程中实时检测到碰撞，立即终止发送并发出人为干扰信号 | 无法实时感知碰撞，整帧发送完毕后依靠未收到 ACK 判定失败 |
| **链路层确认机制** | **无 ACK 确认**（不可靠数据链路服务） | **必须有显式 ACK 确认**（单播逐帧停等确认） |
| **信道预约支持** | 无信道预约机制 | **支持可选的 RTS / CTS 握手信道预约** |
| **退避算法触发时机** | **仅在发生碰撞后**才触发退避 | **在发送数据前**（当信道由忙变闲时）即触发退避 |
