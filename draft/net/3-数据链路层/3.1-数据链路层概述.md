# 3.1 数据链路层概述

物理层只负责在传输媒体上传送原始的 0/1 比特流。然而，单纯的物理比特流是无结构、无边界且无法感知差错的。数据链路层位于物理层与网络层之间，其核心功能是：**在相邻节点间的物理链路上，为网络层提供结构化、可检错的帧传输通道**。

---

## 一、为什么需要数据链路层

物理层交付给上层的是一条“仅保证透明传输比特，但既无边界也不保证正确”的原始比特管道（见 2.1 节）。这种底层特性引发了三个基本矛盾：
1. **边界矛盾（缺乏成帧机制）**：物理层只看到连续的高低电平脉冲，不知道数据从何处开始、何处结束。网络层交付的 IP 数据报必须具备明确的数据边界；
2. **可靠性矛盾（缺乏差错感知）**：物理信道存在热噪声与电磁干扰，比特翻转（0 变 1、1 变 0）不可避免。物理层无法感知差错，更无法纠正；
3. **介质共享矛盾（缺乏争用协调）**：当多个主机共享同一段总线或无线电磁波时，若多方同时发送信号，将在信道上发生叠加碰撞。物理层不具备仲裁与介质访问控制能力。

**数据链路层的基本职责**：将物理层提供的不可靠、无边界的位流管道，改造为相邻节点之间具有确定边界、具备检错能力的**数据帧（Frame）**通路。

---

## 二、通信层级划分：节点到节点 vs 端到端

在计算机网络体系结构中，不同层级的通信管辖范围存在严格的分工：

```text
+-----------------------------------------------------------------------------------+
|  源主机 A -------------- 路由器 R1 -------------- 路由器 R2 -------------- 目的主机 B   |
+-----------------------------------------------------------------------------------+
|<----------------------------- 网络层：主机到主机 (Host-to-Host) ------------------------>|
|<--------------------------- 传输层：进程到进程 / 端到端 (End-to-End) ------------------>|
|<-- 数据链路层：节点到节点 -->|<-- 数据链路层：节点到节点 -->|<-- 数据链路层：节点到节点 -->|
    (第一跳: A -> R1)              (第二跳: R1 -> R2)             (第三跳: R2 -> B)
```

- **数据链路层：节点到节点（Node-to-Node / Hop-by-Hop）**
  - 管辖范围严格限制在**紧邻的两个节点之间（单跳物理链路）**，负责把数据帧从一台设备送达相邻的下一台设备（如主机到路由器、路由器到路由器、路由器到主机）；
  - 一旦数据帧到达路由器，该帧的使命即告终结：路由器解封装去掉原链路层的首部和尾部，提取出 IP 数据报，检查网络层目的 IP 并查找路由表，随后为出接口链路**重新封装上该链路所要求的全新链路层帧首部与尾部**。
- **网络层：主机到主机（Host-to-Host）**
  - 负责根据 IP 地址进行全局路由选择，实现逻辑上跨越异构网络的两个主机之间的互联。
- **传输层：端到端（End-to-End）**
  - 负责在源主机的进程与目的主机的进程之间建立逻辑通信。

## 三、链路、数据链路与网络适配器

### 1. 概念界定
- **链路（Link）**：从一个节点到相邻节点的一段物理线路（双绞线、光纤、同轴电缆或无线信道），中间没有其他交换节点。一条链路只是一条无源的物理通路；
- **数据链路（Data Link）**：除了物理链路外，还必须包含实现链路通信协议所必需的硬件和软件。通常，**数据链路 = 物理链路 + 相关的通信规程（协议）**；
- **帧（Frame）**：数据链路层处理和传输的数据单元。它由网络层下发的 IP 数据报加上链路层首部（包含地址、控制信息等）和链路层尾部（包含校验和）封装而成。

### 2. 硬件实现载体：网络适配器（网卡）
数据链路层的核心功能（如封装成帧、物理寻址、硬件 CRC 校验、以太网 CSMA/CD 碰撞检测等）并非由操作系统软件轮询完成，而是由**网络适配器（Network Interface Card, NIC）内部专用的硬件芯片（如 MAC 控制器与 PHY 芯片）**直接在硬件线速下处理。只有少量的链路管理与配置逻辑驻留在操作系统内核的网卡驱动程序中。因此，数据链路层是计算机网络分层中典型的**软硬件结合层**。

### 3. 两类基础信道类型
根据物理拓扑与节点连接形式，数据链路层可分为两类信道环境：

```text
1. 点对点信道 (Point-to-Point):
   [ 主机 A ] <================ 专线链路 (如 PPP) ================> [ 路由器 R ]
   - 链路两端各仅有 1 个通信节点；
   - 双方独占物理介质，不存在冲突与多节点碰撞问题，无需复杂的介质访问控制子层。

2. 广播信道 (Broadcast):
          +------------------ 共享介质 (总线 / 空中无线电磁波) ------------------+
          |                         |                          |
      [ 主机 A ]                [ 主机 B ]                 [ 主机 C ]
   - 多个节点挂接在同一共享传输介质上；
   - 任何一个节点发送信号，信道上所有其他节点在物理上均能接收到；
   - 必须通过**介质访问控制（MAC, Medium Access Control）**机制解决信道争用与信号碰撞冲突。
```

## 四、跨路由多跳传输中的首部封装与字段演变

数据包在跨越异构网络的多跳传输过程中，各层协议首部的封装与解封装机制呈现出明显的层级差异。

### 1. 跨跳封装与解封装流程
假设主机 A 经以太网连至路由器 R1，R1 与 R2 之间通过点对点广域网专线（使用 PPP 协议）相连，R2 经以太网连至主机 B：

```text
主机 A (以太网)              路由器 R1 (以太网+PPP)          路由器 R2 (PPP+以太网)          目的主机 B (以太网)
+-------------+             +-------------------+          +-------------------+          +-------------+
| 网络层 IP   |             |     网络层 IP     |          |     网络层 IP     |          | 网络层 IP   |
+-------------+             +---------+---------+          +---------+---------+          +-------------+
| 链路层 MAC  |             | MAC子层 | PPP子层 |          | PPP子层 | MAC子层 |          | 链路层 MAC  |
+-------------+             +---------+---------+          +---------+---------+          +-------------+
| 物理层 PHY  |             |   PHY   |   PHY   |          |   PHY   |   PHY   |          | 物理层 PHY  |
+------+------+             +----+----+----+----+          +----+----+----+----+          +------+------+
       |                         |         |                    |         |                      |
       +=== 以太网帧(第1跳) =====+         +==== PPP帧(第2跳) ==+         +=== 以太网帧(第3跳) ==+
```

### 2. 首部字段在逐跳流动中的变化规律
当数据从主机 A 发往主机 B 的全过程中，报文各字段的处理规则如下：

| 报文构成部分 | 在第 1 跳 (A $\to$ R1) | 在第 2 跳 (R1 $\to$ R2) | 在第 3 跳 (R2 $\to$ B) | 演进特征 |
| :--- | :--- | :--- | :--- | :--- |
| **源 IP 地址** | 主机 A 的 IP | 主机 A 的 IP | 主机 A 的 IP | **端到端保持不变**（常规无 NAT 场景） |
| **目的 IP 地址** | 主机 B 的 IP | 主机 B 的 IP | 主机 B 的 IP | **端到端保持不变**（常规无 NAT 场景） |
| **IP 首部 TTL** | $T$ | $T - 1$ | $T - 2$ | 路由器每转发一次，TTL 减 1 并重算首部校验和 |
| **链路层帧首部** | 以太网源/目的 MAC 地址 | PPP 首部（包含固定控制字，无 MAC 地址） | 以太网源/目的 MAC 地址 | **每跨越一段链路重新构建封装** |
| **链路层物理寻址** | 源：MAC_A<br>目的：MAC_R1_in | 无 MAC 寻址（点对点直达） | 源：MAC_R2_out<br>目的：MAC_B | 广播信道依赖 MAC 寻址，点对点信道无需 MAC 寻址 |

## 五、多跳传输封装推导示例

### 场景设定
- 主机 H1（IP: `192.168.1.2`, MAC: `00-1A-2B-3C-4D-01`）；
- 主机 H2（IP: `192.168.2.2`, MAC: `00-1A-2B-3C-4D-02`）；
- 路由器 R 互联两个以太网子网：
  - 接口 E0 连接 H1 所在局域网（IP: `192.168.1.1`, MAC: `00-1A-2B-3C-4D-E0`）；
  - 接口 E1 连接 H2 所在局域网（IP: `192.168.2.1`, MAC: `00-1A-2B-3C-4D-E1`）；
- H1 向 H2 发送一个携带 1000 字节 TCP 数据的 IP 数据报（假设无分片、无可选字段，TCP 首部 20 字节，IP 首部 20 字节）。

```text
H1[192.168.1.2] ───(以太网1)───> [E0: 192.168.1.1] 路由器 R [E1: 192.168.2.1] ───(以太网2)───> H2[192.168.2.2]
  MAC: ..01                       MAC: ..E0                 MAC: ..E1                       MAC: ..02
```

### 1. 第一跳链路（H1 发往 R）的报文头部参数
- **源 IP 地址**：`192.168.1.2`（源端 H1 的全局 IP）；
- **目的 IP 地址**：`192.168.2.2`（目的端 H2 的全局 IP，网络层寻址是端到端的，绝不写网关 R 的 IP）；
- **源 MAC 地址**：`00-1A-2B-3C-4D-01`（H1 的网卡硬件地址）；
- **目的 MAC 地址**：`00-1A-2B-3C-4D-E0`（下一跳默认网关 R 的入接口 E0 MAC 地址）。

### 2. 第二跳链路（R 转发给 H2）的报文头部参数
- **源 IP 地址**：`192.168.1.2`（保持不变）；
- **目的 IP 地址**：`192.168.2.2`（保持不变）；
- **源 MAC 地址**：`00-1A-2B-3C-4D-E1`（路由器出接口 E1 的 MAC 地址，旧帧头已被剥除）；
- **目的 MAC 地址**：`00-1A-2B-3C-4D-02`（目的主机 H2 的 MAC 地址）。

### 3. 帧长度与物理层传输开销推导
1. **网络层 IP 数据报总长度**：
   $$\text{IP 数据报长度} = \text{IP 首部 (20B)} + \text{TCP 首部 (20B)} + \text{TCP 数据 (1000B)} = 1040\text{ 字节}$$
2. **数据链路层以太网 V2 MAC 帧总长**：
   - 目的 MAC（6B） + 源 MAC（6B） + 类型字段（2B） = 14 字节首部；
   - 帧检验序列 FCS（CRC 校验） = 4 字节尾部；
   $$\text{MAC 帧长度} = 14\text{ (首部)} + 1040\text{ (载荷)} + 4\text{ (尾部)} = 1058\text{ 字节}$$
3. **物理层线路上占用的总传输字节**：
   - 物理层在 MAC 帧发送前插入 7 字节前导码与 1 字节帧开始定界符（SFD），共 8 字节；
   - 发送完毕后需维持 96 比特时间的帧间最小间隔（IFG，相当于 12 字节时间）；
   - 在考虑物理层完整信道占用的情况下，总开销为：
     $$\text{物理层总传输占用} = 8\text{ (前导/SFD)} + 1058\text{ (MAC 帧)} + 12\text{ (IFG)} = 1078\text{ 字节} = 8624\text{ bit}$$
