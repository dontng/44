# 3.1 数据链路层概述

---

## 1. 为什么需要数据链路层

在计算机网络体系结构中，物理层仅负责在物理传输介质上传输原始的电信号或光脉冲比特流（0 和 1）。然而，单纯的比特流是无结构、无边界且容易受到物理干扰发生畸变的。

如果直接把物理比特流交给网络层处理，会产生三大根本问题：
1. **数据缺乏边界（没有成帧）**：物理层只看到连续传输的高低电平，无法分辨一个数据分组（IP 数据报）从哪里开始、到哪里结束；
2. **无法感知传输差错**：物理信道存在热噪声和突发电磁干扰，比特在传输中难免会发生差错（`0` 变 `1` 或 `1` 变 `0`）。物理层无法发现这些差错，更无法纠正；
3. **介质共享冲突**：当多台计算机连接在同一根同轴电缆或无线信道上时，若多方同时发送信号，信号叠加将导致通信混乱，物理层无法协调信道使用秩序。

**数据链路层的基本任务**：将物理层提供的不可靠、无边界的物理比特通路，改造成相邻节点之间有明确边界、能够发现传输差错的**数据链路**。

---

## 2. 节点到节点与端到端的分工

数据链路层的通信范围与高层协议有着严格的分工区别：

```text
主机 A ────────────── 路由器 R1 ────────────── 路由器 R2 ────────────── 主机 B
  │                      │                      │                     │
  ├────── 数据链路层 ────┤                      │                     │
  │     (第 1 跳: A->R1) │                      │                     │
  │                      ├────── 数据链路层 ────┤                     │
  │                      │    (第 2 跳: R1->R2) │                     │
  │                      │                      ├────── 数据链路层 ───┤
  │                      │                      │    (第 3 跳: R2->B) │
  │                                                                   │
  └────────────────────────── 网络层：主机到主机 ───────────────────────┘
  └────────────────────────── 传输层：进程到进程 (端到端) ───────────────┘
```

1. **数据链路层：节点到节点（Node-to-Node / 逐跳 Hop-by-Hop）**：
   - 它的管辖范围**仅限于两个直接相连的相邻节点之间的一段物理链路**；
   - 当一个数据帧从主机 A 到达路由器 R1 后，该帧的使命便告终结。路由器 R1 会剥去该帧的链路层首部和尾部，取出内部的 IP 数据报；
   - R1 检查目的 IP 地址并查路由表决定下一跳后，在向路由器 R2 发送时，**会为该 IP 数据报重新封装上符合下一段链路协议的全新帧首部和尾部**；
2. **网络层：主机到主机（Host-to-Host）**：
   - 负责在整个互联网范围内，根据 IP 地址寻找路径，将分组从源主机送达目的主机；
3. **传输层：进程到进程（端到端 End-to-End）**：
   - 负责在源主机的应用进程和目的主机的应用进程之间建立端到端的完整逻辑通信。

## 3. 链路、数据链路与帧

在数据链路层中，有三个经常出现的基本概念：
- **链路（Link）**：从一个节点到相邻节点的一段物理线路（双绞线、光纤等），中间没有任何其他的交换节点。链路只是一条纯粹的物理通路；
- **数据链路（Data Link）**：当在物理链路的基础上，加上实现通信协议所必需的硬件和软件（如网络适配器及其驱动程序）后，就构成了数据链路。通常，**数据链路 = 物理链路 + 相关的通信协议**；
- **帧（Frame）**：数据链路层所处理和传输的数据单元。数据链路层把网络层交下来的 IP 数据报添加首部和尾部后，封装成帧。

## 4. 两类基本信道类型

根据物理介质与连接方式的不同，数据链路层协议主要运行在两类信道之上：

### 4.1 点对点信道（Point-to-Point）

- **拓扑特征**：专用的两端点对点连接（例如两台核心路由器之间的串行专线，或计算机通过调制解调器连接 ISP）；
- **通信特点**：信道只有两个通信端点，一端发送的数据对端是唯一的接收者。双方独占信道，不存在信号碰撞，无需复杂的介质访问控制；
- **代表协议**：**PPP 协议（Point-to-Point Protocol）**。

### 4.2 广播信道（Broadcast）

- **拓扑特征**：多个节点连接在同一个共享传输介质上（例如早期使用同一根同轴电缆的以太网总线，或无线局域网 Wi-Fi）；
- **通信特点**：任何一个节点发出的信号，所有其他节点都能在物理上接收到。若两个节点同时发送，信号将在介质上叠加发生碰撞；
- **解决机制**：必须通过**介质访问控制（MAC, Medium Access Control）**协议来协调各个节点的发送行为；
- **代表协议**：以太网的 **CSMA/CD 协议**、无线局域网的 **CSMA/CA 协议**。

## 5. 跨路由器多跳传输中的首部与地址变化规律

当一个 IP 数据报在互联网中跨越多个路由器转发时，其首部各字段的变化遵循以下基本规律：

| 报文字段 | 跨路由器转发过程中的变化规律 | 机制原因 |
| :--- | :--- | :--- |
| **源 IP 地址** | **全程保持不变**（源主机的 IP 地址） | 标识端到端发送方的主机逻辑地址（常规无 NAT 场景） |
| **目的 IP 地址**| **全程保持不变**（目的主机的 IP 地址） | 标识端到端最终接收方的主机逻辑地址 |
| **IP 首部 TTL**| **每经过一个路由器减 1** | 防止数据报在路由环路中无限循环兜圈 |
| **链路层帧首部**| **每跨越一段链路就被彻底拆除并重新封装** | 每段链路可能采用不同的技术（如以太网、PPP、Wi-Fi），其帧格式和寻址机制各不相同 |
| **MAC 地址** | **源 MAC 地址和目的 MAC 地址每经过一跳都在变化** | MAC 地址只用于单段链路内的局部物理寻址：源 MAC 为本跳发送节点的端口硬件地址，目的 MAC 为本跳下一接收节点的端口硬件地址 |
