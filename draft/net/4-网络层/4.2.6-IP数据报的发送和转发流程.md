# 4.2.6 IP 数据报的发送和转发流程

IP 数据报从源主机产生，到最终递交给目的主机，涉及主机本地发送判断以及沿途路由器的逐跳转发。理解这一全过程必须掌握**直接交付与间接交付的判别条件**、**路由器转发表结构与最长前缀匹配原则**，以及**逐跳转发中的协议首部动态修改**。

---

## 一、直接交付与间接交付

在 IP 层进行分组传送时，根据目的主机是否与发送方（或当前转发设备）处于同一个物理网络，划分为两种交付方式：

```
[发送端主机 S] ---------------- (物理链路/交换机) ---------------- [目的端主机 D]
   (IP_S, MAC_S)                                                  (IP_D, MAC_D)
       │
       ├─ 情况 1: S 与 D 处于【同一子网】 (Net_S == Net_D)
       │   └──> 无需路由器中继，直接通过 ARP 解析 MAC_D 并封装发送 ──> 【直接交付】
       │
       └─ 情况 2: S 与 D 处于【不同子网】 (Net_S != Net_D)
           └──> 跨越不同广播域，S 必须将数据报发送给【默认网关】 ──> 【间接交付】
```

### 1. 直接交付（Direct Delivery）
- **判定依据**：发送方与目的端处于**同一个子网（同一广播域）**；或者路由器转发时，目的主机直接连接在路由器的某个物理接口所在的网络上；
- **传输过程**：不需要再经过其他路由器进行三层路由中继。发送方利用 ARP 协议直接解析出**目的主机**的 MAC 地址，将 IP 数据报封装入链路层 MAC 帧中直接送达目的主机。

### 2. 间接交付（Indirect Delivery）
- **判定依据**：发送方与目的端处于**不同子网**；
- **传输过程**：数据帧无法在二层直接送达目的主机。发送方必须将数据报发送给本地子网的**默认网关（Default Gateway，即本地路由器连接该子网的接口）**：
  - 发送方利用 ARP 解析出**默认网关**的 MAC 地址；
  - 数据帧的目的 MAC 填入默认网关的 MAC 地址，而内部封装的 IP 数据报的**目的 IP 依然保持为远程目的主机的 IP**；
- **端到端流程本质**：跨越多个网络的间接交付，是由“源主机到第一跳路由器的间接发送 + 中间路由器之间的若干跳间接转发 + 最后一跳路由器到目的主机的直接交付”组成的。**间接交付的最后一跳必定是一次直接交付**。

## 二、主机发送 IP 数据报的判断流程

当主机 S（IP 地址 $IP_S$，子网掩码 $Mask_S$，默认网关 $GW$）的应用层产生数据，准备向目的 IP $IP_D$ 发送数据报时，主机操作系统执行以下算法：

1. **计算目的网络**：将目的 IP 地址与本机的子网掩码进行按位与运算：
   $$\text{目的网络} = IP_D \ \& \ Mask_S$$
2. **比较源网络与目的网络**：
   - **若 $(IP_D \ \& \ Mask_S) == (IP_S \ \& \ Mask_S)$**：
     - 说明目的主机与本机同处一个子网，执行**直接交付**；
     - 检索本地 ARP 缓存（若无则广播 ARP 请求），获取 $IP_D$ 对应的物理地址 $MAC_D$；
     - 封装数据帧并直接发送（目的 MAC = $MAC_D$）。
   - **若 $(IP_D \ \& \ Mask_S) \neq (IP_S \ \& \ Mask_S)$**：
     - 说明目的主机处于不同网络，执行**间接交付**；
     - 检索本地 ARP 缓存（若无则广播 ARP 请求），获取**默认网关 $GW$** 的物理地址 $MAC_{GW}$；
     - 封装数据帧并发送给默认网关（目的 MAC = $MAC_{GW}$，帧内 IP 数据报的源 IP = $IP_S$，目的 IP = $IP_D$）。

## 三、路由器转发表结构与最长前缀匹配原则

路由器的核心任务是根据转发表（Forwarding Table）将接收到的数据报从合适的输出端口转发出去。

```
+-----------------------+---------------------+-------------------+------------+
| 目的网络前缀 (Prefix) | 子网掩码 (Netmask)  | 下一跳 (Next-Hop) | 输出接口   |
+-----------------------+---------------------+-------------------+------------+
| 192.168.1.0/24        | 255.255.255.0       | 直接交付          | eth0       |
| 10.0.0.0/8            | 255.0.0.0           | 192.168.1.254     | eth0       |
| 10.1.0.0/16           | 255.255.0.0         | 192.168.1.253     | eth0       |
| 10.1.2.0/24           | 255.255.255.0       | 192.168.1.252     | eth0       |
| 202.112.14.5/32       | 255.255.255.255     | 192.168.1.100     | eth0       |
| 0.0.0.0/0 (默认路由)  | 0.0.0.0             | 192.168.1.1       | eth0       |
+-----------------------+---------------------+-------------------+------------+
```

### 最长前缀匹配原则（Longest Prefix Match）
在采用 CIDR 的环境中，路由表中的各条目的网络前缀可能存在重叠包含关系：
- 当路由器收到一个目的 IP 时，会依次将其与转发表中各条目的掩码进行按位与运算；
- 如果发现**有多个路由条目都成功匹配**，路由器必须严格选择**网络前缀最长（掩码中 1 最多）**的条目作为转发依据；
- **原因**：网络前缀越长，其代表的地址范围越具体、越精确，指示的传输路径越优。

## 四、路由器转发 IP 分组的完整微观流程

当路由器接口从数据链路层接收到一个 MAC 帧并解封装出 IP 数据报后，按如下标准步骤处理：

```
                    [ 接收 MAC 帧，剥离帧头尾，提取 IP 数据报 ]
                                         │
                                         ▼
                               [ 步骤 1: 检验 IP 首部校验和 ]
                                         │
                               校验和错误? ──是──> [ 直接丢弃，不发差错报文 ]
                                         │ 否
                                         ▼
                               [ 步骤 2: TTL 递减 (TTL - 1) ]
                                         │
                                TTL <= 0? ──是──> [ 丢弃数据报，回复 ICMP 超时报文 (Type 11) ]
                                         │ 否
                                         ▼
                               [ 步骤 3: 重新计算首部校验和 ]
                                         │
                                         ▼
                               [ 步骤 4: 检查是否交付本机 ]
                                         │
                           目的 IP 是本机接口? ──是──> [ 上送本机协议栈高层处理 ]
                                         │ 否
                                         ▼
                               [ 步骤 5: 检索转发表进行选路 ]
                                         │
                                         ├─ 5.1 是否直接交付? (目的网络直连在本机某端口)
                                         │       └── 是 ──> 通过 ARP 解析目的主机 MAC，从该端口直接发送
                                         │
                                         ├─ 5.2 匹配特定主机路由 (/32)? ──> 命中则转发给指定下一跳
                                         │
                                         ├─ 5.3 匹配最长网络前缀 (CIDR LPM)? ──> 命中则转发给对应下一跳
                                         │
                                         ├─ 5.4 匹配默认路由 (0.0.0.0/0)? ──> 命中则转发给默认下一跳
                                         │
                                         ▼ (全部未命中)
                               [ 步骤 6: 丢弃分组，向源主机回复 ICMP 目的不可达报文 (Type 3) ]
                                         │
                                         ▼ (若步骤 5 匹配成功)
                               [ 步骤 7: 检查 MTU 与重新封装 ]
                                         │
                         分组长度 > 出接口 MTU? ──是──> [ 检查 DF 位：DF=1 则丢弃回送 ICMP / DF=0 则分片 ]
                                         │ 否
                                         ▼
                        [ ARP 查询下一跳 MAC ──> 重新封装二层帧头尾 ──> 从输出物理端口发出 ]
```

### 逐跳转发中各层首部字段的“变”与“不变”：
- **保持不变的字段**：
  - IP 首部中的 **源 IP 地址** 和 **目的 IP 地址**（在端到端无 NAT 转发中严格保持不变）；
  - 数据报的标识符（Identification）；
- **必定改变的字段**：
  - 数据链路层帧头中的 **源 MAC 地址**（变为当前转发路由器出接口的 MAC 地址）；
  - 数据链路层帧头中的 **目的 MAC 地址**（变为下一跳路由器入接口或目的主机的 MAC 地址）；
  - IP 首部中的 **生存时间 TTL**（每经一跳路由器递减 1）；
  - IP 首部中的 **首部校验和（Header Checksum）**（由于 TTL 改变，必须重新计算）。
