# 4.2.6 IP数据报的发送和转发流程

> **408 考纲地位**：**绝对命题核心（历年综合大题与选择题高频必考点）**。贯穿整套网络体系的生命线——从主机应用层发包，到封装 IP 数据报，再到本地直接交付或通过路由器进行多跳间接交付。408 核心考查点包括：**直接交付与间接交付的判别条件**、**路由器转发表的核心字段与最长前缀匹配原则**、**逐跳转发中的首部字段动态修改（TTL、Checksum、MAC 地址）**、以及**分组匹配与转发异常处理全流程**。

---

## 一、为什么需要严格区分直接交付与间接交付？（设计哲学与物理边界）

在 TCP/IP 体系中，通信双方的逻辑 IP 编址是平坦全局唯一的，但底层的物理传输介质是受物理网络拓扑（局域网广播域）严格隔离的。

```text
[发送端主机 S] ---------------- (物理链路/交换机) ---------------- [目的端主机 D]
   (IP_S, MAC_S)                                                  (IP_D, MAC_D)
      │
      ├─ 情况 1: S 与 D 处于【同一子网】 (Net_S == Net_D)
      │   └──> 无需第三层路由器中继，直接通过链路层广播 ARP 获取 MAC_D，装帧发送 ──> 【直接交付】
      │
      └─ 情况 2: S 与 D 处于【不同子网】 (Net_S != Net_D)
          └──> 链路层广播无法跨越路由器！S 必须将数据包送至【默认网关 (Default Gateway)】──> 【间接交付】
```

### 1. 物理本质判定
- **直接交付（Direct Delivery）**：
  - **判定依据**：发送方的源 IP 与目的 IP 经由发送方的子网掩码计算后，处于**同一个子网（同一广播域）**；或者路由器输出端口直接相连的网络即为目的网络。
  - **物理动作**：发送方不需要路由器进行 IP 层路由中继。源主机直接通过 ARP 获取**目的主机**的 MAC 地址，直接将 IP 数据报封装入链路层 MAC 帧中交付。
- **间接交付（Indirect Delivery）**：
  - **判定依据**：源主机与目的主机处于**不同子网**。
  - **物理动作**：数据帧不可能在二层直达目的主机。源主机通过 ARP 获取**本地默认网关（路由器接口）**的 MAC 地址，目的 MAC 填网关 MAC，而目的 IP 仍然保持为目的主机 IP。
  - **拓扑铁律**：一次跨网络的端到端间接交付，是由 **“源主机到第一跳网关的间接发送 + 路由器之间的若干跳间接转发 + 最后一跳路由器到目的主机的直接交付”** 串联组成的！**间接交付的最后一步必定是一次直接交付**。

## 二、主机发送与路由器转发的微观时序图

### 1. 主机发送分组时的判断算法
当主机 $S$（IP: $IP_S$，掩码: $Mask_S$，默认网关: $GW$）的应用层产生数据，准备向目的 IP $IP_D$ 发送数据报时：
1. **本地子网比对**：计算 $IP_D \ \& \ Mask_S$。
   - 若 $(IP_D \ \& \ Mask_S) == (IP_S \ \& \ Mask_S)$：说明目的主机在同一物理网段内，执行**直接交付**。
     - 查询本地 ARP 缓存表，获取 $IP_D$ 的 $MAC_D$（若无则广播 ARP 请求）。
     - 封装以太网帧：源 MAC = $MAC_S$，目的 MAC = $MAC_D$。
   - 若 $(IP_D \ \& \ Mask_S) \neq (IP_S \ \& \ Mask_S)$：说明目的主机在外部网络，执行**间接交付**。
     - 查询本地 ARP 缓存表，获取**默认网关 $GW$** 的 $MAC_{GW}$（若无则广播 ARP 请求 $GW$ 的 MAC）。
     - 封装以太网帧：源 MAC = $MAC_S$，目的 MAC = $MAC_{GW}$，**帧内封装的 IP 数据报内：源 IP 依旧为 $IP_S$，目的 IP 依旧为 $IP_D$**！

### 2. 路由器核心转发表结构与最长前缀匹配（CIDR Longest Prefix Match）

在 CIDR 环境下，路由表中一个目的网络可能被多条不同掩码长度的条目同时覆盖（例如汇聚路由 `/16` 与细化子网路由 `/24`）。

```text
+-----------------------+---------------------+-------------------+------------+
| 目的网络前缀 (Prefix) | 子网掩码 (Netmask)  | 下一跳 (Next-Hop) | 输出接口   |
+-----------------------+---------------------+-------------------+------------+
| 192.168.1.0/24        | 255.255.255.0       | 直接交付          | eth0       |
| 10.0.0.0/8            | 255.0.0.0           | 192.168.1.254     | eth0       |
| 10.1.0.0/16           | 255.255.0.0         | 192.168.1.253     | eth0       |
| 10.1.2.0/24           | 255.255.255.0       | 192.168.1.252     | eth0       |
| 202.112.14.5/32       | 255.255.255.255     | 192.168.1.100     | eth0       |
| 0.0.0.0/0 (默认路由)  | 0.0.0.0             | 192.168.1.1       | eth0       |
+-----------------------+---------------------+-------------------+------------+
```

#### 最长前缀匹配原则（Longest Prefix Match）
当输入数据报的目的 IP 为 `10.1.2.88` 时：
- 与 `10.0.0.0/8` 按位与：匹配！
- 与 `10.1.0.0/16` 按位与：匹配！
- 与 `10.1.2.0/24` 按位与：匹配！
- 与 `0.0.0.0/0` 按位与：匹配！
- **决胜规则**：掩码长度越长，网络前缀位数越多，代表**该路由指定的地址范围越狭窄、路径越精确**！因此路由器选择前缀最长的条目 `10.1.2.0/24`，转发给下一跳 `192.168.1.252`。

### 3. 路由器转发 IP 分组的“标准微观七步法”

每当路由器接口从二层解封装出一个合法且目的 MAC 为自己的 IP 数据报时，严格执行以下硬件状态机操作：

```text
                     [物理层/链路层接收帧]
                              │
                              ▼
            [剥去链路层首部和尾部，提取 IP 数据报]
                              │
                              ▼
               ┌──────────────┴──────────────┐
               │ 步骤 1: 检验 IP 首部检验和   │
               └──────────────┬──────────────┘
                              │
                    校验和错误? ──是──> [静默丢弃 (不发任何差错报文!)]
                              │ 否
                              ▼
               ┌─────────────────────────────┐
               │ 步骤 2: TTL 递减 (TTL - 1)  │
               └──────────────┬──────────────┘
                              │
                    TTL <= 0? ──是──> [丢弃数据报，向源主机发送 ICMP 超时报文 (Type 11)]
                              │ 否
                              ▼
               ┌─────────────────────────────┐
               │ 步骤 3: 重新计算首部检验和  │ (因 TTL 减 1，首部改变，必须重算 Checksum)
               └──────────────┬──────────────┘
                              │
                              ▼
               ┌─────────────────────────────┐
               │ 步骤 4: 判断是否本路由器接口│
               └──────────────┬──────────────┘
                              │
              目的 IP 是本机? ──是──> [交付给本机协议栈高层 (TCP/UDP/ICMP/OSPF)]
                              │ 否
                              ▼
               ┌─────────────────────────────┐
               │ 步骤 5: 检索转发表 (查路由) │
               └──────────────┬──────────────┘
                              │
                              ├─ 5.1 是否直接交付? (目的网络在路由器某个直连端口上)
                              │       └── 是 ──> 通过 ARP 解析目的主机 MAC，封装帧从该端口直接发送！
                              │
                              ├─ 5.2 匹配特定主机路由 (/32)?
                              │       └── 命中 ──> 转发给指定下一跳
                              │
                              ├─ 5.3 最长前缀匹配 (CIDR LPM)?
                              │       └── 命中 ──> 转发给最长前缀对应的下一跳
                              │
                              ├─ 5.4 匹配默认路由 (0.0.0.0/0)?
                              │       └── 命中 ──> 转发给默认网关
                              │
                              ▼ (全未命中)
               ┌─────────────────────────────┐
               │ 步骤 6: 丢弃分组 & 报告差错 │
               └──────────────┬──────────────┘
                              │
                              └──> [丢弃分组，向源主机发送 ICMP 目的不可达报文 (网络不可达/主机不可达 Type 3)]
                              │
                              ▼ (若步骤 5 成功匹配到下一跳与输出接口)
               ┌─────────────────────────────┐
               │ 步骤 7: 检查 MTU 与重新封装 │
               └──────────────┬──────────────┘
                              │
            分组长度 > 接口 MTU? ──是──> [DF 位为 1? 丢弃并回送 ICMP / 否则进行 IP 分片]
                              │ 否
                              ▼
          [ARP 查下一跳 MAC ──> 重新封装二层帧头尾 ──> 从输出物理端口发出]
```

> **注意：逐跳转发中哪些字段变了？哪些字段没变？（408 核心经典选择题）**
> - **变了的字段**：
>   1. **源 MAC 地址**：变成当前转发路由器的出接口 MAC。
>   2. **目的 MAC 地址**：变成下一跳路由器入接口 MAC（或目的主机 MAC）。
>   3. **IP 首部 TTL**：减 1。
>   4. **IP 首部 Checksum**：由于 TTL 变化，重新计算。
> - **绝对没变（正常情况下无 NAT）**：
>   1. **源 IP 地址**：保持原始源主机 IP。
>   2. **目的 IP 地址**：保持最终目的主机 IP。
>   3. **IP 首部总长度、标识、协议号**：不分片时不变。

## 三、408 经典高频真题精析

### 【题型：路由表最长前缀匹配与转发决策综合题】

**【题目描述】**
某路由器的路由表如下所示：

| 序号 | 目的网络 / 前缀 | 下一跳地址 | 输出接口 |
|---|---|---|---|
| 1 | `192.168.1.0/24` | 直接交付 | eth0 |
| 2 | `10.0.0.0/8` | `192.168.1.254` | eth0 |
| 3 | `10.128.0.0/10` | `192.168.1.253` | eth0 |
| 4 | `10.130.0.0/16` | `192.168.1.252` | eth0 |
| 5 | `10.130.12.0/22` | `192.168.1.251` | eth0 |
| 6 | `0.0.0.0/0` | `192.168.1.1` | eth0 |

现该路由器分别收到 3 个目的 IP 地址如下的 IP 数据报：
- 分组 A：`10.130.15.88`
- 分组 B：`10.131.20.1`
- 分组 C：`172.16.1.10`

请回答：
1. 路由器将分别把分组 A、分组 B、分组 C 转发给哪一个下一跳地址？写出判断和计算过程。
2. 若分组 A 进入路由器时的 TTL 为 1，路由器将如何处理该分组？源主机将收到什么报文？
3. 分组从路由器输出端口发出时，其封装的以太网帧首部中，目的 MAC 地址是填目的主机的 MAC 还是下一跳路由器的 MAC？为什么？

---

### 【标准解题步骤（120+ 考场标准规范）】

#### 第一问：最长前缀匹配判定
**对分组 A（目的 IP: `10.130.15.88`）**：
- 第一步（二进制展开分析）：
  - `10` 展开：`00001010`
  - `130` 展开：`10000010`
  - `15` 展开：`00001111`
- 第二步（匹配各条目）：
  - 检查条目 5 (`10.130.12.0/22`)：
    - 前缀 `/22` 覆盖前 22 位。第三字节前 6 位为子网位。
    - `12` 的二进制为 `00001100`，前 6 位是 `000011`。
    - 分组 A 的第三字节 `15` 二进制为 `00001111`，前 6 位同样是 `000011`！
    - 因此，`10.130.15.88` 与 `/22` 掩码做按位与后，结果为 `10.130.12.0`，**完全匹配条目 5**！
  - 检查条目 4 (`10.130.0.0/16`)：前 16 位为 `10.130`，也匹配。
  - 检查条目 3 (`10.128.0.0/10`)：`130` 的前 2 位为 `10`，匹配。
  - 检查条目 2 (`10.0.0.0/8`)：匹配。
  - 检查默认路由 (`/0`)：匹配。
- 第三步（选择最长前缀）：
  - 匹配的条目掩码长度分别为 `/22`, `/16`, `/10`, `/8`, `/0`。
  - 根据**最长前缀匹配原则**，优先选择前缀最长的条目 5（`/22`）。
  - **结论**：分组 A 转发给下一跳地址 **`192.168.1.251`**。

**对分组 B（目的 IP: `10.131.20.1`）**：
- 第一步：检查条目 5 (`/22`) 和条目 4 (`/16`)：第二字节为 `131`（`10000011`），而条目 4 要求第二字节为 `130`（`10000010`），不匹配！
- 第二步：检查条目 3 (`10.128.0.0/10`)：
  - 前 10 位由第一字节 `10`（8 位）和第二字节的前 2 位组成。
  - 条目 3 第二字节 `128` 二进制为 `10000000`，前 2 位是 `10`。
  - 分组 B 第二字节 `131` 二进制为 `10000011`，前 2 位也是 `10`！
  - 因此，分组 B 与 `/10` 掩码按位与得到 `10.128.0.0`，**匹配条目 3**。
- 第三步：同时匹配条目 2 (`/8`) 和条目 6 (`/0`)。
- 第四步：根据最长前缀匹配，条目 3 的 `/10` 长度最长。
  - **结论**：分组 B 转发给下一跳地址 **`192.168.1.253`**。

**对分组 C（目的 IP: `172.16.1.10`）**：
- 第一步：条目 1~5 目的网络第一字节分别为 `192` 和 `10`，与 `172` 均不匹配。
- 第二步：只有条目 6（默认路由 `0.0.0.0/0`）匹配。
  - **结论**：分组 C 转发给默认网关 **`192.168.1.1`**。

#### 第二问：TTL 耗尽异常处理
- 路由器收到分组 A 后，执行 TTL 检查：将 TTL 减 1，得到 $1 - 1 = 0$。
- **路由器动作**：因 TTL 减为 0，路由器**直接丢弃**该 IP 数据报。
- **回送报文**：路由器向源主机发送 **ICMP 时间超过报文（Time Exceeded，Type 11，Code 0：传输期间生存时间为 0）**。

#### 第三问：链路层地址封装判定
- 转发时封装的目的 MAC 地址是 **下一跳路由器（`192.168.1.251`）对应的端口 MAC 地址**，而不是目的主机的 MAC。
- **原因**：因为本路由器与目的主机不在同一个物理局域网内，本路由器的二层数据帧无法直接跨网段跨越其他路由器广播或直达目的主机。链路层 MAC 帧的寻址范围严格局限于两台直连网络设备之间的单跳链路（Hop-by-Hop）。

## 四、考场肌肉记忆与避坑指南

### 1. 致命易错陷阱
- 陷阱 1：**首部检验和出错 vs TTL 减为 0 的 ICMP 差错回送区别**
  - **首部检验和出错**：路由器**直接静默丢弃**，**绝对不发送** ICMP 差错报文！（因为首部出错时，源 IP 地址很可能是坏的，胡乱回发 ICMP 会导致网络风暴）。
  - **TTL 减为 0**：路由器丢弃分组，并**必须回发** ICMP 超时报文（Type 11）。
- 陷阱 2：**转发表中的“下一跳”填的是什么？**
  - 在选择题中，若目的网络是直连网络，下一跳应填 **“直接交付”** 或该接口标识（如 eth0），而**不是**填本路由器的 IP！
  - 若为间接交付，下一跳必须填**相邻路由器的入接口 IP 地址**，不能跨跳填写远端路由器 IP。
- 陷阱 3：**路由表和转发表是一回事吗？**
  - **路由表（Routing Table）**：由软件/路由协议（RIP/OSPF/BGP）计算生成，基于软件控制层面，结构复杂（包含协议类型、度量值、老化时间等）。
  - **转发表（Forwarding Table）**：由硬件芯片（ASIC/TCAM）根据路由表直接导出，面向数据层面的极速硬件匹配，表项紧凑（仅包含目的前缀、输出端口和下一跳 MAC/IP），实现纳秒级查表。

### 2. 秒杀公式与反射条件
$$\text{匹配判断}：\text{目的 IP} \ \& \ \text{条目子网掩码} \stackrel{?}{=} \text{目的网络前缀}$$
$$\text{冲突决策}：\text{所有匹配成功的条目中，挑选前缀长度 } /n \text{ 最大的条目转发！}$$
