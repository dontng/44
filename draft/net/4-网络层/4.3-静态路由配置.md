# 4.3 静态路由配置

静态路由（Static Routing）是由网络管理员通过人工配置的方式在路由器中创建并维护的路由条目。与之相对的是由动态路由选择协议（如 RIP、OSPF、BGP）自动发现和更新的动态路由。

---

## 一、为什么需要静态路由？

虽然动态路由协议能够根据网络拓扑的变化自动调整路径，但在很多网络场景下，静态路由依然不可或缺：
1. **零协议通信开销**：动态路由协议需要周期性或触发式地在路由器之间收发控制报文，消耗链路带宽和路由器 CPU 算力。静态路由不产生任何控制报文，开销为零；
2. **安全性高**：动态路由协议容易受到虚假路由通告和路由毒化攻击；静态路由完全由管理员手工掌控，不向外部通告网络内部拓扑；
3. **适用于简单与末梢网络（Stub Network）**：对于只有一个出口网关的家庭网络、小型企业分支或园区边缘路由器，没有多条出口路径可选，运行复杂的动态路由协议毫无必要，配置静态路由或默认路由是最优解。

- **局限性**：无法自动适应网络拓扑的变化。当某条物理链路断开时，静态路由不能自动切换，需要管理员人工介入重新配置，否则会导致路由黑洞。

---

## 二、静态路由的配置要素

在路由器中配置一条标准的静态路由，通常必须指定三个核心要素：
1. **目的网络地址与子网掩码（或网络前缀长度）**：指明该条路由所覆盖的目标网络；
2. **下一跳 IP 地址（Next-hop IP）**：与当前路由器直接相连的相邻路由器的接口 IP 地址；
3. **本地输出接口（Outgoing Interface）**：数据报从本地路由器的哪个物理接口发出。

```
+-----------------------------------------------------------------------------------+
| 接口类型       | 下一跳 IP 与出接口的指定规则                                      |
+-----------------------------------------------------------------------------------+
| 点对点链路     | 可以仅指定出接口，也可以指定下一跳 IP (点对点链路上仅有对端唯一节点)|
| (PPP, HDLC)    |                                                                   |
+-----------------------------------------------------------------------------------+
| 广播多路访问链路| 必须明确指定【下一跳 IP 地址】!                                  |
| (以太网)       | 原因：以太网上连接了多台设备，路由器出接口必须依靠下一跳 IP        |
|                | 通过 ARP 协议解析出对端的 MAC 地址，才能完成以太网帧的封装。       |
+-----------------------------------------------------------------------------------+
```

## 三、特殊静态路由类型

### 1. 默认路由（Default Route，`0.0.0.0/0`）
- **定义**：目的网络为 `0.0.0.0`，子网掩码为 `0.0.0.0`（记为 `0.0.0.0/0`）的特殊路由；
- **核心机制**：
  - 默认路由具有最短的网络前缀（0 位）；
  - 任何 IPv4 目的地址与掩码 `0.0.0.0` 进行按位与运算，结果均为 `0.0.0.0`，因此**默认路由能够匹配所有的 IP 数据报**；
  - 依据**最长前缀匹配原则**，默认路由的匹配优先级最低，作为最后的“保底路由”；
- **作用**：当转发表中所有的具体明细路由均未命中时，数据报统一按照默认路由转发给指定的出口网关。大幅减少了边缘路由器的路由表条目数量。

### 2. 特定主机路由（Host Route，`/32`）
- **定义**：目的网络为某台具体主机的 IP 地址，子网掩码为 `255.255.255.255`（前缀长度为 `/32`）的路由；
- **核心机制**：
  - 前缀长度为全满的 32 位；
  - 依据**最长前缀匹配原则**，特定主机路由具有**最高匹配优先级**；
- **应用场景**：用于对特定重要服务器（如认证服务器、网管监控机）进行精确选路或安全审计控制。

### 3. 空接口路由 / 黑洞路由（Null0）与路由环路防范
- **空接口（Null0）**：路由器操作系统内部的一个伪虚拟接口。任何被路由转发到 Null0 接口的数据报，都会被路由器**直接静默丢弃**；
- **产生路由环路的场景（路由聚合缺陷）**：
  - 当路由器 R1 将下辖的多个子网（如 `192.168.1.0/24` 和 `192.168.2.0/24`）聚合成超网 `192.168.0.0/22` 通告给上级路由器 R2 时，该超网还涵盖了物理上并不存在的子网（如 `192.168.3.0/24`）；
  - 若 R1 配置了指向 R2 的默认路由（`0.0.0.0/0`）；
  - 当外部有流量发往不存在的 `192.168.3.x` 时，R2 查表命中聚合超网发给 R1；R1 查表未找到明细路由，命中默认路由又回甩给 R2，导致数据报在 R1 和 R2 之间无限来回弹跳，形成**路由环路**；
- **黑洞路由防环机制**：
  - 管理员在 R1 上添加一条针对聚合超网 `192.168.0.0/22`、出接口为 `Null0` 的空接口路由；
  - 当发往真实存在的 `192.168.1.x` 时，明细路由 `/24` 掩码更长，优先命中，正常转发；
  - 当发往不存在的 `192.168.3.x` 时，未命中明细路由，命中 `/22` 的 Null0 路由（相比 `/0` 默认路由优先），数据报直接在 Null0 被丢弃，彻底消除了路由环路。
