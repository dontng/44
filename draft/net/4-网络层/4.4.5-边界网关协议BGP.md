# 4.4.5 边界网关协议 BGP

边界网关协议（BGP，Border Gateway Protocol）是目前全球互联网中各自治系统（AS）之间使用的外部网关协议（EGP）的事实国际标准。现行标准版本为 BGP-4（RFC 4271）。

---

## 一、为什么域间路由需要采用 BGP？

### 1. 自治系统之间选路面临的现实约束
在自治系统内部（IGP），所有路由器归属于单一组织，选路的目标纯粹追求技术上的最优（如代价最小、跳数最少）；
但在全球互联网的自治系统之间：
1. **因特网规模庞大**：全球自治系统数量成千上万，若在 AS 之间运行链路状态协议（OSPF），全网路由器将无法承受存储全球链路状态信息及频繁计算 SPF 树的计算与内存开销；
2. **策略路由（Policy Routing）凌驾于技术最优之上**：各个自治系统代表了不同的国家、机构或商业运营商。运营商之间存在复杂的商业结算协议与安全隔离策略。自治系统必须能够自主控制：哪些流量允许借道本 AS 过境，哪些流量必须绕行；
3. **选路目标**：**BGP 的核心使命不是寻找技术上的“最佳路径”，而是寻找一条“满足政治/经济策略的、无环路的、可达的路径”**。

---

## 二、BGP-4 的核心工作机制：路径向量（Path Vector）

为了在大规模分布式环境下消除路由环路并实施策略控制，BGP 采用了 **路径向量（Path Vector）算法**。

### 1. 协议核心属性
- **底层报文封装**：BGP 是一个**应用层协议**，其控制报文直接运行在传输层的 **TCP** 协议之上，熟知端口号为 **179**；
  - **采用 TCP 的原因**：自治系统边界路由器之间传输距离远、链路跨越广域网，由 TCP 提供可靠的数据传输，免去了 BGP 自行实现分片、确认与重传的复杂性；
- **邻居（对等体 Peer）建立**：BGP 路由器之间不能通过广播自动发现邻居，必须由管理员在两端手工指定对端 IP 地址，通过 TCP 三次握手显式建立连接；
- **增量更新**：BGP 在刚建立连接时交换全量路由表，此后**仅在拓扑发生改变时触发发送增量更新**，不进行周期性的全表刷新。

---

## 三、AS-Path 属性与无环路保障

在 BGP 的路由更新报文（Update 报文）中，每一个被通告的目的网络前缀，都强制绑定了一组**路径属性（Path Attributes）**。其中最核心的属性是**自治系统路径向量（AS-Path）**：

```
  [AS 100 发起网络 N: 192.168.0.0/16]
                  │
                  ▼ (通告中 AS-Path 属性为: [100])
           +--------------+
           | 路由器 AS 200| ──> 向后传递时，在最左侧追加本 AS 编号: [200, 100]
           +--------------+
                  │
                  ▼ (通告中 AS-Path 属性为: [200, 100])
           +--------------+
           | 路由器 AS 300| ──> 追加本 AS 编号: [300, 200, 100]
           +--------------+
                  │
                  ▼ (通告中 AS-Path 属性为: [300, 200, 100])
           +--------------+
           | 路由器 AS 100| ──> 收到通告！检查 AS-Path 列表发现已包含自己的 ASN [100]！
           +--------------+     【断定存在环路：立即强制丢弃该条路由！】
```

### AS-Path 的双重核心功能：
1. **防止自治系统间的路由环路**：任何 BGP 路由器在接收到一条路由更新时，只要检查到其 `AS-Path` 属性列表中**已经包含了本自治系统的 AS 编号**，即可断定该路由绕回了自身，**直接丢弃该路由条目**；
2. **作为路径优选依据**：在各项策略等同的情况下，**AS-Path 越短（经过的 AS 数量越少）的路径被优先选择**。

## 四、外部 BGP（EBGP）与内部 BGP（IBGP）

根据对等体双方所处的自治系统归属，BGP 会话分为两类：

```
+-----------------------+                         +-----------------------+
|    自治系统 AS 100    |                         |    自治系统 AS 200    |
|                       |                         |                       |
|   +---------------+   |         EBGP 会话       |   +---------------+   |
|   | 路由器 R1 (ASBR)|<===========================>| 路由器 R3 (ASBR)|   |
|   +---------------+   |      (跨 AS 边界对等体)  |   +---------------+   |
|           ▲           |                         |           ▲           |
|           ║ IBGP 会话 |                         |           ║ IBGP 会话 |
|           ▼           |                         |           ▼           |
|   +---------------+   |                         |   +---------------+   |
|   | 路由器 R2 (内部)| |                         |   | 路由器 R4 (内部)| |
|   +---------------+   |                         |   +---------------+   |
+-----------------------+                         +-----------------------+
```

1. **EBGP（External BGP）**：
   - 运行在**处于不同自治系统（AS）的 BGP 边界路由器之间**；
   - 通常要求在物理直连链路上建立，TTL 默认设置为 1；
2. **IBGP（Internal BGP）**：
   - 运行在**处于同一个自治系统（AS）内部的 BGP 路由器之间**；
   - 用于在自治系统内部传播从外部学到的 BGP 路由信息；
   - IBGP 对等体之间不需要物理直连，可以通过内部的 IGP（如 OSPF）实现底层网络连通。

## 五、BGP-4 的四种报文类型

BGP 报文直接承载在 TCP 连接中传输，包括以下四种标准类型：

| 报文类型 | 报文名称 | 主要功能与机制 |
| :---: | :--- | :--- |
| **类型 1: Open** | **打开报文** | 在建立 TCP 连接后发送，用于与相邻对等体协商 BGP 版本、自治系统号（ASN）及保持时间（Hold Time）等会话参数。 |
| **类型 2: Update** | **更新报文** | **BGP 中最重要的报文**。用于通告一条或多条可行的网络路由（附带 AS-Path 等属性），或者撤销不可达的无效路由。 |
| **类型 3: Keepalive**| **保活报文** | 周期性发送（默认 60 秒），用于向对端确认 TCP 连接及 BGP 进程存活（若在保持时间内未收到则断开连接）。 |
| **类型 4: Notification**| **通知报文** | 差错报告报文。当检测到错误时向对端发送该报文，并**立即关闭该 BGP 会话及底层的 TCP 连接**。 |
