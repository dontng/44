# 4.4.5 边界网关协议BGP

> **408 考纲地位**：**外部网关协议唯一事实标准（选择题必考机制，大题考查体系架构）**。重点考查：**域间路由为什么不能采用纯算法最短路径（政治、商业、安全与策略路由）**、**BGP-4 基于 TCP 179 端口的连接机制**、**路径向量（Path Vector）与 AS-Path 属性的防环判定**、**IBGP 与 EBGP 的运行场景及四大核心报文类型**。

---

## 一、为什么域间路由绝不能使用 RIP 或 OSPF？（主权与经济学的博弈）

在自治系统内部（IGP），所有路由器归属于同一个管理者（如同一个公司或一所大学），大家的目标纯粹是“技术性能最优”（带宽最高、时延最小）。但全球互联网是由成千上万个相互竞争、甚至政治对立的自治系统（AS）共同构成的：

1. **因特网规模不可承受之重**：
   - 全球有数以万计的自治系统、数以百万计的网络前缀。
   - 若在全网运行链路状态协议（OSPF），全网每台路由器都要存储全球所有链路的 LSDB，一旦全球某个偏僻链路闪断，全球数万台核心路由器都要重新计算 Dijkstra SPF 树，全球互联网将瞬间瘫痪崩溃。
2. **策略路由（Policy Routing）凌驾于技术最优之上**：
   - **经济结算驱动**：ISP A 与 ISP B 是对等互联（Peering，免费互换双方客户流量），ISP C 是向 ISP A 付费的客户。ISP A 绝对不允许 ISP B 的流量免费借道 ISP A 的骨干网去往 ISP C！
   - **政治与安全边界**：某些敏感金融或国家骨干网流量，必须严格限制路径，宁可绕远路走卫星或备用链路，也绝不能流经特定竞争对手管辖的 AS。
   - 因此，**域间路由追求的不是“寻找技术最短路径”，而是“寻找满足政治/经济策略的可达路径（Policy-constrained Reachable Path）”**。

## 二、BGP-4 的核心工作机制：路径向量（Path Vector）

为了在大规模分布式环境下消除路由环路并实施策略控制，BGP 采用了 **路径向量（Path Vector）算法**。

### 1. 协议核心运行参数（考点秒杀表）

```text
+-----------------------+-------------------------------------------------------------+
| 核心属性              | 协议规范与考点定义                                          |
+-----------------------+-------------------------------------------------------------+
| 协议体系归属          | 应用层协议！基于 TCP 连接传输，熟知端口号为 179             |
|                       | (原因：跨 AS 传输距离遥远、网络不可靠，依赖 TCP 提供可靠通信)|
+-----------------------+-------------------------------------------------------------+
| 选路度量与算法        | 路径向量算法 (Path Vector)。不使用单一数字跳数或代价，      |
|                       | 而是通过丰富的【路径属性 (Path Attributes)】进行多准则裁决  |
+-----------------------+-------------------------------------------------------------+
| 邻居建立方式          | 手工指定对等体 IP，通过三次握手建立 TCP 长连接              |
+-----------------------+-------------------------------------------------------------+
| 路由更新时机          | 仅在首次启动时交换整表，后续【仅在拓扑改变时触发增量更新】  |
+-----------------------+-------------------------------------------------------------+
```

---

### 2. BGP 的灵魂属性：AS-Path 与绝对防环机制

在 BGP 路由通告（Update 报文）中，每一个被通告的目的网络前缀，都强制绑定一个属性——**自治系统路径向量（AS-Path）**。AS-Path 记录了该路由通告沿途穿过的所有自治系统的 ASN 编号有序列表。

```text
  [AS 100 发起网络 N: 192.168.0.0/16]
                  │
                  ▼ (AS-Path: [100])
           +--------------+
           | 路由器 AS 200| ──> 向后传递时，在最左侧前置追加本 AS: [200, 100]
           +--------------+
                  │
                  ▼ (AS-Path: [200, 100])
           +--------------+
           | 路由器 AS 300| ──> 追加本 AS: [300, 200, 100]
           +--------------+
                  │
                  ▼ (AS-Path: [300, 200, 100])
           +--------------+
           | 路由器 AS 100| ──> 收到通告！检查 AS-Path 列表发现已包含 [100]！
           +--------------+     【命中防环准则：立即强制静默丢弃该路由！】
```

#### AS-Path 的双重致命作用：
1. **彻底消除 AS 级路由环路**：任何 BGP 发言人收到一条更新时，只要在 `AS-Path` 属性列表中发现**包含自己的 AS 编号**，就断定该路由已经绕了一圈形成闭环，**直接无条件丢弃**！
2. **作为选路优选准则**：在策略允许的前提下，**AS-Path 越短（经过的 AS 数量越少）的路径越优先**。

### 3. EBGP vs IBGP（边界与内部协同）

```text
+-----------------------+                         +-----------------------+
|    自治系统 AS 100    |                         |    自治系统 AS 200    |
|                       |                         |                       |
|   +---------------+   |         EBGP 连接       |   +---------------+   |
|   | 路由器 R1 (ASBR)|<===========================>| 路由器 R3 (ASBR)|   |
|   +---------------+   |     (跨 AS 边界路由器)  |   +---------------+   |
|           ▲           |                         |           ▲           |
|           ║ IBGP 连接 |                         |           ║ IBGP 连接 |
|           ▼           |                         |           ▼           |
|   +---------------+   |                         |   +---------------+   |
|   | 路由器 R2 (内部)| |                         |   | 路由器 R4 (内部)| |
|   +---------------+   |                         |   +---------------+   |
+-----------------------+                         +-----------------------+
```

- **EBGP（External BGP）**：
  - 运行在**处于不同 AS 的两台 BGP 边界路由器之间**。
  - 通常直接物理链路直连，TTL 默认设置为 1。
- **IBGP（Internal BGP）**：
  - 运行在**处于同一个 AS 内部的两台 BGP 路由器之间**。
  - 目的：让 AS 内部所有核心路由器都能学到外部 AS 通告的路由，确保域内向外转发不丢包。
  - 注意：IBGP 路由器之间不一定物理直连，可以通过内部 IGP（OSPF/RIP）多跳打通底层 IP 连通性，TCP 连接基于 Loopback 接口建立。

### 4. BGP-4 的四种核心报文类型

BGP 报文直接作为 TCP 的载荷传输，包含以下四种标准类型：

| 报文类型 | 中文名称 | 报文功能与触发时机 |
|:---:|---|---|
| **类型 1: Open** | **打开报文** | 用于与相邻对等体建立连接，协商 BGP 版本、ASN、Hold Time 保持时间等参数 |
| **类型 2: Update** | **更新报文** | **BGP 最核心报文！** 用于通告一条或多条可行路由（附带 AS-Path 等属性），或撤销不可达路由 |
| **类型 3: Keepalive**| **保活报文** | 周期性发送（默认 60 秒），确认 TCP 连接两端存活（若 180 秒未收到则断开 BGP 连接） |
| **类型 4: Notification**| **通知报文** | 差错报告！一旦检测到差错，向对端发送该报文并**立即关闭 TCP 连接** |

## 三、408 经典高频真题精析

### 【题型：BGP 路径向量选路与防环机制综合分析】

**【题目描述】**
设互联网中有 4 个自治系统，编号分别为 AS1、AS2、AS3、AS4。网络拓扑及相互连接关系如下：
- AS1 内部拥有网络 $N_1$（`202.112.0.0/16`）。
- AS1 分别与 AS2、AS3 建立 EBGP 连接。
- AS2 与 AS4 建立 EBGP 连接。
- AS3 与 AS4 建立 EBGP 连接。
- 此外，AS2 与 AS3 之间也有一条专用的 EBGP 互联链路。

各自治系统通告的 BGP 路由信息如下：
- AS1 向 AS2 和 AS3 通告到达 $N_1$ 的路由；
- AS2 收到 AS1 的通告后，分别向 AS3 和 AS4 转发；
- AS3 收到 AS1 的通告后，分别向 AS2 和 AS4 转发。

请回答：
1. AS4 将从 AS2 和 AS3 分别收到关于到达网络 $N_1$ 的 BGP 更新报文。请分别写出 AS4 收到的这两条路由中的 `AS-Path` 属性序列。
2. 若 AS2 向 AS3 转发到达 $N_1$ 的路由时，AS3 接收到的路由 `AS-Path` 是什么？若随后 AS3 试图将该路由再转发回 AS1，AS1 的边界路由器将如何处理该报文？为什么？
3. BGP 为什么选择建立在 TCP 协议之上，而 RIP 选择 UDP，OSPF 选择直接基于 IP？请从可靠性、开销和运行环境三个角度阐述其设计差异。

---

### 【标准解题步骤（120+ 考场标准规范）】

#### 第一问：AS4 收到的 AS-Path 序列推导
- 路径 1（经由 AS2）：
  - AS1 发起通告，属性为 `(AS1)`。
  - AS2 接收并向 AS4 转发，将自身 ASN 追加到最前侧，生成序列：**`(AS2, AS1)`**。
  - 因此 AS4 从 AS2 处收到的 AS-Path 为：**`(AS2, AS1)`**。
- 路径 2（经由 AS3）：
  - AS1 发起通告，属性为 `(AS1)`。
  - AS3 接收并向 AS4 转发，将自身 ASN 追加到最前侧，生成序列：**`(AS3, AS1)`**。
  - 因此 AS4 从 AS3 处收到的 AS-Path 为：**`(AS3, AS1)`**。

#### 第二问：AS-Path 变化与环路规避判定
- AS2 向 AS3 转发时，AS2 在通告中携带的 AS-Path 为 **`(AS2, AS1)`**。
- 若 AS3 将此路由（追加后为 `(AS3, AS2, AS1)`）转发回 AS1：
  - AS1 的 BGP 发言人收到该报文，检查 `AS-Path` 列表；
  - 发现列表中已包含自身的自治系统编号 **`AS1`**；
  - **处理结果**：判定存在自治系统间路由环路，AS1 **直接静默丢弃（Discard）**该更新报文，绝不采纳！

#### 第三问：三者底层承载协议选型的第一性原理对比
1. **BGP 选用 TCP（端口 179）**：
   - **运行环境**：BGP 运行在 AS 之间的广域网甚至跨洲际链路上，跨度大、网络丢包率和抖动不确定；
   - **可靠性需求**：BGP 路由表庞大，采用触发增量更新，一旦丢包会导致路由不一致甚至断网；利用成熟的 TCP 滑动窗口、三次握手和重传机制，可无需在 BGP 协议内部重复实现可靠传输机制。
2. **RIP 选用 UDP（端口 520）**：
   - **运行环境**：小型局域网内部，拓扑简单，跳数不超过 15；
   - **开销考量**：RIP 依赖每 30 秒高频周期广播整张表，本身具有天然容错性（丢一次 30 秒后可刷新），无需建立面向连接的 TCP 握手开销。
3. **OSPF 选用 IP（协议号 89）**：
   - **运行环境**：中大型局域网/园区网，路由器密集；
   - **设计纯粹性**：OSPF 自行设计了报文序号、LSU 洪泛和 LSAck 确认机制，完全自主掌控传输可靠性，直接使用 IP 传输避免了传输层 UDP/TCP 的协议头封装开销与握手延迟，传输效率最高。

## 四、考场肌肉记忆与避坑指南

### 1. 致命易错陷阱
- 陷阱 1：**AS-Path 序列的书写顺序**
  - BGP 通告每穿过一个 AS，该 AS 将自己的编号添加到序列的**最左端（最前端）**。离目标网络最近的原始源 AS 位于序列的最末尾。
- 陷阱 2：**BGP 与传输层关系的记忆混淆**
  - 很多考生误以为“网络层协议只能承载在网络层以下”，而 BGP 是路由协议，误认为在 IP 层或网络层。
  - **死记**：**BGP 是应用层协议！使用 TCP 179！**（OSPF 才是网络层，IP 89；RIP 是应用层，UDP 520）。

### 2. 秒杀公式与反射条件
$$\text{BGP 承载}：\text{TCP 端口 179} \quad (\text{长连接，可靠传输})$$
$$\text{BGP 防环}：\text{收到报文若 } AS_{\text{local}} \in \text{AS-Path} \implies \text{无条件丢弃！}$$
$$\text{更新机制}：\text{初次整表同步} + \text{拓扑变动时触发增量更新}$$
