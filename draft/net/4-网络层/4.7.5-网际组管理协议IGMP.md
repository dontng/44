# 4.7.5 网际组管理协议 IGMP

网际组管理协议（IGMP，Internet Group Management Protocol）是负责在主机与本地直连多播路由器之间建立和维护多播组成员关系的协议。

---

## 一、IGMP 的协议特性与封装格式

- **协议层次**：IGMP 属于**网络层协议**；
- **封装机制**：IGMP 报文直接作为 **IP 数据报的数据载荷** 进行封装，IP 首部的协议字段固定为 **2**；
- **作用范围与 TTL 限制**：IGMP 的功能严格限定在本地直接连接的局域网内部，其 IP 首部中的 **TTL 字段严格固定为 1**，路由器绝不向外转发 IGMP 报文；
- **状态维护原则**：多播路由器仅维护“本地直连接口是否存在属于某多播组的成员”，而不记录具体成员主机的 IP 地址或数量。

---

## 二、IGMPv2 的核心操作流程

```
       [多播路由器 R]                                  [主机 H1 (属于组 G)]         [主机 H2 (属于组 G)]
             │                                                  │                           │
             │                                                  ├─ 1. 主动加入报告 (Report) │
             │<── 发送 IGMP 成员报告 (Report, 目的 IP: G) ──────┤ (无需等待查询，立刻通告)  │
             │   (R 记录本地存在组 G 成员，开启转发)            │                           │
             │                                                  │                           │
             │=== 2. 周期性常规查询 (默认每 125s) ==============│===========================│
             │─── 发送通用查询报文 (Query, 目的 IP: 224.0.0.1) ─>│                           │
             │                                                  │                           │
             │                                                  │ 【3. 触发响应抑制机制】   │
             │                                                  │ H1 随机计时器: 2 秒       │ H2 随机计时器: 7 秒
             │                                                  │                           │
             │                                                  ├─ 2秒到期! 抢先发 Report! ─┐
             │<── 发送加入报告 (目的 IP: G) ────────────────────┤                           │ (H2 监听到该 Report)
             │   (R 刷新组 G 的老化计时器)                      │                           ▼
             │                                                  │                  【H2 自动抑制并取消自己的报告】
             │                                                  │                  (避免并发风暴)
             │                                                  │                           │
             │=== 4. 离开组机制 (Leave) ========================│===========================│
             │                                                  ├─ H1 退出组 G ─────────────┤
             │<── 发送离开报文 (Leave, 目的 IP: 224.0.0.2) ─────┤                           │
             │                                                  │                           │
             │─── 发送特定组查询 (Group-Specific Query) ───────>│                           │
             │    (询问: 局域网内是否还有组 G 成员?)            │                           │
             │<── H2 立即回复 Report! ──────────────────────────┼───────────────────────────┤
             │   (R 确认仍有成员 H2，继续转发，不切断流)        │                           │
```

### 1. 主动加入报告（Join Report）
当主机上的某个应用程序进程加入多播组 G 时，主机不必等待路由器的周期性查询，而是**立即主动发送 IGMP 成员报告报文（目的 IP 设为该多播组地址 G）**。路由器收到后，立刻将该多播组加入到对应的接口转发表中，开始转发多播数据流。

### 2. 周期性常规查询（General Query）
多播路由器周期性（默认每 125 秒）向局域网广播发送通用查询报文：
- **目的 IP 地址**：**`224.0.0.1`**（表示本网段上的所有主机和路由器）；
- 用于探询局域网内是否还有任何多播组的活跃成员。

### 3. 响应抑制机制（Feedback Suppression）
- 每台成员主机收到通用查询后，在 $[0, \text{Max Response Time}]$ 范围内随机生成一个倒计时定时器；
- 定时器最先超时的主机抢先向对应的多播组发送成员报告；
- 同网段内的其他同组成员主机监听到该报告后，**自动取消并静默自身的报告报文**；
- 该机制使得整个局域网在每个查询周期内，每个多播组仅产生 1 个响应报告，消除了并发回复风暴。

### 4. 离开多播组（Leave Message）
- 当某台主机退出多播组 G 时，向 **`224.0.0.2`**（本网段上的所有多播路由器）发送离开报文；
- 路由器收到离开报文后，向多播组 G 发送**特定组查询报文（Group-Specific Query）**；
- 若超时未收到任何主机的成员报告，路由器才停止向该局域网转发该多播组的数据流。
