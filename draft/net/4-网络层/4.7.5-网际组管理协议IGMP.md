## 一、为什么需要 IGMP？（本地末梢网段感知的第一性原理）

多播路由器连接着广域网与本地各个局域网（LAN）。
- **痛点**：若路由器不管局域网内有没有人看，盲目地将互联网上成百上千个组播流全部往局域网里倾倒，局域网带宽会被瞬间占满瘫痪；反之，若局域网内有用户启动了播放器订阅组播，路由器若毫不知情，用户就永远收不到数据。
- **解法**：必须有一种轻量级协议，让主机能够随时向直连的路由器通报自己的加入与退出状态，这就是 **网际组管理协议（Internet Group Management Protocol，IGMP）**。

## 二、IGMP 协议的微观规范与报文交互

### 1. 协议核心属性全景图
```text
+-----------------------+-------------------------------------------------------------+
| 核心属性              | 协议规范与考点定义                                          |
+-----------------------+-------------------------------------------------------------+
| 协议体系归属          | 网络层协议！直接封装在 IP 数据报中传输，协议号字段为 2       |
+-----------------------+-------------------------------------------------------------+
| IP 首部 TTL 约束      | TTL 必须严格固定设置为 1！绝不允许跨越路由器转发到外部网络   |
+-----------------------+-------------------------------------------------------------+
| 通信目标地址          | - 常规查询报文 (Query): 目的 IP 为 224.0.0.1 (本网所有主机)  |
|                       | - 成员加入报告 (Report): 目的 IP 为 所加入的多播组地址 G     |
|                       | - 离开组报文 (Leave): 目的 IP 为 224.0.0.2 (本网所有路由器)  |
+-----------------------+-------------------------------------------------------------+
| 状态维护原则          | 路由器仅记录“本网段是否有组 G 的成员”，不记录具体主机 IP     |
+-----------------------+-------------------------------------------------------------+
```

```text
             │                                                  │                           │
             │                                                  ├─ 2秒到期! 抢先发 Report! ─┐
             │<── 发送加入报告 (目的 IP: G) ────────────────────┤                           │ (H2 监听到该 Report)
             │   (R 刷新组 G 的老化计时器)                      │                           ▼
             │                                                  │                  【H2 自动抑制并取消自己的报告!】

             │                                                  │                           │
             │                                                  │                           │
             │=== 4. 离开组机制 (Leave) ========================│===========================│
             │                                                  ├─ H1 退出组 G ─────────────┤
             │<── 发送离开报文 (Leave, 目的 IP: 224.0.0.2) ─────┤                           │

             │─── 发送特定组查询 (Group-Specific Query) ───────>│                           │
             │    (询问: "局域网内还有没有人收听组 G?")         │                           │
             │<── H2 立即回复 Report! ──────────────────────────┼───────────────────────────┤
             │   (R 确认仍有成员 H2，维持转发，不切断流!)       │                           │
```

## 三、408 经典高频真题精析

### 【题型：IGMP 报文行为与响应抑制机制综合分析】

**【题目描述】**
某以太网局域网内连接有一台多播路由器 R 和 100 台主机（$H_1 \sim H_{100}$）。其中有 30 台主机同时运行某网络直播软件，加入了同一个 IP 多播组 `224.1.2.3`。
多播路由器 R 每隔 125 秒向局域网广播一次 IGMP 常规查询报文（目的 IP: `224.0.0.1`，最大响应时间设置为 10 秒）。

请回答：
1. 路由器 R 发出的常规查询报文在以太网封装时，其以太网目的 MAC 地址是多少？
2. 在该查询周期内，局域网中理论上最少会产生多少个针对多播组 `224.1.2.3` 的 IGMP 成员报告报文？这是由什么机制保证的？请简述其工作原理。
3. 若此时主机 $H_1$ 关闭了直播软件退出该多播组，多播路由器 R 是否会立即切断该多播组在局域网内的数据流转发？为什么？

---

### 【标准解题步骤（120+ 考场标准规范）】

#### 第一问：常规查询报文的以太网 MAC 地址
- 常规查询报文的目的 IP 为 `224.0.0.1`。
- 将 `224.0.0.1` 映射为以太网组播 MAC 地址：
  - 低 23 位为：第二字节后 7 位（全 0）+ 第三字节（全 0）+ 第四字节（1）。
  - MAC 后 24 位 = `0` 拼接低 23 位 = `00-00-01`。
  - 前 24 位固定为 `01-00-5E`。
- **结论**：以太网目的 MAC 地址为 **`01-00-5E-00-00-01`**。

#### 第二问：成员报告报文数量与响应抑制机制
- **理论最少报文数**：**1 个**。
- **机制名称**：**IGMP 响应抑制机制（Feedback Suppression）**。
- **工作原理**：
  - 当局域网内的 30 台成员主机收到通用查询后，各自在 $[0, 10]$ 秒之间独立随机生成一个倒计时定时器；
  - 倒计时最短的那台主机（例如随机到 1.5 秒的主机）最先超时，向组播组 `224.1.2.3` 广播发送一个成员报告报文；
  - 局域网内的另外 29 台主机网卡监听到该报文后，得知“本网段已有人向路由器汇报了本组的存在”，于是立即自动取消并静默自己原本即将发送的报告报文；
  - 从而使得整个局域网在本次查询周期内，仅产生 1 个响应报告，彻底杜绝了并发回复风暴。

#### 第三问：退出组处理机制
- **结论**：**绝对不会立即切断数据流转发**！
- **原因**：
  - 当 $H_1$ 发送 IGMP 离开报文（目的 IP: `224.0.0.2`）后，路由器 R 只知道 $H_1$ 离开了，但不知道局域网内是否还有其他成员；
  - 路由器 R 会立即向组 `224.1.2.3` 连续发送**特定组查询报文（Group-Specific Query）**；
  - 此时局域网内仍有 29 台主机正在收看直播，其中某台主机会迅速回复成员报告报文；
  - 路由器收到该报告后确认本网段仍有活跃成员，继续维持组播流的转发。

## 四、考场肌肉记忆与避坑指南

### 1. 致命易错陷阱
- 陷阱 1：**以为离开报文发出后路由器就停止转发**
  - 只要还有其他主机响应特定组查询，转发绝不中断！
- 陷阱 2：**特定组查询的目标 IP 是什么？**
  - 常规查询发往 `224.0.0.1`（问全网）；特定组查询发往**该多播组本身的 IP**（精准问该组）。

### 2. 秒杀公式与反射条件
$$\text{常规查询目标} = 224.0.0.1 \iff \text{MAC: 01-00-5E-00-00-01}$$
$$\text{离开报文目标} = 224.0.0.2 \iff \text{MAC: 01-00-5E-00-00-02}$$
$$\text{响应抑制核心} = \text{随机倒计时} + \text{抢先通告} + \text{同组成员静默取消}$$
