# 4.4.1+4.4.2 因特网的路由选择协议概述

由于因特网由全球数以万计的异构网络互联而成，且规模极其庞大，路由选择协议必须兼顾**网络规模的可扩展性**与**管理主权与商业策略**的独立性。因此，因特网采用了**分层次的路由选择体系**。

---

## 一、自治系统（Autonomous System，AS）

### 1. 为什么不能在全网运行单一平面路由算法？
若在全网所有路由器之间运行同一种平面的路由选择协议：
1. **路由表规模爆炸与计算崩溃**：全球路由器数量极其庞大，若每个路由器都记录全网明细拓扑，路由表将耗尽内存；任何一条远端链路的微小抖动都会触发全网重新计算最短路径，导致全网计算资源瘫痪；
2. **管理主权与策略差异**：因特网由许多不同的国家、企业、高校及互联网服务提供商（ISP）共同组建。各机构需要自主决定内部的路由度量标准，并根据商业契约对过境流量实施策略限制（如禁止特定竞争对手借道）。

### 2. 自治系统的概念
**自治系统（AS，Autonomous System）** 是指在**单一技术管理机构**管辖下的一组路由器和网络。在同一个 AS 内部，网络使用统一的路由选择策略，运行同一种内部路由选择协议和度量标准。
- 全球每个自治系统拥有一个由 IANA/ICANN 统一分配的自治系统编号（ASN）。

---

## 二、两级路由选择协议架构：IGP 与 EGP

因特网将路由选择协议划分为两大层次：

```
===================================================================================
                       外部网关协议 (EGP) 运行层: BGP-4
        [面向 AS 之间: 路径向量算法 / 基于策略路由 / 解决网络可达性]
===================================================================================
              ▲                                              ▲
              │                                              │
      +───────▼──────────────+                       +───────▼──────────────+
      │ 自治系统 AS 1 (企业网) │                       │  自治系统 AS 2 (ISP)  │
      │ 内部网关协议 (IGP)   │                       │ 内部网关协议 (IGP)   │
      │   RIP 或 OSPF        │                       │   OSPF 或 IS-IS      │
      │ [追求最优与快速收敛]  │                       │ [追求大容量与高稳定性]│
      +──────────────────────+                       +──────────────────────+
```

### 1. 内部网关协议（IGP，Interior Gateway Protocol）
- **运行范围**：运行在**同一个自治系统（AS）内部**；
- **首要目标**：寻找技术上的**最优路径**（如跳数最少、开销最小、时延最短、带宽最高），追求快速收敛；
- **典型协议**：
  - **RIP**（路由信息协议，基于距离向量算法）；
  - **OSPF**（开放最短路径优先协议，基于链路状态算法）；
  - IS-IS（中间系统到中间系统协议）。

### 2. 外部网关协议（EGP，Exterior Gateway Protocol）
- **运行范围**：运行在**不同的自治系统（AS）之间**；
- **首要目标**：在满足各自治系统的商业合同、安全政策和政治约束的前提下，交换**网络可达性信息**，执行**策略路由**；
- **典型协议**：**BGP-4**（边界网关协议第 4 版，基于路径向量算法）。

### 3. IGP 与 EGP 核心对比表

| 对比维度 | 内部网关协议 IGP | 外部网关协议 EGP |
| :--- | :--- | :--- |
| **运行范围** | **同一个自治系统（AS）内部** | **不同的自治系统（AS）之间** |
| **选路目标** | 技术性能最优（距离最短、时延最小、带宽最大） | 策略优先（商业契约、政治约束、安全隔离），保证可达 |
| **典型代表** | **RIP**、**OSPF**、IS-IS | **BGP-4** |
| **底层协议封装** | RIP 封装在 **UDP**（端口 520）；OSPF 封装在 **IP**（协议号 89） | BGP-4 封装在 **TCP**（端口 179） |

## 三、内部网关协议的两大算法流派：距离向量算法 vs 链路状态算法

在 IGP 内部，主要存在两种截然不同的路由算法设计流派：

```
       【距离向量算法 (DV)】                              【链路状态算法 (LS)】
        (以 RIP 协议为代表)                                (以 OSPF 协议为代表)
    
       +--------------------+                            +--------------------+
       |  "传闻式的路标"    |                            |  "全网统一拓扑图"  |
       +--------------------+                            +--------------------+
       路由器仅知道：                                    路由器知道：
       - 到各个目的地的距离 (跳数)                       - 全网所有路由器的连接关系
       - 该往哪个相邻邻居走                              - 每条链路的具体代价 (Cost)
       不知道全网整体拓扑图                              全网维护一致的链路状态数据库 (LSDB)
```

### 距离向量算法与链路状态算法全维对比表

| 对比维度 | 距离向量路由算法（DV，如 RIP） | 链路状态路由算法（LS，如 OSPF） |
| :--- | :--- | :--- |
| **基础数学算法** | **Bellman-Ford 算法**（分布式迭代） | **Dijkstra 算法**（计算最短路径优先树 SPF） |
| **向谁通告信息** | **仅向直接相连的相邻路由器** 通告 | **向全网所有路由器** 进行洪泛（Flooding）通告 |
| **通告什么信息** | 本路由器**当前的整张路由表**（各目的网络及距离） | 仅通告本路由器**直连链路的状态**（接口 IP、邻居及链路度量） |
| **何时通告信息** | **固定周期性通告**（如每 30 秒广播一次）及变化时通告 | **仅在链路状态发生改变时** 触发洪泛更新 |
| **对拓扑的认知** | **缺乏全网视图**（仅知道下一跳和距离，容易引发环路） | **全网全局视图**（全网维护一致的 LSDB，生成无环的最短路径树） |
| **收敛速度** | **收敛慢**，容易出现“好消息传得快，坏消息传得慢” | **收敛极快**，链路改变瞬间同步并重新计算 SPF 树 |
| **系统资源消耗** | 内存与 CPU 开销小，但周期性整表广播消耗链路带宽 | 内存需维护全网 LSDB，CPU 需计算 SPF 树，但稳态带宽开销小 |
