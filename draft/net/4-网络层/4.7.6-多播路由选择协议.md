# 4.7.6 多播路由选择协议

单播路由选择协议为单一目的地计算一条最优路径；而多播通信面临一个发送源对应多个接收者的拓扑结构。多播路由器必须协同构建一棵**无环路的多播分发树（Multicast Distribution Tree）**，确保多播数据报仅沿着树状结构单向流动，并在分叉节点进行按需复制。

---

## 一、两类多播分发树体系：基于源的树 vs 组共享树

```
 1. 基于源的树 (SPT / 最短路径树)                 2. 组共享树 (RPT / 汇聚点树)
 
       [源 S1]        [源 S2]                           [源 S1]        [源 S2]
          │              │                                 │              │
          ▼ (各自建树)   ▼                                 ▼ (先单播发给 RP)▼
      (分发树 1)     (分发树 2)                      +──────────────────────────+
          │              │                           | 核心汇聚点 RP (Rendezvous) |
          ▼              ▼                           +──────────────────────────+
     [接收端组 G]   [接收端组 G]                                   │ (共享同一棵树)
                                                                   ▼
                                                             [接收端组 G]
```

### 1. 基于源的树（Source-Based Tree / 最短路径树 SPT）
- **树的根节点**：以**每一个具体的多播发送源主机 S** 作为树的根节点；
- **树的数量**：若一个多播组中有 $M$ 个发送源，网络中将为该组构建 **$M$ 棵独立的树** $(S, G)$；
- **路径质量**：**时延最优**。每个接收端到特定发送源都沿着最短路径传送；
- **路由器开销**：路由器需要为每个发送源和组维护独立的表项，路由器路由表开销较大；
- **典型协议**：PIM-DM（密集模式）、DVMRP、MOSPF。

### 2. 组共享树（Shared Tree / 汇聚点树 RPT）
- **树的根节点**：以全网统一选定的核心路由器——**汇聚点（RP，Rendezvous Point）** 作为树的根节点；
- **树的数量**：全网所有发送源共享同一棵多播分发树 $(*, G)$；
- **路径质量**：**次优**。所有发送源的流量必须先送至汇聚点 RP，再由 RP 分发给各个接收端，存在绕路时延；
- **路由器开销**：路由器只需维护少量与组相关的共享表项，路由表体积小，扩展性好；
- **典型协议**：PIM-SM（稀疏模式）、CBT。

## 二、反向路径转发（RPF，Reverse Path Forwarding）算法

多播路由协议防范环路的核心机制是 **反向路径转发（RPF）**。

### 1. RPF 检查的工作逻辑
与单播转发只检查“目的地址”不同，**RPF 检查依据的是多播数据报的【源 IP 地址】和【数据报流入的入接口】**：

```
                      [ 收到多播数据报 (源: S, 目的: G) ]
                                     │
                       从接口 I (Incoming Interface) 流入
                                     │
                                     ▼
                ┌────────────────────────────────────────┐
                │ 路由器查询自身的【单播路由表】:         │
                │ "若本机要向源 S 发单播包，出接口是哪个?"│
                └────────────────────┬───────────────────┘
                                     │
                    出接口刚好是接口 I 吗?
                         │            │
                      是 │            │ 否
                         ▼            ▼
             【RPF 检查通过】             【RPF 检查失败】
             数据报沿着最短路径正向流入，   数据报是从环路或次优路径渗漏进来的，
             予以接收并向下游接口转发!     【直接静默丢弃】!
```

### 2. RPF 的核心优势
- **直接复用现有的单播路由表**：无需为多播单独建立复杂的反向拓扑，借助现成的单播路由（如 OSPF/BGP）即可完成环路检测；
- **杜绝多播环路风暴**：任何偏离最短路径树的分支流量在流入时都会因 RPF 检查失败而被直接丢弃，彻底消除了多播风暴。

## 三、协议无关组播（PIM，Protocol Independent Multicast）

目前互联网中最为通用的多播路由协议是 **PIM（协议无关组播）**。
- *“协议无关”* 指 PIM 可以利用任意单播路由协议（RIP、OSPF、BGP 或静态路由）所生成的单播路由表来执行 RPF 检查。

### 1. PIM 密集模式（PIM-DM，Dense Mode）
- **适用场景**：多播组成员密集分布、几乎每个子网都有成员的局域网环境；
- **工作机制（推模式 Push）**：
  1. **泛洪（Flooding）**：假设全网主机都需要数据，定期向全网所有路由器广播洪泛多播数据报；
  2. **剪枝（Pruning）**：下游路由器若发现本地没有该组的接收者，向上游路由器发送剪枝报文，切断该分支的流量转发；
  3. **嫁接（Grafting）**：被剪枝的分支若后续有新成员加入，下游路由器主动向上游发送嫁接报文，快速恢复数据转发。

### 2. PIM 稀疏模式（PIM-SM，Sparse Mode）
- **适用场景**：多播组成员稀疏分布在广阔广域网中的场景；
- **工作机制（拉模式 Pull）**：
  1. 不采用漫灌泛洪。全网预先选定**汇聚点（RP）**；
  2. 只有当某末梢路由器通过 IGMP 确认本地有主机加入该多播组时，该路由器才主动向 RP 发送**显式加入报文（Join）**，按需构建组共享树（RPT）。
