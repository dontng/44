# 4.2.5 地址解析协议 ARP

在 TCP/IP 体系中，网络层使用 IP 地址寻址，而数据链路层传输 MAC 帧时必须使用物理硬件地址（MAC 地址）。**地址解析协议（ARP，Address Resolution Protocol，RFC 826）** 的核心功能就是**在同一个局域网（广播域）内部，根据已知的下一跳或目的主机的 IP 地址，动态解析出其对应的 MAC 地址**。

---

## 一、为什么需要 ARP 协议？

### 1. 软件逻辑寻址与硬件物理寻址的断层
- **网络层（逻辑世界）**：操作系统协议栈和应用程序只使用 IP 地址进行端到端识别与寻址；
- **数据链路层（物理硬件）**：以太网或 Wi-Fi 芯片的硬件控制器在接收和发送帧时，只识别 48 位的 MAC 地址；
- 当网络层将一个 IP 数据报交由数据链路层发送时，网卡驱动必须在以太网 MAC 帧头中填入目的 MAC 地址。如果不知道目的 IP 对应的 MAC 地址，数据链路层就无法完成成帧封装，数据报便无法发送出去。

### 2. ARP 的工作边界
- ARP 依靠广播请求来发现目标，而广播帧无法跨越路由器；
- **ARP 仅在单个局域网（同一广播域）内部有效**。ARP 绝不能用于跨网段直接解析远程主机的 MAC 地址。

---

## 二、ARP 报文格式与以太网封装

ARP 虽然在逻辑功能上服务于网络层，但它的报文**直接封装在数据链路层的 MAC 帧中发送**（不通过 IP 协议封装）：

```
 以太网 MAC 帧头 (14 字节):
 +-------------------+-------------------+-------------------+
 | 目的 MAC (6 字节) |  源 MAC (6 字节)  | 帧类型 (2 字节)   |
 | (全F广播 或 单播) | (发送端网卡 MAC)  | 固定为 0x0806     |
 +-------------------+-------------------+-------------------+
                                           |
                                           v 紧随其后承载 28 字节 ARP 报文
 ARP 报文格式 (固定 28 字节):
 字节偏移:
  0                   2                   4         5         6                   8
 +-------------------+-------------------+---------+---------+-------------------+
 | 硬件类型 (2 字节) | 协议类型 (2 字节) | 硬件长1B| 协议长1B| 操作码 (2 字节)   |
 | (以太网: 0x0001)  | (IPv4: 0x0800)    | (MAC: 6)| (IP: 4) | (1=请求, 2=应答)  |
 +-------------------+-------------------+---------+---------+-------------------+
  8                   14                  18                  24                  28
 +-------------------+-------------------+-------------------+-------------------+
 | 发送端 MAC (6 字节)| 发送端 IP (4 字节)| 目的 MAC (6 字节) | 目的 IP (4 字节)  |
 | (Sender MAC)      | (Sender IP)       | (Target MAC)      | (Target IP)       |
 +-------------------+-------------------+-------------------+-------------------+
```

### 关键字段说明：
1. **以太网帧类型**：固定为十六进制 **`0x0806`**，表示载荷为 ARP 报文（若为普通 IPv4 数据报则为 `0x0800`）；
2. **硬件类型**：表示底层网络技术，以太网取值为 `1`（`0x0001`）；
3. **协议类型**：表示待映射的逻辑协议，IPv4 取值为 `0x0800`；
4. **硬件地址长度与协议地址长度**：MAC 地址为 6 字节，IPv4 地址为 4 字节；
5. **操作码（Opcode）**：
   - **`1`**：**ARP 请求（ARP Request）**；
   - **`2`**：**ARP 应答（ARP Reply）**；
6. **目的 MAC 地址（Target MAC）**：在发送 **ARP 请求** 时，由于该硬件地址正是待求解的目标，此字段**填为全 0**（`00-00-00-00-00-00`）。

## 三、ARP 的基本工作流程

假设主机 A（IP_A, MAC_A）准备向同局域网内的主机 B（IP_B, MAC_B）发送数据报：

```
[主机 A]                                                 [主机 B]
   |                                                        |
   |---- 1. 查询本地 ARP 缓存 (未命中)                      |
   |                                                        |
   |==== 2. 广播发送 ARP 请求 (目的 MAC: FF-FF-FF-FF-FF-FF) ==>| (局域网内全网接收)
   |        [问: IP_B 的 MAC 是多少? 我是 IP_A, MAC_A]      |
   |                                                        |---- 3. 比对 Target IP (匹配!)
   |                                                        |     记录 <IP_A, MAC_A> 到自身缓存
   |                                                        |
   |<--- 4. 单播回复 ARP 应答 (目的 MAC: MAC_A) -------------|
   |        [答: 我是 IP_B, 我的 MAC 是 MAC_B]              |
   |                                                        |
   |---- 5. 将 <IP_B, MAC_B> 写入本地 ARP 缓存              |
   |---- 6. 封装以太网帧，单播发送真实数据 ---------------->|
```

### 1. 查询本地 ARP 高速缓存（ARP Cache）
- 主机 A 首先在操作系统的本地 ARP 缓存表中检索 IP_B；
- 若命中映射表项，直接取出 MAC_B 封装 MAC 帧发送；
- 若未命中，则将待发送的数据报挂起，启动 ARP 地址解析流程。

### 2. 广播发送 ARP 请求（ARP Request）
- 主机 A 封装 ARP 请求报文，操作码置为 1，Target MAC 置为全 0；
- 封装入以太网 MAC 帧，**目的 MAC 填全 1 广播地址（`FF-FF-FF-FF-FF-FF`）**；
- 交换机将该广播帧泛洪至局域网内的所有接口，所有接入的主机均接收并解封装该 ARP 报文。

### 3. 主机比对与学习
- 局域网内的其他主机（非主机 B）检查报文中的 Target IP，发现与本机 IP 不符，直接静默丢弃该请求；
- 主机 B 检查发现 Target IP 与本机 IP 一致：
  - 主机 B 将发送方主机 A 的映射关系 `<IP_A, MAC_A>` 记录到自己的 ARP 缓存表中（避免之后主机 B 给主机 A 回复数据时再次发起 ARP 请求）。

### 4. 单播回复 ARP 应答（ARP Reply）
- 主机 B 封装 ARP 应答报文，操作码置为 2，将自己的 MAC_B 填入 Sender MAC；
- 封装入以太网 MAC 帧，**目的 MAC 明确填写主机 A 的物理地址 MAC_A（单播）**；
- 交换机根据转发表将该应答帧精准送达主机 A。

### 5. 更新缓存并发送数据
- 主机 A 收到 ARP 应答后，将 `<IP_B, MAC_B>` 映射写入本地 ARP 高速缓存；
- 从发送队列中取出挂起的数据报，封装以太网帧（目的 MAC 为 MAC_B）并发送。

> **ARP 高速缓存的生存时间（TTL）**：
> ARP 表项具有老化时间（通常为数分钟到二十分钟）。若一段时间内未与某主机通信，该动态表项将被自动删除，以适应网卡更换或主机 IP 重新分配的动态变化。

## 四、跨网段通信时的 ARP 行为

当源主机 A 向处于不同子网的远程目的主机 C 发送数据时：
1. **源主机 A 执行子网比对**：源主机 A 将目的 IP 与自己的子网掩码进行按位与运算，发现目的主机 C 与自己不在同一子网；
2. **尋找下一跳（默认网关）**：
   - 处于不同子网的主机无法直接二层通信，广播帧也无法穿透路由器；
   - **主机 A 发送的 ARP 请求，其目标是查询本地默认网关（路由器接口）的 MAC 地址，而不是远程目的主机 C 的 MAC 地址**；
3. **分段解析**：
   - 主机 A 将数据帧封装后发送给默认网关（目的 MAC 为网关 MAC，目的 IP 仍为目的主机 C 的 IP）；
   - 路由器收到后，在下一段链路上再通过 ARP（若下一段是以太网）解析目的主机 C（或下一个路由器接口）的 MAC 地址。

---

## 五、免费 ARP（Gratuitous ARP）

**免费 ARP** 是指主机发送的 ARP 请求报文中，**源 IP 地址和目的 IP 地址均填写为本机自身的 IP 地址**。

### 核心作用：
1. **检测 IP 地址冲突**：
   - 主机在网络接口启动或配置新 IP 地址后，主动广播一发免费 ARP 请求；
   - 若局域网中有其他主机正在使用该 IP，该主机会回复 ARP 应答，本机会立即收到该应答并向操作系统报警“IP 地址冲突”，停止使用该冲突 IP；
2. **通告新的 MAC 地址（刷新网络缓存）**：
   - 当主机的网卡更换、或集群高可用网关发生主备切换时，新主设备发送免费 ARP；
   - 局域网内的所有主机和交换机收到后，会依据报文中的源 MAC 地址自动刷新本地的 ARP 缓存表和 MAC 转发表，从而使流量无缝切换到新网卡上。
