# 4.2.5 地址解析协议ARP

在 TCP/IP 体系中，通信双方在网络层使用 IP 地址寻址，但在实际的数据链路层物理网络中，帧的转发必须依据网卡的硬件物理地址——**MAC 地址**。

**地址解析协议（Address Resolution Protocol，ARP）** 的核心功能就是：**根据已知主机的 IP 地址，自动动态解析出其对应的 MAC 地址**。

---

## 一、ARP 协议的核心工作流程

假设主机 A（`IP_A`, `MAC_A`）要向同一局域网内的主机 B（`IP_B`, `MAC_B`）发送数据：

```
+--------------------------------------------------------------------------------+
| 步骤 1: 查询本地 ARP 高速缓存 (ARP Cache)                                      |
| 主机 A 首先在本地缓存表中查找是否有 IP_B 对应的 MAC 地址。                     |
| - 若命中: 直接取出 MAC_B 封装入帧发送!                                         |
| - 若未命中: 启动 ARP 广播解析。                                                |
+--------------------------------------------------------------------------------+
                                       |
                                       v
+--------------------------------------------------------------------------------+
| 步骤 2: 广播发送 ARP 请求分组 (ARP Request)                                    |
| 主机 A 在局域网内广播发送 ARP 请求:                                            |
|   [源 IP: IP_A | 源 MAC: MAC_A | 目的 IP: IP_B | 目的 MAC: 00-00-00-00-00-00]   |
| 以太网帧头封装: 目的 MAC = FF-FF-FF-FF-FF-FF (局域网内所有主机网卡均接收)      |
+--------------------------------------------------------------------------------+
                                       |
                                       v
+--------------------------------------------------------------------------------+
| 步骤 3: 目的主机 B 单播回复 ARP 应答分组 (ARP Reply)                           |
| 局域网所有主机收到广播，拆包比对目的 IP:                                       |
| - 其他主机发现目的 IP 不是自己，静默丢弃;                                      |
| - 主机 B 发现目的 IP 与自己匹配，首先将 A 的映射 <IP_A, MAC_A> 写入自己的缓存; |
| - 主机 B 单播向主机 A 发送 ARP 应答:                                           |
|   [源 IP: IP_B | 源 MAC: MAC_B | 目的 IP: IP_A | 目的 MAC: MAC_A]               |
+--------------------------------------------------------------------------------+
                                       |
                                       v
+--------------------------------------------------------------------------------+
| 步骤 4: 更新缓存与发送数据                                                     |
| 主机 A 收到单播应答，将 <IP_B, MAC_B> 写入本地 ARP 缓存表，完成数据帧封装发送。 |
+--------------------------------------------------------------------------------+
```

---

## 二、跨网段通信时的 ARP 行为（最经典大题陷阱）

> **极其高频的 408 考点**：若主机 A 要发送数据给**外网/不同网段**的主机 C，主机 A 的 ARP 请求中查询的是谁的 MAC 地址？

- **正确答案**：查询的是**默认网关（本网段路由器接口）的 MAC 地址**，而不是目的主机 C 的 MAC 地址！
- **原因**：跨网段通信必须由默认网关接管路由转发。主机 A 只能在本物理链路内广播，无法穿透路由器；主机 A 先把帧封装网关 MAC 交给路由器，由路由器在下一跳链路上再去解析下一跳或目的地的 MAC 地址。

---

## 三、ARP 高速缓存的老化机制（Aging Time）

- ARP 缓存中的条目不是永久保存的，每个动态表项均设有一个**生存时间（通常 10 ~ 20 分钟）**。
- **目的**：适应主机更换网卡、IP 地址重新分配（DHCP）以及物理位置移动。超时未通信的表项自动被操作系统剔除。

---

## 四、免费 ARP（Gratuitous ARP）

主机启动刚配置好 IP 地址时，主动向局域网广播发送一个以**自己本机的 IP 地址**为目的 IP 的 ARP 请求。
- **核心作用**：
  1. **IP 地址冲突检测**：若收到回复，说明局域网内已有其他主机占用了该 IP，系统弹出“IP冲突”告警。
  2. **刷新对端缓存**：更换网卡或网关主备切换后，通知全网其他主机刷新其 ARP 缓存。

> **考点小结**：ARP 请求是**广播**（目的 MAC 全 F），ARP 应答是**单播**；跨网段通信解析的是**网关 MAC**。
