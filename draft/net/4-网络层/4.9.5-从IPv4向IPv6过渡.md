# 4.9.5 从IPv4向IPv6过渡

> **408 考纲地位**：**过渡期核心工程技术（选择题高频机制，大题数据报封装分析点）**。深入考查：**双协议栈技术（Dual Stack）运行机理与局限性**、**隧道技术（Tunneling / IPv6-in-IPv4）的封装过程与协议号 41**、**两类技术的本质优缺点横向对比**。

---

## 一、为什么 IPv4 不能一夜之间升级为 IPv6？（互联网共存现实）

因特网是一个由数万个独立自治系统、数十亿台终端设备、数百万台路由器构成的超大规模异构系统。
- **痛点**：IPv4 首部与 IPv6 首部格式完全不兼容。一台纯 IPv4 路由器收到纯 IPv6 数据报，由于版本号为 6 且首部完全不同，会将其作为非法报文直接丢弃。
- **不可行方案**：全球所有 ISP 和用户不可能在同一个约定时刻同时关机并升级为纯 IPv6。
- **必然选择**：必须采用**平滑演进与长期共存机制**。当前国际通行的两大核心过渡技术为：**双协议栈（Dual Stack）** 与 **隧道技术（Tunneling）**。

---

## 二、两大核心过渡技术微观机制

```text
 1. 双协议栈技术 (Dual Stack)                     2. 隧道技术 (Tunneling / 穿透 IPv4 海洋)
 
    +------------------------+                     [IPv6 孤岛] ──> [双栈边界路由器 R1]
    |      应用程序层        |                                              │
    +------------------------+                                     (IPv4 骨干网隧道)
    |  IPv4 栈  |  IPv6 栈   |                                     [外层 IPv4 首部]
    +-----------+------------+                                     [内层 IPv6 载荷]
    |     数据链路层/物理层   |                                              │
    +------------------------+                     [IPv6 孤岛] <── [双栈边界路由器 R2]
   (同一台设备拥有双重 IP 地址)
```

### 1. 双协议栈技术（Dual Stack）
- **实现机理**：
  - 一台主机或路由器**同时安装 IPv4 和 IPv6 两套完整的网络层协议栈**；
  - 拥有一个合法的 IPv4 地址和一个合法的 IPv6 地址；
  - DNS 服务器根据通信对端返回 A 记录（IPv4）还是 AAAA 记录（IPv6），由双栈协议栈自适应选择使用 IPv4 还是 IPv6 进行通信。
- **局限性**：
  - 双栈节点仍然必须占用宝贵的 IPv4 公网地址，**没有从根本上解决全球 IPv4 地址枯竭问题**；
  - 设备的协议栈占用双倍内存与计算资源。

---

### 2. 隧道技术（Tunneling / 封装过渡）
- **核心应用场景**：在 IPv6 孤岛想要跨越中间成熟的“IPv4 海洋网络”进行互联时。
- **实现微观时序**：
  1. **入站封装**：双栈边界路由器 R1 收到来自 IPv6 孤岛的 IPv6 数据报；
  2. **IPv6-in-IPv4 封装**：R1 将整个 IPv6 数据报原封不动地作为载荷，在其外部**封装一个新的 IPv4 首部**：
     - **外层源 IPv4 地址**：R1 的 IPv4 出口接口 IP；
     - **外层目的 IPv4 地址**：隧道终点路由器 R2 的 IPv4 入口接口 IP；
     - **IPv4 首部协议号（Protocol）**：设置为 **`41`**（表示载荷封装的是 IPv6 数据报！）；
  3. **公网标准路由**：中间的纯 IPv4 骨干路由器仅根据外层 IPv4 首部进行跳数转发，完全不知晓内部包裹着 IPv6；
  4. **出站解封装**：终点双栈路由器 R2 收到该 IPv4 数据报后，剥去外层 IPv4 首部，将内部纯 IPv6 数据报安全交付给 IPv6 目的孤岛。

---

## 三、双协议栈 vs 隧道技术横向对比矩阵（408 秒杀表）

| 对比维度 | 双协议栈技术 (Dual Stack) | 隧道技术 (Tunneling) |
|---|---|---|
| **核心思路** | 让所有节点“学会说两种语言” | 把 IPv6“装进 IPv4 盒子里”邮寄穿过 IPv4 网络 |
| **中间网络要求**| 沿途所有路由器**必须支持双协议栈** | 中间网络只需**支持纯 IPv4 即可，零改造成本** |
| **数据报修改** | 协议栈直接生成对应版本的原生数据报 | 将 IPv6 整体封装在 IPv4 载荷中（协议号 41） |
| **地址消耗** | 仍需大量消耗稀缺的 IPv4 公网地址 | 仅隧道两端的边界网关需要公网 IPv4 地址 |
| **典型代表** | 现代智能手机、服务器双栈并网运行 | 6to4 隧道、Teredo 隧道、ISATAP 隧道 |

## 四、408 经典高频真题精析

### 【题型：IPv4 向 IPv6 过渡中隧道封装字段分析综合题】

**【题目描述】**
某大学有两个采用纯 IPv6 编址的新校区，分别通过边界路由器 R1 和 R2 接入公共 IPv4 骨干互联网。两校区之间配置了 IPv6-over-IPv4 隧道。已知：
- 校区 A 内部的主机 H1 的 IPv6 地址为 `2001:DA8::1`；
- 校区 B 内部的主机 H2 的 IPv6 地址为 `2001:DA8::2`；
- 边界路由器 R1 的 IPv4 接口地址为 `202.112.10.1`；
- 边界路由器 R2 的 IPv4 接口地址为 `202.114.20.2`。

现主机 H1 向主机 H2 发送一个数据载荷为 1000 字节的 TCP 报文段（数据报未发生分片）。
请回答：
1. 当该数据报在 IPv4 骨干网中穿越隧道传输时，其外层 IPv4 首部的源 IP、目的 IP 以及协议（Protocol）字段分别是什么？
2. 骨干网中的纯 IPv4 路由器是否需要解析内层的 IPv6 首部？为什么？
3. 该复合数据报在 IPv4 骨干网传输时的总长度是多少字节？（设 IPv4 基本首部为 20 字节，IPv6 基本首部为 40 字节，TCP 首部为 20 字节，且无任何选项与扩展首部）。

---

### 【标准解题步骤（120+ 考场标准规范）】

#### 第一问：外层 IPv4 首部参数推导
- 数据报通过隧道穿透 IPv4 网络，由双栈网关 R1 发往 R2：
  - **外层源 IP 地址**：`202.112.10.1`（边界路由器 R1 的 IPv4 接口地址）；
  - **外层目的 IP 地址**：`202.114.20.2`（边界路由器 R2 的 IPv4 接口地址）；
  - **IPv4 协议字段 (Protocol)**：填入 **`41`**（IANA 规定协议号 41 专用于标识 IPv6 封装）。

#### 第二问：中间 IPv4 路由器行为分析
- **结论**：**不需要解析内层 IPv6 首部**。
- **原因**：IPv4 骨干路由器工作在纯 IPv4 数据平面，它们仅依据外层 IPv4 首部中的目的 IP 地址（`202.114.20.2`）进行常规路由查表与转发。整个内层 IPv6 数据报在 IPv4 路由器眼中仅仅是一段透明无差别的字节流载荷（Payload）。

#### 第三问：复合数据报总长度计算推导
- 数据报在隧道中由三层嵌套构成：
  $$\text{总长度} = \text{外层 IPv4 首部} + \text{内层 IPv6 首部} + \text{TCP 首部} + \text{数据载荷}$$
- 代入具体数值：
  $$\text{总长度} = 20\text{ B} + 40\text{ B} + 20\text{ B} + 1000\text{ B} = \mathbf{1080 \text{ 字节}}$$
- **结论**：复合数据报在骨干网中的总长度为 **1080 字节**。

## 五、考场肌肉记忆与避坑指南

### 1. 致命易错陷阱
- 陷阱 1：**隧道封装时 IPv4 协议号填多少？**
  - **填 41！**（既不是 TCP 的 6，也不是 UDP 的 17，而是专指 IPv6 的 41）。
- 陷阱 2：**混淆双栈与隧道的适用边界**
  - 如果整条路径上的路由器都支持 IPv6，直接原生传输；只有在**两头支持 IPv6、中间只支持 IPv4** 时才使用隧道！

### 2. 秒杀公式与反射条件
$$\text{双协议栈} \iff \text{双 IP 地址} + \text{双路由表} + \text{硬件资源开销大}$$
$$\text{隧道技术} \iff \text{IPv6 外套 IPv4} + \text{IPv4 协议号 41} + \text{骨干网零改造}$$
