# 4.9.5 从IPv4向IPv6过渡

> **408 考纲地位**：**过渡期核心工程技术（选择题高频机制考点，综合题潜在封装分析点）**。深入考查：**向 IPv6 过渡的客观必然性与平滑演进要求**、**双协议栈技术（Dual Stack）实现原理、工作流程与局限性**、**隧道技术（Tunneling / 6-over-4）的封装时序、首部嵌套结构与 IPv4 协议号 41**、**两类技术的本质适用场景与横向对比**。

---

## 一、IPv4 向 IPv6 过渡的客观背景

因特网是一个由全球数万个自治系统、数十亿台终端设备以及数百万台核心路由器构成的超大规模异构系统：
- **格式不兼容**：IPv4 首部与 IPv6 首部格式完全不兼容。一台纯 IPv4 路由器收到版本号为 6 的 IPv6 数据报时，因无法解析其格式而会直接将其作为无效报文丢弃；
- **演进不可一蹴而就**：全球所有 ISP、企业与终端设备不可能在同一时刻统一停机升级为纯 IPv6；
- **工程解决路线**：必须采用长期共存、渐进演进的过渡策略。IETF 确立了两种最核心的过渡技术：**双协议栈（Dual Stack）** 与 **隧道技术（Tunneling）**。

---

## 二、双协议栈技术（Dual Stack）

### 1. 实现原理
双协议栈是指在**同一台主机或路由器上同时运行 IPv4 和 IPv6 两套完整的网络层协议栈**。
- 设备同时配置一个合法的 IPv4 地址和一个合法的 IPv6 地址；
- 设备既能直接收发原生的 IPv4 数据报，也能直接收发原生的 IPv6 数据报。

```text
+---------------------------------------+
|              应用层程序               |
+-------------------+-------------------+
|     IPv4 协议栈   |    IPv6 协议栈    |
+-------------------+-------------------+
|              网络接口层               |
+---------------------------------------+
```

### 2. 工作与协商机制
- 当双栈主机与远端节点发起通信时，首先通过 DNS 查询目的主机的地址记录：
  - 若 DNS 返回 A 记录（32 位 IPv4 地址），则本地协议栈选择 IPv4 栈并封装 IPv4 数据报发送；
  - 若 DNS 返回 AAAA 记录（128 位 IPv6 地址），则本地协议栈选择 IPv6 栈并封装 IPv6 数据报发送。
- **沿途网络要求**：若通信双方采用 IPv6 传输，则沿途经过的每一台路由器也必须全部是支持 IPv6 的双栈或纯 IPv6 设备，否则数据报在中途会被纯 IPv4 路由器丢弃。

### 3. 技术局限
- **未根本缓解 IPv4 枯竭**：双协议栈节点依然必须分配并占用公网 IPv4 地址；
- **资源开销大**：每台网络设备必须同时维护两张独立的路由表（IPv4 FIB 与 IPv6 FIB），消耗更多的内存与 CPU 处理资源。

## 三、隧道技术（Tunneling）

### 1. 核心应用场景与设计思想
当两个采用 IPv6 的独立网络（“IPv6 孤岛”）需要相互通信，但它们之间仅能通过现存的纯 IPv4 骨干网络（“IPv4 海洋”）连接时，使用双协议栈技术要求中间所有骨干路由器全部升级，成本极高。

**隧道技术（6-over-4）** 的核心思想是：**将整个 IPv6 数据报直接作为有效载荷，完整封装在 IPv4 数据报的数据字段中，借由 IPv4 骨干网络透明传输**。

```text
[ IPv6 孤岛 A ] ──> [ 双栈边界路由器 R1 ] ───( IPv4 骨干网隧道 )───> [ 双栈边界路由器 R2 ] ──> [ IPv6 孤岛 B ]
   (原生 IPv6)                                                          (原生 IPv6)
                            │                                                 ▲
                            ▼                                                 │
                   +-------------------+                             +-------------------+
                   |  外层 IPv4 首部   |                             | 剥去外层 IPv4 首部 |
                   +-------------------+                             +-------------------+
                   |  内层 IPv6 首部   |                             | 交付原生 IPv6     |
                   +-------------------+                             +-------------------+
                   |    数据载荷       |
                   +-------------------+
```

### 2. 隧道封装的微观处理时序
1. **入站识别与封装**：
   - 双栈边界路由器 R1 收到来自 IPv6 网络的数据报，目的地址为远端 IPv6 网络；
   - R1 检查路由表，判定下一跳需要跨越 IPv4 隧道；
   - R1 在原有的 IPv6 数据报外部**附加一个 20 字节的 IPv4 首部**：
     - **外层源 IPv4 地址**：隧道入口路由器 R1 自身的 IPv4 出口接口地址；
     - **外层目的 IPv4 地址**：隧道出口路由器 R2 的 IPv4 入口接口地址；
     - **IPv4 首部协议号（Protocol）**：设置为 **`41`**（IANA 规定协议号 41 专用于标识承载 IPv6 载荷）。
2. **中间网络透明路由**：
   - 骨干网中的纯 IPv4 路由器仅依据外层 IPv4 首部的目的 IP 进行常规查表转发；
   - 沿途 IPv4 路由器对内部封装的 IPv6 首部与数据毫无感知，仅将其视为普通的数据载荷；
   - 路由器每跳对**外层 IPv4 首部**执行 TTL 递减并重新计算首部检验和，内层 IPv6 首部的 Hop Limit 保持不变。
3. **出站解封装与交付**：
   - 隧道出口路由器 R2 接收到该 IPv4 数据报后，检查协议号为 41；
   - R2 剥去外层 IPv4 首部，还原出原始的 IPv6 数据报；
   - R2 根据内层 IPv6 首部的目的 IPv6 地址，将该数据报直接转发至目的 IPv6 网络。

## 四、双协议栈与隧道技术全方位横向对比

| 评估维度 | 双协议栈技术 (Dual Stack) | 隧道技术 (Tunneling) |
|---|---|---|
| **基本实现机制** | 网络设备同时运行两套协议栈，分别处理 IPv4 和 IPv6 | 将 IPv6 数据报封装入 IPv4 数据报载荷中穿透传输 |
| **骨干网络改造要求** | 传输路径上的**所有路由器必须全部升级支持 IPv6** | 中间骨干路由器**仅需支持纯 IPv4 即可，零改造成本** |
| **首部封装开销** | 原生首部，无额外首部开销 | 额外增加 20 字节的外层 IPv4 首部开销 |
| **协议号标识** | 依传输层协议填写（TCP 为 6，UDP 为 17） | 外层 IPv4 首部的协议字段必须设置为 **`41`** |
| **中间路由器感知** | 中间路由器必须识别并解析 IPv6 首部 | 中间路由器完全不感知内层 IPv6，仅视作透明数据 |
| **公网 IPv4 地址需求** | 所有双栈终端与路由器均需分配 IPv4 地址 | 仅隧道两端的边界路由器需要分配公网 IPv4 地址 |
| **典型适用场景** | 终端设备接入、逐步升级的局域网环境 | 异地 IPv6 网络跨越纯 IPv4 互联网骨干互联 |
