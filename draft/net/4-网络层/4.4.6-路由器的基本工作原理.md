# 4.4.6 路由器的基本工作原理

路由器是一种具有多个输入端口和多个输出端口的专用计算机，其核心任务是在网络层实现分组的**路由选择（控制平面）**与**分组转发（数据平面）**。

---

## 一、路由器的两大核心功能部件（控制平面 vs 数据平面）

```text
+-------------------------------------------------------------+
|             路由选择部分 (控制平面 / 软件慢速处理)           |
|  - 路由选择处理器: 运行路由协议 (OSPF/BGP), 计算并维护路由表|
+-------------------------------------------------------------+
                              |
                     下发转发表 (FIB)
                              |
                              v
+-------------------------------------------------------------+
|             分组转发部分 (数据平面 / 硬件微秒级线速处理)     |
|                                                             |
|  +------------+       +----------------+       +------------+
|  | 输入端口   | ----> | 交换结构       | ----> | 输出端口   |
|  | (查表排队) |       | (内部硬件总线) |       | (排队调度) |
|  +------------+       +----------------+       +------------+
+-------------------------------------------------------------+
```

1. **路由选择部分（控制平面）**：
   - 核心是路由选择处理器。负责执行路由协议软件、处理链路状态更新或路由更新报文，构建全局**路由表（Routing Table）**。
   - 属于**宏观控制**，由软件在通用 CPU 上运行，处理频率较低（秒级）。
2. **分组转发部分（数据平面）**：
   - 根据路由表提取生成硬件**转发表（FIB，Forwarding Information Base）**。
   - 输入端口对接收到的每个数据报提取目的 IP，利用硬件 ASIC/TCAM 芯片进行纳秒级的**最长前缀匹配查表**，驱动交换结构将数据报送达指定输出端口。
   - 属于**微观转发**，纯硬件实现，线速（Line-Rate）执行。

---

## 二、路由表（Routing Table）与转发表（Forwarding Table）的辨析

- **路由表**：是软件概念，根据复杂的网络拓扑和路由协议算法计算得出，条目包含目的网络、掩码、下一跳、Metric 评价等，重点面向**拓扑最优化**；
- **转发表**：是从路由表直接导出的硬件查找表，结构极度简化和扁平化（通常由特殊的 TCAM 三态内容寻址寄存器实现），直接建立“目的网络前缀 $	o$ 物理出端口 / 下一跳 MAC 地址”的直接映射，重点面向**线速极速查找**。

---

## 三、交换结构（Switch Fabric）的三种演进形态

交换结构是路由器内部将分组从输入端口送达输出端口的物理机制：

1. **通过内存交换**：最早期的形态。输入端口通过中断通知 CPU 将分组复制到内存，CPU 查表后再复制到输出端口。性能受限于内存总线带宽。
2. **通过总线交换**：输入端口通过内部共享总线直接将分组发送到输出端口，无需 CPU 参与。但在任意时刻**仅允许一个分组穿越总线**，存在总线争用瓶颈。
3. **通过互联网络（交叉开关 Crossbar）交换**：现代高性能路由器的标准架构。采用 $N 	imes N$ 的纵横交叉矩阵总线，支持**多个输入端口到不同输出端口的无阻塞并发并行转发**。

---

## 四、输入排队与输出排队（路由器丢包本质）

- **线路端（Head-of-Line，HOL）阻塞（输入排队）**：当输入端口排在最前面的分组因目标输出端口正忙而被阻塞时，其后面排队的所有分组即便目标端口完全空闲，也被迫一同等待阻滞。
- **丢包与缓冲区溢出（输出排队）**：当多条输入链路同时向同一个输出端口发送大量突发数据报，交换速度超过了输出端口物理链路的发射速率时，输出队列缓冲区被迅速耗尽。缓冲区满溢时，新到达的数据报被路由器直接丢弃——**这就是因特网产生分组丢失的最主要根源**。
