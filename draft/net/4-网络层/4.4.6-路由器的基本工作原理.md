# 4.4.6 路由器的基本工作原理

路由器（Router）是连接两个或多个不同网络、实现网络层分组转发的核心设备。现代高性能路由器在体系结构上普遍将**控制平面（软件选路）**与**数据平面（硬件转发）**进行物理分离，以满足高速骨干网的转发吞吐需求。

---

## 一、控制平面与数据平面的结构分离

在早期的单处理器路由器中，分组的接收、路由表查找和转发全部由通用 CPU 通过软件中断处理完成。当网络进入千兆及以上速率时，纯软件处理会产生严重的 CPU 性能瓶颈。现代路由器在体系结构上清晰地划分为两大部分：

```
+=================================================================================+
|                      控制平面 (Control Plane / 软件通用 CPU 处理)               |
|                                                                                 |
|   +-------------------------------------------------------------------------+   |
|   | 路由选择处理器: 运行动态路由协议 (OSPF/RIP/BGP), 计算并生成【路由表】   |   |
|   +-------------------------------------------------------------------------+   |
+=================================================================================+
                                        │
                                生成并下发【硬件转发表 (FIB)】
                                        │
+=======================================▼=========================================+
|                      数据平面 (Data Plane / 硬件专用芯片线速转发)               |
|                                                                                 |
|   +------------------+         +--------------------+         +------------------+   |
|   |   输入端口部件   | =======>|      交换结构      | =======>|   输出端口部件   |   |
|   | (物理/链路/查表) |         | (Switch Fabric 矩阵|         | (排队调度/装帧)  |   |
|   +------------------+         +--------------------+         +------------------+   |
+=================================================================================+
```

### 1. 控制平面（路由选择部分）
- **核心组件**：路由选择处理器（通用 CPU 与内存）；
- **核心任务**：运行动态路由选择协议（如 OSPF、RIP、BGP），收集网络拓扑并计算生成**路由表（Routing Table）**；同时处理网络管理协议报文；
- **运行特征**：属于软件层面的计算过程，动作周期在毫秒或秒级。

### 2. 数据平面（分组转发部分）
- **核心组件**：由**输入端口**、**交换结构**和**输出端口**组成；
- **核心任务**：根据主控下发的**转发表（Forwarding Table）**，将到达输入接口的 IP 数据报以极高速度搬移到合适的输出接口；
- **运行特征**：由专用的硬件芯片直接在微秒或纳秒级别独立完成。

---

## 二、路由表与转发表的区别

| 对比维度 | 路由表（Routing Table） | 转发表（Forwarding Table / FIB） |
| :--- | :--- | :--- |
| **归属平面** | **控制平面**（软件层面） | **数据平面**（硬件层面） |
| **存放位置** | 路由处理器的通用主存中 | 接口板的专用存储器或高速缓存中 |
| **生成方式** | 路由协议算法（或静态配置）计算得出 | 由主控系统根据路由表提取、精简并下发 |
| **表项结构** | 包含拓扑、协议类型、开销 Metric、老化时间等完整信息 | 结构高度精简：主要包含目的网络前缀 $\to$ 输出接口 / 下一跳 MAC |
| **设计目标** | 面向拓扑维护与网络决策的最优化 | 面向硬件查表的高吞吐与低时延 |

## 三、三种交换结构（Switch Fabric）的特点与瓶颈

交换结构负责将数据报从输入端口传送至输出端口，主要有三种实现形式：

```
1. 经由内存交换                   2. 经由总线交换                   3. 经由纵横交叉矩阵 (Crossbar)
   +----+        +----+              +----+       +----+              +----+       +----+
   |入口|        |出口|              |入口|       |出口|              |入 1|       |出 1|
   +----+        +----+              +----+       +----+              +--┬-+       +-▲--+
     │             ▲                   │            ▲                    │           │
   ==╪=============╪====             ==╪============╪====             ───┼─────╳─────┼───
     │   系统总线  │                      共享总线                      │     │     │
     ▼             │                                                 ───┼─────┼─────╳───
    +---------------+                                                   │     │     │
    | 操作系统内存  |                                                +--┴-+       +-▲--+
    +---------------+                                                |入 2|       |出 2|
                                                                     +----+       +----+
 [吞吐受限于内存带宽，              [吞吐受限于总线争用，             [支持多对输入输出端口
  数据报两次穿越总线]                同一时刻仅允许一个分组通过]       完全并发传输，吞吐量极大]
```

1. **经由内存交换（Switching via Memory）**：
   - 输入端口将分组通过系统总线复制到主存中，提取目的地址查表后，再通过总线复制到输出端口；
   - **瓶颈**：转发速率受限于内存带宽，每个分组进出主存两次穿越总线。
2. **经由总线交换（Switching via Bus）**：
   - 输入端口通过共享的背板总线直接将分组传送到指定的输出端口，无需主存中转；
   - **瓶颈**：存在**总线争用（Bus Contention）**。同一时间总线上仅允许一个分组通过，整机的交换容量受限于总线带宽。
3. **经由纵横交叉开关网络交换（Crossbar）**：
   - 现代高性能路由器的标准架构。通过 $N \times N$ 的网格矩阵交叉点闭合；
   - **优势**：**允许多对不同的输入端口与输出端口在同一时间完全并行传输**，只要它们的目的输出端口不同，就不存在总线阻塞，整机交换容量大幅提升。

## 四、输入排队与输出排队：丢包与延时机理

### 1. 输入排队与头端阻塞（Head-of-Line Blocking，HOL 阻塞）
当多个输入端口的队首分组同时竞争同一个输出端口时：
- 交换结构在一个周期内只能选择其中一个分组转发，其余输入端口被迫等待；
- **头端阻塞（HOL 阻塞）**：排在队首被阻塞的分组，会导致其**队尾后面排队的其他分组全部被迫滞留**，即便队尾后面的分组所要前往的输出端口当前完全处于空闲状态；
- HOL 阻塞严重限制了 FIFO 先入先出输入缓冲队列的交换效率。

### 2. 输出排队与缓冲区满溢丢包
当多个输入端口以极高线速向同一个输出端口发送数据时，如果短时间内到达的流量速率远大于输出物理链路的发射速率：
- 分组必须在输出端口的缓冲区队列中排队等待发送；
- 当突发流量持续、输出端口缓冲区被彻底耗尽时，随后到达的分组无法被容纳，路由器硬件只能执行**尾部丢弃（Drop-tail）**；
- **本质结论**：**网络层分组丢失的根本原因通常不是物理传输错误，而是网络拥塞导致路由器队列缓冲区满溢而执行的主动丢弃**。
