# 4.2.4 IPv4地址与MAC地址

IP 地址与 MAC 地址在网络通信中分工协作，分别承担**端到端逻辑寻址**与**逐跳物理转发**的职责。

---

## 一、双重寻址体系的必要性

| 对比维度 | IP 地址（逻辑地址） | MAC 地址（物理硬件地址） |
|---|---|---|
| **所在层次** | 网络层（第 3 层） | 数据链路层（第 2 层） |
| **地址长度** | 32 bit（IPv4） / 128 bit（IPv6） | 48 bit（6 字节） |
| **地址结构** | **层次化结构**（网络前缀 + 主机号） | **扁平结构**（OUI 厂商号 + 序列号） |
| **寻址范围** | **全球全局路由**（跨越异构网络） | **仅局限于单段物理链路/局域网内部** |
| **移动性** | 随接入网络变动（拓扑相关） | 烧录在网卡 ROM 中，设备移动不变 |

> **为什么不能只用一种地址？**
> 1. **不能只用 MAC 地址**：MAC 地址是扁平无层次的，若因特网路由器直接用 MAC 选路，路由器必须记录全球数亿块网卡的路由表，根本无法实现路由聚合；
> 2. **不能只用 IP 地址**：世界上存在大量异构局域网，局域网芯片出厂时完全独立于 IP 协议，依赖硬件地址才能进行多路争用与接收过滤。

## 二、分组转发过程中的地址变化规律（最核心必考规律）

当主机 A 经过若干台路由器转发将数据报发送给主机 B 时，各层首部中的源地址与目的地址遵循严格的变化法则：

```text
主机 A (源) --------[ 路由器 R1 ]--------[ 路由器 R2 ]-------- 主机 B (目的)
        (链路 1)                 (链路 2)                 (链路 3)
```

```text
+-------------------------------------------------------------------------------+
|  网络层 IP 首部:                                                               |
|  - 源 IP 地址: 始终是 主机 A 的 IP (不变!)                                      |
|  - 目的 IP 地址: 始终是 主机 B 的 IP (不变!)                                    |
|  *(端到端传输中，除经过 NAT 转换外，IP 首部源/目的地址自始至终绝对保持不变)*  |
+-------------------------------------------------------------------------------+
                                      |
                                      v
+-------------------------------------------------------------------------------+
|  数据链路层 MAC 帧头:                                                          |
|  - 链路 1: 源 MAC = MAC_A,          目的 MAC = MAC_R1_in                       |
|  - 链路 2: 源 MAC = MAC_R1_out,     目的 MAC = MAC_R2_in                       |
|  - 链路 3: 源 MAC = MAC_R2_out,     目的 MAC = MAC_B                           |
|  *(每经过一个路由器/每跨越一段链路，帧头的源 MAC 和目的 MAC 必须完全重新封装改写!)*|
+-------------------------------------------------------------------------------+
```

## 三、网络设备对两类地址的感知层级

- **集线器 (Hub)**：物理层设备，对 MAC 和 IP 毫无感知；
- **交换机 (Switch)**：数据链路层设备，只读取 MAC 帧头，不解封装、不查看 IP 首部；
- **路由器 (Router)**：网络层设备，剥离链路层 MAC 帧头，读取 IP 首部的目的 IP 进行查表转发，并重新封装下一跳 MAC 帧头。
