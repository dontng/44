# 4.2.4 IPv4 地址与 MAC 地址

在 TCP/IP 体系中，网络层使用 IP 地址（逻辑地址），数据链路层使用 MAC 地址（硬件物理地址）。深入理解这两类地址的协同工作机制，是掌握网络层分组端到端传输的关键。

---

## 一、为什么需要同时存在 IP 地址与 MAC 地址？

### 1. 两类地址的根本分工差异
- **IP 地址（网络层逻辑地址）**：
  - 由网络管理员配置或 DHCP 动态分配；
  - 具有层次结构（网络前缀 + 主机号）；
  - **核心功能**：负责宏观选路。指示数据报端到端（End-to-End）传输的起点和终点，供网络中的路由器进行全局路径规划和路由聚合。
- **MAC 地址（数据链路层物理地址）**：
  - 由网卡生产厂商固化在硬件芯片中；
  - 采用 48 位扁平结构，无地理拓扑层次性；
  - **核心功能**：负责微观传输。指示数据帧在单段链路（Hop-by-Hop）上直接相邻的物理设备之间的传输。

```
+---------------------------------------------------------------------------------------------------+
|  IP 地址 (网络层 L3):  端到端寻址 (End-to-End)，全局有效，标识最终通信源与目的端系统               |
+---------------------------------------------------------------------------------------------------+
                                                  |
                                                  v
+---------------------------------------------------------------------------------------------------+
|  MAC 地址 (链路层 L2): 单跳寻址 (Hop-by-Hop)，局域网内部有效，标识当前物理信道的直接收发接口      |
+---------------------------------------------------------------------------------------------------+
```

### 2. 双重地址体系的必要性
1. **屏蔽底层异构物理网络**：世界上存在多种不同的链路层协议（如以太网、Wi-Fi、PPP 等），有的使用 48 位 MAC 地址，有的不使用 MAC 地址。如果在网络层直接使用 MAC 地址，网络层将与底层特定硬件强行绑定，无法实现异构互联；
2. **避免全球路由表崩溃**：若直接基于无拓扑层次的扁平 MAC 地址进行全球路由，全球路由器将必须记录每一张网卡的表项，导致路由表规模膨胀到无法承载的程度。

## 二、多跳传输中 IP 地址与 MAC 地址的演变规律

当主机 H1 通过多台路由器向处于不同网络的远程主机 H2 发送数据报时，两类地址在传输过程中表现出严格的演变规律：

```
[ 源主机 H1 ] =========(链路 1)=========> [ 路由器 R1 ] =========(链路 2)=========> [ 目的主机 H2 ]
+------------+                            +---------+---------+                            +------------+
| 网络层 IP  |                            |     网络层 IP     |                            | 网络层 IP  |
+------------+                            +---------+---------+                            +------------+
| 链路层 MAC |                            | 链路MAC | 链路MAC |                            | 链路层 MAC |
+------+-----+                            +----+----+----+----+                            +------+-----+
       |                                       |         |                                        |
       v (帧 1)                                v         v (帧 2)                                 v
[ 目的MAC: MAC_R1_in  ]                   [ 剥除帧1] [ 封装帧2 ]                     [ 目的MAC: MAC_H2     ]
[ 源 MAC : MAC_H1     ]                   [ 查路由表]                                [ 源 MAC : MAC_R1_out ]
[ 目的 IP: IP_H2      ] -----------------------------------------------------------> [ 目的 IP: IP_H2     ] (保持不变)
[ 源  IP : IP_H1      ] -----------------------------------------------------------> [ 源  IP : IP_H1     ] (保持不变)
```

### 1. IP 首部中 IP 地址的“端到端恒定”
在无网络地址转换（NAT）的常规网络中：
- **源 IP 地址**：始终是最初发起传输的源主机 IP 地址（`IP_H1`）；
- **目的 IP 地址**：始终是最终接收数据的目的主机 IP 地址（`IP_H2`）；
- 无论数据报经过多少台中间路由器的逐跳转发，**IP 首部中的源 IP 和目的 IP 保持严格不变**。
- *(伴随变化：路由器转发时，IP 首部的生存时间 TTL 字段逐跳减 1，首部校验和字段重新计算)*。

### 2. 链路层首部中 MAC 地址的“逐跳改变”
- 数据链路层的 MAC 帧只在单段物理链路或单个广播域内部有效；
- 数据帧到达路由器后，路由器硬件剥离该帧的链路层首部和尾部，提取出 IP 数据报；
- 路由器根据目的 IP 查表选路后，在输出接口上为该 IP 数据报**重新封装全新的链路层首部**：
  - **源 MAC 地址**：更新为**当前转发路由器出接口的 MAC 地址**；
  - **目的 MAC 地址**：更新为**下一跳紧邻设备（下一跳路由器或目的主机）入接口的 MAC 地址**。

## 三、网络设备对两类地址的处理层级

不同网络设备根据其工作层次，对数据单元的首部有着不同的解析能力：

1. **集线器 / 中继器（物理层设备）**：
   - 仅对信号进行放大和整形，不解析任何数据帧首部；
   - 无法感知 MAC 地址和 IP 地址。
2. **以太网交换机（数据链路层设备）**：
   - 解析数据链路层的 MAC 帧首部；
   - 根据源 MAC 地址学习转发表，根据目的 MAC 地址进行查表转发；
   - 不解封装数据载荷，**无法感知网络层的 IP 地址**。
3. **路由器（网络层设备）**：
   - 解析数据链路层首部以接收数据帧；
   - 解封装并解析网络层的 IP 数据报首部，依据目的 IP 地址查询路由表进行选路；
   - 重新封装新的链路层首部后转发出去。
