# 4.1 网络层概述

网络层（Network Layer）是计算机网络体系结构中的关键层次。网络层向上为传输层提供服务，向下依赖数据链路层提供的单段链路帧传输能力。网络层的核心任务是**实现主机到主机（Host-to-Host）的端到端分组传输**。

---

## 一、网络层向上提供的两种服务：虚电路服务与数据报服务

在计算机网络发展史上，关于网络层应当向运输层提供“可靠的面向连接的服务”还是“不可靠的无连接服务”，曾有过长期的争论。这代表了电信网络与计算机网络两种完全不同的设计哲学。

```
1. 电信网设计思路 (虚电路服务 Virtual Circuit, VC):
   [源主机] ---呼叫建立---> (节点 A) ------> (节点 B) ---呼叫接受---> [目的主机]
   - 核心思想：端系统终端简单，网络核心（交换机/路由器）负责可靠传输与资源预留。

2. 因特网设计思路 (数据报服务 Datagram):
   [源主机] ---独立发送分组---> (节点 A) ------> (节点 B) ---独立到达---> [目的主机]
   - 核心思想：端系统具备强大的计算处理能力，网络核心保持极致简单，向上仅提供无连接的、尽最大努力交付的数据报服务。
```

### 1. 虚电路服务（Virtual Circuit）
- **通信过程**：通信双方在传输数据之前，必须先建立虚电路连接（经历建立连接、数据传输、拆除连接三个阶段）；
- **寻址方式**：仅在建立连接阶段需要使用全网唯一的主机网络地址。连接建立后，每个分组只需要携带一条极短的**虚电路编号（VC ID）**，以减小报头开销；
- **传输路径与顺序**：属于同一条虚电路的所有分组，都沿着预先建立好的同一条物理路径依次传送，保证分组严格按序到达目的端；
- **网络状态与故障影响**：沿途所有的路由器都必须维护虚电路状态表。一旦网络中某个路由器或某条链路发生故障，所有经过该故障点的虚电路将全部中断，必须重新建立连接；
- **代表技术**：早期的 X.25、帧中继（Frame Relay）以及 ATM 网络。

### 2. 数据报服务（Datagram）
- **通信过程**：**不需要预先建立连接**。每个分组（在网络层称为数据报，Datagram）独立发送，随时可以注入网络；
- **寻址方式**：**每个数据报的首部必须携带完整的源 IP 地址和目的 IP 地址**；
- **传输路径与顺序**：每个数据报在路由器处独立查表选路。先后发送的各个数据报可能经过完全不同的物理路径到达目的地，因此**可能出现乱序、重复甚至丢失**；
- **网络状态与故障影响**：路由器不维护端到端的连接状态（即网络核心是无状态的 Stateless）。当某个中间节点发生故障时，路由协议能够动态感知拓扑变化并自动重新计算路径，后续数据报可动态绕开故障节点；
- **代表技术**：TCP/IP 体系中的网际协议（IP 协议）。

### 3. 虚电路服务与数据报服务对比表

| 对比维度 | 虚电路服务 (Virtual Circuit) | 数据报服务 (Datagram / 因特网采用) |
| :--- | :--- | :--- |
| **连接建立** | **必须建立**（建立、传输、释放三阶段） | **不需要建立连接** |
| **终点地址标识** | 仅连接建立时使用完整地址，传输时仅携带**虚电路号** | **每个分组必须携带完整的源与目的 IP 地址** |
| **分组传送路径** | 同一连接的所有分组沿**同一预定固定路径**传送 | 每个分组独立查表选路，路径可能各不相同 |
| **到达顺序与可靠性** | **严格按序到达**，网络核心负责差错与流量控制 | **尽最大努力交付**（可能乱序、丢失、重复） |
| **端系统与网络分工** | 智能网络核心，哑终端（电信思维） | **简单网络核心，智能端系统**（由传输层 TCP 保证可靠性） |
| **中间节点故障影响** | 经过故障节点的虚电路全部瘫痪中断 | 路由协议动态重新计算选路，后续分组自动绕开故障 |
| **节点状态开销** | 路由器必须维护海量虚电路状态表 | 路由器**无连接状态**，查表转发效率高 |

## 二、网络层的两个核心功能：数据平面（转发）与控制平面（路由）

现代网络体系结构将网络层的功能清晰划分为微观的“转发”与宏观的“路由”：

```
                      +---------------------------------------+
                      |       控制平面 (Control Plane)        |
                      |  - 运行 OSPF, RIP, BGP 等路由协议     |
                      |  - 计算并生成全局【路由表 (Routing Table)】|
                      +-------------------+-------------------+
                                          | 下发
                                          v
                      +---------------------------------------+
                      |        数据平面 (Data Plane)          |
                      |  - 维护由硬件直接执行的【转发表】     |
                      |  - 执行微观单分组查表与端口转发       |
                      +---------------------------------------+
```

### 1. 转发（Forwarding / 数据平面）
- **定义**：当一个分组到达路由器的某条输入链路时，路由器将其搬移到合适的输出链路的本地动作；
- **特点**：发生在微观的单个路由器内部，通常由硬件芯片根据转发表在微秒甚至纳秒级别完成。

### 2. 路由选择（Routing / 控制平面）
- **定义**：全网范围内的协同过程，通过运行特定的路由选择算法（如链路状态算法、距离-向量算法），决定分组从源节点到目的节点所经过的端到端最佳路径；
- **特点**：属于宏观的网络范围控制过程，通常由路由协议在路由器的软件层面周期性或事件驱动地计算，并生成路由表，随后转换为转发表下发给数据平面。

## 三、网络层核心协议体系与封装关系

在 TCP/IP 体系中，网络层由网际协议 IP 及其配套的控制管理协议组成：

```
+-------------------------------------------------------------------------------+
|  网络层辅助控制协议:                                                          |
|  - ICMP (网际控制报文协议, 用于差错报告及网络探活 Ping)  ===> 封装在 IP 数据报中  |
|  - IGMP (网际组管理协议, 用于组播组成员管理)           ===> 封装在 IP 数据报中  |
+-------------------------------------------------------------------------------+
|  路由协议:                                                                    |
|  - RIP (基于距离-向量算法, 封装在 UDP 报文中, 端口 520)                        |
|  - OSPF (基于链路状态算法, 直接封装在 IP 数据报中, 协议号 89)                  |
|  - BGP (基于路径-向量算法, 封装在 TCP 报文中, 端口 179)                        |
+-------------------------------------------------------------------------------+
                                      |
                                      v
+-------------------------------------------------------------------------------+
|  【核心协议】：网际协议 IP (IPv4 / IPv6)                                      |
|  - 向上屏蔽底层异构物理网络差异，提供统一编址与不可靠无连接数据报传输        |
|  - 向下配合 ARP (地址解析协议, 封装在数据链路层 MAC 帧中) 实现 IP 到 MAC 映射 |
+-------------------------------------------------------------------------------+
```

### 关键协议的封装归属：
- **ARP（地址解析协议）**：工作在数据链路层与网络层之间，报文直接封装在数据链路层的 MAC 帧中传送（以太网帧类型为 `0x0806`）；
- **IP（网际协议）**：网络层的核心协议，报文直接封装在数据链路层 MAC 帧的数据载荷中（以太网帧类型为 `0x0800`）；
- **ICMP 与 IGMP**：逻辑上属于网络层协议，但在报文封装上**直接作为 IP 数据报的数据部分进行封装**（IP 首部中的协议字段分别对应 1 和 2）；
- **OSPF 路由协议**：直接封装在 IP 数据报中（协议字段为 89）；
- **RIP 路由协议**：封装在传输层的 UDP 用户数据报中（端口 520）；
- **BGP 路由协议**：封装在传输层的 TCP 报文段中（端口 179）。
