# 4.8 移动 IP 技术概述

移动 IP（Mobile IP，RFC 3344）是一项允许移动节点（如笔记本电脑、车载终端）在互联网中自由跨网段移动时，**保持其原有的 IP 地址不变，从而维持正在进行的网络层及传输层连接（如 TCP 连接）不中断**的技术。

---

## 一、为什么需要移动 IP？

在传统的 TCP/IP 体系中，IP 地址具有双重属性：
1. **身份标识符**：传输层的 TCP 连接以套接字（源 IP、源端口、目的 IP、目的端口）作为连接的唯一标识；
2. **位置定位符**：网络层的路由器依据 IP 地址的网络前缀进行路由转发。

当移动终端从一个物理网络移动到另一个网络时：
- 若修改自身的 IP 地址：传输层的原有 TCP 连接会因 IP 地址改变而**立刻中断**；
- 若不修改自身的 IP 地址：外部网络发送给该终端的数据报仍会被路由到原来的归属网络，移动终端在外地无法接收到数据；
- **移动 IP 的解决思想**：将主机的身份标识与拓扑物理位置解耦。移动终端在对外通信时始终使用固定的**永久主地址（维持连接）**，而在底层通过动态获取的**转交地址（反映当前物理位置）**及**隧道技术**实现数据报的重定向。

---

## 二、移动 IP 的三大实体与双重地址

```
       【归属网络 / 家乡网络 (Home Network)】                 【外地网络 / 拜访网络 (Foreign Network)】
       +------------------------------------+             +------------------------------------+
       |  归属代理 HA (Home Agent)          |             |  外地代理 FA (Foreign Agent)       |
       |  (家乡路由器，负责捕获并转交报文)    |             |  (外地路由器，负责协助注册并拆包)  |
       |                                    |             |                                    |
       |  移动节点 MN 的永久属地            |             |  移动节点 MN 当前漫游所在的新网段  |
       +------------------------------------+             +------------------------------------+
```

### 1. 三大网络实体
1. **移动节点（MN，Mobile Node）**：具备漫游通信能力的移动终端设备；
2. **归属代理（HA，Home Agent / 家乡代理）**：位于移动节点归属网络中的一台路由器。当移动节点离开归属网络时，归属代理负责捕获所有发往该移动节点的数据报，并经由隧道中继转交给移动节点；
3. **外地代理（FA，Foreign Agent / 拜访代理）**：位于移动节点当前接入的外地网络中的一台路由器。负责向移动节点提供转交地址，协助移动节点向归属代理注册，并接收来自归属代理的隧道数据报并交付给移动节点。

### 2. 双重地址体系
- **永久主地址（Home Address）**：
  - 移动节点在其归属网络中分配到的固定的、长期的 IP 地址；
  - 无论移动节点漫游至何处，其主地址保持不变，上层应用程序始终以此地址作为通信身份；
- **转交地址（CoA，Care-of Address）**：
  - 移动节点漫游接入外地网络时获取到的临时 IP 地址，反映了移动节点当前所处的实际拓扑位置；
  - 最常见的是**外地代理转交地址**（即外地代理 FA 接口的 IP 地址）。

## 三、移动 IP 的通信过程

```
【阶段 1: 移动感知与注册】
   移动节点 MN ─────────────> 监听 FA 发出的代理通告报文 (获取转交地址 CoA)
        │
        ├─ 1. 发送注册请求 (Registration Request) ────────> [外地代理 FA]
        │                                                          │
        │                                                          ├─ 2. 转发注册请求 ───> [归属代理 HA]
        │                                                          │                        │ (建立绑定缓存:
        │                                                          │<── 3. 返回注册应答 ────┤  主地址 -> CoA)
        │<─ 4. 交付注册应答 ───────────────────────────────────────┤
        ▼ (注册成功，建立转发隧道)

【阶段 2: 数据通信与中继转发】
[通信对端 CN]
     │
     ├─ 1. 发送数据报 (源 IP: CN, 目的 IP: MN永久主地址)
     │     (因特网路由器按常规单播路由将数据报路由至 MN 的归属网络)
     ▼
[归属代理 HA 拦截]
     │
     ├─ 2. 【IP 隧道封装】:
     │     - 外层 IP 首部: 源 IP = HA, 目的 IP = CoA (FA 的 IP)
     │     - 内层原始数据报: 源 IP = CN, 目的 IP = MN永久主地址 (保持不变)
     ▼ (跨越因特网隧道传送)
[外地代理 FA 接收]
     │
     ├─ 3. 剥除外层 IP 首部，还原原始 IP 数据报，交付给 MN
     ▼
[移动节点 MN 收到数据]
     │
     └─ 4. MN 发送响应数据报给通信对端 CN:
           - 源 IP = MN永久主地址 (必须填主地址，以维持 TCP 连接)
           - 目的 IP = CN
           (沿最优单播路径直接发送给 CN，【不经过归属代理 HA】)
           ▼
     [通信对端 CN 接收响应]
```

## 四、三角路由问题及其优化

### 1. 三角路由问题（Triangle Routing）
在移动 IP 的基本模式中，数据的收发路径呈现非对称的“三角形”结构：
- **从通信对端 CN 到移动节点 MN（入站）**：必须先绕经归属代理 HA，再由 HA 经隧道转发至外地代理 FA，产生了迂回绕路时延；
- **从移动节点 MN 到通信对端 CN（出站）**：MN 直接通过外地代理向 CN 发送单播数据报，无需经过 HA。

### 2. 路由优化机制
- 归属代理 HA 在收到通信对端 CN 发送的第一个数据报后，向 CN 发送绑定更新报文，告知 CN 移动节点当前的转交地址 CoA；
- 通信对端 CN 在本地缓存该绑定关系后，后续发送的数据报直接由 CN 封装隧道发送给转交地址 CoA，避免了绕道归属代理 HA，消除了三角路由。
