# 4.2+4.2.1 网际协议 IP 和异构网络互连

现实世界中存在着种类繁多的物理网络（如以太网、Wi-Fi 无线局域网、点对点专线、移动通信蜂窝网络等）。由于不同的物理网络在传输介质、寻址方案、数据帧格式以及最大传输单元（MTU）上存在巨大差异，如何将这些“异构网络”连接成一个统一的通信体系，是计算机网络的核心课题。

---

## 一、为什么需要异构网络互连？

### 1. 异构网络的客观必然性
不同的应用场景对通信网络的物理特性有着相互矛盾的要求：
- **局域办公网**：要求布线成本低、带宽高、传输距离短（小于 100 米），广泛采用以太网双绞线；
- **移动通信网**：要求终端支持自由移动和无线电波空间传输，采用蜂窝无线网或 IEEE 802.11 Wi-Fi；
- **远程骨干网**：要求跨越数百至数千公里的大容量传输，采用光纤密集波分复用及点对点专线。

世界上不可能存在某一种单一的物理网络能够同时满足所有场景的工程需求。因此，网络的多样性与异构性是客观存在的。

### 2. 异构网络之间的主要物理与链路层差异
当尝试直接连通两个异构物理网络时，面临以下根本性差异：
1. **物理寻址方案不同**：以太网和 Wi-Fi 使用 48 位的 IEEE 802 MAC 地址；点对点链路（如 PPP 协议）不需要物理 MAC 寻址；一些广域网技术采用层次化电话号码形式的地址；
2. **数据链路层帧格式不同**：以太网 V2 帧头为 14 字节；802.11 帧头最长可达 30 字节；PPP 帧首部采用固定的 5 字节结构；
3. **最大传输单元（MTU）不同**：以太网的标准 MTU 为 1500 字节；802.11 的理论 MTU 可达 2312 字节；某些点对点专线的 MTU 可能仅为数百字节；
4. **服务质量与时钟速率不同**：光纤专线误码率极低，而无线信道存在高衰减与多径时延扩展。

## 二、虚拟互联网络（Virtual IP Network）与沙漏模型

### 1. 虚拟互联网络的设计理念
面对异构网络的差异，因特网采用了**“沙漏模型（Hourglass Model）”**：在各种多样的物理网络之上，抽象出一个统一的、虚拟的网络层协议——**网际协议 IP（Internet Protocol）**。

```
                     +---------------------------------------+
                     |  应用层 (HTTP, DNS, SMTP, FTP...)     |
                     +---------------------------------------+
                     |  传输层 (TCP, UDP)                    |
                     +-------------------+-------------------+
                                         |
                                         v
                     +=======================================+
                     |      【核心枢纽】：网际协议 IP        |  <=== 统一所有网络数据流
                     +=======================================+
                                         |
                                         v
                     +-------------------+-------------------+
                     |  异构链路层 (以太网, Wi-Fi, PPP, 蜂窝)|
                     +---------------------------------------+
                     |  异构物理层 (双绞线, 光纤, 无线电波)  |
                     +---------------------------------------+
```

- **屏蔽物理差异**：通过在所有互联的主机和路由器上运行 IP 协议，使原本在物理上完全异构的各种网络，在网络层逻辑上表现为一个**平坦、统一、同构的虚拟互联网络（Virtual IP Network）**；
- 无论底层采用何种链路层技术，上层应用程序看到的都是统一格式的 IP 数据报和统一的 IP 地址空间。

---

## 三、网络互连设备与分层边界

根据互联设备工作的最高协议层次，通常将网络互连设备划分为四类：

| 设备名称 | 工作层次 | 隔离冲突域？ | 隔离广播域？ | 能否互联异构数据链路层？ | 核心功能与工作机制 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **中继器 / 集线器** | **物理层 (L1)** | **否** | **否** | **否** | 仅对衰减的电信号或光信号进行整形放大；两端连接的介质类型、传输速率和协议必须严格一致。 |
| **网桥 / 交换机** | **数据链路层 (L2)** | **能** | **否** | **局限** | 依据 MAC 地址进行过滤与转发；可互联不同传输速率或介质的网段（如 10M 双绞线与 100M 光纤），**但两端必须属于同一种局域网链路层协议（以太网）**。无法直接将以太网互联到 PPP 专线。 |
| **路由器 (Router)** | **网络层 (L3)** | **能** | **能** | **完全支持** | **互连异构网络的核心设备**。依据 IP 地址进行路由与转发。支持输入端口为以太网、输出端口为 PPP 或 Wi-Fi 等任意异构链路层协议。 |
| **网关 (Gateway)** | **传输层及以上 (L4~L7)**| **能** | **能** | **完全支持** | 通常指应用层网关。负责在两个不同高层协议栈之间进行语法和语义转换（如邮件网关、协议代理）。 |

## 四、路由器互联异构网络的工作机制

当一个 IP 数据报从源主机出发，经过路由器跨越异构链路传送到目的主机时，路由器通过**解封装与重封装**实现链路层异构转换：

```
[ 主机 A (以太网) ] ==============> [ 路由器 R ] ==============> [ 主机 B (PPP 链路) ]
+-----------------+                 +-----------------+          +-----------------+
|   网络层 IP     |                 |   网络层 IP     |          |   网络层 IP     |
+-----------------+                 +--------+--------+          +-----------------+
|  数据链路层 MAC |                 | 链路MAC|链路PPP |          |  数据链路层 PPP |
+--------+--------+                 +---+----+----+---+          +--------+--------+
         | (以太网 MAC 帧)               |         | (PPP 帧)             |
         +===============================+         +======================+
```

### 1. 入端口解封装（Decapsulation）
- 路由器 R 的以太网接口接收到物理信号并验证 FCS 校验和；
- 剥除以太网帧首部（目的 MAC、源 MAC、类型）和尾部校验和；
- 提取出承载的原始 IP 数据报，将其交付给网络层进行处理。

### 2. 查表与选路（Forwarding）
- 路由器检查 IP 首部，执行生存时间 TTL 减 1 动作，并重新计算 IP 首部校验和；
- 提取目的 IP 地址，在路由表/转发表中检索下一跳，确定该数据报应由连接 PPP 链路的输出端口发出；
- 若 IP 数据报总长度超过出接口链路的 MTU，且禁止分片标志未置位，路由器将负责对 IP 数据报执行分片操作。

### 3. 出端口重封装（Re-encapsulation）
- 路由器出接口将（分片后的）IP 数据报放入 PPP 协议的发送队列；
- 为其封装全新的 PPP 帧首部（标志字段 `0x7E`、地址 `0xFF`、控制 `0x03`、协议 `0x0021`）并追加 PPP 校验和；
- 将新的 PPP 帧推送到物理信道发出。

### 4. 传输过程中的“变”与“不变”
- **不变的部分**：在常规无 NAT 的端到端转发过程中，**IP 数据报首部的源 IP 地址与目的 IP 地址在全程跳跃中保持不变**；
- **变化的部分**：
  - 数据链路层的帧格式、帧首部、源硬件地址和目的硬件地址**在每一跳都在发生改变**（在以太网链路填充具体网卡的 MAC，在 PPP 链路则无 MAC 概念）；
  - IP 数据报首部中的 **TTL 字段每经过一台路由器都减 1**，相应的 **首部校验和（Checksum）也必须重新计算更新**。
