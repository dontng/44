# 4.4.3 路由信息协议RIP

**路由信息协议（Routing Information Protocol，RIP）** 是因特网自治系统内部最早广泛使用的**内部网关协议（IGP）**，基于经典的 **距离向量（Distance Vector, DV）算法**。

---

## 一、RIP 协议的核心规则与特征

1. **协议层次归属**：RIP 是应用层协议，**使用 UDP 传送，熟知端口号为 520**。
2. **度量标准（Metric / 距离）**：
   - 纯粹以**跳数（Hop Count）**作为代价度量。
   - 路由器到直接相连网络的距离定义为 **1**（有些教材定义为 0，408 统考统一以到直连网络为 1 为准）。
   - 每经过一个路由器，跳数加 1。
   - **最大跳数限制**：RIP 规定距离的最大有效值为 **15**，**距离为 16 即表示网络不可达（无穷大）**。这限制了 RIP 只能适用于小型网络。
3. **周期性通告**：
   - 仅与**相邻路由器**交换信息。
   - 交换的是自己**当前的整个路由表**。
   - **固定周期性交换**（默认每隔 **30 秒** 发送一次完整更新）。

---

## 二、距离向量路由表的更新算法（Bellman-Ford 算法）

假设路由器 X 收到相邻路由器 Y 发来的路由更新报文（载有 Y 到各网络的距离）：

```
+-------------------------------------------------------------------------------+
| 步骤 1: 修正接收报文                                                          |
| 将收到的报文中所有条目的【距离加 1】，并将【下一跳路由器均改为 Y】。           |
+-------------------------------------------------------------------------------+
                                       |
                                       v
+-------------------------------------------------------------------------------+
| 步骤 2: 逐条比对本地路由表并更新                                              |
| 对修正后的每一条路由 <目的网络 Net, 距离 d, 下一跳 Y> 进行研判:               |
|                                                                               |
| - 若本地【无 Net 条目】: 直接将该新路由添加进本地路由表!                      |
|                                                                               |
| - 若本地【已有 Net 条目，且下一跳正是 Y】:                                    |
|   无论 d 变大还是变小，无条件用新距离覆盖更新! (说明最新路况来自 Y，必须信任) |
|                                                                               |
| - 若本地【已有 Net 条目，但下一跳是其他路由器 Z】:                            |
|   若新距离 d < 本地原距离: 择优录取! 更新距离为 d，下一跳改为 Y;               |
|   否则保留原路由，忽略该条目。                                                |
+-------------------------------------------------------------------------------+
                                       |
                                       v
+-------------------------------------------------------------------------------+
| 步骤 3: 超时处理                                                              |
| 若某相邻路由超过 180 秒未收到更新，标记为不可达 (距离设为 16)。               |
+-------------------------------------------------------------------------------+
```

---

## 三、RIP 协议的致命缺陷：“好消息传得快，坏消息传得慢”

也称**路由环路与计数到无穷问题（Count to Infinity）**。

### 产生根源场景演示
1. 路由器 R1 直连网络 N1 断开故障。R1 立即将 N1 置为不可达（距离 16）。
2. 但在 R1 发出通告之前，相邻的 R2 刚好发来了原本的周期更新：“我到 N1 距离为 2，下一跳 R1”。
3. R1 误以为 R2 还有另一条去往 N1 的路，于是修改自身：“到 N1 距离 $2+1=3$，下一跳 R2”！
4. 紧接着 R2 又收到 R1 的更新，修改为：“到 N1 距离 $3+1=4$，下一跳 R1”……
5. 两个路由器相互欺骗递增，直到**跳数慢慢累加到 16**，双方才最终确认 N1 彻底不可达。这期间产生了严重的通信环路。

### 防范策略（缓解措施，不能完全根除）
- **限制最大跳数为 15**（减小计数到无穷的时间）。
- **水平分割（Split Horizon）**：从一个接口学到的路由，绝不向该接口反向通告回去。
- **毒性逆转（Poison Reverse）**：从某接口学到的路由，向该接口反向通告时将距离直接标记为 16（不可达）。
- **触发更新（Triggered Update）**：一旦网络拓扑发生变化，立即发送更新报文，无需干等 30 秒周期计时。
