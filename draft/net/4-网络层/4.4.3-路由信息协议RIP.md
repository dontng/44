# 4.4.3 路由信息协议 RIP

路由信息协议（RIP，Routing Information Protocol）是内部网关协议（IGP）中最先得到广泛应用的经典协议。它基于分布式的**距离向量（Distance Vector）**路由选择算法。

---

## 一、RIP 协议的基本概念与运行规则

### 1. 协议的核心属性与约束
- **协议层次与报文封装**：RIP 是一个**应用层协议**，其控制报文直接封装在传输层的 **UDP** 用户数据报中传送，熟知端口号为 **520**；
- **度量标准（Metric）**：
  - RIP 纯粹以**跳数（Hop Count）**作为衡量路径好坏的唯一代价；
  - 路由器到直接相连的网络的跳数定义为 1；每经过一台外部路由器，跳数加 1；
  - RIP 不考虑物理链路的带宽、时延、误码率和信道负荷；
- **最大跳数限制**：
  - RIP 规定最大有效跳数为 **15**；
  - **跳数达到 16 即表示距离无穷大，代表目的网络不可达**；
  - 该规定限制了 RIP 只能应用于网络直径不超过 15 的小型互联网中；
- **信息交换的三个核心要素**：
  1. **和谁交换**：仅与**直接相连的相邻路由器**交换信息；
  2. **交换什么**：交换本路由器**当前的整张路由表**；
  3. **何时交换**：**固定周期性交换**（默认每隔 30 秒广播一次路由更新报文）；
- **老化与超时机制**：若某路由器超过 180 秒未收到相邻路由器发来的更新报文，则判定该邻居故障失效，并将经过该邻居的所有路由条目的距离标记为 16（不可达）。

---

## 二、距离向量路由更新算法（Bellman-Ford 算法）

当路由器 $X$ 收到相邻路由器 $Y$ 发送来的 RIP 路由更新报文时，按照以下两阶段步骤进行路由表的维护与更新：

```
[ 接收到相邻路由器 Y 发送来的路由表 ]
                  │
                  ▼
【阶段 1: 预处理修正】
   将收到的所有路由条目:
   - 距离数值统一加 1 (d = d + 1)
   - 下一跳地址统一强制修改为发信邻居 Y
                  │
                  ▼
【阶段 2: 逐条与本地路由表比对更新】
   对修正后的每个条目 <Net, d, Y>，检索本地路由表中是否存在目的网络 Net:
                  │
                  ├─ 规则 1: 本地路由表中【不存在目的网络 Net】
                  │          └──> 直接作为新路由无条件添加进本地路由表！
                  │
                  ├─ 规则 2: 本地【已有网络 Net，且原记录的下一跳正是 Y】
                  │          └──> 无条件用新收到的距离 d 覆盖本地原条目！
                  │               (无论新距离变大还是变小，都必须服从负责该路径的邻居 Y 的最新状态)
                  │
                  └─ 规则 3: 本地【已有网络 Net，但原记录的下一跳是其他路由器 Z】
                             │
                             ├─ 若修正后新距离 d < 本地原距离:
                             │   └──> 择优更新！将本地条目的距离改为 d，下一跳改为 Y。
                             │
                             └─ 若修正后新距离 d >= 本地原距离:
                                 └──> 忽略，保持本地原条目不变。
```

## 三、“好消息传得快，坏消息传得慢”（计数到无穷问题）

由于距离向量算法依赖于相邻节点之间的“间接传闻”，缺乏全网全局拓扑视野，导致其存在一个致命缺陷：**好消息传得快，坏消息传得慢**。

### 1. 产生环路与计数到无穷的过程分析
设某网络拓扑为：`网络 N1 ── 路由器 R1 ── 路由器 R2`。正常状态下：
- R1 到 N1：距离为 1，直接交付；
- R2 到 N1：距离为 2，下一跳为 R1。

```
时间 T0: 链路故障发生
         - 网络 N1 发生物理断开；
         - R1 检测到链路中断，将 N1 的距离置为 16 (不可达)；
         - 但在 R1 发出更新之前，R2 的 30 秒周期定时器恰好到期，R2 向 R1 发出自己的路由表：
           “我到 N1 距离为 2，下一跳为 R1”。

时间 T1: R1 误判与环路形成
         - R1 收到 R2 的报文，预处理后为：到 N1 距离为 2 + 1 = 3，下一跳为 R2；
         - R1 查本地路由表，N1 原为 16；因为 3 < 16，R1 误以为 R2 找到了一条绕道到达 N1 的新路径；
         - R1 更新自身路由表为：到 N1 距离为 3，下一跳为 R2。

时间 T2: 相互欺骗与递增
         - R1 发出更新报文通告自身路由表；
         - R2 收到 R1 的报文：到 N1 距离为 3；预处理后为：距离为 4，下一跳为 R1；
         - R2 查本地，到 N1 的下一跳原本就是 R1，按照规则无条件覆盖，更新为：距离为 4，下一跳为 R1；
         - 随后 R1 与 R2 之间不断相互通告，跳数持续递增（5, 6, 7...），直至累加到 16 时双方才最终断定不可达。
```
- 在整个跳数累加递增期间，如果有发往 N1 的数据报到达，将在 R1 与 R2 之间无限来回弹跳，直到 TTL 耗尽，造成严重的**路由环路**。

### 2. 缓解环路问题的四项技术机制

| 机制名称 | 原理与工作规则 | 作用 |
| :--- | :--- | :--- |
| **定义最大度量值（16 为不可达）** | 规定跳数达到 16 即为不可达。 | 限制计数到无穷的过程在 16 次以内必须终止，防止死锁无休止持续。 |
| **水平分割（Split Horizon）** | **从一个接口学到的路由信息，绝对不再从该接口反向通告回去**。 | 在上述拓扑中，R2 从 R1 处学到了关于 N1 的路由，则 R2 向 R1 发出的更新中禁止包含 N1，直接阻断互相欺骗。 |
| **毒性逆转（Poison Reverse）** | 允许将从某接口学到的路由反向通告回去，但**将其距离强制标记为 16（不可达）**。 | 明确告知对端“不要试图通过我来绕道回到你教给我的网络”。 |
| **触发更新（Triggered Update）** | 当路由器检测到网络拓扑发生变动时，**不必等待 30 秒周期定时器**，立即向前发送更新报文。 | 加快故障信息的全网扩散速度，降低陈旧信息冲突的概率。 |
