# 4.7.4+4.7.5 网际组管理协议 IGMP 与因特网多播体系

在因特网范围内实现端到端的多播通信，必须依赖两种不同功能的协议协同配合：一种负责在**局域网本地**建立和维护组成员关系，另一种负责在**广域网路由器之间**构建多播分发树。

---

## 一、因特网多播体系的两大协议分工

```
[多播源] ======> [多播路由器 R1] ===================> [多播路由器 R2] ======> [接收端主机 H1, H2]
                                 (广域网多播路由协议)                         ^
                                 - 负责构建全局多播分发树                     | (本地局域网: IGMP)
                                 - 决定数据报在路由器间怎么转发                - 探测本网段有无组播成员
```

1. **本地成员感知协议：网际组管理协议（IGMP，Internet Group Management Protocol）**
   - 运行在**主机与本地直接相连的多播路由器之间**；
   - 让多播路由器知道本局域网内是否存在某个多播组的订阅主机。
2. **骨干分发路由协议：多播路由选择协议（如 PIM、MOSPF）**
   - 运行在**多播路由器之间**；
   - 跨越多个自治系统与骨干网络，协同构建无环的多播数据分发树，使多播数据报能够按需转发到有成员的末梢路由器。

---

## 二、网际组管理协议（IGMP）

### 1. 协议层次与报文封装
- **协议层次**：IGMP 属于**网络层协议**；
- **报文封装**：IGMP 报文直接装载在 **IP 数据报的数据部分** 传输：
  - IP 首部的协议字段固定为 **2**；
  - IP 首部的 **TTL 字段严格固定为 1**（IGMP 仅用于本地直连局域网网段内的成员关系同步，路由器绝不向外转发）。

### 2. IGMP 工作的核心指导原则
> **多播路由器不关心具体的成员主机是谁，也不记录加入多播组的主机 IP 地址列表。路由器仅关心：本局域网网段内，是否存在“至少一个”主机属于某个特定的多播组！**

只要本网段内还存在哪怕一台订阅主机，路由器就继续向该局域网转发对应的多播数据流；当网段内所有成员主机全部离开后，路由器才停止转发。

---

## 三、IGMPv2 的核心工作流程

```
       [多播路由器 R]                                  [主机 H1 (属于组 G)]         [主机 H2 (属于组 G)]
             │                                                  │                           │
             │                                                  ├─ 1. 主动加入报告 (Report) │
             │<── 发送 IGMP 成员报告 (Report, 目的 IP: G) ──────┤ (无需等待查询，立刻通告)  │
             │   (R 记录本地存在组 G 成员，开启转发)            │                           │
             │                                                  │                           │
             │=== 2. 周期性常规查询 (默认每 125s) ==============│===========================│
             │─── 发送通用查询报文 (Query, 目的 IP: 224.0.0.1) ─>│                           │
             │                                                  │                           │
             │                                                  │ 【3. 触发响应抑制机制】   │
             │                                                  │ H1 随机计时器: 2 秒       │ H2 随机计时器: 7 秒
             │                                                  │                           │
             │                                                  ├─ 2秒到期! 抢先发 Report! ─┐
             │<── 发送加入报告 (目的 IP: G) ────────────────────┤                           │ (H2 监听到该 Report)
             │   (R 刷新组 G 的老化计时器)                      │                           ▼
             │                                                  │                  【H2 自动抑制并取消自己的报告】
             │                                                  │                  (避免并发风暴)
             │                                                  │                           │
             │=== 4. 离开组机制 (Leave) ========================│===========================│
             │                                                  ├─ H1 退出组 G ─────────────┤
             │<── 发送离开报文 (Leave, 目的 IP: 224.0.0.2) ─────┤                           │
             │                                                  │                           │
             │─── 发送特定组查询 (Group-Specific Query) ───────>│                           │
             │    (询问: 局域网内是否还有组 G 成员?)            │                           │
             │<── H2 立即回复 Report! ──────────────────────────┼───────────────────────────┤
             │   (R 确认仍有成员 H2，继续转发，不切断流)        │                           │
```

### 四大核心交互机制说明：
1. **加入多播组（主动上报）**：
   - 当主机进程加入多播组 G 时，主机**主动向该多播组 G 发送一个 IGMP 成员报告报文（Report）**；
   - 目的 IP 填写该多播组地址 G；本地多播路由器收到后，在转发表中记录该接口存在组 G 成员，开启数据转发；
2. **周期性成员探询（通用查询）**：
   - 路由器每隔一定周期（默认 125 秒）向局域网广播一次 **通用查询报文（General Query）**；
   - 目的 IP 为 **`224.0.0.1`**（代表本网段的所有主机和路由器）；
3. **响应抑制机制（Feedback Suppression）**：
   - 为避免局域网内成百上千台同组主机同时回复导致广播风暴，每台成员主机在收到查询后启动一个随机倒计时定时器；
   - **定时器最先到期的主机抢先发送成员报告报文**；
   - 局域网内的其他同组成员主机监听到该报告后，**自动取消并静默自身即将发送的报告**；
   - 在每个查询周期内，每个多播组在整个局域网上**仅产生 1 个响应报告**；
4. **离开多播组（离开与特定组查询）**：
   - 当主机退出组 G 时，向 **`224.0.0.2`**（本网段所有多播路由器）发送一个 **离开报文（Leave Message）**；
   - 路由器收到后，并不立即停止转发，而是向组 G 发送 **特定组查询报文（Group-Specific Query）**；
   - 若在超时时间内有其他主机响应，路由器继续维持转发；若无人响应，路由器才将该多播组从出接口列表中剪除。
