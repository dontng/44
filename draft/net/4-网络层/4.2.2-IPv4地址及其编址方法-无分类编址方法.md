# 4.2.2 IPv4 地址及其编址方法-无分类编址方法

> **本节在 408 中的定位**：无分类域间路由选择（CIDR，Classless Inter-Domain Routing，RFC 1519）是现代互联网运行的绝对中枢，也是 408 统考综合大题（尤其是结合路由表的转发大题）中最核心的命题刀刃。本节必须彻底掌握**“斜线记法（Slash Notation）与地址块边界计算”**、**“超网聚合（Supernetting / Route Aggregation）的二进制公共前缀提取法”**，以及**“最长前缀匹配原则（Longest Prefix Match）在路由器转发表中的精准判决”**。

---

## 一、第一性原理与设计动因：为什么 CIDR 拯救了 20 世纪 90 年代的因特网？

### 1. 1993 年因特网面临的“近在咫尺的崩溃”
在 1992~1993 年，由于 Web（万维网）的爆发式普及，基于分类编址的因特网遭遇了两大毁灭性打击：
1. **B 类地址空间彻底见底**：全球所有企业争抢 B 类地址，预计在 1994 年底前全部耗尽；
2. **全球骨干网路由器因路由表爆炸而瘫痪**：为了避免申请 B 类，大量企业申请了数十个分散的 C 类地址块，导致全球因特网骨干路由器的路由表条目以指数级速度暴涨，路由器的 CPU 和内存濒临崩溃！

### 2. CIDR 的划时代革命：彻底砸碎 A/B/C 的枷锁
1993 年发布的 RFC 1519（CIDR）做出了一个颠覆性的决策：
- **彻底消灭 A 类、B 类、C 类网络的概念**！
- **彻底消灭“主类网络”与“子网”的区别**！
- **32 位的 IP 地址重新变为平滑的两级结构：网络前缀（Network-Prefix） + 主机号（Host-ID）**；
- 网络前缀的长度 $n$ 可以是 **$1 \sim 32$ 之间的任意整数**！需要 2000 个地址就分配 `/21`，需要 500 个就分配 `/23`，地址分配粒度从粗糙的“大斧头劈柴”精细化为“手术刀雕刻”！

---

## 二、微观结构：CIDR 斜线记法与地址块微观参数

### 1. CIDR 地址表示法
$$\text{CIDR 地址} = \{ <\text{网络前缀 Network-Prefix}>, \; <\text{主机号 Host-ID}> \} / n$$
- **斜线记法（Slash Notation）**：在点分十进制 IP 地址后追加 `/n`，其中 $n$ 直接标明**网络前缀占用的二进制位数**（同时等价于子网掩码中连续 `1` 的个数）。
- **CIDR 地址块**：一个包含 $2^{32-n}$ 个连续 IP 地址的集合。

```
以 128.14.35.7/20 为例进行微观剖析:
  128  .  14  .   35   .   7
10000000.00010000.0010 0011.00000111
|<--- 网络前缀 20 位 --->|<-- 主机 12 位 -->|
```

### 2. CIDR 地址块四大核心边界参数推导表

对于任意 CIDR 地址块 `A.B.C.D/n`，设剩余主机位数为 $h = 32 - n$：

| 参数名称 | 二进制状态 | 计算方法 / 物理意义 | 408 考场规范 |
| :--- | :--- | :--- | :--- |
| **掩码 (Mask)** | 前 $n$ 位全为 1，后 $h$ 位全为 0 | 连续 $n$ 个 1 的点分十进制 | 如 `/20` 对应 `255.255.240.0` |
| **地址总数** | 涵盖所有 $2^h$ 种状态 | **$2^{32-n} = 2^h$ 个** | 包含该块内的所有地址 |
| **网络地址 (块首)** | 前 $n$ 位保持不变，**后 $h$ 位主机位全 0** | IP 与掩码按位与（AND）的结果 | 代表该 CIDR 块本身，不可配给网卡 |
| **直接广播地址 (块尾)**| 前 $n$ 位保持不变，**后 $h$ 位主机位全 1** | 网络地址加上 $2^h - 1$ | 针对该地址块的广播，不可配给网卡 |
| **最小可用主机 IP** | 网络地址末位加 1 | 主机号取 `0...01` | 第 1 个可分配给主机的合法 IP |
| **最大可用主机 IP** | 广播地址末位减 1 | 主机号取 `1...10` | 最后一个可分配给主机的合法 IP |
| **最大可用主机数** | 扣除块首与块尾 | **$2^{32-n} - 2 = 2^h - 2$ 个** | **必须严格减 2！** |

## 三、路由聚合（Route Aggregation / 构成超网 Supernetting）

CIDR 不仅解决了地址浪费，更核心的使命是**路由聚合**：将原本分散的、具有相同前缀的一组较小路由条目，在骨干路由器中**合并压缩为一条更短前缀的大路由（超网）**！

```
【路由聚合的微观二进制提取法则】
四个分散的待聚合地址块:
192.168.0.0/24  --->  11000000.10101000.000000 00.00000000
192.168.1.0/24  --->  11000000.10101000.000000 01.00000000
192.168.2.0/24  --->  11000000.10101000.000000 10.00000000
192.168.3.0/24  --->  11000000.10101000.000000 11.00000000
                      |<- 完全相同的公共前 22 位 ->|
                      
===> 聚合为一条超网路由: 192.168.0.0/22 (掩码 255.255.252.0)
     路由表条目由 4 条压缩为 1 条，骨干网路由器查表速度提升 4 倍!
```

> **聚合成功的数学充要条件**：
> 要将 $2^k$ 个连续的 $/n$ 地址块完美聚合成一个 $/(n-k)$ 的超网，必须满足：
> 1. 地址块个数必须是 **2 的整数次幂**（如 2个、4个、8个、16个）；
> 2. 地址块在数值上必须**严格连续**；
> 3. 起始地址块的网络地址在发生变化的字节上，必须能够被 $2^k$ **整除**（基数对齐）！

## 四、最长前缀匹配原则（Longest Prefix Match，408 核心判决铁律）

在采用 CIDR 路由聚合后，路由表中可能会出现**网络范围相互重叠包含的多条匹配路由**！

### 1. 核心判决法则
**“当路由器在路由表中检索目的 IP 时，如果发现有多条路由条目均能与该目的 IP 匹配，路由器必须严格选择【网络前缀最长（即掩码中 1 的个数最多、/n 中 n 最大）】的那一条路由作为下一跳转发依据！”**

### 2. 为什么必须选“最长”？（第一性原理）
- **网络前缀越长 $\implies$ 掩码中 1 越多 $\implies$ 主机号位数越少 $\implies$ 该地址块包含的主机范围越小！**
- **范围越小，代表这条路由所指定的物理目的地越具体、越精准、越接近目标设备！**
- 相反，前缀越短（如默认路由 `/0`），范围越广大模糊。路由选择永远遵循**“由具体到一般、优先服从特例精准指示”**的原则。

## 五、408 统考真题级场景逆向与最长前缀匹配演算

### 【题型模型：多路由条目并发重叠匹配与最长前缀转发推导】

**【考题背景】**
某核心路由器 R 的 IPv4 路由表结构如下表所示：

```text
+-------------------+---------------------+---------------+
| 目的网络 / 前缀   | 子网掩码            | 下一跳接口    |
+-------------------+---------------------+---------------+
| 192.168.0.0/16    | 255.255.0.0         | 接口 E0       |
| 192.168.64.0/18   | 255.255.192.0       | 接口 E1       |
| 192.168.64.0/20   | 255.255.240.0       | 接口 E2       |
| 192.168.70.0/24   | 255.255.255.0       | 接口 E3       |
| 0.0.0.0/0         | 0.0.0.0 (默认路由)  | 接口 E4       |
+-------------------+---------------------+---------------+
```

现路由器 R 依次接收到 3 个目的 IP 地址如下的数据报：
- **数据报 1**：目的 IP 为 `192.168.70.15`
- **数据报 2**：目的 IP 为 `192.168.68.200`
- **数据报 3**：目的 IP 为 `192.168.100.5`

**【试推导并求解】**：
1. 分别分析上述 3 个数据报能与路由表中的哪些条目成功匹配？
2. 依据最长前缀匹配原则，确定路由器 R 最终将这 3 个数据报分别从哪个接口转发出去？
3. 假设将目的网络 `192.168.70.0/24`、`192.168.71.0/24`、`192.168.72.0/24`、`192.168.73.0/24` 进行路由聚合，能否直接聚合成单一的 `/22` 超网？请通过二进制展开严密证明。

---

### 【草稿纸执行第一步：将关键 IP 的第 3 字节展开为二进制】
```
目的 1 (70)  : 0100 0110
目的 2 (68)  : 0100 0100
目的 3 (100) : 0110 0100

路由表各条目的第 3 字节掩码要求:
/16 : 不看第 3 字节
/18 : 要求第 3 字节前 2 位为 01 (即 64~127 之间)
/20 : 要求第 3 字节前 4 位为 0100 (即 64~79 之间)
/24 : 要求第 3 字节严格等于 70
/0  : 匹配一切
```

---

### 【严密推导过程】

#### 第 1 问 & 第 2 问：逐包匹配与转发判决推导

**【分析数据报 1：目的 IP = `192.168.70.15`】**
- 拿目的 IP 与各条目掩码逐一做按位与运算：
  1. 与 `/16`（`255.255.0.0`）做与运算 $\to$ 得 `192.168.0.0` $\implies$ **匹配成功！**
  2. 与 `/18`（`255.255.192.0`）做与运算：`70 & 192 = 64` $\to$ 得 `192.168.64.0` $\implies$ **匹配成功！**
  3. 与 `/20`（`255.255.240.0`）做与运算：`70 & 240 = 64` $\to$ 得 `192.168.64.0` $\implies$ **匹配成功！**
  4. 与 `/24`（`255.255.255.0`）做与运算：`70 & 255 = 70` $\to$ 得 `192.168.70.0` $\implies$ **匹配成功！**
  5. 默认路由 `/0` $\implies$ 匹配成功！
- **最长前缀判决**：同时匹配 5 条路由，前缀长度分别为 $16, 18, 20, 24, 0$。其中 **/24 最长**！
- **最终转发决策**：从 **接口 E3** 转发！

**【分析数据报 2：目的 IP = `192.168.68.200`】**
- 拿目的 IP 与各条目做与运算：
  1. 与 `/16` 做与运算 $\to$ `192.168.0.0` $\implies$ 匹配成功；
  2. 与 `/18` 做与运算：`68 & 192 = 64` $\to$ `192.168.64.0` $\implies$ 匹配成功；
  3. 与 `/20` 做与运算：`68 & 240 = 64` $\to$ `192.168.64.0` $\implies$ 匹配成功；
  4. 与 `/24` 做与运算：`68 & 255 = 68 \neq 70` $\implies$ **匹配失败！**
  5. 默认路由 `/0` $\implies$ 匹配成功；
- **最长前缀判决**：成功匹配 `/16, /18, /20, /0`。其中 **/20 最长**！
- **最终转发决策**：从 **接口 E2** 转发！

**【分析数据报 3：目的 IP = `192.168.100.5`】**
- 拿目的 IP 与各条目做与运算：
  1. 与 `/16` 做与运算 $\to$ `192.168.0.0` $\implies$ 匹配成功；
  2. 与 `/18` 做与运算：`100 & 192 = 64` $\to$ `192.168.64.0` $\implies$ 匹配成功；
  3. 与 `/20` 做与运算：`100 & 240 = 96 \neq 64` $\implies$ **匹配失败！**
  4. 与 `/24` 做与运算：匹配失败；
  5. 默认路由 `/0` $\implies$ 匹配成功；
- **最长前缀判决**：成功匹配 `/16, /18, /0`。其中 **/18 最长**！
- **最终转发决策**：从 **接口 E1** 转发！

---

#### 第 3 问：路由聚合合法性证明
展开 4 个网络的第 3 字节二进制：
- 70 = `0100 0110`
- 71 = `0100 0111`
- 72 = `0100 1000`
- 73 = `0100 1001`
- 观察公共前缀：
  前 4 个地址的前 5 位均为 `01000`（前缀相同），但：
  - 70 和 71 的第 6 位是 **`1`**（`0100 01xx`）；
  - 72 和 73 的第 6 位是 **`0`**（`0100 10xx`）；
  - 要包含这 4 个网络，公共前缀只能提取到前 5 位（即前缀长度为 $16 + 5 = \mathbf{21\text{ 位}}$，对应网络为 `192.168.64.0/21`）！
- **若强行聚合为 `/22`**：
  - `/22` 要求前 22 位固定，但 70、71 与 72、73 在第 22 位上并不相同！
  - 且若以 70 为基数，70 无法被 4 整除（$70 \div 4 = 17.5$），基数不对齐！
- **结论**：**这 4 个网络绝对不能直接聚合成单一的 `/22` 超网**！它们只能分别两两聚合成两个 `/23`（`192.168.70.0/23` 和 `192.168.72.0/23`）。

## 六、考场诱惑性暗礁与秒杀口诀

### 1. 致命诱惑与错误路线踩刹车

> [!CAUTION]
> **陷阱 1：看到能匹配就立刻停下，不再看后面的路由**
> - **408 查表大题头号死因**：做题时从上往下看，发现第 1 条 `/16` 匹配上了，直接草率写出“从 E0 转发”。
> - **铁律警示**：**必须把路由表中所有条目全看完！** 找到所有匹配项，最后比对前缀长度，选 `/n` 最大的那个！

> [!CAUTION]
> **陷阱 2：以为连续的 4 个网络就一定能聚合成 /22**
> - 连续 4 个网络能否聚合成 `/22`，**必须看起始数字是否为 4 的整数倍（基数对齐）！**
>   - 如 `0, 1, 2, 3`（0 是 4 的倍数 $\implies$ 能聚成 `/22`）；
>   - 如 `4, 5, 6, 7`（4 是 4 的倍数 $\implies$ 能聚成 `/22`）；
>   - 但 `1, 2, 3, 4` 或 `70, 71, 72, 73` 起始非 4 的倍数，**绝对不能聚合成单个 /22！**

### 2. 考场核心记忆桩
- **“CIDR 破主类，斜线后跟前缀位”**：无分类编址极速定义。
- **“多条匹配莫心急，前缀最长才落地”**：最长前缀匹配秒杀桩。
- **“超网聚合看公共，连续对齐方能合”**：路由聚合合法性判定法则。
