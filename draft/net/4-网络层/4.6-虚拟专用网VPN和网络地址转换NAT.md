# 4.6 虚拟专用网VPN和网络地址转换NAT

在 IPv4 地址严重枯竭的背景下，**虚拟专用网（VPN）** 和 **网络地址转换（NAT）** 是解决地址不足、保障通信安全的最核心过渡与工程技术。两者均基于**专用地址（私网 IP）**构建。

---

## 一、私有 IP 地址范围回顾（核心基石）

根据 RFC 1918 规定，因特网骨干路由器对以下三段专用 IP 地址**绝不转发路由**（路由器收到目的 IP 为私网的数据报直接丢弃）：

| 类别 | 私网 IP 范围 | CIDR 聚合表示 | 网络数量 |
|:---:|---|:---:|:---:|
| **A 类** | `10.0.0.0` ～ `10.255.255.255` | `10.0.0.0/8` | 1 个 A 类网络 |
| **B 类** | `172.16.0.0` ～ `172.31.255.255` | `172.16.0.0/12` | 16 个连续 B 类网络 |
| **C 类** | `192.168.0.0` ～ `192.168.255.255` | `192.168.0.0/16` | 256 个连续 C 类网络 |

---

## 二、虚拟专用网 VPN（Virtual Private Network）

### 1. 核心需求与本质
机构（如跨国公司）的不同分支机构位于不同的地理位置，各自拥有独立的内部专用网络（私网），机构希望利用公用的因特网作为本机构各专用网之间的通信载体，同时**保证外部无法窃听篡改**。

### 2. 隧道技术（IP 隧道 / 封装）
VPN 的核心技术是**IP 隧道（Tunneling）技术**：

```text
部门 A 主机 (10.1.0.3)                   部门 B 主机 (10.2.0.5)
         |                                       ^
         | 原始内部 IP 数据报                    | 还原后的内部 IP 数据报
         v                                       |
    [边界路由器 R1]                         [边界路由器 R2]
   (公网IP: 125.1.2.3)                     (公网IP: 198.2.3.4)
         |                                       ^
         +========== [因特网 IP 隧道] ===========+
                    (公网加密封装后的数据报)
```

**数据封装过程**：
1. **源端边界路由器 R1 拦截**：发现目的 IP `10.2.0.5` 属于远端分支机构；
2. **加密并二次封装**：将原始 IP 数据报整个作为载荷，前面加上一个新的公网 IP 首部：
   - **外层源 IP**：`125.1.2.3`（R1 的公网接口 IP）
   - **外层目的 IP**：`198.2.3.4`（R2 的公网接口 IP）
   - **内层源 IP**：`10.1.0.3`（被加密保护）
   - **内层目的 IP**：`10.2.0.5`（被加密保护）
3. **公网路由**：因特网路由器仅根据外层公网 IP 进行常规路由；
4. **宿端边界路由器 R2 解密拆包**：剥除外层公网首部，还原内部 IP 数据报，交付给内网主机。

## 三、网络地址转换 NAT（Network Address Translation）

### 1. 核心工作原理
NAT 安装在连接私网与公网的专用路由器（NAT 路由器）上。其核心功能是：**在私网数据报流向公网时，将私网 IP 替换为合法的全球公网 IP；反向回包时，将公网 IP 替换回原始私网 IP**。

### 2. 网络地址与端口转换 NAPT（实际应用最广的形式）
传统的纯 NAT 仅转换 IP（需要 1 对 1 的公网 IP 映射，节省地址效果有限）。目前网络中绝大多数使用的是 **NAPT（Network Address Port Translation，也称 PAT）**，利用**传输层端口号**实现**多台内网主机共享一个公网 IP 同时上网**。

#### NAPT 转换表工作流程演练
假设内网主机 A（`192.168.1.2`）通过端口 `3000` 访问外网 Web 服务器（`202.108.22.5:80`），NAT 路由器的公网 IP 为 `120.24.1.1`：

```text
[内网主机 A]                                     [NAT 路由器]                               [公网 Web 服务器]
192.168.1.2:3000                                 公网 IP: 120.24.1.1                        202.108.22.5:80
       |                                               |                                           |
       |--- 1. 源: 192.168.1.2:3000 ----------------->|                                           |
       |    目: 202.108.22.5:80                        | (查表/新建映射: 端口 3000 -> 50001)       |
       |                                               |--- 2. 源: 120.24.1.1:50001 -------------->|
       |                                               |    目: 202.108.22.5:80                    |
       |                                               |                                           | (处理请求)
       |                                               |<-- 3. 源: 202.108.22.5:80 ----------------|
       |                                               |    目: 120.24.1.1:50001                   |
       |                                               | (查 NAPT 表: 端口 50001 还原为内网主机)    |
       |<-- 4. 源: 202.108.22.5:80 -------------------|                                           |
       |    目: 192.168.1.2:3000                       |                                           |
```

#### NAT 路由器内部维护的 NAPT 映射表
| 私网套接字 (IP + Port) | 公网套接字 (NAT公网IP + 转换端口) |
|---|---|
| `192.168.1.2 : 3000` | `120.24.1.1 : 50001` |
| `192.168.1.3 : 3000` | `120.24.1.1 : 50002` |

> **关键考点**：即使两台内网主机使用的**源端口号完全相同**（如都是 `3000`），NAT 路由器也会将其分配映射到**不同的公网端口号**（如 `50001` 与 `50002`），从而保证回包时能够精准区分并分用给不同的内网主机！

## 四、VPN 与 NAT 的根本区别（408 高频概念辨析）

| 对比维度 | 虚拟专用网 (VPN) | 网络地址转换 (NAT) |
|---|---|---|
| **通信终点两端** | **私网到私网**（分支与总部） | **私网到公网**（内网 PC 访问外网服务器） |
| **主要目的** | 安全加密通信、逻辑专用网络 | 缓解 IPv4 地址短缺、隐藏内网结构 |
| **数据报修改行为** | **不修改原 IP 首部**，而是加密并在外层**包装新公网 IP 首部**（隧道封装） | **直接修改 IP 首部**（替换源/目的 IP），并**协同修改传输层端口号**（重新计算校验和） |
| **跨层越界争议** | 纯网络层协议行为 | **违反分层原则**：网络层路由器读取并修改了**传输层（TCP/UDP）端口号** |

---

## 五、NAT 的固有局限性（考研问答常见）

1. **外网无法主动发起连接**：NAT 映射表项必须由内网主机主动发起外发流量时动态创建；外部公网主机在无预设端口映射（Port Forwarding）时无法主动穿透连接内网主机（阻碍了 P2P 应用）。
2. **违反分层解耦原则**：路由器本应只处理网络层首部，但 NAPT 深度读取并篡改传输层端口，且必须重新计算传输层校验和，增加路由时延。
3. **部分应用协议失效**：某些应用层协议（如早期 FTP 主动模式）在报文载荷中携带了本地 IP 地址，NAT 若不具备应用层网关（ALG）深度检测能力，会导致该类应用通信失败。
