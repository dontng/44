# 4.6 虚拟专用网VPN和网络地址转换NAT

> **408 考纲地位**：**现代网络工程与高频计算综合大题必考点**。主要考查：**RFC 1918 三大私网 IP 地址范围与路由器不转发规则**、**VPN 隧道技术（IP-in-IP 二次加密封装与外层公网路由）**、**NAT 与 NAPT（网络地址端口转换）核心映射表工作流程**、**跨网通信中 IP 首部与传输层端口号的动态替换及校验和重算**、**NAT 违反分层原则的深层讨论**。

## 一、为什么会有 VPN 与 NAT？（地址枯竭与安全边界的妥协）

在 20 世纪 90 年代，随着全球互联网呈指数级爆炸扩张，IPv4 的 32 位地址空间（约 43 亿个）迅速面临彻底耗尽的危机。在下一代 IPv6 无法瞬间全面普及的漫长过渡期内，计算机网络工程界提出了两大救命技术：
1. **网络地址转换（NAT）**：
   - 将内部私有局域网的主机全部配置为“私网 IP”，仅在接入公网的边界网关上配置少量全球唯一的“公网 IP”。
   - 通过**网络地址与端口转换（NAPT）**，使得上千台内部私网主机能够**共享同一个公网 IP** 同时访问互联网，将 IPv4 的寿命延长了数十年。
2. **虚拟专用网（VPN）**：
   - 跨国企业或高校的不同物理校区各自运行着私有网络，若要互联，租用跨国物理专用裸光纤成本是天文数字。
   - VPN 利用公用因特网作为底层传输介质，通过**隧道（Tunneling）加密技术**，在逻辑上构建出一条安全、透明、私密的虚拟专线。

## 二、私有 IP 地址范围（RFC 1918 必考基石）

因特网管理机构在 A、B、C 三类地址中各划出了一段专用地址空间，供机构内部自由分配使用。
- **全球公网路由器铁律**：**任何因特网主干路由器，对目的 IP 地址属于私有地址的数据报一律不予转发（直接静默丢弃）！**

```text
+----------+-----------------------------------+--------------------+------------------------+
| 类别     | 私有 IP 地址范围                  | CIDR 聚合网络前缀  | 包含的连续网络数量     |
+----------+-----------------------------------+--------------------+------------------------+
| **A 类** | `10.0.0.0` ～ `10.255.255.255`     | `10.0.0.0/8`       | 1 个大型 A 类网络      |
+----------+-----------------------------------+--------------------+------------------------+
| **B 类** | `172.16.0.0` ～ `172.31.255.255`   | `172.16.0.0/12`    | 16 个连续 B 类网络     |
+----------+-----------------------------------+--------------------+------------------------+
| **C 类** | `192.168.0.0` ～ `192.168.255.255` | `192.168.0.0/16`   | 256 个连续 C 类网络    |
+----------+-----------------------------------+--------------------+------------------------+
```

## 三、虚拟专用网 VPN（IP 隧道技术原理）

VPN 的核心是 **IP 隧道技术（Tunneling / IP-in-IP）**。

```text
 [部门 A 主机]                                                                        [部门 B 主机]
 (10.1.0.3)                                                                          (10.2.0.5)
     │                                                                                    ▲
     │ 1. 原始内部 IP 数据报:                                                             │ 4. 剥离外层首部，
     │    [源: 10.1.0.3 | 目: 10.2.0.5 | 内部数据]                                        │    还原出原始内部数据报
     ▼                                                                                    │
[VPN 边界网关 R1]                                                                   [VPN 边界网关 R2]
(公网 IP: 125.1.2.3)                                                                (公网 IP: 198.2.3.4)
     │                                                                                    ▲
     └───────────── 2. 加密并封装为【公网 IP 数据报 (IP 隧道)】───────────────────────────┘
                       [外层源: 125.1.2.3 | 外层目: 198.2.3.4 | 加密密文(内层数据报)]
                       (因特网骨干路由器仅根据外层公网 IP 路由，内层私网 IP 完全隐形!)
```

### 微观装帧拆包四步骤
1. **源端边界拦截**：部门 A 主机发送数据报，源 IP 为 `10.1.0.3`，目的 IP 为 `10.2.0.5`。本地网关 R1 拦截该数据报，识别出目的 IP 属于远端分支部门 B 的私网。
2. **二次封装与加密**：R1 将整个原始 IP 数据报作为载荷进行对称加密，并在其前部加上一个**全新的公网 IP 首部**：
   - **外层源 IP**：`125.1.2.3`（R1 的公网出口 IP）。
   - **外层目的 IP**：`198.2.3.4`（R2 的公网入口 IP）。
3. **公网普通路由**：公网路由器只查看外层公网 IP 首部进行常规跳数转发，完全不知晓内部包裹着什么内容。
4. **宿端解密分用**：R2 收到公网数据报后，剥去外层公网 IP 首部，对载荷进行解密，还原出原始内部 IP 数据报，直接在内部局域网交付给部门 B 主机 `10.2.0.5`。

## 四、网络地址与端口转换 NAPT（微观状态机）

普通的 NAT 仅实现 IP 地址的 1 对 1 转换，无法实现节省公网 IP 的目的。工程界与考研 408 重点考查的是 **网络地址与端口转换（NAPT，Network Address and Port Translation）**。

### 1. NAPT 双向通信微观时序图

```text
[私网主机 H1]                          [NAPT 路由器 (公网 IP: 120.24.1.1)]                  [外网 Web 服务器 S]
192.168.1.10:5000                                                                           202.108.22.5:80
       │                                              │                                             │
       ├─ 1. 发送 HTTP 请求 ─────────────────────────>│                                             │
       │     源: 192.168.1.10 : 5000                  │ 【查/建 NAPT 表项】                         │
       │     目: 202.108.22.5 : 80                    │  将私网端口 5000 映射为公网端口 60001       │
       │                                              │  改写源 IP 为 120.24.1.1                    │
       │                                              │  改写源端口为 60001                         │
       │                                              │  重新计算 IP 和 TCP 首部检验和!             │
       │                                              ├─ 2. 发送改写后的公网请求 ──────────────────>│
       │                                              │     源: 120.24.1.1 : 60001                  │
       │                                              │     目: 202.108.22.5 : 80                   │
       │                                              │                                             │
       │                                              │                                     (服务器处理完毕，回包)
       │                                              │                                             │
       │                                              │<─ 3. 服务器回送响应 ────────────────────────┤
       │                                              │     源: 202.108.22.5 : 80                   │
       │                                              │     目: 120.24.1.1 : 60001                  │
       │                                              │                                             │
       │                                              │ 【反向检索 NAPT 映射表】                    │
       │                                              │  根据端口 60001 查得内网主机:               │
       │                                              │  IP: 192.168.1.10, 端口: 5000               │
       │                                              │  改写目的 IP 与目的端口，重算 Checksum!     │
       │<─ 4. 发送还原后的响应 ───────────────────────┤                                             │
       │     源: 202.108.22.5 : 80                    │                                             │
       │     目: 192.168.1.10 : 5000                  │                                             │
```

### 2. NAPT 转换表核心结构
| 私网套接字 (Private IP + Port) | 转换后公网套接字 (Public IP + Port) | 协议类型 |
|:---:|:---:|:---:|
| `192.168.1.10 : 5000` | `120.24.1.1 : 60001` | TCP |
| `192.168.1.11 : 5000` | `120.24.1.1 : 60002` | TCP |

> **关键机制**：即使内网主机 H1 和 H2 **碰巧使用了完全相同的源端口号（如都是 5000）**，NAPT 路由器也会分配给它们**不同的公网端口号（60001 和 60002）**。当公网服务器回包时，NAPT 路由器根据回包中的**目的端口号**，就能 100% 精确分流还给各自的主机！

## 五、NAT 违反协议分层体系的争议（408 理论深化）

在传统 TCP/IP 体系中，各层各司其职：
- 网络层路由器原本**只应该查看和修改网络层 IP 首部**，对传输层及以上载荷一视同仁，透明传输；
- 但 NAT 路由器为了实现端口复用，**强行深入读取并修改了传输层的 TCP/UDP 端口号**！
- **负面影响**：
  1. **破坏端到端原则（End-to-End Principle）**：使得外网主机无法主动发起连接访问内网主机（内网穿透困难）；
  2. **协议兼容性差**：某些应用层协议（如 FTP 协议主动模式在应用层报文载荷中明文传输客户端 IP 和端口），NAT 必须部署专门的应用层网关（ALG）深度解析载荷，否则应用直接崩溃；
  3. **计算开销增大**：NAT 路由器必须对每个进出的数据包重新计算 IP 首部校验和以及 TCP/UDP 校验和。

## 六、408 经典高频真题精析

### 【题型：NAPT 转换表与数据报字段变迁综合大题】

**【题目描述】**
某局域网通过一台 NAPT 路由器接入 Internet。该 NAPT 路由器的 LAN 接口 IP 地址为 `192.168.1.1`，WAN 接口全球公网 IP 地址为 `218.199.80.1`。局域网内部有两台主机：
- 主机 H1：IP 地址为 `192.168.1.10`
- 主机 H2：IP 地址为 `192.168.1.20`

现主机 H1 和 H2 同时访问 Internet 上的同一台 Web 服务器 S（IP 地址为 `61.135.169.121`，端口号为 `80`）。H1 发出的 TCP 报文段的源端口号为 `4001`；H2 发出的 TCP 报文段的源端口号也刚好为 `4001`。
NAPT 路由器为 H1 的会话分配的外网端口号为 `30001`，为 H2 的会话分配的外网端口号为 `30002`。

请回答：
1. 请写出该 NAPT 路由器当前维护的 NAPT 转换表中的两个关键表项内容（包含私网 IP、私网端口、公网 IP、公网端口）。
2. 当主机 H1 发出的 HTTP 请求数据报离开 NAPT 路由器的 WAN 接口时，该数据报的 IP 首部源 IP、目的 IP 以及 TCP 首部的源端口、目的端口分别被改写为什么值？
3. 当 Web 服务器 S 对 H2 发出的请求进行响应，响应数据报到达 NAPT 路由器 WAN 接口时，该数据报中的源 IP、目的 IP、源端口、目的端口分别是什么？NAPT 路由器将其转发给局域网时，这 4 个字段又将分别变成什么值？

---

### 【标准解题步骤（120+ 考场标准规范）】

#### 第一问：NAPT 转换表内容构建
根据题意，NAPT 维护的映射表项为：

| 私网 IP | 私网端口 | 公网 IP | 映射公网端口 | 协议 |
|:---:|:---:|:---:|:---:|:---:|
| `192.168.1.10` | 4001 | `218.199.80.1` | 30001 | TCP |
| `192.168.1.20` | 4001 | `218.199.80.1` | 30002 | TCP |

#### 第二问：H1 发出的请求报文在 WAN 接口的字段值
数据报从内网流向外网，NAPT 将源地址与源端口替换为公网映射参数，目的地址保持不变：
- **源 IP 地址**：由 `192.168.1.10` 改写为 **`218.199.80.1`**（NAPT 公网 IP）；
- **目的 IP 地址**：保持不变，为 **`61.135.169.121`**（Web 服务器 IP）；
- **源端口号**：由 `4001` 改写为 **`30001`**（映射公网端口）；
- **目的端口号**：保持不变，为 **`80`**。

#### 第三问：服务器 S 对 H2 响应报文的双向字段变换推导
- **1. 到达 NAPT WAN 接口时（公网传入）**：
  - 服务器 S 回包，源即为服务器，目的为 NAPT 公网：
  - **源 IP 地址**：`61.135.169.121`
  - **目的 IP 地址**：`218.199.80.1`
  - **源端口号**：`80`
  - **目的端口号**：`30002`（正是对应 H2 的公网分配端口！）
- **2. NAPT 转换后转发给局域网 H2 时（局域网送出）**：
  - NAPT 查表将目的公网 IP 与目的公网端口还原为 H2 的私网参数：
  - **源 IP 地址**：保持不变，为 **`61.135.169.121`**
  - **目的 IP 地址**：改写为 **`192.168.1.20`**（H2 私网 IP）
  - **源端口号**：保持不变，为 **`80`**
  - **目的端口号**：改写为 **`4001`**（H2 原始监听端口）

## 七、考场肌肉记忆与避坑指南

### 1. 致命易错陷阱
- 陷阱 1：**公网路由器是否转发私网 IP？**
  - **绝对不转发！** 若在综合拓扑中看到发往 `10.x.x.x`、`172.16.x.x`、`192.168.x.x` 的数据报进入公网核心路由器，答案必定是“丢弃”。
- 陷阱 2：**NAT 转换中被修改的字段有哪些？**
  - **出内网**：改写 **源 IP** 和 **源端口**；
  - **进内网**：改写 **目的 IP** 和 **目的端口**；
  - **核心连带动作**：每次改写后，必须**重新计算 IP 首部校验和与 TCP/UDP 校验和**！
- 陷阱 3：**VPN 与 NAT 的数据报封装差别**
  - NAT 是在原首部上**直接修改**替换 IP 和端口；
  - VPN 是保留原 IP 首部，在外面**套上新的一层公网 IP 首部（隧道封装）**。

### 2. 秒杀公式与反射条件
$$\text{出站 NAPT}：\text{源 IP} \to \text{NAT 公网 IP}, \quad \text{源 Port} \to \text{NAT 映射端口}$$
$$\text{入站 NAPT}：\text{目的 IP} \to \text{内网主机 IP}, \quad \text{目的 Port} \to \text{内网原始端口}$$
$$\text{私网三大网段}：10.0.0.0/8, \quad 172.16.0.0/12, \quad 192.168.0.0/16$$
