# 4.6 虚拟专用网 VPN 和网络地址转换 NAT

随着全球互联网络规模的急剧扩大，IPv4 的 32 位地址空间面临日益严重的枯竭危机。同时，企业与机构对跨地域私密通信的需求日益增长。**虚拟专用网（VPN）** 与 **网络地址转换（NAT）** 是解决这两大核心矛盾的关键工程技术。

---

## 一、私有 IP 地址（RFC 1918）

为了解决全球公网 IP 地址不足，并满足机构内部专用组网的需求，因特网管理机构在 A、B、C 类地址中分别划出了一段专用地址：

```
+----------+-----------------------------------+--------------------+------------------------+
| 类别     | 私有 IP 地址范围                  | CIDR 聚合网络前缀  | 包含的连续网络数量     |
+----------+-----------------------------------+--------------------+------------------------+
| **A 类** | `10.0.0.0` ～ `10.255.255.255`     | `10.0.0.0/8`       | 1 个大型 A 类网络      |
+----------+-----------------------------------+--------------------+------------------------+
| **B 类** | `172.16.0.0` ～ `172.31.255.255`   | `172.16.0.0/12`    | 16 个连续 B 类网络     |
+----------+-----------------------------------+--------------------+------------------------+
| **C 类** | `192.168.0.0` ～ `192.168.255.255` | `192.168.0.0/16`   | 256 个连续 C 类网络    |
+----------+-----------------------------------+--------------------+------------------------+
```

### 核心规则：
- 私有 IP 地址仅在机构内部使用，全世界所有企业和家庭局域网均可自由重复配置使用；
- **因特网公共主干路由器绝不为私有 IP 地址分配路由条目**。若公网路由器接收到目的 IP 为私有地址的数据报，将直接静默丢弃。

---

## 二、虚拟专用网（VPN，Virtual Private Network）

当一个机构的多个部门分布在不同地域时，若专门铺设跨地域的物理专线，成本极为高昂。**虚拟专用网（VPN）** 利用公用因特网作为底层传输介质，通过软件加密与隧道技术，在逻辑上构建出一条专用的、安全的内部通信网络。

```
 [部门 A 主机]                                                                        [部门 B 主机]
 (10.1.0.3)                                                                          (10.2.0.5)
     │                                                                                    ▲
     │ 1. 原始内部 IP 数据报:                                                             │ 4. 剥离外层首部，
     │    [源: 10.1.0.3 | 目的: 10.2.0.5 | 内部数据]                                     │    还原出原始内部数据报
     ▼                                                                                    │
[VPN 边界网关 R1]                                                                   [VPN 边界网关 R2]
(公网 IP: 125.1.2.3)                                                                (公网 IP: 198.2.3.4)
     │                                                                                    ▲
     └───────────── 2. 隧道封装: 加密并加上【公网 IP 首部】───────────────────────────────┘
                       [外层源: 125.1.2.3 | 外层目的: 198.2.3.4 | 加密密文(内层数据报)]
                       (因特网路由器仅根据外层公网 IP 路由，内层私网 IP 完全隐形)
```

### IP 隧道技术（Tunneling）工作流程：
1. **源端边界拦截**：部门 A 主机发送数据报，源 IP 为内部私网 IP `10.1.0.3`，目的 IP 为部门 B 的私网 IP `10.2.0.5`。本地 VPN 网关 R1 拦截该数据报；
2. **隧道封装与加密**：R1 将整个原始内部 IP 数据报进行加密处理，并在其外侧重新封装一个**全新的公网 IP 首部**：
   - 外层源 IP 填入 R1 自己的公网接口 IP（`125.1.2.3`）；
   - 外层目的 IP 填入远端网关 R2 的公网接口 IP（`198.2.3.4`）；
3. **公网普通路由**：公网路由器仅依据外层公网 IP 首部进行普通的查表转发，对内层加密数据完全透明；
4. **宿端解密还原**：远端网关 R2 收到数据报后，剥去外层公网 IP 首部，对载荷进行解密，还原出原始内部 IP 数据报，交付给部门 B 的目的主机 `10.2.0.5`。

## 三、网络地址转换（NAT）与网络地址端口转换（NAPT）

由于私网 IP 地址无法直接在公网上路由，局域网内部的主机若要访问因特网，必须借助**网络地址转换（NAT，Network Address Translation）**。

### 1. 网络地址与端口转换（NAPT）的工作机制
在实际工程与现代路由器中，绝大多数采用的是支持端口复用的 **网络地址与端口转换（NAPT）**。它允许多台私网主机共享同一个公网 IP 地址同时访问因特网。

```
[私网主机 H1]                          [NAT 路由器 (公网 IP: 120.24.1.1)]                   [外网 Web 服务器 S]
192.168.1.10:5000                                                                            202.108.22.5:80
       │                                              │                                              │
       ├─ 1. 发送请求 ────────────────────────────────>│                                              │
       │     源: 192.168.1.10 : 5000                  │ 【查/建 NAT 映射表项】                       │
       │     目: 202.108.22.5 : 80                    │  私网 192.168.1.10:5000 映射为 120.24.1.1:60001│
       │                                              │  改写源 IP 为 120.24.1.1, 源端口为 60001      │
       │                                              │  重新计算 IP 和 TCP 校验和                   │
       │                                              ├─ 2. 发送改写后的公网请求 ────────────────────>│
       │                                              │     源: 120.24.1.1 : 60001                   │
       │                                              │     目: 202.108.22.5 : 80                    │
       │                                              │                                              │
       │                                              │                                      (服务器响应，回包)
       │                                              │                                              │
       │                                              │<─ 3. 服务器回送响应 ─────────────────────────┤
       │                                              │     源: 202.108.22.5 : 80                    │
       │                                              │     目: 120.24.1.1 : 60001                   │
       │                                              │                                              │
       │                                              │ 【反向检索 NAT 映射表】                     │
       │                                              │  根据外网端口 60001 查得私网主机:            │
       │                                              │  IP: 192.168.1.10, 端口: 5000                │
       │                                              │  改写目的 IP 与目的端口，重新计算校验和      │
       │<─ 4. 发送还原后的数据 ───────────────────────┤                                              │
       │     源: 202.108.22.5 : 80                    │                                              │
       │     目: 192.168.1.10 : 5000                  │                                              │
```

### 2. NAPT 转换表结构
NAPT 路由器内部维护一张动态转换表：

| 私网套接字（私网 IP : 端口） | 映射的公网套接字（公网 IP : 端口） | 传输层协议 |
| :---: | :---: | :---: |
| `192.168.1.10 : 5000` | `120.24.1.1 : 60001` | TCP |
| `192.168.1.20 : 5000` | `120.24.1.1 : 60002` | TCP |

- **端口区分机制**：即使内部多台不同的私网主机巧合地使用了相同的源端口号（如都是 5000），NAPT 路由器会为其分配不同的外部公网端口号（60001 与 60002）；
- 当服务器返回响应时，路由器根据数据报中的**目的端口号**检索映射表，即可准确将流量交付给对应的内部私网主机。

## 四、NAT 对网络体系结构的影响与争议

NAT 极大缓解了 IPv4 地址枯竭的问题，但也带来了一些结构性争议：
1. **违反网络分层原则**：原本工作在网络层（L3）的路由器，为了实现 NAPT，必须跨层深入读取并修改传输层（L4）的 TCP/UDP 端口号；
2. **破坏端到端通信原则（End-to-End Principle）**：外网主机无法在无预先映射的情况下主动发起连接访问内网主机（内网主机对外部透明），导致 P2P 业务和内网穿透变得复杂；
3. **计算开销增加**：由于 IP 地址和传输层端口号在每一跳进出时被动态修改，NAT 路由器必须对每个数据包重新计算 IP 首部校验和与 TCP/UDP 校验和。
