# 4.7.1+4.7.2 IP多播技术的相关基本概念、IP多播地址和多播组

与传统的单播（点对点 Unicast）和广播（一点到全体 Broadcast）不同，**多播（Multicast，组播）** 实现了**一点向特定群体（一点到多点）的高效传输**。

---

## 一、为什么需要多播？（与单播复制的本质区别）

在视频直播或股票行情分发场景中，如果有 1000 个用户同时收看同一个视频流：
- **传统单播方式**：服务器必须生成 1000 个完全相同的单播 IP 数据报副本，各自独立发送。骨干路由器的主干链路上充斥着 1000 份重复流量，网络带宽被严重浪费。
- **IP 多播方式**：服务器**只发送一份数据报**，目的地址指定为多播组地址。沿途的多播路由器仅在路径分叉处才复制该数据报并分流转发。

```text
单播复制:   [服务器] ===== 1000份相同副本 =====> [骨干路由器] ----> 浪费全网带宽!
多播传输:   [服务器] ----- 1份原始多播流 -----> [多播路由器] ----> 仅在分叉点复制分发!
```

## 二、IP 多播地址（D 类地址）体系

IP 多播采用专门的 **D 类 IP 地址**，范围为 **`224.0.0.0` ～ `239.255.255.255`**（前 4 位固定为二进制 `1110`）。

### 核心特性（选择题考点）
1. **多播地址标识的是“一个组”，而不是具体主机**：多播地址绝不能作为任何主机或路由器网卡的单播源地址（**多播数据报的源 IP 始终是发送端的单播 IP 地址**，目的 IP 才是 D 类多播组地址）。
2. **多播数据报没有子网掩码**：D 类地址不区分网络号与主机号。
3. **不可靠尽最大努力交付**：多播数据报基于 UDP 传输，不提供 ACK 确认与重传（若上层用 TCP，TCP 三次握手和重传无法一对多收敛）。

### 常见保留多播组地址
- `224.0.0.1`：本子网内的**所有主机和路由器**；
- `224.0.0.2`：本子网内的**所有多播路由器**；
- `224.0.0.5` 与 `224.0.0.6`：OSPF 协议专用组播地址。
