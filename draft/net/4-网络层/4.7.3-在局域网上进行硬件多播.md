# 4.7.3 在局域网上进行硬件多播

IP 多播运行在第三层（网络层），而局域网主机与交换机工作在第二层（数据链路层）。如果局域网直接使用全 1 的以太网广播地址传输多播数据报，会导致网段内的所有主机都被迫接收并处理该帧，失去了多播仅分发给订阅者的优势。因此，必须在数据链路层实现硬件级别的多播支持。

---

## 一、以太网多播 MAC 地址的构成标准

IEEE 规定，以太网组播 MAC 地址的第 1 个字节的最低有效位（I/G 位）必须为 **1**（表示组播）。
为了支持 IP 多播，IANA（因特网编号分配机构）申请了一段专用的以太网 MAC 地址块：

- **高 24 位（OUI 组织唯一标识符）**：固定为十六进制 **`01-00-5E`**；
- **第 25 位**：固定为二进制 **`0`**；
- **低 23 位**：直接由 **32 位 D 类 IP 多播地址的低 23 位** 机械复制填充。

```
 32 位 D 类 IP 多播地址:
   1 1 1 0   [ 丢弃 5 位 ]   [           提取低 23 位用于映射           ]
 +---------+---------------+-----------------------------------------+
 |  1110   |  x x x x x    |  b22 b21 b20 ...                    b1 b0|
 +---------+---------------+-----------------------------------------+
                                                │
                               (直接机械复制)   ▼
 48 位以太网多播 MAC 地址:
   [ 高 24 位固定为 01-00-5E ]  0  [           复制低 23 位           ]
 +-----------------------------+--+-----------------------------------+
 |   01  -  00  -  5E          | 0|  b22 b21 b20 ...             b1 b0|
 +-----------------------------+--+-----------------------------------+
   <--------- 24 位 ---------> 1位 <-------------- 23 位 ------------->
                              第25位
```

---

## 二、32 对 1 地址映射冲突的成因与过滤机制

### 1. 冲突成因的数学推导
1. D 类 IP 地址共有 32 位，其中最高 4 位固定为 `1110`，因此可自由变化的组播标识位有：
   $$32 - 4 = 28\text{ 位}$$
2. 然而，以太网多播 MAC 地址只分配了 **23 位** 用于映射 IP 地址；
3. 在转换过程中，D 类 IP 地址中有：
   $$28 - 23 = \mathbf{5\text{ 位}}$$
   的信息在映射时被**直接丢弃**；
4. **数学结论**：
   $$2^5 = \mathbf{32\text{ 个不同的 IP 多播地址}} \longleftrightarrow \mathbf{映射到同一个以太网多播 MAC 地址}$$

```
 [IP 多播地址 1: 224.0.1.1]   ─────┐
 [IP 多播地址 2: 224.128.1.1] ─────┼───> 映射为相同的以太网 MAC: 01-00-5E-00-01-01
               ...                 │
 [IP 多播地址 32: 239.128.1.1] ────┘
```

### 2. 网卡硬件与系统协议栈的两级过滤
由于存在 32 对 1 的映射冲突，接收端主机通过两级过滤来确保只接收本机订阅的多播流：

```
               [ 局域网物理信道接收到数据帧: 目的 MAC 为 01-00-5E-00-01-01 ]
                                          │
                                          ▼
   +─────────────────────────────────────────────────────────────────────────────+
   | 第一级: 网卡芯片 (NIC 硬件初筛)                                             |
   | - 网卡比对自身注册的组播 MAC 列表;                                          |
   | - 命中 01-00-5E-00-01-01 ──> 接收数据帧，剥去 MAC 首部，送交操作系统内核     |
   | - 未命中 ──> 硬件直接丢弃，不触发 CPU 中断                                  |
   +─────────────────────────────────────────────────────────────────────────────+
                                          │
                                          ▼
   +─────────────────────────────────────────────────────────────────────────────+
   | 第二级: 操作系统网络层协议栈 (内核软件精确过滤)                             |
   | - 解析 IP 首部，提取真正的 32 位目的 IP 地址 (如 224.128.1.1);              |
   | - 检查本机是否有进程真正加入了该组播组:                                     |
   |   - 若加入了: 向上交付给应用程序处理;                                       |
   |   - 若本机只订阅了 224.0.1.1 (仅为 MAC 冲突): 内核静默丢弃，不予交付        |
   +─────────────────────────────────────────────────────────────────────────────+
```
