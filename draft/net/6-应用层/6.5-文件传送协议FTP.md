# 6.5 文件传送协议FTP

> **408 考纲地位**：**经典双连接文件传输应用协议（选择题高频细节考点）**。深入考查：**FTP 屏蔽底层操作系统异构文件存储差异的设计哲学**、**双独立 TCP 连接架构（控制连接与数据连接）的职责分工与生命周期对比**、**熟知端口号分配（控制连接 21，主动数据连接 20）**、**主动模式（PORT）vs 被动模式（PASV）在防火墙/NAT 穿透下的微观建立时序差异**、**带外控制（Out-of-Band）的核心机制与优势**。

---

## 一、FTP 的定位与异构文件系统屏蔽

### 1. 为什么不能像复制单机文件一样直接网络拷贝？
在因特网中，不同的主机硬件体系与操作系统具有巨大的异构性：
- 文件的目录结构、权限机制不同（UNIX 树状层级 vs Windows 盘符路径）；
- 文本行结束符不同（Windows 使用 `\r\n`，Linux 使用 `\n`，旧 Mac 使用 `\r`）；
- 文件的内部数据类型与表示形式各不相同。
- **文件传送协议（FTP，File Transfer Protocol，RFC 959）** 屏蔽了各操作系统的细节差异，允许用户在不同体系的主机之间进行透明、可靠的文件上传与下载。

---

## 二、FTP 的双连接架构：控制连接与数据连接

FTP 区别于其他应用层协议（如 HTTP、SMTP）最显著的结构特征是：**在通信过程中并发使用两条独立的 TCP 连接**。

```text
       FTP 客户机 (Client)                                   FTP 服务器 (Server)
  +─────────────────────────+                           +─────────────────────────+
  |    客户控制进程 (PI)    | <==== 控制连接 (Port 21) ====>|    服务控制进程 (PI)    |
  | (发送指令, 接收状态码)  |     (在整个会话期间一直保持)  | (解析指令, 维护会话状态)|
  +─────────────────────────+                           +─────────────────────────+
  |    客户数据传送进程(DTP)| <==== 数据连接 (Port 20) ====>|    服务数据传送进程(DTP)|
  | (负责真正传输文件数据)  |      (每次传输完毕后立即关闭) | (负责读写磁盘并传输文件)|
  +─────────────────────────+                           +─────────────────────────+
```

### 1. 控制连接（Control Connection）
- **功能职责**：用于传送与文件传输相关的**控制命令与服务器响应状态码**（如登录用户名密码 `USER`/`PASS`、改变目录 `CWD`、文件列表 `LIST`、下载指令 `RETR`、上传指令 `STOR` 等）；
- **端口号**：服务器端在 **`熟知端口 21`** 上监听等待客户端发起连接；
- **生命周期**：**长连接（Persistent）**。在客户端与服务器建立会话的整个期间，控制连接**始终保持打开状态**，直到会话正式结束客户端发送 `QUIT`。

### 2. 数据连接（Data Connection）
- **功能职责**：专门用于传送**实际的文件内容（二进制文件或文本）以及目录文件清单（`DIR/LIST` 输出）**；
- **端口号**：在传统主动模式下，服务器端固定使用 **`熟知端口 20`**；
- **生命周期**：**短连接（Non-Persistent）**。每传送一个文件（或获取一次目录列表），客户端与服务端便新建一条数据连接；**传输完毕后该数据连接立即关闭释放**。若用户连续下载 10 个文件，期间控制连接保持 1 条不变，但数据连接将先后经历 10 次独立的创建与断开。

### 3. 带外控制（Out-of-Band Control）
- 因为 FTP 将控制信息与数据内容完全隔离在两条物理上独立的 TCP 连接中，这种控制机制称为 **带外控制（Out-of-Band）**（对比 HTTP 将请求头与正文混在同一条 TCP 连接中称为带内控制）；
- **优势**：即使正在进行数个 GB 大文件的漫长数据传输，控制连接依然畅通无阻，客户端可以随时在控制连接上发送中断指令（如 `ABOR`），服务器能即刻捕获并终止后台数据连接传输。

## 三、主动模式（PORT）vs 被动模式（PASV）

由于网络防火墙与 NAT 设备的广泛存在，数据连接究竟由谁主动发起分为两种截然不同的工作模式：

```text
【1. 主动模式 (PORT Mode - 服务器主动连客户)】:
  客户端 Client (Port c)                   服务器 Server (Port 21)
      │                                                │
      ├─ 控制连接中发送指令: PORT IP_C, Port_c2 ──────>│
      │                                                │
  客户端 Client (Port c2)                  服务器 Server (Port 20)
      │                                                │
      │<── 数据连接发起: SYN (由服务器主动连客户端!) ──┤ (极易被客户端本地防火墙拦截!)
      
-----------------------------------------------------------------------------

【2. 被动模式 (PASV Mode - 客户端主动连服务器)】:
  客户端 Client (Port c)                   服务器 Server (Port 21)
      │                                                │
      ├─ 控制连接中发送指令: PASV ─────────────────────>│
      │<─ 回复: "进入被动模式, 请连接我的端口 p2" ─────┤
      │                                                │
  客户端 Client (Port c2)                  服务器 Server (Port p2)
      │                                                │
      ├─── 数据连接发起: SYN (由客户端主动连服务器!) ──>│ (防火墙天然放行出站连接, 畅通无阻!)
```

### 1. 主动模式（PORT Mode / Active Mode）
- **工作机制**：
  1. 客户端先与服务器 21 端口建立控制连接；
  2. 客户端在本地临时挑选一个未被占用的动态端口 $c_2$，通过控制连接发送 `PORT` 命令，明确告知服务器客户端的数据端口号 $c_2$；
  3. **服务器端主动使用自己的 20 端口发起向客户端 $c_2$ 端口的 TCP 连接请求**。
- **局限性**：现代客户端普遍位于内网路由器的 NAT 之后或开启了个人本地防火墙。当外部服务器主动尝试连接客户端内部端口时，防火墙会判定其为未授权的入站探测并直接拦截丢弃，导致主动模式连接失败。

### 2. 被动模式（PASV Mode / Passive Mode）
- **工作机制**：
  1. 客户端通过控制连接向服务器发送 `PASV` 指令，告知服务器采用被动模式；
  2. 服务器收到后，在本地动态开启一个临时的未占用非熟知高位端口 $p_2$（并非 20 端口！），并通过控制连接回复客户端；
  3. **客户端收到该端口号后，由客户端主动发起向服务器临时端口 $p_2$ 的 TCP 数据连接**。
- **优势**：从内网客户端向公网服务器发起的出站 TCP 连接天然会被本地防火墙与 NAT 规则无缝放行，被动模式已成为当今绝大多数 FTP 客户端的默认工作方式。
