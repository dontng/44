# 6.3 动态主机配置协议DHCP


## 一、DHCP 的产生背景与协议封装

### 1. 为什么需要 DHCP？
在早期局域网中，每台主机接入网络必须由管理员手工配置四大核心参数：
1. **本机的 IPv4 地址**；
2. **子网掩码（Subnet Mask）**；
3. **默认网关路由器的 IP 地址（Default Gateway）**；
4. **本地首选域名服务器的 IP 地址（DNS Server）**。
- 手工配置繁琐易错，且对于移动终端（如笔记本、手机）在不同网段之间漫游时，手动切换 IP 极其不便。
- **动态主机配置协议（DHCP，Dynamic Host Configuration Protocol，RFC 2131）** 实现了网络配置参数的**即插即用（Plug-and-Play）**：主机只要物理连入网络，即可自动获取全部配置参数并开始通信。

### 2. 传输层封装与特殊端口号
- DHCP 属于**应用层协议**；
- 传输层使用 **UDP 协议** 封装；
- **端口号分配**：
  - **DHCP 服务器端监听端口**：**`67`**；
  - **DHCP 客户端监听端口**：**`68`**。
  - *为什么客户端也有专用熟知端口 68？因为在初始化时客户端尚未分配 IP 地址，只能通过 UDP 广播接收服务器响应；若客户端使用随机端口，操作系统将无法把网络层广播正确分用至对应的 DHCP 客户进程。*

## 二、DHCP 四步交互时序（微观报文与地址演变）

当一台新主机刚接入局域网开机时，与 DHCP 服务器之间经历经典的“四步交互时序”：

```text
       新开机客户机 (Client)                                 DHCP 服务器 (Server)
      (无 IP, 拥有 MAC_C)                                   (已配 IP_S, MAC_S)
              │                                                     │
              │ 1. 【DHCP DISCOVER (发现报文)】                     │
              │    源 IP: 0.0.0.0          目的 IP: 255.255.255.255 │
              │    源 MAC: MAC_C           目的 MAC: FF-FF-FF-FF-FF │
              ├────────────────────────────────────────────────────>│
              │                                                     │
              │ 2. 【DHCP OFFER (提供报文)】                        │
              │    源 IP: IP_S             目的 IP: 255.255.255.255 │ (或单播提供)
              │    源 MAC: MAC_S           目的 MAC: FF-FF-FF-FF-FF │
              │    (携带: 拟分配 IP、租用期、网关、DNS)             │
              │<────────────────────────────────────────────────────┤
              │                                                     │
              │ 3. 【DHCP REQUEST (请求报文)】                      │
              │    源 IP: 0.0.0.0          目的 IP: 255.255.255.255 │
              │    源 MAC: MAC_C           目的 MAC: FF-FF-FF-FF-FF │
              │    (显式声明: 正式接受该 IP，并让其他服务器撤回)     │
              ├────────────────────────────────────────────────────>│
              │                                                     │
              │ 4. 【DHCP ACK (确认报文)】                          │
              │    源 IP: IP_S             目的 IP: 255.255.255.255 │
              │    源 MAC: MAC_S           目的 MAC: FF-FF-FF-FF-FF │
              │    (正式批准绑定，客户端即刻配置生效!)              │
              │<────────────────────────────────────────────────────┤
              ▼                                                     ▼
        [客户端配置生效，正式接入网络!]
```

### 1. 第一步：DHCP DISCOVER（发现报文）
- **客户端动作**：广播寻找局域网内可用的 DHCP 服务器；
- **首部各字段（核心机制）**：
  - **网络层源 IP**：**`0.0.0.0`**（客户端尚未获得合法 IP）；
  - **网络层目的 IP**：**`255.255.255.255`**（本网段受限广播地址）；
  - **链路层源 MAC**：客户端网卡的物理地址 `MAC_C`；
  - **链路层目的 MAC**：全 1 广播物理地址 `FF-FF-FF-FF-FF-FF`；
  - **报文载荷**：携带一个随机生成的事务 ID（Transaction ID），并携带客户端自身的硬件 MAC 地址。

### 2. 第二步：DHCP OFFER（提供报文）
- **服务器动作**：局域网内所有收到 DISCOVER 的 DHCP 服务器，各自在自身的地址池中挑选一个尚未分配的可用 IP 地址（并在发出前通常用 ARP ping 探测防冲突），向客户端回送 OFFER；
- **首部与载荷字段**：
  - **提供内容**：拟分配给客户端的 IP 地址（`yiaddr`）、子网掩码、租用期（Lease Time）、默认网关 IP、DNS 服务器 IP；
  - **投递方式**：网络层通常采用广播 `255.255.255.255` 发送（部分厂商实现支持直接单播发给 `MAC_C`）。

### 3. 第三步：DHCP REQUEST（请求报文）
- **为什么需要第三步？**
  - 局域网内可能存在多台 DHCP 服务器，客户端可能同时收到多个 DHCP OFFER 报文；
  - 客户端通常挑选**最先到达的那个 OFFER**；
- **客户端动作**：客户端向全网广播发送 REQUEST 报文：
  - **显式通知选中的服务器**：在报文选项中指明“我正式接受你的 IP 分配”；
  - **委婉拒绝其他服务器**：同时通知其他提供了 OFFER 的服务器“我没有选你们，请将为我预留的 IP 地址释放回地址池”。
- **首部特征**：
  - **此时客户端仍未正式获得该 IP 的合法绑定！** 因此**网络层源 IP 依然必须是 `0.0.0.0`**，目的 IP 依然是广播 `255.255.255.255`。

### 4. 第四步：DHCP ACK（确认报文）
- **服务器动作**：被选中的 DHCP 服务器向客户端发回最后的确认报文（DHCP ACK）；
- **客户端生效**：客户端收到 ACK 后，正式将该 IP 地址、子网掩码、网关和 DNS 绑定到本地网卡，配置正式生效；
- **若发生异常**：若服务器此时发现该 IP 已不可用，则回送 DHCP NAK（否认报文），客户端必须重新退回第一步发送 DISCOVER。

## 三、DHCP 中继代理（Relay Agent）跨网段转发机制

根据路由器的工作原理，**路由器默认绝对不转发目的 IP 为 `255.255.255.255` 的受限广播数据报**。
- 若每个物理局域网网段都单独采购部署一台专用的 DHCP 物理服务器，硬件和维护成本过高；
- **工程解决机制**：引入 **DHCP 中继代理（Relay Agent）**（通常直接由该网段的默认网关路由器接口兼任）。

```text
  [ 局域网 1 客户机 ]                      [ 默认网关路由器 / 中继代理 ]                     [ 集中式 DHCP 服务器 ]
         │                                            │                                            │
         ├─ 1. 广播 DISCOVER (目的 255.255.255.255) ──>│                                            │
         │                                            │ 2. 单播转换 (IP-in-UDP):                   │
         │                                            │    源 IP: 路由器自身的接口 IP               │
         │                                            │    目的 IP: DHCP 服务器的真实单播 IP        │
         │                                            ├───────────────────────────────────────────>│
         │                                            │                                            │
         │                                            │<── 3. 单播回送 OFFER ──────────────────────┤
         │<─ 4. 在局域网 1 内转交该报文 ──────────────┤                                            │
```

- **工作流程**：
  1. 局域网内的客户端仍然发送标准的广播 DISCOVER；
  2. 路由器作为中继代理捕获该广播报文，提取其内容，将其封装为正常的**单播 IP 数据报**；
  3. 路由器将该单播数据报跨越三层网络转发给远端集中数据中心部署的专用 DHCP 服务器；
  4. DHCP 服务器根据报文中记录的中继代理接口 IP，判定客户端所在的子网网段，从对应网段的地址池中挑选 IP 并单播发回中继代理；
  5. 中继代理收到后再在本地局域网交付给客户端。

## 四、DHCP 租用期与动态续租时序

DHCP 分配的 IP 地址是有有效时限的，称为**租用期（Lease Time）**。为了保证连接不中断，客户端需进行续约：

```text
 租用期开始 (0%)              到达 50% 租约时限              到达 87.5% 租约时限           租用期届满 (100%)
      │                             │                              │                             │
      ▼                             ▼                              ▼                             ▼
 [获取 IP 成功] ──────────> 【第一阶段续租】 ────────────> 【第二阶段续租】 ────────────> [必须立即停用该 IP!]
                            - 客户端直接向原服务器          - 仍未收到回复,               - 释放地址并重新发起
                              发送【单播】DHCP REQUEST        向全网发送【广播】            完整的 DISCOVER 流程!
                            - 成功则刷新租期                DHCP REQUEST 寻找任意服务器
```

1. **到达租期 50%（$T_1 = 0.5 \times \text{Lease}$）**：
   - 客户端主动向当初为自己分配 IP 的那台 DHCP 服务器**单播发送 DHCP REQUEST 报文**；
   - 若服务器同意续租，回送单播 DHCP ACK，租用期计数器复位重新计时；
2. **到达租期 87.5%（$T_2 = 0.875 \times \text{Lease}$）**：
   - 若在 50% 时原服务器无响应（可能该服务器故障或关机），客户端在租期剩余 12.5% 时发起紧急抢救；
   - 客户端向全网**广播发送 DHCP REQUEST 报文**，允许网络中任何其他可用的 DHCP 服务器为自己续租；
3. **到达租期 100%**：
   - 若一直未收到任何 ACK，租用期彻底耗尽；
   - 客户端必须**立即停止使用该 IP 地址**，网络连接中断；
   - 客户端退回初始状态，重新广播发送 DHCP DISCOVER 重新申请全新的 IP。
