# 6.6 电子邮件


## 一、电子邮件系统的体系架构与组成构件

电子邮件（E-mail）是一种典型的**异步非实时通信系统**：发送方发送邮件时，接收方并不需要同时在线。

```text
  [ 发送方用户代理 UA ]
         │
         │ 1. 邮件发送: 【SMTP 推协议】 (TCP 25)
         ▼
  [ 发送方邮件服务器 ]
         │
         │ 2. 邮件在服务器间中继传输: 【SMTP 推协议】 (TCP 25)
         ▼
  [ 接收方邮件服务器 ] (邮件暂存在接收方个人邮箱中)
         ▲
         │ 3. 邮件读取下载: 【POP3 / IMAP 拉协议】 (TCP 110 / 143)
         │
  [ 接收方用户代理 UA ]
```

### 1. 三大核心构件
1. **用户代理（UA，User Agent）**：
   - 用户与电子邮件系统的接口（常见的如 Foxmail、Outlook，或移动端邮件 App）；
   - 功能：撰写、显示、处理和阅读邮件。
2. **邮件服务器（Mail Server）**：
   - 电子邮件系统的核心功能实体，24 小时不间断运行在公网服务器上；
   - 功能：维护邮件发送队列、接收外部中继邮件、维护用户的个人电子邮箱目录，并处理邮件投递失败通知。
3. **邮件传输与访问协议**：
   - 规定了 UA 与服务器之间、以及服务器与服务器之间如何交换报文。

## 二、邮件发送协议：SMTP（推协议）

### 1. SMTP 的核心属性
- **简单邮件传送协议（SMTP，Simple Mail Transfer Protocol，RFC 821/5321）**；
- 属于**推协议（Push Protocol）**：负责将邮件由客户端“推”向服务器，或由发送方服务器向接收方服务器“推”进；
- **底层传输**：使用 **TCP 协议，熟知端口号为 `25`**。

### 2. SMTP 的通信时序阶段
SMTP 客户端与服务器之间的交互采用纯文本的“命令-应答”方式（类似于客户端说英语动词，服务器返回三位十进制状态码）：
1. **连接建立**：客户端发起向服务器 25 端口的 TCP 握手。建立后服务器发送 `220` 服务就绪，客户端发送 `HELO` 或 `EHLO` 自报家门；
2. **邮件传送**：
   - 客户端发送 `MAIL FROM: <sender@a.com>` 指示发件人地址；
   - 客户端发送 `RCPT TO: <receiver@b.com>` 指示收件人地址（可多次发送以支持群发）；
   - 客户端发送 `DATA` 请求传送邮件正文；
   - 服务器回复 `354` 开始输入，客户端发送邮件内容，**以单行的英文句点 `.` 加上换行回车（`\r\n.\r\n`）作为正文传输的结束标记**；
3. **连接释放**：客户端发送 `QUIT`，服务器回复 `221` 并关闭 TCP 连接。

### 3. SMTP 的历史缺陷与 MIME 扩展
- **历史缺陷（7 位 ASCII 限制）**：
  - SMTP 最初设计仅支持传输 **7 位的 ASCII 码文本**；
  - 无法直接传输中文等非拉丁双字节字符，更无法直接传输声音、图像、视频或二进制可执行文件；
- **通用互联网邮件扩充（MIME，Multipurpose Internet Mail Extensions，RFC 2045）**：
  - MIME 并没有废除或修改底层原有的 SMTP 协议；
  - **工作机制**：MIME 作为夹在用户代理与 SMTP 之间的适配器，定义了多用途的首部字段（如 `Content-Type`、`Content-Transfer-Encoding`）；
  - MIME 将任何非 ASCII 的多媒体或二进制数据，在发送端统一转换编码（如 Base64 编码）为纯 7 位 ASCII 字符流，交由 SMTP 传输；接收端用户代理收到后再根据 MIME 首部反向解码还原为原始多媒体文件。

## 三、邮件读取协议：POP3 与 IMAP（拉协议）

收件人通常不能直接通过 SMTP 接收邮件，因为用户的个人电脑或手机不可能 24 小时开机并拥有固定公网 IP 来监听 25 端口。邮件必须暂存在接收方邮件服务器的个人邮箱中，用户开机后主动**拉取（Pull）**。

### 1. 邮局协议版本 3（POP3，Post Office Protocol 3）
- 属于**拉协议（Pull Protocol）**，使用 **TCP 协议，熟知端口号为 `110`**；
- **工作模式**：
  - **下载并删除方式（Download-and-Delete）**：客户端将服务器上的邮件全部下载到本地电脑后，服务器立即从邮箱中删除该邮件；
  - **下载并保留方式（Download-and-Keep）**：客户端下载邮件后，在服务器上保留备份；
- **局限性**：POP3 协议极其简单，不支持客户端与服务器之间的状态双向同步。若用户在电脑上阅读了一封邮件，手机端 POP3 客户端无法同步已读状态，两端状态分裂。

### 2. 因特网报文访问协议（IMAP，Internet Message Access Protocol）
- 属于现代高级**拉协议**，使用 **TCP 协议，熟知端口号为 `143`**；
- **核心机制**：
  - **真正的全双工云端双向同步**：邮件始终保存在远端邮件服务器上；
  - 客户端操作（如标记已读、打星标、移动到自定义文件夹、删除）会即刻同步更新服务器状态，用户在多台设备（PC、手机、平板）间查看时状态高度一致；
  - **按需部分下载**：支持客户端只下载邮件的首部摘要或只下载正文，大附件可由用户决定是否按需下载，极大节省了移动网络流量。

## 四、基于万维网的电子邮件系统（Webmail）

现代用户广泛通过网页浏览器（如访问 `mail.google.com` 或 `mail.qq.com`）收发邮件：

```text
  [ 浏览器 Client A ]                                              [ 浏览器 Client B ]
          │                                                                ▲
          │ 1. HTTP/HTTPS 发信                                             │ 4. HTTP/HTTPS 收信
          ▼                                                                │
  [ 邮件服务器 A ] ─── 2. 邮件在服务器间中继: 【SMTP】 ───> [ 邮件服务器 B ] ┘
                     (基于公网标准 TCP 25 端口互联)
```

- **协议分工边界（核心机制边界）**：
  - 用户浏览器与本地邮件服务器之间的通信（发信和读信），**全部采用 HTTP/HTTPS 协议**；
  - **邮件服务器与外部邮件服务器之间的跨域邮件投递，依然严格必须使用标准的 SMTP 协议**！
