# 6.4 域名系统DNS


## 一、域名系统的诞生背景与层次化域名空间

### 1. 为什么不能直接记 IP 地址？
因特网上的路由器和网络设备只识别纯二进制或点分十进制的 IP 地址（如 `202.108.22.5`）。
- **痛点**：纯数字的 IP 地址缺乏人类可读性且极难记忆，且当服务器由于扩容、迁移更换机房改变 IP 时，用户无法感知；
- **解决机制**：引入 **域名系统（DNS，Domain Name System，RFC 1034/1035）**，建立一套全球分布式的、高可用的“名字到 IP 地址（以及反向 IP 到名字）”的映射转换数据库。

### 2. 层次化树状域名空间结构
因特网采用**分层次的树状命名结构**，域名从右向左书写，级别由高到低，不同级别之间用英文句点 `.` 分隔：

```text
                                  【 根 域 ( . ) 】
                                         │
              ┌──────────────────────────┼──────────────────────────┐
              ▼                          ▼                          ▼
       【 国家顶级域 nTLD 】      【 通用顶级域 gTLD 】      【 基础建设域 】
         .cn, .uk, .us              .com, .edu, .org                .arpa
              │                          │
              ▼                          ▼
       【 二级域名 】             【 二级域名 】
         .edu.cn, .gov.cn           google.com, baidu.com
              │                          │
              ▼                          ▼
       【 三级域名 】             【 三级域名 / 主机名 】
         pku.edu.cn, tsinghua.edu.cn    www.google.com, mail.google.com
```

- **顶级域名（TLD，Top-Level Domains）主要分类**：
  1. **国家顶级域名（nTLD）**：如 `.cn`（中国）、`.us`（美国）、`.uk`（英国）；
  2. **通用顶级域名（gTLD）**：如 `.com`（商业机构）、`.edu`（教育机构）、`.org`（非营利组织）、`.net`（网络服务机构）；
- **域名不区分大小写**：域名中的英文字母在 DNS 解析时不区分大小写（`WWW.PKU.EDU.CN` 与 `www.pku.edu.cn` 等价）；
- **标号长度限制**：单个标号不超过 63 个字符，完整域名的总长度不得超过 255 个字符。

## 二、四级域名服务器体系架构

为了避免集中式服务器的单点瘫痪和海量查询瓶颈，DNS 数据库被切分成数百万个分散的区域（Zone），部署在四级层级服务器上：

```text
+=================================================================================+
|                           1. 根域名服务器 (Root DNS Servers)                    |
|   (全网共有 13 个逻辑根域名服务器名字 a.root-servers.net ~ m.root-servers.net,   |
|    部署了全球数百台镜像任播集群。掌握所有顶级域名服务器的 IP 地址!)            |
+=================================================================================+
                                        ▲
                                        │ 指引下一级
                                        ▼
+=================================================================================+
|                       2. 顶级域名服务器 (TLD DNS Servers)                       |
|   (管理该顶级域下的所有二级域名。如负责 .com 的 TLD 服务器, 负责 .cn 的 TLD 服务器) |
+=================================================================================+
                                        ▲
                                        │ 指引下一级
                                        ▼
+=================================================================================+
|                    3. 权威/权限域名服务器 (Authoritative DNS Servers)           |
|   (负责某一个组织或单位内部的主机名解析。如管理 pku.edu.cn 的权威服务器,      |
|    最终给出该域名对应主机的真实公网 IP 地址!)                                  |
+=================================================================================+

-----------------------------------------------------------------------------------
【不属于上述树状层次、但最贴近用户终端的核心实体】:
+=================================================================================+
|                       4. 本地域名服务器 (Local DNS Server)                      |
|   (通常由本地校园网、企业网或接入 ISP 如电信/联通提供, 通常是网关自动分配的 DNS|
|    主机的每次 DNS 查询第一跳必定直接发给本地域名服务器, 起到代理查询与缓存核心枢纽)|
+=================================================================================+
```

## 三、DNS 查询的两大方式与完整微观时序

当主机发起解析请求（如解析 `www.pku.edu.cn`）时，DNS 查询分为 **递归查询（Recursive Query）** 与 **迭代查询（Iterative Query）** 两种工作模式：

### 1. 递归查询 vs 迭代查询的定义
- **递归查询（Recursive Query）**：“一步到位，负责到底”。被查询的服务器如果不知道答案，它必须以 DNS 客户端的身份替查询者向其他服务器继续追问，直到查出结果并原路返回给查询者；
- **迭代查询（Iterative Query）**：“指路模式，自行前往”。被查询的服务器如果不知道答案，它不替查询者追问，而是直接告诉查询者：“我不知道具体 IP，但你应该去问下一台服务器，它的 IP 地址是 $X$”，由查询者亲自去联系下一台服务器。

### 2. 因特网标准推荐查询时序（主机到本地递归，本地向外迭代）

```text
  [ 本机客户端 Host ]
         │
         │ 1. 递归查询: "请告诉我 www.pku.edu.cn 的 IP" (负责到底)
         ▼
  [ 本地域名服务器 Local DNS ]
         │
         ├─ 2. 迭代查询 ─────────> [ 根域名服务器 Root DNS ]
         │<─ 3. 告知: "去问 .cn 的 TLD 服务器, IP 是 A" ──┤
         │
         ├─ 4. 迭代查询 ─────────> [ 顶级域名服务器 TLD (.cn) ]
         │<─ 5. 告知: "去问 pku.edu.cn 的权威服务器, IP 是 B" ──┤
         │
         ├─ 6. 迭代查询 ─────────> [ 权威域名服务器 (pku.edu.cn) ]
         │<─ 7. 回复最终结果: "IP 地址是 162.105.131.8" ────────┤
         │
         │ 8. 原路返回最终 IP
         ▼
  [ 本机客户端 Host 获取到 IP, 开始发起 TCP 握手访问! ]
```

- **微观八步时序解析**：
  1. 主机向本地域名服务器发起查询，这一步通常采用**递归查询**；
  2. 本地域名服务器先查本地缓存，若未命中，向全球**根域名服务器**发起查询（采用**迭代查询**）；
  3. 根域名服务器回复指向 `.cn` 顶级域名服务器的 IP 地址；
  4. 本地域名服务器向 **`.cn` 顶级域名服务器** 发起迭代查询；
  5. 顶级域名服务器回复指向 `pku.edu.cn` 权威域名服务器的 IP 地址；
  6. 本地域名服务器向 **`pku.edu.cn` 权威域名服务器** 发起迭代查询；
  7. 权威域名服务器在其数据库中查到 `www.pku.edu.cn` 的正向 A 记录，返回真实 IP 地址；
  8. 本地域名服务器将结果写入本地高速缓存，并将最终 IP 返回给主机客户端。

## 四、DNS 协议底层传输与缓存机制

### 1. 传输层协议使用规则（UDP 53 vs TCP 53）
- **常规查询与响应**：默认使用 **UDP 协议，熟知端口号为 `53`**。
  - *设计依据*：单次 DNS 请求与响应通常只有几十字节，UDP 避免了三次握手与四次挥手的连接开销，极大降低了解析延迟。
- **何时切换为 TCP 53？**
  1. **响应报文长度超过 512 字节**：标准 UDP DNS 报文最大限制为 512 字节。若返回的解析记录过多导致首部 TC（截断标志位）置为 1，客户端必须切换为 TCP 协议重新发起查询；
  2. **DNS 区域传送（Zone Transfer）**：主 DNS 服务器与从 DNS 服务器之间同步完整的域名数据库文件时，数据量巨大且要求绝对可靠，强制使用 **TCP 53 端口**。

### 2. 高速缓存与生存时间（TTL）
- **加速机制**：为了大幅减轻根域名和顶级域名服务器的查询压力，各级域名服务器以及终端操作系统的 DNS 缓存服务都会将最近查询到的 `(域名, IP)` 映射暂存至本地内存；
- **生存时间（TTL，Time-To-Live）**：由权威域名服务器在返回资源记录时指定（以秒为单位）。在 TTL 倒计时结束前，后续针对该域名的查询直接在本地缓存命中返回；TTL 过期后自动失效，下次查询重新向权威服务器同步，保证了域名更新时的最终一致性。
