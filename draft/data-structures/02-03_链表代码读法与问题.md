# 链表｜代码读法与问题

## 1. `p`、`*p`、`p->next` 怎么读

```c
typedef struct Node {
    ElemType data;
    struct Node *next;
} Node;

Node *p;
```

假设 `p` 指向结点 A：

```text
p
|
v
[ data: A | next ] -----> [ data: B | next ] -----> [ data: C | NULL ]
```

```c
p                // A 的地址
*p               // A 这个完整结点
p->data          // A 的 data 字段
p->next          // A 的 next 字段中保存的地址，即 B 的地址
p->next->data    // B 的 data 字段
p->next->next    // B 的 next 字段中保存的地址，即 C 的地址
```

`next` 是当前结点里的一个字段，里面保存下一个**完整结点**的地址。它不是只指向下一个结点的 `data`。

下面两个赋值必须分清：

```c
p = p->next;     // 改变量 p：p 从 A 移到 B，链本身没变
p->next = q;     // 改 A 的 next 字段：A 的后继变成 q，链变了，p 没动
```

后面的链表算法，本质上都在安排这两类动作：游标怎样前进，链接何时改向。

## 2. `head`、首元结点、头结点

没有头结点时：

```text
head -----> [ A | next ] -----> [ B | NULL ]
              ^
              首元结点
```

`head` 是保存 A 地址的指针变量。若首元结点换了，必须直接修改 `head`。

带头结点时：

```text
head -----> [ 头结点 | next ] -----> [ A | next ] -----> [ B | NULL ]
                                      ^
                                      首元结点
```

头结点通常不存业务数据。它的作用是让首元结点也成为“某个结点的后继”，从而把表头处的改链和表中间的改链统一起来。题目是否带头结点，必须单独确认。

## 3. 四种链表改了哪里

### 单链表

```text
[ data | next ] -----> [ data | next ] -----> NULL
```

每个结点只知道后继，沿 `next` 单向前进。

### 双链表

```c
typedef struct DNode {
    ElemType data;
    struct DNode *prior;
    struct DNode *next;
} DNode;
```

```text
NULL <- [ prior | A | next ] <-> [ prior | B | next ] -> NULL
```

`prior` 是英文词，表示“在前的”；教材用它表示前驱指针。其他代码也常写 `prev`，`prev` 才是 `previous` 的缩写。

双链表增加的不只是“可以往前走”，还增加了一条一致性要求：

```text
A.next == B    时，应有    B.prior == A
```

只改一边，会出现向后能走、向前却断掉的链。

### 循环链表

尾结点不指向 `NULL`，而是指回头部：

```text
head -> A -> B -> C
        ^         |
        +---------+
```

不带头结点、`head` 指向首元结点时，可这样遍历：

```c
p = head;
do {
    visit(p);
    p = p->next;
} while (p != head);
```

若带头结点，尾结点通常指回头结点：

```c
for (p = head->next; p != head; p = p->next)
    visit(p);
```

循环链表不能用“走到 `NULL`”作为结束条件。

### 静态链表

```c
typedef struct {
    ElemType data;
    int next;
} SNode;

SNode space[MAXSIZE];
```

所有结点都待在预先分配的数组格子里，物理位置不动；`next` 保存数组下标，用下标决定逻辑上的后继：

```text
space[2].next = 7    // 逻辑上，2 号结点的后继是 7 号结点
```

顺序表默认“数组相邻就是逻辑相邻”；静态链表则由 `next` 下标另行规定逻辑次序。未使用的数组格子通常还会串成一条备用链。

## 4. 两次改链先看懂

### 在 `p` 后插入 `q`

```text
修改前：p -> B
修改后：p -> q -> B
```

```c
q->next = p->next;   // q 先接住 B
p->next = q;         // p 再改为指向 q
```

若先写 `p->next = q`，又没有提前保存 B 的地址，原来的后半条链就丢了。

### 删除 `p` 的后继

```text
修改前：p -> q -> B
修改后：p ------> B
```

```c
q = p->next;         // 记住要删除的结点
p->next = q->next;   // 让 p 越过 q，直接接到 B
free(q);
```

这两段已经包含单链表改链的核心：先保住以后还要访问的地址，再覆盖旧链接。

双链表还必须同时维护反向关系。例如把 `q` 插到 `p` 与 `p->next` 之间，除了让 `p->next = q`，还要保证新后继的 `prior` 最终指回 `q`。

## 5. 真正值得解决的问题

### 为什么“链表插入、删除是 `O(1)`”必须带条件？

已知要改链的位置或前驱时，只修改有限个指针，是 `O(1)`。

若只给“第 i 个结点”或“值为 x 的结点”，通常要先从头沿链定位；定位是 `O(n)`，所以整个操作仍是 `O(n)`。

```text
总时间 = 定位位置 + 修改链接
```

### 为什么反转前必须保存旧后继？

```c
q = p->next;     // 保存旧后继
p->next = pre;   // 当前箭头反向
pre = p;
p = q;           // 沿旧链继续
```

若先改 `p->next`，又没保存旧后继，剩余链就失去入口。每个结点被访问一次、改一次链接，所以反转是 `O(n)`。

### 两条有序链为什么是 `O(m+n)` 合并？

比较两条链当前的首个未处理结点，接走较小者，只让对应指针前进。每个结点接入结果链一次，不回头扫描。

因此总工作量是两条链长度之和 `m+n`，不是两两比较的 `mn`。

### 有序链表为什么不能直接二分到 `O(log n)`？

二分查找不仅要比较中间值，还要能迅速到达中间位置。数组可按下标 `O(1)` 到中点；单链表要从已有位置沿 `next` 逐结点走到中点。

有序性减少了比较方向，却没有提供随机定位能力，所以普通单链表查找仍是线性量级。

### 循环链表最容易错在哪里？

错误地等 `NULL`，或者让 `p` 初始等于 `head` 后先判断 `p != head`，导致循环一次也不执行。应使用 `do...while`，或在带头结点时从 `head->next` 出发、以回到 `head` 为终点。

### 静态链表的“静态”静在哪里？

静态的是数组格子的物理位置，不是逻辑链接。修改 `next` 下标仍可改变逻辑次序；只是在没有真实指针的环境里，用数组下标模拟地址。
