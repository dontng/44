# 栈、队列和数组｜代码读法与问题

## 1. 栈：`top` 到底指向哪里

栈只允许在同一端加入和取出元素，这一端叫栈顶。数组实现常见两种 `top` 约定，读代码时先确认采用哪一种。

### `top` 指向当前栈顶元素

```c
typedef struct {
    ElemType data[MAXSIZE];
    int top;
} SqStack;
```

```text
空栈：top == -1

下标       0       1       2
data    [  A  ]  [  B  ]  [  C  ]
                            ^
                           top
```

```c
S.data[++S.top] = x;   // 入栈：top 先上移，再写入
x = S.data[S.top--];   // 出栈：先读取栈顶，再让 top 下移
```

### `top` 指向下一个可写位置

```text
空栈：top == 0

下标       0       1       2       3
data    [  A  ]  [  B  ]  [  C  ]  [ 空 ]
                                    ^
                                   top
```

```c
S.data[S.top++] = x;
x = S.data[--S.top];
```

同样叫 `top`，一个指当前元素，一个指空位。不能脱离初始化和自增、自减的位置背公式。

### 链栈改变了什么

链栈通常让链表头部充当栈顶：

```text
top -> [ C | next ] -> [ B | next ] -> [ A | NULL ]
```

入栈和出栈只改表头附近的链接，不需要移动其他元素。链栈没有固定数组容量，但每个结点要额外保存指针。

## 2. 队列：`front` 与 `rear` 分别站在哪里

队列从队尾加入、从队头取出。常见顺序队列约定：

```text
front 指向当前队头元素
rear  指向下一个可写位置
```

```text
下标       0       1       2       3
data    [ 已出 ] [  B  ] [  C  ] [ 空 ]
                 ^                 ^
               front             rear
```

```c
Q.data[Q.rear++] = x;    // 入队
x = Q.data[Q.front++];   // 出队
```

元素出队后，数组前面的格子并没有自动搬回来。即使前面有空位，`rear` 走到数组末端仍会造成“假溢出”。循环队列就是为了解决这个问题。

链队列通常同时保存队头、队尾指针。若带头结点：

```text
front -> [ 头结点 ] -> [ A ] -> [ B ] <- rear
```

空队列时 `front == rear`，二者都指向头结点。入队在 `rear` 后接结点；出队摘下 `front->next`。若删掉的是最后一个数据结点，还要让 `rear` 回到头结点。

## 3. 循环队列：为什么空和满会撞在一起

数组长度为 `M` 时，指针到末端后用取模回到开头：

```c
Q.rear  = (Q.rear + 1) % M;
Q.front = (Q.front + 1) % M;
```

若只记录 `front` 和 `rear`，队列为空时有：

```text
front == rear
```

但所有格子都装满、`rear` 绕一圈追上 `front` 时，也会得到 `front == rear`。仅凭两个下标无法区分这两种状态。

常用处理是牺牲一个数组格子：

```text
空：front == rear
满：(rear + 1) % M == front
```

此时队列长度为：

```c
(rear - front + M) % M
```

也可以另设元素个数 `size` 或最近一次操作标志，不必牺牲格子。题目给出哪种约定，就按哪种约定判断容量、空满和长度。

## 4. 双端队列：受限的是哪一端

双端队列允许在两端插入、两端删除：

```text
左端 <== [ A ][ B ][ C ] ==> 右端
```

- 输入受限双端队列：只允许从一端输入，两端都可输出。
- 输出受限双端队列：两端都可输入，只允许从一端输出。

判断某个序列是否可能，不是背排列数量，而是从空队列开始按允许的端点一步步推进。普通栈和普通队列都可以看作双端队列进一步受限后的情况。

## 5. 栈为什么能解决这些问题

### 括号匹配

左括号入栈；遇到右括号时，它只能与最近尚未匹配的左括号配对，因此检查栈顶。类型不匹配、右括号到来时栈空、扫描结束后栈非空，都会失败。

每个字符至多入栈、出栈一次，时间是 `O(n)`，额外空间最坏为 `O(n)`。

### 表达式转换与求值

操作数可以直接输出或入数值栈；运算符不能一出现就都计算，因为优先级和括号可能要求它等待。运算符栈保存的是“已经看见、但还不能结算”的运算。

中缀转后缀时，读到新运算符，要比较它与栈顶运算符的优先级；该弹出的先弹出，括号只控制边界、不进入最终后缀表达式。

后缀表达式求值时：

```text
遇到操作数：入栈
遇到运算符：弹出右操作数，再弹出左操作数，计算后把结果入栈
```

减法和除法不能颠倒两个出栈值。每个记号被处理常数次，因此转换和求值都是 `O(n)`。

### 递归调用

一次函数调用还没结束就进入下一次调用，需要保存返回位置、参数和局部状态。系统调用栈按“最后进入的调用最先返回”恢复这些信息。

递归深度决定栈空间，不等于总时间。例如单分支递归可能深度 `O(n)`、总时间 `O(n)`；二叉递归深度可能只有 `O(n)`，调用总数却是指数级。分析时要分别数最大同时未返回的层数和全部调用次数。

## 6. 队列为什么能解决这些问题

### 层序遍历与广度优先搜索

先发现的结点应先扩展，所以把新发现但尚未处理的结点放到队尾，从队头取出下一个处理对象：

```text
发现对象 -> 入队等待
取队头   -> 处理并发现它的邻接对象
```

树的层序遍历中，每个结点入队、出队一次，时间为 `O(n)`。图的 BFS 中，若使用邻接表，每个顶点入队至多一次，每条边被检查常数次，时间为 `O(V+E)`。

### 缓冲与调度

生产者与消费者速度不一致时，队列把已经到达、尚未处理的对象暂存起来。先进先出保持到达顺序；若任务有优先级，则需要优先队列，不能再把它当普通 FIFO 队列。

队列本身的单次入队、出队通常是 `O(1)`；整个算法的时间仍取决于总共有多少对象进入队列，以及处理每个对象时还做了什么。

## 7. 数组地址：二维下标怎样落到一维内存

设二维数组 `A[rows][cols]` 按行优先存储，元素大小为 `w`，下标从 0 开始：

```text
A[0][0], A[0][1], ..., A[0][cols-1], A[1][0], ...
```

`A[i][j]` 前面有 `i` 个完整行和当前行的 `j` 个元素：

```c
offset = i * cols + j;
address = base + offset * w;
```

按列优先时则先跨过 `j` 个完整列：

```c
offset = j * rows + i;
```

地址计算是常数次算术，因此按下标访问是 `O(1)`。题目若从 1 开始编号，应先把行列下标各减 1，再代入零基公式。

## 8. 特殊矩阵为什么能压缩

压缩的前提不是“零很多”这一句，而是矩阵中有大量位置可以由规则推知，无须分别保存。

### 对称矩阵

`a[i][j] == a[j][i]`，所以上三角和下三角只需保存一份。若按行存下三角、使用 0 基下标，把任意位置先映射到：

```text
r = max(i, j)
c = min(i, j)
```

下三角第 `r` 行之前共有 `r(r+1)/2` 个元素，因此：

```c
k = r * (r + 1) / 2 + c;
```

这不是背两套上下三角公式，而是先利用对称性把坐标折到已存的一侧，再数前面有多少元素。

### 三角矩阵

上三角或下三角中的一侧按三角形存储；另一侧若全为同一个常量，只需额外留一个位置保存该常量。访问时先判断 `(i,j)` 位于存储三角、对角线，还是常量区。

### 三对角矩阵

只有主对角线及其上下各一条对角线可能非零，非零元素数量从 `n²` 降到约 `3n`。定位时先检查 `|i-j| <= 1`，再按行数出它前面实际保存了多少个带内元素。

真正要会的是从存储顺序重新推下标，而不是孤立背公式；首行和末行比中间行少一个元素，是最容易漏掉的边界。

## 9. 稀疏矩阵：为什么快速转置更快

稀疏矩阵没有固定的对称规则，但非零元素很少，可以只保存三元组：

```text
(row, col, value)
```

若三元组按原矩阵行号有序，转置后需要按原列号组织输出。

普通转置可以依次检查原矩阵的每一列，并扫描全部 `t` 个非零元寻找属于该列的元素。若列数为 `cols`，时间为：

```text
O(cols * t)
```

快速转置先做两件预处理：

1. 统计原矩阵每一列有多少个非零元；
2. 对这些数量做前缀累加，得到转置后每一行的起始写入位置。

随后只扫描全部三元组一次，把每个元素直接写到它应去的位置：

```text
统计列数：O(cols)
扫描三元组：O(t)
总时间：O(cols + t)
```

它快的原因不是“转置公式更好”，而是用计数和起始位置换掉了对全部三元组的反复扫描；代价是额外的计数与位置数组。
