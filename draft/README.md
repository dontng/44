# draft｜408 复习草稿区

`draft/` 保存可以跨设备继续的项目上下文。Codex CLI 在电脑上工作，iPhone 上的 GPT App Work 接力时，都以这里的文件为准；聊天记录可能丢失，不作为唯一依据。

## 目标

用王道章节保证知识面完整，用 `code/` 把定义、操作和应用落实为可运行代码，用专题草稿记录真正妨碍理解的问题，再用复杂度把各章算法横向串起来。

这是快速复习草稿，不是重写教材，也不是逐题 TLDR：

- 用户已四战，默认认识线性表、链表、树、图等名称，不从零扫盲。
- 不能只写一句定义。字段、指针、英文缩写、图和代码若可能产生歧义，要解释到能够继续读算法。
- 代码地图要覆盖章节骨架，但不要求把其中每种增删改查和全部边界一次练到满分。
- 当前内容已不妨碍后续理解，就结束本节；真题或复杂度讨论暴露问题时再回来补。

数据结构采用“建设完整、训练按需”的分工：`code/README.md` 负责替用户记住有哪些代码及它们位于哪里；各章源码负责提供统一、可编译的实现；`draft/data-structures/` 中的专题稿是可增删的理解记录，不承担代码覆盖职责，也不限制源码建设。

## 文件分工

```text
data-structures/        数据结构
computer-organization/ 计算机组成原理
operating-systems/      操作系统
computer-networks/      计算机网络
```

每科草稿目录内有两类文件；数据结构的正式代码另见 `code/`。

### 章节骨架

例如：

```text
ch02_线性表.md
ch03_栈队列和数组.md
```

骨架只保存王道章节和小节名称，用来确认全貌与位置。保持轻、小、稳定，不把聊天正文填进去。

### 数字专题稿

例如：

```text
02-03_链表代码读法与问题.md
03-00_栈队列和数组代码读法与问题.md
```

命名规则：

```text
章号-节号_自然标题.md
```

- 对应单节时使用真实节号，如 `02-03`。
- 覆盖整章时使用 `00`，如 `03-00`。
- 文件名必须以两位数字开头，便于跨客户端稳定排序。

专题稿承载解释、问题、代码、图、复杂度连接和快速回忆。新内容写进专题稿，不占用章节骨架。

## 一篇专题稿怎样写

先解决“怎么读”，再解决“哪里会出问题”。正文通常按以下顺序组织，但不强求机械套模板：

1. **读法说清**：直接解释字段、指针、下标、表达式和图分别表示什么。
2. **相邻对象对清**：说明结构变体究竟改了哪个字段、约束或终点条件。
3. **最小代码走通**：只写足以看清机制的代码，不扩成完整 CRUD 手册。
4. **问题直接解决**：问题用问句点出，紧接答案、推进过程和必要边界。
5. **复杂度接上**：说明数的基本动作、为什么只做这些次、快的前提和代价转移。
6. **快速回忆**：结尾留下几条能暴露含糊的短问题，方便手机复习。

好的解释应像当面对话：

```text
p = p->next;    // 游标移动，链没变
p->next = q;    // 结点字段改变，链变了
```

不能只写“单链表有 next，双链表有 prior”，也不要写“链表究竟链了什么”这类面向零基础的铺垫。

## 深度边界

专题稿需要解决：

- 一个表达式到底取到谁；
- 一条语句改变了变量、状态还是结构；
- 算法靠什么信息继续推进；
- 边界条件为什么与普通情况不同；
- 复杂度结论带着什么前提。

专题稿暂不追求：

- 所有操作的完整代码模板；
- 为覆盖而堆砌冷门题型；
- 把王道正文逐页改写；
- 用“全部会做”作为继续下一章的门槛。

这些边界只约束专题稿篇幅，不约束 `code/` 的章节覆盖。源码可以预先建全，实际复习时仍按当前考点只训练一小部分。

判断是否可以继续，只看当前理解能否支撑后续内容。不能，就补当前堵点；能，就往前走。

## 真题与复杂度怎样介入

- 王道章节决定应看见的全貌。
- 数字专题稿保存已经解决的堵点和算法机制。
- `src/` 真题能力线负责暴露问题，不负责替代教材全貌。
- `tldr/` 只在真实作答暴露缺口后做逐题诊断和验证。
- 复杂度是横向观察线：检查每个对象被处理几次、为何不回退、预先维护了什么，以及代价移到了空间、更新、输入条件还是最坏情况。

同一专题若没有真实问题，不为显得完整而继续加深。

## Codex CLI 与 GPT App Work 的接力规则

任何一次工作结束前，都把下面四件事落进仓库，而不是只留在聊天里：

1. 已确认的写作标准写进本 README；
2. 已解决的内容写进对应数字专题稿；
3. 当前覆盖状态更新到下方“当前进度”；
4. 下一次应读的文件和继续任务写清楚。

GPT App Work 接力时，先读：

```text
draft/README.md
对应学科的章节骨架
已有数字专题稿
```

然后按“当前进度”继续。不得根据一般教学经验擅自把任务改成零基础课程、题库或教材重写。

可直接交给 GPT App Work 的入口指令：

```text
先阅读 draft/README.md，把它当作本项目的持久上下文和执行规范；
再阅读当前学科的章节骨架与已有数字专题稿。
沿“当前进度”继续生成或修订专题稿，把所有关键判断写回仓库文件，
不要依赖当前聊天保存上下文。
```
