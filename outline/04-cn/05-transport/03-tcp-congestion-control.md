- **考察要点**：

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 流量控制 vs 拥塞控制：端系统局部视角 vs 网络全局容量
- **物理困境**：
  - **流量控制（Flow Control）**：属于**点对点**（端到端）的速率匹配机制。接收端处理速度有限，通过 TCP 报文首部的 `rwnd`（Receive Window）通知发送端抑制注入速率，防止接收端缓冲区溢出。
  - **拥塞控制（Congestion Control）**：属于**全局网络**层面的资源分配与保护机制。网络中存在大量路由器与链路，其排队缓冲区（Buffer）和带宽是共享资源。若所有主机根据接收端容量全速发送，中间路由器缓冲区将被填满并发生丢包，导致重传风暴与全局吞吐量雪崩（Congestion Collapse）。
- **统一约束方程**：
  发送端在任意时刻能够连续发送的最大字节数受限于两者的极小值：
  $$\text{swnd} = \min(\text{cwnd}, \text{rwnd})$$
  其中 `rwnd` 由接收端显式反馈，`cwnd`（Congestion Window）由发送端基于对网络拥塞状态的隐式探测动态调整。

### (2) 为什么采用 AIMD（加法增大，乘法减小）？
- **物理直觉**：
  - 网络容量未知且随时间剧烈波动。
  - 若采用乘法增大（MIMD），网络负荷将以几何级数逼近容量极限，由于网络反馈存在往返时延（RTT），极易产生严重超调（Overshoot）导致剧烈震荡与大面积丢包。
  - 加法增大（Additive Increase）：在线性探测阶段，每个 RTT 窗口仅增加 1 个 MSS，确保平缓逼近链路带宽极限，保持系统阻尼稳定。
  - 乘法减小（Multiplicative Decrease）：一旦察觉拥塞，立即将发送速率减半（或直接归一），迅速腾出缓冲区空间，为全网路由器提供泄洪窗口，阻止拥塞扩散。数学上，AIMD 能够证明在分布式竞争中收敛到高效率与公平性（Efficiency & Fairness Vector）。

### (3) 状态机与状态跃迁全景
TCP 拥塞控制通过慢启动门限（`ssthresh`）作为临界状态分水岭：

```
[连接建立]
    │
    ▼
[慢启动 Slow Start] ──────────────── (cwnd >= ssthresh) ────────────────► [拥塞避免 Congestion Avoidance]
    │                                                                             │
    ├─────────────── (3个重复ACK) ──────────────┐                                 │
    │                                            │                                 │
    │ (超时 RTO)                                 │ (3个重复ACK)                     │ (超时 RTO)
    ▼                                            ▼                                 ▼
[超时恢复] ◄─────────────────────────────────────┴────────────────────────────► [超时恢复]
    │                                            │                                 │
 ssthresh = cwnd / 2                          ssthresh = cwnd / 2               ssthresh = cwnd / 2
 cwnd = 1 MSS                                 cwnd = ssthresh + 3 MSS           cwnd = 1 MSS
 重新进入慢启动                                进入 [快恢复 Fast Recovery]         重新进入慢启动
```

#### ① 慢启动（Slow Start）
- **触发起点**：连接初建，或发生 RTO 超时之后。
- **增长规律**：每收到 1 个合法的确认报文（ACK），`cwnd` 增加 1 个 MSS。
  - 在无丢包且 ACK 逐一返回的情况下，经过 1 个 RTT，整个窗口内发送的所有报文都被确认，`cwnd` 翻倍：$1 \to 2 \to 4 \to 8 \dots$。
  - 物理意义：所谓“慢”，仅仅是**初始发送速率慢**（从 1 MSS 起步，避免连接刚建立就撑爆链路），但增长速度是**指数级爆炸增长**。

#### ② 拥塞避免（Congestion Avoidance）
- **触发切入点**：当 `cwnd >= ssthresh` 时。
- **增长规律**：每经过 1 个 RTT，`cwnd` 仅增加 1 个 MSS（即每个 ACK 到达时，$\text{cwnd} = \text{cwnd} + \frac{1}{\text{cwnd}} \times \text{MSS}$）。
- **物理意义**：由指数扩张转入线性探测，谨慎逼近瓶颈带宽。

#### ③ 超时（RTO 超时）与快重传（Fast Retransmit）的物理判别差异
- **RTO 超时（严重拥塞）**：
  - 发送端长时间未收到任何 ACK，说明整批报文或反向 ACK 在网络中遭遇严重丢包或断连。
  - **处置动作**：
    1. $\text{ssthresh} = \max(\lfloor \text{cwnd} / 2 \rfloor, 2)$
    2. $\text{cwnd} = 1\text{ MSS}$
    3. 重置 RTO 定时器，重新从**慢启动**开始。
- **3 个重复 ACK（轻度孤立丢包）**：
  - 接收端每收到一个失序报文（如收到 3、4、5，但缺失 2），都必须立即向发送端发送对缺失段的重复确认（ACK 2）。
  - 当发送端连续收到 3 个对同一报文的重复 ACK（累计 4 个相同 ACK）时，发送端能够确定：**网络仍然具备双向转发能力，后续报文已顺利到达对端，丢失很可能只是单个报文偶发受损或局部微拥塞**。
  - **处置动作（快重传）**：无需等待 RTO 定时器超时，立即重传缺失报文。

#### ④ 快恢复（Fast Recovery - TCP Reno）
- 在快重传之后执行，避免退回到 `cwnd = 1` 的深渊：
  1. $\text{ssthresh} = \lfloor \text{cwnd} / 2 \rfloor$
  2. $\text{cwnd} = \text{ssthresh} + 3\text{ MSS}$（将收到 3 个重复 ACK 的报文视为已离开发送管道，允许暂借 3 个缓冲额度）。
  3. 在快恢复期间，每多收到一个重复 ACK，`cwnd` 增加 1 MSS。
  4. 一旦收到新数据（重传段的累积确认）的 ACK，结束快恢复，令 $\text{cwnd} = \text{ssthresh}$，直接进入**拥塞避免**阶段（线性增长）。

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 传输层: TCP 滑动窗口与可靠传输 │
                     └──────────────┬───────────────┘
                                    │ swnd = min(cwnd, rwnd)
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 数据链路层: 流量控制与窗口限制 │         │ 网络层: 路由器队列管理与丢包 │
│  - 停等 / GBN / SR 机制      │ ◄────── │  - 队列溢出引发丢包超时      │
│  - 物理信道带宽时延积 (BDP)  │         │  - RED / ECN 显式拥塞通知    │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与数据链路层滑动窗口对比**：
   - 链路层滑动窗口针对**单段物理链路**，窗口上限由帧序号编码比特位数确定（如 GBN 的 $2^n-1$，SR 的 $2^{n-1}$），窗口大小通常在链路配置阶段静态设定。
   - 传输层 TCP 面向**端到端全网多跳链路**，不仅窗口受双方协商与拥塞探测动态调整，其确认机制兼顾累积确认（类似 GBN）与 SACK 选择确认（类似 SR）。
2. **与信道带宽时延积（BDP）的物理映射**：
   - $\text{BDP} = \text{Bandwidth} \times \text{RTT}$。
   - 网络管道的最大未确认载荷容量等于 BDP。若 $\text{cwnd} < \text{BDP}$，链路无法跑满，信道利用率低下；若 $\text{cwnd} > \text{BDP}$，多余的报文将在瓶颈路由器排队，导致 RTT 增大；一旦路由器队列溢出，则触发丢包与拥塞控制降速。

## 4. 闭环决策模型与核心认知结论

### (1) 考场计算与追踪核心准则
1. **单位统一**：
   - 必须看清题目是以 **MSS（报文段）** 为单位，还是以 **KB / Byte** 为单位。
   - 若题目给定 `MSS = 1KB`，则 1 MSS 与 1KB 数值等价；若未说明，按 MSS 数量纯计数迭代。
2. **RTT 周期步进与 cwnd 变化规律**：
   - **慢启动阶段**：每过 1 个 RTT，若未达 `ssthresh`，$\text{cwnd}_{t+1} = 2 \times \text{cwnd}_t$。
   - **触达阈值时刻**：若当前 `cwnd = 8`，`ssthresh = 12`，在下一个 RTT 期间，翻倍会跨越阈值，则先指数增长到 12，再转为线性增长（严格依题意按整轮结算还是逐 ACK 结算）。
   - **拥塞避免阶段**：每过 1 个 RTT，$\text{cwnd}_{t+1} = \text{cwnd}_t + 1$。
3. **拥塞降速动作分流**：
   - **如果判定为“超时 / 严重拥塞”**：
     $$\text{ssthresh} = \max(\lfloor \text{cwnd} / 2 \rfloor, 2), \quad \text{cwnd} = 1$$
   - **如果判定为“连续收到 3 个重复 ACK / 快重传 / 轻微拥塞”**：
     $$\text{ssthresh} = \lfloor \text{cwnd} / 2 \rfloor, \quad \text{cwnd} = \text{ssthresh} \quad (\text{或 Reno 快恢复 } \text{ssthresh} + 3)$$
