## 1. 考纲考点与核心认知

- **考纲考察要点**：
  - 单帧滑动窗口（停止-等待协议，Stop-and-Wait）机制与性能瓶颈；
  - 多帧滑动窗口：后退 N 帧协议（GBN）与选择重传协议（SR）的运行机理；
  - 确认策略（累计确认 vs 独立逐帧确认）与超时重传动作；
  - 帧序号比特数 $n$ 与发送窗口 $W_T$、接收窗口 $W_R$ 的数学不等式推导；
  - 信道利用率与有效吞吐率的严格分段饱和方程（利用率上限 $U \le 100\%$ 约束）。

## 2. 核心机理与五步推演

### (1) 为什么必须引入滑动窗口协议？

#### ① 物理矛盾：停止-等待协议的信道利用率坍塌
在长距离、高带宽链路中（例如卫星通信或光纤广域网，往返传播时延 $\text{RTT}$ 极大）：
- 若采用**停止-等待协议**（发送窗口 $W_T = 1$，接收窗口 $W_R = 1$）：
  发送方在发送完毕一个数据帧后，必须静止等待一个完整的往返时延 $\text{RTT}$，直到收到接收方的确认帧 ACK 才能发送下一帧。
- **信道利用率物理困境**：
  设数据帧长 1000 字节，传输速率 100 Mbps，发送时延 $T_f = 0.08\text{ ms}$；若单向传播时延为 $50\text{ ms}$（$\text{RTT} = 100\text{ ms}$）：
  $$U = \frac{T_f}{T_f + \text{RTT}} = \frac{0.08}{0.08 + 100} \approx 0.08\%$$
  信道在 $99.92\%$ 的时间内处于完全空置的死寂状态，物理带宽被严重荒废。

#### ② 滑动窗口的设计哲学：管道流水线填满
滑动窗口机制允许发送端在收到前一帧的确认之前，**连续将多个数据帧注入信道**，使信道中始终充盈着前行的数据帧和返航的 ACK 帧。通过增大发送窗口 $W_T$，彻底填平信道的**带宽时延积（BDP, Bandwidth-Delay Product）**。

### (2) 三大滑动窗口协议全景横向对比

| 协议类型 | 发送窗口 $W_T$ | 接收窗口 $W_R$ | 确认机制与 ACK 内容 | 乱序到达处理 | 超时重传策略 | 接收端缓存 |
| :--- | :---: | :---: | :--- | :--- | :--- | :---: |
| **停止-等待 (Stop-and-Wait)** | 1 | 1 | 逐帧确认（仅确认当前帧） | 丢弃 | 仅重传当前单帧 | 无 |
| **后退 N 帧 (GBN)** | $> 1$ | **严格为 1** | **累计确认（Cumulative ACK）** | **直接丢弃，不予缓存** | **全量回退，重传自超时帧起的所有未确认帧** | **无（必须严格按序接收）** |
| **选择重传 (SR)** | $> 1$ | **$> 1$** | **非累计独立确认（Individual ACK）** | **接收并放入缓冲区暂存** | **精准重传，仅重发真正超时的那一个损坏/丢失帧** | **有（缓存失序到达的帧）** |

### (3) 窗口尺寸与序号位数 $n$ 的数学物理硬约束

设帧序号采用 $n$ 位二进制编码，序号空间模数为 $2^n$（编号范围 $0 \sim 2^n - 1$）。

#### ① 后退 N 帧协议（GBN）的窗口约束推导
- **物理绝境（新旧帧序号重叠混淆）**：
  若发送窗口 $W_T > 2^n - 1$（例如 $n=3$，总序号 8 个，若设 $W_T = 8$）：
  1. 发送方连续发射帧 `[0, 1, 2, 3, 4, 5, 6, 7]`；
  2. 接收方全部正确接收，接收窗口向前滑动到新一轮的 `0` 号；
  3. 假如此时所有的反向确认帧在信道中全部丢失；
  4. 发送方定时器超时，触发全量回退重传，重新发送老一轮的 `0` 号帧；
  5. **接收端逻辑混乱**：接收方当前正在翘首期待新一轮的 `0` 号帧，面对到来的老 `0` 号帧，**根本无法在数学上区分这是“新一轮的数据”还是“老一轮的重发”**，导致静默数据重复入库！
- **数学硬性约束**：
  $$1 < W_T \le 2^n - 1 \quad \text{且} \quad W_R = 1$$
  *(例如 $n=3$ 时，GBN 最大发送窗口严格为 $2^3 - 1 = \mathbf{7}$，绝不能取 8)*。

#### ② 选择重传协议（SR）的窗口约束推导
- **物理绝境（接收窗口前移与发送窗口重传交叠）**：
  在 SR 中，接收方拥有大小为 $W_R$ 的接收缓存窗口。为了保证“接收窗口接收完毕向前滑动后的最新范围”与“发送方超时可能重发的最老未确认帧的序号范围”在模 $2^n$ 下没有任何交集：
- **数学硬性约束**：
  $$W_T + W_R \le 2^n$$
  **在对称常规设计下（令 $W_T = W_R$）**：
  $$W_T \le 2^{n-1} \quad \text{且} \quad W_R \le 2^{n-1}$$
  *(例如 $n=3$ 时，SR 的最大发送和接收窗口均为 $2^{3-1} = \mathbf{4}$，必须对半切分)*。

### (4) 状态追踪：丢包与重传极简执行时序

以 $n=3$（序号 $0 \sim 7$）为例，设定发送窗口 $W_T = 4$。发送方发射帧 `0, 1, 2, 3`，其中**帧 1 在信道中发生比特差错丢失**。

#### ① GBN 执行追踪（回退全发）
```
发送方:  [发 0] ──[发 1 (丢包)]── [发 2] ───────── [发 3] ────────────────────────►
          │                          │                │
接收方:   ▼                          ▼                ▼
         [收 0, 回 ACK 0]          [收到2: 乱序丢弃!] [收到3: 乱序丢弃!]
                                   [重回 ACK 0]     [重回 ACK 0]
          │
发送方:  收到 ACK 0 (窗口滑移); 帧 1 定时器超时!
         ──[重发 1] ─── [重发 2] ─── [重发 3] ────────────────────────────────►
```
- **机制真相**：接收方由于 $W_R = 1$，面对失序的帧 2 和帧 3，没有存储缓存能力，只能无情丢弃；发送方超时后不仅重传丢失的帧 1，连同后续已成功送达的帧 2、帧 3 也必须**全盘重传**，浪费信道带宽。

#### ② SR 执行追踪（局部缓存与精准重发）
```
发送方:  [发 0] ──[发 1 (丢包)]── [发 2] ───────── [发 3] ────────────────────────►
          │                          │                │
接收方:   ▼                          ▼                ▼
         [收 0, 回 ACK 0]          [收 2, 缓存!]     [收 3, 缓存!]
         [窗口移至 1..4]           [回 ACK 2]       [回 ACK 3]
          │                          │                │
发送方:  收到 ACK 0; 收到 ACK 2 (标记2已收); 收到 ACK 3 (标记3已收);
         仅【帧 1】定时器超时!
         ──[精准重传 1] ───────────────────────────────────────────────────────►
                                     │
接收方:                              ▼
                                    [收到补发的 1, 拼合 1, 2, 3 连贯数据!]
                                    [回 ACK 1, 下沿从 1 移至 4，移动 3 格，新窗口 4..7]
```

#### ③ ACK 编号语义的两套考场约定辨析
在做历年习题时，必须首先通过题干判明其采用的确认号语义：
- **约定 1（期待下一帧法，类似 TCP 逻辑）**：
  若接收方回复 `ACK 3`，其含义是**“前 2 号及之前的帧已全部正确收妥，我正期待接收第 3 号帧”**；
- **约定 2（累计已收到法）**：
  若接收方回复 `ACK 3`，其含义是**“第 3 号帧及其以前的帧均已正确接收”**。

### (5) 信道利用率与吞吐率的严格分段饱和方程

很多初学者容易盲目套用线性公式，计算出利用率大于 $100\%$ 的荒谬结果。

#### ① 物理参数与分段定义
- $T_f = \frac{L}{C}$：数据帧的发送时延（$L$ 为帧长，$C$ 为数据传输速率）；
- $\text{RTT}$：往返传播时延；
- $T_{\text{ack}}$：确认帧的发送时延（若题干说明“确认帧很短可忽略”，则 $T_{\text{ack}} \approx 0$）；
- $t_{\text{proc}}$：节点处理时延（通常忽略）。

从发送方开始发送第一个比特，到收到该帧对应的 ACK 并能继续释放窗口所经历的一个完整周期时间为：
$$T_{\text{cycle}} = T_f + \text{RTT} + T_{\text{ack}}$$

#### ② 分段与饱和封顶方程
若发送窗口为 $W$，在一个往返周期内发送端最多能够连续发出 $W \times T_f$ 时间的数据。

信道利用率 $U$ 的**严格数学定义是发送端实际发射数据的时间与总消耗时间之比**，物理极限绝不能超过 1（100%）：
$$U = \min\left(1, \quad \frac{W \times T_f}{T_f + \text{RTT} + T_{\text{ack}}}\right)$$

- **信道有效吞吐率（Throughput）**：
  $$\text{Throughput} = U \times C$$

#### ③ 临界饱和窗口大小推导
要让信道利用率达到极致的 $100\%$（流水线完全填满，发送端毫无空转等待）：
$$\frac{W \times T_f}{T_f + \text{RTT} + T_{\text{ack}}} \ge 1 \implies W_{\min} = \left\lceil \frac{T_f + \text{RTT} + T_{\text{ack}}}{T_f} \right\rceil$$

#### ④ 两组定性定量数值算例对比

设链路传输速率 $C = 10\text{ Mbps}$，数据帧长 $L = 1250\text{ 字节}$（则 $T_f = \frac{1250 \times 8}{10 \times 10^6} = 1\text{ ms}$）。往返时延 $\text{RTT} = 5\text{ ms}$，确认帧时延忽略（$T_{\text{ack}} = 0$）。
单周期基准耗时 $T_{\text{cycle}} = 1\text{ ms} + 5\text{ ms} = 6\text{ ms}$。达到 100% 饱和所需的最小窗口为：
$$W_{\min} = \frac{1 + 5}{1} = 6$$

1. **场景 A（未饱和状态，窗口 $W = 3 < W_{\min}$）**：
   $$U = \frac{3 \times 1\text{ ms}}{6\text{ ms}} = \mathbf{50\%} < 100\%$$
   $$\text{Throughput} = 50\% \times 10\text{ Mbps} = 5\text{ Mbps}$$
2. **场景 B（过饱和状态，窗口 $W = 8 > W_{\min}$）**：
   - 若不加封顶盲目计算：$\frac{8 \times 1}{6} = 133.3\%$（错误！利用率绝不可能大于 1）；
   - 正确分段计算：
     $$U = \min\left(1, \quad \frac{8 \times 1}{6}\right) = \mathbf{100\%}$$
     $$\text{Throughput} = 100\% \times 10\text{ Mbps} = 10\text{ Mbps}$$

### (6) 典型反例证伪（常见认知陷阱）

1. **反例 1：“只要增大发送窗口 $W$，信道的利用率和吞吐率就可以无限成倍增加。”**
   - **反例证伪**：错误。当窗口增大到临界饱和窗口 $W \ge W_{\min}$ 后，信道发射机已处于 100% 满负荷流水线发射状态，信道物理利用率饱和封顶在 100%，吞吐率被物理带宽 $C$ 锁定，无法再增加。
2. **反例 2：“后退 N 帧（GBN）协议中，由于支持连续发送，所以接收方必须具备保存失序帧的接收缓冲区。”**
   - **反例证伪**：错误。GBN 的接收窗口尺寸严格恒等于 1（$W_R = 1$），接收端只认当前期待的唯一序号。任何失序帧即使完好到达也会被无情直接丢弃，不设任何失序接收缓冲区。
3. **反例 3：“在 3 位序号编码下（$0 \sim 7$），GBN 的发送窗口最大可以设置为 8。”**
   - **反例证伪**：若设为 8，一旦 8 个帧全部发出且所有 ACK 全部丢失，超时重发的老 0 号帧会被接收方误判为新一轮的 0 号帧接收，发生新旧帧混淆。因此 GBN 发送窗口上限严格为 $2^n - 1 = 7$。

## 3. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型（学理解题口径） | 现代工程实现边界（工业级协议规范） |
| :--- | :--- | :--- |
| **滑动窗口单位** | **以“数据帧（Frame）”为离散计数单位** | 传输层 **TCP 以“字节（Byte）”为流式单位**，数据链路层 HDLC 仍以帧为单位 |
| **重传与确认粒度** | 严格区分 GBN 纯累计确认与 SR 纯单独确认两分法 | 现代 TCP 采用 **SACK（选择确认选项，RFC 2018）**：在累计确认的主流框架下，通过 TCP 选项字段携带非连续块的左右边界，兼具 GBN 简便与 SR 局部重传优势 |
| **往返时延测算** | 题目通常给定恒定的静态固定 $RTT$ | 现实网络中 RTT 动态剧烈抖动，采用 **Jacobson / Karn 算法**通过指数加权移动平均动态估算平滑 RTT 与超时重传时间 RTO |

## 4. 跨章节与跨学科关联

### 1. 本学科内跨章节关联
- $\to$ 关联 [计算机网络性能指标与时延计算](../01-architecture/02-performance-delays.md)：
  - **共同机制**：信道利用率计算深度依赖传输时延 $T_f$ 与传播时延 $T_p$ 的比值关系。
  - **关键差异**：性能指标单节侧重物理时延分类；滑动窗口在此基础上引入协议反馈回路与窗口并发机制。
  - **不可直接迁移的判据**：当往返时延 $\text{RTT} \to 0$ 时，停止-等待协议即可达到接近 100% 的利用率，此时无需费力启用复杂的大窗口 GBN/SR 协议。
- $\to$ 关联 [TCP 连接管理与流量控制](../05-transport/02-tcp-connection-and-flow.md)：
  - **共同机制**：均利用滑动窗口机制实现流量控制与差错恢复。
  - **关键差异**：链路层窗口受限于物理帧序号比特数 $n$（通常 3 位）；TCP 拥有 32 位序号空间，窗口受接收方通告窗口 `rwnd` 与拥塞窗口 `cwnd` 动态取小调节。
  - **不可直接迁移的判据**：链路层帧确认丢失可能引发 GBN 全量重传；TCP 收到 3 个重复 ACK 会触发快速重传，无需等待全量超时。

### 2. 跨学科协同关联
- $\to$ 关联 [计算机组成原理 / 指令流水线与冒险处理](../../02-co/05-cpu/03-pipeline-hazards.md)：
  - **共同机制**：滑动窗口连续发送与 CPU 指令流水线的设计哲学完全相通，均是通过流水线重叠执行消除等待气泡。
  - **关键差异**：CPU 指令流水线在芯片内部以纳秒为单位推移，依靠硬件旁路（Bypassing）消除数据冒险；网络滑动窗口跨越广域网以毫秒为单位推移，依靠网络 ACK 确认帧消除差错。
  - **不可直接迁移的判据**：指令流水线分支预测失败需冲刷整个流水线（类似 GBN 全量回退）；但网络丢包在 SR 协议下支持乱序暂存，不可套用流水线冲刷的结论。

## 5. 核心考点自查清单与闭环判据

1. **窗口与序号硬性不等式**：
   - GBN：$W_R = 1, \quad 1 < W_T \le 2^n - 1$
   - SR（对称）：$W_T = W_R \le 2^{n-1}$
2. **信道利用率封顶计算**：
   $$U = \min\left(1, \quad \frac{W \times T_f}{T_f + \text{RTT} + T_{\text{ack}}}\right)$$
   - 结果绝不能大于 $100\%$；
   - 临界饱和窗口：$W_{\min} = \lceil (T_f + \text{RTT} + T_{\text{ack}}) / T_f \rceil$。
3. **协议重传特征区分**：
   - GBN：接收端无缓存，丢弃失序帧，累计确认，全量回退重传；
   - SR：接收端有缓存，暂存失序帧，单帧独立确认，精准局部重传。
