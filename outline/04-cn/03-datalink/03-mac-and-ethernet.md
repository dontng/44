## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - 介质访问控制（MAC）三大协议族体系：信道划分（静态）、随机访问（动态争用）、轮询访问（受控无争用）。
  - CSMA/CD 协议的核心机理（先听后发、边发边听、冲突停发、随机重发）。
  - 争用期（碰撞窗口 $2\tau$）与最小帧长 $L_{\min} = 2\tau \times R$ 的物理必然性推导。
  - **截断二进制指数退避算法（Truncated Binary Exponential Backoff）** 的完整步骤、随机退避范围与 16 次重传失败丢弃机制。
  - Ethernet V2（DIX）以太网 MAC 帧格式详解、前导码与 $64\text{ B} \sim 1518\text{ B}$ 帧长边界、填充字段（Padding）。
  - **以太网交换机（透明网桥）自学习与帧转发机制**：MAC 地址表动态构建、未知单播泛洪（Flooding）、精准单播、同网段过滤（Filtering）与老化时间（Aging Time）。
- **思维摩擦点（为什么容易错）**：
  - **混淆物理层前导码与 MAC 帧长**：以太网物理层在发送 MAC 帧前附加了 8 字节的前导码（7 字节前同步码 + 1 字节帧开始定界符 SFD），但这 8 字节仅用于物理时钟同步，**绝对不计入以太网 MAC 帧的 $64\text{ B} \sim 1518\text{ B}$ 长度范围**！
  - **截断退避算法中的截断参数 $k$**：$k = \min(n, 10)$，当重传次数 $n > 10$ 时，随机数上限不再继续翻倍，而是被冻结在 $2^{10} - 1 = 1023$；达到 16 次仍碰撞才彻底放弃。
  - **误以为交换机的“泛洪”等同于“广播帧”**：目的 MAC 为全 F 的广播帧必定泛洪；但对于目的 MAC 未记录在表中的未知单播帧，交换机同样执行泛洪操作，但该帧的协议属性依然是单播。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 介质访问控制（MAC）三大分类全景

在共享传输信道中，若多个节点同时发射信号，电平叠加会导致信号畸变损坏（冲突/碰撞）。介质访问控制协议负责分配信道使用权：

| MAC 分类 | 核心代表协议 | 信道分配机理与冲突特征 | 负载适应性 | 机制分水岭 |
| :--- | :--- | :--- | :--- | :--- |
| **信道划分 MAC** (静态划分) | **FDM**（频分）、**TDM**（时分）、**WDM**（波分）、**CDM**（码分） | 依靠物理维度（频率、时隙、波长、正交正负码片）将单一物理信道静态切分为多个互不干扰的逻辑子信道。**绝对无冲突**。 | 适合重负载且流量平稳的通信（如电信骨干网）；突发轻负载时未用时隙被浪费。 | 通过物理正交性提前固化信道分配，消除动态协调开销 |
| **随机访问 MAC** (动态争用) | **纯 ALOHA**、**时隙 ALOHA**、**CSMA**（1-坚持、非坚持、$p$-坚持）、**CSMA/CD**、**CSMA/CA** | 所有节点根据需要随时竞争发送，不预先分配。**存在发生碰撞冲突的可能**，发生冲突后各节点退避重发。 | 适合轻负载、高突发性的局域网通信；重负载时碰撞率飙升，吞吐量趋于归零。 | 允许冲突自由发生，依托冲突检测与退避重传来化解争用 |
| **轮询访问 MAC** (受控无争用) | **集中式轮询 (Polling)**、**令牌环 (Token Ring)** | 依靠中央主节点轮询或物理/逻辑环上传递微小“令牌帧（Token）”。仅持有令牌的节点允许发送。**完全无冲突**。 | 适合中高负载网络；轻负载时令牌在空闲节点间巡回带来不必要的时延开销。 | 动态循环移交单一发射权，兼顾无冲突与负载公平 |

#### 随机访问演进链条与冲突窗口

```
1. 纯 ALOHA
   - 机制: 任何节点想发就发。发完通过 ACK 确认，若超时未收到则认为碰撞。
   - 冲突危险期: 2 * T0 (T0 为单帧发送耗时)。
   - 最大吞吐率: S_max = 1 / (2e) ≈ 18.4%

2. 时隙 ALOHA (Slotted ALOHA)
   - 机制: 将时间硬性划分为等长时隙 T0，节点只允许在时隙起始点发射。
   - 冲突危险期: 减半为 T0 (前一个时隙产生的帧不会波及后一个时隙)。
   - 最大吞吐率: S_max = 1 / e ≈ 36.8% (吞吐率翻倍)

3. 载波监听多路访问 (CSMA)
   - 机制: 发送前先听信道 (Carrier Sense)。
     * 1-坚持: 忙则一直听，一旦空闲立即以概率 1 发送 (可能有多人同时听完空闲一起发，冲突率高)。
     * 非坚持: 忙则放弃监听，随机延迟一段时间后再来听 (降低了冲突率，但信道可能出现空闲浪费)。
     * p-坚持: 忙则一直听，一旦空闲以概率 p 发送、以概率 (1-p) 推迟到下一时隙 (兼顾信道利用与防冲撞)。

4. 带碰撞检测的 CSMA (CSMA/CD，经典以太网)
   - 机制: 先听后发，边发边听，冲突停发，随机重发。
```

### (2) CSMA/CD 协议的核心物理机理与三大公式

#### ① 争用期（碰撞窗口，Contention Period）
- **单程传播时延 $\tau$**：电磁波在以太网同轴电缆或双绞线中传播的物理速度 $v \approx 2 \times 10^8\text{ m/s}$。设总线两端最远两台主机相距 $D$，则 $\tau = \frac{D}{v}$。
- **争用期为 $2\tau$ 的物理必然性**：
  - 设主机 A 在 $t = 0$ 开始发送数据；
  - 信号在 $t = \tau - \epsilon$ 时刻即将到达最远端主机 B，此时主机 B 刚刚监听信道发现空闲，也启动发送；
  - 两台主机的信号在距离 B 极近处发生碰撞；
  - 碰撞产生的破坏电平波反向传回主机 A，主机 A 收到碰撞信号的时刻为 $t = (\tau - \epsilon) + \tau = 2\tau - \epsilon \approx 2\tau$。
  - **结论**：主机发送数据后，**经过 $2\tau$ 的时间即可断定本次发送是否遭遇了碰撞**。因此，$2\tau$ 被称为**争用期（碰撞窗口）**。

#### ② 最小帧长公式（以太网核心物理铁律）
- **物理底线**：在最坏碰撞信号传回发送端之前，**发送端必须还没有把该帧发送完毕**！若帧太短，主机早早就把整个帧发完并释放了总线，远处传回的碰撞波到达时，主机网卡以为刚才发送成功，根本不知道帧已受损，导致数据静默丢失且无法重传。
- **严谨推导公式**：
  $$L_{\min} = 2\tau \times R = \frac{2D}{v} \times R$$
  - $R$：数据传输速率（如 $10\text{ Mb/s}$）；$L_{\min}$：最小帧长（比特）。
- **标准以太网常数**：
  传统 $10\text{ Mb/s}$ 以太网规定争用期 $2\tau = 51.2\text{ }\mu\text{s}$（对应 512 比特时间）：
  $$L_{\min} = 10\text{ Mb/s} \times 51.2\text{ }\mu\text{s} = 512\text{ bits} = \mathbf{64\text{ Bytes}}$$
  - **考场判据**：凡是在半双工以太网中检测到的长度**小于 64 字节的帧，一律判定为因冲突而异常中止的残存碎片帧（Runt Frame）**，接收方网卡硬件直接丢弃！

### (3) 截断二进制指数退避算法（Truncated Binary Exponential Backoff）

当检测到碰撞后，节点停止发送并发送 32~48 位的强化碰撞干扰信号（Jamming Signal），随后按照以下 4 步计算随机退避等待时间：

```
步骤 1: 确定基本退避时间为争用期 2τ (以太网标准为 51.2 μs，即 512 比特时间)。
步骤 2: 设当前帧已遭遇的连续碰撞次数为 n (初始 n = 1)。
        计算退避参数 k = min(n, 10)。
步骤 3: 从离散整数集合 [0, 1, 2, ..., 2^k - 1] 中，等概率随机取出一个整数 r。
        计算本次推迟发送的退避等待时间:
                  T_backoff = r * 2τ
步骤 4: 重传判定:
        - 若当前重传次数 n <= 16: 等待 T_backoff 时间后，重新开始载波监听准备发送；
        - 若重传次数达到 n = 16 次仍发生碰撞: 说明网络极度过载或物理链路短路，
          彻底丢弃该帧，并向高层网络协议上报传输失败异常！
```

#### 手算算例追踪表

| 碰撞次数 $n$ | 退避参数 $k = \min(n, 10)$ | 离散随机整数取值集合 $r$ | 随机可选状态数 $2^k$ | 退避时间范围 ($2\tau = 51.2\mu\text{s}$) |
| :---: | :---: | :--- | :---: | :--- |
| **第 1 次** | $k = 1$ | $\{0, 1\}$ | 2 个 | $0\text{ 或 } 51.2\text{ }\mu\text{s}$ |
| **第 2 次** | $k = 2$ | $\{0, 1, 2, 3\}$ | 4 个 | $0 \sim 153.6\text{ }\mu\text{s}$ ($r \times 51.2$) |
| **第 3 次** | $k = 3$ | $\{0, 1, 2, \dots, 7\}$ | 8 个 | $0 \sim 358.4\text{ }\mu\text{s}$（若取 $r=5$，等待 $256\mu\text{s}$） |
| $\dots$ | $\dots$ | $\dots$ | $\dots$ | $\dots$ |
| **第 10 次** | $k = 10$ | $\{0, 1, 2, \dots, 1023\}$ | 1024 个 | $0 \sim 52.38\text{ ms}$ |
| **第 11~15 次** | **$k = 10$ (截断)** | $\{0, 1, 2, \dots, 1023\}$ (集合不再扩大) | 1024 个 | $0 \sim 52.38\text{ ms}$ |
| **第 16 次** | $k = 10$ | 试发第 16 次仍碰撞 $\to$ **直接丢弃该帧，不再重传** | - | 向上层上报致命错误 |

### (4) Ethernet V2（DIX）以太网 MAC 帧格式

```
 物理层前导码 (8B，不计入帧长)                                MAC 帧 (64B ~ 1518B)
┌─────────────────┬──────────┬──────────┬──────────┬──────────┬──────────────────────┬──────────┐
│  前同步码 (7B)  │ SFD (1B) │ 目的 MAC │  源 MAC  │ 类型 Type│   数据载荷 Payload   │ FCS 校验 │
│ 101010...101010 │ 10101011 │   (6B)   │   (6B)   │   (2B)   │     (46B ~ 1500B)    │   (4B)   │
└─────────────────┴──────────┴──────────┴──────────┴──────────┴──────────────────────┴──────────┘
```

#### 字段深度拆解与物理边界：
1. **物理层前导码（Preamble）**：
   - 7 字节前同步码（`101010...`）：交替的高低电平，使接收端网卡硬件的时钟频率与发送端完全锁定同步；
   - 1 字节帧开始定界符（SFD，`10101011`）：最后连续两个 `1` 声明物理帧真正开始。
   - **严谨考据**：**物理层这 8 字节在到达网卡 MAC 芯片前已被剥除，绝不计入 MAC 帧长范围**。
2. **目的 MAC 地址（6 字节 / 48 位）** 与 **源 MAC 地址（6 字节 / 48 位）**：
   - 固化在网卡 ROM 中，全球唯一。单播帧目的 MAC 第一字节最低位为 0，组播为 1，广播为全 1（`FF-FF-FF-FF-FF-FF`）。
3. **类型字段（Type，2 字节）**：
   - 标识网络层交由哪个协议处理：`0x0800` 表示 IPv4 数据报，`0x0806` 表示 ARP 请求/应答，`0x86DD` 表示 IPv6。
4. **数据载荷（Payload，46 ~ 1500 字节）**：
   - **上限 1500 字节**：即以太网的最大传输单元（MTU = 1500 B）；
   - **下限 46 字节与填充字段（Padding）**：由于最小 MAC 帧长必须为 64 字节，扣除首部（目的 6B + 源 6B + 类型 2B = 14B）和尾部（FCS 4B）共 18 字节后，**载荷部分最少必须有 $64 - 18 = 46$ 字节**！若 IP 分组不足 46 字节（如仅 20 字节），数据链路层必须在载荷末尾填充 Padding 补足到 46 字节。
5. **帧检验序列（FCS，4 字节）**：
   - 采用 CRC-32 循环冗余校验码，校验范围涵盖目的 MAC、源 MAC、类型、载荷与填充，发现误码直接丢弃。

### (5) 以太网交换机（透明网桥）自学习与帧转发机制

以太网交换机工作在第二层（数据链路层），每个端口都是一个独立的冲突域（支持全双工通信，无需 CSMA/CD）。交换机内部维护一张 **MAC 地址转发表（CAM 表）**。

#### 拓扑场景设定
- 交换机 $S_1$ 拥有端口 1、2、3；交换机 $S_2$ 拥有端口 1、2、3。
- $S_1$ 的端口 3 与 $S_2$ 的端口 3 通过干道互连；
- 主机 A、主机 B 接在 $S_1$ 的端口 1 和端口 2；主机 C、主机 D 接在 $S_2$ 的端口 1 和端口 2；
- 初始时刻，$S_1$ 与 $S_2$ 的 MAC 地址表均处于**完全清空的初始状态**。

#### 四步执行流追踪表

| 步序 | 数据传输事件 | 交换机 | 执行自学习动作（记录源 MAC） | 目的 MAC 查找与转发决策 | 物理网络后果 |
| :---: | :--- | :---: | :--- | :--- | :--- |
| **1** | **主机 A 发送帧给主机 B**<br>(Src: A, Dst: B) | **$S_1$** | 从端口 1 收到 A 的帧，在 MAC 表中写入：`A -> 端口 1`，重置老化计时器。 | 查表检索目的 MAC B：**未命中（未知单播帧）**。<br>向除入端口 1 以外的所有端口（端口 2、3）**泛洪（Flooding）**。 | 主机 B（端口 2）收到该帧；交换机 $S_2$（端口 3）也收到该帧。 |
|  | *(续前)* $S_2$ 收到此泛洪帧 | **$S_2$** | 从端口 3 收到帧，记录：`A -> 端口 3`。 | 查表检索 B：未命中，向端口 1、2 泛洪。 | 主机 C 和 D 收到该帧并丢弃（MAC 不匹配）。 |
| **2** | **主机 B 响应回复主机 A**<br>(Src: B, Dst: A) | **$S_1$** | 从端口 2 收到 B 的帧，记录：`B -> 端口 2`。 | 查表检索目的 MAC A：**命中（A 在端口 1）**！<br>仅向端口 1 执行**精准单播转发**，绝对不向端口 3 转发！ | 主机 A 收到响应；$S_2$ 完全收不到任何干扰流量！ |
| **3** | **主机 A 发帧给同端口集线器上的同伴**（设该同伴此前已发送过帧，其源 MAC 已被 $S_1$ 学习记录在接口 1） | **$S_1$** | 刷新 `A -> 端口 1` 的老化时间。 | 查表检索目的 MAC：发现目的 MAC **也在端口 1**（即源端口与目的端口相同）！<br>交换机直接**丢弃过滤（Filtering）**，不向其他端口转发。 | 避免同网段本地流量扩散至整个交换网络。 |
| **4** | **老化机制（Aging）** | **$S_1, S_2$** | 转发表项均设置生存时间（如 300 秒）。若某主机长时间静默无通信，表项超时自动剔除。 | 动态自适应主机物理插拔与端口迁移。 | 防止过时拓扑导致单播黑洞。 |

## 3. 关联知识体系

### 1. 本学科内跨章节关联
- **数据链路层交换机 vs 物理层集线器**：
  - 集线器（Hub）工作在物理层，仅做信号放大整形，所有端口处于同一个冲突域中，必须依赖 CSMA/CD；
  - 交换机（Switch）工作在链路层，识别 MAC 帧头，每个端口独占一个冲突域，全双工下消除了冲突。
- **数据链路层 MAC 地址 vs 网络层 ARP 协议**：
  - 上层 IP 分组无法直接在物理链路上传送，必须通过 ARP 协议广播查询下一跳的 MAC 地址，再封装入以太网 MAC 帧头中。

### 2. 408 考场标准模型 vs 现代工程实现边界
- **408 考场模型**：聚焦于经典半双工总线以太网的 CSMA/CD 碰撞窗口与退避手算。
- **现代工程实现**：现代快速以太网（100BASE-TX）与千兆以太网（1000BASE-T，通过混合电路与回波抵消在四对线上双向并发）在实际交换式组网中普遍运行于**点对点全双工模式（Full-Duplex）**，全双工链路下无需启用碰撞检测（CSMA/CD）；而在无线局域网中因无法边发边听，演进为 **CSMA/CA（带碰撞避免与 RTS/CTS 握手）**。

## 4. 闭环决策模型与核心认知结论

### (1) 考场做题定性铁律
1. **只要题目出现“网络传输速率翻倍”或“网线长度增加”**：
   - 速率 $R$ 变大 $\implies$ 最小帧长 $L_{\min}$ **同比例增大**；
   - 距离 $D$ 变长（$\tau$ 变大） $\implies$ 最小帧长 $L_{\min}$ **同比例增大**。
2. **截断指数退避算法取值判定**：
   - 第 $n$ 次冲突后，随机数候选个数为 $2^{\min(n, 10)}$ 个；
   - 选中的随机数 $r$ 必须乘以基本争用期 $2\tau$（或 512 比特时间）得到等待时间。
3. **交换机转发表操作四字诀**：
   - **“看源地址自学习，看目的地址做转发；目的已知精准发，目的未知全泛洪，源目同口直接扔”**。
