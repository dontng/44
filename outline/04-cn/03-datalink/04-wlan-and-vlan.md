## 2. 核心机理与五步推演

### (1) 为什么无线网络必须使用 CSMA/CA，而不能照搬 CSMA/CD？

以太网的 CSMA/CD 依赖“边发边听（碰撞检测）”，一旦检测到总线电压异常便立即停发。在无线信道环境下，这一套机制物理上彻底失效，必须转向 **CSMA/CA（碰撞避免，Collision Avoidance）**：

#### ① 物理功率差距悬殊（无法边发边听）
无线电磁波的信号强度随着传播距离呈平方甚至四次方指数衰减（Path Loss）。
无线网卡在发送数据时，本地天线处感应到的发射信号功率极强；而远端主机传来的电磁波经过空间衰减到达本地天线时，其功率可能仅为本地发射功率的百万分之一（$-60\text{ dB}$ 以下）。
网卡若在发送数据的同时打开接收电路，自身发射的强烈电磁波会完全淹没远端传来的微弱信号。要在硬件层面抵消自身发射回波以实现全双工碰撞检测，硬件成本和电路复杂度在消费级网卡上极其高昂。因此，**无线网卡在发送时通常无法可靠地接收外部信号**。

#### ② 隐蔽站问题（Hidden Station Problem）
如下图所示，基站 AP 位于中心，终端 A 与终端 C 分别位于 AP 两侧，超出了彼此的无线电通信覆盖范围：

```
   【终端 A】 ──信号覆盖──►                  ◄──信号覆盖── 【终端 C】
 (听不见 C 发送)           【基站 AP (B)】           (听不见 A 发送)
                          (交叠接收区)
```
- **冲突推演**：终端 A 与 C 彼此互为“隐蔽站”（A 听不见 C，C 也听不见 A）。
- 当 A 准备发数据给 AP 时，A 监听本地信道，发现空间完全空闲；此时 C 恰好也准备发数据给 AP，C 监听本地信道同样判定空闲。
- 于是 A 和 C 同时向 AP 发送数据，两路无线电波在中间的 AP 接收天线处严重叠加碰撞，导致 AP 接收彻底乱码失败。
- 但由于 A 和 C 各自听不见对方，在发送过程中**两端均自以为发送完全成功**，无法触发任何基于发送端的碰撞检测！

#### ③ 暴露站问题（Exposed Station Problem）
与隐蔽站相反，暴露站会导致**信道的无谓空耗**：

```
 【终端 A】 ◄──正在接收── 【终端 B】 ──信号覆盖──► 【终端 C】 ──准备发送──► 【终端 D】
                         (B 发给 A)               (C 想发给 D)
```
- 终端 B 正在向终端 A 发送数据，终端 C 处于 B 的发射覆盖范围内。
- 此时终端 C 想向其右侧的终端 D 发送数据（终端 D 并不在 B 的发射范围内，接收不会受到 B 的干扰）。
- 但 C 监听信道时，检测到 B 正在发射信号，于是判定信道处于忙碌状态，被迫挂起等待。
- **机制真相**：实际上 C 向 D 发送数据在物理空间上完全不会影响 A 对 B 的接收，也不会影响 D 对 C 的接收。C 因为听到 B 的信号而盲目推迟，造成了信道传输容量的不必要浪费。

### (2) CSMA/CA 协议机制、IFS 优先级与退避时序

为了在无法硬件检测碰撞的环境下降低冲突概率，802.11 构建了四层防御机制：**帧间间隔优先级**、**二进制指数退避（冻结恢复）**、**链路层 ACK 确认**与 **RTS/CTS 预约信道**。

#### ① 三级帧间间隔（IFS）与优先级调度
所有站点在监听到信道空闲后，必须强制等待一段特定的帧间间隔（Inter-Frame Space, IFS）后才能采取下一步动作。规定长短关系为：
$$\text{SIFS} < \text{PIFS} < \text{DIFS}$$

```
时间轴 ──────────────────────────────────────────────────────────►
信道变空闲 │◄── SIFS ──►│ (最高优先级: ACK, CTS, 分片后继帧)
           │◄───── PIFS ─────►│ (中优先级: AP 轮询 PCF 模式)
           │◄────────── DIFS ──────────►│ (普通优先级: DCF 数据帧与 RTS 争用)
```

- **SIFS（短帧间间隔，Short IFS）**：时间最短（通常 $10\ \mu\text{s}$）。用于最高优先级的控制帧，如单播 **ACK 确认帧**、**CTS 清除发送帧**。
  - **核心设计意图**：当一个数据帧传输完毕信道变空闲时，接收方只需等待极短的 SIFS 即可开始回复 ACK。由于普通站点发起新传输至少需要等待更长的 DIFS，**等待 SIFS 的控制帧能够无条件抢先占领信道**，确保整个握手会话不被外界突发的新数据帧打断。
- **PIFS（点协调帧间间隔，PCF IFS）**：居中。用于 AP 在集中控制轮询模式下抢占信道调度终端。
- **DIFS（分布式协调帧间间隔，DCF IFS）**：时间最长（通常 $50\ \mu\text{s}$）。普通站点发送常规数据帧或发送 RTS 预约信道前，必须首先在信道中监听并持续保持空闲满一个 DIFS。

#### ② 退避机制的关键差异：802.3 CSMA/CD vs 802.11 CSMA/CA

| 机制维度 | 802.3 以太网（CSMA/CD） | 802.11 无线局域网（CSMA/CA） |
| :--- | :--- | :--- |
| **退避触发时机** | **仅在检测到碰撞后**才触发退避；首次发送只要信道空闲即刻发出 | **每次发送数据帧**（除信道持续空闲且队列首次到达外）均强制进入退避争用 |
| **退避倒数时钟** | 碰撞后生成随机数，定时器走完后重新监听信道 | 退避计数器（Backoff Counter）以**时隙（Slot Time）**为单位逐步递减 |
| **信道变忙时的动作** | 定时器在本地盲跑，不关心信道当前是否空闲 | **立即冻结（Freeze）剩余退避计数！挂起倒数** |
| **信道重新空闲后的动作** | 重新进行完整的先听后发判定 | 必须再次等待信道持续空闲满一个 **DIFS** 后，**从上次冻结的剩余值继续向下倒数** |
| **可靠传输保障** | 无链路层确认帧（依靠上层 TCP 确认重传） | **强制要求链路层单播 ACK**；未收到 ACK 判定丢失并退避加倍重传 |

> **退避计数器“冻结与恢复”的物理公平性**：
> 假设站点 A 抽得退避值为 8，站点 B 抽得退避值为 3。倒数 3 个时隙后站点 B 归零开始发帧，信道变忙。站点 A 此时倒数到 5，立即将 5 冻结。当 B 发送完毕且信道再度空闲满 DIFS 后，站点 A 直接从 5 继续往下倒数，而新加入争用的站点 C 重新从较大窗口抽签。这保证了**已经等待较久的站点具有更高的信道获取特权**，避免长久饥饿。

### (3) RTS/CTS 信道预约与 NAV 虚拟监听精算

为了彻底消除隐蔽站引起的严重碰撞，802.11 引入了短控制帧握手机制：**RTS（请求发送，Request to Send）**与 **CTS（允许发送，Clear to Send）**。

#### ① 通信时序交互图与 NAV 设定
- **源站 A** 发送短帧 RTS，其中包含本次传输（CTS + Data + ACK）所需的总时间。
- **基站 AP** 收到后，以广播方式回复短帧 CTS，其中写入剩余所需的保留时间。
- **隐蔽站 C** 虽然听不见 A 发送的 RTS，但**必然能够听见 AP 发送的 CTS**。C 收到 CTS 后，提取其中的保留时间字段，将本地的**网络分配向量（NAV, Network Allocation Vector）**设置为该时长。
- 在 NAV 倒计时归零前，站点 C 的物理天线即便检测到空间无信号，也坚决不发送任何数据（**虚拟载波监听**），从而彻底杜绝了隐蔽站向 AP 侧并发撞车。

```
源站 A:   ──[ DIFS ]──[ RTS ]────────────────────────[ Data 帧 ]─────────────►
                       │                              ▲
                       ▼ SIFS                         │ SIFS
AP:       ────────────────────[ CTS ]─────────────────────────────[ ACK ]────►
                               │                                   ▲
                               ▼                                   │ SIFS
其他站 C: ──(收到CTS)──────────[ ====== NAV 虚拟载波监听挂起 ====== ]───────►
```

#### ② 考场精算模型与数值算例

**完整会话总耗时理论公式**：
$$T_{\text{total}} = \text{DIFS} + T_{\text{RTS}} + \text{SIFS} + T_{\text{CTS}} + \text{SIFS} + T_{\text{Data}} + \text{SIFS} + T_{\text{ACK}}$$

**【标准考场算例】**：
设某无线局域网传输速率为 $R = 10\text{ Mbps}$（即 $1.25\text{ B}/\mu\text{s} = 10\text{ bit}/\mu\text{s}$）。
系统物理层参数配置如下：
- $\text{DIFS} = 50\ \mu\text{s}$，$\text{SIFS} = 10\ \mu\text{s}$；
- 控制帧长：$\text{RTS} = 20\text{ 字节}$，$\text{CTS} = 14\text{ 字节}$，$\text{ACK} = 14\text{ 字节}$；
- 传输的数据帧载荷及头部总长为 $\text{Data} = 1500\text{ 字节}$；
- 忽略极短的电磁波空间传播时延 $\tau$。

**逐步求解步骤**：
1. **计算各帧在信道上的物理发送时延（$t = \text{FrameSize} / R$）**：
   - $T_{\text{RTS}} = \frac{20 \times 8\text{ bit}}{10\text{ Mbps}} = \frac{160\text{ bit}}{10\text{ bit}/\mu\text{s}} = 16\ \mu\text{s}$
   - $T_{\text{CTS}} = \frac{14 \times 8\text{ bit}}{10\text{ Mbps}} = \frac{112\text{ bit}}{10\text{ bit}/\mu\text{s}} = 11.2\ \mu\text{s}$
   - $T_{\text{Data}} = \frac{1500 \times 8\text{ bit}}{10\text{ Mbps}} = \frac{12000\text{ bit}}{10\text{ bit}/\mu\text{s}} = 1200\ \mu\text{s}$
   - $T_{\text{ACK}} = \frac{14 \times 8\text{ bit}}{10\text{ Mbps}} = \frac{112\text{ bit}}{10\text{ bit}/\mu\text{s}} = 11.2\ \mu\text{s}$
2. **时序汇总求和**：
   $$\begin{aligned}
   T_{\text{total}} &= \text{DIFS} + T_{\text{RTS}} + \text{SIFS} + T_{\text{CTS}} + \text{SIFS} + T_{\text{Data}} + \text{SIFS} + T_{\text{ACK}} \\
   &= 50 + 16 + 10 + 11.2 + 10 + 1200 + 10 + 11.2 \\
   &= 1308.4\ \mu\text{s}
   \end{aligned}$$
3. **NAV 持续时间设定规则（物理含义）**：
   - RTS 中填写的持续时间值：覆盖后续直至 ACK 接收完毕的全部时间：
     $$\text{Duration}_{\text{RTS}} = \text{SIFS} + T_{\text{CTS}} + \text{SIFS} + T_{\text{Data}} + \text{SIFS} + T_{\text{ACK}} = 10 + 11.2 + 10 + 1200 + 10 + 11.2 = 1242.4\ \mu\text{s}$$
   - CTS 中填写的持续时间值：覆盖从 CTS 结束到 ACK 接收完毕的时间：
     $$\text{Duration}_{\text{CTS}} = \text{Duration}_{\text{RTS}} - (\text{SIFS} + T_{\text{CTS}}) = 1242.4 - 21.2 = 1221.2\ \mu\text{s}$$

### (3) 802.11 MAC 帧格式与四个地址字段变迁

以太网帧只需源 MAC 和目的 MAC 两个地址，而 802.11 必须支持无线终端经由接入点（AP）中继进入有线分布式系统（DS, Distribution System），因此帧首部设置了 **4 个 6 字节地址字段**。

```
802.11 MAC 帧首部核心控制位：
┌──────────────┬──────────┬──────────┬──────────┬──────────┬────────────┐
│ 帧控制 (FC)  │  地址 1  │  地址 2  │  地址 3  │ 序号控制 │   地址 4   │
└──────────────┴──────────┴──────────┴──────────┴──────────┴────────────┘
       │
       ├─► To DS (去往有线系统): 0 或 1
       └─► From DS (来自有线系统): 0 或 1
```

#### ① 四大工作模式映射全景表

| `To DS` | `From DS` | 应用拓扑场景 | 地址 1（接收端 RA） | 地址 2（发射端 TA） | 地址 3（过滤/寻址） | 地址 4（仅网桥） |
| :---: | :---: | :--- | :--- | :--- | :--- | :---: |
| **0** | **0** | **自组网（IBSS / Ad-hoc）**<br>无 AP，两终端直接通信 | 目的终端 MAC（DA） | 源终端 MAC（SA） | BSSID（子网标识） | 未使用（缺省） |
| **1** | **0** | **无线终端发往 AP（上行）**<br>数据经 AP 注入有线网络 | **AP 的 MAC（BSSID）**<br>(当前无线跳的接收端) | **源终端 MAC（SA）**<br>(当前无线跳的发起端) | **目的主机 MAC（DA）**<br>(有线网内最终接收端) | 未使用 |
| **0** | **1** | **AP 发往无线终端（下行）**<br>数据从有线网络出流至终端 | **目的终端 MAC（DA）**<br>(当前无线跳的接收端) | **AP 的 MAC（BSSID）**<br>(当前无线跳的发起端) | **源主机 MAC（SA）**<br>(有线网内原始源端) | 未使用 |
| **1** | **1** | **无线网桥（WDS 模式）**<br>AP 与 AP 之间无线中继 | 接收端 AP MAC（RA） | 发送端 AP MAC（TA） | 最终目的 MAC（DA） | **原始源 MAC（SA）** |

#### ② 考场核心记忆铁律（两步定位法）
1. **地址 1 永远是当前无线跳的直接接收者（RA, Receiver Address）**；
2. **地址 2 永远是当前无线跳的直接发送者（TA, Transmitter Address）**；
3. 地址 3 承担剩余的关键寻址任务：
   - 若去往 DS（`To DS = 1`），AP 必须知道进入有线网后交给谁，因此**地址 3 = 最终目的 MAC（DA）**；
   - 若来自 DS（`From DS = 1`），目标终端必须知道是谁发来的，因此**地址 3 = 原始源 MAC（SA）**。

### (4) 虚拟局域网（VLAN / IEEE 802.1Q）机制全解

#### ① VLAN 的物理隔离本质
- **核心功能**：VLAN 是在二层交换网络中**逻辑划分广播域（Broadcast Domain）**的技术。
- **物理界限**：
  - 同一个 VLAN 内的主机，广播报文（如 ARP 请求）在 VLAN 内部自由泛洪；
  - 不同的 VLAN 之间**广播域完全隔离**。即使两台主机插在同一台物理交换机上，若划分在不同 VLAN，二层帧绝对无法直接跨 VLAN 送达；
  - **跨 VLAN 通信必须借助三层设备（三层交换机路由模块或外部单臂路由器）完成 IP 路由转发**；
  - 交换机的**每个物理端口始终是一个独立的冲突域（Collision Domain）**，划分 VLAN 不改变冲突域边界。

#### ② IEEE 802.1Q 帧结构（插入 4 字节 VLAN Tag）
802.1Q 协议在标准以太网帧的“源 MAC 地址”与“类型/长度”字段之间，强行插入了 **4 字节的 802.1Q 标签（Tag）**：

```
标准以太网帧 (最大 1518 字节):
[ 目的 MAC (6B) ] [ 源 MAC (6B) ] [ 类型 (2B) ] [ 数据载荷 (46~1500B) ] [ FCS (4B) ]

802.1Q 标记帧 (最大 1522 字节):
[ 目的 MAC (6B) ] [ 源 MAC (6B) ] ┌── [ 4 字节 802.1Q Tag ] ──┐ [ 类型 (2B) ] [ 数据载荷 ] [ FCS (4B) ]
                                   │                           │
                                   ├─► TPID (2B): 固定为 0x8100 (指示为 VLAN 帧)
                                   └─► TCI (2B):
                                        ├─► Priority (3 bit): 0~7 优先级 (802.1p)
                                        ├─► CFI/DEI (1 bit): 规范格式指示
                                        └─► VID (12 bit): VLAN 标识符 (0 ~ 4095)
```

- **VID（VLAN ID）的数学容量**：占 **12 个比特**，取值范围为 $0 \sim 2^{12}-1 = 0 \sim 4095$。
  - `VID = 0` 与 `VID = 4095` 保留作特殊用途；
  - **用户实际可用有效 VLAN ID 范围为 $1 \sim 4094$**。
- **最大帧长变迁**：标准以太网最大传输单元 MTU = 1500B，最大帧长为 $6+6+2+1500+4 = 1518\text{ 字节}$。插入 4B Tag 后，最大帧长变为 **$1522\text{ 字节}$**。

#### ③ 交换机端口类型与标签剥离机制

| 端口类型 | 连接对象 | 接收未打标帧（Untagged） | 接收带标帧（Tagged） | 发送数据帧处理 |
| :--- | :--- | :--- | :--- | :--- |
| **Access 端口** | 连接终端主机（PC、服务器、普通打印机） | **打上该端口默认的 PVID**，在交换机内部按此 VID 转发 | 若 VID 等于本端口 PVID 则接收，不等于则直接丢弃 | **剥离（Strip）4 字节 VLAN Tag**，还原为标准无标记帧送给主机（主机网卡完全无感知） |
| **Trunk 端口** | 连接交换机与交换机、或交换机与路由器 | **打上本 Trunk 端口的 Native VLAN（PVID）** | 检查其 VID 是否在 Trunk 允许通过列表（Allow List）中；在则接收，不在则丢弃 | - 若帧的 VID **等于本端口 PVID**：**剥离 Tag** 后发送；<br>- 若帧的 VID **不等于 PVID 但在允许列表内**：**保持携带 Tag 原样发送** |

### (5) 典型介质访问控制协议横向闭环对比

| 协议分类 | 典型协议 | 发送时机与冲突解决 | 理论最大吞吐率 / 适用环境 |
| :--- | :--- | :--- | :--- |
| **随机访问**<br>（争用型） | **纯 ALOHA** | 想发就发；若未收到确认则判定碰撞，随机退避重发。**脆弱期为 $2T_0$** | **$S_{\max} = \frac{1}{2e} \approx 18.4\%$**（轻负载极低延迟，重负载雪崩崩溃） |
| | **时隙 ALOHA (S-ALOHA)** | 将时间划分为等长时隙 $T_0$，只能在时隙起点发送。**脆弱期减半为 $T_0$** | **$S_{\max} = \frac{1}{e} \approx 36.8\%$**（吞吐量比纯 ALOHA 翻倍） |
| | **CSMA/CD** | 先听后发、边发边听、冲突停发、随机退避。争用期 $2\tau$，受最小帧长约束 | 有线总线型以太网标准；全双工交换机时代已退役 |
| | **CSMA/CA** | 碰撞避免、三级 IFS、退避计时器冻结、RTS/CTS 握手、链路层强制 ACK | 无法全双工检测碰撞的无线局域网环境（802.11） |
| **受控访问**<br>（无争用型） | **轮询（Polling）** | 集中式主站点轮流向各从属站点询问是否有数据发送 | 集中式控制，无数据碰撞；存在轮询开销与主站单点故障 |
| | **令牌环（Token Ring）** | 环路上循环传递一帧“令牌”，仅持有令牌的节点拥有发送权，发完归还 | **重负载下无任何信道冲突，吞吐率和信道利用率极高**；轻负载下有无谓等待令牌的循环时延 |

### (6) 典型反例证伪（常见认知陷阱）

1. **反例 1：“终端 A 和 C 相互为隐蔽站，只要将发射功率调大，让它们能互相听见，就无需任何防冲突协议。”**
   - **反例证伪**：错误。盲目加大发射功率不仅受无线电管理委员会法定辐射功率上限（EIRP）制约，而且会导致对邻近其他 WLAN 子网产生严重的同频/邻频干扰；同时移动终端电池续航无法承受高功率发射。必须从协议层采用 RTS/CTS 虚拟载波监听解决。
2. **反例 2：“交换机划分了 VLAN 之后，不仅隔离了广播域，而且将一个冲突域进一步切分为了多个更小的冲突域。”**
   - **反例证伪**：错误。交换机本身的物理架构决定了**其每一个物理端口天然就是一个独立的冲突域**。划不划分 VLAN，端口与端口之间在全双工模式下都绝无物理碰撞。VLAN 的作用范围且仅在**二层广播域的逻辑隔离**，与物理冲突域毫无关系。
3. **反例 3：“802.11 无线局域网中，既然每次发送都执行了退避算法，那么无线数据帧就绝不会在信道上遭遇任何碰撞。”**
   - **反例证伪**：错误。退避算法只是极大降低碰撞概率，绝不能消除碰撞。若两个站点的退避计数器在同一个时隙恰好同时递减归零，双方仍会在同一时刻发射数据导致碰撞；此外，若未开启 RTS/CTS，隐蔽站并发发送在 AP 处必定碰撞。
4. **反例 4：“为了网络传输安全，Trunk 端口跨交换机传输数据时，所有经过它的数据帧都必须携带 4 字节的 802.1Q Tag 标签。”**
   - **反例证伪**：错误。Trunk 端口拥有默认的 PVID（Native VLAN）。当经过 Trunk 发送的帧其 VLAN ID **恰好等于该端口的 PVID 时，Trunk 端口会将其 4 字节 Tag 剥除（Untagged）后再发射出去**，以保持对非 802.1Q 传统设备的向后兼容性。

## 3. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型（学理解题口径） | 现代工程实现边界（Wi-Fi 6 / 现代交换技术） |
| :--- | :--- | :--- |
| **信道接入控制** | 默认采用经典的 CSMA/CA 分布式竞争（DCF）与 RTS/CTS 机制 | **Wi-Fi 6（802.11ax）全面引入 OFDMA（正交频分多址）与 MU-MIMO**：AP 集中按子载波资源块（RU）精确调度多个终端并发传输，与传统 EDCA/CSMA 接入共存：AP 通常先竞争取得 TXOP，再在该传输机会内调度多个用户的 RU；OFDMA 不是对争用退避机制的整体废弃 |
| **小帧传输效率** | 教材设定每个数据帧均独立封包、独立退避、独立回复 ACK | **帧聚合技术（802.11n/ac A-MPDU / A-MSDU）与 Block ACK**：将数十个数据包聚合为超长物理帧一次发送，接收方仅回复一个位图 Block ACK，消除了大量 IFS 与物理前导码开销 |
| **VLAN 标签层数** | 标准单层 802.1Q Tag（12 bit VID，上限 4094 个） | **QinQ 技术（IEEE 802.1ad 双层 Tag）与 VXLAN 封装**：运营商网络在用户 802.1Q 标签外再套一层运营商 VLAN 标签；数据中心网络采用 VXLAN（24 bit VNI，支持 1600 万租户）穿透三层网络 |
| **交换机端口分类** | 严格区分为 Access 端口与 Trunk 端口两分法 | 现代数据中心交换机支持 **Hybrid 混合端口**与 **vxlan vtep** 端口，允许根据流表策略任意指定对特定 VLAN 的打标、剥标或多层重写动作 |

## 4. 跨章节与跨学科关联

### 1. 本学科内跨章节关联
- $\to$ 关联 [介质访问控制与以太网（CSMA/CD）](03-mac-and-ethernet.md)：
  - **共同机制**：CSMA/CD 与 CSMA/CA 均遵循“先听后发（载波监听）”的基本思想，以退避机制分散再次尝试的冲突时间。
  - **关键差异**：CSMA/CD 支持边发边听、强化碰撞中断发射，无链路层 ACK；CSMA/CA 发送时闭眼无法监听，依靠 DIFS/SIFS 优先级保护、退避冻结与链路层显式 ACK 兜底。
  - **不可直接迁移的判据**：以太网最小帧长公式 $\text{L}_{\min} = \text{DataRate} \times 2\tau$ 在无线局域网中**完全不适用**，因为无线根本不存在 $2\tau$ 碰撞窗口检测机制。
- $\to$ 关联 [网络层设备与路由选择](../04-network/03-routing-devices-and-icmp.md)：
  - **共同机制**：VLAN 间通信需要通过三层路由模块解封装二层头部，再重新按三层目标 IP 封装下一跳 MAC 地址。
  - **关键差异**：二层交换机仅查看 802.1Q 标签与 MAC 映射表，生命周期局限于本网段；三层路由器剥除二层报头、递减 TTL、重算 IP 校验和。
  - **不可直接迁移的判据**：Access 端口连接普通主机时剥离标签；但连接支持 802.1Q 的虚拟化宿主机（如 ESXi / KVM 虚拟化交换机）时，物理网卡必须配置为 Trunk 模式透传各虚拟机 Tag。

### 2. 跨学科协同关联
- $\to$ 关联 [操作系统 / I/O控制方式与层次结构](../../03-os/05-io/01-io-control-and-layers.md)：
  - **共同机制**：操作系统虚拟网卡驱动（如 Linux `vlan` 子接口 `eth0.100`）在收到物理网卡提交的带有 Hardware Offload 剥离标签的 SKB 缓存后，按 VID 分发至对应的虚拟网络命名空间（Network Namespace）。
  - **关键差异**：硬件交换机依靠专用 ASIC 芯片线速打标/剥标；操作系统依靠内核协议栈 CPU 指令解析内存数据包缓冲区。
  - **不可直接迁移的判据**：在 Linux 内核开启 VLAN 硬件卸载（Rx VLAN Acceleration）后，抓包工具（如 tcpdump）在宿主机网络栈看到的报文可能已被网卡剥除了 802.1Q 头部，不可因此判定数据包未带 Tag 传输。

## 5. 核心考点自查清单与闭环判据

1. **帧间间隔核心不等式**：
   $$\text{SIFS} < \text{PIFS} < \text{DIFS}$$
   - ACK、CTS 用 SIFS，确保最高优先权无缝插入。
2. **802.11 退避计时器核心行为**：
   - 信道忙碌时**挂起冻结**；信道空闲满 DIFS 后**从剩余值继续倒数**。
3. **802.11 帧地址字段极速定位**：
   - 地址 1 是下一跳**无线接收端（RA）**；地址 2 是上一跳**无线发送端（TA）**。
   - `To DS = 1, From DS = 0` 时：地址 1 = AP，地址 2 = 源终端，地址 3 = 最终目的 MAC。
4. **VLAN 核心考点判据**：
   - 4 字节 Tag 插入在源 MAC 与 Type 之间；
   - 12 bit VID，有效取值 **$1 \sim 4094$**；
   - Access 端口“进打出剥”，连接终端主机；Trunk 端口“透传带标，遇 PVID 剥标”。
