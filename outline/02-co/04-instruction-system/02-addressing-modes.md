## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么需要丰富的寻址方式？
- **物理矛盾**：指令字长受到微架构与总线位宽的严格限制（如 16 位或 32 位）。扣除操作码和寻址模式标志后，指令中留给形式地址（$A$）的物理位数极其有限（如 8 位或 12 位）。
  - 若单纯使用直接寻址，当 $A$ 仅为 8 位时，寻址范围仅为 $2^8 = 256$ 个单元，甚至装不下一个微型驱动。
- **体系结构解法**：
  - 引入寄存器间接寻址，以寄存器全字长（32 位/64 位）作为指针，直接突破指令字长的桎梏；
  - 引入基址寻址与相对寻址，使得程序可以任意浮动装载，催生了多道程序设计与位置无关代码（PIC）；
  - 引入变址寻址，让循环结构无需动态自修改指令即可顺序扫过大型数组。

### (2) 核心寻址方式机制与执行期访存矩阵

> [!NOTE]
> **重要物理前提约定（408 考场基准）**：
> 1. 下表统计的“执行阶段访存次数”**严格不包含取指令周期的访存**（取指固定需要访问内存读取指令本身）；
> 2. 假设主存为**按字节编址**，操作数按字对齐存放；
> 3. 若未特殊指明，“间接寻址”默认指**一次间接寻址**。

```
1. 立即寻址 (Immediate)
   指令: [ OP | 模式 | 立即数 #data ]
   机理: 操作数就是形式地址字段本身，无有效地址 EA。
   执行期访存: 0 次。常用于给变量赋初值。

2. 直接寻址 (Direct)
   指令: [ OP | 模式 | 形式地址 A ]
   机理: EA = A。
   执行期访存: 1 次 (读写主存单元 A)。寻址范围受限于 A 的位宽 2^n。

3. 一次间接寻址 (Indirect)
   指令: [ OP | 模式 | 形式地址 A ]
   机理: EA = (A)。A 单元内保存的是有效地址。
   执行期访存: 2 次 (第一次读取 EA，第二次根据 EA 访问操作数)。

4. 寄存器寻址 (Register)
   指令: [ OP | 模式 | 寄存器编号 R_i ]
   机理: 操作数在通用寄存器 R_i 中，无主存 EA。
   执行期访存: 0 次。执行速度最快，完全在 CPU 内部完成。

5. 寄存器间接寻址 (Register Indirect)
   指令: [ OP | 模式 | 寄存器编号 R_i ]
   机理: EA = (R_i)。寄存器 R_i 中保存的是操作数在主存中的物理/逻辑地址。
   执行期访存: 1 次 (根据寄存器中的地址读取主存)。
```

#### 寻址方式核心指标全景对照表

| 寻址方式 | 有效地址 $\text{EA}$ 计算公式 | 执行阶段访存次数（读操作） | 寻址物理范围 | 典型应用场景与优缺点 |
| :--- | :--- | :---: | :--- | :--- |
| **立即寻址** | 无物理地址（操作数在指令内） | **0 次** | 受限于指令字中立即数字段位宽 | 常数初始化；修改常数需修改指令代码 |
| **直接寻址** | $\text{EA} = A$ | **1 次** | $2^{\text{地址码位数}}$ 个存储单元 | 访问静态全局变量；地址空间受限 |
| **间接寻址** | 一次间址：$\text{EA} = (A)$<br>二次间址：$\text{EA} = ((A))$ | 一次间址：**2 次**<br>多次间址：$k+1$ 次 | 由存储字长决定（突破形式地址位数限制） | 动态指针寻址、子程序返回；多次访存延迟巨大 |
| **寄存器寻址** | 无主存地址（操作数在寄存器） | **0 次** | 通用寄存器个数 $2^{\text{寄存器字段位宽}}$ | 访问局部高频变量；指令短、执行极速 |
| **寄存器间接** | $\text{EA} = (R_i)$ | **1 次** | 由寄存器位宽决定（可达主存全寻址空间） | 循环体内数组扫描、指针解引用；兼顾速度与容量 |
| **基址寻址** | $\text{EA} = (\text{BR}) + A$ | **1 次** | 由基址寄存器 BR 位宽决定 | 多道程序动态重定位；用户程序不可随意修改 BR |
| **变址寻址** | $\text{EA} = (\text{IX}) + A$ | **1 次** | 由变址寄存器 IX 位宽决定 | 数组遍历、向量运算；用户循环指令动态修改 IX |
| **相对寻址** | $\text{EA} = (\text{PC}) + A$ | 若为取数则 **1 次**；若为转移跳转则 **0 次** | 以当前 PC 为中心的双向相对窗口 | 分支转移、编写位置无关代码（PIC） |

### (3) 三大偏移寻址的深层辨析（基址 vs 变址 vs 相对）

三大偏移寻址在算术逻辑上均体现为**加法器相加**：$\text{EA} = \text{基准寄存器} + \text{形式偏移量}$。但其软硬件控制权与系统语义存在根本差异：

| 寻址方式 | 谁提供基准值？ | 谁提供偏移量？ | 软硬件权责划分与物理本质 |
| :--- | :--- | :--- | :--- |
| **基址寻址**<br>(Base) | **基址寄存器（BR）**<br>（或专用基址寄存器，或指定的通用寄存器） | 指令中的形式地址 $A$ | **由操作系统（OS）或特权指令维护 BR**，用户程序不可擅自更改。用户代码中的 $A$ 作为程序内逻辑偏移。用于实现**多道程序的物理动态重定位**。 |
| **变址寻址**<br>(Index) | 指令中的形式地址 $A$ | **变址寄存器（IX）** | **由用户程序自由修改 IX**，指令中的 $A$ 保持恒定。$A$ 锚定数组的首地址，循环体每次通过加法指令递增 IX，实现无需改写指令即可自动步进遍历数据。 |
| **相对寻址**<br>(Relative) | **程序计数器（PC）** | 指令中的带符号位移量 $A$ | **硬件自动随取指递增 PC**，指令中的 $A$ 为补码形式的相对距离（可正可负）。用于实现**分支跳转与位置无关代码（PIC）**。 |

---

### (4) 相对寻址 PC 基准值的时序与体系结构分歧（最高频陷阱）

初学者最容易将“当前指令地址 + 指令长度 + 偏移量”视为一条不加前提的普适铁律。事实上，**相对寻址究竟以哪一个时刻的 PC 作为基准，完全取决于具体 ISA 体系结构的微架构取指时序约定**！

#### 模型 A：408 经典教材模型 / x86 / MIPS 架构
- **硬件时序基准**：在流水线或多周期控制通路中，**CPU 在取指令周期（IF 阶段）一将指令读入指令寄存器（IR），硬件 PC 计数器就已经自动自增，指向了下一条紧邻指令的起始物理地址**！
- **数学公式**：
  $$\text{EA} = \mathbf{PC_{\text{next}}} + A = (\mathbf{PC_{\text{current}}} + \text{Instruction\_Length}) + A$$
- **算例推导**：
  - 设当前机器指令字长为 2 字节，当前跳转指令存放于地址 `1000H`，形式位移量为 `A = 0008H`（字节偏移）；
  - 取指令完成后，$\text{PC}_{\text{next}} = 1000\text{H} + 2 = 1002\text{H}$；
  - 转移目标有效地址：$\text{EA} = 1002\text{H} + 0008\text{H} = \mathbf{100AH}$。

#### 模型 B：现代真实架构标准 —— RISC-V（RV32I / RV64I）
- **硬件规范约定**：在 RISC-V 官方指令集手册中，所有分支指令（如 `beq, bne`）与无条件跳转指令（`jal`）的相对寻址，**其基准地址严格定义为当前这条跳转指令自身的程序计数器 $\mathbf{PC_{\text{current}}}$，而非下一条指令**！
- **数学公式**：
  $$\text{EA} = \mathbf{PC_{\text{current}}} + \text{SignExtend}(\text{Offset})$$
  *(注意：RISC-V 分支偏移量以半字 2B 为单位对齐，最低位固定补 0)*
- **同一参数在 RISC-V 下的算例推导**：
  - 设当前指令位于 `1000H`，指令给出的位移量为 `0008H`；
  - 转移目标有效地址严格计算为：$\text{EA} = 1000\text{H} + 0008\text{H} = \mathbf{1008H}$！

#### 考场闭环决策
在 408 统考题中，若未显式指明体系结构规范，**一律遵循 408 经典教材模型（即 PC 已自增完毕指向下一条指令）**；若题目明确指明“基于 RISC-V 指令集”，则必须使用当前指令自身的 PC 作为基准！

### (5) 重点辨析：硬件基址寻址 vs 操作系统动态重定位 vs MMU 页表基址（CR3）

在过去的跨学科复习中，常有将“操作系统动态重定位和 CR3 页表转换直接等价为基址寻址”的严重混淆。必须建立三者的严密边界：

| 比较维度 | 共同机制（Commonality） | 关键差异（Differences） | 不可直接迁移的判据 |
| :--- | :--- | :--- | :--- |
| **指令级基址寻址**<br>($\text{EA} = (\text{BR}) + A$) | **基准值 + 偏移量算术相加**<br>都利用加法器硬件计算目标地址。 | **作用于用户指令内部，生成程序内逻辑/有效地址**<br>基址寄存器由编译器或操作系统设定，形式地址 $A$ 是指令内字段。主要用于单道或多道程序内部的局部数据块或代码块基址重定位，计算出的 EA 往往依然是逻辑地址。 | 基址寻址是 CPU **指令集体系结构（ISA）**层面的寻址模式，程序员/编译器可以通过指令显式指定基址寄存器，它并不改变物理内存的映射拓扑。 |
| **操作系统连续分配动态重定位**<br>($\text{PA} = \text{Base} + \text{LA}$) | **基准值 + 偏移量算术相加**<br>将相对偏移变换为目标地址。 | **作用于整个进程地址空间，将逻辑地址变换为物理地址**<br>硬件重定位寄存器（Relocation Register）保存整个进程在连续内存中的起始物理地址，硬件越界检查寄存器（Limit Register）防止越界。每次用户发出逻辑地址，MMU 自动将其加上基准值映射到 DRAM。 | 连续分配动态重定位要求**整个作业在物理内存中必须绝对连续存放**。若内存碎片化无法找到整块连续空间，动态重定位直接无法装载作业；而基址寻址无此宏观物理连续限制。 |
| **现代分页系统 MMU 页表基址**<br>(x86 `CR3` / RISC-V `satp`) | **存储高阶基准地址**<br>均由操作系统特权指令在进程上下文切换时写入硬件寄存器。 | **索引查表 + 帧拼接（Concatenation），绝非简单加法！**<br>CR3 保存的是顶级页目录的物理基地址。地址转换过程是：用虚拟地址中的页号作为索引去查找页表项（PTE），取出物理页框号（PFN），最后将 PFN 与页内偏移量直接**位拼接（Bit Concatenation）**得到物理地址，根本不是把 CR3 与逻辑地址直接做加法！ | **绝对不能把 CR3 当作算术基址寄存器！**<br>若错误地把 CR3 加上逻辑地址，逻辑地址中的高位页号将被当作算术数相加，直接导致内存访问灾难。CR3 是指针的指针，而非线性位移基准。 |

### (6) 408 考场标准模型 vs 现代工程实现边界

```
┌────────────────────────────────────────────────────────┐
│ 408 考场标准模型                                        │
│  - 纯经典定长/变长寻址模式，重视纸面 EA 手工推导           │
│  - 默认 PC 自动加指令长度 (PC_next + A)                  │
│  - 统计访存次数假定无 Cache、单级页表或纯物理寻址           │
└───────────────────────────┬────────────────────────────┘
                            │ 现实微架构落地
                            ▼
┌────────────────────────────────────────────────────────┐
│ 现代工程实现边界                                        │
│  1. 现代 RISC 寻址极度精简 (Load/Store 架构)            │
│     - 算术指令 (ADD/SUB) 仅支持纯寄存器寻址             │
│     - 仅 Load/Store 指令支持基址变址访存: R[rd] = M[R[rs1] + imm] │
│     - 彻底抛弃复杂的多级主存间接寻址 (访存延迟不可控)   │
│  2. Cache 使得“访存次数”不再等同于“内存时延”            │
│     - 所谓“1 次主存访存”，若命中 L1 Data Cache 仅耗时 1 周期 │
│     - 若 Cache 缺失访问 DRAM 则高达 200 周期            │
│  3. 虚拟地址转换开销被 TLB 吸收                         │
│     - 真实执行阶段由 MMU 介入，若 TLB 命中，物理转换 0 周期 │
└────────────────────────────────────────────────────────┘
```

## 3. 本学科内跨章节关联与跨学科协同关联

### 1. 本学科内跨章节关联

#### (1) 与 CPU 指令流水线冲突（冒险）的紧密耦合
- **共同机制**：有效地址生成对流水线周期的占用。
- **关键差异**：
  - 寄存器寻址的操作数在 ID 阶段从通用寄存器堆直接读出，可在 EX 阶段直接参与 ALU 运算；
  - 变址或基址寻址的有效地址 $\text{EA} = (\text{R}) + A$ 必须占用 EX 阶段的一个完整 ALU 加法周期，若紧随其后是 Load 指令，将触发典型的 **Load-Use 数据冒险**，强制流水线插入气泡。
- **不可直接迁移的判据**：立即寻址无数据冒险，但它包含在指令流中，若立即数超长会导致指令预取带宽（IF 阶段）压力倍增。

#### (2) 与汇编语言数组遍历的数据对齐
- **共同机制**：变址寻址 $\text{EA} = A + (\text{IX}) \times \text{Scale}$。
- **关键差异**：
  - 考场简单变址默认为 1 字节步进；
  - 真实 x86 提供了比例变址（`Scale = 1, 2, 4, 8`），硬件自动将变址寄存器左移 1 位（`short`）、2 位（`int`）或 3 位（`double`），完美契合数据类型的物理内存对齐。
- **不可直接迁移的判据**：若未开启比例变址，遍历 `int` 数组时变址寄存器每次必须手动 `+4`，若错写为 `+1` 将导致非对齐跨界甚至数据截断错误。

---

### 2. 跨学科协同关联

#### (1) 操作系统：进程地址空间布局与位置无关代码（PIC）
- **共同机制**：动态加载共享动态链接库（.so / .dll）。
- **关键差异**：
  - 普通绝对跳转使用直接寻址，代码烧录死物理/逻辑地址，不同进程加载该库时若发生地址冲突，必须重新执行耗时的文本重定位（Text Relocation）；
  - 位置无关代码（PIC）全程采用**相对寻址（PC-relative）配合全局偏移表（GOT）**，库函数内部调用全部通过与当前 PC 的相对位移寻址，无论共享库被操作系统加载到物理内存的哪一个虚拟基地址，其相对位移恒定不变，实现全系统跨进程纯物理代码段共享。
- **不可直接迁移的判据**：相对寻址有其位移量窗口限制（如 $\pm 2\text{KB}$ 或 $\pm 1\text{MB}$）。若跨模块跳转距离超出相对偏移字段的最大位宽，必须退化为通过 GOT 表进行寄存器间接绝对长跳转。

## 4. 闭环决策模型与核心认知结论

### (1) 相对寻址跳转目标地址精算闭环决策流

```
第一步: 明确考卷 ISA 假设
  ├─ 若为 408 统考通用题型 / x86 / MIPS:
  │    基准值 Base = 当前跳转指令的起始地址 + 当前指令的字节长度 (即 PC_next)
  └─ 若明确题干指明 RISC-V 体系:
       基准值 Base = 当前跳转指令自身的起始地址 (即 PC_current)

第二步: 确定形式偏移量 A 的属性
  - 检查 A 是否为带符号补码 (若最高位为 1 则为负向后跳，为 0 为正向前跳)
  - 检查 A 的单位是【字节 (Byte)】还是【字 / 半字】:
      * 若 A 为半字单位 (如 RISC-V B 型): 实际字节位移 = A << 1
      * 若 A 为字单位 (如部分微机): 实际字节位移 = A << 2
      * 若 A 已为字节编址: 实际字节位移 = A

第三步: 最终有效地址求和
  EA = Base + 实际字节位移 (十六进制严格相加)
```

### (2) 常见认知误区反例剖析

#### 误区 1：“间接寻址执行阶段访存 2 次，所以间接寻址总共访存 2 次。”
- **反例与真相**：错！“执行阶段”不包含取指令。一条间接寻址指令从取指到执行完毕，**总共访存 3 次**（1 次取指令 + 1 次读有效地址 EA + 1 次读写操作数）。考场审题必须看清题干问的是“整个指令周期”还是“执行阶段”。

#### 误区 2：“寄存器间接寻址中，操作数保存在寄存器中。”
- **反例与真相**：错！寄存器中保存的是**主存有效地址**，操作数依然静静躺在主存中，因此必须执行 1 次主存访存才能拿到数据。操作数保存在寄存器中的是“寄存器寻址”。
