## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么需要这么多纷繁复杂的寻址方式？
- **物理困境**：
  - 机器指令的字长是极其有限的（如 16 位或 32 位）。扣除操作码（OP）和寻址特征位后，留给形式地址（$A$）的物理位数往往只有十几位甚至几位。
  - 若仅采用直接寻址，当地址码仅有 8 位时，CPU 只能寻址 $2^8 = 256$ 个字节，甚至无法覆盖一个最简单的操作系统内核。
- **工程解法**：
  - 引入多元寻址方式：通过寄存器间接、基址偏移、变址跳跃等硬件组合，**在指令形式地址位数极其短小的前提下，极大地扩展寻址物理空间，并为动态重定位、循环遍历与过程调用提供硬件级原生加速**。

---

### (2) 核心寻址方式的机制与有效地址（EA）全景推导

```
1. 立即寻址 (Immediate)
   指令格式: [ OP | 寻址 | 立即数 #data ]
   机理: 操作数直接封装在指令的地址字段中。
   EA: 无物理地址。执行阶段【0 次访存】。常用于赋常数初始值。

2. 直接寻址 (Direct)
   指令格式: [ OP | 寻址 | 形式地址 A ]
   机理: 形式地址就是真实物理/逻辑地址。
   EA = A。执行阶段【1 次访存】。

3. 间接寻址 (Indirect)
   指令格式: [ OP | 寻址 | 形式地址 A ]
   机理: 形式地址指向主存单元，该单元内保存的是有效地址。
   EA = (A)。执行阶段【至少 2 次访存】。极大拓宽寻址范围，但访存延迟剧增。

4. 寄存器寻址 (Register)
   指令格式: [ OP | 寻址 | 寄存器编号 R_i ]
   机理: 操作数存放在 CPU 内部通用寄存器中。
   EA: 无主存地址。执行阶段【0 次访存】。执行速度最快。

5. 寄存器间接寻址 (Register Indirect)
   指令格式: [ OP | 寻址 | 寄存器编号 R_i ]
   机理: 寄存器中存放的是操作数在主存中的有效地址。
   EA = (R_i)。执行阶段【1 次访存】。
```

### (3) 三大偏移寻址的深层辨析（基址 vs 变址 vs 相对）

| 寻址方式 | 有效地址计算公式 | 谁决定基准值？谁决定偏移量？ | 核心应用场景与物理本质 |
| :--- | :--- | :--- | :--- |
| **基址寻址**<br>(Base Addressing) | $$\text{EA} = (\text{BR}) + A$$ | **操作系统**管理基址寄存器 BR；<br>**用户程序/编译器**给定偏移 $A$ | **多道程序设计与动态重定位（浮动程序）**。<br>程序装入内存不同物理位置时，代码内部偏移量 $A$ 保持不变，OS 只需修改 BR 即可。 |
| **变址寻址**<br>(Index Addressing) | $$\text{EA} = (\text{IX}) + A$$ | **用户程序/循环变量**修改变址寄存器 IX；<br>**系统/指令**给定基地址 $A$ | **数组遍历、向量运算与循环结构**。<br>形式地址 $A$ 锁定数组首地址，循环体每次只递增 IX，无需动态修改指令代码。 |
| **相对寻址**<br>(Relative Addressing) | $$\text{EA} = (\text{PC}) + A$$ | 当前程序计数器 **PC 自增后的值**作为基准；<br>指令给定带符号相对位移 $A$ | **转移指令与位置无关代码（PIC）**。<br>代码在内存中整体搬家时，相对跳转偏移量 $A$ 完全不受物理装载地址变动的影响。 |

#### 考场绝对深水区：相对寻址的 PC 自增陷阱！
- **硬件执行时序**：
  在取指周期中，CPU 刚把当前指令读入指令寄存器（IR）的瞬间，**硬件计数器 PC 就已经自动递增指向了下一条指令的起始地址**！
- **严密计算法则**：
  $$\text{目标跳转地址 EA} = \mathbf{PC_{\text{next}}} + A = (\mathbf{当前指令地址} + \mathbf{当前指令字节长度}) + A$$
  - **陷阱警示**：若指令字长为 2 字节（16 位），当前指令地址为 `1000H`，跳转偏移量为 `A = 0008H`，则 $\text{EA} = 1000\text{H} + 2 + 8 = \mathbf{100AH}$，绝对不能直接用 $1000\text{H} + 8$！

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 计组: 指令寻址方式与 EA 计算  │
                     └──────────────┬───────────────┘
                                    │ 硬件地址生成逻辑
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 操作系统: 进程重定位与内存管理│         │ 计组: CPU 流水线控制冒险      │
│  - 动态重定位等价于基址寻址  │ ◄────── │  - 相对寻址分支计算目标地址  │
│  - 浮动程序与页表基址 CR3    │         │  - 目标地址未算出前流水线阻塞│
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与操作系统内存重定位机制的物理同一性**：
   - 操作系统的“动态运行时重定位”在微架构层面就是完全依托 CPU 的**基址寻址（Base Addressing）**硬件电路实现的。现代操作系统中进程上下文切换时恢复的页表基址寄存器（CR3），本质上就是虚拟分页系统的高阶基址寄存器。
2. **与指令流水线分支预测控制冒险的协同**：
   - 条件转移指令使用相对寻址计算跳转目标。由于目标地址 $\text{EA} = (\text{PC}) + A$ 必须在译码（ID）甚至执行（EX）阶段由 ALU 计算出来，在算出正确跳转目标前，取指阶段（IF）无法获知下一条指令从哪取，从而引发流水线气泡。

## 4. 闭环决策模型与核心认知结论

### (1) 寻址方式执行阶段（操作数获取）访存次数绝对判定表

| 寻址方式 | 执行阶段访存次数 | 寻址范围特征 |
| :--- | :---: | :--- |
| **立即寻址** | **0 次** | 操作数受限于指令中立即数字段位宽 |
| **寄存器寻址** | **0 次** | 寻址范围受限于 CPU 通用寄存器个数 |
| **直接寻址** | **1 次** | 受限于指令字中形式地址 $A$ 的位宽 |
| **寄存器间接寻址** | **1 次** | 由寄存器位宽决定（可达主存全物理范围） |
| **基址寻址 / 变址寻址** | **1 次** | 由基址/变址寄存器位宽决定（可达全内存空间） |
| **相对寻址 (数据寻址时)** | **1 次** | 以当前 PC 为中心的向前/向后局部范围 |
| **一次间接寻址** | **2 次** | 第一次读出有效地址，第二次读出操作数 |
| **两次间接寻址** | **3 次** | 经历两次指针跳跃，第三次读出操作数 |

### (2) 考场定性闭环判据
1. **只要看到“为多道程序动态重定位或代码浮动提供支持”** $\to$ 必为 **基址寻址**。
2. **只要看到“便于处理数组、向量遍历，循环程序设计”** $\to$ 必为 **变址寻址**。
3. **只要看到“编写位置无关代码（PIC），支持条件转移跳转”** $\to$ 必为 **相对寻址**。
4. **计算相对寻址目标地址时** $\to$ 务必先将当前 PC 加上**当前指令的字节长度**，再加上偏移量 $A$！
