## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须引入 Cache 映射与地址划分？
- **物理困境**：
  - CPU 运算核心在 GHz 级别高频运转（时钟周期小于 1ns），而主存 DRAM 的随机访问时延通常在 50~100ns 级别，形成巨大的“内存墙（Memory Wall）”。
  - SRAM 速度极快（纳秒级），但每个位元需要 6 个晶体管（6T SRAM），硅片面积大、功耗高、成本极其昂贵，无法将全部内存做成 SRAM。
  - 依据**局部性原理**（时间局部性：被访问的数据不久后可能再次访问；空间局部性：被访问的数据其相邻数据不久后可能被访问），CPU 与主存之间设置小容量但高速的 SRAM 缓存（Cache），以数据块（Line/Block，通常为 32B 或 64B）为基本传输单位。
- **核心硬件问题**：
  - 当 CPU 发出一个物理地址时，如何在 1~2 个时钟周期内判定目标数据是否已在 Cache 中？若命中，它位于哪一个具体的 Cache 行？这就必须依赖**地址映射机制**。

---

### (2) 三大映射方式的硬件实现与折中（Trade-off）

#### ① 直接映射（Direct Mapped）
- **映射规则**：主存块号 $i$ 只能映射到唯一固定的 Cache 行号 $j$：
  $$j = i \pmod{M} \quad (M \text{ 为 Cache 总行数})$$
- **主存地址划分**：
  ```
  ┌──────────────────────┬──────────────────────┬──────────────────────┐
  │      主存标记 (Tag)    │    Cache 行号 (Index) │    块内地址 (Offset)  │
  └──────────────────────┴──────────────────────┴──────────────────────┘
  ```
- **物理优缺点**：
  - 优点：硬件实现极简。根据 Index 字段直接寻址唯一的 1 个 Cache 行，仅需 **1 个硬件比较器**比对 Tag，判断命中极快。
  - 缺点：灵活性最差。若两个高频访问的主存块恰好模 $M$ 同余，即便 Cache 中有大量其他空闲行，它们也会在同一个位置互相淘汰，引发剧烈的**乒乓效应（冲突缺失）**。

#### ② 全相联映射（Fully Associative）
- **映射规则**：主存块可以放置在 Cache 的**任意一个空闲行**。
- **主存地址划分**：
  ```
  ┌─────────────────────────────────────────────┬──────────────────────┐
  │                主存标记 (Tag)                 │    块内地址 (Offset)  │
  └─────────────────────────────────────────────┴──────────────────────┘
  ```
- **物理优缺点**：
  - 优点：空间利用率最高，完全消除了模同余导致的冲突缺失，只有当整个 Cache 彻底填满后才会触发容量替换。
  - 缺点：硬件代价极大。地址中不包含行索引，CPU 访问时必须**同时并行比较所有 Cache 行的 Tag**。若 Cache 包含 1024 行，就需要 1024 个硬件比较器（相联存储器 CAM），硬件电路庞大、功耗剧增、查找延迟难以压缩。

#### ③ 组相联映射（$k$-Way Set Associative）——工程黄金折中
- **映射规则**：将 Cache 划分为 $S$ 个组（Set），每组固定包含 $k$ 个行。主存块按组直接映射，组内按全相联自由放置在 $k$ 个行中：
  $$\text{组号 } q = i \pmod{S} \quad (S = \text{总行数 } M / k)$$
- **主存地址划分**：
  ```
  ┌──────────────────────┬──────────────────────┬──────────────────────┐
  │      主存标记 (Tag)    │       组号 (Set)     │    块内地址 (Offset)  │
  └──────────────────────┴──────────────────────┴──────────────────────┘
  ```
- **字段位宽计算准则**：
  1. $\text{Offset 位数} = \log_2(\text{块大小（以最小寻址单元计）})$。在标准字节编址下，即为 $\log_2(\text{每行字节数})$。
  2. $\text{Set 位数} = \log_2(\text{总组数 } S) = \log_2\left(\frac{\text{Cache 数据总容量}}{\text{块大小} \times k}\right)$。
  3. $\text{Tag 位数} = \text{主存物理地址总位数} - \text{Set 位数} - \text{Offset 位数}$。
- **物理折中**：仅需 $k$ 个硬件比较器并行比对目标组内的 $k$ 个行，既消除了直接映射的严重冲突，又规避了全相联映射不可承受的硬件成本。

### (3) Cache 行元数据构成与总容量严谨计算模型

一个物理 Cache 行由**数据阵列（Data Array）**与**标记阵列（Tag Array）**共同构成：

```
┌─────────────────────────────────────────────────────────────┬─────────────────────────────────┐
│                    标记阵列 (Tag Array)                      │        数据阵列 (Data Array)     │
├─────────────┬─────────────┬──────────────────────────┬──────┼─────────────────────────────────┤
│   有效位    │    脏位     │          替换位          │ Tag  │        数据块内容 (Data Block)   │
│   (Valid)   │   (Dirty)   │          (LRU)           │      │                                 │
└─────────────┴─────────────┴──────────────────────────┴──────┴─────────────────────────────────┘
```

1. **有效位（Valid bit）**：必占 **1 位**。系统上电复位时全置 0，当对应 Cache 行装入有效主存块后置 1。
2. **脏位（Dirty bit）**：
   - 仅在**写回策略（Write-Back）**下存在，占用 **1 位**。指示该行数据是否已被 CPU 修改（与主存不一致）；换出时若脏位为 1 必须刷回主存。
   - 若采用**写直达策略（Write-Through）**，CPU 写入时同步更新主存，Cache 与主存始终一致，**无脏位**（0 位）。
3. **替换位（LRU bits）——严防双重计算陷阱**：
   - **408 考场标准计数器法（行级计数器）**：
     在 $k$ 路组相联 Cache 中，若采用行级计数器维护访问热度，计数器取值范围为 $0 \sim k-1$，因此**每个 Cache 行需占用 $\log_2 k$ 位**（当 $k=4$ 时每行需 2 位）。
     $$\text{全 Cache 替换位总数} = \text{Cache 总行数} \times \log_2 k$$
   - **硬件严格配对矩阵法（组级矩阵）**：
     若题目明确指定使用矩阵法维护 LRU，每组需要一个 $k \times k$ 的布尔矩阵对角线三角部分，即**每个组（Set）占用 $\frac{k(k-1)}{2}$ 位**。
     $$\text{全 Cache 矩阵替换位总数} = \text{总组数 } S \times \frac{k(k-1)}{2}$$
     > [!CAUTION]
     > **警惕双重计数错误**：绝对不能将组级矩阵位数 $\frac{k(k-1)}{2}$ 乘以总行数！

#### 通用 Cache 芯片总硅片存储容量公式
$$\text{总位数} = \text{总行数} \times \left( \text{数据块位数} + \text{Tag 位数} + 1\text{ (Valid)} + [1\text{ (Dirty, 写回)}] + [\log_2 k\text{ (LRU, 计数器法)}] \right)$$

### (4) 经典计算范例（逐步推导）

**设某系统物理地址 32 位，按字节编址；Cache 数据容量为 64KB，Cache 行大小（块大小）为 64B，采用 4 路组相联映射，写回策略（Write-Back），计数器 LRU 替换策略。求该 Cache 芯片的总存储容量。**

1. **计算行数与组数**：
   - Cache 总行数 $M = \frac{64\text{KB}}{64\text{B}} = \frac{64 \times 1024}{64} = 1024$ 行。
   - 总组数 $S = \frac{1024}{4} = 256$ 组。
2. **划分地址各字段位宽**：
   - 块内偏移位：$\text{Offset} = \log_2(64) = 6$ 位。
   - 组号位：$\text{Set} = \log_2(256) = 8$ 位。
   - 主存标记位：$\text{Tag} = 32 - 8 - 6 = 18$ 位。
3. **计算单行标记阵列开销**：
   - Tag：18 位
   - 有效位：1 位
   - 脏位（写回）：1 位
   - LRU 位（4 路计数器）：$\log_2 4 = 2$ 位
   - 单行元数据总计：$18 + 1 + 1 + 2 = 22$ 位。
4. **计算总容量**：
   - 单行总位数 = 数据位（$64 \times 8 = 512$ 位）$+$ 元数据位（$22$ 位）$= 534$ 位。
   - Cache 芯片总容量 = $1024 \times 534 = 546,816$ 位。
   - 折合字节数：$546,816 / 8 = 68,352$ 字节 $\approx 66.75$ KB（其中数据占 64KB，标记与控制元数据占 2.75KB）。

### (5) 状态机执行轨迹：2 路组相联 Cache 访存与写回全过程

设某 2 路组相联 Cache 共分为 $S = 4$ 组（组号 = 主存块号 $\bmod 4$，标记 $\text{Tag} = \lfloor \text{主存块号} / 4 \rfloor$），考察其组 0（包含 Way 0 与 Way 1 两个槽位，块 0、8、16、24 均映射至组 0，对应 $\text{Tag} = 0, 2, 4, 6$），采用写回（Write-Back）+ 写分配（Write-Allocate）+ LRU 替换策略（1 位 LRU 位：0 表示最近刚访问 MRU，1 表示最久未访问 LRU）。

#### 连续 6 次访问组 0 的执行状态追踪表

| 步序 | 访问动作 | 目标块号 | Tag | 命中判定 | Way 0 状态 `(Tag, V, D, LRU)` | Way 1 状态 `(Tag, V, D, LRU)` | 触发的物理动作 |
| :---: | :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **0** | 初始状态 | - | - | - | `(-, 0, 0, 0)` | `(-, 0, 0, 0)` | 系统复位，所有行无效 |
| **1** | 读 Block 0 | 0 | 0 | **Miss (冷启动)** | **`(0, 1, 0, 0)` [MRU]** | `(-, 0, 0, 1)` [LRU] | 从主存调入 Block 0 至 Way 0，脏位清 0 |
| **2** | 写 Block 8 | 8 | 2 | **Miss (冷启动)** | `(0, 1, 0, 1)` [LRU] | **`(2, 1, 1, 0)` [MRU]** | 调入 Block 8 至 Way 1 并写入，置脏位 $D=1$ |
| **3** | 写 Block 0 | 0 | 0 | **Hit** | **`(0, 1, 1, 0)` [MRU]** | `(2, 1, 1, 1)` [LRU] | Way 0 命中写入，置脏位 $D=1$，翻转为 MRU |
| **4** | 读 Block 16| 16| 4 | **Miss (冲突)** | `(0, 1, 1, 1)` [LRU] | **`(4, 1, 0, 0)` [MRU]** | **淘汰 Way 1 (Tag 2)：因 $D=1$，触发将 Block 8 写回主存！** 调入 Block 16 |
| **5** | 读 Block 0 | 0 | 0 | **Hit** | **`(0, 1, 1, 0)` [MRU]** | `(4, 1, 0, 1)` [LRU] | Way 0 命中，保持 $D=1$，刷新为 MRU |
| **6** | 读 Block 24| 24| 6 | **Miss (冲突)** | `(0, 1, 1, 1)` [LRU] | **`(6, 1, 0, 0)` [MRU]** | **淘汰 Way 1 (Tag 4)：因 $D=0$，直接丢弃（无写回）！** 调入 Block 24 |

### (6) 写策略的工程组合

| 策略组合 | 写入命中 (Write Hit) 处理 | 写入缺失 (Write Miss) 处理 | 硬件复杂度与总线压力 |
| :--- | :--- | :--- | :--- |
| **写直达 + 非写分配**<br>(Write-Through + No-Write-Allocate) | 同时写入 Cache 和主存（常配合写缓冲 Write Buffer 降低等待） | 直接将数据写入主存，**不调块入 Cache** | 简单，无脏位，但写操作频繁挤占内存总线带宽 |
| **写回 + 写分配**<br>(Write-Back + Write-Allocate) | 只写入 Cache，置脏位为 1，换出时才刷回主存 | 先从主存将缺失块载入 Cache，再写入 Cache | 速度快，大幅降低总线写冲突，需额外脏位与掉电保护 |

### (7) 平均访存时间（AMAT）计算模型

设 Cache 命中率为 $h$，Cache 访问时间为 $t_c$，主存访问时间为 $t_m$。

1. **串行访问体系（先查 Cache，缺失后再访主存）**：
   $$\text{AMAT} = t_c + (1 - h) \cdot t_m$$
   - 物理机理：CPU 发出访存请求时，先花费 $t_c$ 时间检索 Cache。若命中直接返回；若发生缺失（概率为 $1-h$），再额外花费 $t_m$ 时间访问主存并将数据送入 CPU。
2. **并行/同时访问体系（同时启动 Cache 与主存）**：
   $$\text{AMAT} = h \cdot t_c + (1 - h) \cdot t_m$$
   - 物理机理：CPU 发出访存请求时，硬件控制器同时向 Cache 与主存发起读取。若 Cache 命中（概率为 $h$），耗时 $t_c$ 获得数据并立刻中止主存总线事务；若 Cache 缺失，主存数据在耗时 $t_m$ 时到达。
   > [!IMPORTANT]
   > 考场审题必须仔细甄别题干给出的缺失代价是否已经包含了 Cache 探测时间 $t_c$。

```
                     ┌──────────────────────────────────────┐
                     │    计组: Cache 映射与地址切分逻辑     │
                     └──────────────────┬───────────────────┘
                                        │ 物理地址切分 (Tag/Set/Offset)
                   ┌────────────────────┴────────────────────┐
                   ▼                                         ▼
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│  计组: 虚拟存储器与 TLB 转换          │  │  计组: CPU 指令流水线执行           │
│  - TLB 是页表的 Cache (快表)         │  │  - Load/Store 指令触发访存级       │
│  - PIPT: 先经 TLB 查出 PA 再查 Cache │  │  - Cache Miss 产生多周期流水线气泡 │
└──────────────────────────────────────┘  └──────────────────────────────────────┘
```

1. **与虚拟存储器及 TLB 的层级映射对照**：
   - [存储器分类与技术](01-memory-types.md)：SRAM 与 DRAM 的物理电气差异决定了 Cache 与主存的层级分工。
   - [硬件级虚拟存储与TLB](03-virtual-memory-hardware.md)：TLB 实质上是页表项的专用高速 Cache，通常采用全相联或高路数组相联。在物理索引物理标记（PIPT）架构下，虚拟地址（VA）必须先经 TLB/页表翻译出物理地址（PA），再利用 PA 拆解为 Tag/Set/Offset 查 Cache。
2. **与操作系统页置换算法的机理同构**：
   - Cache 行替换由**纳秒级纯硬件逻辑**执行，因此只能选用电路开销小的 LRU 计数器、FIFO 或随机替换。
   - 操作系统的[基本分页与分段](../../03-os/03-memory/02-paging-and-segmentation.md)页面置换由**操作系统缺页异常处理程序（毫秒级软件）**接管，因而可以维护更加复杂的 Clock（时钟）与改进型 Clock 链表。

## 4. 闭环决策模型与核心认知结论

### (1) 地址切分三步法（考场不可动摇的运算步骤）
1. **第 1 步：算 Offset 位数**
   $$\text{Offset} = \log_2(\text{Cache 行大小字节数})$$
2. **第 2 步：算 Index / Set 位数**
   - 直接映射：$\text{Index 位数} = \log_2(\text{Cache 总行数})$
   - $k$ 路组相联：$\text{Set 位数} = \log_2(\text{总组数 } S) = \log_2\left(\frac{\text{Cache 总行数}}{k}\right)$
   - 全相联：$\text{Set 位数} = 0$
3. **第 3 步：算 Tag 位数**
   $$\text{Tag} = \text{物理地址总位数} - \text{Set位数} - \text{Offset位数}$$

### (2) 考场定性闭环判据
- **写回策略（Write-Back）** $\to$ 标记阵列中**必含 1 位脏位（Dirty Bit）**。
- **写直达策略（Write-Through）** $\to$ 标记阵列中**无脏位（0 位）**。
- **直接映射** $\to$ 每组只有 1 行，新块进入直接覆盖，**不需要任何替换位（0 位）**。
- **$k$ 路组相联 LRU 计数器模型** $\to$ 每个 Cache 行需要 $\log_2 k$ 位替换位。
