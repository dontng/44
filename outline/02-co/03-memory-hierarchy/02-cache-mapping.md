## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - 局部性原理：时间局部性与空间局部性在硬件缓存上的物理实现。
  - 主存-Cache 地址映射机制：直接映射、全相联映射、组相联映射的地址字段拆分与硬件实现。
  - Cache 行结构与总容量计算：标记项（Tag）、有效位（Valid）、脏位（Dirty）、替换位（LRU）的位宽与存储开销。
  - 替换策略（LRU、FIFO、RAND）与缺失类型（冷启动缺失、冲突缺失、容量缺失）。
  - 写策略：写直达（Write-Through）与写回（Write-Back），写分配（Write-Allocate）与非写分配（No-Write-Allocate）。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须引入 Cache 映射与地址划分？
- **物理困境**：
  - CPU 运算频率在 GHz 级别（周期纳秒级），而主存 DRAM 访问时延在数十纳秒级，形成巨大“内存墙”。
  - SRAM 速度极快但单位面积硅片成本高昂、发热量大，无法将全部内存做成 SRAM。
  - 依据局部性原理：90% 的指令执行和数据访问集中在 10% 的空间内。Cache 作为高速 SRAM 缓存，保存主存中最活跃的块（Block/Line，通常为 32B 或 64B）。
  - **核心硬件问题**：当 CPU 给出主存物理地址时，如何在纳秒级的时间内快速判断该地址所在的数据块是否已在 Cache 中？如果存在，它被放在了哪个具体的 Cache 行中？

### (2) 三大映射方式的硬件折中（Trade-off）

#### ① 直接映射（Direct Mapped）
- **映射规则**：主存块号 $i$ 只能映射到固定的 Cache 行号 $j$：
  $$j = i \pmod{M} \quad (M \text{ 为 Cache 总行数})$$
- **主存地址划分**：
  ```
  ┌──────────────────────┬──────────────────────┬──────────────────────┐
  │      主存标记 (Tag)    │    Cache 行号 (Index) │    块内地址 (Offset)  │
  └──────────────────────┴──────────────────────┴──────────────────────┘
  ```
- **物理优缺点**：
  - 优点：硬件实现极简，每次只需根据 Index 索引到唯一的 1 个 Cache 行，只需 1 个硬件比较器比对 Tag，速度最快。
  - 缺点：灵活性最差。若两个高频访问的主存块恰好模 $M$ 同余，即使 Cache 内有大量其他空闲行，它们也会在同一个位置互相踢出（乒乓效应/冲突缺失严重）。

#### ② 全相联映射（Fully Associative）
- **映射规则**：主存块可以放置在 Cache 的**任意空闲行**。
- **主存地址划分**：
  ```
  ┌─────────────────────────────────────────────┬──────────────────────┐
  │                主存标记 (Tag)                 │    块内地址 (Offset)  │
  └─────────────────────────────────────────────┴──────────────────────┘
  ```
- **物理优缺点**：
  - 优点：空间利用率最高，完全消除冲突缺失，只有当整个 Cache 彻底填满时才会发生替换（容量缺失）。
  - 缺点：硬件代价极大。地址中没有行号，CPU 访问时必须**同时并行比较所有 Cache 行的 Tag**。若 Cache 有 1024 行，就需要 1024 个硬件比较器（相联存储器 CAM），面积大、功耗高、时延难以压缩。

#### ③ 组相联映射（$k$-Way Set Associative）——工程黄金折中
- **映射规则**：将 Cache 划分为 $S$ 个组（Set），每组包含 $k$ 个行。主存块按组直接映射，组内全相联自由放置：
  $$\text{组号 } q = i \pmod{S}$$
- **主存地址划分**：
  ```
  ┌──────────────────────┬──────────────────────┬──────────────────────┐
  │      主存标记 (Tag)    │       组号 (Set)     │    块内地址 (Offset)  │
  └──────────────────────┴──────────────────────┴──────────────────────┘
  ```
  其中：
  - 块内偏移位数 = $\log_2(\text{块大小})$
  - 组号位数 = $\log_2(\text{总组数 } S) = \log_2\left(\frac{\text{Cache总容量}}{\text{块大小} \times k}\right)$
  - Tag 位数 = 主存地址总位数 - 组号位数 - 块内偏移位数
- **物理折中**：既不需要全相联成百上千的比较器，又不像直接映射那样死板。对于 $k$ 路组相联，硬件只需要 $k$ 个比较器并行工作，便能取得接近全相联的低冲突缺失率。

### (3) Cache 行的硬件构成与总容量计算
Cache 中不仅存储用户可见的数据（Data Array），还必须存储维持硬件逻辑运转的元数据（Tag Array）。每个 Cache 行硬件上由两部分构成：

```
┌─────────────────────────────────┬─────────────────────────────────┐
│         标记阵列 (Tag Array)     │        数据阵列 (Data Array)     │
├─────────┬─────────┬────────┬────┼─────────────────────────────────┤
│ 有效位  │  脏位   │ 替换位 │Tag │        数据块内容 (Data Block)   │
│ (Valid) │ (Dirty) │ (LRU)  │    │                                 │
└─────────┴─────────┴────────┴────┴─────────────────────────────────┘
```

1. **有效位（Valid bit）**：必占 1 位。开机或复位时置 0，载入有效数据后置 1。
2. **脏位（Dirty bit）**：仅在**写回策略（Write-Back）**下存在（1 位）。指示该块是否被 CPU 写入修改过；若为 1，被换出时必须写回主存；若为**写直达策略（Write-Through）**，无此位。
3. **替换位（LRU bits）**：组相联或全相联映射下，记录使用热度。对于 $k$ 路组相联，使用硬件计数器实现完全 LRU 算法时，替换位需要 $\log_2 k$ 位（或严格矩阵法 $\frac{k(k-1)}{2}$ 位，408 题目若未特指通常按 $\lceil \log_2 k \rceil$ 或题目直接给出）。
4. **标记位（Tag bits）**：根据地址划分公式计算得出。

$$\text{Cache 芯片总硅片存储容量} = (\text{数据位宽} + \text{Tag位宽} + \text{有效位} + \text{脏位} + \text{LRU位}) \times \text{Cache总行数}$$

### (4) 写策略的工程抉择

| 策略组合 | 写入命中 (Write Hit) 处理 | 写入缺失 (Write Miss) 处理 | 硬件复杂度与总线压力 |
| :--- | :--- | :--- | :--- |
| **写直达 + 非写分配**<br>(Write-Through + No-Write-Allocate) | 同时写入 Cache 和主存（常配合写缓冲 Write Buffer） | 直接将数据写入主存，**不调块入 Cache** | 简单，但频繁占用内存总线写带宽 |
| **写回 + 写分配**<br>(Write-Back + Write-Allocate) | 只写入 Cache，置脏位为 1，换出时才刷回主存 | 先从主存将缺失块载入 Cache，再写入 Cache | 速度快，大幅降低总线写冲突，但需要脏位及断电数据一致性处理 |

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 计组: Cache 映射与硬件控制器   │
                     └──────────────┬───────────────┘
                                    │ 物理地址切分 (Tag/Set/Offset)
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 计组: 虚拟存储器与 TLB 转换    │         │ 计组: CPU 流水线访存阶段      │
│  - TLB 是页表的 Cache        │ ◄────── │  - Load/Store 指令触发访存    │
│  - 物理地址 PA 查 L1/L2 Cache │         │  - Cache 缺失引发流水线气泡    │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与虚拟存储器及 TLB 的层级映射对照**：
   - TLB 是“页表的 Cache”，采用全相联或高路数组相联，由硬件 MMU 极速比对。
   - 现代 CPU 普遍采用 VIPT（Virtual Index Physical Tag，虚索引实标记）或 PIPT（Physically Indexed Physically Tagged）。在 PIPT 中，CPU 发出的虚拟地址（VA）必须先经 TLB/页表翻译出物理地址（PA），再用 PA 拆解为 Tag/Set/Offset 访问 Cache。
2. **与操作系统页置换算法的机理同构**：
   - Cache 行替换是**纳秒级纯硬件电路**完成的（由状态机或有限门电路执行），因此只能采用 LRU、FIFO 或随机等低复杂度算法。
   - 操作系统的虚存页面置换是**毫秒级纯软件（OS 缺页中断）**完成的，因而可以维护更加复杂的 Clock、改进型 Clock 等软件链表。

## 4. 闭环决策模型与核心认知结论

### (1) 地址切分三步法（考场不可动摇的运算步骤）
1. **第 1 步：算 Offset**
   $$\text{Offset 位数} = \log_2(\text{Cache 行大小 / 主存块大小字节数})$$
2. **第 2 步：算 Index / Set**
   - 若为直接映射：$\text{Index 位数} = \log_2(\text{Cache 总行数})$
   - 若为 $k$ 路组相联：$\text{Set 位数} = \log_2\left(\frac{\text{Cache 总行数}}{k}\right) = \log_2(\text{总组数})$
   - 若为全相联：$\text{Set 位数} = 0$
3. **第 3 步：算 Tag**
   $$\text{Tag 位数} = \text{物理地址总位数} - \text{Set位数} - \text{Offset位数}$$

### (2) 闭环判定定性规则
- **只要题目说明“采用写回（Write-Back）策略”** $\to$ Cache 行首部必包含 **1 位脏位（Dirty Bit）**。
- **只要题目说明“采用写直达（Write-Through）策略”** $\to$ Cache 行**无脏位**。
- **只要题目说明“$k$ 路组相联且采用 LRU 替换”** $\to$ 每个 Cache 行需要的替换状态位一般为 $\log_2 k$ 位。
- **对于直接映射**：由于每组只有 1 行，**不需要任何替换位**（发生冲突时只能无条件替换原有行）。
