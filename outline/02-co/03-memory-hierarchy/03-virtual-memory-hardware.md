## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么需要 MMU 与硬件分页？
- **物理困境**：
  - 多任务并发时，若程序直接操作物理内存：
    1. **内存碎片与非连续分配**：大进程因缺乏连续物理空间而无法加载；
    2. **安全性与越权**：恶意程序可直接篡改其他进程或内核的物理内存数据；
    3. **物理容量瓶颈**：程序体量超过物理 DRAM 大小时直接无法运行。
- **硬件解法**：
  - CPU 内部集成 **MMU（内存管理单元）**，CPU 指令中执行的所有地址均为**虚拟地址（VA）**。
  - 将虚拟地址空间切分为固定大小的“虚拟页（Virtual Page, VP）”，将物理内存切分为等大的“物理页框（Page Frame, PF）”，通常为 4KB。
  - 无论物理页框离散分布在 DRAM 的何处，硬件通过**页表（Page Table）**将离散的物理页框映射为连续的虚拟地址空间。

### (2) 硬件地址切分与基准转换公式
假设虚拟地址为 32 位，页面大小为 4KB（$4\text{KB} = 2^{12}\text{B}$）：

```
虚拟地址 (VA):
┌───────────────────────────────────────────────┬──────────────────────────────┐
│            虚拟页号 VPN (20 bits)             │       页内偏移 (12 bits)      │
└───────────────────────────────────────────────┴──────────────────────────────┘
                         │ 查页表 (PTE)
                         ▼
物理地址 (PA):
┌───────────────────────────────────────────────┬──────────────────────────────┐
│            物理页框号 PFN (假设 20 bits)       │       页内偏移 (12 bits)      │
└───────────────────────────────────────────────┴──────────────────────────────┘
```

- **物理不变性**：
  $$\text{虚拟页内偏移} \equiv \text{物理页框内偏移}$$
  因为虚拟页与物理页框的尺寸在硬件上严格相等，低位偏移量无需任何转换，直接按位拷贝拼接。硬件翻译的核心任务仅仅是将 **VPN $\to$ PFN**。

### (3) 为什么必须有快表（TLB）？
- **访存翻倍悖论**：
  - 没有 TLB 时，CPU 每执行一次访存操作（如读取一个变量）：
    1. 第一次访存：MMU 必须先访问主存中的页表，读出页表项（PTE），得到物理页框号 PFN；
    2. 第二次访存：MMU 用 PFN 拼接页内偏移得到物理地址 PA，再次访问主存读取实际数据。
  - 这导致 CPU 的访存时延直接**增加一倍**（两级页表则增加两倍，需要 3 次访存）。
- **工程解法：TLB 快表**
  - 在 MMU 芯片内部集成一块微型、超高速的 SRAM（相联存储器 CAM），称为 **TLB（Translation Lookaside Buffer）**。
  - TLB 专门用来缓存最近使用过的**页表项（VPN $\to$ PFN 映射）**。
  - CPU 发出 VA 时，VPN 同时与 TLB 内部所有项高速并行比对：
    - **TLB 命中（TLB Hit）**：0 个主存周期内直接输出 PFN，彻底消除查页表开销。
    - **TLB 缺失（TLB Miss）**：硬件（或硬件遍历器 Page Table Walker）再到主存页表中查找 PTE，并将其更新载入 TLB。

### (4) 现代处理器的完整访存全流程（TLB $\to$ Page Table $\to$ Cache $\to$ Main Memory）

```
                     CPU 发出虚拟地址 VA (VPN + Offset)
                                    │
                                    ▼
                          【 步骤 1: 查 TLB 】
                                 /     \
                       (命中 Hit)       (缺失 Miss)
                             /             \
                            /          【 步骤 2: 查主存页表 】
                           /                  /         \
                          /         (在主存 Hit)         (不在主存 Miss: 产生缺页中断)
                         /                 /                     │
                        │        更新载入 TLB                     ▼
                        │               │               【 操作系统介入: 软件缺页处理 】
                        │               │                - 磁盘 I/O 调入页面到物理页框
                        │               │                - 更新页表项 (有效位/PFN)
                        │               │                - 重新执行引发缺页的原指令
                        ▼               ▼                        │
                      拼接得到物理地址 PA (PFN + Offset) ◄────────┘
                                    │
                                    ▼
                          【 步骤 3: 查 L1/L2 Cache 】
                                 /     \
                       (命中 Hit)       (缺失 Miss)
                             /             \
                            /          【 步骤 4: 访问主存 DRAM 】
                           /               - 读取数据块填充 Cache
                          /                - 交付 CPU 寄存器
                         ▼
                   返回数据给 CPU
```

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 计组: 硬件 MMU 与 TLB 结构   │
                     └──────────────┬───────────────┘
                                    │ 缺页时硬件抛出中断信号
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 操作系统: 缺页异常与页面置换   │         │ 计组: CPU 异常响应与指令重执  │
│  - 调页策略 (请求调页)        │ ◄────── │  - 压栈断点 PC (指向当前指令) │
│  - Clock / LRU 页面置换      │         │  - 软件处理完后 iret 重新执行 │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **软硬件分工边界（极为关键）**：
   - **硬件职责（MMU 内部全自动电路）**：地址拆分、TLB 并行查找、物理地址拼接、有效位检测、越权写保护检测。
   - **操作系统职责（纯软件中断处理程序）**：缺页异常响应、磁盘外存交换区 I/O 调度、物理页框分配与回收、页面置换算法决策、进程切换时刷新 CR3/PDBR 寄存器。
2. **多级页表的物理本质**：
   - 32 位平坦页表需要 $2^{20} \times 4\text{B} = 4\text{MB}$ 连续物理内存，每个进程都独占 4MB，主存不堪重负。
   - 二级页表将页表本身进行离散分页。**顶级页目录表必须常驻物理内存**，而二级页表只有在对应的虚拟地址区间实际被分配使用时才按需动态建立，极大地压缩了内存开销。

## 4. 闭环决策模型与核心认知结论

### (1) 访存状态组合“合法性”四字禁令表

| 组合情形 | TLB 状态 | 页表状态 (Page Table) | Cache 状态 | 物理合法性判定与客观机理 |
| :---: | :---: | :---: | :---: | :--- |
| **A** | **命中** | **命中** | **命中** | **完全合法**。最快路径，纯高速缓存极速响应。 |
| **B** | **命中** | **命中** | **缺失** | **完全合法**。虚实地址转换命中，但目标数据块尚未载入 Cache。 |
| **C** | **缺失** | **命中** | **命中** | **完全合法**。TLB 未缓存页表项，但目标数据其实已在 Cache 中（使用 PIPT 时查出 PA 后命中 Cache）。 |
| **D** | **缺失** | **命中** | **缺失** | **完全合法**。普通访存缺失，从 DRAM 载入数据并补充 TLB 和 Cache。 |
| **E** | **命中** | **缺失** | 任意 | **物理绝对不可能！**<br>TLB 是页表的子集（缓存）。页表中不存在/缺失意味着该页根本不在主存中，TLB 绝不可能凭空命中。 |
| **F** | **缺失** | **缺失(缺页)**| **命中** | **物理绝对不可能！**<br>页表缺失说明数据还在磁盘外存中，主存中根本没有该物理页框，Cache 作为主存的子集绝不可能命中。 |

### (2) 考场做题闭环判据
1. **只要 TLB 命中** $\to$ 该虚拟页**必定在主存中**（页表必命中），**绝不可能发生缺页异常**。
2. **只要 Cache 命中** $\to$ 该数据**必定在主存中**（页表必命中），**绝不可能发生缺页异常**。
3. **只要发生缺页异常** $\to$ **TLB 必定缺失**，且 **Cache 必定缺失**。
