## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 物理困境与硬件分页的必要性
- **物理困境**：
  - 在早期无虚拟存储的系统中，程序直接在物理内存（DRAM）中寻址运行。随着多任务操作系统并发运行，面临三大物理障碍：
    1. **内存碎片与非连续分配**：动态分配导致物理内存出现大量外部碎片，即便空闲总容量足够，也因缺乏连续物理空间而无法加载大程序；
    2. **安全性与进程越权**：应用程序能够直接读写任意物理内存地址，缺乏硬件级隔离机制，可能恶意篡改其他进程或内核的数据；
    3. **物理容量硬上限**：程序工作集必须完全载入物理 DRAM 才能运行，无法运行超过物理内存容量的程序。
- **硬件解法：MMU 与分页机制**：
  - CPU 内部集成 **内存管理单元（MMU）**，CPU 执行指令生成的所有地址均为**虚拟地址（VA）**。
  - 将虚拟地址空间切分为固定大小的“虚拟页（Virtual Page, VP）”，将物理内存切分为等大的“物理页框（Page Frame, PF）”，标准页面大小通常为 4KB（$4\text{ KB} = 2^{12}\text{ B}$）。
  - 无论物理页框在 DRAM 中如何离散分布，硬件通过驻留在主存中的**页表（Page Table）**将离散的物理页框映射为连续的虚拟地址空间。

```
虚拟地址 (VA):
┌───────────────────────────────────────────────┬──────────────────────────────┐
│            虚拟页号 VPN (n - k 位)             │       页内偏移 (k 位)         │
└───────────────────────────────────────────────┴──────────────────────────────┘
                         │ 查页表项 (PTE: VPN → PFN)
                         ▼
物理地址 (PA):
┌───────────────────────────────────────────────┬──────────────────────────────┐
│            物理页框号 PFN (m - k 位)           │       页内偏移 (k 位)         │
└───────────────────────────────────────────────┴──────────────────────────────┘
```

- **物理不变性**：
  $$\text{虚拟页内偏移} \equiv \text{物理页框内偏移}$$
  因为虚拟页与物理页框的几何尺寸在硬件上严格相等（均为 $2^k$ 字节），低位偏移量无需任何运算，直接透明按位拷贝拼接。硬件翻译的核心任务仅为：将 **VPN 映射为 PFN**。

### (2) 访存翻倍悖论与 TLB 硬件加速
- **访存翻倍悖论**：
  - 没有 TLB 时，CPU 每执行一次数据访存指令（如读取一个变量）：
    1. **第一次访存**：MMU 必须首先访问物理主存中存储的页表，根据 VPN 读出页表项（PTE），获取目标物理页框号 PFN；
    2. **第二次访存**：MMU 用 PFN 拼接页内偏移得到实际物理地址 PA，再次访问主存读取真实数据。
  - 若采用两级页表，单次访存前必须先访存 2 次查询页表，总访存次数增至 3 次；四级页表则高达 5 次访存。访存时延成倍暴增，处理器性能将严重降低。
- **工程解法：TLB 快表**：
  - 在 MMU 内部集成一块微型、超高速的 SRAM（通常采用内容寻址相联存储器 CAM），称为 **TLB（Translation Lookaside Buffer）**。
  - TLB 专门用来缓存最近使用过的**页表项（VPN $\to$ PFN 映射关系及其状态位）**。
  - CPU 发出 VA 时，VPN 在单个时钟周期内与 TLB 中所有表项并行比对：
    - **TLB 命中（TLB Hit）**：直接输出 PFN，消除查主存页表的访存开销；
    - **TLB 缺失（TLB Miss）**：硬件（或软件中断）启动页表遍历，从主存页表中读取 PTE，并将其更新载入 TLB。

---

### (3) 硬件页表遍历（Hardware Page Table Walker）vs 软件管理 TLB
在发生 TLB 缺失后，系统如何补全缺失的映射？体系结构存在两条截然不同的路线：

| 对比维度 | 硬件管理页表（x86 / ARM 等标准考查模型） | 软件管理 TLB（MIPS / SPARC 等架构） |
| :--- | :--- | :--- |
| **缺失处理主体** | **MMU 内部硬件状态机（Page Table Walker）** | **操作系统内核轻量异常处理程序（TLB Refill Trap）** |
| **页表结构约束** | 页表格式（树状多级、项格式）被硬件固化，OS 必须遵守 | 硬件不规定页表格式，OS 可自由采用哈希、反置或树状页表 |
| **TLB Miss 时延** | 极低（数十纳秒硬件有限状态机自动遍历） | 较高（陷入异常、保存通用寄存器、执行遍历代码、恢复现场） |
| **发生缺页处理** | 仅当硬件查到 PTE 的有效位 `Valid = 0` 时，才触发缺页异常中断 | 软件遍历发现 PTE 无效时，直接跳转至通用缺页异常服务程序 |

> **408 标准考场基准**：408 统考默认采用 **硬件页表遍历模型**。当 TLB 缺失且主存中 PTE 有效时，由 MMU 硬件电路自动完成查表并填充 TLB，此过程属于正常的硬件时延，**不产生操作系统软件中断**；只有当 PTE 的有效位为 0（物理页框未分配或数据在外存）时，硬件才会向 CPU 产生 **缺页异常（Page Fault Exception）** 软硬件交接信号。

### (4) 408 考场标准模型 vs 现代工程实现边界：PIPT 与 VIPT 机制解耦
当 CPU 从虚地址发起读请求，既要经过 MMU/TLB 翻译地址，又要经过 L1 Cache 读取数据，二者的时序关系在体系结构上有两种核心实现：

```
1. 物理索引物理标记 (PIPT, 考场基准模型):
   VA ──► [ TLB / 页表 翻译 ] ──► PA ──► [ Cache 组索引 (Index) ] ──► [ Cache Tag 比较 ]
   (缺点: 串行化，Cache 查找必须等待地址翻译彻底完成，增加流水线周期时延)

2. 虚索引物理标记 (VIPT, 现代高性能 L1 Cache):
   VA ──┬──► [ VPN (高位) ] ──────► [ TLB 并行翻译 ] ──► PFN (物理页框号)
        │                                                        │
        └──► [ 页内偏移 (低位) ] ──► [ Cache 组索引 (Index) ]      │ 并行比对
                                              │                   │
                                              ▼                   ▼
                                      [ 读出 Cache Tag ] ◄──比较──┘
```

#### VIPT 杜绝重名（Aliasing / Synonym）的充要数学条件
- **重名问题（Aliasing）**：若两个不同的虚拟地址映射到同一个物理地址，且它们在 Cache 中被索引到不同的 Cache 组，将导致同一物理数据在 Cache 中存在多份副本，造成严重的数据不一致。
- **消除重名的硬件铁律**：Cache 寻址所用的 **组索引（Index）字段必须完全落在虚拟地址的“页内偏移（Page Offset）”范围内**。
  - 设虚拟页大小为 $\text{PageSize} = 2^k$ 字节（如 4KB，则 $k = 12$）；
  - 设 Cache 块大小为 $\text{BlockSize} = 2^b$ 字节（如 64B，则 $b = 6$）；
  - 设 Cache 组数为 $\text{SetCount} = 2^s$ 组（组索引占用 $s$ 位）；
  - 组索引的最高位比特下标为 $b + s - 1$。
  - **无重名充要条件**：
    $$b + s \le k \iff 2^s \times 2^b \le 2^k \iff \frac{\text{Cache 容量}}{\text{相联度（路数）}} \le \text{页面大小}$$
  - **物理含义**：只要 Cache 单个路（Way）的容量不超过单个虚拟页面大小，组索引位全部来自未经翻译的页内偏移位。由于虚拟页内偏移与物理页框内偏移在二进制位上严格恒等，VIPT 的虚索引与物理索引物理完全一致，既实现了 TLB 与 Cache 的完全并行启动，又在物理电路上杜绝了重名歧义。

## 3. 层次化访存协同联动与 8 种组合合法性判定

### (1) 物理与操作系统一致性前提假设
在分析 TLB、页表与 Cache 的所有状态组合时，必须明确以下三个底层系统前提：
1. **地址有效性前提**：目标虚拟地址位于该进程合法的虚拟内存空间内，忽略权限违规（如向只读代码段写入触发的保护异常）；
2. **TLB 包含性与一致性**：TLB 是主存页表的缓存子集。操作系统在将主存页面置换到外存交换区时，必须通过硬件指令（如 x86 的 `invlpg` 指令或多核下的 TLB 击落 TLB Shootdown）将 TLB 中对应的表项同步置为无效；
3. **Cache 包含性与一致性**：Cache 是主存物理数据的缓存子集。操作系统或 DMA 换出物理页框前，必须将 Cache 中该页所有脏数据写回主存，并将对应 Cache 行置为无效（Invalid）。

---

### (2) 全状态组合合法性判定矩阵

| 组合编号 | TLB 状态 | 页表状态 (Page Table) | Cache 状态 | 物理合法性 | 机制剖析与客观发生场景 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **1** | **命中** | **命中** | **命中** | **完全合法** | **极速读写路径**：TLB 迅速给出 PFN，Cache 迅速命中并交付数据，无需任何主存 DRAM 交互。 |
| **2** | **命中** | **命中** | **缺失** | **完全合法** | **数据初次载入**：地址翻译命中，但目标数据块尚未缓存在 Cache 中，需从物理 DRAM 读取数据并填充 Cache。 |
| **3** | **缺失** | **命中** | **命中** | **完全合法** | **TLB 替换重叠**：TLB 容量较小，原表项因容量冲突被驱逐置换；但目标数据所在的 Cache 行生命周期更长仍驻留于 Cache，重新通过硬件页表遍历得到 PFN 后直接命中 Cache。 |
| **4** | **缺失** | **命中** | **缺失** | **完全合法** | **常规双缺失**：新访问区域，TLB 与 Cache 均未建立映射。硬件查页表载入 TLB，读主存载入 Cache。 |
| **5** | **命中** | **缺失(缺页)** | **命中** | **物理绝对不可能** | **包含关系矛盾**：TLB 缓存的是主存中有效 PTE 的副本。若页表缺失（页面未分配或在外存），TLB 绝不可能凭空命中；且外存数据未入物理主存，Cache 绝不可能缓存外存数据。 |
| **6** | **命中** | **缺失(缺页)** | **缺失** | **物理绝对不可能** | **子集约束违背**：页表项无效意味着该页不在内存，在严格一致性协议下 TLB 中该项必已被清除，TLB 绝不可能命中。 |
| **7** | **缺失** | **缺失(缺页)** | **命中** | **物理绝对不可能** | **存储层级颠倒**：Cache 存储的是物理主存块的副本。页表缺失表明该虚拟页尚未调入物理主存，物理 DRAM 中甚至没有分配页框，Cache 绝不可能存储不存在的物理页数据。 |
| **8** | **缺失** | **缺失(缺页)** | **缺失** | **完全合法** | **经典缺页异常路径**：TLB 查无此项，硬件遍历页表检测到 `Valid = 0`，MMU 抛出缺页异常，CPU 挂起当前指令，操作系统调页中断服务程序介入，从磁盘读入物理页框。 |

---

### (3) 考场做题闭环判据
1. **只要 TLB 命中** $\implies$ 该页**必定已在主存中**（页表必命中），**绝不可能发生缺页异常**；
2. **只要 Cache 命中** $\implies$ 该数据**必定已在主存中**（页表必命中），**绝不可能发生缺页异常**；
3. **只要发生缺页异常** $\implies$ **TLB 必定缺失**，且 **Cache 必定缺失**。

## 4. 有效访存时间（EAT）精确数值推导与多路径展开

### (1) 参数定义与时延分量
设计算机系统采用 PIPT 串行访存体系，包含 TLB、单级/两级页表、L1 Cache 与主存外存系统，基准参数定义如下：
- $t_{\text{tlb}} = 1\text{ ns}$（TLB 查询时间，SRAM 阵列）
- $t_{\text{cache}} = 2\text{ ns}$（L1 Cache 查询时间，SRAM 阵列）
- $t_{\text{mem}} = 50\text{ ns}$（主存 DRAM 一次读写时间）
- $t_{\text{fault}} = 5\text{ ms} = 5,000,000\text{ ns}$（操作系统缺页中断服务时间，含磁盘 I/O）
- $h_{\text{tlb}} = 95\%$（TLB 命中率）
- $h_{\text{cache}} = 90\%$（Cache 命中率）
- $p_{\text{fault}} = 0.001\% = 10^{-5}$（缺页率，即主存页表中有效位为 0 的概率）

---

### (2) 互斥访问路径时延精算表

在发生访存时，各分支路径的执行行为与绝对物理耗时如下：

| 访问路径分类 | 路径触发条件 | 硬件执行动作序列 | 路径耗时计算公式与数值 |
| :--- | :--- | :--- | :--- |
| **路径 1：极速命中** | TLB 命中 且 Cache 命中 | 查 TLB 输出 PFN $\to$ 查 Cache 读出数据 | $t_{\text{tlb}} + t_{\text{cache}} = 1 + 2 = \mathbf{3\text{ ns}}$ |
| **路径 2：Cache 缺失** | TLB 命中 且 Cache 缺失 | 查 TLB 输出 PFN $\to$ 查 Cache 缺失 $\to$ 读 DRAM 主存 | $t_{\text{tlb}} + t_{\text{cache}} + t_{\text{mem}} = 1 + 2 + 50 = \mathbf{53\text{ ns}}$ |
| **路径 3：TLB 缺失 Cache 命中** | TLB 缺失、页表命中 且 Cache 命中 | 查 TLB 缺失 $\to$ 读 DRAM 页表更新 TLB $\to$ 查 Cache 命中 | $t_{\text{tlb}} + t_{\text{mem}} + t_{\text{cache}} = 1 + 50 + 2 = \mathbf{53\text{ ns}}$ |
| **路径 4：双缺失** | TLB 缺失、页表命中 且 Cache 缺失 | 查 TLB 缺失 $\to$ 读 DRAM 页表 $\to$ 查 Cache 缺失 $\to$ 读 DRAM 数据 | $t_{\text{tlb}} + t_{\text{mem}} + t_{\text{cache}} + t_{\text{mem}} = 1 + 50 + 2 + 50 = \mathbf{103\text{ ns}}$ |
| **路径 5：缺页异常** | TLB 缺失 且 页表缺失 (缺页) | 查 TLB 缺失 $\to$ 查页表发现缺页 $\to$ 软件缺页处理 $\to$ 重执指令命中 | $t_{\text{tlb}} + t_{\text{mem}} + t_{\text{fault}} + (t_{\text{tlb}} + t_{\text{cache}}) \approx \mathbf{5,000,054\text{ ns}}$ |

> **注**：在两级页表结构下，若 TLB 缺失且页表命中，硬件需要访问主存 2 次（页目录表 + 二级页表），则查页表耗时由 $t_{\text{mem}}$ 变为 $2 \times t_{\text{mem}} = 100\text{ ns}$。

---

### (3) 有效访存时间（EAT）加权综合公式
综合概率加权，平均有效访存时间公式展开如下：

$$\begin{aligned}
\text{EAT} = &\; h_{\text{tlb}} \left[ h_{\text{cache}} (t_{\text{tlb}} + t_{\text{cache}}) + (1 - h_{\text{cache}})(t_{\text{tlb}} + t_{\text{cache}} + t_{\text{mem}}) \right] \\
&+ (1 - h_{\text{tlb}}) (1 - p_{\text{fault}}) \left[ h_{\text{cache}} (t_{\text{tlb}} + t_{\text{mem}} + t_{\text{cache}}) + (1 - h_{\text{cache}})(t_{\text{tlb}} + 2t_{\text{mem}} + t_{\text{cache}}) \right] \\
&+ (1 - h_{\text{tlb}}) p_{\text{fault}} \left[ t_{\text{tlb}} + t_{\text{mem}} + t_{\text{fault}} + (t_{\text{tlb}} + t_{\text{cache}}) \right]
\end{aligned}$$

代入数值验证：
- TLB 命中子分支均值：$0.95 \times [0.90 \times 3 + 0.10 \times 53] = 0.95 \times [2.7 + 5.3] = 0.95 \times 8 = 7.6\text{ ns}$
- TLB 缺失但无缺页子分支均值：$0.05 \times (1 - 10^{-5}) \times [0.90 \times 53 + 0.10 \times 103] \approx 0.05 \times [47.7 + 10.3] = 0.05 \times 58 = 2.9\text{ ns}$
- 缺页子分支均值：$0.05 \times 10^{-5} \times (5 \times 10^6) = 5 \times 10^{-7} \times 5 \times 10^6 = 2.5\text{ ns}$
- **系统最终总体 EAT**：
  $$\text{EAT} \approx 7.6 + 2.9 + 2.5 = \mathbf{13.0\text{ ns}}$$

> **工程现实扩展说明**：在真实现代 CPU 中，页表项（PTE）本身也是物理主存数据，**页表项同样能够被缓存进 L1/L2/L3 Cache**。因此，当 TLB 缺失时，硬件页表遍历器首先在 Cache 中寻找页表项，若 PTE 命中了 Cache，查页表耗时仅为 $t_{\text{cache}}$（数纳秒），而非主存访问 $t_{\text{mem}}$（数十纳秒）。

## 5. 端到端地址切分与转换手算追踪（Minimal Execution Trace）

### (1) 系统物理参数模型
- **虚拟地址空间**：32 位，按字节编址。
- **页面大小**：$4\text{ KB} = 2^{12}\text{ B}$（页内偏移占用 12 位）。
- **两级分页结构**：
  - 一级页目录（Page Directory）：占用 10 位，共 $2^{10} = 1024$ 个页目录项（PDE）。
  - 二级页表（Page Table）：占用 10 位，共 $2^{10} = 1024$ 个页表项（PTE）。
  - 每个 PDE 和 PTE 均占 4 字节，单个页目录或页表恰好占满一个 4KB 物理页框。
- **物理内存**：容量 1GB（$2^{30}\text{ B}$），物理地址占 30 位，物理页框号 PFN 占 $30 - 12 = 18$ 位。
- **L1 Cache 参数**：
  - 组织方式：直接映射（Direct-Mapped），容量 32KB（$2^{15}\text{ B}$）。
  - Cache 块大小：$64\text{ B} = 2^6\text{ B}$（块内偏移占用 6 位）。
  - Cache 行数：$32\text{ KB} / 64\text{ B} = 512 = 2^9$ 行（Cache 组索引 Index 占用 9 位）。
  - 物理地址 30 位划分：Tag（$30 - 9 - 6 = 15$ 位）、Index（9 位）、Offset（6 位）。

---

### (2) 手算全流程推演

给定 CPU 访问的虚拟地址：
$$\text{VA} = \mathtt{0x00403018}$$

#### 步骤 1：虚拟地址切分二进制解构
将 32 位十六进制写为二进制：
$$\mathtt{0x00403018} = \mathtt{0000\;0000\;0100\;0000\;0011\;0000\;0001\;1000_2}$$

按照 `[页目录索引 10 位 | 页表索引 10 位 | 页内偏移 12 位]` 划界：
- **一级页目录索引 (Directory Index)**：
  高 10 位：$\mathtt{0000\;0000\;01_2} = \mathtt{0x001}$（十进制索引 1）
- **二级页表索引 (Table Index)**：
  中 10 位：$\mathtt{00\;0000\;0011_2} = \mathtt{0x003}$（十进制索引 3）
- **页内偏移 (Offset)**：
  低 12 位：$\mathtt{0000\;0001\;1000_2} = \mathtt{0x018}$（十进制偏移 24）

```
虚拟地址二进制划分:
┌──────────────────────┬──────────────────────┬──────────────────────────────────┐
│  0000 0000 01 (10b)  │  00 0000 0011 (10b)  │       0000 0001 1000 (12b)       │
└──────────────────────┴──────────────────────┴──────────────────────────────────┘
    Directory = 1            Table = 3                    Offset = 0x018
```

#### 步骤 2：硬件页表查表状态模拟
1. **查 TLB**：未命中。
2. **查一级页目录**：
   - CPU 控制寄存器 CR3 保存顶级页目录的物理基地址，假设为 `0x00100000`。
   - MMU 计算 PDE 地址：$\text{Addr}_{\text{PDE}} = \text{CR3} + \text{Directory} \times 4\text{ B} = \mathtt{0x00100000} + 1 \times 4 = \mathtt{0x00100004}$。
   - 读取该 PDE 内容，假设得到二级页表的物理基地址为 `0x00200000`，且存在位有效（`Valid = 1`）。
3. **查二级页表**：
   - MMU 计算 PTE 地址：$\text{Addr}_{\text{PTE}} = \mathtt{0x00200000} + \text{Table} \times 4\text{ B} = \mathtt{0x00200000} + 3 \times 4 = \mathtt{0x0020000C}$。
   - 读取该 PTE 内容，假设读出目标物理页框号为 $\text{PFN} = \mathtt{0x002A5}$（18 位二进制：$\mathtt{00\;0000\;0010\;1010\;0101_2}$），且标志位 `Valid = 1`。
4. **回填 TLB**：硬件将 `VPN(0x00403) → PFN(0x002A5)` 存入 TLB。

#### 步骤 3：拼接物理地址 (PA)
将 18 位 PFN 与 12 位页内偏移直接拼装：
$$\text{PA} = \text{PFN (18 位)} \mathbin{\Vert} \text{Offset (12 位)}$$
$$\text{PA} = \mathtt{00\;0000\;0010\;1010\;0101} \mathbin{\Vert} \mathtt{0000\;0001\;1000_2}$$
$$\text{PA} = \mathtt{00\;0000\;0010\;1010\;0101\;0000\;0001\;1000_2} = \mathtt{0x002A5018}$$

#### 步骤 4：Cache 映射拆解与命中检测
将 30 位物理地址 $\mathtt{0x002A5018}$ 按照直接映射 Cache 的字段规则拆解：
- **Cache 块内偏移 (Offset)**：低 6 位
  $\mathtt{01\;1000_2} = \mathtt{0x18}$（第 24 字节）
- **Cache 组索引 (Index)**：中间 9 位
  $\mathtt{0\;0000\;0001_2} = \mathtt{0x001}$（第 1 行）
- **Cache 标记 (Tag)**：高 15 位
  $\mathtt{00\;0000\;0010\;1010\;0_2} = \mathtt{0x0054}$

```
物理地址二进制划分 (Cache 字段):
┌─────────────────────────────────┬───────────────────────┬──────────────────────┐
│    00 0000 0010 1010 0 (15b)    │    0 0000 0001 (9b)   │      01 1000 (6b)    │
└─────────────────────────────────┴───────────────────────┴──────────────────────┘
          Cache Tag = 0x0054             Index = 1             Offset = 0x18
```

- **Cache 判定逻辑**：
  Cache 控制器寻址到第 1 行（Index = 1）：
  1. 检查第 1 行的有效标志位（Valid Bit）。若为 1 且 Tag 字段与 `0x0054` 严格相等，则 **Cache 命中**，直接从该 Cache 行的第 24 字节偏移处提取数据送入 CPU 寄存器。
  2. 若 Valid 为 0 或 Tag 不匹配，则 **Cache 缺失**，主存控制器向物理地址 `0x002A5000` 发起突发读传输，载入 64 字节数据块更新第 1 行 Cache，并向 CPU 交付所需数据。

## 6. 条件变迁与机制变体

### (1) 大页机制（Huge Pages）
- **机制变迁**：
  - 标准页为 4KB。在 64 位 x86-64 系统中，支持将第二级或第三级页表项直接配置为大页（如 2MB 或 1GB）。
  - 当配置为 2MB 大页时，跳过最底层的 4KB 页表，虚拟地址的低 21 位直接作为大页页内偏移。
- **物理收益**：
  - 单个 TLB 项覆盖的地址范围由 4KB 扩大到 2MB（提升 512 倍），显著提升了大型数据库、虚拟化与高性能计算场景下的 **TLB 覆盖率（TLB Coverage）**，大幅减少 TLB 缺失频率。

### (2) 多核并发下的 ASID 与 TLB 击落（TLB Shootdown）
- **ASID（地址空间标识符）**：
  - 传统设计中，操作系统在进程上下文切换时必须刷新（Flush）全部用户空间 TLB，导致新进程启动时遭遇频繁的“冷启动 TLB 缺失”。
  - 现代架构在每个 TLB 表项中附加进程标识位（如 ARM 的 ASID，x86 的 PCID）。进程切换时仅需切换寄存器中的当前 ASID/PCID，无需刷空 TLB，不同进程的页表项可在 TLB 中安全共存。
- **TLB 击落（TLB Shootdown）**：
  - 在多核对称多处理器（SMP）系统中，若核心 A 的内核线程修改了共享页表（如释放某页内存），核心 A 必须通过核间中断（IPI, Inter-Processor Interrupt）通知所有其他核心将各自片内 TLB 中的陈旧表项失效，此过程称为 TLB 击落。

## 7. 常见认知反例与排错

### 反例 1：误以为“TLB 命中时主存访存次数为 0，因此耗时为 0”
> **反例辨析**：TLB 本身是采用 SRAM/CAM 阵列实现的片内硬件存储器。虽然 TLB 命中避免了访问速度极慢的外部物理 DRAM 主存（主存访存次数为 0），但比对与读取 TLB 表项本身仍需消耗物理时间（通常为 0.5 ~ 1 个时钟周期）。在精确计算有效访存时间（EAT）时，TLB 的查询耗时 $t_{\text{tlb}}$ 绝不可忽略。

### 反例 2：误以为“缺页异常中断返回时，CPU 恢复执行下一条指令”
> **反例辨析**：中断（Interrupt/外中断）通常在指令执行完成后响应，返回时执行下一条指令（$\text{PC} + 4$）；但缺页异常属于 **故障（Fault/内中断）**，它在当前指令的访存执行阶段（MEM）被触发，当前指令尚未执行成功。因此硬件在抛出缺页异常保存断点时，压入堆栈的断点 PC 是 **引发缺页的当前指令本身的物理地址**。当操作系统调页完成通过特权指令（如 x86 的 `iret`）返回后，CPU 重新执行该指令。

### 反例 3：误以为“Cache 命中就说明数据不需要走页表，因而无需 TLB”
> **反例辨析**：在标准的 PIPT（物理索引物理标记）架构中，Cache 的组索引和 Tag 比较完全基于物理地址。程序生成的任何地址都是虚拟地址，CPU 必须首先通过 TLB 或页表将虚拟地址翻译为物理地址，才拥有去 Cache 中索引与比对 Tag 的资格。只有在 VIVT（虚索引虚标记）架构中才可能直接查 Cache，但 VIVT 存在极难克服的重名与同名歧义，现代主流通用 CPU 均不采用纯粹的 VIVT 数据缓存。

## 8. 本学科内与跨学科系统性关联

### 1. 本学科内跨章节关联
- [存储芯片与存储扩展](01-memory-types.md)：
  - **共同机制**：多级存储体系的时延隐藏与层次化缓存。
  - **关键差异**：存储芯片章节关注外部总线上的 DRAM 行激活（Row Active）、预充电（Precharge）与突发读取时延；虚拟存储章节关注内部 MMU 对 DRAM 物理页框的抽象与映射。
  - **不可直接迁移的判据**：低位交叉存储器的流水线重叠计算不可直接套用于页表遍历；硬件页表遍历本质是串行依赖的树状访存（必须根据上一级 PDE 的输出作为下一级 PTE 的物理基址）。
- [Cache映射与替换策略](02-cache-mapping.md)：
  - **共同机制**：利用程序访问的时间局部性与空间局部性，缓存高频访问条目。
  - **关键差异**：TLB 缓存的是**地址翻译映射元数据（VPN $\to$ PFN）**，Cache 缓存的是**实际指令与数据内容**。
  - **不可直接迁移的判据**：Cache 缺失只会带来流水线停顿并从主存读数据；TLB 缺失可能触发两级甚至四级主存页表查询，或进一步引发缺页异常陷入操作系统内核调度。
- [CPU 数据通路与控制信号](../05-cpu/01-cpu-datapath.md)：
  - **共同机制**：异常事件在流水线特定阶段的捕获与硬件响应。
  - **关键差异**：数据通路负责在执行访存阶段（MEM）采样 MMU 抛出的缺页异常引脚电平；虚拟存储硬件负责具体的地址翻译与异常信号生成。
  - **不可直接迁移的判据**：缺页异常产生后，指令流水线必须被清空（Flush），未完成的写回（WB）操作必须全部撤销，这与正常中断执行完毕当前指令的处理完全不同。

### 2. 跨学科协同关联
- [操作系统：虚拟存储器与请求分页](../../03-os/03-memory/03-virtual-memory-basics.md)：
  - **共同机制**：软硬件协同支撑的按需调页（Demand Paging）与写时复制（COW）。
  - **关键差异**：
    - **计组侧（硬件边界）**：关注纳秒级硬件电路并发（CAM 并行比对、MMU 有限状态机遍历、PIPT/VIPT 延迟比拼、异常引脚触发）；
    - **操作系统侧（软件边界）**：关注毫秒级磁盘外存 I/O 调度、内核空闲页框链表分配、Clock / LRU 页面置换算法决策与进程页表结构维护。
  - **不可直接迁移的判据**：计组中的硬件页表遍历器绝对无法自行到磁盘外存调页或分配新的空闲物理页框，硬件一旦遇到 `Valid = 0` 只能产生中断将 CPU 控制权交由操作系统处理。
