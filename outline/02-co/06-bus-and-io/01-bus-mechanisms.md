## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须引入总线？（从全互连网状走向分时共享）
- **物理困境**：
  - 早期计算机各部件之间采用“专用点对点连接（Dedicated Point-to-Point）”。若系统中有 $N$ 个功能模块，需要 $\frac{N(N-1)}{2}$ 组连线。
  - 随着外设与存储设备暴增，芯片管脚引线密集交织，硬件布线复杂度呈爆炸式坍塌，系统根本无法扩展。
- **总线架构哲学**：
  - **分时共享（Time-sharing & Shared）**：将一组公用的物理导线作为公共通道。
  - **物理制约铁律**：
    1. **分时**：在同一瞬间，**只允许一个主设备（Master）占用总线向外发送信息**；若多个设备同时发射，电平信号叠加将造成总线争用（Bus Contention）破坏数据；
    2. **共享**：发送出的数据可以被挂在总线上的多个从设备（Slave）同时接收。

---

### (2) 集中式总线仲裁三大机制深度对比
当多个主控设备（CPU、DMA 控制器等）同时申请使用总线时，必须由中央仲裁器进行仲裁。

```
1. 链式查询 (Daisy Chain)
   控制线: 总线请求 BR (1根), 总线授权 BG (1根菊花链串联), 总线忙 BS (1根)
   机理: 仲裁器发出 BG 信号，沿物理导线由近及远逐个设备串行传递。
   特征: 离仲裁器最近的设备优先级最高；若某个设备故障，链条彻底断开；硬件线数极少 (仅 3 根)。

2. 计数器定时查询 (Polling)
   控制线: 总线请求 BR (1根), 总线忙 BS (1根), 设备地址线 log2(n) 根
   机理: 仲裁器内部计数器按地址轮询。
   特征: 灵活性极高。若每次从 0 开始计数，则近端优先；若从上一次中止处继续计数，则实现循环公平轮转。

3. 独立请求方式 (Independent Request)
   控制线: 每个设备各配对 1 对独立的 BR_i 和 BG_i，共 2n 根，加 1 根 BS
   机理: 所有设备直接向中央仲裁器并发提申请，内部排队逻辑裁决。
   特征: 响应速度最快，优先级可通过软件编程动态重设；但控制线数量随设备数线性膨胀。
```

#### 控制线开销速查矩阵

| 仲裁方式 | 仲裁控制线总根数 | 优先级判定方式 | 故障敏感度与可靠性 |
| :--- | :---: | :--- | :--- |
| **链式查询** | **固定 3 根**（与设备数无关） | **绝对固定**（由物理连接先后顺序决定） | **极高**（菊花链中单个元件受损导致全线瘫痪） |
| **计数器定时查询** | **$2 + \lceil \log_2 n \rceil$ 根** | 依据计数器起始初始值可灵活配置 | 中等 |
| **独立请求方式** | **$2n + 1$ 根** | 极度灵活，可编程自适应排队 | **最低**（各设备独立，单点故障不扩散） |

### (3) 总线通信定时方式：同步 vs 异步握手

#### ① 同步定时方式（Synchronous）
- **机理**：系统内所有部件共享同一个全局公共时钟信号。读写操作严格在固定的时钟周期节拍内按序完成。
- **物理权衡**：
  - 优点：控制逻辑极简，总线传输速率极高；
  - 缺点：**强制向慢速设备看齐**。时钟周期的长度必须按照总线上最慢的设备以及最长的物理连线时延来标定，导致快速设备被迫降速等待。

#### ② 异步定时方式（Asynchronous / 握手握紧协议）
- **机理**：没有统一的全局时钟，完全依靠发送方发出的“请求（Request）”信号与接收方返回的“回答（Acknowledge）”信号之间的状态联动（握手 Handshake）。
- **三种互锁状态机深度辨析（考场常考细节）**：

```
1. 不互锁 (Non-interlocked)
   - 主设备发出请求后，不等待回答，延时固定时间后自动撤销请求；
   - 从设备收到请求发出回答后，延时固定时间自动撤销回答。
   - 特征: 速度最快，但可靠性最差（若从设备未收到，主设备已将请求撤销）。

2. 半互锁 (Semi-interlocked)
   - 主设备发出请求后，【必须等待收到从设备的回答】才允许撤销请求；
   - 从设备发出回答后，延时固定时间自动撤销回答（不确认主设备是否已撤销请求）。
   - 特征: 解决了一半的问题，若从设备回答过早撤销，可能引起时序混乱。

3. 全互锁 (Fully-interlocked)
   - 主设备发出请求，【必须等从设备回答】才撤销请求；
   - 从设备发出回答，【必须等主设备撤销请求】才允许撤销回答！
   - 特征: 双向因果闭环，时序极其稳健可靠，但握手开销最大，速度相对最慢。
```

### (4) 突发传输（Burst Transmission）与 Cache 块填充
- **传统单字读写的总线浪费**：
  若要读取 4 个连续字的数据，传统方式必须重复 4 次完整的“发送地址 $\to$ 内存寻址 $\to$ 回传数据”周期。地址总线被频繁冗余占用。
- **突发传输机理**：
  - 主设备在第一个时钟周期向总线**仅发送一次首地址**；
  - 随后的连续时钟周期内，主存储器内部地址计数器自动加 1，**连续并发地将紧随其后的若干个连续数据字高速吐出到数据总线上**。
  - **核心应用**：CPU 从主存将一个 64 字节的 Cache 行调入 Cache 时，全面采用突发传输模式，极大释放了系统总线带宽。

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 计组: 总线仲裁与突发传输       │
                     └──────────────┬───────────────┘
                                    │ 块传输与主存交互
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 计组: Cache 缺失与行填充      │         │ 计组: DMA 高速外设数据传输    │
│  - 突发传输完成 Cache 块替换  │ ◄────── │  - DMA 控制器作为总线主设备   │
│  - 减少总线寻址握手时延      │         │  - 周期挪用 / 周期窃取仲裁   │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与 DMA 接口的“总线主控权”争夺联动**：
   - 在计算机中，CPU 并不是总线的唯一主控者。
   - 当 DMA 控制器需要向主存批量吐出磁盘数据时，DMA 控制器作为总线主设备向仲裁器发出总线请求，通过“周期挪用（Cycle Stealing）”暂时剥夺 CPU 的总线控制权，直接与主存完成高速数据突发对拷。

## 4. 闭环决策模型与核心认知结论

### (1) 总线带宽严密算力模型（考场不可动摇的公式）
$$\text{总线带宽 } B = \text{总线工作频率 } f \times \frac{\text{总线位宽 } W \text{ (bits)}}{8} \quad (\text{单位: Byte/s})$$
- 若题目给出总线时钟周期 $\tau$：
  $$B = \frac{\text{每次传输的数据量 (Bytes)}}{\text{传输所耗费的总时钟周期数} \times \tau}$$

### (2) 考场定性闭环判据
1. **只要题目提到“电路发生单点故障可能导致整个总线系统无法工作”** $\to$ 必定是集中式仲裁中的**链式查询方式**。
2. **总线中各部件的地位是否平等？**
   - 不平等！只有**主设备（Master）**有权发起总线请求并控制总线传输；从设备（Slave）只能被动响应主设备的命令。
3. **数据总线、地址总线和控制总线的传输方向**：
   - **数据总线**：必定是**双向的**（CPU 既可读内存也可写内存）；
   - **地址总线**：在单主控系统中是**单向的**（由 CPU/主控设备指向内存和外设从设备）；
   - **控制总线**：对于总线整体而言是**双向并存的**（有的控制线由 CPU 发出如读写命令，有的控制线由从设备输入给 CPU 如中断请求、总线忙信号）。
