## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 从“程序轮询”到“中断驱动”再到“DMA”的演进必然性
- **程序查询（轮询）的低效物理本质**：
  CPU 主动不断读状态寄存器“忙等”。外设耗时毫秒级，CPU 数百万个有效计算周期被白白烧死在死循环空转中。
- **中断驱动方式的突破**：
  外设准备数据期间，CPU 照常执行其他程序；数据准备就绪后，外设向 CPU 发出中断请求（INTR），CPU 暂停当前程序转去读取数据。
  - **瓶颈残留**：每个字节/字的传输，都必须经过 **外设 $\to$ I/O端口 $\to$ CPU内部寄存器 $\to$ 主存** 的链路。CPU 仍然是数据的搬运工，面对磁盘、网卡等 MB/s 级的高速流，CPU 将被密集的中断处理彻底淹没。
- **DMA（直接内存访问）的终极解耦**：
  在高速外设与主内存之间建立一条**绕过 CPU 数据通路的高速直达专用总线**。数据成块（Block）在内存与外设间直接对拷，CPU 仅在整批数据传输开始前做参数配置，在整批数据传输完成后收一次完成通知。

### (2) 硬件中断系统的严密执行全景

#### ① 硬件隐指令（Hardware Implicit Instruction）
- **核心定义**：它**不是指令系统（ISA）中的任何一条可见机器指令**，而是 CPU 内部硬件电路在指令执行周期的末尾（中断周期）自动触发的一连串微操作。
- **不可分割的三大硬件动作**：
  1. **关中断（Disable Interrupt）**：将中断允许标志位 `IF` 置 0，屏蔽新的中断，保护断点现场不被扰乱；
  2. **保存断点（Save PC & PSW）**：将当前的断点 PC 和程序状态字寄存器（PSW）压入**内核系统栈**（或暂存专用寄存器）；
  3. **引出中断服务程序（Vector Jump）**：硬件根据中断源发出的中断类型号查**中断向量表**，将中断服务程序（ISR）的首地址强行装入 PC，实现无缝跳转。

#### ② 中断服务程序（ISR）与多重中断屏蔽字（Mask Word）
若允许中断嵌套（高优先级中断打断低优先级中断），软件必须精巧编排开中断与屏蔽字时序：

```
[硬件隐指令] 关中断 -> 压栈断点 PC/PSW -> 跳转 ISR 入口
     │
     ▼
[软件执行 ISR]
  1. 保护通用寄存器现场 (Push 寄存器)
  2. 设置新屏蔽字 (屏蔽同级及低优先级中断) ──┐
  3. 【开中断】(允许更高优先级抢占) ◄────────┘ (从此进入可嵌套临界区)
  4. 执行实际设备服务 (数据读取/写入)
  5. 【关中断】(保护现场恢复过程不被打断)
  6. 恢复旧屏蔽字
  7. 恢复通用寄存器现场 (Pop 寄存器)
  8. 【开中断】并在原子操作中执行 IRET 指令 (恢复断点 PC 和 PSW，重返原程序)
```

#### ③ 响应优先级 vs 处理优先级（屏蔽字核心模型）
- **响应优先级（硬件决定，不可更改）**：
  多个中断源**同时向 CPU 发出请求时**，硬件排队器（菊花链或编码器）优先响应谁。这个优先级由硬件线路焊死，软件无法改动。
- **处理优先级（软件屏蔽字决定，可动态重塑）**：
  CPU **正在执行某个中断服务程序时，能够被谁打断**。
  - **屏蔽字规则**：屏蔽字中的某位为 `1` 表示屏蔽该中断（不允许其打断），为 `0` 表示开放（允许打断）。
  - **黄金铁律**：**任何设备必须将自身对应的屏蔽位置 1（杜绝自己打断自己）；一个设备的屏蔽字中包含的 1 越多，其处理优先级越高**！

### (3) DMA 机制与“周期挪用（Cycle Stealing）”
DMA 控制器（DMAC）内部包含四大核心寄存器：
- **MAR（内存地址寄存器）**：存放主存中缓冲区的物理起始地址；
- **WC（计数器，Word Counter）**：存放待传输的总字数（通常为负补码递增到 0，或正数递减到 0）；
- **CR（控制/状态寄存器）**：存放传输方向（读/写）和中断使能；
- **BR（数据缓冲寄存器）**：在总线与外设间暂存 1 个数据字。

#### 周期挪用的物理机制（考场计算焦点）
- **现象**：当 DMA 控制器准备好 1 个字的数据需要刷入内存时，向 CPU 发出总线占用请求。
- **总线争用裁决**：
  - 若此时 CPU 正在执行**片内 ALU 运算**，并未访问外部总线，CPU 与 DMA 各自全速并行，互不干扰；
  - 若此时 CPU 恰好也需要**访存**，总线仲裁器优先将总线使用权让给 DMA，**DMA 挪用/借用 1 个主存存取周期（约数十纳秒）**将该字打入内存，随后立即交还总线。CPU 流水线仅被动停滞 1 个时钟周期。

### (4) 中断 vs DMA 核心维度终极对决表

| 对比维度 | 中断驱动方式 (Interrupt) | 直接内存访问 (DMA) |
| :--- | :--- | :--- |
| **数据通路** | **必须途经 CPU 内部寄存器**（外设 $\to$ CPU $\to$ 内存） | **绕过 CPU**，外设通过 DMAC 直接与主存对拷 |
| **硬件开销** | 极小，完全依托现有 CPU 寄存器和 ALU | 较大，需额外配备专用的 DMA 控制器硬件芯片 |
| **CPU 介入时机** | **每个字节 / 每个字传输一次**，CPU 都要被中断一次 | **整批数据块（Block）传输完毕**，才向 CPU 发一次中断 |
| **中断响应时机** | 必须等待当前**一条机器指令执行周期结束**时响应 | 可在**任何一个总线机器周期结束**时响应（周期挪用） |
| **优先级** | 优先级相对低于 DMA 请求 | **总线请求优先级严格高于普通中断请求**（防止外设溢出） |
| **适用外设** | 慢速、中速、突发性交互外设（键盘、鼠标、串口） | **高速、大批量块设备**（机械硬盘、SSD、千兆/万兆网卡） |

```
│  - DMA 缓冲区分配与零拷贝    │         │  - 硬件隐指令直接操纵 PC/PSW  │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与操作系统“零拷贝（Zero-Copy）”技术的底层贯通**：
   - 现代 Linux 高性能网络编程中的 `sendfile()` 零拷贝机制，其物理底层正是通过操作系统直接将磁盘文件的物理页框地址赋给网卡的 DMA 控制器，网卡通过 DMA 直接从内存读取数据发送出去，全程彻底消除了 CPU 介入数据搬运的巨额开销。
2. **与指令周期的时序锚定**：
   - CPU 在取指、间址、执行阶段均处于指令处理的封闭状态，**只有在执行阶段完全结束的末尾，硬件才统一检测 INTR 引脚**。若有有效中断信号，CPU 强行插入一个“中断周期（硬件隐指令）”，绝不会在单条指令执行中途劈开插入中断（微指令异常除外）。

## 4. 闭环决策模型与核心认知结论

### (1) 屏蔽字求解与优先级判定闭环法则
1. **看对角线**：每个设备在自身所对应的位上，**必须填 1**。
2. **看处理优先级顺序**：
   - 若题目给定处理优先级由高到低为：$A > B > C > D$。
   - $A$ 的优先级最高，能打断所有人，任何人不能打断 $A$，因此 $A$ 的屏蔽字中 **$A, B, C, D$ 位全为 1**。
   - $B$ 的屏蔽字中，$A$ 位为 0（允许 $A$ 打断），$B, C, D$ 位为 1。
   - $D$ 的处理优先级最低，谁都能打断它，因此其屏蔽字中除自身 $D$ 位为 1 外，其余全为 0。

### (2) 考场定性闭环判据
1. **CPU 在何时响应外部中断请求？** $\to$ **当前指令执行周期结束时**。
2. **CPU 在何时响应 DMA 请求？** $\to$ **当前总线机器存取周期结束时**（远比指令周期更短、更频繁）。
3. **硬件隐指令由什么产生？存放在哪里？** $\to$ 由 **CPU 内部微操作硬件电路直接发射**，**不存在于内存任何指令序列中**！
4. **关中断的目的是什么？** $\to$ 确保断点 PC 和程序状态字 PSW 的压栈保存操作具备**严格原子性**，绝对不被新的嵌套中断破坏。
