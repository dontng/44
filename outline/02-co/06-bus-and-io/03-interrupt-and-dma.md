## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - 中断系统三阶响应流：中断判优（硬件响应优先级）、硬件隐指令三大动作、中断服务程序（ISR）。
  - 单重中断 vs 多重中断（中断嵌套）的执行时序、开/关中断临界区与屏蔽字（Mask Word）设计。
  - DMA（直接内存访问）控制器物理硬件结构：主存地址寄存器（MAR）、计数器（WC）、控制/状态寄存器（CR）、数据缓冲寄存器（BR）。
  - DMA 传输三阶段（预处理、数据传送、后处理）与总线使用方式（停止 CPU 访存、周期挪用、交替访存）。
  - 中断驱动方式与 DMA 方式在响应时机、数据通路、传输粒度与 CPU 算力开销上的本质区别与严谨定量计算。
- **思维摩擦点（为什么容易错）**：
  - **混淆“响应优先级”与“处理优先级”**：响应优先级由硬件排队器物理接线决定，裁决“多个中断同时到达时 CPU 先响应谁”；处理优先级由软件设置的屏蔽字动态决定，裁决“CPU 正在服务当前中断时能被谁抢占打断”。
  - **机械理解“DMA 周期挪用导致 CPU 停顿”**：DMA 周期挪用抢占的是**主存总线存取周期**，而非 CPU 主频时钟周期。若 CPU 此时执行寄存器运算或命中片内 L1/L2 Cache，CPU 与 DMA 完全并行运行，CPU 实际停顿周期为 0。
  - **多重中断返回中的竞态漏洞**：若在 ISR 结尾先通过软件指令显式开中断（`STI`），再执行中断返回（`IRET`），在两条指令的微小缝隙间若有新中断到来，会导致堆栈无序膨胀甚至溢出。现代体系结构通过 `IRET` 指令从栈中原子恢复 `PSW`（包含 `IF` 位）来安全关闭这一缝隙。
  - **片面宣称“sendfile 零拷贝完全消除了 CPU 开销”**：在硬件网卡不支持分散-聚集 DMA（Scatter-Gather DMA）的早期系统中，CPU 仍需将页缓存数据拷贝到套接字缓冲区。真正的完全零 CPU 搬运要求硬件 SG-DMA 支持。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 从“程序轮询”到“中断驱动”再到“DMA”的演进必然性
- **程序查询（轮询，Polling）的物理低效**：
  CPU 主动不断读状态寄存器“忙等”。外设机械动作耗时毫秒级，CPU 数百万个有效计算时钟周期被白白烧死在死循环空转中。
- **中断驱动方式（Interrupt-Driven）的解耦**：
  外设准备数据期间，CPU 照常执行其他程序；数据准备就绪后，外设向 CPU 发出中断请求（INTR），CPU 暂停当前程序转去读取数据。
  - **性能瓶颈**：每个字节/字的传输，都必须经过 **外设 $\to$ I/O 端口 $\to$ CPU 内部寄存器 $\to$ 主存** 的链路。CPU 仍然是数据的搬运工；面对数十 MB/s 的高速外设，CPU 将被密集的中断彻底淹没。
- **DMA（直接内存访问）的终极解耦**：
  在高速外设与主内存之间建立一条**绕过 CPU 寄存器的数据通路**。数据成块（Block）在内存与外设间直接对拷，CPU 仅在整批数据传输开始前做参数初始化，并在整批数据传输完成后接收一次“完成通知”中断。

<a id="interrupt-mechanism"></a>
### (2) 硬件中断系统的严密执行全景

#### ① 硬件隐指令（Hardware Implicit Instruction）
- **核心定义**：它**不是指令系统（ISA）中的任何一条可见机器指令**，而是 CPU 内部硬件电路在指令执行周期的末尾（中断周期）自动触发的一组微操作节拍。
- **不可分割的三大硬件动作**：
  1. **关中断（Disable Interrupt）**：硬件自动将中断允许标志位 `IF` 置 0，屏蔽新的可屏蔽中断，确保断点现场压栈过程不被打断；
  2. **保存断点（Save PC & PSW）**：硬件将当前的断点 PC 和程序状态字寄存器（PSW/EFLAGS）压入**内核系统栈**；
  3. **引出中断服务程序（Vector Jump）**：硬件根据中断源发出的中断类型号或中断向量，从主存中的**中断向量表（IVT）**或中断描述符表（IDT）中取出中断服务程序（ISR）的入口地址，强行装入 PC，实现无缝跳转。

---

#### ② 中断服务程序（ISR）原子安全返回与多重中断时序

在支持中断嵌套（多重中断）的高级系统中，软件必须精细编排开中断与屏蔽字时序：

```
[硬件隐指令阶段 (关中断保护)]
  1. 关中断 (IF = 0)
  2. 压栈保存断点 PC 与 PSW
  3. 硬件引出中断向量，PC <- ISR 入口地址
       │
       ▼
[软件执行 ISR 阶段]
  4. 保护通用寄存器现场 (Push 通用寄存器到系统栈)
  5. 设置当前中断源对应的【新屏蔽字】(屏蔽同级及低优先级中断) ──┐
  6. 【开中断】(IF = 1，从此开放更高优先级中断抢占) ◄──────────┘
  7. 执行实际设备服务例程 (从 I/O 端口读写数据、处理事务)
  8. 【关中断】(IF = 0，关闭嵌套抢占，保护恢复现场阶段的原子性)
  9. 恢复先前的【旧屏蔽字】
 10. 恢复通用寄存器现场 (Pop 通用寄存器)
 11. 【原子返回与恢复状态】
     执行 IRET 指令：硬件从栈中同时弹出 PC 和原程序的 PSW (原子恢复原程序的 IF 标志位)！
```

> [!IMPORTANT]
> **多重中断返回竞态漏洞与原子保障**：
> 绝不能在第 10 步与第 11 步之间通过显式软件指令 `STI` 开中断！若在 `STI` 之后、`IRET` 之前发生高优先级中断，CPU 会在半恢复的栈指针状态下再次被抢占，导致系统栈结构混乱崩溃。
> 正确机制是由硬件执行 `IRET` 指令时，**伴随栈顶 PSW 的弹出原子恢复原程序的 `IF` 位**；或者依据处理器特性（如 x86 的 `STI` 具有一指令延迟阴影特性，延迟到紧随其后的 `IRET` 执行完才使能中断）。

---

#### ③ 响应优先级 vs 处理优先级（屏蔽字核心模型）
- **响应优先级（硬件决定）**：
  多个中断源**同时向 CPU 发出请求时**，硬件排队器（菊花链或硬件优先编码器）优先响应谁。这个优先级由硬件电路物理连线焊死，通常反映了外设对数据丢失的紧急程度。
- **处理优先级（软件屏蔽字决定）**：
  CPU **正在执行某个中断服务程序时，能够被谁打断**。
- **屏蔽字设计闭环准则**：
  1. **对角线置 1 铁律**：任何中断源的屏蔽字中，**自身对应位必须置 1**（杜绝自身打断自身，防止 ISR 重入死循环）；
  2. **高优压制低优准则**：设备 $X$ 的屏蔽字中，所有**处理优先级低于或等于 $X$ 的设备位全部置 1（屏蔽）**，所有**处理优先级高于 $X$ 的设备位必须置 0（允许抢占）**；
  3. **1 的总数决定优先级**：在屏蔽字矩阵中，某中断源对应的屏蔽字中 **`1` 的个数越多，其处理优先级越高**。

### (3) DMA 机制与“周期挪用”的物理微架构

DMA 控制器（DMAC）内部包含四大核心寄存器：
- **MAR（主存地址寄存器）**：存放主存中数据缓冲区的当前物理地址（每传送一个字自动递增或递减）；
- **WC（计数器，Word Counter）**：存放待传输的总字数（通常存负补码递增到 0，或存正数递减到 0 触发溢出信号）；
- **CR（控制/状态寄存器）**：存放传输方向（外设到内存 / 内存到外设）、工作模式与中断使能位；
- **BR（数据缓冲寄存器）**：暂存 1 个由外设送来、即将打入主存的数据字。

```
                    ┌────────────────────────────────────────────────────────┐
                    │                      主存储器 (DRAM)                    │
                    └──────────────────────────┬─────────────────────────────┘
                                               │ 系统总线 (共享)
                   ┌───────────────────────────┴─────────────────────────────┐
                   │                                                         │
                   ▼                                                         ▼
    ┌──────────────────────────────┐                         ┌──────────────────────────────┐
    │          CPU 核心            │                         │      DMA 控制器 (DMAC)       │
    │  - 寄存器组 / ALU            │                         │  - MAR (内存地址计数器)       │
    │  - L1 / L2 高速缓存 (Cache)  │                         │  - WC  (传输字计数器)         │
    │  - 发起控制 / 最终响应中断   │                         │  - CR  (控制与状态寄存器)     │
    └──────────────┬───────────────┘                         │  - BR  (数据缓冲寄存器)       │
                   │ 总线请求/授权                                   └──────────────┬───────────────┘
                   │ (HRQ / HLDA)                                                   │ 专用外设总线
                   └────────────────────────────────────────────────────────────────┘
                                                                                    │
                                                                                    ▼
                                                                     ┌──────────────────────────────┐
                                                                     │   高速外设 (磁盘/网卡/SSD)   │
                                                                     └──────────────────────────────┘
```

#### 周期挪用（Cycle Stealing）的严谨物理时序
- **核心判定**：DMA 控制器挪用的是 **1 个主存总线存取周期（Memory Bus Cycle）**，绝对不是 CPU 时钟周期。
- **CPU 停顿条件细分**：
  1. **CPU 正在执行片内寄存器运算**（如 `ADD R1, R2`）：CPU 完全不访问外部总线，DMA 全速占用总线存取主存，**CPU 停顿周期 = 0**；
  2. **CPU 执行访存指令且命中 L1/L2 Cache**：在哈佛架构分离 Cache 体系下，CPU 直接访问 Cache，DMA 占用主存总线，**CPU 停顿周期 = 0**；
  3. **CPU 发生 Cache 缺失或需要访问系统总线**：总线仲裁器优先将总线判给 DMA（DMA 优先级高于 CPU 访存，防止外设 FIFO 溢出），此时 **CPU 被迫插入总线等待周期（Stall）**，直到 DMA 释放总线。

### (4) 中断驱动方式 vs DMA 方式终极决策对比表

| 对比维度 | 中断驱动方式 (Interrupt) | 直接内存访问 (DMA) | 机制分水岭 |
| :--- | :--- | :--- | :--- |
| **数据传输通路** | **必须途经 CPU 内部通用寄存器**<br>（外设 $\to$ I/O 端口 $\to$ CPU 寄存器 $\to$ 主存） | **彻底绕过 CPU 寄存器**<br>（外设 $\to$ DMAC 内部 BR $\to$ 主存） | 数据流是否占用 CPU 算力核心与寄存器组 |
| **传输基本粒度** | **单字或单字节**（Byte / Word） | **连续数据块**（Block / Page，如 4 KB） | 数据传输的汇聚与调度单位 |
| **CPU 介入时机** | **每传输一个字节/字**，CPU 就要被中断打断一次并执行 ISR | **整批数据块全部传输完毕后**，DMAC 仅向 CPU 发送一次中断 | CPU 介入频率从每个数据字降至每个数据块 |
| **总线申请时机** | 在当前一条**机器指令执行周期结束**（中断周期）响应 | 可在**任何一个总线机器存取周期结束**响应（周期挪用） | 响应时间颗粒度：指令边界 vs 机器存取周期边界 |
| **硬件仲裁优先级** | 中断请求优先级**低于** DMA 请求 | DMA 总线请求优先级**严格高于**普通中断请求 | 硬件防丢包约束：慢速外设数据可重试，高速外设溢出即丢失 |
| **硬件开销** | 极小，完全复用现有 CPU 寄存器与内核栈 | 较大，需单独设计配置专用的 DMAC 控制芯片 | 纯软件协议栈 vs 专用硬件控制器 |
| **适用外设场景** | 慢速、非连续突发外设（键盘、鼠标、控制台串口） | 高速、连续块存储/网络外设（SSD、SATA 硬盘、千兆网卡） | 吞吐率匹配原则 |

## 3. 手算推演与执行轨迹跟踪

### (1) 手算追踪 1：多重中断屏蔽字矩阵与嵌套抢占时序

#### 场景设定
- 系统配置 4 个中断源：$A, B, C, D$。
- **硬件排队器响应优先级**：$A > B > C > D$（硬件固定）。
- **期望的软件处理优先级**：$D > A > C > B$（软件动态重塑）。
- 屏蔽字格式：4 位二进制数，按位对应 $[A, B, C, D]$（`1` 表示屏蔽，`0` 表示开放允许打断）。

#### 屏蔽字矩阵推导表

| 中断源 | 处理优先级顺位 | 允许抢占的中断源 (填 0) | 禁止打断的中断源（含自身，填 1） | 4 位屏蔽字 $[A, B, C, D]$ | `1` 的计数 |
| :---: | :---: | :--- | :--- | :---: | :---: |
| **$D$** | 第 1 名 (最高) | 无 | $D, A, C, B$ (全屏蔽) | `1 1 1 1` | 4 个 |
| **$A$** | 第 2 名 | 仅 $D$ | $A, C, B$ | `1 1 1 0` | 3 个 |
| **$C$** | 第 3 名 | $D, A$ | $C, B$ | `0 1 1 0` | 2 个 |
| **$B$** | 第 4 名 (最低) | $D, A, C$ | 仅 $B$ 自身 | `0 1 0 0` | 1 个 |

---

#### 抢占执行轨迹（Preemption Timeline Trace）
- **事件输入时序**：
  - $t = 0\text{ }\mu\text{s}$：主程序正常运行；
  - $t = 5\text{ }\mu\text{s}$：$B$ 发出中断请求，CPU 响应进入 $B$ 的 ISR；
  - $t = 10\text{ }\mu\text{s}$：$A$ 发出中断请求；
  - $t = 15\text{ }\mu\text{s}$：$C$ 发出中断请求；
  - $t = 18\text{ }\mu\text{s}$：$D$ 发出中断请求；
  - 设各中断源的纯服务执行时长均为 $10\text{ }\mu\text{s}$。

#### 嵌套执行与栈状态跟踪表

| 时间区间 | 活跃执行实体 | 屏蔽字状态 $[A,B,C,D]$ | 内核系统栈断点深度 | 发生的关键硬件/软件事件 |
| :---: | :---: | :---: | :---: | :--- |
| **0 ~ 5 μs** | **主程序** | `0 0 0 0` | 0 (空) | 主程序执行 |
| **5 ~ 10 μs** | **ISR $B$** | `0 1 0 0` | 1 (保存主程序断点) | $B$ 响应，$B$ 屏蔽自身，开中断，已执行 $5\mu\text{s}$（剩余 $5\mu\text{s}$） |
| **10 μs** | 抢占触发 | 切换至 $A$ 屏蔽字 | 2 (压入 $B$ 断点) | $A$ 请求到达；检查 $B$ 屏蔽字中 $A$ 位为 `0` $\to$ **$A$ 成功抢占 $B$** |
| **10 ~ 15 μs** | **ISR $A$** | `1 1 1 0` | 2 | $A$ 执行 $5\mu\text{s}$，屏蔽 $A, C, B$，仅开放 $D$ |
| **15 μs** | 挂起等待 | 维持 $A$ 屏蔽字 | 2 | $C$ 请求到达；检查 $A$ 屏蔽字中 $C$ 位为 `1` $\to$ **$C$ 被屏蔽，挂起等待** |
| **15 ~ 18 μs** | **ISR $A$** | `1 1 1 0` | 2 | **ISR $A$ 继续执行 $3\mu\text{s}$（累计已执行 $8\mu\text{s}$，仅剩 $2\mu\text{s}$）** |
| **18 μs** | 抢占触发 | 切换至 $D$ 屏蔽字 | 3 (压入 $A$ 断点) | $D$ 请求到达；检查 $A$ 屏蔽字中 $D$ 位为 `0` $\to$ **$D$ 成功抢占 $A$** |
| **18 ~ 28 μs** | **ISR $D$** | `1 1 1 1` | 3 | $D$ 连续执行完整 $10\mu\text{s}$，屏蔽所有中断，任何请求不可打断，在 $t=28\mu\text{s}$ 结束 |
| **28 μs** | $D$ 完成返回 | 恢复至 $A$ 屏蔽字 | 2 (弹出 $A$ 断点) | $D$ 执行完毕，原子返回 $A$ 的被中断点继续执行 |
| **28 ~ 30 μs** | **ISR $A$** | `1 1 1 0` | 2 | **ISR $A$ 恢复执行剩余的 $2\mu\text{s}$，在 $t=30\mu\text{s}$ 结束** |
| **30 μs** | $A$ 完成返回 | 恢复至 $B$ 屏蔽字 | 1 (弹出 $B$ 断点) | $A$ 执行完毕返回；此时挂起等待的 $C$ 请求被检测到！由于 $B$ 屏蔽字中 $C$ 位为 `0` $\to$ **$C$ 立即抢占 $B$** |
| **30 ~ 40 μs** | **ISR $C$** | `0 1 1 0` | 2 (再次压入 $B$ 断点) | $C$ 执行完整 $10\mu\text{s}$ 服务，在 $t=40\mu\text{s}$ 结束 |
| **40 μs** | $C$ 完成返回 | 恢复至 $B$ 屏蔽字 | 1 (弹出 $B$ 断点) | $C$ 执行完毕返回，恢复被中断的 $B$ 继续执行 |
| **40 ~ 45 μs** | **ISR $B$** | `0 1 0 0` | 1 | **ISR $B$ 补齐剩余的 $5\mu\text{s}$ 服务，在 $t=45\mu\text{s}$ 结束** |
| **45 μs** | $B$ 完成返回 | `0 0 0 0` | 0 | $B$ 执行完毕，执行 `IRET` 彻底返回主程序继续运行（全过程严密无缝，总耗时 $5 + 4 \times 10 = 45\mu\text{s}$） |

### (2) 手算追踪 2：中断方式 vs DMA 方式 CPU 负荷严谨定量核算

**题目模型**：
- 某高性能磁盘接口数据传输速率为 $40\text{ MB/s}$（按 $40 \times 10^6\text{ Bytes/s}$ 计算）；
- CPU 主频为 $500\text{ MHz}$，即每秒拥有时钟周期数为 $5 \times 10^8\text{ cycles/s}$；
- 数据总线位宽为 32 位（每次传输 1 个数据字 = 4 字节）。

---

#### 方案 1：采用程序中断传输方式
- 机制：磁盘接口内部每积攒满 1 个数据字（4 字节），就向 CPU 发起一次中断请求。
- **中断请求频率**：
  $$f_{\text{intr}} = \frac{40 \times 10^6\text{ B/s}}{4\text{ B}} = 10^7\text{ 次/s} \quad (10\text{ MHz})$$
- 设每次中断服务程序（硬件隐指令 + 保护寄存器 + 读端口传送字 + 恢复现场 + 中断返回）共耗费 **500 个 CPU 时钟周期**。
- **CPU 每秒用于中断服务的时钟周期开销**：
  $$T_{\text{intr\_cycles}} = 10^7\text{ 次/s} \times 500\text{ cycles/次} = 5 \times 10^9\text{ cycles/s}$$
- **CPU 占用率（CPU Utilization）**：
  $$\text{Utilization}_{\text{intr}} = \frac{5 \times 10^9\text{ cycles/s}}{5 \times 10^8\text{ cycles/s}} = \mathbf{1000\%}$$
- **结论**：中断开销是 CPU 全部算力极限的 **10 倍**！CPU 流水线被彻底压垮挂起，磁盘数据发生严重 FIFO 溢出丢弃，系统根本无法运转。

---

#### 方案 2：采用 DMA 控制器成块传输方式
- 机制：磁盘数据通过 DMA 控制器以 **4 KB（$4096\text{ Bytes}$）数据块**为基本单位直接刷入内存；
- 数据传输期间采用**周期挪用**，主存控制器自动为 DMA 调度总线，CPU 访问片内 Cache 全速并行；
- **块中断频率**：
  $$f_{\text{dma}} = \frac{40 \times 10^6\text{ B/s}}{4096\text{ B}} \approx 9765.6\text{ 次/s}$$
- 仅在每个 4 KB 块传输完毕后，DMAC 才向 CPU 发出一次块结束中断通知。设 CPU 执行一次块中断处理程序（更新文件系统元数据、切换下一块缓冲区）需耗费 **1000 个 CPU 时钟周期**。
- **CPU 每秒用于 DMA 中断服务的时钟周期开销**：
  $$T_{\text{dma\_cycles}} = 9765.6\text{ 次/s} \times 1000\text{ cycles/次} \approx 9.77 \times 10^6\text{ cycles/s}$$
- **CPU 占用率（CPU Utilization）**：
  $$\text{Utilization}_{\text{dma}} = \frac{9.77 \times 10^6\text{ cycles/s}}{5 \times 10^8\text{ cycles/s}} \approx \mathbf{1.95\%}$$
- **性能质变**：DMA 控制器将 CPU 开销从无法承受的 **$1000\%$ 骤降至不到 $2\%$**！CPU 腾出了 $98\%$ 以上的算力专心运行用户应用程序。

## 4. 关联知识体系

### 1. 本学科内跨章节关联
- **计组指令周期与中断周期**：
  - CPU 仅在每条指令执行周期的末尾（执行阶段结束、下一次取指之前）检测可屏蔽外部中断引脚；
  - DMA 请求由总线仲裁器在每个机器存取周期（Bus Cycle）末尾采样判定，时序响应频率远高于中断。
- **计组 Cache 一致性（Cache Coherence）**：
  - DMA 控制器直接修改主存数据时，若对应的主存块已被 CPU 缓存到 Cache 且采用写回（Write-Back）策略，会导致“DMA 读到旧数据”或“CPU 读到旧数据”的 DMA Cache 不一致问题。现代系统通过硬件总线监听（Bus Snooping）或将 DMA 缓冲区配置为不可缓存来解决。

### 2. 跨学科协同关联
- **计组 DMA 传输 vs 操作系统“零拷贝（Zero-Copy）”与 SG-DMA**：
  - **共同机制**：消除 CPU 作为搬运工的性能浪费，让外设硬件直接存取内存物理页框。
  - **关键差异**：计组研究 DMAC 硬件的 MAR/WC 计数器与总线周期挪用；操作系统利用页高速缓存（Page Cache）并通过系统调用（如 `sendfile()`, `splice()`）组装物理页链表。
  - **不可直接迁移的判据**：纯软件的零拷贝系统调用（如早期 `sendfile`）若缺少网卡硬件 **分散-聚集 DMA（Scatter-Gather DMA）** 的支持，依然无法实现真正的“零 CPU 拷贝”（仍需 CPU 将数据从 Page Cache 拷贝到 Socket 缓冲区）。只有当网卡支持 SG-DMA 时，CPU 仅需向网卡传递包含物理页地址与偏移的缓冲区描述符链表，数据完全由网卡自主直接抓取。

## 5. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型 (经典教科书模型) | 现代工程实现边界 (PCIe MSI-X / APIC) |
| :--- | :--- | :--- |
| **中断物理信号线** | 单一专用硬件引脚 `INTR`、`NMI`，外设通过中断请求线拉低电平 | **消息信号中断（MSI / MSI-X）**。外设不使用物理中断专线，而是通过 PCIe 总线向 CPU 特殊地址写入特定数据包（In-band Write）触发中断 |
| **中断响应与判优** | 简单菊花链或单片 8259A 优先编码器，单核 CPU | **高级可编程中断控制器（APIC / GIC）**。支持多核心中断亲和性（Affinity）绑定、动态负载均衡与虚拟化中断直通 |
| **DMA 总线抢占** | 共享单一系统总线，周期挪用时 CPU 与主存彻底断开 | **多级交叉开关矩阵（Crossbar Switch）**。DMA 通道与 CPU 访存通道独立并行，只要不访问同一 DRAM 存储体（Bank），互不阻塞 |
| **零拷贝支持** | 仅定性理解 DMA 绕过 CPU | **IOMMU（输入输出内存管理单元）与 SG-DMA**。外设通过设备虚拟地址（IOVA）直接安全存取不连续物理页框，支持硬件级内存保护 |

## 6. 闭环决策模型与核心认知结论

### (1) 考场做题定性铁律
1. **CPU 响应中断请求的时机** $\to$ 必须处于**当前指令执行周期的末尾**。
2. **CPU 响应 DMA 请求的时机** $\to$ 可在**任意一个总线机器存取周期结束**（远比指令周期频繁）。
3. **硬件隐指令由什么产生？存放在哪里？** $\to$ 由 **CPU 内部微操作时序发生器直接硬件发射**，**绝对不存在于主存任何指令序列中**！
4. **关中断的物理目的** $\to$ 确保保护断点 PC 和程序状态字 PSW 的压栈操作具备**不可分割的原子性**。
5. **屏蔽字优先级判定** $\to$ 看对角线必为 1；某设备对应行中 `1` 的数量越多，其处理优先级越高。

### (2) 常见易错反例验证（3~6 元素测试）
- **反例 1：误以为中断响应优先级与处理优先级完全绑定一致**
  - 测试：若硬件响应优先级为 $1 > 2 > 3 > 4$，而系统希望优先处理紧急控制任务 4。通过将设备 4 的屏蔽字设为全 1，设备 1 的屏蔽字中第 4 位置 0，则一旦设备 4 请求到达，即可成功中断设备 1 的 ISR，实现处理优先级的逆转。
- **反例 2：误以为 DMA 周期挪用下 CPU 主频 2 GHz 必须停顿 1 个主频周期（0.5 ns）**
  - 真实物理过程：若总线存取周期为 50 ns，挪用的是 1 个主存存取周期（50 ns）。若 CPU 此时需要访问主存，CPU 停顿的是整整 100 个主频时钟周期（$50\text{ ns} / 0.5\text{ ns} = 100$），而非 1 个周期！
