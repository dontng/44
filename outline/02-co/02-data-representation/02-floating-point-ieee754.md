## 2. 核心机理与五步推演

### (1) 为什么需要浮点数？

- **定点数的物理局限**：
  定点数的小数点位置在硬件中固定。若用 32 位定点小数表示微观物理量（如 $10^{-30}$），或用 32 位定点整数表示天体距离（如 $10^{30}$），需要成百上千位的超长寄存器，造成硬件硅片面积的极大浪费。
- **动态浮动思想**：
  将数值解耦为**比例规模（阶码 Exponent）**与**有效精度（尾数 Mantissa）**：
  $$V = (-1)^S \times M \times 2^E$$
  使得有限的 32 位或 64 位机器字长能够覆盖极其广阔的动态数值范围。

### (2) IEEE 754 存储布局与单/双精度参数对照

```
单精度 float (32 位):
  31      30          23 22                                 0
 ┌───┬──────────────────┬─────────────────────────────────────┐
 │ S │    e (8 位阶码)   │           f (23 位尾数小数)         │
 └───┴──────────────────┴─────────────────────────────────────┘
  符号位  移码 (偏置值 127)         尾数有效位 1.f (隐藏最高位 1)

双精度 double (64 位):
  63      62          52 51                                 0
 ┌───┬──────────────────┬─────────────────────────────────────┐
 │ S │   e (11 位阶码)  │           f (52 位尾数小数)         │
 └───┴──────────────────┴─────────────────────────────────────┘
  符号位  移码 (偏置值 1023)        尾数有效位 1.f (隐藏最高位 1)
```

| 参数维度 | 单精度 float (32 位) | 双精度 double (64 位) |
| :--- | :---: | :---: |
| **数符位 $S$** | 1 位（0 为正，1 为负） | 1 位（0 为正，1 为负） |
| **阶码位宽与偏置值** | **8 位**，偏置值 $\text{Bias} = 2^{8-1} - 1 = \mathbf{127}$ | **11 位**，偏置值 $\text{Bias} = 2^{11-1} - 1 = \mathbf{1023}$ |
| **规格化阶码取值范围** | 机器码 $1 \sim 254 \implies$ 真实指数 $E = e - 127 \in [-126, +127]$ | 机器码 $1 \sim 2046 \implies$ 真实指数 $E = e - 1023 \in [-1022, +1023]$ |
| **尾数小数位宽 $f$** | **23 位**（物理存储） | **52 位**（物理存储） |
| **有效数值精度** | **24 位**（由于隐藏了前导整数 `1.`，即 $1.f$） | **53 位**（隐藏前导整数 `1.`，即 $1.f$） |
| **十进制有效数字精度** | $\approx 24 \times \log_{10} 2 \approx \mathbf{7 \text{ 位}}$ | $\approx 53 \times \log_{10} 2 \approx \mathbf{15 \sim 16 \text{ 位}}$ |

### (3) IEEE 754 五大数值状态全景判决表

| 阶码 $e$ | 尾数小数 $f$ | 数值类型 | 真值解码公式 | 物理功能与设计意图 |
| :---: | :---: | :---: | :---: | :--- |
| **$1 \sim 2^{k}-2$** | 任意 | **规格化数（Normal）** | $(-1)^S \times (1.f) \times 2^{e - \text{Bias}}$ | 绝大部分常规计算，隐藏前导 1 生效 |
| **全 0** | **全 0** | **真值零（$\pm 0$）** | $(-1)^S \times 0.0$ | 符号位区分 $+0$ 与 $-0$（全 0 位串为 $+0$） |
| **全 0** | **非零** | **非规格化数（Subnormal）** | $(-1)^S \times (\mathbf{0.}f) \times 2^{1 - \text{Bias}}$ | **隐藏位变为 0**！指数固定为 $-126$（单精度）；实现渐进下溢（Gradual Underflow），填补 0 附近缝隙 |
| **全 1** | **全 0** | **无穷大（$\pm \infty$）** | 溢出饱和值 | 发生阶码上溢或非零数除以零（如 `1.0 / 0.0`） |
| **全 1** | **非零** | **非数（NaN）** | 非法未定义操作 | 非法数学运算结果（如 `0.0 / 0.0`、负数开方） |

### (4) 强制类型转换的精度与越界边界剖析

在 32 位机器模型下（`int` 为 32 位补码，`float` 32 位，`double` 64 位）：

```
int (32位补码, 31位有效位)
  ├── 转换到 double (53位有效精度) ──► 53 > 31: 绝对无损, 精确转换!
  └── 转换到 float  (24位有效精度) ──► 24 < 31: 低位可能被舍入, 丢失精度!
```

| 类型转换路径 | 是否会发生精度丢失？ | 是否会发生数值范围溢出？ | 典型考点剖析与边界反例 |
| :--- | :---: | :---: | :--- |
| **`int -> double`** | **绝无可能** | **绝无可能** | `double` 有效尾数达 53 位，远超 `int` 的 31 位有效数值位，**100% 精确无损**。 |
| **`int -> float`** | **可能丢失** | **绝无可能** | `float` 动态范围约 $\pm 3.4 \times 10^{38}$，完全包容 `int`（约 $\pm 2.1 \times 10^9$），故绝不溢出；但 `float` 有效位仅 24 位，当 `int` 超过 $2^{24} = 16777216$ 时，低位将被舍入。 |
| **`float -> double`**| **绝无可能** | **绝无可能** | 精度与范围全方位覆盖，完全无损。 |
| **`double -> float`**| **可能丢失** | **可能溢出** | 高精度到低精度：低位截断发生舍入丢精度；若原数绝对值 $> 3.4 \times 10^{38}$，阶码上溢变为 $\pm \infty$。 |
| **`float/double -> int`** | **可能丢失** | **可能越界** | 小数部分被**直接向零截断（丢精度）**；若数值超出 `int` 表示范围，属于**未定义行为（Undefined Behavior）**。 |

#### 【不对称极值核心纠偏：`-2147483648` 在 `float` 下能否精确表示？】
- **常见误区**：“因为 `int` 是 31 位有效位，而 `float` 只有 24 位，所以最大的负数 `-2147483648` 转成 `float` 也一定会丢精度。”
- **真相**：
  32 位补码的最小负数真值为 $-2^{31} = -2147483648$。
  写成科学计数法：$-2^{31} = -1.0 \times 2^{31}$。
  - 数符位：$S = 1$；
  - 阶码：$E = 31 \implies e = 31 + 127 = 158 = 10011110_2$；
  - 尾数小数部分：$M = 000\dots 0$（全部 23 位均为 0）！
  - 机器码十六进制表示为：**`0xCF000000`**。
  - **`float` 可以 100% 精确无损地表示 `-2147483648`（$-2^{31}$）**！
- **反观正数最大值**：$2^{31}-1 = 2147483647$ 在二进制下需要连续 31 个 1（`1.1111...1 x 2^30`），由于 `float` 尾数只有 23 位，低位发生偶舍入，被直接进位舍入为 $+2^{31}$（`0x4F000000`），产生精度畸变。

### (5) 浮点数加减运算五步硬件流水全过程与二进制手算推演

浮点数加减法运算必须在硬件浮点运算部件（FPU）中经历完整的五步流水线操作：

```
操作数 X, Y ──► 1. 对阶 ──► 2. 尾数加减 ──► 3. 规格化 ──► 4. 舍入 ──► 5. 溢出判定 ──► 最终结果
```

#### ① 第一步：对阶（Align Exponents）
- **核心法则**：**小阶向大阶看齐**。
- **物理原因（为什么绝不能大阶向小阶看齐？）**：
  若大阶向小阶看齐，大数的尾数必须左移，导致大数的最高有效位从高位溢出丢失，造成巨大计算灾难；
  而小阶向大阶看齐时，小数的尾数右移，仅可能在低位丢失不重要的微小精度。
- **操作步骤**：
  计算阶差 $\Delta E = E_x - E_y$。将阶码较小者的尾数连同隐藏位 $1.$ 连续逻辑右移 $|\Delta E|$ 位，小阶的阶码每右移一位便加 1，直至两数阶码完全相等。

#### ② 第二步：尾数加减（Mantissa Addition / Subtraction）
- 将两数对阶后的有效尾数（包含前导整数位）送入定点 ALU 进行加减运算。
- 硬件中通常采用带双符号位的定点补码运算完成。

#### ③ 第三步：规格化（Normalization）
加减运算后的尾数形式必须恢复为 IEEE 754 规定的规格化形式 $1.f$：
- **右规（Right Normalization）**：
  若尾数加法产生了进位（例如双符号位变为 `01.` 或 `10.`），说明尾数溢出。
  - **动作**：尾数整体向右移 1 位，阶码同时加 1。
- **左规（Left Normalization）**：
  若尾数相减导致有效位相消，最高有效位不再是 1（例如双符号位呈现 `00.001...`）。
  - **动作**：尾数持续向左移动 $k$ 位，阶码相应连续减 $k$，直至最高有效位恢复为 1 为止。

#### ④ 第四步：舍入（Rounding）
在对阶右移和右规过程中，移出的低位有效位如果直接丢弃会产生累计误差。
IEEE 754 硬件在尾数右端保留 3 个额外的辅助位：
- **保护位（Guard bit）**：紧跟在保留尾数后面的第一位；
- **舍入位（Round bit）**：保护位后面的第二位；
- **粘滞位（Sticky bit）**：舍入位后面只要有任何非 0 比特被移出，粘滞位立即置 1。
- **就近舍入到偶数（Round to Nearest, Ties to Even，默认标准）**：
  当移出的部分恰好等于一半（即刚好处于两数正中间，保护位为 1 且后续全 0 时），选择使保留结果最低位为 `0`（偶数）的方向舍入，避免向同一方向偏移导致的长期统计漂移。

#### ⑤ 第五步：溢出判定（Overflow Check）
- **阶码上溢（Overflow）**：右规后若阶码超过 $254$（单精度），发生上溢，硬件将结果置为 $\pm \infty$ 或触发浮点溢出异常；
- **阶码下溢（Underflow）**：左规后若阶码小于 $1$，说明数值极微小，结果退化为非规格化数或直接置为浮点零（机器零）。

### (6) 完整浮点数加法二进制手算推演

**【题目】**：设单精度浮点数 $X$ 与 $Y$ 的 IEEE 754 十六进制机器码分别为：
$X = \text{0x41C00000}, \quad Y = \text{0x40800000}$，求 $X + Y$ 的 IEEE 754 最终机器码。

#### 1. 解码提取符号、阶码与尾数
- **解码 $X$ (`0x41C00000`)**：
  - 二进制：`0 10000011 10000000000000000000000`
  - $S_x = 0$（正数）；
  - 阶码 $e_x = 10000011_2 = 131 \implies E_x = 131 - 127 = \mathbf{4}$；
  - 完整有效尾数（包含隐藏位）：$M_x = \mathbf{1.1000...0}$（真值 $X = +1.5 \times 2^4 = 24.0$）。
- **解码 $Y$ (`0x40800000`)**：
  - 二进制：`0 10000001 00000000000000000000000`
  - $S_y = 0$（正数）；
  - 阶码 $e_y = 10000001_2 = 129 \implies E_y = 129 - 127 = \mathbf{2}$；
  - 完整有效尾数（包含隐藏位）：$M_y = \mathbf{1.0000...0}$（真值 $Y = +1.0 \times 2^2 = 4.0$）。

#### 2. 第一步：对阶
- 阶差：$\Delta E = E_x - E_y = 4 - 2 = 2$；
- 小阶 $Y$ 向大阶看齐：$Y$ 的阶码调整为 4，其有效尾数 $M_y = 1.000...0$ 逻辑右移 2 位：
  $$M_y' = \mathbf{0.0100...0}$$

#### 3. 第二步：尾数相加
同为正数，尾数直接相加：
```
    M_x  = 1.1000 0000 0000 0000 0000 000
  + M_y' = 0.0100 0000 0000 0000 0000 000
  ──────────────────────────────────────────
    M_z  = 1.1100 0000 0000 0000 0000 000
```

#### 4. 第三步：规格化
当前加法结果整数位恰好为 1（形式为 $1.1100...$），**本身已是合法规格化数，无需右规也无需左规**！阶码维持 $E_z = 4$（机器码 $e_z = 4 + 127 = 131 = 10000011_2$）。

#### 5. 第四步与第五步：舍入与溢出判定
右移过程中未移出任何有效位，无需舍入；阶码 $131 \in [1, 254]$，无溢出。

#### 6. 组装最终结果
- 符号位：$S = 0$；
- 阶码：$e_z = 10000011_2$；
- 尾数小数位（去掉前导 1）：$f_z = 11000000000000000000000_2$；
- 拼装完整 32 位机器码：
  `0 10000011 11000000000000000000000` $\implies$ **`0x41E00000`**
  *(真值验证：$1.75 \times 2^4 = 28.0$，与 $24.0 + 4.0 = 28.0$ 完全吻合！)*

## 3. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型（学理解题口径） | 现代工程实现边界（工业级 FPU） |
| :--- | :--- | :--- |
| **浮点舍入模式** | 考查就近舍入到偶数、截断法、0 舍 1 入法 | 现代 IEEE 754 芯片提供浮点控制字（CW），由程序动态切换 4 种舍入模式：向最近偶数舍入、向 $0$ 截断、向 $+\infty$ 舍入、向 $-\infty$ 舍入 |
| **非规格化数惩罚** | 仅按表格公式计算非规格化数真值 | 现代 CPU 执行非规格化数计算时硬件会产生微码协助（Microcode Assist），计算延迟暴增数十倍，工程上开启 **FTZ/DAZ（Flush-to-Zero / Denormals-Are-Zero）**模式直接将非规格化数强制归零以维持线速 |
| **浮点硬件架构** | 传统分离的 FPU 协处理器模型 | 现代 CPU 全面废弃 x87 栈式浮点单元，全面采用 **AVX-512 / ARM Neon 向量寄存器（SIMD）**并行执行 FMA（乘加一体化，Fused Multiply-Add）指令 |

## 4. 跨章节与跨学科关联

### 1. 本学科内跨章节关联
- $\to$ 关联 [定点数表示与补码运算](01-fixed-point-numbers.md)：
  - **共同机制**：浮点数的尾数加减法运算在底层完全由定点加减法器与移位器完成。
  - **关键差异**：定点数溢出改变符号位；浮点数尾数溢出只需右规一位并递增阶码，只有阶码溢出才是真正的浮点溢出。
  - **不可直接迁移的判据**：定点补码可以做精确算术比较；浮点数在计算机中存在舍入误差，绝对不能直接用 `==` 判断相等。
- $\to$ 关联 [运算器电路与先行进位加法器](03-alu-and-circuits.md)：
  - **共同机制**：对阶与规格化操作在硬件底层依赖多路桶形移位器（Barrel Shifter）在 1 个周期内完成任意位数的并行移位。
  - **关键差异**：ALU 进位链处理单次进位；FPU 包含前导零预测器（Leading Zero Anticipator, LZA）提前预判左规移动位数。
  - **不可直接迁移的判据**：浮点加法不满足代数结合律（由于对阶舍入，$(A + B) + C$ 可能不等于 $A + (B + C)$）。

### 2. 跨学科协同关联
- $\to$ 关联 [操作系统 / 进程上下文与硬件保护](../../03-os/02-process/01-process-states.md)：
  - **共同机制**：进程上下文切换时，若使用了浮点或向量运算，内核必须保存 FPU/AVX 扩展寄存器现场。
  - **关键差异**：普通通用寄存器上下文每次必存；浮点寄存器庞大，操作系统普遍采用**惰性 FPU 保存（Lazy FPU Restore）**技术优化切换开销。
  - **不可直接迁移的判据**：浮点除零不一定会杀死进程，如果线程设置了屏蔽浮点异常标志，硬件直接返回 $\pm \infty$ 继续运行。

## 5. 核心考点自查清单与闭环判据

1. **IEEE 754 参数速查**：
   - `float`：1 位符号 + 8 位阶码（偏置 127） + 23 位尾数（有效精度 24 位）；
   - `double`：1 位符号 + 11 位阶码（偏置 1023） + 52 位尾数（有效精度 53 位）。
2. **特殊数值状态**：
   - 阶码全 0、尾数全 0 $\implies \pm 0$；
   - 阶码全 0、尾数非 0 $\implies$ 非规格化数（无前导 1，指数固定 $-126$）；
   - 阶码全 1、尾数全 0 $\implies \pm \infty$；
   - 阶码全 1、尾数非 0 $\implies \text{NaN}$。
3. **加减运算核心步序**：
   - **小阶向大阶看齐**（小阶尾数右移）；
   - 尾数加减后：溢出右规加阶，相消左规减阶；
   - 最终判溢出看**阶码是否超界**，不看尾数。
