## 2. 核心机理与五步推演

### (1) 为什么现代计算机全盘采用“补码”？

- **物理矛盾（原码与反码的硬件缺陷）**：
  在 CPU 的 ALU 中，加法器硬件极为廉价且速度极快。若采用原码表示带符号数：
  - 做加法遇到异号数时，硬件必须先比绝对值大小，再决定做减法并确定结果符号；
  - 原码与反码均存在 $+0$（`0000...`）与 $-0$（`1000...`）两种表示，破坏了判零逻辑的一致性，硬件需额外增加多路比较门电路。
- **补码的数学哲学（模运算与同余映射）**：
  - 补码利用有限字长的模数特性（$n$ 位寄存器模为 $2^n$），将减法统一转换为加法：$A - B = A + (-B)_{\text{补}} \pmod{2^n}$；
  - **真值 0 的编码唯一性**：$[+0]_{\text{补}} = [-0]_{\text{补}} = 0000\dots 0$；
  - **不对称数值范围（多出一个最小负数）**：$n$ 位补码的表示范围为 $-2^{n-1} \sim 2^{n-1} - 1$。其中最小负数 $-2^{n-1}$ 编码为 `1000...0`（没有对应的 $n$ 位原码）。

### (4) 符号扩展、零扩展与数据截断

#### ① 短字长向长字长扩展（如 `char` $\to$ `int`）
- **零扩展（Zero Extension）**：针对**无符号数**。在新增的高位比特上**全部填充二进制 0**。
  - 例：8 位无符号数 `0x85`（`1000 0101`，真值 133）零扩展为 16 位：`0x0085`（`0000 0000 1000 0101`，真值仍为 133）。
- **符号扩展（Sign Extension）**：针对**带符号补码整数**。在新增的高位比特上**全部复制填充原符号位的值**（正数补 0，负数补 1）。
  - 例：8 位带符号补码 `0x85`（`1000 0101`，真值 $-123$）扩展为 16 位：
    符号位为 1，高 8 位全补 1，得到 `0xFF85`（`1111 1111 1000 0101`），其真值仍精确保持为 $-123$。

#### ② 长字长向短字长截断（Truncation，如 `int` $\to$ `short` / `char`）
- **物理机制**：硬件**直接丢弃多余的高位字节，原封不动截取并保留低位字节**。
- **真值畸变**：截断属于模 $2^k$ 运算，数值极大概率发生符号反转或剧烈溢出。
  - 例：32 位 `int` 值为 257（`0x00000101`），强转为 8 位 `char` 时丢弃高 24 位，仅保留低 8 位 `0x01`，真值突变为 1！

#### ③ C 语言有符号与无符号混合运算隐式转换陷阱
- **C 语言隐式转换规则（Usual Arithmetic Conversions）**：
  当一个带符号整数（`int`）与一个无符号整数（`unsigned int`）同时出现在同一个算术或比较表达式中时，**带符号整数被底层硬件无条件隐式提升转换为无符号整数**！
- **位串不变性与数值陷阱**：
  ```c
  int a = -1;
  unsigned int b = 0;
  if (a > b) {
      // 此分支在 C 语言中必然执行为真！
  }
  ```
  - **比特级推演**：
    `int a = -1` 的 32 位补码二进制位串为 `0xFFFFFFFF`；
    与 `b = 0` 比较时，`a` 被提升为 `unsigned int`，其底层的 32 位位串 `0xFFFFFFFF` 原封不动，但解释方式被强制变更为无符号整数：
    $$\text{真值} = 2^{32} - 1 = 4294967295$$
    显然 $4294967295 > 0$ 成立，导致原本直觉上的负数反而大于 0！

### (5) 补码加减法硬件实现与四大标志位（CF/OF 绝非互斥！）

#### ① ALU 加减法统一硬件数据通路
ALU 通过在加法器前端增加控制异或门与进位初值，将补码减法完美统一为加法：
$$A - B = A + (-B)_{\text{补}} = A + (\sim B) + 1$$
- 当执行减法时，控制信号 $\text{Sub} = 1$，将第二个输入端的所有比特通过异或门**按位取反**，并将加法器最低位进位输入端设为 $C_0 = \text{Sub} = 1$。

#### ② 四大硬件标志位的生成方程
ALU 执行一次运算后，硬件组合逻辑门**在同一个时钟节拍内并行生成四个状态标志位**：
1. **零标志 ZF（Zero Flag）**：结果所有数值位全为 0 时置 1，否则置 0。
2. **符号标志 SF（Sign Flag）**：直接等于结果的最高位（符号位），$\text{SF} = \text{Result}_{n-1}$。
3. **进位/借位标志 CF（Carry Flag）**：
   $$\text{CF} = C_{\text{out}} \oplus \text{Sub}$$
   - 加法时（$\text{Sub} = 0$）：$\text{CF} = C_{\text{out}}$（产生最高位进位即置 1）；
   - 减法时（$\text{Sub} = 1$）：$\text{CF} = C_{\text{out}} \oplus 1$（未产生进位说明发生了借位，置 1）。
4. **溢出标志 OF（Overflow Flag）**：
   $$\text{OF} = C_n \oplus C_{n-1}$$
   - $C_n$ 为最高位（符号位）产生的进位，$C_{n-1}$ 为最高数值位向符号位的进位。
   - 当两符号位同号数相加，结果符号与源操作数相反时，硬件判定有符号数溢出。

#### ③ 核心纠偏：CF 与 OF 的硬件非互斥本质与铁证反例
- **常见致命误区**：“因为 CF 是无符号进位标志，OF 是有符号溢出标志，所以它们在一次计算中必定互斥，不可能同时为 1。”
- **真相**：ALU 是纯粹的无知觉门电路，它根本不知道程序当前执行的是有符号数还是无符号数。**硬件每次运算都会无差别同时生成 CF 和 OF**！两者完全可以**同时为 1**。

**【铁证手算反例】**：8 位定点加法 `0x80 + 0x80 = 0x00`
- 二进制运算过程：
  ```
       1 0 0 0  0 0 0 0   (0x80)
   +   1 0 0 0  0 0 0 0   (0x80)
  ─────────────────────
   (1) 0 0 0 0  0 0 0 0   (8位截断结果为 0x00, 产生最高进位 C_8 = 1, C_7 = 0)
  ```
- **作为无符号数解释**：$128 + 128 = 256 > 255$（超出 8 位无符号上限）。
  最高位进位 $C_8 = 1$，加法 $\text{Sub} = 0 \implies \mathbf{CF = 1 \oplus 0 = 1}$（无符号溢出！）。
- **作为带符号补码解释**：$(-128) + (-128) = -256 < -128$（超出 8 位补码下限）。
  符号位进位 $C_8 = 1$，次高位进位 $C_7 = 0 \implies \mathbf{OF = C_8 \oplus C_7 = 1 \oplus 0 = 1}$（有符号负溢出！）。
- **同时结果为全 0**：$\mathbf{ZF = 1}, \quad \mathbf{SF = 0}$。
- **结论**：本例中 **`CF = 1` 且 `OF = 1` 同时成立**！

#### ④ 真正区分二者的是软件条件跳转指令
ALU 忠实生成所有标志后，编译器根据源代码的数据类型，发射对应的条件跳转指令来选择性地检查标志位：
- **无符号数大小比较**：依赖 `CF` 和 `ZF`（x86 指令：`ja`, `jae`, `jb`, `jbe`）；
- **带符号数大小比较**：依赖 `OF`、`SF` 和 `ZF`（x86 指令：`jg`, `jge`, `jl`, `jle`，判定条件为 $\text{SF} \oplus \text{OF} = 1$）。

## 3. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型（学理解题口径） | 现代工程实现边界（x86-64 / ARM / C 标准） |
| :--- | :--- | :--- |
| **有符号整数溢出** | 详细讨论溢出判断电路、变形补码与 OF 标志位 | 在 C/C++ 语言标准中，**有符号整数溢出属于未定义行为（Undefined Behavior, UB）**；编译器可能假定有符号整数永不溢出而直接优化掉溢出检查代码 |
| **浮点与定点转换** | 关注截断与扩展的比特位数映射 | 现代编译器开启 `-ftrapv` 或 `-fsanitize=undefined` 时，会在汇编中插入 `jo`（Jump on Overflow）指令在发生有符号溢出时触发中断异常 |
| **移位越界行为** | 假定移位位数 $k < n$ | 在 x86 中若移位次数 $\ge$ 寄存器字长，硬件会自动对移位量取模（如 32 位机器执行 `x << 32` 实际执行 `x << 0`） |

## 4. 跨章节与跨学科关联

### 1. 本学科内跨章节关联
- $\to$ 关联 [运算器电路与先行进位加法器](03-alu-and-circuits.md)：
  - **共同机制**：定点补码加减法基于带进位输入的并行全加器阵列实现。
  - **关键差异**：定点表示章节关注数值与标志语义；ALU 章节关注进位链门延迟与超前进位逻辑。
  - **不可直接迁移的判据**：双符号位法（变形补码）在存储器中仍按单符号位存放，仅在进入 ALU 寄存器时在最高位复制一位符号位。
- $\to$ 关联 [指令系统 / 汇编指令与寻址方式](../04-instruction-system/02-addressing-modes.md)：
  - **共同机制**：PC 相对寻址中的偏移量是带符号补码，必须经符号扩展后才能与 PC 相加。
  - **关键差异**：基址寻址偏移量与变址寻址偏移量在位宽不一致时，硬件自动进行有符号扩展。
  - **不可直接迁移的判据**：无符号逻辑地址计算采用零扩展，切不可错误套用符号位扩展。

### 2. 跨学科协同关联
- $\to$ 关联 [操作系统 / 异常与中断机制](../../03-os/01-fundamentals/02-interrupt-and-exception.md)：
  - **共同机制**：除法出错或特定架构下算术溢出被硬件捕获时，会向操作系统上报故障（Fault）或陷阱（Trap）异常。
  - **关键差异**：计组硬件仅负责在 EFLAGS/PSW 寄存器中将 OF 置位；操作系统负责向进程分发 `SIGFPE` 信号。
  - **不可直接迁移的判据**：普通的加减法溢出硬件仅置 `OF = 1`，不会主动暂停 CPU 产生陷阱中断，必须由软件显式检查（如 `INTO` 指令）。

## 5. 核心考点自查清单与闭环判据

1. **CF 与 OF 的本质判据**：
   - 硬件并行生成，**绝不互斥**（如 `0x80 + 0x80` 产生 `CF=1, OF=1`）；
   - $\text{CF} = C_{\text{out}} \oplus \text{Sub}$（无符号借进位）；
   - $\text{OF} = C_n \oplus C_{n-1}$（有符号溢出）。
2. **扩展与截断原则**：
   - 零扩展补 0，符号扩展补符号位；截断直接扔掉高位。
3. **C 语言有符号与无符号混合运算**：
   - 有符号数隐式提升为无符号数，二进制位串不变，解释数值突变（如 `-1 > 0U` 为真）。
