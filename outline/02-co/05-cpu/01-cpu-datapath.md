## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 内部单总线 vs 专用数据通路的物理冲突
* **内部单总线结构**：
  * **理念**：CPU 内部所有的寄存器（PC、IR、MAR、MDR、通用寄存器）、ALU 都挂载在一组公共的总线上。
  * **优势**：电路走线极少，布线简单，结构规整。
  * **物理瓶颈（总线冲突）**：**同一个时钟周期内，只允许一个部件往总线上送数据（输出），但允许多个部件从总线上读数据（输入）**！
    * 若 ALU 要做 $A + B$，两个操作数不能同时送上总线，必须先让一个操作数进暂存寄存器 $Y$，再把另一个操作数送上总线，最后 ALU 输出还要放暂存器 $Z$，导致单条指令耗费大量微操作时钟周期。
* **专用数据通路结构（多总线 / 点对点连接）**：
  * **理念**：在经常需要同时传输数据的部件之间铺设专门的并行硬件连线（如多路选择器 MUX 直连）。
  * **优势**：消除总线瓶颈，多个数据在同一周期内并行流动，**是高性能流水线 CPU 的必然选择**。

### (2) 指令周期的四大标准物理阶段与数据流动（408 每年必考大题）

设内部单总线结构，控制信号约定：`X_in` 为允许总线数据写入部件 X，`X_out` 为允许部件 X 输出到总线。

#### 1. 取指周期（Fetch Cycle，所有指令完全相同！）
* **任务**：根据 PC 从主存中取出指令，放入指令寄存器 IR，PC 自增。
* **微操作时序流**：
  1. `(PC) -> MAR`，发出控制信号：`PC_out, MAR_in`
  2. `M(MAR) -> MDR`，发出控制信号：`Mem_Read`
  3. `(MDR) -> IR`，发出控制信号：`MDR_out, IR_in`
  4. `(PC) + 1 -> PC`，PC 自增指向下一条指令

#### 2. 间址周期（Indirect Cycle，取有效地址）
* **任务**：针对间接寻址指令，根据形式地址从主存中取出操作数的真实有效地址。
* **微操作时序流**：
  1. `Ad(IR) -> MAR`，控制信号：`IR_out, MAR_in`
  2. `M(MAR) -> MDR`，控制信号：`Mem_Read`
  3. `(MDR) -> MAR`（此时 MAR 中存入真正的有效地址 EA）

#### 3. 执行周期（Execute Cycle，依指令而异）
* **加法指令 `ADD (R0), R1`（寄存器间接寻址）**：
  1. `(R0) -> MAR`，控制信号：`R0_out, MAR_in`
  2. `M(MAR) -> MDR`，控制信号：`Mem_Read`
  3. `(MDR) -> Y`（暂存器），控制信号：`MDR_out, Y_in`
  4. `(R1) + (Y) -> Z`，控制信号：`R1_out, ALU_add, Z_in`
  5. `(Z) -> R1`，控制信号：`Z_out, R1_in`

## 4. 闭环判定模型与核心认知结论

* **总线冲突排错铁律**：
  * 在单总线时序题中，若同一个时钟节拍内出现了两个及以上 `_out` 信号（例如同时写 `PC_out, MDR_out`），**该微操作序列必定在物理上是错误的**！
* **MAR 与 MDR 的方向物理约束**：
  * **MAR 只能连主存地址线，只能单向输入（CPU 只能给 MAR 写地址，不能从 MAR 读数据）**；
  * **MDR 连主存数据线，是双向的（可入可出）**。
