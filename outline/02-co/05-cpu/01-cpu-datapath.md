## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 内部单总线 CPU 数据通路完整拓扑架构

在单总线 CPU 内部，所有寄存器的输入输出端口、ALU 的输入输出端口均挂载在同一条公共的内部单总线上。为了保证逻辑电平不冲突，所有向总线输出数据的部件必须通过**三态门（Tri-state Buffer）**驱动。

```
                       ┌─────────────────────────────────────────────────────────┐
                       │                     CPU 内部单总线 (Internal CPU Bus)     │
                       └──┬────────▲───────┬────────▲───────┬────────▲───────┬───▲───┘
                          │        │       │        │       │        │       │   │
                          │ R0in   │ R0out │ R1in   │ R1out │ PCin   │ PCout │   │
                       ┌──▼────────┴──┐ ┌──▼────────┴──┐ ┌──▼────────┴──┐  │   │
                       │ 通用寄存器 R0 │ │ 通用寄存器 R1 │ │ 程序计数器 PC  │  │   │
                       └──────────────┘ └──────────────┘ └──────────────┘  │   │
                                                                           │   │ SPin, SPout
                                                                        ┌──▼───┴───────┐
                                                                        │ 栈指针 SP     │
                                                                        └──────────────┘
                          │        │       │                │
                          │ Y_in   │       │ IR_in          │ MAR_in
                       ┌──▼────────┘       │             ┌──▼────────────┐
                       │ 暂存器 Y   │       │             │ 地址寄存器 MAR │
                       └─────┬──────┘      │             └───────┬───────┘
                             │             │                     │ (单向驱动外部)
                             ▼             │                     ▼
                       ┌────────────┐      │             ═════════════════ 地址总线 (AB)
      总线数据输入 ────►│  ALU 核心  │      │
                       └─────┬──────┘      │                     ▲
                             │             │                     │ MDR_outE / MDR_inE
                             ▼             │             ┌───────▼───────┐
                       ┌────────────┐   ┌──▼────────┐    │ 数据寄存器 MDR │◄────► 数据总线 (DB)
                       │ 暂存器 Z   │   │ 指令寄存器 │    └───────┬───────┘
                       └─────┬──────┘   │    IR     │            │
                             │ Z_out    └─────┬─────┘            │ MDR_in / MDR_out
                             │                │                  │
                             └────────────────┴──────────────────┘
                                              │ (操作码 OP)
                                              ▼
                                    ┌───────────────────┐
                                    │ 控制单元 CU (译码) │◄──── 控制总线 (CB: 时钟/中断/状态)
                                    └───────────────────┘
```

#### 1. 核心寄存器分类与可见性矩阵

| 寄存器名称 | 物理全称 | 核心职能 | 用户/程序员可见性 | 机制分水岭 |
| :--- | :--- | :--- | :---: | :--- |
| **PC** | Program Counter | 存放下一条要执行指令的内存地址 | **用户可见** | 可被跳转指令显式修改或读取 |
| **IR** | Instruction Register | 存放当前正在译码执行的指令字 | **内部透明** | 纯硬件使用，程序员无法直接寻址 |
| **MAR** | Memory Address Register | 锁存要访问的主存物理单元地址 | **内部透明** | 输出端直连外部地址总线 AB |
| **MDR** | Memory Data Register | 暂存要写入主存或刚从主存读出的数据 | **内部透明** | 双向端口，隔离 CPU 内部总线与外部数据总线 DB |
| **通用寄存器**<br>($R_0 \sim R_n$) | General Purpose Registers | 暂存操作数、中间计算结果或地址指针 | **用户可见** | 由汇编指令显式编码指定 |
| **PSW / FLAGS** | Program Status Word | 记录算术标志位（ZF, CF, SF, OF）与中断屏蔽字 | **用户可见** | 条件转移依据，可用特权指令读写 |
| **SP** | Stack Pointer | 存放进程栈顶的内存地址 | **用户可见** | `push/pop/call/ret` 自动修改 |
| **暂存器 Y** | Temporary Register Y | 暂存送入 ALU 的第一个操作数 | **内部透明** | 解决单总线无法同时提供两个输入端的冲突 |
| **暂存器 Z** | Temporary Register Z | 暂存 ALU 计算输出的结果 | **内部透明** | 解决 ALU 输出不能立即环回总线的反馈冲突 |

#### 2. 为什么单总线 CPU 必须配备暂存器 Y 和 Z？
- **输入端冲突（暂存器 Y 的必然性）**：ALU 是一个纯组合逻辑电路，执行诸如 $A + B$ 的双目运算时，两个输入端必须**在同一瞬间同时保持稳定的电平**。但在内部单总线结构中，一个时钟周期内总线上只能传输一个操作数。因此，必须先将第一个操作数（如来自 $R_0$）打入**暂存器 Y 锁存**，下一个时钟周期再把第二个操作数（如来自 $R_1$）放上内部总线，ALU 方可稳定运算。
- **输出端反馈冲突（暂存器 Z 的必然性）**：ALU 计算出的结果不能直接接回内部总线。如果 ALU 的输出端直连总线，而总线此时正连接着 ALU 的某个输入端，就会形成一个**不受时钟控制的环路振荡（Race Hazard）**。必须在 ALU 输出端设置**暂存器 Z**，先将结果锁存在 Z 中，待运算彻底稳定后，再在下一个时钟节拍打开 $Z_{\text{out}}$ 将结果送上总线。

#### 3. MAR 与 MDR 的通路物理约束
- **MAR 仅具备单向输出至外部地址总线**：在大多数 408 经典数据通路模型中，MAR 的输出端唯一连接外部地址总线（AB），**并不具备回送 CPU 内部总线的 $MAR_{\text{out}}$ 通路**。因此在间址寻址中，有效地址必须从 MDR 或 IR 送入 MAR，不可设计依赖 $MAR_{\text{out}}$ 的微操作。
- **MDR 具备两套独立的双向收发三态门**：
  - CPU 内部端：`MDRin`（总线打入 MDR）、`MDRout`（MDR 输出到内部总线）；
  - CPU 外部端：`MDRinE`（外部数据总线打入 MDR）、`MDRoutE`（MDR 输出到外部数据总线）。

### (2) 机器指令周期的四大工作周期与状态机转换

一个完整的指令周期在物理上被切分为至多四个机器周期（工作周期）：

```
                    ┌────────────────────────┐
                    │     取指周期 (FE)       │
                    └───────────┬────────────┘
                                │
               ┌────────────────┴────────────────┐
               ▼ (指令为间接寻址)                  ▼ (指令为直接/寄存器寻址)
    ┌──────────────────────┐                     │
    │     间址周期 (IND)    │                     │
    └──────────┬───────────┘                     │
               │                                 │
               └────────────────┬────────────────┘
                                │
                                ▼
                    ┌────────────────────────┐
                    │     执行周期 (EX)       │
                    └───────────┬────────────┘
                                │
               ┌────────────────┴────────────────┐
               ▼ (有未屏蔽中断请求)                 ▼ (无中断请求)
    ┌──────────────────────┐                     │
    │     中断周期 (INT)    │                     │
    └──────────┬───────────┘                     │
               │                                 │
               └────────────────┬────────────────┘
                                │
                                ▼ (回跳至下一条指令)
                    ┌────────────────────────┐
                    │     取指周期 (FE)       │
                    └────────────────────────┘
```

#### 四大工作周期的物理职责与 CPU 标志触发器
CPU 内部维护 4 个工作周期触发器（`FE`, `IND`, `EX`, `INT`），在任意时刻**有且仅有 1 个触发器处于置位状态（1）**，标识当前 CPU 所处的工作状态：
1. **取指周期（FE, Fetch）**：
   - 将 PC 指向的内存单元中的指令代码读入 IR，并将 PC 自增指向下一条指令。
   - **PC 自增精算**：必须精确表述为 **$(PC) + k \to PC$**，其中 $k$ 为当前指令占用的**字节长度**。在按字节编址的 32 位机器中，一条指令占 4 字节，故为 $(PC) + 4 \to PC$；只有按字编址时才简写为 $(PC) + 1 \to PC$。
2. **间址周期（IND, Indirect）**：
   - 针对间接寻址指令，将指令中的形式地址送入 MAR，读出真正的有效地址 EA。
3. **执行周期（EX, Execute）**：
   - 译码器识别操作码，控制 ALU 进行算术/逻辑运算，或访问内存读写操作数。
4. **中断周期（INT, Interrupt）**：
   - 在执行周期的最后时刻，CPU 硬件采样中断请求引脚。若有未被屏蔽的中断请求，CPU 进入中断周期；
   - **中断周期三步硬件动作**：
     1. **关中断**：将中断允许标志（IF）清零，禁止更低优先级的中断打扰；
     2. **保存断点**：将当前的断点 PC 压入内存堆栈（或硬件专用暂存单元）；
     3. **引出中断服务程序**：根据中断向量，将对应中断服务程序的入口地址写入 PC。

### (3) 单总线数据通路微操作序列与时序追踪大表（手算大题范例）

#### 经典指令任务设定
在如图所示的单总线 CPU 数据通路中，执行一条主存间接寻址的加法指令：
$$\text{ADD } R_1, \; @(R_2)$$
- **语义**：将通用寄存器 $R_2$ 的内容作为内存地址读出有效地址 EA，再根据 EA 从主存读出源操作数，与通用寄存器 $R_1$ 的内容相加，结果写回 $R_1$。在指令执行结束后，响应外部中断。
- **系统总线控制信号约定**：
  - `Mem_Read`：发出主存读命令，内存读出完毕后由硬件产生等待完成信号（MFC）；
  - `Mem_Write`：发出主存写命令；
  - `_in` 表示打入该寄存器，`_out` 表示该寄存器输出到内部单总线。

#### 完整四周期单步微操作与控制信号追踪表

| 工作周期 | 时钟节拍 | 微操作内容 (Micro-operation) | 有效控制信号 (Control Signals) | 内部总线驱动源 | 物理设计约束与防冲突说明 |
| :---: | :---: | :--- | :--- | :---: | :--- |
| **取指周期 (FE)** | $T_0$ | $(PC) \to MAR$ | `PCout, MARin` | $PC$ | 将当前指令地址送入地址寄存器 |
| | $T_1$ | $M(MAR) \to MDR$<br>$(PC) + 4 \to PC$ | `Mem_Read, MDRinE`<br>*(由专用硬件自增器完成)* | **无内部总线占用** | 主存读取期间，PC 在内部独立自增，不占用内部总线 |
| | $T_2$ | $(MDR) \to IR$ | `MDRout, IRin` | $MDR$ | 指令进入 IR，指令译码器开始工作 |
| **间址周期 (IND)** | $T_0$ | $(R_2) \to MAR$ | `R2out, MARin` | $R_2$ | 将形式地址指针从 $R_2$ 送入 MAR |
| | $T_1$ | $M(MAR) \to MDR$ | `Mem_Read, MDRinE` | **无内部总线占用** | 启动主存读，读取有效地址 EA |
| | $T_2$ | $(MDR) \to MAR$ | `MDRout, MARin` | $MDR$ | 将读取出的有效地址 EA 重新装入 MAR |
| **执行周期 (EX)** | $T_0$ | $M(MAR) \to MDR$ | `Mem_Read, MDRinE` | **无内部总线占用** | 启动主存读，根据 EA 读取真实源操作数 |
| | $T_1$ | $(MDR) \to Y$ | `MDRout, Yin` | $MDR$ | 将源操作数打入 ALU 暂存器 Y 锁存 |
| | $T_2$ | $(R_1) + (Y) \to Z$ | `R1out, ALU_add, Zin` | $R_1$ | $R_1$ 放上总线，ALU 计算并打入暂存器 Z |
| | $T_3$ | $(Z) \to R_1$ | `Zout, R1in` | $Z$ | 运算结果写回通用寄存器 $R_1$ |
| **中断周期 (INT)** | $T_0$ | $(SP) - 4 \to SP$<br>$(SP) \to MAR$ | `SPout, ALU_sub4, SPin, MARin` | $SP$ | 堆栈指针自减并送入 MAR（准备压栈保存 PC） |
| | $T_1$ | $(PC) \to MDR$ | `PCout, MDRin` | $PC$ | 将断点 PC 送入数据寄存器 |
| | $T_2$ | $(MDR) \to M(MAR)$ | `MDRoutE, Mem_Write` | **无内部总线占用** | 启动主存写，将断点写入栈顶 |
| | $T_3$ | 向量地址 $\to PC$ | `Vector_out, PCin, Clear_IF` | 向量发生器 | 将中断服务入口送 PC，关中断（清 IF） |

> [!IMPORTANT]
> **总线互斥绝对铁律（考场阅卷核心得分点）**：
> 在任意一个时钟节拍（Clock Step）内：
> 1. **有效输出信号（`_out`）最多只能有 1 个**（若同时出现两个 `_out` 必定导致总线短路烧毁）；
> 2. **有效输入信号（`_in`）可以同时有多个**（总线数据广播给多个寄存器并行锁存，如 $T_0$ 的 `SPin, MARin`）。

## 3. 本学科内跨章节关联与跨学科协同关联

### 1. 本学科内跨章节关联

#### (1) 与存储器层次结构（Cache / 主存）的读写握手
- **共同机制**：异步总线定时与就绪握手。
- **关键差异**：
  - 数据通路微操作中的 `Mem_Read` 发出后，CPU 不能盲目进入下一个执行节拍；
  - 现代硬件通过 **内存就绪信号（MFC, Memory Function Completed）** 进行硬件插入等待周期（Tw）。若 Cache 命中，1 个周期即可继续；若 Cache 缺失，硬件自动阻塞数据通路直到 DRAM 返回。
- **不可直接迁移的判据**：做题时若未提及 MFC 信号，默认主存读取在一个固定时钟节拍内完成。

#### (2) 与指令流水线的硬件解耦
- **共同机制**：取指、译码、执行的功能划分。
- **关键差异**：
  - 单总线数据通路中，所有阶段强行共享同一条总线，各个阶段必须**分时串行推进**；
  - 流水线数据通路将各个阶段彻底拆解为独立的物理硬件流水段，各段之间通过**段间寄存器（Pipeline Registers, 如 IF/ID, ID/EX）**隔离，消除了公共总线瓶颈。
- **不可直接迁移的判据**：流水线必须建立在专用数据通路（哈佛结构）基础之上，在内部单总线架构上无法构建多指令重叠流水线。

---

### 2. 跨学科协同关联

#### (1) 操作系统：进程上下文切换与硬件现场保存
- **共同机制**：执行现场的断点压栈。
- **关键差异**：
  - CPU 中断周期（硬件隐指令）在硬件层面仅自动压入 **断点 PC 与 PSW**（部分机器压入 SP）；
  - 操作系统中断处理程序（软件内核）必须在进入服务例程后，通过软件指令依次将通用寄存器 $R_0 \sim R_n$ 全量压入内核栈。
- **不可直接迁移的判据**：不能以为硬件中断周期会自动备份全部通用寄存器，硬件只保存恢复控制流所必需的极小上下文。

## 4. 闭环决策模型与核心认知结论

### (1) 单总线微操作控制信号排错 3 秒决策树

```
检视给出的时钟节拍控制信号组合:
  ├─ 检查该节拍是否有 >= 2 个不同的 _out 信号被同时拉高?
  │    └─ 是 ──► 【必定错误!】违反单总线同一时刻唯一驱动源物理约束。
  │
  ├─ 检查对 ALU 进行加减运算的节拍:
  │    ├─ 是否漏掉了提前将第一个操作数装入暂存器 Y (Yin)? ──► 【必定错误!】
  │    └─ 是否运算当周期直接把 ALU 输出写回寄存器而未经过 Z (Zin)? ──► 【必定错误!】
  │
  └─ 检查主存读写时序:
       └─ 是否在未将地址送入 MAR (MARin) 的情况下就提前发出了 Mem_Read? ──► 【必定错误!】
```

### (2) 考场定性闭环判据
1. **指令周期各阶段出现频率**：
   - **取指周期（FE）**：任何指令都必须经历，且所有指令的取指微操作序列完全相同。
   - **间址周期（IND）**：仅在指令明确采用间接寻址时才出现。
   - **中断周期（INT）**：仅在指令执行末尾检测到未屏蔽中断请求时才出现。
2. **PC 自增的时机**：
   - 可以在读主存的等待期间（$T_1$）由专用自增器自动完成，避免占用公共内部总线。
