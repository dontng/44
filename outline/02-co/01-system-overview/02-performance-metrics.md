## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 三大“字长”的硬件物理定位（不可混淆）
在计算机硬件中，有三个经常容易混淆的概念：
1. **机器字长（Machine Word Length）**：
   - **硬件物理实体**：CPU 内部**算术逻辑单元（ALU）单次能够并行处理的二进制整数运算位数**，通常等于通用内部寄存器的位宽。
   - 标志着 CPU 的整数运算精度与寻址潜力（如 32 位 CPU、64 位 CPU）。
2. **指令字长（Instruction Word Length）**：
   - **硬件物理实体**：一条机器指令所包含的二进制代码的总位数。
   - 指令字长可以等于机器字长，也可以是半字长、双字长或多字长（变长指令集）。
3. **存储字长（Storage Word Length）**：
   - **硬件物理实体**：主存储器中**一个存储单元（由 MDR 寄存器宽度决定）所包含的二进制位数**。
   - 现代计算机普遍采用**字节编址**（存储单元为 8 位），但内存总线单次迸发传送的位宽（存储字长）通常为 32 位或 64 位。

### (2) 计算机性能的核心基石：CPU 时间方程
评价一台计算机执行某个程序快慢的**唯一客观物理标准是：该程序的实际执行耗时（Wall-Clock Execution Time）**！

$$\text{CPU 运行时间} = \text{程序包含的总指令条数 (IC)} \times \text{每条指令平均时钟周期数 (CPI)} \times \text{时钟周期时长 (T)}$$
$$\text{CPU 运行时间} = \frac{\text{IC} \times \text{CPI}}{\text{CPU 主频 } f}$$

- **公式的三维物理制约平衡（Trade-off）**：
  1. **指令数（Instruction Count, IC）**：由**编译器算法**和**指令集架构（ISA）**决定。CISC 指令条数少，RISC 指令条数多。
  2. **CPI（Cycles Per Instruction）**：由**微体系结构设计**（如超标量流水线、分支预测器、Cache 命中率）决定。流水线越深、乱序调度越强，CPI 越低（IPC 越高）。
  3. **时钟主频（$f$ / $T$）**：由**半导体工艺制程**（如 3nm/5nm）和**门电路逻辑延迟**决定。流水线切得越细，单级门延迟越小，主频可以飙得越高。

### (3) MIPS 与主频的经典物理陷阱（考场极高频辨析）

#### ① MIPS 算力指标公式
$$\text{MIPS} = \frac{\text{指令数 IC}}{\text{执行时间} \times 10^6} = \frac{\text{主频 } f}{\text{CPI} \times 10^6}$$
- 其中 $f$ 的单位为 Hz（若 $f$ 为 MHz，公式分母的 $10^6$ 恰好约掉，即 $\text{MIPS} = \frac{f(\text{MHz})}{\text{CPI}}$）。

#### ② 为什么 MIPS 和主频不能跨架构衡量机器性能？（深刻剖析）
- **谬误 1：“主频 4.0 GHz 的 CPU 一定比主频 3.0 GHz 的 CPU 快”**：
  - 若 4.0 GHz 的 CPU 由于流水线过深或 Cache 频繁缺失导致平均 $\text{CPI} = 2.0$；
  - 而 3.0 GHz 的 CPU 架构优秀，平均 $\text{CPI} = 1.0$；
  - 同样执行 1 亿条指令，3.0 GHz CPU 耗时 $\frac{10^8 \times 1}{3 \times 10^9} = 0.033\text{s}$，远快于 4.0 GHz CPU 的 $\frac{10^8 \times 2}{4 \times 10^9} = 0.050\text{s}$！
- **谬误 2：“MIPS 更高的电脑性能一定更好”**：
  - 在执行同一个上层 C 语言排序程序时：
    - RISC 机器由于指令极其简单，编译出 200 万条精简指令，平均 $\text{CPI} = 1$，主频 1GHz，其 $\text{MIPS} = 1000$，运行耗时 2ms；
    - CISC 机器支持强大的复杂指令，编译出的程序仅需 50 万条复杂指令，平均 $\text{CPI} = 3$，主频 1GHz，其 $\text{MIPS} = 333$，运行耗时仅需 1.5ms！
  - 显然，**MIPS 仅为 333 的机器实际性能反而彻底碾压了 MIPS 达到 1000 的机器**！因此，MIPS 只能用于同一种指令架构下的微架构改进对比，严禁跨 ISA 架构盲目横评。

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 计组: 性能指标与 CPI 方程     │
                     └──────────────┬───────────────┘
                                    │ 微架构制约因果
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 计组: 指令流水线与相关冒险    │         │ 计组: 存储层次与 Cache 缺失   │
│  - 数据/控制冒险引发流水停顿  │ ◄────── │  - 缺失惩罚 (Miss Penalty)   │
│  - 气泡拉高 CPI (降低 IPC)   │         │  - 访存时延直接推高平均 CPI   │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与指令流水线及 Cache 缺失惩罚的精确耦合**：
   $$\text{实际平均 CPI} = \text{理想流水线 CPI}_{\text{ideal}} + \text{结构冒险停顿} + \text{数据相关停顿} + \text{分支预测失败停顿} + \mathbf{Cache 缺失率 \times 缺失惩罚周期}$$
   现代 CPU 的 CPI 波动绝大部分是由底层 Cache 缺失和流水线冲刷造成的。
2. **与 CISC vs RISC 架构设计哲学的根源映射**：
   - CISC 追求**减少指令数 IC**（一条指令干很多事）；
   - RISC 追求**压缩 CPI 到极限**（每条指令 1 周期）并**拉高主频 $f$**。

## 4. 闭环决策模型与核心认知结论

### (1) 考场计算绝对换算基准
- **单位换算绝对不要错位**：
  - 频率：$1\text{ GHz} = 10^3\text{ MHz} = 10^6\text{ kHz} = 10^9\text{ Hz}$。
  - 时间：$1\text{ s} = 10^3\text{ ms} = 10^6\text{ \mu s} = 10^9\text{ ns}$。
  - 主频 $f$ 与时钟周期 $T$ 互为倒数：$T = \frac{1}{f}$（如主频 2GHz 对应的时钟周期严格为 $0.5\text{ ns}$）。

### (2) 综合平均 CPI 严谨加权公式
若一个程序包含 $k$ 种不同类型的指令，每种指令的出现频率为 $p_i$，其单条指令耗费周期数为 $\text{CPI}_i$：
$$\text{平均 CPI} = \sum_{i=1}^{k} (p_i \times \text{CPI}_i)$$

### (3) 考场定性闭环判据
1. **评价计算机硬件性能的最根本、唯一权威指标**：**执行特定基准测试程序所花费的实际 CPU 时间（响应时间）**。
2. **主频相同的两台计算机，性能是否一定相同？** $\to$ **绝对不一定**，还取决于微架构的 CPI 以及编译器编译出的指令条数 IC。
3. **基准程序（Benchmark）得分越高是否代表所有软件都跑得更快？** $\to$ 不一定，基准程序只代表特定工作负载（如 SPEC CPU、Linpack 测试），无法覆盖所有特定业务场景。
