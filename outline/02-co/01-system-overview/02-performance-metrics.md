## 2. 核心机理与五步推演

### (1) 四大“字长与宽度”硬件概念彻底解耦

计算机硬件中涉及数据位宽的四大概念常常被笼统混用，必须从物理部件与寄存器载体上予以严格厘清：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        CPU 芯片内部                                    │
│  [通用寄存器 R0..R7] (机器字长) ◄──► [ALU 算术逻辑单元] (机器字长)     │
│  [PC 程序计数器] ───────────────► [IR 指令寄存器] (指令字长)          │
│  [MAR 地址寄存器]               [MDR 数据寄存器] (存储字长)          │
└───────┬───────────────────────────────────▲────────────────────────────┘
        │ 地址总线                          │ 外部数据总线 (数据总线宽度)
┌───────▼───────────────────────────────────┴────────────────────────────┐
│                        主存储器 (DRAM)                                 │
│  存储矩阵: 每个存储单元包含若干位二进制信息 (对应存储字长)             │
└────────────────────────────────────────────────────────────────────────┘
```

| 概念名称 | 核心物理载体与硬件实体 | 决定因素与功能定位 | 典型特征与制约关系 |
| :--- | :--- | :--- | :--- |
| **机器字长**<br>(Machine Word) | CPU 内部**通用寄存器**与 **ALU** 的物理二进制位数 | 决定 CPU **一次整数运算的精度**与内部数据通路带宽（如 32 位 CPU、64 位 CPU） | 标志计算机处理核心算力档次；通常等于内部定点整数数据通路宽度 |
| **存储字长**<br>(Storage Word) | 主存一个存储单元的二进制位数，对应 **MDR（主存数据寄存器）** 宽度 | 决定主存一次读写操作能够**并行输出/输入的二进制总位数** | 现代主存多按字节（8 位）编址，但读写访问可以按存储字长（如 32 位、64 位）对齐并行进出 |
| **指令字长**<br>(Instruction Word) | **IR（指令寄存器）** 中一条机器指令包含的二进制代码总位数 | 由**指令集架构（ISA）**的操作码字段与地址码字段设计决定 | 可以是定长的（如 RISC-V 32 位固定），也可以是变长的（如 x86 的 1~15 字节）；可等于半字长、单字长或双字长 |
| **数据总线宽度**<br>(Data Bus Width) | CPU 芯片引脚与主板之间**外部双向数据总线的物理导线根数** | 决定 CPU 与主存/外设之间**单次时钟节拍能够并行传输的物理位数** | 可以小于或等于存储字长。若存储字长为 64 位而总线宽度仅为 32 位，则读取一个存储字需分两次总线传输完成 |

### (2) 性能指标三大维度的严格物理边界

评判计算机性能指标时，必须区分三种不同维度的耗时与速率：

1. **CPU 执行时间（CPU Time / $T_{\text{CPU}}$）**：
   - **严格物理定义**：**纯粹由 CPU 硬件消耗在当前进程指令执行上的有效时钟周期时间**（包含用户态时间 User CPU Time 与内核态系统调用时间 System CPU Time）；
   - **绝不包含**：等待外部硬盘/网络 I/O 的阻塞时间，以及操作系统因多任务分时将 CPU 调度给其他进程运行的时间。
2. **系统响应时间（Wall-clock Time / Elapsed Time / 墙钟时间）**：
   - 外部观察者用秒表记录从程序启动到最终产生结果的**总流逝物理时间**：
     $$\text{响应时间} = T_{\text{CPU}} + \text{I/O 等待时延} + \text{操作系统调度等待开销} + \text{其他并发任务争用时延}$$
3. **系统吞吐率（Throughput）**：
   - 单位时间内整个计算机系统或数据中心完成的总任务或事务数量（例如 Web 服务器的 QPS、TPS）。

### (3) CPU 时间方程三要素与流水线深度制约平衡

评价单道程序计算性能的最根本客观标准是 **CPU 执行时间**：
$$T_{\text{CPU}} = \text{程序包含的总指令条数 (IC)} \times \text{每条指令平均时钟周期数 (CPI)} \times \text{时钟周期时长 } T_{\text{clk}}$$
$$T_{\text{CPU}} = \frac{\text{IC} \times \text{CPI}}{\text{CPU 主频 } f}$$

#### ① 三要素之间的相互牵制权衡（Trade-off）
- **指令条数（Instruction Count, IC）**：由**编译器优化质量**和**指令集架构（ISA）**共同决定；
- **每条指令平均周期数（CPI）**：由**微体系结构设计**（流水线级数、超标量发射度、分支预测精度、Cache 命中率）决定；
- **时钟频率（$f = 1/T_{\text{clk}}$）**：由**芯片半导体工艺制程**（如 3nm/5nm）与**关键路径组合逻辑门延迟**决定。

#### ② 流水线级数切分对主频与 CPI 的双向制约（打破“流水线越深越好”的误区）
- **积极效应（拉高主频 $f$）**：
  将原本复杂的指令执行逻辑切分为更细的多级流水线（如从 5 级切到 20 级），每一级包含的门电路逻辑显著减少，最大单级组合逻辑延迟被大幅压缩，使得 CPU 可以飙到极高主频（$f$ 激增）；
- **消极效应（推高综合 CPI，吞吐反受损）**：
  1. 理想标量流水线稳态时 $\text{CPI}_{\text{ideal}} = 1$。
  2. 流水线切得过深会导致：**数据冒险的转发旁路级数剧增**，无法旁路时停顿的气泡周期成倍增加；
  3. **分支预测失败的冲刷惩罚（Branch Misprediction Penalty）急剧放大**！若在第 15 级才算出分支跳转结果，预测失败需无情清空前 14 级已取指令，一次惩罚白白浪费 14 个时钟周期，导致**实际综合 $\text{CPI}$ 严重劣化上升**！
  4. 当流水线切分过细超过临界点时，CPI 的上升幅度将彻底盖过主频提升的收益，总执行时间 $T_{\text{CPU}}$ 反而变长。

### (4) 包含 Cache 缺失惩罚的精确 CPI 模型

在真实微体系结构中，单条指令在流水线中不仅经历取指，还可能触发数据访存。必须将**存储层次的缺失惩罚**纳入 CPI 方程：

$$\text{CPI}_{\text{eff}} = \text{CPI}_{\text{base}} + \text{Memory Stall Cycles Per Instruction}$$
$$\text{CPI}_{\text{eff}} = \text{CPI}_{\text{base}} + \Big( \text{I-Cache 缺失率} \times 1 + \text{D-Cache 缺失率} \times f_{\text{mem\_data}} \Big) \times \text{Miss Penalty}$$

- $\text{CPI}_{\text{base}}$：理想情况下 Cache 全部命中时的基础 CPI；
- $\text{I-Cache 缺失率} \times 1$：因为**每条指令都必须发生且仅发生 1 次取指令访存**；
- $f_{\text{mem\_data}}$：程序中数据访存指令（Load / Store）占所有指令的百分比（通常为 $20\% \sim 40\%$）；
- $\text{Miss Penalty}$：Cache 未命中时从下级存储器（L2/L3 或 DRAM 主存）调块所需的额外等待时钟周期数。

### (5) 算力指标换算与经典 MIPS 评价陷阱

#### ① 算力常用衡量指标定义与数量级换算
- **MIPS（Million Instructions Per Second，每秒百万条指令）**：
  $$\text{MIPS} = \frac{\text{指令数 IC}}{T_{\text{CPU}} \times 10^6} = \frac{\text{主频 } f}{\text{CPI} \times 10^6} \quad (\text{若 } f \text{ 以 MHz 计，则 } \text{MIPS} = \frac{f(\text{MHz})}{\text{CPI}})$$
- **浮点运算能力指标（FLOPS，Floating Point Operations Per Second）**：
  - $\text{MFLOPS} = 10^6\text{ FLOPS}$（百万次/秒）
  - $\text{GFLOPS} = 10^9\text{ FLOPS}$（十亿次/秒）
  - $\text{TFLOPS} = 10^{12}\text{ FLOPS}$（万亿次/秒）
  - $\text{PFLOPS} = 10^{15}\text{ FLOPS}$（千万亿次/秒，超级计算机基准）
  - $\text{EFLOPS} = 10^{18}\text{ FLOPS}$（百亿亿次/秒，百亿亿级超算 Exascale）

#### ② 综合数值计算与 MIPS 评价陷阱手算推演

**【基准程序参数】**：
设某编译生成的程序包含总指令数 $\text{IC}_1 = 10^6$ 条，各类型指令占比与单条周期数如下：
- **ALU 类指令**：占比 $50\%$，$\text{CPI}_{\text{ALU}} = 1$
- **Load/Store 类指令**：占比 $30\%$，$\text{CPI}_{\text{MEM}} = 2$
- **Branch 分支类指令**：占比 $20\%$，$\text{CPI}_{\text{BR}} = 3$
CPU 主频 $f = 2.0\text{ GHz} = 2 \times 10^9\text{ Hz}$。

1. **手算加权平均 $\text{CPI}_1$**：
   $$\text{CPI}_1 = 0.50 \times 1 + 0.30 \times 2 + 0.20 \times 3 = 0.5 + 0.6 + 0.6 = \mathbf{1.7}$$
2. **手算总执行时钟周期数**：
   $$\text{Total Cycles}_1 = \text{IC}_1 \times \text{CPI}_1 = 10^6 \times 1.7 = 1.7 \times 10^6\text{ 周期}$$
3. **手算纯 CPU 执行时间 $T_{\text{CPU1}}$**：
   $$T_{\text{CPU1}} = \frac{1.7 \times 10^6}{2 \times 10^9\text{ Hz}} = 0.85 \times 10^{-3}\text{ s} = \mathbf{0.85\text{ ms}}$$
4. **手算此时的 $\text{MIPS}_1$**：
   $$\text{MIPS}_1 = \frac{f}{\text{CPI}_1 \times 10^6} = \frac{2 \times 10^9}{1.7 \times 10^6} \approx \mathbf{1176.47}$$

**【经典 MIPS 评价陷阱反例（编译器激进优化）】**：
现采用高级编译器优化技术，引入复合寻址与循环展开：
- 大量简单 ALU 指令被复合指令吞并，总指令数锐减到 $\text{IC}_2 = 6 \times 10^5$ 条；
- 但由于简单的 1 周期指令大幅减少，复杂的访存和分支占比大幅上升，导致加权平均 $\text{CPI}_2$ 恶化攀升为 **$2.5$**；
- 此时重新计算指标：
  1. $\text{MIPS}_2 = \frac{2 \times 10^9}{2.5 \times 10^6} = \mathbf{800}$（表面看 MIPS 指标从 1176 暴跌至 800！）；
  2. 实际 CPU 执行时间：
     $$T_{\text{CPU2}} = \frac{\text{IC}_2 \times \text{CPI}_2}{f} = \frac{(6 \times 10^5) \times 2.5}{2 \times 10^9} = \frac{1.5 \times 10^6}{2 \times 10^9} = \mathbf{0.75\text{ ms}}$$
- **结论**：机器实际耗时从 $0.85\text{ ms}$ 缩短到了 **$0.75\text{ ms}$（计算速度实际提升了 $13.3\%$）**，而其 $\text{MIPS}$ 读数却反而缩水了 $32\%$！
  因此，**MIPS 绝对不能作为跨编译器、跨指令架构评判性能的可靠标准**！

## 3. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型（学理解题口径） | 现代工程实现边界（现代芯片与工业测试） |
| :--- | :--- | :--- |
| **主频与功耗** | 假定主频恒定，追求高主频就是追求高性能 | 遭遇半导体物理的**“功耗墙（Power Wall）”**，散热极限将主频锁死在 $4\sim 5\text{GHz}$；全面转向多核并发（Multi-core）与动态睿频调频（DVFS） |
| **性能基准评估** | 依赖 MIPS、MFLOPS 或纯理论时钟周期公式手工运算 | 工业界严禁以纯指令速率为准，全面采用标准化实际工作负载基准：**SPEC CPU 2017**（整数/浮点套件几何平均加权）、**Linpack**（TOP500 超算基准） |
| **IPC 波动性** | 假设特定指令类型的 CPI 固定不变 | 现代超标量乱序执行（如 6 发射架构）使 IPC 动态剧烈浮动，依赖硬件性能计数器（PMU，如 Linux `perf`）采样统计实际运行周期 |

## 4. 跨章节与跨学科关联

### 1. 本学科内跨章节关联
- $\to$ 关联 [CPU 数据通路与指令流水线](../05-cpu/01-cpu-datapath.md)：
  - **共同机制**：流水线吞吐率与加速比计算直接决定了程序稳态的 CPI 水平。
  - **关键差异**：概述章节给出的宏观平均 CPI；流水线章节细化为时钟节拍、数据转发与气泡开销。
  - **不可直接迁移的判据**：5 级流水线吞吐率理论最大提升 5 倍，但受制于冒险停顿，实际综合加速比永远低于理想级数。
- $\to$ 关联 [Cache 替换算法与性能分析](../03-memory-hierarchy/02-cache-mapping.md)：
  - **共同机制**：平均访存时间（AMAT）作为缺失惩罚项，直接通过相加反馈到等效 CPI 方程中。
  - **关键差异**：Cache 章节关注命中率百分比与组相联映射；性能方程关注访存缺失对全程序总耗时的拉低效应。
  - **不可直接迁移的判据**：L1 Cache 命中率提升 1% 带来的 CPI 缩减红利，远大于 L3 Cache 命中率提升 1% 的收益。

### 2. 跨学科协同关联
- $\to$ 关联 [操作系统 / 进程调度与上下文切换](../../03-os/02-process/02-cpu-scheduling.md)：
  - **共同机制**：操作系统的周转时间与计组中的系统响应时间同构，均度量作业从提交到完成的总流逝时间。
  - **关键差异**：计组 $T_{\text{CPU}}$ 剥离了多任务排队等待；操作系统调度算法（如 RR、优先级）直接操控就绪队列排队时延。
  - **不可直接迁移的判据**：提高 CPU 主频能缩短 $T_{\text{CPU}}$，但若瓶颈在磁盘 I/O 阻塞上，提升 CPU 主频对缩短系统总响应时间几乎毫无帮助（阿姆达尔定律 Amdahl's Law）。

## 5. 核心考点自查清单与闭环判据

1. **CPU 执行时间标准方程**：
   $$T_{\text{CPU}} = \frac{\text{IC} \times \text{CPI}}{f} = \text{IC} \times \text{CPI} \times T_{\text{clk}}$$
   - 响应时间包含 I/O 等待，CPU 时间不包含。
2. **四大字长辨析**：
   - 机器字长：ALU 与通用寄存器位宽；
   - 存储字长：MDR 位宽，主存单次并行读写位数；
   - 指令字长：IR 中指令总位数；
   - 数据总线宽度：总线导线根数，可小于等于存储字长。
3. **MIPS 核心陷阱**：
   - $\text{MIPS} = \frac{f}{\text{CPI} \times 10^6}$；
   - 绝不可用于跨 ISA 架构、跨编译器的绝对性能优劣比较。
