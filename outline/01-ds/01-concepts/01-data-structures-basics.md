## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - 数据、数据元素、数据项与数据对象的形式化边界。
  - 数据结构的三要素：逻辑结构、物理（存储）结构、数据的运算。
  - 四大逻辑结构（集合、线性、树形、图形）与四大物理存储结构（顺序、链式、索引、散列）。
  - 数据的运算定义（依赖逻辑结构）与运算实现（依赖物理存储结构）的解耦原理。
  - 存储密度（Storage Density）的计算模型与内存对齐开销。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须将“逻辑结构”与“存储结构”严格解耦？
- **物理困境**：
  - 现实世界的问题关系极其多样：有的一对一（线性排队）、有的一对多（组织层级树）、有的多对多（交通网络拓扑图）。
  - 而计算机体系结构的内存系统在程序视角下是一个由字节编址构成的**一维地址阵列**。
  - 如果算法的设计直接与具体的内存地址紧密绑定，那么任何物理存储布局的变动都会导致上层算法逻辑推倒重写。
- **解耦机制**：
  - **逻辑结构（抽象层）**：只描述数据元素之间的逻辑关系，**独立于计算机硬件和存储介质**。定义了“数据的数学模型是什么”以及“允许对其进行什么样的合法运算（如插入、删除、遍历）”。
  - **存储结构（实现层）**：研究如何把多维、分支或网状的逻辑关系映射到计算机的一维地址空间中。决定了“算法在具体硬件上执行的时空效率”。

### (2) 四大物理存储结构的硬件权衡与内存寻址模型

| 存储结构 | 地址排布特征 | 寻址与访问机制 | 动态增删特性 | 空间开销 (存储密度) |
| :--- | :--- | :--- | :--- | :--- |
| **顺序存储** | 逻辑相邻物理亦相邻（虚拟地址连续） | 支持**随机存取**（通过基址 $+ i \times \text{size}$ 在 $O(1)$ 定位） | 插入删除需搬移后续连续内存块（平均 $\Theta(n)$） | **存储密度最高**（考场理论值为 1，无指针或索引元数据） |
| **链式存储** | 逻辑相邻物理任意（节点地址离散） | 仅支持**顺序存取**（必须沿指针链逐节点遍历） | **持有所需前驱指针时**插入删除为 $O(1)$；若按值/按位序查找则需 $\Theta(n)$ 遍历 | **存储密度 $< 1$**（每个节点需额外承担指针元数据与结构体对齐填充开销） |
| **索引存储** | 主数据区 + 独立索引表 | 先查索引表定位数据块，再在块内定位（如 B+ 树、倒排索引） | 增删数据时必须同步更新/分裂索引表项，开销较高 | **存储密度中等**（索引表本身占用额外存储空间） |
| **散列存储** | 基于哈希函数计算存储槽位 | 根据关键字通过哈希函数直接计算目标槽位地址（期望 $O(1)$） | 需处理哈希冲突（拉链法或开放定址法），装填因子过高需重哈希 | **存储密度受装填因子约束**，需预留空闲槽位以降低冲突概率 |

> [!IMPORTANT]
> **双轨模型边界：顺序存储的“物理连续”真实含义**
> - **408 考场标准模型**：将顺序表（如 C 数组）视作在“连续的物理内存空间”中分配，下标 $i$ 直接通过基址加偏移量计算。
> - **现代操作系统工程实现**：程序中通过 `malloc` 或全局/栈分配的连续数组，**仅保证在虚拟地址空间（Virtual Address Space）中严格连续**。在底层的分页虚存机制下，该数组跨越的多个 4KB 物理页框（Page Frames）在实际 DRAM 物理硬件中完全可能是离散乱序的。但在同一个 4KB 页面内部，物理地址绝对连续，能够充分利用 CPU L1/L2 Cache 的空间局部性预取缓存行（Cache Line，通常 64B）。

### (3) 存储密度公式与考场/工程两轨计算

$$\text{存储密度} = \frac{\text{节点中数据元素本身所占存储量}}{\text{该节点实际所占的总存储量}}$$

以包含一个 32 位整型数据（4 字节）与单链表指针（64 位系统下指针占 8 字节）的单链表节点为例：

1. **408 考场标准模型（忽略 ABI 对齐填充）**：
   - 考场教材默认总存储量为数据大小加指针大小：
     $$\text{存储密度} = \frac{4\text{B}}{4\text{B} + 8\text{B}} = \frac{4}{12} \approx 33.3\%$$
2. **64 位真实 C ABI 布局（结构体边界对齐）**：
   - C 语言结构体定义如下：
     ```c
     struct Node {
         int data;           // 4 字节
         // [4 字节填充 Padding]：因指针需按 8 字节边界对齐
         struct Node *next;  // 8 字节
     };                      // sizeof(struct Node) == 16 字节
     ```
   - 实际内存占用中，`int` 之后被编译器插入 4 字节填充字节以满足 8 字节对齐，实际节点占用 16 字节：
     $$\text{真实有效负载密度} = \frac{4\text{B}}{16\text{B}} = 25.0\%$$
   - 结论：在现代 64 位体系结构下，单链表存储简单基础类型时，高达 75% 的物理堆内存被指针与对齐填充消耗。

### (4) 状态执行轨迹：4 元素线性表 `(A, B, C, D)` 的双结构映射对比

假设数据元素为 4 字节整数 `A=10, B=20, C=30, D=40`。

#### 1. 顺序表存储映射（虚拟地址基址 `0x1000`）
```
虚拟地址:  0x1000       0x1004       0x1008       0x100C
物理内容: [ 10 (A) ]   [ 20 (B) ]   [ 30 (C) ]   [ 40 (D) ]
下标索引:    arr[0]       arr[1]       arr[2]       arr[3]
```
- **访问 `C`**：执行 `*(arr + 2)` $\to$ 基址 `0x1000 + 2 * 4 = 0x1008`，硬件乘加器 1 个周期完成地址计算，属于 $O(1)$ 随机存取。
- **在 `B` 和 `C` 之间插入 `X`**：必须将 `0x100C`（D）搬至 `0x1010`，将 `0x1008`（C）搬至 `0x100C`，腾出 `0x1008` 写入 `X`，耗费数据搬迁时间。

#### 2. 单链表存储映射（离散堆地址分配，头指针 `head = 0x2040`）
```
节点地址   | 数据域 (data) | 指针域 (next) | 逻辑角色
----------+--------------+---------------+---------
0x2040    | 10 (A)       | 0x1080        | 首节点 (A)
0x1080    | 20 (B)       | 0x3010        | 第二节点 (B)
0x3010    | 30 (C)       | 0x1500        | 第三节点 (C)
0x1500    | 40 (D)       | NULL          | 尾节点 (D)
```
- **访问 `C`**：无法通过公式计算。必须从 `head (0x2040)` 出发，解引用读出 `0x1080`，再解引用读出 `0x3010`，经历 2 次指针解引用寻道，耗费 $\Theta(n)$ 顺序存取。
- **在 `B` 和 `C` 之间插入 `X`（位于 `0x4000`）**：
  - **前置条件必须严格满足**：**已持有指向 `B` 的指针 `p_B = 0x1080`**。
  - 仅需修改指针：`node_X->next = p_B->next (0x3010)`，`p_B->next = 0x4000`。两步赋值仅耗费 $O(1)$，无需搬动 `C` 与 `D` 的物理内存。
  - **常见认知陷阱**：若未持有前驱指针，仅给出“在第 3 个位置插入”或“在值为 20 的节点后插入”，定位该前驱节点本身仍需耗费 $\Theta(n)$ 的时间遍历链表。

│  - 二叉树顺序存储 (堆) vs 孩子链表     │  │  - 文件分配: 连续分配/显式链接FAT/索引inode│
│  - 图: 邻接矩阵 (顺序) vs 邻接表 (链式) │  │  - 栈溢出: 固定数组上溢 vs 堆耗尽 OOM    │
└──────────────────────────────────────┘  └──────────────────────────────────────┘

1. **与线性表、树、图的内部映射对照**：
   - [顺序表](../02-linear-list/01-sequential-list.md) 与 [链表](../02-linear-list/02-linked-list.md)：展示了同一线性逻辑结构在连续与链式存储下的极端性能分水岭。
   - [树与二叉树性质](../04-tree/01-binary-tree-properties.md)：完全二叉树可以无缝使用顺序数组按下标倍增公式存储；而一般树和森林必须依赖[孩子兄弟表示法](../04-tree/04-forest-conversion.md)（二叉链表）进行离散存储。
2. **与操作系统文件物理分配方式的同构性**：
   - 数据结构中的“顺序、链式、索引”三大存储结构，与操作系统中[文件结构与索引节点](../../03-os/04-file/01-file-concepts-and-inode.md)在磁盘上的三大物理分配方式（连续分配、隐式/显式链接分配、多级索引分配）在设计机理上完全同构。
3. **运算定义与物理实现的边界：溢出（Overflow）的真实机理**：
   - 考场常称“链栈/链队列绝不会发生上溢”：这一论断建立在**教科书简化抽象模型**之上，假定操作系统堆空间无限。
   - **工程真实情况**：顺序栈由于预分配了固定长度的连续数组，当 `top == MAXSIZE - 1` 时触发**数组容量上溢**；而链栈每次入栈调用 `malloc()` 向操作系统申请堆内存，当宿主机物理内存与 Swap 分区被耗尽、或进程虚拟地址空间耗尽时，`malloc()` 将返回 `NULL`，若未判空会引发段错误，或被操作系统的 OOM Killer 强制终止。

## 4. 闭环决策模型与核心认知结论

### (1) 逻辑结构 vs 物理结构 严谨分类定性表

| 概念名称 | 所属分类 | 物理依据与鉴别核心 |
| :--- | :--- | :--- |
| **线性表、栈、队列、双端队列** | **逻辑结构** | 描述元素间一对一的前驱后继关系，与具体物理存储方式无关。 |
| **树、二叉树、森林** | **逻辑结构** | 描述一对多的分层分支关系。 |
| **图、有向图、无向图** | **逻辑结构** | 描述多对多的网状关系。 |
| **顺序表、顺序栈、循环队列** | **物理存储结构** | 明确指定了采用**一维虚拟连续内存**实现。 |
| **单链表、双向链表、静态链表** | **物理存储结构** | 明确指定了采用**指针或数组游标链式寻址**实现。 |
| **哈希表（散列表）** | **物理存储结构** | 明确指定了通过关键字计算存储槽位地址。 |

### (2) 考场定性闭环判据
1. **名称形态判定法**：
   - 概念名称带有“顺序”、“单链”、“双向链”、“循环链”、“散列/哈希”、“静态链表” $\to$ **必为物理（存储）结构**。
   - 概念名称仅描述元素间的组织关系或特征（如“有序表”、“集合”、“树”、“有向无环图”） $\to$ **必为逻辑结构**。
   - **关键混淆辨析**：“有序表”是逻辑结构（指元素按关键字单调排列），而“顺序表”是存储结构（指地址连续）。有序表既可以用顺序表实现，也可以用单链表实现。
2. **算法性能决定因素判据**：
   - 算法的执行时间复杂度由**逻辑算法本身的控制流程**与**底层选用的物理存储结构**共同决定。相同的逻辑操作在不同物理存储结构下时间复杂度差异显著（例如有序表折半查找在顺序表上为 $O(\log n)$，而在单链表上因无法随机存取退化为 $O(n)$）。
