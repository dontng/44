## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - 数据、数据元素、数据项与数据对象的形式化边界。
  - 数据结构的三要素：逻辑结构、物理（存储）结构、数据的运算。
  - 四大逻辑结构（集合、线性、树形、图形）与四大物理存储结构（顺序、链式、索引、散列）。
  - 数据的运算定义（依赖逻辑结构）与运算实现（依赖物理存储结构）的解耦原理。
  - 存储密度（Storage Density）的物理定义与空间利用率开销。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须将“逻辑结构”与“存储结构”严格解耦？
- **物理困境**：
  - 物理内存（DRAM）在硬件层面只是一个由字节编址构成的**一维线性地址阵列**。
  - 现实世界的问题关系极其多样：有的一对一（线性排队）、有的一对多（组织层级树）、有的多对多（社交拓扑图）。
  - 如果算法的设计直接与一维内存物理地址紧密绑定，那么任何存储形式的变动都会导致算法逻辑全部重写。
- **解耦机制**：
  - **逻辑结构（抽象层）**：只描述数据元素之间的逻辑关系，**独立于计算机硬件和内存**。定义了“数据的数学模型是什么”以及“允许对其进行什么样的合法运算（如插入、删除、遍历）”。
  - **存储结构（实现层）**：研究如何把多维、网状的逻辑关系映射到计算机的一维连续物理地址空间中。决定了“算法在具体硬件上执行的时空效率”。

---

### (2) 四大存储结构的硬件权衡（Trade-off）

| 存储结构 | 物理地址排布 | 寻址与访问机制 | 动态增删特性 | 空间开销 (存储密度) |
| :--- | :--- | :--- | :--- | :--- |
| **顺序存储** | 连续物理内存 | 支持**随机存取**（通过基址 + $i \times \text{size}$ 在 $O(1)$ 寻址） | 插入删除需挪移整块内存（$O(n)$），容量扩展困难 | **存储密度为 1**（无额外指针或索引开销，空间效率最高） |
| **链式存储** | 离散物理内存 | 仅支持**顺序存取**（必须沿指针链逐节点遍历寻址） | 插入删除只需修改指针（$O(1)$），天然支持动态扩容 | **存储密度 $< 1$**（每个节点需额外付出 4B 或 8B 的指针域开销） |
| **索引存储** | 建立额外索引表 | 通过索引表快速定位数据块（如 B 树、倒排索引） | 增删数据时必须同步维护索引表项，开销较高 | **存储密度中等**（索引表本身占用额外存储空间） |
| **散列存储** | 基于哈希函数计算物理地址 | 根据关键字直接计算目标物理地址（期望 $O(1)$） | 需设计冲突处理机制（开放定址法或拉链法） | **存储密度取决于装填因子**，需预留空闲插槽以降低冲突概率 |

### (3) 存储密度公式与工程意义
$$\text{存储密度} = \frac{\text{节点中数据元素本身所占存储量}}{\text{该节点实际所占的总存储量}}$$

- 顺序存储结构中，节点内仅包含数据元素本身，无任何额外结构开销，其存储密度恒等于 **1**。
- 链式存储结构中，若每个节点存储一个 4 字节的整型变量，在 64 位操作系统下指针占用 8 字节，则：
  $$\text{存储密度} = \frac{4\text{B}}{4\text{B} + 8\text{B}} = 33.3\%$$
  此时三分之二的物理内存被指针元数据侵占。

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 数据结构: 逻辑与物理存储解耦   │
                     └──────────────┬───────────────┘
                                    │ 决定具体数据类型的实现
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 数据结构: 线性表 / 栈 / 队列  │         │ 操作系统: 物理页框与文件分配  │
│  - 顺序表 vs 链表 (离散 vs 连续)│ ◄────── │  - 连续分配 (顺序)          │
│  - 循环队列 (顺序取模映射)   │         │  - 链式分配 / 索引分配 (inode)│
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与操作系统文件物理分配方式的同构性**：
   - 数据结构中的“顺序、链式、索引”三大存储结构，与操作系统中文件在磁盘上的三大物理分配方式（连续分配、隐式/显式链接分配、多级索引分配）在设计机理上完全同构。
2. **运算定义与运算实现的绝对边界**：
   - 在栈的逻辑定义中，“入栈（Push）和出栈（Pop）在栈顶进行且遵循 LIFO 规则”是**运算的逻辑定义**。
   - 而“栈顶指针 `top` 递增或递减、是否会发生上溢（Overflow）”则是**顺序栈在物理存储实现上的具体细节**；若换成链栈实现，则根本不会发生上溢。

## 4. 闭环决策模型与核心认知结论

### (1) 逻辑结构 vs 物理结构 严谨分类定性表

| 概念名称 | 所属分类 | 物理依据与鉴别核心 |
| :--- | :--- | :--- |
| **线性表、栈、队列、双端队列** | **逻辑结构** | 描述元素间一对一的前驱后继关系，不管内存怎么存。 |
| **树、二叉树、森林** | **逻辑结构** | 描述一对多的层次结构。 |
| **图、有向图、无向图** | **逻辑结构** | 描述多对多的网状关系。 |
| **顺序表、顺序栈、循环队列** | **物理存储结构** | 明确指定了采用**顺序连续内存**实现。 |
| **单链表、双向链表、静态链表** | **物理存储结构** | 明确指定了采用**指针/数组游标链式存储**实现。 |
| **哈希表（散列表）** | **物理存储结构** | 明确指定了通过关键字计算存储物理地址。 |

### (2) 考场定性闭环判据
1. **只要概念名称带有“顺序”、“单链”、“双向链”、“循环链”、“散列/哈希”** $\to$ 必定属于**存储（物理）结构**。
2. **只要概念名称仅描述元素组织规则（如“有序表”、“集合”、“有向无环图”）** $\to$ 必定属于**逻辑结构**。
   - 特别注意：“有序表”是逻辑结构（指元素按关键字递增或递减排列），而“顺序表”是存储结构（指物理内存地址连续）。
3. **算法的效率由什么决定？** $\to$ 依赖于算法本身的设计逻辑以及所选用的**物理存储结构**。相同的逻辑结构在不同存储结构下，算法复杂度天差地别（如顺序查找 $O(n)$ 与哈希查找 $O(1)$）。
