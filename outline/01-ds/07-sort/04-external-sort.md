## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 外部排序的物理瓶颈与总耗时方程式

#### 物理困境
当待排序数据量极其庞大（例如 200GB），而计算机的物理主存容量有限（例如 8GB）时，无法将所有数据一次性全部装入内存进行内部排序。必须借助于外存（机械硬盘或 SSD）进行分批排序与逐步归并。

#### 外部排序耗时模型
$$\text{外部排序总耗时} = \text{内部生成初始段耗时} + \mathbf{外存 I/O 读写时间 (占 99\% 以上)} + \text{内部归并比较耗时}$$
- 磁盘由于机械寻道与旋转延迟（或 SSD 的块擦除与总线传输），其读写速度比内存慢数千至数万倍；
- **核心优化唯一法则**：**减少外部排序总耗时的根本手段，就是尽可能减少磁盘数据块的读写总次数**！

---

### (2) 归并趟数公式与两大优化主线

外部排序标准流程分为两阶段：
1. **第一阶段**：将大文件切片读入内存，采用某种内部排序方法生成 $r$ 个内部有序的文件片段，写回外存，称为**初始归并段（Initial Runs）**。
2. **第二阶段**：对这 $r$ 个初始归并段执行 $k$ 路归并，逐层合并，直到最终合并为 1 个完整的全局有序文件。

#### 归并趟数方程
设初始归并段数为 $r$，采用 $k$ 路平衡归并，则总归并趟数 $S$ 严格为：
$$S = \lceil \log_k r \rceil$$
- **物理 I/O 成本**：在每一趟归并中，文件中的每一个数据块都必须**从外存读入内存 1 次，并在归并后写回外存 1 次**（每块产生 2 次 I/O）。若文件总块数为 $N_{\text{block}}$，则每增加一趟归并，外存 I/O 次数就增加 $2 \times N_{\text{block}}$。
- **两大优化破局主线**：
  - **主线 A：增大归并路数 $k$** $\implies$ 以对数底数加速压缩归并趟数 $S$；
  - **主线 B：减少初始归并段数 $r$** $\implies$ 设法使生成的初始归并段突破内存容量限制，变得更长。

### (3) 主线 A：$k$ 路归并、败者树与内存缓冲区约束

#### 1. 内存缓冲区分配约束：单缓冲 vs 并行双缓冲
要进行 $k$ 路平衡归并，内存中必须划分出专用缓冲区来周转数据：
- **方案 A：基础单缓冲配置（$k + 1$ 个缓冲区）**
  - **输入缓冲区**：为参与归并的 $k$ 个归并段各分配 1 个大小为 1 个物理块的输入缓冲区，共 $k$ 个；
  - **输出缓冲区**：分配 1 个大小为 1 块的输出缓冲区，用于暂存已归并排好的数据，写满一块即刷盘；
  - **内存块数硬性约束**：若系统可用内存块数为 $B$，则最大归并路数受限于：
    $$k \le B - 1$$
- **方案 B：并行双缓冲配置（$2k + 2$ 个缓冲区）**
  - 为了彻底实现 **磁盘 I/O 传输与 CPU 内部归并计算的时间重叠（Overlap）**，必须引入双缓冲机制；
  - 每个输入通道分配 2 个缓冲区（一个供 CPU 读取归并，另一个由 DMA 控制器后台异步从磁盘预读下一块）；输出通道同样配备 2 个缓冲区；
  - **双缓冲内存约束**：
    $$k \le \left\lfloor \frac{B - 2}{2} \right\rfloor$$

#### 2. 败者树（Loser Tree）的微架构机理
- **增大 $k$ 的新矛盾**：若单纯将 $k$ 增大到 16 或 32，在内存中从 $k$ 个输入段首元素中挑选最小者，若采用朴素线性比较，每输出一个元素需要执行 $k - 1$ 次比较。内部归并比较次数将呈 $O(k)$ 线性激增，抵消 I/O 收益。
- **败者树拓扑设计**：
  - 败者树是一棵完全二叉树。设 $k$ 个归并段的当前记录存放在叶子节点 `b[0 .. k-1]` 中；
  - 设置 $k - 1$ 个内部节点 `ls[1 .. k-1]`：**每个内部节点记录该子树比赛的“失败者（较大者）的段号”**；
  - **额外头节点 `ls[0]`**：专门用于**存放最终全局比赛的胜利者（绝对冠军，即最小者）的段号**！

```
5 路败者树拓扑示例 (当前 5 个段的首元素: b[0]=10, b[1]=15, b[2]=12, b[3]=6, b[4]=20):

             [ ls[0] = 3 ]  <-- 记录全局总冠军 (b[3]=6 获胜)
                   │
             [ ls[1] = 0 ]  <-- 树顶内部节点 (记录败者段号 0, 权值 10)
            /             \
      [ ls[2] = 2 ]     [ ls[3] = 4 ]
      /           \           │
  [ ls[4] = 1 ]  b[2]=12    b[4]=20
   /         \
 b[0]=10   b[1]=15       b[3]=6 (来自段 3)
```

#### 3. 元素重构比对全追踪（仅需 $\lceil \log_2 k \rceil$ 次比较）
设当前冠军 `b[3]=6` 输出到输出缓冲区后，从段 3 读入下一个新元素 `18` 填入 `b[3]`：
1. **启动向上单链筛选**：新元素 `b[3]=18` 沿着通往树根的固定父节点路径向上攀升；
2. **第一步（攀升至 `ls[3]`）**：
   - 当前父节点 `ls[3]` 记录的败者是段 4（`b[4]=20`）；
   - 比较 `b[3]=18` 与 `b[ls[3]]=20`：$18 < 20$，`18` 胜出！段 4（`b[4]`）依然是败者，`ls[3] = 4` 保持不变；
3. **第二步（攀升至 `ls[1]`）**：
   - 树顶节点 `ls[1]` 记录的败者是段 0（`b[0]=10`）；
   - 比较当前的晋级胜者 `b[3]=18` 与 `b[ls[1]]=10`：$18 > 10$，**`18` 败下阵来！**
   - **败者就地留下**：将 `ls[1]` 的败者更新为段 3（即 `ls[1] = 3`）；
   - **胜者继续晋级**：段 0（`b[0]=10`）作为新胜者晋升到树顶；
4. **第三步（更新全局冠军 `ls[0]`）**：
   - 段 0 无其他对手，直接写入全局冠军节点：`ls[0] = 0`。
- **单步性能验证**：从叶子攀升到根，整棵树高度为 $\lceil \log_2 5 \rceil = 3$ 层，整个重构过程**仅执行了 2 次关键码比较**！

### (4) 主线 B：置换-选择排序（打破内存容量限制）

#### 为什么传统内部排序生成的归并段太短？
若内存工作区可容纳 $M$ 个记录，使用快速排序或堆排序，每次只能把内存填满排序后写出，因此**每个初始归并段的长度死板地受限于内存容量 $M$**。总段数为 $r = \lceil N / M \rceil$。

#### 置换-选择排序的“水流传送带”机理
在内存工作区维护一个大小为 $M$ 的候选区数组 `WA[0 .. M-1]`，按最小堆/选择树组织。
- **核心操作状态流**：
  1. 设定当前归并段的最近输出极值 `MINIMAX`；
  2. 选出当前候选区中大于等于 `MINIMAX` 的最小元素输出，更新 `MINIMAX`；
  3. 从输入流读入新记录 $X$ 填补空位：
     - **若 $X \ge \text{MINIMAX}$**：说明 $X$ 的数值大于等于刚刚输出的值，**能够追加在当前归并段后方**，标记为**活跃状态（Active）**；
     - **若 $X < \text{MINIMAX}$**：$X$ 若放入当前段将破坏单调递增性，**必须将其标记为冻结状态（`*`）**，退出当前段的竞争；
  4. 重复上述操作，直至工作区内所有 $M$ 个元素**全部被冻结**。此时当前初始归并段结束！
  5. **解冻全部元素**，重置 `MINIMAX = -\infty`，开启下一个初始归并段。

#### 完整单步执行轨迹追踪
- **工作区容量**：$M = 3$；
- **输入数据流**：`[17, 21, 05, 44, 10, 12, 03, 56]`；
- **执行过程详细追踪表**：

| 步骤 | 内存工作区 `WA` 状态（带 `*` 为冻结） | 当前选出的最小有效元素 | 动作与输出 | 新读入的记录与判定 | 当前段输出累积结果 |
| :---: | :--- | :---: | :--- | :--- | :--- |
| **初始** | 装满前 3 个数: `[17, 21, 05]` | `05` | 输出 `05`, `MINIMAX = 05` | 读入 `44` $\ge 05$ (活跃) | **段 1**: `[05]` |
| **1** | `[17, 21, 44]` (全活跃) | `17` | 输出 `17`, `MINIMAX = 17` | 读入 `10` $< 17$ (**冻结 `10*`**) | **段 1**: `[05, 17]` |
| **2** | `[10*, 21, 44]` (10 冻结) | `21` | 输出 `21`, `MINIMAX = 21` | 读入 `12` $< 21$ (**冻结 `12*`**) | **段 1**: `[05, 17, 21]` |
| **3** | `[10*, 12*, 44]` (仅 44 活跃) | `44` | 输出 `44`, `MINIMAX = 44` | 读入 `03` $< 44$ (**冻结 `03*`**) | **段 1**: `[05, 17, 21, 44]` |
| **4** | `[10*, 12*, 03*]` (**全被冻结!**) | - | **段 1 强制结束！全员解冻！** | 重置 `MINIMAX = -\infty` | **段 1 完工 (长度 4)** |
| **5** | 开启段 2: `[10, 12, 03]` (全解冻) | `03` | 输出 `03`, `MINIMAX = 03` | 读入 `56` $\ge 03$ (活跃) | **段 2**: `[03]` |
| **6** | `[10, 12, 56]` (全活跃) | `10` | 输出 `10`, `MINIMAX = 10` | 输入流耗尽 | **段 2**: `[03, 10]` |
| **7** | `[12, 56]` | `12` | 输出 `12`, `MINIMAX = 12` | - | **段 2**: `[03, 10, 12]` |
| **8** | `[56]` | `56` | 输出 `56` | 工作区清空 | **段 2 完工 (长度 4)** |

- **结果验证**：
  - 传统内排：$N=8, M=3 \implies \lceil 8 / 3 \rceil = 3$ 个初始段；
  - 置换-选择排序：仅生成了 **2 个初始段**（段 1 为 `[05, 17, 21, 44]`，段 2 为 `[03, 10, 12, 56]`），每个段的长度均达到了 4（大于内存容量 $M=3$）。
- **数学期望性质**：在输入随机分布时，置换-选择排序生成的初始归并段**平均期望长度严格为 $2M$**。
  - *最好情况*（输入已正序）：仅生成 1 个长度为 $N$ 的完整归并段！
  - *最坏情况*（输入完全逆序）：每个元素读入即被冻结，段长退化为 $M$。

### (5) 最佳归并树与虚段（$k$ 叉哈夫曼树）

当生成的各个初始归并段长度不同时，为了使第二阶段总的外存 I/O 读写量最小，必须构建 **$k$ 叉哈夫曼树**，以各段的物理块数作为叶子权值。

#### 1. 虚段（Dummy Run）补充严密公式
$k$ 叉哈夫曼树要求所有分支节点必须严格拥有 $k$ 个孩子，每轮合并净减少 $k - 1$ 个根。
设初始段总数为 $n_0$，归并路数为 $k$。计算模余：
$$rem = (n_0 - 1) \bmod (k - 1)$$
**需补充权值为 0 的虚段数量 $u$ 严格分为两分支**：
$$u = \begin{cases} 0, & \text{若 } (n_0 - 1) \bmod (k - 1) == 0 \\ (k - 1) - \big( (n_0 - 1) \bmod (k - 1) \big), & \text{若 } (n_0 - 1) \bmod (k - 1) \neq 0 \end{cases}$$

#### 2. 外存 I/O 读写总次数完整算例推导
- **题设条件**：
  某文件经置换-选择排序生成了 **5 个初始归并段**，其长度（所占物理块数）分别为：
  $$\{2, \; 3, \; 6, \; 9, \; 12\} \quad (\text{总块数 } N_{\text{block}} = 2 + 3 + 6 + 9 + 12 = 32 \text{ 块})$$
  采用 **$k = 3$ 路平衡归并**进行外部排序。计算最佳归并树拓扑、虚段数及全流程磁盘 I/O 总次数。

##### 第一步：虚段检验
- $n_0 = 5, k = 3$；
- $rem = (5 - 1) \bmod (3 - 1) = 4 \bmod 2 = \mathbf{0}$；
- 因为 $rem == 0$，**无需补充任何虚段（$u = 0$）**！

##### 第二步：构建 3 叉最佳归并树
1. 挑选 3 个最小权值 `{2, 3, 6}` 合并，生成中间节点 `(11)`；
2. 候选集变为：`{(11), 9, 12}`；
3. 刚好剩下 3 个节点，全部合并，生成最终根节点 `(32)`。

```
3 叉最佳归并树拓扑:
              [ 32 ] (根)
             /   |   \
           [11]  9    12    (9 与 12 处于深度 1)
          / |  \
         2  3   6           (2, 3, 6 处于深度 2)
```

##### 第三步：带权路径长度 WPL 与总 I/O 计算
- **方法 A（定义式计算 WPL）**：
  $$\text{WPL} = (2 \times 2) + (3 \times 2) + (6 \times 2) + (9 \times 1) + (12 \times 1) = 4 + 6 + 12 + 9 + 12 = \mathbf{43}$$
- **方法 B（非叶节点累加法）**：
  $$\text{WPL} = 11 + 32 = \mathbf{43}$$
- **全流程磁盘 I/O 读写总次数精确推导**：
  1. **初始段生成阶段**：每个数据块读入内存 1 次、写回外存 1 次：
     $$\text{I/O}_{\text{init}} = 2 \times N_{\text{block}} = 2 \times 32 = \mathbf{64} \text{ 次}$$
  2. **归并阶段**：处于深度 $d$ 的归并段中的每一个数据块，在整个多趟归并中必须被读 $d$ 次、写 $d$ 次（每块经历 $2d$ 次 I/O）。因此归并阶段总 I/O 严格等于：
     $$\text{I/O}_{\text{merge}} = 2 \times \text{WPL} = 2 \times 43 = \mathbf{86} \text{ 次}$$
  3. **全流程总 I/O 读写次数**：
     $$\text{I/O}_{\text{total}} = \text{I/O}_{\text{init}} + \text{I/O}_{\text{merge}} = 64 + 86 = \mathbf{150} \text{ 次}$$

## 3. 本学科内跨章节关联与跨学科协同关联

### 1. 本学科内跨章节关联

#### (1) 与哈夫曼树（最优二叉树）的理论同构
- **共同机制**：基于贪心思想构建带权路径长度最小的多叉拓扑。
- **关键差异**：普通哈夫曼树是二叉的，用于报文前缀编码；最佳归并树是 $k$ 叉的，用于外存数据块调度，且必须在整除不成立时补充虚拟段。
- **不可直接迁移的判据**：普通哈夫曼树的叶子权值是字符频数，最佳归并树的叶子权值是归并段占用的物理块数，二者度量单位不同。

#### (2) 与优先队列堆调整的算法复用
- **共同机制**：维护动态极值序列。
- **关键差异**：置换-选择排序在堆顶元素小于 `MINIMAX` 时并不将其从数组物理删除，而是打上冻结标记并缩小活动堆规模，直到全员冻结后批量复苏。
- **不可直接迁移的判据**：普通堆排序每次交换破坏了原元素，置换-选择排序通过流水线持续吞入新数据，动态输出流式有序序列。

### 2. 跨学科协同关联

#### (1) 操作系统：磁盘调度算法与块缓冲管理
- **共同机制**：平滑机械外存与高速 CPU 之间的速度鸿沟。
- **关键差异**：
  - 操作系统侧重单次 I/O 的磁头寻道优化（SSTF, SCAN, C-SCAN）；
  - 外部排序侧重大规模批处理的流式顺序读写（Sequential I/O），尽量使一次 I/O 连续读写多个簇或扇区，避开随机寻道。
- **不可直接迁移的判据**：即便采用了最佳归并树，如果磁盘碎片严重导致连续块被打散，外部排序的物理耗时依然会因为频繁随机寻道而急剧恶化。

## 4. 闭环决策模型与核心认知结论

### (1) 最佳归并树虚段速算决策模型

```
输入: 初始段数 n0, 归并路数 k
第一步: 计算模余 rem = (n0 - 1) % (k - 1)
第二步: 分支判定
  ├─ 若 rem == 0:
  │    无需补虚段，虚段数 u = 0！
  │
  └─ 若 rem != 0:
       虚段数 u = (k - 1) - rem！
       补齐 u 个权值为 0 的虚段，作为叶子优先参与第一轮最小归并！
```

### (2) 考场定性闭环判据
1. **外部排序全流程 I/O 读写总次数**：
   $$\text{总 I/O} = \mathbf{2 \times \text{总块数}} \text{ (生成初始段)} + \mathbf{2 \times \text{WPL}} \text{ (归并阶段)}$$
2. **败者树与胜者树相比的决定性优势**：
   - 重构时新节点**仅需沿着父指针单链向上与记录的败者比较 1 次**（无需访问兄弟节点），单次调整总比较次数严格为 **$\lceil \log_2 k \rceil$**。
3. **置换-选择排序的段长**：
   - 随机输入下，初始归并段的平均长度等于内存工作区容量的 **2 倍（$2M$）**。
