## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 排序算法的“稳定性”物理本质
- **定义**：
  若待排序记录序列中存在多个关键字相等的记录（即 $K_i = K_j$ 且排序前在原序列中下标满足 $i < j$）。**若在排序后的输出序列中，$i$ 对应的记录依然严格排在 $j$ 对应的记录之前**，则称该排序算法是**稳定（Stable）的**；反之，若可能发生相对前后次序颠倒，则称该排序算法是**不稳定（Unstable）的**。
- **物理工程价值**：
  在多关键字复合排序中（例如电商订单中“先按成交金额次关键字排序，再按下单时间主关键字排序”），若第二轮排序算法不稳定，会将第一轮已排好的同时间订单金额相对次序全盘打乱，导致前序运算结果彻底失效。

### (2) 五大简单排序算法深度横向对比（解耦比较与移动）

许多学习者往往将“时间复杂度”笼统记为单一的 $O(n^2)$，从而在考场面对“最好情况下折半插入排序与直接插入排序比较次数谁更优”等高鉴别度考题时出现失误。必须将**关键字比较次数**与**记录物理移动次数**彻底解耦分析：

| 排序算法 | 最好比较 | 最坏比较 | 最好移动 | 最坏移动 | 最好总时间 | 平均总时间 | 最坏总时间 | 辅助空间 | 稳定性 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **直接插入排序** | $n - 1 \implies \Theta(n)$ | $\frac{n(n-1)}{2} \implies \Theta(n^2)$ | $0 \implies \Theta(1)$ | $\approx \frac{n^2}{2} \implies \Theta(n^2)$ | **$\Theta(n)$** | $\Theta(n^2)$ | $\Theta(n^2)$ | $O(1)$ | **稳定** |
| **折半插入排序** | $\approx n\log_2 n \implies \Theta(n\log n)$ | $\approx n\log_2 n \implies \Theta(n\log n)$ | $0 \implies \Theta(1)$ | $\approx \frac{n^2}{2} \implies \Theta(n^2)$ | **$\Theta(n\log n)$** | $\Theta(n^2)$ | $\Theta(n^2)$ | $O(1)$ | **稳定** |
| **冒泡排序 (带Flag)** | $n - 1 \implies \Theta(n)$ | $\frac{n(n-1)}{2} \implies \Theta(n^2)$ | $0 \implies \Theta(1)$ | $3 \times \frac{n(n-1)}{2} \implies \Theta(n^2)$ | **$\Theta(n)$** | $\Theta(n^2)$ | $\Theta(n^2)$ | $O(1)$ | **稳定** |
| **简单选择排序** | $\frac{n(n-1)}{2} \implies \Theta(n^2)$ | $\frac{n(n-1)}{2} \implies \Theta(n^2)$ | $0 \implies \Theta(1)$ | $3(n - 1) \implies \Theta(n)$ | **$\Theta(n^2)$** | $\Theta(n^2)$ | $\Theta(n^2)$ | $O(1)$ | **不稳定** |
| **比较计数排序** | $\frac{n(n-1)}{2} \implies \Theta(n^2)$ | $\frac{n(n-1)}{2} \implies \Theta(n^2)$ | $n \implies \Theta(n)$ | $n \implies \Theta(n)$ | **$\Theta(n^2)$** | $\Theta(n^2)$ | $\Theta(n^2)$ | $O(n)$ | **稳定** |

> [!IMPORTANT]
> **核心认知突破：折半插入排序最好情况时间复杂度是 $\Theta(n\log n)$ 而非 $O(n^2)$！**
> - **比较次数必然性**：折半插入排序在处理第 $i$ 个元素时，总是对前 $i$ 个已排序元素进行折半二分查找。每次查找必做 $\approx \lceil \log_2(i+1) \rceil$ 次比较，处理完整个数组共进行 $\sum_{i=1}^{n-1} \log_2 i \approx n\log_2 n - 1.44n$ 次比较。无论输入初始序列是否有序，**比较次数恒为 $\Theta(n\log n)$**。
> - **移动次数必然性**：当输入序列**原本即为升序（最好情况）**时，折半查找返回的插入点索引 `low` 恰好等于当前位置 $i$。后续的元素搬迁循环 `for (j = i - 1; j >= low; j--) A[j+1] = A[j];` 条件直接不满足，**执行 0 次移动**！
> - **总时间复杂度**：最好情况下总耗时为 $\Theta(n\log n) \text{ (比较)} + 0 \text{ (移动)} = \Theta(n\log n)$。

### (3) 简单选择排序不稳定的经典反例验证
- **待排序输入**：包含相同关键字的 3 元素序列 `[ 2(a), 2(b), 1 ]`（其中 `2(a)` 下标为 0，`2(b)` 下标为 1，`1` 下标为 2）。
- **执行追踪**：
  1. 第 1 趟扫描：在未排序区 `[0..2]` 中寻找最小值，发现最小值为位于下标 2 的 `1`。
  2. 物理交换：将最小值 `1` 与未排序区第 1 个元素（即下标 0 的 `2(a)`）交换。
  3. 交换后状态：序列变为 `[ 1, 2(b), 2(a) ]`。
- **证伪结论**：原本排在前面的 `2(a)` 被直接扔到了 `2(b)` 之后，同值元素相对先后顺序被破坏，**证明简单选择排序属于不稳定排序**。

### (4) 比较计数排序（Counting Rank Sort）机制与执行轨迹

- **设计思路**：不进行相邻元素交换或多轮数据搬迁，而是统计“全序列中有多少个元素严格小于我”，所得计数值即为最终输出数组中的唯一目标下标。
- **无重复成对比较的严谨循环设计**：
  若采用两层完全循环遍历所有 $(i, j)$，会导致同一对元素被比较两次，且相等元素若处理不当会导致写入同一目标插槽。严格正确的双重循环应只遍历上三角有序数对（共 $\frac{n(n-1)}{2}$ 次比较），并在相等时以初始下标较小者优先：

```c
void counting_rank_sort(int A[], int B[], int n) {
    int count[n];
    for (int i = 0; i < n; i++) count[i] = 0;

    // 每对数 (i, j) 仅比对 1 次，无重复比较
    for (int i = 0; i < n - 1; i++) {
        for (int j = i + 1; j < n; j++) {
            if (A[i] < A[j]) {
                count[j]++;  // A[j] 大于 A[i]，A[j] 排名后移
            } else if (A[i] > A[j]) {
                count[i]++;  // A[i] 大于 A[j]，A[i] 排名后移
            } else {
                // A[i] == A[j]：由于 i < j，A[i] 在原表中先出现
                // 为保证排序稳定性，将后出现的 A[j] 计为更大，确保其排在 A[i] 后面
                count[j]++;
            }
        }
    }

    // 根据计数值将元素直接投递到目标有序数组 B 中
    for (int i = 0; i < n; i++) {
        B[count[i]] = A[i];
    }
}
```

#### 4 元素含重复值执行轨迹：`A = [25, 12, 25', 8]`

- **初始状态**：`count = [0, 0, 0, 0]`，待比较数对共 $\frac{4 \times 3}{2} = 6$ 组：
  1. $i=0, j=1$：比对 $A[0]=25$ 与 $A[1]=12 \implies 25 > 12 \implies count[0]++ \to [1, 0, 0, 0]$
  2. $i=0, j=2$：比对 $A[0]=25$ 与 $A[2]=25' \implies 25 == 25' \implies count[2]++ \to [1, 0, 1, 0]$
  3. $i=0, j=3$：比对 $A[0]=25$ 与 $A[3]=8 \implies 25 > 8 \implies count[0]++ \to [2, 0, 1, 0]$
  4. $i=1, j=2$：比对 $A[1]=12$ 与 $A[2]=25' \implies 12 < 25' \implies count[2]++ \to [2, 0, 2, 0]$
  5. $i=1, j=3$：比对 $A[1]=12$ 与 $A[3]=8 \implies 12 > 8 \implies count[1]++ \to [2, 1, 2, 0]$
  6. $i=2, j=3$：比对 $A[2]=25'$ 与 $A[3]=8 \implies 25' > 8 \implies count[2]++ \to [2, 1, 3, 0]$
- **最终排名与定位**：
  - `count = [2, 1, 3, 0]`
  - `B[count[0]] = B[2] = 25`
  - `B[count[1]] = B[1] = 12`
  - `B[count[2]] = B[3] = 25'`
  - `B[count[3]] = B[0] = 8`
- **输出结果**：`B = [8, 12, 25, 25']`。
  所有目标槽位 `[0, 1, 2, 3]` 无任何冲突，$25$ 依然严格排在 $25'$ 之前，**稳定性得以保全**。

## 4. 闭环判定模型与核心认知结论

### (1) 考场选型决策模型

| 待排序数据场景特征 | 首选算法推荐 | 物理机理与必然性 |
| :--- | :--- | :--- |
| **序列基本有序（正序占比极高）** | **直接插入排序** | 逆序对少时后移次数少，比较与后移的总成本接近线性；只有已完全有序等输入才无记录后移，不能将“基本有序”当作移动为 0。 |
| **序列规模极小（$n \le 16$）** | **直接插入排序** | 控制逻辑极简，无复杂函数调用栈开销，常数项极小。 |
| **要求算法绝对稳定且空间严格为 $O(1)$** | **直接插入排序 / 冒泡排序** | 满足无辅助空间且等值元素相对顺序绝不颠倒。 |
| **记录关键字较小但元素本身占用巨大内存** | **简单选择排序** | 无论何种情况，移动次数严格不超过 $3(n-1)$，搬迁开销极小。 |

### (2) 稳定性记忆判据
- **不稳定内部排序算法**：**快速排序、简单选择排序、希尔排序、堆排序**。
- **稳定内部排序算法**：**直接插入排序、折半插入排序、冒泡排序、归并排序、基数排序**。
