## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 痛点与朴素匹配（Brute-Force）回溯缺陷
在字符串匹配任务中，设主串 $S$ 长度为 $n$，模式串 $T$ 长度为 $m$（通常 $n \ge m$）。

#### 朴素匹配的状态转移与指针回退
朴素算法采用双指针：主串指针 $i$ 与模式串指针 $j$ 从头开始逐字符比较。
- 若 $S[i] == T[j]$，则双指针同步推进：`i++; j++;`
- 若遇到失配字符（$S[i] \neq T[j]$），算法放弃当前轮次的匹配，执行暴力回溯：
  - 主串指针 $i$ 必须回退到本轮起始位置的下一个字符：
    - **1-based 体系**：$i = i - j + 2$；模式串复位：$j = 1$。
    - **0-based 体系**：$i = i - j + 1$；模式串复位：$j = 0$。

#### 为什么朴素匹配在最坏情况下退化为 $\Theta(n \times m)$？
自构造极简输入样例：
- 主串 $S = \text{"aaaaab"}$（长度 $n = 6$）
- 模式串 $T = \text{"aaab"}$（长度 $m = 4$）

下表展示朴素匹配指针移动与重复比较的无用功轨迹（以 1-based 为例）：

| 轮次 | 初始比对区间 | 比对过程与失配点 | 指针回溯操作 | 本轮比较次数 | 冗余分析 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **第 1 轮** | $S[1..4]$ vs $T[1..4]$ | $S[1..3]$ 与 $T[1..3]$ 均为 `'a'`（成功），$S[4]=\text{'a'} \neq T[4]=\text{'b'}$（失配） | $i$ 回退到 $4 - 4 + 2 = 2$；$j = 1$ | 4 次 | 事实上在第 1 轮已知 $S[2..3]$ 全是 `'a'`，本无须重新比对 |
| **第 2 轮** | $S[2..5]$ vs $T[1..4]$ | $S[2..4]$ 与 $T[1..3]$ 均为 `'a'`（成功），$S[5]=\text{'a'} \neq T[4]=\text{'b'}$（失配） | $i$ 回退到 $5 - 4 + 2 = 3$；$j = 1$ | 4 次 | 再次重复扫描主串已探知的位置 |
| **第 3 轮** | $S[3..6]$ vs $T[1..4]$ | $S[3..5]$ 与 $T[1..3]$ 均为 `'a'`（成功），$S[6]=\text{'b'} == T[4]=\text{'b'}$（完全匹配） | 匹配成功，返回起始位置 3 | 4 次 | 最终命中 |

在上述最坏情况下，主串每前进一步都需要将模式串完整比较 $m$ 次，总比较次数达到 $(n - m + 1) \times m \approx \Theta(n \times m)$。其物理根源在于：**朴素算法将每一次失配当作全新的未知状态，丢弃了前期比对中已经获取的主串字符信息**。

### (2) KMP 核心不变量与前缀/后缀公共长度（LPS）

#### 核心不变量：主串指针 $i$ 永不回退
Knuth-Morris-Pratt（KMP）算法的核心物理不变量是：**主串扫描指针 $i$ 绝不向左回退，永远单调向右递增（或在原地等待）**。

#### 最长公共真前后缀（LPS）的数学本质
- **真前缀（Proper Prefix）**：包含首字符、但不包含尾字符的连续子串。
- **真后缀（Proper Suffix）**：包含尾字符、但不包含首字符的连续子串。
- **最长公共真前后缀（Longest Proper Prefix which is also Suffix, LPS）**：既是真前缀又是真后缀的所有子串中，长度最长的那一个。

#### 为什么失配时模式串指针 $j$ 跳到 `next[j]` 不会漏解？
假设在主串位置 $i$ 与模式串位置 $j$ 处发生失配（$S[i] \neq T[j]$）：
1. **已知事实**：模式串的前 $j-1$ 个字符与主串的对应窗口完全吻合，即：
   $$T[1 \dots j-1] == S[i-j+1 \dots i-1]$$
2. **目标**：不挪动 $i$，将模式串向右滑动，寻找下一个可能与主串对齐的前缀。
3. **几何对齐**：要让模式串向右滑动后，其前缀能与主串在 $i$ 之前的字符继续保持匹配，意味着**模式串滑动后的新前缀，必须等于模式串在 $j-1$ 处的某一段后缀**。
4. **最大化保持**：为了不错过任何可能的匹配位置，模式串向右滑动的距离应当**尽可能小**，等价于新匹配的前缀长度 $k$ 应当**尽可能大**。因此，$k$ 必须严格取模式串子串 $T[1 \dots j-1]$ 的**最长公共真前后缀长度**。
5. **反证法排除漏解**：假设存在一个更小的右移距离（对应一个更大的前缀重合长度 $k' > k$），使得模式串能从某个新起点与主串对齐。根据等量代换，该长度为 $k'$ 的前缀必然也是 $T[1 \dots j-1]$ 的公共真前后缀。然而 $k$ 已经是最大长度，假设 $k' > k$ 与最大性公理矛盾。因此，直接跳转到最大长度位置绝不会漏掉任何合法的匹配起点。

```
主串 S:    ... [ a  b  a  b ] c ...
               │  │  │  │   ▲
模式串 T:       [ a  b  a  b ] a ...      (j = 5 处 'a' != 'c' 失配)
                 └──┬──┘└──┬──┘
                    前缀    后缀 (T[1..4] 的公共真前后缀为 "ab"，长度 k = 2)

向右滑动对齐:
主串 S:    ... [ a  b  a  b ] c ...
                       │  │   ▲ (i 指针不动，继续比对 S[i] 与 T[3])
模式串 T:             [ a  b ] a  b  a ...
                       └──┬──┘
                       新前缀直接对齐原后缀，j 跳转到 k + 1 = 3
```

### (3) 0-based 与 1-based 下标口径显式对照

在 408 考场与工程实践中，由于下标起点（0 还是 1）和数组定义不同，存在多种等价表达，是最高频的概念混淆区。

#### 常见三种口径的数学定义

1. **口径 A：408 统考标准（1-based 位序，教材经典体系）**
   - 模式串从下标 1 开始存储（$T[1 \dots m]$）。
   - $\text{next}[j]$ 的物理含义：当在模式串第 $j$ 个字符处失配时，模式串下一次参与比对的字符位序。
   - 基础值定义：$\text{next}[1] = 0$。
   - 换算关系：当 $j > 1$ 时，$\text{next}[j] = (\text{前 } j-1 \text{ 个字符的最长公共真前后缀长度}) + 1$。
   - 失配转移：$j = \text{next}[j]$；若 $j == 0$，表明当前主串字符连模式串第 1 个字符都无法匹配，此时双指针同步推进：`i++; j++;`（即 $i$ 前进一步，模式串 $j$ 复位到 1）。

2. **口径 B：工程/竞赛前缀表（0-based LPS 数组）**
   - 模式串从下标 0 开始存储（$T[0 \dots m-1]$）。
   - $\pi[j]$（或 $\text{LPS}[j]$）直接存储以 $j$ 结尾的前缀子串 $T[0 \dots j]$ 的最长公共真前后缀长度。
   - 失配转移：当在 $j$ 处失配时，若 $j > 0$，模式串跳转到 $j = \pi[j-1]$；若 $j == 0$，则 `i++`。

3. **口径 C：0-based 下标右移一位的 `next` 数组**
   - 在 0-based 字符串下，为了让代码逻辑与 1-based 完全同构，将 LPS 数组整体右移一位，首位补 -1：
     - $\text{next}[0] = -1$
     - $\text{next}[j] = \pi[j-1] \quad (j > 0)$
   - 失配转移：$j = \text{next}[j]$；若 $j == -1$，则 `i++; j++;`。

#### 逐位手算转换公式与对照样例

给定两个经典自构造模式串，展示各口径下的严格数值对应：

##### 样例 1：模式串 $T = \text{"abaabcac"}$

| 位序 $j$ (1-based) | 字符 $T[j]$ | 对应子串 $T[1..j-1]$ | 最长公共真前后缀 | LPS 长度 | **408 标准 $\text{next}[j]$** | **0-based 下标** | **0-based $\text{next}$ (右移)** |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **1** | `'a'` | $\emptyset$ | 无 | 0 | **0** | 0 | **-1** |
| **2** | `'b'` | `"a"` | 无 | 0 | **1** | 1 | **0** |
| **3** | `'a'` | `"ab"` | 无 | 0 | **1** | 2 | **0** |
| **4** | `'a'` | `"aba"` | `"a"` | 1 | **2** | 3 | **1** |
| **5** | `'b'` | `"abaa"` | `"a"` | 1 | **2** | 4 | **1** |

### (4) `next` 递推构造与 `nextval` 修正算法

#### `next` 数组的递推构造逻辑（以 1-based 为例）
设已知 $\text{next}[j] = k$，即子串 $T[1 \dots j-1]$ 的最长公共真前后缀长度为 $k-1$：
1. 若 $T[j] == T[k]$，则表示该公共前后缀可以向后延伸 1 个字符，因此：
   $$\text{next}[j+1] = k + 1$$
2. 若 $T[j] \neq T[k]$，则需要寻找更短的公共前后缀，令 $k = \text{next}[k]$，递归回溯，直到找到匹配或回退到 $k = 0$。若 $k = 0$，则 $\text{next}[j+1] = 1$。

#### 为什么原始 `next` 数组存在冗余？
考虑模式串 $T = \text{"aaaab"}$，其 $\text{next}$ 数组如下：

| $j$ | 1 | 2 | 3 | 4 | 5 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| $T[j]$ | a | a | a | a | b |
| $\text{next}[j]$ | 0 | 1 | 2 | 3 | 4 |

假设主串为 $S = \text{"aaacaaaab"}$，在 $i = 4$ 处为字符 `'c'`，与模式串 $j = 4$ 处的 `'a'` 失配：
- 按照原始 $\text{next}$ 规则：$j$ 回退到 $\text{next}[4] = 3$；由于 $T[3] == \text{'a'} \neq \text{'c'}$，再次失配；
- $j$ 接着回退到 $\text{next}[3] = 2$；由于 $T[2] == \text{'a'} \neq \text{'c'}$，再次失配；
- $j$ 接着回退到 $\text{next}[2] = 1$；由于 $T[1] == \text{'a'} \neq \text{'c'}$，再次失配；
- 最后 $j$ 退到 $\text{next}[1] = 0$，$i++, j++$。

**物理缺陷**：若 $T[j] == T[\text{next}[j]]$，则由于 $S[i] \neq T[j]$，必然也有 $S[i] \neq T[\text{next}[j]]$。因此退回到与自身字符完全相同的下标纯属徒劳比较。

#### `nextval` 判定规则
在求解 $\text{nextval}[j]$ 时：
- 先按常规方法求出初级候选值 $k = \text{next}[j]$。
- **分支判定**：
  - 若 $k == 0$（即首字符），则 $\text{nextval}[1] = 0$；
  - 若 $T[j] == T[k]$，则当前字符与回退后的字符相同，直接继承回退位置的优化值：
    $$\text{nextval}[j] = \text{nextval}[k]$$
  - 若 $T[j] \neq T[k]$，则回退后的字符与当前字符不同，可能匹配成功，保留原回退值：
    $$\text{nextval}[j] = k = \text{next}[j]$$

#### 完整状态轨迹表：$T = \text{"ababaa"}$

| 位序 $j$ | 字符 $T[j]$ | $T[1..j-1]$ 的 LPS | $\text{next}[j]$ | 递归比较与判定条件 | $\text{nextval}[j]$ |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **1** | `'a'` | - | **0** | 首字符无前驱 | **0** |
| **2** | `'b'` | 0 | **1** | $T[2]=\text{'b'} \neq T[\text{next}[2]]=T[1]=\text{'a'}$，保留 $\text{next}$ | **1** |
| **3** | `'a'` | 0 | **1** | $T[3]=\text{'a'} == T[\text{next}[3]]=T[1]=\text{'a'}$，继承 $\text{nextval}[1]$ | **0** |
| **4** | `'b'` | 1 | **2** | $T[4]=\text{'b'} == T[\text{next}[4]]=T[2]=\text{'b'}$，继承 $\text{nextval}[2]$ | **1** |
| **5** | `'a'` | 2 | **3** | $T[5]=\text{'a'} == T[\text{next}[5]]=T[3]=\text{'a'}$，继承 $\text{nextval}[3]$ | **0** |
| **6** | `'a'` | 3 | **4** | $T[6]=\text{'a'} \neq T[\text{next}[6]]=T[4]=\text{'b'}$，保留 $\text{next}$ | **4** |

#### 主串匹配单步执行轨迹
- **输入主串**：$S = \text{"ababaababaa"}$（长度 $n = 11$）
- **模式串**：$T = \text{"ababaa"}$（使用上述 `nextval` 数组）

| 步骤 | 主串指针 $i$ | 主串字符 $S[i]$ | 模式串指针 $j$ | 模式串字符 $T[j]$ | 比对结果 | 指针后续动作 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 1 | 1 | `'a'` | 1 | `'a'` | 匹配成功 | `i=2, j=2` |
| 2 | 2 | `'b'` | 2 | `'b'` | 匹配成功 | `i=3, j=3` |
| 3 | 3 | `'a'` | 3 | `'a'` | 匹配成功 | `i=4, j=4` |
| 4 | 4 | `'b'` | 4 | `'b'` | 匹配成功 | `i=5, j=5` |
| 5 | 5 | `'a'` | 5 | `'a'` | 匹配成功 | `i=6, j=6` |
| 6 | 6 | `'b'` | 6 | `'a'` | **失配！** | $j$ 跳转到 $\text{nextval}[6] = 4$；$i$ 保持 6 |
| 7 | 6 | `'b'` | 4 | `'b'` | 匹配成功 | `i=7, j=5` |
| 8 | 7 | `'a'` | 5 | `'a'` | 匹配成功 | `i=8, j=6` |
| 9 | 8 | `'b'` | 6 | `'a'` | **失配！** | $j$ 跳转到 $\text{nextval}[6] = 4$；$i$ 保持 8 |
| 10 | 8 | `'b'` | 4 | `'b'` | 匹配成功 | `i=9, j=5` |
| 11 | 9 | `'a'` | 5 | `'a'` | 匹配成功 | `i=10, j=6` |
| 12 | 10 | `'a'` | 6 | `'a'` | 匹配成功 | `j = 6` 且完全匹配！返回起点 $i - m + 1 = 10 - 6 + 1 = 5$ |

在此过程中，主串指针 $i$ 从 1 线性递增到 10，没有任何回退动作。

### (5) 复杂度与摊还分析

#### 为什么匹配过程虽然有 `while` 回退，总时间仍是 $\Theta(n)$？
匹配核心循环结构如下：
```c
int i = 1, j = 1;
while (i <= n && j <= m) {
    if (j == 0 || S[i] == T[j]) {
        i++;
        j++;
    } else {
        j = nextval[j]; // 仅回退 j
    }
}
```
- **势能分析（Amortized Potential Analysis）**：
  - 定义势能函数 $\Phi = j$。由于 $1 \le j \le m+1$，势能始终非负（$\Phi \ge 0$）。
  - 在 `if` 分支中：$i$ 增加 1，$j$ 增加 1，势能 $\Delta \Phi = +1$。由于 $i$ 从 1 增到 $n$，该分支最多执行 $n$ 次。
  - 在 `else` 分支中：$i$ 不变，模式串发生回溯，$j$ 严格减小（跳转到 $\text{nextval}[j] < j$），因此势能 $\Delta \Phi \le -1$。
  - 核心物理结论：$j$ 减小的总幅度不可能超过其增加的总幅度。既然 $j$ 的总增加次数上限为 $n$，则 $j$ 回退的总次数上限也严格受限于 $n$。
  - 综合两项：字符比较总次数严格不会超过 $2n$。故匹配阶段时间复杂度为严格的 **$\Theta(n)$**。

#### 空间复杂度
仅需为模式串开辟 `next` / `nextval` 线性表，空间复杂度为 **$\Theta(m)$**，与主串长度 $n$ 完全无关。

### (6) 408 考场标准模型 vs 现代工程实现边界

```
┌────────────────────────────────────────────────────────┐
│ 408 考场标准模型                                        │
│  - 纯单模式串匹配，关注 1-based 数组手算                   │
│  - next 数组推导: next[j] = LPS[j-1] + 1               │
│  - nextval 消除连续冗余: 若 T[j]==T[next[j]] 递归继承    │
└───────────────────────────┬────────────────────────────┘
                            │ 现实工程扩展
                            ▼
┌────────────────────────────────────────────────────────┐
│ 现代工程实现边界                                        │
│  1. 单模式检索: BM (Boyer-Moore) / Sunday 算法          │
│     - 逆向扫描 + 坏字符/好后缀规则，平均时间 O(n/m)      │
│     - grep / 文本编辑器底层很少用 KMP，首选 BM/Horspool │
│  2. 多模式检索: Aho-Corasick (AC 自动机)                │
│     - Trie 字典树 + KMP 失配指针，用于网络入侵检测/WAF   │

│     - glibc memmem/strstr 一次并行对比 32/64 字节       │
└────────────────────────────────────────────────────────┘
```

#### 考场规则与工程实现的断层点
1. **单模式与多模式的分水岭**：
   - 考场 KMP 处理的是单一模式串；
   - 现代防火墙（如 Snort、Suricata）需同时匹配成千上万条恶意特征规则，若运行 KMP $k$ 次耗时 $O(k \cdot n)$。工程上将所有模式串合并为一棵 Trie 树，并在节点间建立类似于 KMP 的失配回退边（Fail Pointer），即 **AC 自动机**，仅需扫描一遍主串 $O(n)$ 即可完成所有模式串的同步匹配。
2. **KMP 与 BM 算法的实际吞吐差异**：
   - KMP 在理论上具备优雅的线性最坏保证，但每次只能跳过前缀部分，主串必须逐字节检视；
   - Boyer-Moore 算法从模式串尾部向前反向比对，当发生坏字符失配时，整段滑动步长可达 $m$。在大型英文字符串搜索中，平均只需要检视 $\frac{n}{m}$ 个字符，实际运行速度远快于 KMP。

## 3. 本学科内跨章节关联与跨学科协同关联

### 1. 本学科内跨章节关联

#### (1) 与线性表/栈的指针回溯与状态保存
- **共同机制**：均涉及下标偏移、当前滑动窗口的状态维护与线性扫描。
- **关键差异**：朴素匹配通过将指针 $i$ 强行回弹重置状态（相当于无条件回滚）；而 KMP 算法把模式串自相似的前缀信息静态固化在 `next` 表中，完全避免了为维护历史上下文而使用动态数据栈，以 $O(m)$ 的静态空间换取了 $O(1)$ 的动态内存开销。
- **不可直接迁移的判据**：若主串不是连续数组而是单向流式输入（如网络管道 `stdin`），朴素匹配因需要向前 Seek 寻址而直接失效崩溃；KMP 的主串指针单调前进特性使得其能无缝天然支持**单向流式数据（Streaming Data）**处理。

#### (2) 与树形结构（Trie 树）的拓扑演进
- **共同机制**：模式串的前缀重合利用。KMP 利用的是单串自身的内部前缀自匹配；Trie 树利用的是多个串之间的公共前缀空间压缩。
- **关键差异**：KMP 处理一维单串，失配回退是指针在一维数组内跳转；AC 自动机则是将 KMP 的 `next` 指针扩展到二维树状拓扑（Trie）上，通过广度优先遍历（BFS）构建全局失配跳转链（Fail 边）。
- **不可直接迁移的判据**：KMP 的 `next` 递推基于严格的一维前后缀拓扑；在树形结构上，一个节点可能属于多个不同分支，其最长公共后缀必须在父节点的 Fail 链上递归求解，不能直接照搬一维线性递推式。

### 2. 跨学科协同关联

#### (1) 计算机组成原理：指令流水线与缓存局部性
- **共同机制**：数据访问连续性与分支预测。
- **关键差异**：
  - 朴素匹配频繁回退主串指针 $i$，破坏了现代 CPU 硬件预取器（Stream Prefetcher）的单向线性顺序，导致频繁触发 L1 Data Cache Miss；
  - KMP 的主串指针 $i$ 纯单调递增，主串数据能以完美的连续空间局部性被 Cache Line 批量装载。但其内部根据 `next` 数组频繁跳转模式串指针 $j$，在乱序执行 CPU 中会导致分支预测（Branch Predictor）出现间歇性停顿。
- **不可直接迁移的判据**：虽然 KMP 理论比较次数远少于朴素匹配，但在随机短文本（如字母集很大、极少长前缀重合）的实际场景下，朴素匹配极少深入比较便迅速失配前进，且指令结构简单无跳转，真实运行耗时可能反而低于需频繁查表的 KMP。

#### (2) 编译原理：有限状态自动机（DFA / NFA）
- **共同机制**：模式串匹配在本质上等价于确定性有限状态自动机（DFA）的状态转移。
- **关键差异**：
  - DFA 针对每个字符集输入 $\Sigma$ 拥有完整且确定性的转移函数 $\delta(state, char)$，匹配时无论命中还是失配，只需单步查表 $\Theta(1)$ 立即转移到下一状态，无需任何回退循环；
  - KMP 为了节省转移表的存储空间（完整的 DFA 状态表需 $O(m \times |\Sigma|)$ 空间），将状态转移拆解为“字符相等推进”与“字符不等按 `next` 回退”两级机制，以最坏多次内部回退换取了更小的 $\Theta(m)$ 内存占用。
- **不可直接迁移的判据**：KMP 的 `next` 数组不能直接充当词法分析器（Lexer）。词法分析器面对成百上千种 Token 和大字符集，必须使用完整 DFA 转移矩阵或压缩状态机，否则 KMP 的回退链条会严重拉低词法扫描吞吐。

## 4. 闭环决策模型与核心认知结论

### (1) 考场手算 `next` 与 `nextval` 三步工作流

```
第一步: 识别考卷口径要求
  ├─ 若给出 next[1] = 0 或要求 1-based 位序: 使用 408 标准公式
  └─ 若给出 next[0] = -1 或 0-based: 先算 1-based, 整体减 1 并右移

第二步: 逐位手算 1-based next 表 (手写草稿规范)
  1. 划定首位: next[1] = 0
  2. 划定次位: next[2] = 1 (因为前 1 个字符不可能有真前后缀)
  3. 对于第 j 位 (j >= 3):
     - 遮住第 j 位及之后字符，仅观察子串 T[1 .. j-1]
     - 找出该子串既是真前缀又是真后缀的最长子串长度 L
     - 填写 next[j] = L + 1

第三步: 逐位修正 nextval 表
  1. nextval[1] = 0
  2. 对于 j = 2 到 m:
     - 查出 k = next[j]
     - 比较字符: 是否有 T[j] == T[k] ?
         ├─ 是: nextval[j] = nextval[k] (继承目标位的优化值)
         └─ 否: nextval[j] = k          (保留原本的 next[j])
```

### (2) 常见认知误区反例剖析

#### 误区 1：“`next` 数组的值只与模式串自身有关，与主串完全无关；而 `nextval` 依赖主串字符。”
- **反例与真相**：`nextval` **同样完全只依赖模式串自身**！从推导规则可知，`nextval[j]` 的计算仅比对了模式串自身的字符 $T[j]$ 与 $T[\text{next}[j]]$，无需提前获知任何主串的字符信息。

#### 误区 2：“求 `next[j]` 时，最长公共真前后缀是在子串 $T[1 \dots j]$ 中寻找。”
- **反例与真相**：极易手滑把 $T[j]$ 自身算入。若 $T = \text{"abac"}$，算 $j = 4$（字符 `'c'`）时，必须仅在 $T[1 \dots 3] = \text{"aba"}$ 中找前后缀，得到 `"a"`（长度 1），因此 $\text{next}[4] = 1 + 1 = 2$。绝不能将 `'c'` 算进去寻找 $T[1 \dots 4]$ 的前后缀。
