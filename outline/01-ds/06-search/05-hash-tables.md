- **考察要点**：

  - 冲突处理机制：开放定址法（线性探测、二次探测/平方探测、双散列）、拉链法（链地址法）。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么需要散列？（从基于比较走向基于寻址）
- **物理困境**：
  - 无论是顺序查找（$O(n)$）、折半查找（$O(\log n)$）还是平衡树查找（$O(\log n)$），它们的本质都建立在**关键字之间的“大小比较”**之上。根据信息论，基于比较的查找时间下限无论如何无法突破 $O(\log n)$。
- **解法：以空间换时间，直接映射**：
  - 散列表通过散列函数 $H(\text{key})$，在关键字与物理内存存储地址之间建立一个直接的确定性映射关系：
    $$\text{Address} = H(\text{key})$$
  - 理想状态下，无需任何关键字比较，只需计算一次哈希函数即可直接命中物理地址，期望时间复杂度达到极致的 **$O(1)$**。

---

### (2) 冲突（Collision）的必然性与除留余数法
- **鸽巢原理**：
  现实世界中关键字的可能取值空间（Universe $U$）往往极其庞大，而计算机为散列表分配的物理内存插槽数量 $m$ 相对有限（$|U| \gg m$）。依据鸽巢原理，**必然存在两个不同的关键字 $k_1 \ne k_2$，使得 $H(k_1) = H(k_2)$**。这种现象称为**冲突**，称 $k_1$ 与 $k_2$ 为**同义词**。
- **除留余数法为什么模数 $p$ 必须选不大于 $m$ 的质数？**
  $$H(\text{key}) = \text{key} \pmod{p} \quad (p \le m)$$
  - 若 $p$ 选用合数（如 2 的幂或包含大量公因子），若关键字序列具有某种步长周期性，取模后的余数将极度集中在公因子的倍数上，导致大量哈希插槽完全空置，而少数插槽严重扎堆。
  - 选取质数 $p$ 能够使关键字中的每一位二进制有效位都充分参与取模运算，最大化打散聚集，使哈希地址呈现均匀的伪随机分布。

---

### (3) 冲突解决策略的工程权衡

#### ① 开放定址法（Open Addressing）
所有元素全部紧凑存放在同一张连续的哈希数组中。当发生冲突时，通过增量序列 $d_i$ 在数组内部寻找下一个空闲插槽：
$$H_i = (H(\text{key}) + d_i) \pmod{m}$$

| 探测方式 | 增量序列 $d_i$ | 物理优缺点与聚集（Clustering）分析 |
| :--- | :--- | :--- |
| **线性探测法** | $d_i = 1, 2, 3, \dots, m-1$ | 优点：算法最简单，缓存局部性好。<br>缺点：**严重的一级聚集（Primary Clustering / 堆积）**。即不同同义词之间会互相争夺同一个探测路径，越聚集的地方后续插入越容易发生碰撞，形成滚雪球效应。 |
| **二次探测法 (平方探测)** | $d_i = 1^2, -1^2, 2^2, -2^2, \dots, k^2, -k^2$ ($k \le m/2$) | 优点：跳跃式探测，**彻底消除一级聚集**。<br>缺点：产生二级聚集；且只有当表长 $m$ 为形如 $4k+3$ 的质数时，才能保证至少探测到一半的插槽。 |
| **伪随机探测法** | $d_i$ 为预设伪随机数序列 | 消除规律性聚集，但需预置随机种子表。 |

- **开放定址法的逻辑删除陷阱**：
  在开放定址法中，**绝对不能物理清空被删除的插槽**（直接置为空），否则会导致沿该插槽向后探测的其他同义词链条被“断开”，造成后续合法的查找判定为失败。必须设立专门的“删除标记（Tombstone 墓碑）”。

#### ② 拉链法（Separate Chaining）
- **机制**：散列表由一个一维指针数组构成，每个插槽作为一个链表的头指针。所有映射到同一个地址的同义词，直接挂载在同一个单链表下。
- **物理优势**：
  - 真正做到了“井水不犯河水”：不同哈希地址的同义词绝对不会互相争抢空间，彻底杜绝任何聚集现象。
  - 删除操作极其简单，仅需标准的单链表节点释放，无需任何复杂的删除标记维护。
  - 装填因子 $\alpha$ 可以突破 1，极大提高了内存弹性和容灾能力。

---

### (4) 装填因子（$\alpha$）的支配地位
$$\text{装填因子 } \alpha = \frac{\text{表中记录数 } n}{\text{散列表物理长度 } m}$$

- **核心认知结论**：
  **散列表的平均查找长度（ASL）仅取决于装填因子 $\alpha$ 和所选的冲突处理方法，而与表中的元素绝对总数 $n$ 或表长 $m$ 几乎无关！**
  - $\alpha$ 越小，表中空闲插槽越多，冲突概率越低，查找越快，但空间浪费越大；
  - $\alpha$ 越大，空间利用率越高，但冲突剧烈飙升，查找效率急剧劣化。工程上通常将 $\alpha$ 动态控制在 $0.7 \sim 0.8$ 之间，一旦超限立即触发扩容（Rehash）。

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 数据结构: 散列与直接地址映射   │
                     └──────────────┬───────────────┘
                                    │ 硬件地址折叠映射
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 计组: Cache 直接映射与组相联  │         │ 计网: 路由器转发表与 NAT 状态 │
│  - 物理地址取模等价于除留余数 │ ◄────── │  - 端口映射表与五元组哈希    │
│  - 冲突引发 Cache 行替换     │         │  - O(1) 极速转发流表查找     │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与计组 Cache 地址映射的机理同构**：
   - 计算机体系结构中 Cache 的“直接映射”（$\text{行号} = \text{主存块号} \pmod M$）本质就是除留余数哈希。
   - Cache 的“冲突缺失”本质就是散列表的“哈希冲突”；而“$k$ 路组相联”则相当于拉链法的有限硬件插槽展开。
2. **与计算机网络 NAT 转换表及转发表的映射**：
   - 工业级路由器处理百万级并发数据流时，必须在几十纳秒内完成转发决策，其底层流表（Flow Table）和 NAT 会话表完全依赖散列表在 $O(1)$ 时间内由连接五元组检索下一跳。

## 4. 闭环决策模型与核心认知结论

### (1) 考场 ASL 计算分步黄金法则

#### 1. 查找成功 ASL 算力模型
$$\text{ASL}_{\text{succ}} = \frac{\sum_{i=1}^{n} (\text{定位到第 } i \text{ 个元素所经历的实际比较次数})}{n}$$
- 分子是**表中已存的每个元素**实际查到它时所比对的次数之和。
- 分母**必须除以元素总数 $n$**！

#### 2. 查找失败 ASL 算力模型
$$\text{ASL}_{\text{fail}} = \frac{\sum_{j=0}^{p-1} (\text{从哈希地址 } j \text{ 出发直到遇到第一个空插槽所需的比较次数})}{p}$$
- 考场核心警示：
  - 只有到达**空插槽**（未存放过元素的槽位），系统才能最终断定“查找失败”并终止探测。
  - 分母**必须除以散列函数的模数 $p$**（即可能的起始哈希地址总数），**严禁除以表长 $m$**！

### (2) 考场定性闭环判据
1. **产生堆积（一级聚集）现象的根本原因**：**冲突处理方法选择不当（采用了线性探测法）**，而与散列函数是否均匀无直接关联。
2. **只要题目采用拉链法** $\to$ 其查找成功与失败的比较次数仅局限在各自的单链表长度内，**绝不存在不同同义词链之间的相互干扰**。
