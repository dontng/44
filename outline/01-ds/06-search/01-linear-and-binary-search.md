## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 平均查找长度（ASL）的度量基准
评价查找算法优劣的核心物理指标不是绝对微秒数，而是关键码与目标值比较次数的数学期望：
- **查找成功时的平均查找长度**：
  $$\text{ASL}_{\text{succ}} = \sum_{i=1}^{n} P_i \times C_i$$
  其中 $P_i$ 为查找到第 $i$ 个元素的先验概率（通常等概率取 $\frac{1}{n}$），$C_i$ 为找到第 $i$ 个元素所需的关键字比较次数。
- **查找失败时的平均查找长度**：
  $$\text{ASL}_{\text{unsucc}} = \sum_{j=1}^{m} Q_j \times C_j$$
  其中 $Q_j$ 为落在第 $j$ 个不存在区间的概率，$C_j$ 为确认该元素不在表中所需的比较次数。

### (2) 顺序查找算法模型与哨兵机制

#### 1. 无序顺序表的增删查代价辨析
- **查找**：从头到尾线性比对，成功时 $\text{ASL}_{\text{succ}} = \frac{n+1}{2} = \Theta(n)$。
- **插入**：尾部追加直接写入，耗费 $O(1)$。
- **删除**：
  - 若**已知待删除元素的物理下标 $i$** 且**无需保持原有先后顺序**：只需执行 `A[i] = A[n-1]; n--;`（将末尾元素覆盖被删位置），耗费 **$O(1)$**。
  - 若**按值查找删除（仅给出 key）**：必须先耗费 $\Theta(n)$ 线性查找其下标，总耗时依然为 **$\Theta(n)$**。

#### 2. “哨兵（Sentinel）”技术与失败比较次数差异
- **无哨兵扫描**：
  ```c
  for (int i = 0; i < n; i++) {
      if (A[i] == key) return i; // 每轮循环做 2 次判断：下标越界检查与关键字比较
  }
  return -1;
  ```
  - 失败时比较次数：遍历 $n$ 个元素比对 $n$ 次，外加 $n+1$ 次下标越界检查。对关键字本身的比较次数为 **$n$ 次**。
- **带哨兵扫描（设在 `A[0]` 处）**：
  ```c
  A[0] = key; // 设置哨兵
  int i = n;
  while (A[i] != key) {
      i--;
  }
  return i; // 返回 0 表示查找失败
  ```
  - **物理优势**：循环体内免去了下标越界判断指令，减少了 CPU 流水线分支预测失败开销。
  - **失败时比较次数**：从 $A[n]$ 一路比对至 $A[0]$（自身与自身比对必定相等跳出），对关键字共比较了 **$n + 1$ 次**！

#### 3. 有序顺序表的提前终止优化与非等概率查找
- **升序顺序表的失败早停**：当扫描到某个元素 $A[i] > \text{key}$ 时，可**立即断定目标元素必然不存在**，无需扫描后续元素。
  - 将 $n$ 个元素切分为 $n+1$ 个失败区间，失败比较次数为 $1, 2, \dots, n, n$，平均失败查找长度从 $n+1$ 压缩到约 $\frac{n}{2} + \frac{n}{n+1}$。
- **非等概率场景优化**：若各元素被访问的概率极不均匀（$P_1 \ge P_2 \ge \dots \ge P_n$），应将高频访问的元素置于表头，使得乘积和 $\sum P_i C_i$ 达到极小值。

<a id="binary-search"></a>
### (3) 折半查找与判定树（Binary Decision Tree）

#### 1. 致命物理前提（二者缺一不可）
1. **必须是顺序存储结构（物理连续数组）**：折半查找依赖 `mid = (low + high) / 2` 并在 **$O(1)$ 时间内由基址变址直接定位中点**。单链表虽可排成有序，但跳转到 `mid` 必须顺序解引用 $\Theta(n)$ 次指针，整体算法退化至 $\Theta(n)$，完全丧失对数优势。
2. **必须按关键字严格有序排列**。

#### 2. $n = 11$ 折半查找判定树完全拓扑与精算范例

设待查数组下标为 `1 ~ 11`，采用考纲标准的向下取整公式：
$$\text{mid} = \left\lfloor \frac{\text{low} + \text{high}}{2} \right\rfloor$$

```
                           [ 6 ]                   <-- 第 1 层 (1 个内部节点)
                        /        \
                    [ 3 ]        [ 9 ]             <-- 第 2 层 (2 个内部节点)
                   /     \      /     \
                [ 1 ]   [ 4 ]  [ 7 ]  [ 10 ]       <-- 第 3 层 (4 个内部节点)
                 / \     / \    / \    /  \
                F1 [2]  F4 [5] F7 [8] F10 [11]     <-- 第 4 层 (4 个内部节点, 4 个失败节点)
                   / \     / \    / \     /  \
                  F2 F3   F5 F6  F8 F9   F11 F12   <-- 第 5 层 (8 个失败节点)
```

##### 拓扑要素解析：
1. **内部节点（圆形/方括号，共 $n = 11$ 个）**：代表查找成功的位置。节点所在层数即为查找成功时比对关键码的实际次数。
   - 第 1 层：`6`（1 个节点，比较 1 次）
   - 第 2 层：`3, 9`（2 个节点，比较 2 次）
   - 第 3 层：`1, 4, 7, 10`（4 个节点，比较 3 次）
   - 第 4 层：`2, 5, 8, 11`（4 个节点，比较 4 次）
2. **外部失败节点（方形 $F_1 \sim F_{12}$，共 $n + 1 = 12$ 个）**：代表查找失败的区间。
   > [!IMPORTANT]
   > **外部失败节点比较次数核心认知**：
   > 外部失败节点是逻辑上的空指针终止点，**不是实际存储的物理数据**！
   > 处于判定树第 $k$ 层的失败节点，其查找失败经历的关键码比较次数等于**从根节点到该外部节点路径上的内部祖先节点数**，即严格为 **$k - 1$ 次**，绝非 $k$ 次！

##### 精确 ASL 有理数计算：
- **查找成功平均查找长度**：
  $$\text{ASL}_{\text{succ}} = \frac{1 \times 1 + 2 \times 2 + 3 \times 4 + 4 \times 4}{11} = \frac{1 + 4 + 12 + 16}{11} = \frac{33}{11} = \mathbf{3}$$
- **查找失败平均查找长度**：
  - 第 4 层有 4 个外部节点（$F_1, F_4, F_7, F_{10}$），各经历 $4 - 1 = 3$ 次比较；
  - 第 5 层有 8 个外部节点（$F_2, F_3, F_5, F_6, F_8, F_9, F_{11}, F_{12}$），各经历 $5 - 1 = 4$ 次比较；
  $$\text{ASL}_{\text{unsucc}} = \frac{3 \times 4 + 4 \times 8}{12} = \frac{12 + 32}{12} = \frac{44}{12} = \mathbf{\frac{11}{3}} \approx 3.67$$
- **与大样本近似公式的区别**：
  教材常用 $\text{ASL}_{\text{succ}} \approx \log_2(n + 1) - 1$ 作为渐进估计；但在 408 考场面对具体给定规模（如 $n=11$ 或 $n=12$）时，**必须画出判定树计算精确有理数分数值**！

### (4) 分块查找（索引顺序查找）与极值块长

- **“块间有序，块内无序”设计折中**：
  - 将长度为 $n$ 的主表划分为 $b$ 个子块，每块包含 $s$ 个元素（$n = b \times s$）。
  - **索引表**：为每个块建立索引项，包含该块的“最大关键字”与“块首物理地址”。索引表按最大关键字升序排列。
  - **数据表**：各块内部的元素可以无序存放。
- **动态维护优势**：
  若数据表各块内部采用**链表**实现，当插入新元素时，只需二分定位索引表找到归属块，再在块内进行 $O(1)$ 头插；删除元素时直接在块链表中摘除节点，**完全避免了纯有序表插入删除时动辄移动半个表的物理开销**。
- **最佳分块大小推导（均值不等式）**：
  若索引表和块内均采用顺序查找：
  $$\text{ASL} = L_I + L_S = \frac{b + 1}{2} + \frac{s + 1}{2} = \frac{1}{2} \left( b + \frac{n}{b} \right) + 1$$
  由均值不等式 $b + \frac{n}{b} \ge 2\sqrt{n}$，当且仅当 $b = \frac{n}{b} \implies \mathbf{b = s = \sqrt{n}}$ 时取等号：
  $$\text{ASL}_{\min} = \sqrt{n} + 1$$

## 4. 闭环判定模型与核心认知结论

### (1) 查找算法核心指标横向对照表

| 查找算法 | 存储物理约束 | 元素排序约束 | 成功 $\text{ASL}_{\text{succ}}$ | 失败 $\text{ASL}_{\text{unsucc}}$ | 动态增删开销 |
| :--- | :--- | :--- | :---: | :---: | :---: |
| **无序顺序查找 (无哨兵)** | 顺序表或单链表 | 无要求 | $\frac{n+1}{2}$ | $n$ | 尾部插入 $O(1)$，按值删 $\Theta(n)$ |
| **无序顺序查找 (带哨兵)** | 顺序存储（含 0 槽） | 无要求 | $\frac{n+1}{2}$ | $n + 1$ | 尾部插入 $O(1)$，按值删 $\Theta(n)$ |
| **有序顺序查找** | 顺序表或单链表 | 必须升序/降序 | $\frac{n+1}{2}$ | $\approx \frac{n}{2}$ | 维持有序需挪移 $O(n)$ |
| **折半查找 (二分)** | **严格顺序存储数组** | **必须递增/递减** | 判定树精确计算 / 渐进 $\log_2(n+1)-1$ | 判定树外节点深度计算 | 插入删除需搬迁 $\Theta(n)$ |
| **分块查找 (均分 $\sqrt{n}$)** | 索引顺序存储 | 块间有序、块内无序 | $\sqrt{n} + 1$ | 索引失败 + 块内扫描 | 块内链表实现时增删极快 |

### (2) 考场定性闭环判据
1. **一个含有 $n$ 个关键字的折半查找判定树**：
   - 内部成功节点数恒等于 **$n$**；
   - 外部失败节点数恒等于 **$n + 1$**；
   - 树的最大高度（最大比较次数）严格为 **$h = \lceil \log_2(n + 1) \rceil$**。
2. **能否在有序单链表上使用折半查找？**
   - **不能获得 $O(\log n)$ 查找性能！** 单链表缺乏 $O(1)$ 随机访问能力，寻址中点需步进 $\Theta(n)$，整体查找复杂度仍为 $\Theta(n)$，无法发挥折半查找的对数加速优势（若需链式结构支持对数查找，需增设多层索引升级为跳表 Skip List）。
