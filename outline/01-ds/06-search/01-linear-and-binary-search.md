## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - 平均查找长度（ASL, Average Search Length）定义：成功查找与失败查找的数学模型。

  - 折半查找（二分查找）：物理前提（顺序存储 + 关键字有序）、判定树拓扑构造与时空分析。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 平均查找长度（ASL）的度量基准
评价查找算法优劣的核心物理指标不是绝对耗时，而是关键字与目标值比较次数的数学期望：
- **查找成功时的平均查找长度**：
  $$\text{ASL}_{\text{success}} = \sum_{i=1}^{n} P_i \times C_i$$
  其中 $P_i$ 为查找到第 $i$ 个元素的先验概率（通常等概率取 $\frac{1}{n}$），$C_i$ 为找到第 $i$ 个元素所需的关键码比较次数。
- **查找失败时的平均查找长度**：
  $$\text{ASL}_{\text{failure}} = \sum_{j=1}^{m} Q_j \times C_j$$
  其中 $Q_j$ 为落在第 $j$ 个不存在区间的概率，$C_j$ 为确认该元素不在表中所需的比较次数。

---

### (2) 顺序查找与“哨兵”优化
- **普通线性扫描的问题**：
  每次循环都要做两次判断：一是判断数组下标是否越界（`i >= 0`），二是判断当前元素是否与目标相等（`data[i] == key`）。
- **哨兵（Sentinel）技术的硬件优化**：
  在数组的 0 号位置存放待查的目标 `key`（哨兵），从数组末尾向前扫描：
  ```c
  ST.elem[0] = key; // 设置哨兵
  int i = ST.length;
  while (ST.elem[i] != key) {
      i--;
  }
  return i; // 返回 0 表示查找失败
  ```
  - **物理优势**：循环体内完全免去了下标越界判断指令，极大减少了 CPU 流水线分支预测失败的开销。
- **有序顺序表的失败早停**：
  若表已按升序排列，当扫描到某个元素 `elem[i] > key` 时，可以**立即断定目标元素必然不存在**，无需继续扫描后续元素，从而将失败 ASL 从 $n+1$ 压缩到约 $\frac{n}{2}$。

### (3) 折半查找与判定树（Binary Decision Tree）
- **致命物理前提（必须同时满足两项，缺一不可）**：
  1. **必须是顺序存储结构（物理数组）**：因为折半查找依赖 `mid = (low + high) / 2` 并在 **$O(1)$ 时间内直接跳转到中点位置**。
     - **反例警告**：单链表虽然可以排成有序链表，但因为链表只能 $O(n)$ 顺序寻址，无法随机跳跃，因此**链表绝对不能实现 $O(\log n)$ 的折半查找**！
  2. **必须按关键字有序排列**。

#### 折半查找判定树的构造与形态不变量
以向下取整 $\lfloor \frac{\text{low} + \text{high}}{2} \rfloor$ 为例：
```
              [ 4 ]
            /       \
        [ 2 ]       [ 6 ]
       /     \     /     \
     [1]     [3] [5]     [7]
     / \     / \ / \     / \
    o   o   o  o o  o   o   o  (失败外部节点，共 n + 1 个)
```

1. **圆节点（内部节点，共 $n$ 个）**：代表查找成功的关键字位置。所在层数即为查找成功时的比较次数。
2. **方形/小圈节点（外部叶子节点，共 $n + 1$ 个）**：代表查找失败的区间。到达该失败节点的父节点比较次数，即为查找失败时的比较次数。
3. **拓扑形态特征**：
   - 折半查找判定树**必然是一棵平衡二叉树（AVL 树）**，任意节点的左右子树高度差绝对值 $\le 1$。
   - 树的高度严格为：$h = \lceil \log_2(n + 1) \rceil$。
   - 查找成功的最大比较次数严格不会超过树的高度 $h$。
   - 时间复杂度严格收敛于 **$O(\log_2 n)$**。

### (4) 分块查找（索引顺序查找）与极值块长
- **物理折中设计（“块间有序，块内无序”）**：
  - 纯顺序表：增删快（直接追加），但查找极慢（$O(n)$）；
  - 纯有序表：查找极快（$O(\log n)$），但插入删除极慢（需挪移整表）。
  - **分块折中**：将包含 $n$ 个元素的表切分为 $b$ 个子块，每块包含 $s$ 个元素（$n = b \times s$）。
    1. 索引表：按块间最大关键字有序排列，存储每个块的最大关键字和物理起始地址；
    2. 数据表：每个块内部的数据可以完全无序。
- **查找两阶段**：
  1. 第一步：在索引表中查找目标所在的分块（可顺序查找或折半查找）；
  2. 第二步：在确定的分块内部执行普通的顺序查找。
- **最佳分块大小推导（均值不等式）**：
  若两阶段均采用顺序查找：
  $$\text{ASL} = \text{ASL}_{\text{index}} + \text{ASL}_{\text{block}} = \frac{b + 1}{2} + \frac{s + 1}{2} = \frac{1}{2}\left( b + \frac{n}{b} \right) + 1$$
  当且仅当 $b = \frac{n}{b}$，即 **$b = s = \sqrt{n}$** 时，ASL 取到物理全局最小值：
  $$\text{ASL}_{\min} = \sqrt{n} + 1$$

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 数据结构: 折半查找与判定树     │
                     └──────────────┬───────────────┘
                                    │ 结构等价于完全平衡二叉树
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 数据结构: 二叉排序树与平衡树   │         │ 操作系统: 文件索引与页目录    │
│  - BST 查找机制与判定树同构   │ ◄────── │  - 分块查找等价于单级页表索引│
│  - 极度不平衡时退化为顺序查找 │         │  - 块间有序对应页目录有序    │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与二叉排序树（BST）的本质同一性**：
   - 折半查找判定树本质上就是一棵经过全局平衡优化后的二叉排序树。
   - 二叉排序树的动态插入可能退化为单支树（查找复杂度退化为 $O(n)$），而折半查找的静态判定树天然受到中点平分约束，深度严格锁定在 $\lceil \log_2(n+1) \rceil$。
2. **与操作系统内存分级分页的映射**：
   - 分块查找的“索引表 + 数据块”两级结构，在计算机体系结构中被广泛应用于页目录与物理页框的二元映射，用微小的索引表换取对海量非连续块的高效导航。

## 4. 闭环决策模型与核心认知结论

### (1) 查找算法核心性能指标对照

| 查找算法 | 存储结构要求 | 元素有序性要求 | 查找成功 ASL | 插入/删除复杂度 |
| :--- | :--- | :--- | :---: | :---: |
| **无序顺序查找** | 顺序存储或链式存储 | **无要求** | $\frac{n + 1}{2}$ | $O(1)$（直接尾插） |
| **有序顺序查找** | 顺序存储或链式存储 | **必须有序** | $\frac{n + 1}{2}$ | $O(n)$（维持有序） |
| **折半查找** | **必须为顺序存储(数组)** | **必须有序** | $\approx \log_2(n + 1) - 1$ | $O(n)$（大量元素挪移） |
| **分块查找 (均分 $\sqrt{n}$)** | 索引顺序存储 | **块间有序，块内无序** | $\sqrt{n} + 1$ | $O(1)$ ~ $O(s)$（块内无序插） |

### (2) 考场定性闭环判据
1. **一个含有 $n$ 个节点的折半查找判定树**：
   - 必定包含 **$n + 1$ 个外部失败节点**。
   - 树的高度必定为 **$\lceil \log_2(n + 1) \rceil$**。
2. **能否在有序单链表上应用折半查找提高效率？**
   - **绝对不能！** 单链表没有随机存取能力，查找中点必须花费 $O(n)$ 步进遍历，总时间复杂度不降反升，退化至 $O(n)$ 甚至更高。
