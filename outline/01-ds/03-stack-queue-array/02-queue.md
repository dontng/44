## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须将顺序队列改造为“循环队列”？
* **顺序队列的物理困境（假溢出）**：
  * 普通顺序队列用一维数组 `Q[Maxsize]` 存储，队头指针 `front` 指向队头元素，队尾指针 `rear` 指向队尾元素的下一个位置；
  * 入队 `rear++`，出队 `front++`；
  * 当频繁入队出队后，`rear` 到达了数组最大上界 `Maxsize`，此时若再入队，系统报“队列已满”；但实际上数组前面由于出队**已经空出了大量闲置空间**！这种空间浪费叫**假溢出**。
* **循环队列的取模逻辑**：
  * 逻辑上把一维数组首尾相连成一个环形表盘：
    * 入队推进：`rear = (rear + 1) % Maxsize`
    * 出队推进：`front = (front + 1) % Maxsize`

---

### (2) 循环队列的核心矛盾：判空与判满的特征重叠
在没有额外辅助机制时：
* 队列为空时：`front == rear`；
* 队列被彻底塞满时：`front == rear`！
* **物理矛盾**：相同的条件无法区分“到底是一个元素都没有，还是全满”！

#### 解决方案一：牺牲一个存储单元（408 最主流考法）
* 数组大小为 `Maxsize`，但最多只允许存放 `Maxsize - 1` 个元素；
* **队空条件**：
  $$\text{front} == \text{rear}$$
* **队满条件**（队尾指针的下一个位置碰到了队头）：
  $$(\text{rear} + 1) \% \text{Maxsize} == \text{front}$$
* **队列中当前实际元素个数计算**：
  $$\text{length} = (\text{rear} - \text{front} + \text{Maxsize}) \% \text{Maxsize}$$

#### 解决方案二：结构体增设 `size` 计数器
* 增设变量 `int size = 0` 记录当前元素总数；
* **队空**：`size == 0`；**队满**：`size == Maxsize`。

#### 解决方案三：增设 `tag` 标志位
* 增设标志位 `int tag`：最近一次操作若是插入成功则 `tag = 1`，若是删除成功则 `tag = 0`；
* **队空**：`front == rear && tag == 0`；
* **队满**：`front == rear && tag == 1`。

---

### (3) 双端队列（Deque）的输出受限与输入受限（408 选择题高频）
* **输入受限双端队列**：只允许在一端输入，两端皆可输出；
* **输出受限双端队列**：允许在两端输入，只允许在一端输出；
* **解题方法**：遇到判定某个输出序列是否可能产生时，采用草稿纸左右两端排查法（一端进，两端出或相反），利用栈与队列的排除法逆向推演。

## 4. 闭环判定模型与核心认知结论

* **元素个数模运算口诀**：**“尾减头，加模数，再取模”** $\implies (\text{rear} - \text{front} + M) \% M$。
* **链式队列（带头结点）判空铁律**：`front->next == NULL` 或 `front == rear`。
