## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须将顺序队列改造为“循环队列”？
- **顺序队列的物理困境（假溢出）**：
  - 顺序队列以固定一维数组 `data[MaxSize]` 存储。若采用静态单向推进：队尾指针 `rear` 随入队单调递增，队头指针 `front` 随出队单调递增。
  - 经过多轮“入队-出队”交替后，`rear` 触达数组最大上限 `MaxSize`，此时继续入队将报错“队满”；但实际上，数组前半部分随着元素出队已腾出大片空闲内存！这种**“数组有物理空闲却报溢出”**的现象称为**假溢出（False Overflow）**。
- **循环队列的取模寻址机制**：
  - 将一维线性数组在逻辑上闭合为一个环状表盘，利用**模除运算（Modulo Arithmetic）**实现指针回绕：
    - 入队推进：`rear = (rear + 1) % MaxSize`
    - 出队推进：`front = (front + 1) % MaxSize`

---

### (2) 循环队列的核心矛盾：判空与判满的特征重叠及三大化解方案

在不引入额外状态时，队空与队满均表现为 `front == rear`。为消除歧义，有三种经典的硬件与软件化解方案：

#### 方案一：牺牲一个存储单元（408 考场基准模型）
- 数组大小为 `MaxSize`，但实际最多只容纳 `MaxSize - 1` 个元素。
- **队空条件**：`front == rear`
- **队满条件**（队尾指针的下一个槽位迎面撞上队头指针）：
  $$(\text{rear} + 1) \% \text{MaxSize} == \text{front}$$
- **当前队列有效元素个数**：
  $$\text{length} = (\text{rear} - \text{front} + \text{MaxSize}) \% \text{MaxSize}$$

#### 方案二：结构体增设 `size` 计数器
- 引入全局计数器 `int size = 0`，随入队递增、随出队递减。
- **队空条件**：`size == 0`；**队满条件**：`size == MaxSize`。
- 允许用满全部 `MaxSize` 个存储单元。

#### 方案三：增设 `tag` 状态标志位
- 引入 `int tag` 记录最近一次成功的操作类型：入队置 `tag = 1`，出队置 `tag = 0`。
- **队空条件**：`front == rear && tag == 0`（由出队导致相遇，必为空）；
- **队满条件**：`front == rear && tag == 1`（由入队导致相遇，必为满）。

#### 考点变体：队尾指针指向的物理差异

| 指针约定变体 | 入队操作执行顺序 | 初始空状态赋值 | 牺牲单元法队满条件 |
| :--- | :--- | :--- | :--- |
| **变体 A：`rear` 指向队尾下一个可用空位**<br>(408 默认主流约定) | `data[rear] = x;`<br>`rear = (rear + 1) % MaxSize;` | `front = 0;`<br>`rear = 0;` | `(rear + 1) % MaxSize == front` |
| **变体 B：`rear` 指向当前队尾有效元素** | `rear = (rear + 1) % MaxSize;`<br>`data[rear] = x;` | `front = 0;`<br>`rear = MaxSize - 1;` | `(rear + 2) % MaxSize == front` |

### (3) 链式队列末节点出队的“野指针悬垂”致命陷阱

带头结点的链式队列结构中：`front` 指向头结点，`rear` 指向队尾最后一个数据节点。
- **出队常规逻辑**：
  ```c
  p = front->next;       // p 指向队头数据节点
  front->next = p->next; // 头结点接管后续节点
  free(p);               // 释放队头节点
  ```
- **单元素出队边界危机**：
  - 当队列中**仅剩 1 个数据节点**时，满足 `front->next == rear`，即 `p` 与 `rear` 指向同一个节点。
  - 若直接执行 `free(p)`，则 `rear` 指针指向的内存被操作系统回收，**`rear` 变成了一个野指针（Dangling Pointer）**！
  - 随后的入队操作若执行 `rear->next = s;`，将直接向已被释放的无效内存区域写入数据，引发致命段错误（SIGSEGV）或堆损坏。
- **防御修复规范**：
  ```c
  if (rear == p) {
      rear = front; // 将队尾指针重置回头结点，使队列安全归为空状态
  }
  ```

### (4) 受限双端队列（Restricted Deques）操作轨迹与可达性推演

设输入元素序列为 `1, 2, 3, 4`，依次入队。分析两个输出候选序列在输入受限与输出受限条件下的物理可达性：

```
                    ┌──────────────────────────────┐
  End 1 (端 1/左端)  │           双端队列           │  End 2 (端 2/右端)
  ◄───────────────► │                              │  ◄───────────────►
                    └──────────────────────────────┘
```

#### 1. 序列 `4, 1, 3, 2` 可达性对比推演

##### 在输入受限双端队列中（仅允许从端 1 入，端 1 和端 2 均可出）：
- **目标**：输出 `4, 1, 3, 2`。
- **推演轨迹**：
  1. 元素 `1, 2, 3, 4` 依次从端 1 压入，队列内部状态为：端 1 `[4, 3, 2, 1]` 端 2。
  2. 第 1 个输出 `4`：从端 1 出队。剩余：端 1 `[3, 2, 1]` 端 2。
  3. 第 2 个输出 `1`：从端 2 出队。剩余：端 1 `[3, 2]` 端 2。
  4. 第 3 个输出 `3`：从端 1 出队。剩余：端 1 `[2]` 端 2。
  5. 第 4 个输出 `2`：从端 1 出队。
- **结论**：**可达（合法）**！

##### 在输出受限双端队列中（端 1 和端 2 均可入，仅允许从端 1 出）：
- **目标**：输出 `4, 1, 3, 2`。
- **推演矛盾**：
  - 所有元素必须从端 1 离开。要让 `4` 第一个离开端 1，`4` 必须是最后从端 1 压入且位于端 1 顶端。
  - 此时 `1` 若要紧接着 `4` 出队，在 `4` 离开后 `1` 必须直接暴露在端 1 顶端。这要求在 `4` 入队前，`1` 必须排在最靠近端 1 的位置。
  - 但随后要求的输出是 `3`，再随后是 `2`。然而此时在端 1 侧，`2` 排在 `3` 的外层（阻挡着 `3`），只能先输出 `2` 再输出 `3`。
- **结论**：**不可达（非法）**！

---

#### 2. 序列 `4, 2, 1, 3` 可达性对比推演

##### 在输入受限双端队列中（仅允许从端 1 入，端 1 和端 2 均可出）：
- **推演矛盾**：
  - 要让 `4` 第一个出队，所有元素必须先全部入队，队列为：端 1 `[4, 3, 2, 1]` 端 2。
  - 从端 1 弹出 `4` 后，队列两端的暴露出队位置分别为 `3`（端 1）和 `1`（端 2）。
  - 当前两端可输出的候选元素只有 `3` 和 `1`，而要求的下一个输出是 `2`。`2` 深埋在队列中间，无法越过端头的 `3` 或 `1` 提前出队。
- **结论**：**不可达（非法）**！

##### 在输出受限双端队列中（端 1 和端 2 均可入，仅允许从端 1 出）：
- **推演轨迹**：
  1. `1` 入队：端 1 `[1]` 端 2。
  2. `2` 从端 1 入队：端 1 `[2, 1]` 端 2。
  3. `3` 从端 2 入队：端 1 `[2, 1, 3]` 端 2。
  4. `4` 从端 1 入队：端 1 `[4, 2, 1, 3]` 端 2。
  5. 此时全部元素都在队列中，端 1 顺次出队：`4` 出、`2` 出、`1` 出、`3` 出。
- **结论**：**可达（合法）**！

> [!IMPORTANT]
> **对比认知结论**：
> 序列 `4, 1, 3, 2` 在输入受限队列合法、在输出受限队列非法；而序列 `4, 2, 1, 3` 在输入受限队列非法、在输出受限队列合法。二者构成了完美的互补排他反例。

## 4. 闭环判定模型与核心认知结论

### (1) 循环队列核心公式闭环表

| 判别维度 | 牺牲一个单元法 | 增设 size 计数器法 | 增设 tag 状态法 |
| :--- | :--- | :--- | :--- |
| **队空条件** | `front == rear` | `size == 0` | `front == rear && tag == 0` |
| **队满条件** | `(rear + 1) % M == front` | `size == M` | `front == rear && tag == 1` |
| **当前有效长度**| `(rear - front + M) % M` | `size` | 相等时依 tag 判定 0 或 M，不等时取模计算 |

### (2) 双端队列判定方法论
- **输入受限队列**：若出现多个元素已被压入队列内部，排在端头中间深处的元素无法跳过两端端点提前出队；
- **输出受限队列**：所有元素必须通过单一输出端口依次离开，等价于检验能否通过将元素分别从左右两端入队构造出目标排列。
