## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 顺序表的物理本质：物理连续与基址偏移
- **物理定义**：用一段地址连续的存储单元依次存储线性表的数据元素。在 C 语言中对应静态数组或 `malloc` 动态分配的堆内存。
- **随机存取（Random Access）的数学物理根源**：
  - 设首元素 $a_1$（逻辑位序从 1 开始）的基地址为 $\text{LOC}(a_1)$，每个元素占用 $L$ 字节；
  - 则第 $i$ 个元素 $a_i$ 的内存地址可由纯算术乘加运算一步得出：
    $$\text{LOC}(a_i) = \text{LOC}(a_1) + (i - 1) \times L$$
  - **硬件执行效能**：CPU 地址生成单元（AGU）在一个时钟周期内即可完成基址加变址计算，**获取任意第 $i$ 个元素的时间复杂度严格为 $O(1)$**。
  - **空间局部性优势**：连续物理排布使得顺序表遍历时能最大限度触发 CPU L1/L2 Cache 预取，大幅减少主存访存缺失（Cache Miss）。

### (2) 插入与删除算法的边界保护与挪动方向必然性

#### 1. 前置条件边界检查（防越界防御式设计）
- **插入操作**：在第 $i$ 个逻辑位置插入元素 $e$（参数：`SqList &L, int i, ElemType e`）
  - 满表判定：`L.length >= MaxSize` $\implies$ 无法插入，返回失败或触发扩容。
  - 合法位序：**$1 \le i \le \text{L.length} + 1$**（可在表头 $i=1$ 插入，亦可在表尾后一个位置 $i = \text{L.length} + 1$ 追加；超出该区间均属非法）。
- **删除操作**：删除第 $i$ 个逻辑位置的元素（参数：`SqList &L, int i, ElemType &e`）
  - 空表判定：`L.length == 0` $\implies$ 无元素可删，返回失败。
  - 合法位序：**$1 \le i \le \text{L.length}$**（超出该区间均属非法）。

#### 2. 挪动方向的物理必然性（5 元素数组追踪）

设初始顺序表有 5 个元素：`L.data = [10, 20, 30, 40, 50]`（`L.length = 5`），物理下标为 `0 ~ 4`。

```
逻辑位序:    1      2      3      4      5
物理下标:   [0]    [1]    [2]    [3]    [4]    [5]
数组元素:   10     20     30     40     50     (空)
```

##### 场景 A：在第 2 个位置（$i=2$）插入新元素 `99`
- **挪动方向物理定律**：必须**从后往前（从末尾元素开始向后搬）**！
  - 第 1 步：将下标 4 的 `50` 搬到下标 5 $\to$ `[10, 20, 30, 40, 50, 50]`
  - 第 2 步：将下标 3 的 `40` 搬到下标 4 $\to$ `[10, 20, 30, 40, 40, 50]`
  - 第 3 步：将下标 2 的 `30` 搬到下标 3 $\to$ `[10, 20, 30, 30, 40, 50]`
  - 第 4 步：将下标 1 的 `20` 搬到下标 2 $\to$ `[10, 20, 20, 30, 40, 50]`
  - 第 5 步：在空出的下标 1 写入 `99` $\to$ `[10, 99, 20, 30, 40, 50]`，`L.length = 6`。
- **反例证伪（若从前往后搬）**：
  - 若先将下标 1 的 `20` 复制到下标 2，则原下标 2 处的 `30` 立即被覆盖摧毁！后续所有元素将被连锁覆盖为 `20`，数据彻底损毁。

##### 场景 B：删除第 2 个位置（$i=2$）的原元素 `20`
- **挪动方向物理定律**：必须**从前往后（从被删元素后继开始向前搬）**！
  - 第 1 步：将下标 2 的 `30` 复制到下标 1 $\to$ `[10, 30, 30, 40, 50]`
  - 第 2 步：将下标 3 的 `40` 复制到下标 2 $\to$ `[10, 30, 40, 40, 50]`
  - 第 3 步：将下标 4 的 `50` 复制到下标 3 $\to$ `[10, 30, 40, 50, 50]`
  - 第 4 步：逻辑长度减 1（`L.length = 4`），原下标 4 标记为失效。最终有效列表为 `[10, 30, 40, 50]`。
- **反例证伪（若从后往前搬）**：
  - 若先将下标 4 的 `50` 复制到下标 3，则原下标 3 的 `40` 被提前覆盖，导致数据丢失。

### (3) 平均移动次数严谨概率推导（408 核心计算）

#### 1. 插入操作平均移动次数
- 在长度为 $n$ 的顺序表中插入元素，合法插入位置有 $n+1$ 个（$i = 1, 2, \dots, n+1$）。
- 在第 $i$ 个位置插入时，需移动其后所有元素共 $n - i + 1$ 个。
- 假设在各个位置插入的概率均等，即 $p_i = \frac{1}{n+1}$：
  $$E_{\text{insert}} = \sum_{i=1}^{n+1} p_i (n - i + 1) = \frac{1}{n+1} \sum_{i=1}^{n+1} (n - i + 1) = \frac{1}{n+1} \times \frac{n(n+1)}{2} = \frac{n}{2}$$
- **结论**：平均需移动表中约**一半（$\frac{n}{2}$）**的元素，时间复杂度为 **$O(n)$**。

#### 2. 删除操作平均移动次数
- 在长度为 $n$ 的顺序表中删除元素，合法删除位置有 $n$ 个（$i = 1, 2, \dots, n$）。
- 删除第 $i$ 个位置时，需移动其后所有元素共 $n - i$ 个。
- 假设删除各个位置的概率均等，即 $p_i = \frac{1}{n}$：
  $$E_{\text{delete}} = \sum_{i=1}^n p_i (n - i) = \frac{1}{n} \sum_{i=1}^n (n - i) = \frac{1}{n} \times \frac{n(n-1)}{2} = \frac{n-1}{2}$$
- **结论**：平均需移动 **$\frac{n-1}{2}$** 个元素，时间复杂度为 **$O(n)$**。

### (4) 动态扩容策略与均摊复杂度（Amortized Analysis）

当静态预分配数组满载时，必须动态扩展容量。动态顺序表（如 C++ `std::vector`）采用倍增扩容策略：

```c
void expand(SqList &L) {
    int new_cap = 2 * L.MaxSize;
    ElemType *new_data = (ElemType *)malloc(sizeof(ElemType) * new_cap);
    for (int i = 0; i < L.length; i++) {
        new_data[i] = L.data[i]; // 搬迁旧元素：耗费 Theta(n)
    }
    free(L.data); // 释放旧连续内存块
    L.data = new_data;
    L.MaxSize = new_cap;
}
```

#### 为什么扩容必须“按倍数扩容（$\times 2$）”而不能“按固定增量扩容（$+C$）”？
1. **倍增扩容（几何级数增长）**：
   - 设初始容量为 1，连续执行 $n$ 次尾部插入（$n = 2^k$）。
   - 触发扩容的时机为容量达到 $1, 2, 4, 8, \dots, 2^k$。
   - 所有扩容步骤累计复制的元素总数为等比数列：
     $$\text{Total Copies} = 1 + 2 + 4 + 8 + \dots + 2^{\lfloor \log_2 n \rfloor} = 2^{\lfloor \log_2 n \rfloor + 1} - 1 < 2n$$
   - $n$ 次插入操作的总耗时 = $n \text{ (直接尾部写入)} + (< 2n) \text{ (扩容搬迁)} < 3n$。
   - **均摊时间复杂度（Amortized Time）**：$\frac{< 3n}{n} = \Theta(1)$！单次最坏情况虽为 $O(n)$，但平摊到每次插入上仅付出 $O(1)$ 常数级代价。
2. **固定增量扩容（算术级数增长）**：
   - 若每次满载时仅增加常数 $C$ 个空间，存入 $n$ 个元素需触发 $n / C$ 次扩容。
   - 累计搬迁次数为 $C + 2C + 3C + \dots + n \approx \frac{n^2}{2C} = \Theta(n^2)$。
   - 均摊单次插入成本退化为 $\Theta(n)$，工程上不可接受。

1. **与链表物理特性的互补对照**：
   - [单链表与双链表](02-linked-list.md)：顺序表空间利用率高（存储密度为 1），查询第 $i$ 个元素为 $O(1)$；链表增删节点仅需修改指针无需搬动数据，但在堆中需承担指针元数据与结构体对齐开销。
2. **为什么折半查找（二分查找）严格绑定顺序存储？**：
   - 许多学习者误以为“只要单链表中的元素递增有序，就能实现 $O(\log n)$ 折半查找”。
   - **机理辨析**：折半查找计算中点 `mid = (low + high) / 2` 仅需 1 个算术周期，在顺序表中访问 `data[mid]` 为 $O(1)$；但在有序单链表中，从当前位置跳转到 `mid` 必须顺序解引用遍历 $\approx n/2$ 个指针，单次定位即耗费 $\Theta(n)$，导致整体算法退化为 $\Theta(n)$，完全丧失对数查找优势。
3. **与树形结构的数组映射**：
   - [树与二叉树性质](../04-tree/01-binary-tree-properties.md)：完全二叉树的顺序存储借助顺序表的下标换算（左孩子 $2i$，右孩子 $2i+1$），省去了左右子树指针的存储开销。

## 4. 闭环判定模型与核心认知结论

### (1) 考场计算核心公式对照

| 考查维度 | 核心公式 | 适用约束与边界 |
| :--- | :--- | :--- |
| **第 $i$ 个元素物理地址** | $\text{LOC}(a_i) = \text{LOC}(a_1) + (i - 1) \times L$ | 逻辑位序 $i$ 从 1 开始，单元素占 $L$ 字节 |
| **插入合法位置** | $1 \le i \le n + 1$ | 插入到表尾追加时 $i = n+1$，挪动 0 个元素 |
| **插入平均移动次数** | $E_{\text{insert}} = \frac{n}{2}$ | 假定 $n+1$ 个插入位置等概率 |
| **删除合法位置** | $1 \le i \le n$ | 删除表尾元素时 $i = n$，挪动 0 个元素 |
| **删除平均移动次数** | $E_{\text{delete}} = \frac{n - 1}{2}$ | 假定 $n$ 个删除位置等概率 |
| **倍增扩容均摊时间** | $\text{Amortized } \Theta(1)$ | 扩容因子 $\times 2$，总复制量受公比 2 截断 |

### (2) 闭环决策速记法则
- **位序与下标对齐**：题目凡说“第 $i$ 个元素”，C 语言对应下标必为 `[i-1]`。
- **挪动方向口诀**：**插入从后往前倒着腾，删除从前往后顺着填**，反向必导致数据覆写丢失。
