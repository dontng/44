## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须引入“头结点（Dummy Head Node）”？
- **物理困境（无头结点的不一致性）**：
  - 若链表不带头结点，`head` 直接指向第一个存储有效数据的节点。
  - 当在第 1 个位置插入节点时，必须直接修改外部的头指针变量 `head` 本身；而在第 2 个及后续位置插入时，修改的是前驱节点的 `next` 指针。
  - 删除第 1 个节点时同理，必须重置 `head = head->next`。这迫使所有增删算法必须引入 `if (i == 1)` 或 `if (p == head)` 的特殊分支，极易产生空指针异常。
- **头结点的解题价值**：
  1. **操作统一**：第 1 个有效数据节点拥有了固定的前驱（即头结点），使得在表头、表中、表尾的插入与删除操作共享完全相同的指针赋值逻辑。
  2. **判空统一**：无论链表是否为空，`head` 指针永远非空（始终指向有效分配的头结点内存），判空条件规范化为 `head->next == NULL`。

### (2) 常见链表类型的判空与操作效率对照表

| 链表类型 | 判空条件 | 访问表头时间 | 访问表尾时间 | 删除表尾时间 | 适用工程场景 |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **带头结点单链表** | `L->next == NULL` | $O(1)$ | $\Theta(n)$ | $\Theta(n)$ | 常规单向顺序访问 |
| **不带头结点单链表** | `L == NULL` | $O(1)$ | $\Theta(n)$ | $\Theta(n)$ | 极度苛求节省头结点指针开销 |
| **仅设头指针的循环单链表** | `L->next == L` | $O(1)$ | $\Theta(n)$ | $\Theta(n)$ | 环形轮询任务 |
| **仅设尾指针的循环单链表** | `rear->next->next == rear->next` | $O(1)$ | **$O(1)$** | $\Theta(n)$ | 需高频访问表头和表尾（如模拟队列） |
| **双向循环链表** | `L->next == L && L->prior == L` | $O(1)$ | **$O(1)$** | **$O(1)$** | 频繁双向扫描与两端增删 |

> [!TIP]
> **尾指针循环单链表的 $O(1)$ 寻址特征**：
> - 找表尾：直接访问 `rear`，时间为 $O(1)$。
> - 找表头（第一个数据节点）：访问 `rear->next->next`（跳过头结点 `rear->next`），时间亦为 $O(1)$。

### (3) 指针操作经典执行链与物理断链防御

#### 1. 单链表节点删除操作
欲删除节点 $p$ 的后继节点 $q$：
```c
q = p->next;       // 1. 暂存待删除节点的地址，防野指针
p->next = q->next; // 2. 前驱直接跨过 q 指向后继（摘除节点）
free(q);           // 3. 显式释放堆内存，防内存泄漏
```

> [!WARNING]
> **单链表尾指针删除的不对称性陷阱**：
> - 很多初学者误以为“单链表只要增加一个尾指针 `tail`，就能使尾部插入和尾部删除都达到 $O(1)$”。
> - **物理必然性分析**：
>   - 尾部插入：执行 `tail->next = s; tail = s;`，仅需两步，确为 $O(1)$。
>   - 尾部删除：删除 `tail` 节点后，`tail` 必须向前回退更新为**倒数第二个节点（`tail` 的前驱）**。然而单链表只有单向 `next` 指针，无法逆向寻找前驱！寻找该前驱节点必须从 `head` 出发完整遍历整个链表（耗费 $\Theta(n)$）。因此，**带尾指针的单链表尾部删除依然是 $\Theta(n)$**！
>   - 只有双向链表（通过 `tail->prior` 在 $O(1)$ 获知前驱）或仅设尾指针的循环单链表删除表头，才能实现两端纯 $O(1)$ 操作。

#### 2. 单链表原地逆置（In-place Reversal）两大标准范式

设单链表带头结点 `L`，数据为 `1 -> 2 -> 3 -> NULL`。

##### 方法一：头插法逐个摘下重挂（语义清晰）
- **核心逻辑**：保留头结点 `L`，将其后继断开；依次取出后续节点，采用头插法重新插入到 `L` 之后。
```c
void reverse_head_insert(LinkList L) {
    LNode *p = L->next; // p 指向当前待处理节点
    L->next = NULL;     // 断开头结点，将其作为初始逆置链表的尾端
    while (p != NULL) {
        LNode *nxt = p->next; // 暂存未处理的后序链表
        p->next = L->next;    // 头插：新节点指向当前逆置链表的首节点
        L->next = p;          // 头结点指向新节点
        p = nxt;              // 推进到下一个待处理节点
    }
}
```

##### 方法二：三指针迭代滑动（`pre`, `cur`, `nxt`）
- **核心逻辑**：维护三个指针，单向滑动，步步逆转局部指针朝向。
```c
LNode* reverse_three_pointers(LNode *head) {
    LNode *pre = NULL;
    LNode *cur = head;
    while (cur != NULL) {
        LNode *nxt = cur->next; // 1. 记录下一个前进位置
        cur->next = pre;        // 2. 翻转指针朝向
        pre = cur;              // 3. pre 前进
        cur = nxt;              // 4. cur 前进
    }
    return pre; // 循环终止时 cur == NULL，pre 成为新头节点
}
```

##### 3 节点执行轨迹追踪（`1 -> 2 -> 3 -> NULL`）

| 循环轮次 | 动作前状态 (`pre, cur, nxt`) | 执行 `cur->next = pre` 后的指向关系 | 指针步进后状态 (`pre, cur`) |
| :---: | :--- | :--- | :--- |
| **初始** | `pre = NULL, cur = 1` | `1 -> 2 -> 3 -> NULL` | `pre = NULL, cur = 1` |
| **轮次 1** | `pre = NULL, cur = 1, nxt = 2` | `1 -> NULL` | `pre = 1, cur = 2` |
| **轮次 2** | `pre = 1, cur = 2, nxt = 3` | `2 -> 1 -> NULL` | `pre = 2, cur = 3` |
| **轮次 3** | `pre = 2, cur = 3, nxt = NULL`| `3 -> 2 -> 1 -> NULL` | `pre = 3, cur = NULL` |
| **结束** | `cur == NULL`，循环退出 | 最终链表：`3 -> 2 -> 1 -> NULL`，返回 `pre` (3) | - |

- **边界容错性**：若输入链表为空（`head == NULL`），直接返回 `NULL`；若只有单节点（`head->next == NULL`），执行 1 轮后返回原节点，均安全无崩溃。

#### 3. 链表合并的两大截然不同模型

##### 模型 A：仅设尾指针的两个循环单链表 $O(1)$ 快速拼接
设两个循环单链表的尾指针分别为 `rearA` 和 `rearB`，欲将其拼接为一个大的循环单链表：
```c
LinkList merge_circular(LinkList rearA, LinkList rearB) {
    LNode *headA = rearA->next;       // 1. 保存链表 A 的头结点
    rearA->next = rearB->next->next;  // 2. A 的尾部直接指向 B 的首个数据节点
    free(rearB->next);                // 3. 释放 B 的冗余头结点
    rearB->next = headA;              // 4. B 的尾部指向 A 的头结点，闭合大环
    return rearB;                     // 返回合并后的新尾指针
}
```
- **复杂度**：仅执行 4 步指针赋值与释放，**时间复杂度严格为 $O(1)$**。

##### 模型 B：两个有序单链表的有序归并（$\Theta(m+n)$）
- 两个递增有序链表 $A$（长 $m$）与 $B$（长 $n$），归并为一个递增链表：
- 每次比较两指针当前元素的大小，将较小者摘下挂接到新链表尾部；
- 当其中一个链表为空时，另一个链表的剩余整段可以在 $O(1)$ 时间内**整块挂接**到表尾（`tail->next = (pA ? pA : pB);`）。
- **复杂度**：元素比较次数最多为 $m + n - 1$，指针修改次数为 $O(m+n)$，**时间复杂度为 $\Theta(m+n)$**。

### (4) 快慢指针（Slow/Fast Pointers）模型与精确边界控制

#### 1. 查找链表倒数第 $k$ 个节点（滑动窗口模型）
- **核心算法**：
  1. 边界检查：若 $k \le 0$ 或 `head == NULL`，直接返回非法。
  2. 让快指针 `fast` 从首节点开始先行向前走 $k$ 步。
     - 若在未走满 $k$ 步时 `fast` 提前遇到 `NULL`，说明链表总长度 $n < k$，此时**安全返回 NULL（或 0）**，绝不引发非法解引用。
  3. `fast` 成功走满 $k$ 步后，慢指针 `slow` 从首节点出发，与 `fast` 同步单步向前推进。
  4. 当 `fast == NULL`（指向尾节点之后的空指针）时，`slow` 恰好指向倒数第 $k$ 个节点。

#### 2. 寻找链表中点的左右中点偏差判定（偶数长度 $n=2m$）
设链表节点数为偶数（如 4 个节点 `A -> B -> C -> D`，长度 $n=4$）：
- **定位到左中点（第 2 个节点 `B`）**：
  - 初始化：`slow = head->next; fast = head->next;`
  - 循环条件：`while (fast->next != NULL && fast->next->next != NULL)`
  - 步进：`slow = slow->next; fast = fast->next->next;`
  - 追踪：第 1 轮步进后 `slow = B, fast = C`；此时 `fast->next->next == NULL`，循环退出，`slow` 准确停在**左中点 `B`**。
- **定位到右中点（第 3 个节点 `C`）**：
  - 初始化：`slow = head->next; fast = head->next;`
  - 循环条件：`while (fast != NULL && fast->next != NULL)`
  - 步进：`slow = slow->next; fast = fast->next->next;`
  - 追踪：第 1 轮步进后 `slow = B, fast = C`；第 2 轮步进后 `slow = C, fast = NULL`，循环退出，`slow` 停在**右中点 `C`**。

## 4. 闭环判定模型与核心认知结论

### (1) 链表操作核心特征速查表

| 操作场景 | 推荐链表形态 | 关键指针代码操作 | 复杂度 |
| :--- | :--- | :--- | :---: |
| **仅在首尾两端高频插入** | 仅设尾指针的循环单链表 | `rearA->next = rearB->next->next` | $O(1)$ |
| **任意位置前驱后继双向查找** | 双向循环链表 | `p->prior` 与 `p->next` | $O(1)$ |
| **单链表原地逆置** | 带头结点单链表 | 头插法重挂或三指针单向推进 | $\Theta(n)$ 时间, $O(1)$ 空间 |
| **环路检测与中点定位** | 快慢双指针 | 慢指针 1 步，快指针 2 步 | $\Theta(n)$ 时间, $O(1)$ 空间 |

### (2) 指针操作防御铁律
- **修改指针永远“先连后断”**：先将新节点的出边链接妥当，再切断原链表的前驱指针；
- **释放内存必须“先存后放”**：删除节点必须先用临时指针保存 `next` 目标，再调用 `free()`，杜绝野指针和断链崩溃。
