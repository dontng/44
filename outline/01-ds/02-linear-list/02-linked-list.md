## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须引入“头结点”？
* **物理矛盾**：若无头结点，在链表第 1 个位置插入或删除节点时，必须直接修改外部的头指针 `head` 本身；而在第 2 个及后续位置操作时，修改的是前驱节点的 `next` 指针。代码必须用 `if (i == 1)` 做特殊分支处理。
* **头结点的统一化作用**：
  1. **操作统一**：第 1 个有效数据节点也有了前驱（即头结点），使得在第 1 个位置的插入/删除操作与在其他位置的操作逻辑完全一致；
  2. **判空统一**：无论链表是否为空，头指针 `head` 永远指向一个分配好的有效头结点（`head != NULL`），判空只需判断 `head->next == NULL`。

### (2) 常见链表类型的边界与判空判定表（408 选择题高频）

| 链表类型 | 判空条件 | 找表头时间 | 找表尾时间 | 适合场景 |
| :--- | :--- | :---: | :---: | :--- |
| **带头结点单链表** | `L->next == NULL` | $O(1)$ | $O(n)$ | 常规单向遍历 |
| **不带头结点单链表** | `L == NULL` | $O(1)$ | $O(n)$ | 极度节省单个指针空间 |
| **带头结点循环单链表** | `L->next == L` | $O(1)$ | $O(n)$（若设头指针）<br>**$O(1)$（若仅设尾指针 rear）** | 环形任务、约瑟夫环 |
| **双向循环链表** | `L->next == L && L->prior == L` | $O(1)$ | $O(1)$（`L->prior` 即为尾节点） | 需前后双向高频扫描 |

> **关键考点（仅设尾指针的循环单链表）**：
> 若一个循环单链表经常需要在表头和表尾做插入删除（如模拟队列），最巧妙的做法是**仅设置一个指向表尾的指针 `rear`**！
> * 找表尾：直接访问 `rear`，时间复杂度 $O(1)$；
> * 找表头：通过 `rear->next->next`（跳过头结点）直接找到，时间复杂度也是 $O(1)$！合并两个链表只需 $O(1)$。

### (3) 指针修改顺序的物理铁律（防止断链）

#### 1. 单链表在节点 $p$ 后插入节点 $s$
* **必须先连后断**：
  ```c
  s->next = p->next; // 1. 先让新节点指向后继（拉住后面的队伍）
  p->next = s;       // 2. 再让前驱指向新节点（切断旧联系）
  ```
* **若顺序颠倒**：先执行 `p->next = s`，则原本 $p$ 后面的整个链表将彻底丢失在内存中，造成内存泄漏和断链崩溃！

#### 2. 双链表在节点 $p$ 后插入节点 $s$
* **四步连线法则（防空指针）**：
  ```c
  s->next = p->next;
  if (p->next != NULL) p->next->prior = s; // 注意若 p 是尾节点，不可直接访问 NULL->prior！
  s->prior = p;
  p->next = s;
  ```

## 4. 闭环判定模型与核心认知结论

* **快慢指针模型（双指针法，408 大题高频考点）**：
  * **找链表中间节点**：慢指针走 1 步，快指针走 2 步；快指针到表尾时，慢指针恰在正中间。
  * **判断链表是否有环**：快慢指针同时从头出发，若有环两者必在环内相遇；若无环快指针先遇 `NULL`。
  * **找倒数第 $k$ 个节点（2009-42 大题原型）**：快指针先走 $k$ 步，随后两指针同步走，快指针到 `NULL` 时慢指针恰好指向倒数第 $k$ 个。
