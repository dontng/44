## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) AOV 网与拓扑排序：先后次序与死锁检测
- **物理本质**：
  - 在工程排期或编译依赖中，某些子任务必须在另一些任务全部完成后方可启动（如“修读高等数学”必须在“修读微积分”之前）。
  - **AOV 网**：用**顶点**表示活动/任务，用**有向边** $\langle u, v \rangle$ 表示活动 $u$ 必须先于活动 $v$ 进行的前驱依赖。
- **拓扑排序（Topological Sort）算法核心机制（Kahn 算法）**：
  1. 统计全图所有顶点的入度（In-degree）。
  2. 从图中选择一个**入度为 0** 的顶点（说明其没有任何前驱约束，可以立刻开工），将其输出到拓扑序列中。
  3. 从图中删除该顶点，并删除以此顶点为起点的所有有向出边（即将其后继顶点的入度各减 1）。
  4. 重复上述步骤 2 和 3，直到：
     - 若**所有顶点均被输出**：拓扑排序成功，图是有向无环图（DAG）。
     - 若**还有剩余顶点未被输出，但已无入度为 0 的顶点**：说明剩余顶点之间**存在有向闭环（死锁环）**，拓扑排序失败。
- **拓扑排序的非唯一性**：
  在任意挑选入度为 0 的节点时，若候选池中同时存在多个入度为 0 的顶点，**选取任意一个均合法**，因此一个 DAG 的拓扑序列通常不是唯一的。

### (2) AOE 网与关键路径：工期极限与松弛余量
- **物理本质**：
  - **AOE 网**：以**顶点表示事件**（瞬时状态，如“基础工程竣工”），以**有向边表示活动**（持续过程，边权为持续耗时，如“浇筑混凝土耗时 5 天”）。
  - **工期极限（瓶颈路径）**：一个工程能够顺利完工的最短时间，取决于从工程源点到汇点的**最长路径长度（即持续时间最长的路径）**，称为**关键路径（Critical Path）**。因为所有平行的支线任务都必须等待这条耗时最长的路径完成，全工程才算真正完工。

#### 四大核心时间参数计算全流程（考场必须闭环推导）

```
               活动 a_i (持续时间 duration)
事件 v_k ────────────────────────────────────► 事件 v_j
(ve[k], vl[k])                                 (ve[j], vl[j])
```

1. **事件最早发生时间 $ve(k)$（正向顺推，取大值）**：
   - 只有指向事件 $k$ 的所有前驱活动全部完工，事件 $k$ 才能发生。
   - 从源点开始，令 $ve(\text{源点}) = 0$。
   - 沿拓扑顺序正向递推：
     $$ve(k) = \max_{\text{所有前驱 } p} \big( ve(p) + \text{weight}(p, k) \big)$$
2. **事件最迟发生时间 $vl(k)$（反向逆推，取小值）**：
   - 事件 $k$ 的推迟发生绝不能拖延整个工程的总工期。
   - 令汇点的最迟发生时间等于其最早发生时间：$vl(\text{汇点}) = ve(\text{汇点})$。
   - 沿逆拓扑顺序反向递推：
     $$vl(k) = \min_{\text{所有后继 } s} \big( vl(s) - \text{weight}(k, s) \big)$$
3. **活动最早开始时间 $e(i)$**：
   - 活动 $a_i$ 只要其弧尾事件一发生就可以立刻启动：
     $$e(i) = ve(\text{弧尾事件})$$
4. **活动最迟开始时间 $l(i)$**：
   - 活动 $a_i$ 最迟必须在何时开工，才不会让其弧头事件逾期：
     $$l(i) = vl(\text{弧头事件}) - \text{duration}(a_i)$$
5. **时间余量（Slack）与关键活动判定**：
   - 活动 $a_i$ 的松弛余量（时差）为：$d(i) = l(i) - e(i)$。
   - **当且仅当 $l(i) == e(i)$（即时差 $d(i) = 0$）时，活动 $a_i$ 为关键活动**。关键活动没有任何拖延余地，拖延一天直接导致总工期推迟一天。

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 数据结构: DAG 拓扑排序与 AOE  │
                     └──────────────┬───────────────┘
                                    │ 死锁检测与指令并行调度
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 操作系统: 进程死锁与资源图    │         │ 计组: 指令流水线数据相关 RAW │
│  - 资源分配图化简            │ ◄────── │  - 依赖有向图与乱序调度      │
│  - 环路等价于死锁            │         │  - 关键路径决定指令退休延迟  │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与操作系统死锁检测（资源分配图化简）的同构性**：
   - 操作系统的资源分配图化简算法，物理本质与 AOV 网拓扑排序完全一致：寻找无阻塞（入度/资源满足条件）的进程节点剔除，若最终图完全化简，则无死锁；若残留环路，则发生了系统死锁。
2. **与指令流水线乱序执行（Out-of-Order）的映射**：
   - 现代超标量 CPU 中的指令调度器在硬件上将指令间的数据相关性（RAW）构建为动态 DAG，在无环依赖的就绪指令队列中并行发射执行，关键路径长度决定了代码段的理论最高 IPC（Instructions Per Cycle）。

## 4. 闭环决策模型与核心认知结论

### (1) 多关键路径工程压缩辨析（考场经典深水区）
- **现象**：一个 AOE 网中可能同时存在**两条或更多条并行的关键路径**。
- **压缩法则**：
  1. **单纯缩短某一条关键路径上的某一个活动，能否缩短整个工程的总工期？**
     - **绝大多数情况下不能！** 因为与之并行的其他关键路径长度没有改变，瓶颈依然存在。
  2. **如何真正缩短总工期？**
     - 必须缩短**所有关键路径上公共的那个关键活动**；
     - 或者，**同时缩短各条并行关键路径上的各自关键活动**，使所有关键路径长度同步递减。
  3. **压缩极限**：一个关键活动不能被无限制压缩，当它被压缩到一定程度时，它可能转变为非关键活动，而原先的次关键路径演变成了新的关键路径。

### (2) 考场定性闭环判据
1. **若一个有向图的邻接矩阵为三角矩阵** $\to$ 该图**必定不存在有向环**，必定存在拓扑序列。
2. **若一个图存在拓扑序列** $\to$ 其顶点编号可以被重排，使得重排后的邻接矩阵为**严格上三角（或严格下三角）矩阵**。
3. **关键路径是 AOE 网中从源点到汇点的最长路径还是最短路径？** $\to$ **从源点到汇点的最长路径**！
