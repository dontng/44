## 2. 核心机理与五步推演

### (1) 为什么图遍历必须引入 `visited[]` 访问标记？

- **物理矛盾**：
  树结构拥有天然的单向分层拓扑（从根向下），绝无环路回路；而图是多对多无向或有向网状结构，回路普遍存在。若直接套用树的遍历逻辑，指针将在环路中陷入**无限死循环与递归栈溢出**。
- **物理防线**：
  必须开辟一个全局布尔状态数组 `bool visited[MAX_VERTEX_NUM]`。在访问一个顶点时将其置为 `true`，向邻接点推进前必须严格判断 `!visited[w]`。

---

### (2) 广度优先搜索（BFS）与深度优先搜索（DFS）标准算法实现

#### ① 广度优先搜索（BFS）算法实现
```c
bool visited[MAX_VERTEX_NUM];

void BFSTraverse(Graph G) {
    for (int v = 0; v < G.vexnum; ++v)
        visited[v] = false;              // 初始化全局标记数组
    InitQueue(Q);                        // 初始化辅助先进先出队列
    for (int v = 0; v < G.vexnum; ++v) {
        if (!visited[v])
            BFS(G, v);                   // 对每个未访问的连通分量调用一次 BFS
    }
}

void BFS(Graph G, int v) {
    visit(v);
    visited[v] = true;                   // 【铁律】入队前即刻打上访问标记!
    EnQueue(Q, v);
    while (!IsEmpty(Q)) {
        DeQueue(Q, u);                   // 队头顶点 u 出队
        for (int w = FirstNeighbor(G, u); w >= 0; w = NextNeighbor(G, u, w)) {
            if (!visited[w]) {           // 检查邻接点 w 是否已受检
                visit(w);
                visited[w] = true;       // 【铁律】入队即打标，坚决不能等出队才标记!
                EnQueue(Q, w);
            }
        }
    }
}
```

#### ② 深度优先搜索（DFS）算法实现
```c
bool visited[MAX_VERTEX_NUM];

void DFSTraverse(Graph G) {
    for (int v = 0; v < G.vexnum; ++v)
        visited[v] = false;
    for (int v = 0; v < G.vexnum; ++v) {
        if (!visited[v])
            DFS(G, v);
    }
}

void DFS(Graph G, int v) {
    visit(v);
    visited[v] = true;                   // 访问并标记当前顶点
    for (int w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w)) {
        if (!visited[w]) {
            DFS(G, w);                   // 递归深入访问未曾探索的分支
        }
    }
}
```

### (3) BFS 关键时序陷阱：为什么“必须在入队时打标，绝对不能在出队时打标”？

#### ① 机制对比与逻辑崩溃追踪
- **正确规则**：发现未访问的邻接点 $w$ 时，**在将其推进队列（`EnQueue`）的同时，必须瞬间将 `visited[w]` 置为 `true`**！
- **错误写法（出队才打标）的灾难轨迹**：
  考虑经典的 4 顶点菱形无向图：
  - 顶点集：$V = \{0, 1, 2, 3\}$
  - 边集：$(0, 1), (0, 2), (1, 3), (2, 3)$

```
        1
      /   \
    0       3
      \   /
        2
```

若将标记动作推迟到“出队时”执行：
1. 从 0 出发：0 出队并标记 `visited[0] = true`；
2. 扫描 0 的邻居 1 和 2：两者均未被标记，将 1 和 2 入队（此时队列：`[1, 2]`，两者 `visited` 仍为 `false`）；
3. 顶点 1 出队并标记 `visited[1] = true`；扫描 1 的邻居 3：由于 3 尚未被标记，**将 3 推进队列**（此时队列：`[2, 3]`）；
4. 顶点 2 出队并标记 `visited[2] = true`；扫描 2 的邻居 3：**由于 3 此时仍躺在队列中未出队，其 `visited[3]` 依然是 `false`**！
5. 算法误以为 3 从未被发现，**再次将 3 推进队列**（此时队列：`[3, 3]`）！
6. **后果**：顶点 3 被重复入队并被二次访问。在稠密图或大图中，这种失序会导致队列结点指数级冗余爆炸，完全破坏 BFS 的时空复杂度下界。

### (4) 遍历序列唯一性与存储结构的必然因果

- **基于邻接矩阵存储**：
  从任意固定起点出发，由于邻接矩阵的行遍历严格按照顶点下标升序（$0, 1, \dots, |V|-1$）扫描，因此其 **DFS 遍历序列与 BFS 遍历序列是严格唯一的**。
- **基于邻接表存储**：
  邻接表中各边结点的挂载次序取决于具体的建图输入流（头插法、尾插法或乱序插入）。不同的边表链接顺序会导致出边遍历次序不同，因此其 **DFS/BFS 遍历序列是非唯一的**。

---

### (5) 图的连通性分析与完全图误区澄清

#### ① 连通分量计数与连通图判定
- 在 `TraverseGraph` 中，外层 `for` 循环中调用 `DFS` 或 `BFS` 的总次数，**严格等于该无向图的连通分量（Connected Components）个数**；
- 若从任意指定顶点 $v$ 出发仅调用一次 `DFS(G, v)`，遍历结束后的全局访问计数器满足：
  $$\text{visited 计数 } == |V| \iff \text{该无向图是连通图（Connected Graph）}$$

#### ② 关键概念纠偏：连通图 $\ne$ 完全图！
- **易错混淆**：一次 DFS 访问了全部 $|V|$ 个顶点，只能证明该图是一个**连通图**（图中任意两点之间均存在路径相通，最少仅需 $|V|-1$ 条边，例如一条简单的链式拓扑）；
- **完全图（Complete Graph）**：要求图中**任意两个不同顶点之间都必须存在一条直接相连的边**，无向完全图的边数严格恒等于 $\frac{|V|(|V|-1)}{2}$。不可将连通图妄断为完全图。

### (6) 欧拉通路（EL 路径）与欧拉回路判定机制

#### ① 严格概念统一
- **欧拉通路（Eulerian Trail / EL 路径）**：通过图中**每一条边且仅通过一次**的通路（开路径，起点与终点不同）；
- **欧拉回路（Eulerian Circuit）**：通过图中**每一条边且仅通过一次**的闭合回路（起点与终点相同，因此所有欧拉回路在广义上均属于欧拉通路的一种闭合特例）。

#### ② 无向图存在欧拉通路/回路的充要条件
设无向图 $G$ 至少包含一条边：
1. **基准连通性约束**：
   图中**所有非零度顶点（度数 $> 0$ 的顶点）必须属于同一个连通分量**。
   *(注：若题干已明确假定图为无孤立点的连通图，则直接执行一次 DFS 访问全顶点验证；若存在度为 0 的孤立点，孤立点不影响欧拉通路的构成，只要所有有边的顶点连通即可)*。
2. **奇数度顶点个数判定**：
   - **奇数度顶点数为 0** $\iff$ 存在欧拉回路（全图所有顶点度数均为偶数，任意顶点均可作为起点/终点）；
   - **奇数度顶点数严格为 2** $\iff$ 存在非闭合欧拉通路（这两个奇数度顶点必定**分别作为该通路的唯一起点和唯一终点**）；
   - **奇数度顶点数为其他任何数值**（如 1、3、4 等） $\implies$ **绝不存在欧拉通路**！
   *(握手定理证明：无向图所有顶点的度数之和等于 $2|E|$，必为偶数，因此图中奇数度顶点的总个数必然是偶数，绝不可能出现奇数个奇数度顶点)*。

### (7) 典型反例证伪（常见认知陷阱）

1. **反例 1：“从顶点 0 出发调用一次 DFS，若访问完了图的所有顶点，则该图必然是无向完全图。”**
   - **反例证伪**：错误。若 4 个顶点通过 3 条边连成一条单链：$0-1-2-3$。从 0 出发调用 DFS 一次即可遍历所有 4 个顶点，但该图边数仅为 3，远低于 4 阶完全图所需的 6 条边。它只是连通图，绝非完全图。
2. **反例 2：“BFS 算法中，在将顶点从队列头部取出（DeQueue）时再将其标记为已访问，对算法正确性没有任何影响。”**
   - **反例证伪**：错误。在菱形图 $0-1, 0-2, 1-3, 2-3$ 中，若出队才打标，顶点 3 会在 1 出队和 2 出队时被先后两次误判定为未受检，导致顶点 3 两次入队，破坏算法时空界限。
3. **反例 3：“只要一个无向图中有 2 个奇数度顶点，那么从任意一个顶点出发都能走出一条遍历所有边的欧拉通路。”**
   - **反例证伪**：错误。当且仅当以**这两个奇数度顶点中的某一个作为起点**出发时，才能遍历完所有边；若以度数为偶数的顶点作为起点出发，中途必定提前在起点或无路可走处卡死。

## 3. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型（学理解题口径） | 现代工程实现边界（工业级搜索引擎与图系统） |
| :--- | :--- | :--- |
| **DFS 递归实现** | 默认采用直接递归调用（依赖操作系统调用栈） | 工业图搜索（如网络爬虫深度遍历）绝对禁止纯递归以防几万层栈溢出（Stack Overflow），全面改用**显式用户态堆栈迭代模拟** |
| **BFS 队列规模** | 内存充足，队列无界开辟 | 真实大图（亿级节点）BFS 面临“前沿爆炸（Frontier Explosion）”，需采用**双向 BFS（Bidirectional BFS）**或外存切片分层遍历（Direction-optimizing BFS） |
| **连通性计算** | 多次调用 DFS/BFS 统计连通分量 | 动态图拓扑频繁变动时，普遍采用 **并查集（Union-Find）** 或 Tarjan 离线算法进行动态增量连通性维护 |

## 4. 跨章节与跨学科关联

### 1. 本学科内跨章节关联
- $\to$ 关联 [二叉树的遍历算法](../04-tree/02-tree-traversal.md)：
  - **共同机制**：DFS 与二叉树先序遍历同构（栈展开），BFS 与二叉树层次遍历同构（队列分层）。
  - **关键差异**：二叉树无环，不需要 `visited[]` 数组；图存在环路，必须通过全局标记数组打破回路。
  - **不可直接迁移的判据**：二叉树遍历无需考虑回边与交叉边；图遍历会产生树边、回边、前向边和横跨边，生成的是支撑树或森林。
- $\to$ 关联 [单源最短路径（Dijkstra）](04-shortest-path.md)：
  - **共同机制**：Dijkstra 算法本质上是基于优先权队列（最小堆）的带权广度优先搜索。
  - **关键差异**：未加权图的 BFS 依靠普通 FIFO 队列即可天然获得按边数计的最短路径；加权图必须按权值大小贪心出队松弛。
  - **不可直接迁移的判据**：对于带权图，普通 BFS 首次访问某顶点得到的路径长度不一定是最短路径。

### 2. 跨学科协同关联
- $\to$ 关联 [操作系统 / 进程管理与死锁检测](../../03-os/02-process/06-deadlock.md)：
  - **共同机制**：操作系统检测死锁的“死锁定理”中，化简资源分配图的过程与 DFS 检测拓扑环路的逻辑高度相通。
  - **关键差异**：死锁化简基于寻找可释放资源的非阻塞节点；纯图 DFS 仅顺着有向边追索路径。
  - **不可直接迁移的判据**：单实例资源图中包含环路必定死锁；多实例资源分配图包含环路不一定死锁。

## 5. 核心考点自查清单与闭环判据

1. **BFS 打标死律**：
   - **入队即打标（EnQueue 时 `visited[w] = true`）**，绝不延后至出队。
2. **序列唯一性两步断定**：
   - 邻接矩阵 $\implies$ 遍历序列唯一；
   - 邻接表 $\implies$ 遍历序列非唯一（取决于邻接点挂载顺序）。
3. **欧拉路径快速判据**：
   - 连通性：所有非零度顶点同属一个连通块；
   - 奇数度顶点个数：
     - $0$ 个奇数度 $\implies$ 欧拉回路；
     - $2$ 个奇数度 $\implies$ 欧拉通路（起点和终点必为这两个奇数度顶点）；
     - 其余数值 $\implies$ 无欧拉通路。
