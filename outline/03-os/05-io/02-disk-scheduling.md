## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 机械磁盘的物理结构与“柱面优先编址”的物理本质
- **机械构造**：
  一个硬盘由多个同轴高速旋转的金属盘片构成。所有盘面的读写磁头被固定在**同一个机械传动臂**上，由音圈电机驱动**同步内外径移动**。
- **物理地址的三元组排列：`(柱面号, 磁头号, 扇区号)`**：
  - **为什么不是 `(磁头号, 柱面号, 扇区号)`？（考场极高频设问）**
    - **物理开销差异**：
      - 移动传动臂切换“柱面（磁道）”：涉及机械臂的物理加速、匀速位移与精确定位，**耗时在数毫秒（ms）级**；
      - 切换“磁头（盘面）”：所有盘面的磁头已经在同一个垂直圆柱面上，只需**通过电子开关电路在微秒（$\mu\text{s}$）内完成选通**，无任何机械位移！
    - **连续读写优化**：将柱面号放在高位、磁头号放在低位，当连续读取一个大文件时，操作系统先将同一个柱面上所有盘面的扇区全部读完（纯电子极速切换磁头），最后才万不得已移动一次机械臂跳到下一个柱面，将机械寻道开销压缩到极致！

### (2) 磁盘读写总耗时三大物理阶段方程

$$\text{磁盘总访问时间 } T_{\text{total}} = T_s (\text{寻道时间}) + T_r (\text{旋转延迟}) + T_t (\text{传输时间})$$

1. **寻道时间 $T_s$（机械臂移动到目标磁道耗时 —— 占绝对大头）**：
   $$T_s = m \times \Delta n + s$$
   其中 $m$ 为跨越一个磁道的常数位移耗时，$\Delta n$ 为移动磁道数，$s$ 为机械臂启动/制动时延。通常为 $3 \sim 10\text{ ms}$。
2. **旋转延迟 $T_r$（扇区旋转到磁头正下方耗时）**：
   - 设硬盘转速为 $r$ 转/分钟（RPM，如 7200 RPM 或 5400 RPM）：
   - 磁盘旋转一周的时间为 $T_{\text{rev}} = \frac{60}{r}\text{ s}$。
   - 磁头落在目标扇区前方的概率均匀分布，**平均旋转延迟恒等于旋转半周的耗时**：
     $$T_r = \frac{1}{2 \times r} = \frac{60}{2 \times r} \quad (\text{如 7200 RPM 时 } T_r \approx 4.17\text{ ms})$$
3. **传输时间 $T_t$（数据从扇区实际读出写入耗时）**：
   $$T_t = \frac{b}{r \times N}$$
   其中 $b$ 为待读写字节数，$N$ 为单个磁道的总容量字节数。通常仅需几十微秒。

### (3) 扇区交替编号（Interleaving）的物理必然性
- **物理现象**：
  磁头从盘面连续读出扇区 0 后，需要经过控制器处理并向内存传输，这段电子处理需要花费微小的延迟（如 0.5ms）。
  如果扇区物理排布是连续的：`[0] [1] [2] [3]...`
  当磁头读完扇区 0，控制器处理完毕准备读扇区 1 时，磁盘正在高速旋转，**扇区 1 恰好已经从磁头下方滑过飞走了**！磁头必须被迫苦苦等待磁盘再空转一整圈（白白损失 8.33ms）才能等来扇区 1。
- **工程解法：交替编号（错位编号）**：
  将逻辑上相邻的扇区在物理圆周上**隔位交叉排列**（如 `[0] [4] [1] [5] [2] [6]...`）。读完 0 之后处理耗时期间，盘面正好转过空闲插槽，处理完毕时扇区 1 严丝合缝地恰好转到磁头下方，实现零等待连续流式读取！

### (4) 四大磁头寻道调度算法的机理博弈（考场绝对焦点）

```
当前磁头位置: 100 号柱面 (假设往大号方向移动)
请求队列: 55, 58, 39, 18, 90, 160, 150, 38, 184
```

| 调度算法 | 磁头移动逻辑 | 优缺点与物理局限 | 饥饿现象 (Starvation) |
| :--- | :--- | :--- | :---: |
| **先来先服务 (FCFS)** | 严格按请求到达的先后顺序移动 | 最公平，无饥饿；但磁头反复横跳，**平均寻道距离极长，性能最差** | **无饥饿** |
| **最短寻道时间优先 (SSTF)** | 贪心策略：优先选择**距离当前磁头最近**的请求 | 平均寻道距离大幅缩短，吞吐量高；但磁头容易被局限在某一个区域反复震荡 | **严重饥饿**！<br>（远离磁头的边缘请求可能永久得不到响应） |
| **扫描算法 (SCAN / 电梯算法)** | 磁头沿固定方向移动，沿途服务所有请求，**直到最边缘端点才掉头反向服务** | 寻道性能极佳，彻底消除了 SSTF 的饥饿；但对刚被访问过的区域不公（两端等待周期不均） | **无饥饿** |
| **循环扫描 (C-SCAN)** | 磁头**单向移动服务**（如只从小到大）；到达最边缘后，**快速直接折返最外端（折返途中不服务任何请求）** | **消除了两端与中间等待时延的不均匀性**，全盘请求的平均等待时间高度均一稳定 | **无饥饿** |
| **LOOK 与 C-LOOK** | SCAN 与 C-SCAN 的微调：**只需到达请求队列中最远的一个请求位置即可掉头**，无需傻傻走到物理最外边缘 | 进一步减少了无谓的无效机械寻道行程，是工业界现代驱动的标准实现 | **无饥饿** |

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 操作系统: 磁盘调度与扇区管理   │
                     └──────────────┬───────────────┘
                                    │ 降低机械寻道时延
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 操作系统: 进程 CPU 调度算法   │         │ 计组: 存储层次结构与访问延迟 │
│  - FCFS 对应短作业优先 (SSTF) │ ◄────── │  - 机械寻道 (ms) 决定外存壁垒 │
│  - 电梯调度类似循环轮转公平性 │         │  - 固态硬盘 (SSD) 消除寻道延迟│
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与进程 CPU 调度算法的哲学同构**：
   - 磁盘调度中的 **FCFS** 与进程调度中的 **FCFS** 完全同构；
   - 磁盘中的 **SSTF（最短寻道优先）** 在设计哲学上等价于进程调度中的 **SJF（短作业优先）**，它们都在追求数学上的平均等待时间最小，但代价都是导致长作业/远端请求陷入**严重饥饿**。
2. **与现代固态硬盘（SSD）的底层对比**：
   - SSD 彻底消除了电机和机械臂，基于闪存芯片（Flash Memory）由门电路直接寻址，其寻道时间在物理上等于零。因此在 SSD 上，SCAN/SSTF 算法彻底失效，转而由磨损均衡（Wear Leveling）算法主导。

## 4. 闭环决策模型与核心认知结论

### (1) 考场计算平均寻道长度（柱面数）闭环步骤
1. **画出一维数轴**：将所有请求的磁道号按递增顺序标在数轴上，标出磁头当前起始位置和**移动方向**。
2. **按算法规则排列访问次序**：
   - 若是 **SSTF**：每次找距离当前点绝对值最近的点跳跃；
   - 若是 **SCAN**：沿指定方向一直走到最极值的请求（或题目要求的边缘磁道 0 或 199），再调转方向反向扫回；
   - 若是 **C-SCAN**：单向扫到最极值后，**瞬间跨越到另一端的最小极值请求点**，再继续同向扫描。
3. **计算绝对位移**：
   $$\text{平均寻道长度} = \frac{\sum |\text{当前磁道} - \text{下一个磁道}|}{\text{总请求个数 } N}$$

### (2) 考场定性闭环判据
1. **磁头寻道算法中唯一会产生饥饿现象的是哪一个？** $\to$ **SSTF（最短寻道时间优先）**。
2. **哪个算法能够提供最均匀、最平衡的等待服务时间？** $\to$ **C-SCAN（循环扫描算法）**。
3. **磁盘格式化分为哪两级？**
   - **低级格式化（物理格式化）**：划分物理扇区、写入扇区头尾及校验码；
   - **高级格式化（逻辑格式化）**：创建文件系统，写入超级块、位示图、inode 表及根目录。
