## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 程序从源码到物理内存的三阶演变
程序员编写的代码若想在物理硅片上被 CPU 执行，必须经历三个核心步骤：
1. **编译（Compile）**：将高级语言源代码翻译成目标模块（Object Modules，如 `.o` 文件）。此时指令中引用的是以 0 为基准的**逻辑地址（相对地址）**。
2. **链接（Link）**：将编译出的多个目标模块及所需的系统库函数装配成一个完整的装入模块（可执行文件，如 ELF）。
   - **静态链接**：在运行前将所有库代码完整拷贝并入单一可执行文件（体积大、浪费内存，但独立）；
   - **装入时动态链接**：在程序装入内存的同时边装入边链接；
   - **运行时动态链接（工业标准，如 `.so / .dll`）**：在程序执行过程中，只有实际执行到该函数调用时才动态将其调入内存并链接（支持多进程共享和内存热更新）。
3. **装入（Load）**：将可执行模块最终搬入真实的物理主存（DRAM）。

### (2) 重定位（Relocation）的物理本质：地址空间转换
- **物理困境**：
  在多任务并发系统中，多个程序同时在内存中运行，编译器在编译程序时根本无法预测该程序在未来会被操作系统加载到物理内存的哪一个具体基地址上。
- **两大装入/重定位方案深度对比**：

#### ① 静态重定位（可重定位装入，早期批处理）
- **机理**：在程序**装入内存的瞬间**，由操作系统装入程序一次性修改程序代码中所有的绝对地址指令（将逻辑地址统一加上物理装入基地址）。
- **物理缺陷**：
  - 一旦装入完成，程序内部地址被焊死，**在运行期间绝不能在物理内存中发生任何位置移动**；
  - 必须为程序分配一块严格连续的物理内存。

#### ② 动态重定位（动态运行时装入，现代标准）
- **机理**：程序装入内存时，**指令中的逻辑地址保持原样（0 偏移）完全不做任何修改**。
- **硬件支持**：CPU 内部 MMU 配备两个核心专用寄存器：
  - **重定位寄存器（基址寄存器 Base Register）**：存放该进程在内存中的物理起始基地址；
  - **界地址寄存器（限长寄存器 Limit Register）**：存放该进程的逻辑地址最大合法范围（长度）。
- **硬件实时地址转换流程**：
  ```
  CPU 发出逻辑地址 (LA)
          │
          ├────────────────────────┐
          ▼                        ▼
   【比较器检查】            【加法器转换】
   若 LA >= 限长值 Limit    物理地址 PA = LA + 基址 Base
          │                        │
          ▼ (越界)                 ▼
     触发【越界中断】       送往总线访问物理 DRAM
  ```
- **物理优势**：
  - 程序在运行过程中可以被操作系统任意搬移、换出到磁盘交换区、再换回内存的全新物理位置，操作系统只需在进程切换时原子更新 Base 寄存器数值即可。

### (3) 连续分配四大动态分区算法的博弈与碎片成因

#### ① 内部碎片 vs 外部碎片的绝对界定
- **内部碎片（Internal Fragmentation）**：**已经被分配给进程**，但进程本身使用不完而闲置浪费在分区内部的内存空间（如固定分区或分页的最后一页）。
- **外部碎片（External Fragmentation）**：**未被分配给任何进程**，由于容量太小、离散零碎，而无法满足任何一个新进程需求的内存空洞（动态分区的产物）。
  - **外部碎片消除手段**：内存紧凑技术（Compaction，即物理搬迁进程合并空洞，必须依赖动态重定位）。

#### ② 动态分区分配四大家族深度横向比对

| 算法名称 | 查找与匹配规则 | 空间与碎片演变趋势 | 综合性能评价 |
| :--- | :--- | :--- | :--- |
| **首次适应 (First Fit, FF)** | 从空闲链表**表头开始**顺序查找，使用**第一个**能满足大小的空闲分区 | 优先消耗低地址空间，将低地址切成细碎碎片；但在**高地址保留了完整的大空闲区** | **综合性能最好、运行速度最快**（考场首选推荐） |
| **循环首次适应 (Next Fit, NF)** | 从**上一次分配位置的下一个**空闲分区开始循环查找 | 空闲空洞在全内存空间均匀分布；但**过早分割消耗了高地址的大空闲区**，导致后续大作业无法载入 | 性能往往不如首次适应 |
| **最佳适应 (Best Fit, BF)** | 遍历所有空闲分区，挑选**能满足要求的最小空闲区**（空闲链表按容量升序排列） | 每次切割都保留最小的剩余部分，导致**产生大量极其微小的外部碎片**（极度恶化） | **最容易产生无法利用的微小外部碎片** |
| **最坏适应 (Worst Fit, WF)** | 遍历所有空闲分区，挑选**全局容量最大的空闲区**进行切割（空闲链表按容量降序排列） | 分割后剩余空洞依然较大，不易产生微小碎片；但**极速破坏系统中的大容量连续空间**，大进程很快饿死 | 缺乏大连续空间承载力 |

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 操作系统: 连续内存分配与重定位 │
                     └──────────────┬───────────────┘
                                    │ 物理连续性缺陷倒逼架构升级
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 操作系统: 分页与离散存储管理  │         │ 计组: 基址寻址硬件与 MMU     │
│  - 消除外部碎片的唯一出路    │ ◄────── │  - 基址寄存器 BR 硬件运算    │
│  - 纯分页仅留极小内部碎片    │         │  - 硬件越界比较保护          │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与基本分页/离散分配的物理因果承接**：
   - 动态分区分配的致命死穴是“外部碎片”以及随之而来的高昂“紧凑”开销。这直接倒逼了操作系统抛弃物理连续性，全面演进为固定大小的离散分页（Paging）架构。
2. **与计组基址寻址的软硬件一体化映射**：
   - 操作系统的“动态重定位”正是利用计组中 CPU 的“基址寻址”机制实现的。基址寄存器由操作系统内核以特权指令管理，对普通用户程序完全隐蔽。

## 4. 闭环决策模型与核心认知结论

### (1) 考场碎片类型绝对闭环速查
1. **单一连续分配** $\to$ 仅有严重的**内部碎片**（整机只有用户程序和 OS）。
2. **固定分区分配** $\to$ 产生大量**内部碎片**，**无外部碎片**。
3. **动态分区分配** $\to$ 产生大量**外部碎片**，**无内部碎片**。
4. **基本分页存储管理** $\to$ 仅在最后一个物理页产生微量的**内部碎片**（平均半个页），**无外部碎片**。
5. **基本分段存储管理** $\to$ 产生**外部碎片**，**无内部碎片**。

### (2) 考场定性闭环判据
1. **哪种动态分区算法综合性能最优秀？** $\to$ **首次适应算法（First Fit）**。
2. **哪种算法最容易产生大量无法利用的细小空洞？** $\to$ **最佳适应算法（Best Fit）**。
3. **实现动态重定位必须依赖什么？** $\to$ 必须依赖硬件级别的**重定位寄存器（Base）与限长寄存器（Limit）**在指令运行周期中实时相加与越界判断。
