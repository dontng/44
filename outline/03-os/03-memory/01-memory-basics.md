## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - **程序装入与链接全流程**：三种链接方式（静态链接、装入时动态链接、运行时动态链接）与三种装入方式（绝对装入、可重定位装入、动态运行时装入）的物理分水岭。

  - **动态分区分配与回收算法精算**：首次适应（FF）、邻近适应（NF）、最佳适应（BF）、最坏适应（WF）的手算追踪；内部碎片与外部碎片的严格判据及回收四种合并状态。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 程序从源码到物理执行的三阶转换

程序员书写的源程序（`.c` 等）若要最终在物理硅片上被 CPU 推进执行，必须经历编译、链接、装入三个阶段：

```
源代码 (.c/.cpp)
  │
  ▼ 编译 (Compile): 编译器将源代码翻译成目标模块，生成以 0 为基准的逻辑相对地址
目标模块 1 (.o) + 目标模块 2 (.o) + 系统库函数
  │
  ▼ 链接 (Link): 链接程序将各目标模块及所需库函数装配成一个完整的装入模块
装入模块 / 可执行文件 (Executable, 如 ELF / a.out)
  │
  ▼ 装入 (Load): 装入程序将可执行文件搬移至物理内存 (DRAM) 中
物理主存 (Physical Memory)
```

#### 三种链接方式的横向比对表

| 链接方式 | 链接发生时机 | 库代码处理方式 | 内存利用率与更新成本 | 机制分水岭 |
| :--- | :--- | :--- | :--- | :--- |
| **静态链接** | 程序**运行之前** | 将所有引用的目标模块与静态库（`.a / .lib`）完整拷贝塞入可执行文件 | 生成文件体积巨大；多个进程使用相同库时物理内存严重重复浪费；库更新必须全量重新链接 | 运行前直接焊死为一个大文件 |
| **装入时动态链接** | 目标模块**装入内存时** | 边装入内存边链接，装入程序一边装入目标模块，一边找出其外部引用并填入物理基址 | 便于模块修改与版本更新；但若库函数在当前运行中未被调用，依然被强制装入内存 | 装入时统一解引用 |
| **运行时动态链接** | 程序**运行中用到时** | 在程序执行过程中，当 CPU 指令首次跳转到该未链接模块时，才由 OS 动态调入内存并链接（现代 `.so / .dll`） | **内存利用率极高**，未执行模块绝不占用物理内存；多个进程可安全共享只读动态库代码段；支持热更新 | 延迟到执行瞬间按需绑定 |

### (2) 三种装入方式与重定位（Relocation）机理

#### 逻辑地址与物理地址的物理矛盾
- **逻辑地址（Logical / Relative Address）**：由编译器生成，每个模块内部通常以 0 单元作为基准编址，程序员看到的均是逻辑地址。
- **物理地址（Physical / Absolute Address）**：物理内存芯片（DRAM）实际引脚寻址的总线绝对地址。
- **物理困境**：多任务系统中，操作系统无法在编译期预知程序在运行时会被放入哪一块物理空闲区域，必须通过**重定位技术**完成从逻辑地址到物理地址的映射。

#### 三种装入方式对比表

| 装入方式 | 重定位时机 | 逻辑地址何时转物理地址 | 内存运行特征与限制 | 机制分水岭 |
| :--- | :--- | :--- | :--- | :--- |
| **绝对装入 (Absolute Loading)** | **编译/汇编阶段** | 编译出的机器代码中**直接就是绝对物理内存地址** | 仅适用于**单道程序环境**（早期裸机）；程序必须固定装在特定内存段，完全无法并发加载多道程序 | 编译期确定物理地址 |
| **可重定位装入 (静态重定位)** | **装入内存阶段** | 装入程序根据分配的物理起始地址，**一次性修改指令中的所有逻辑地址** | 适用于早期批处理系统；**装入后在内存中的物理位置不可改变**（因为内部地址已被改写焊死）；必须占用连续内存块 | 装入时一次性改写指令代码 |
| **动态运行时装入 (动态重定位)** | **CPU 执行指令阶段** | 指令内部的逻辑地址保持 0 偏移原样不变，**在 CPU 每次取指访存的硬件时钟周期内实时计算转换** | **现代多道程序标准**；程序在运行期间可以随意搬移、换出到磁盘交换区再换回全新物理位置；支持连续分配与离散分页 | 访存瞬间由硬件加法器实时转换 |

#### 动态重定位的硬件支撑与内存保护机制

> [!IMPORTANT] 动态重定位属于连续分配（可变分区）时代的硬件核心基石，**绝不能把“动态重定位”片面等同于“必须离散分页”**！在现代连续分配或基本分段中，它均依靠硬件基址与限长寄存器实现。

CPU 内部的存储管理单元（MMU）配备两组硬件寄存器来实现地址转换与边界保护：
1. **重定位寄存器（基址寄存器 BR, Base Register）**：存放该进程在内存中的物理起始基地址；
2. **界地址寄存器（限长寄存器 LR, Limit Register）**：存放该进程逻辑地址的最大合法长度。

```
CPU 发出逻辑地址 (LA)
        │
        ├─────────────────────────────────┐
        ▼                                 ▼
【越界比较器 (硬件检查)】          【硬件加法器 (实时重定位)】
 若 LA >= 限长值 LR                     物理地址 PA = BR + LA
        │                                 │
        ▼ (越界)                          ▼
 触发【越界中断 (保护性异常)】      送往内存总线访问 DRAM 物理芯片
```

- **双重保护机制对比**：
  - **基址 + 限长寄存器方案**：先用比较器检查 $\text{LA} < \text{LR}$（防止访问越过私有空间），若合法则硬件加法器输出 $\text{PA} = \text{BR} + \text{LA}$。
  - **上下限寄存器方案**：硬件维护下限物理寄存器（Low）与上限物理寄存器（High），直接对发出的物理地址进行双向比对：$\text{Low} \le \text{PA} < \text{High}$。

### (3) 连续分配四大动态分区分配算法深度推演

#### 内部碎片 vs 外部碎片的绝对界定
- **内部碎片（Internal Fragmentation）**：**已分配给进程**，但由于分配粒度过大，进程自身用不完而在分区内部闲置浪费的存储空间（如固定分区、分页管理的最后一个页面）。
- **外部碎片（External Fragmentation）**：**未被分配给任何进程**，分布在各个已占用分区之间，但因单个空洞容量过小而无法满足任何一个新请求的离散碎块（动态分区分配的天然产物）。
  - **外部碎片消除手段**：**内存紧凑技术（Compaction / 拼凑）**。操作系统将所有在内存中的进程向一端物理平移压紧，把零散碎片拼合成一个大空闲区。**内存紧凑必须以硬件动态重定位为前提**，平移过程中只需修改进程的基址寄存器 BR。

#### 四大动态分区算法手算算例追踪大题

设系统初始空闲分区链（按物理地址递增排列）如下：
- 分区 1：起始地址 `100 KB`，容量 `20 KB`；
- 分区 2：起始地址 `150 KB`，容量 `50 KB`；
- 分区 3：起始地址 `240 KB`，容量 `30 KB`；
- 分区 4：起始地址 `300 KB`，容量 `15 KB`。

现系统依次到来三个作业请求：**作业 A 申请 `18 KB`**、**作业 B 申请 `25 KB`**、**作业 C 申请 `12 KB`**。

```
初始物理空闲分区状态 (按地址递增):
  [分区 1: 100K~120K (20K)] ──► [分区 2: 150K~200K (50K)] ──► [分区 3: 240K~270K (30K)] ──► [分区 4: 300K~315K (15K)]
```

##### 1. 首次适应算法 (First Fit, FF)
- **规则**：空闲分区链按**地址递增排列**，从表头顺序查找，挑选**第一个能满足容量的分区**进行切割。
- **分配追踪**：
  1. 作业 A (18K)：从表头查，分区 1 (20K) $\ge$ 18K。分配分区 1，占用 `100K ~ 118K`，**分区 1 剩余 2K（起始 118K）**。
  2. 作业 B (25K)：从表头查，分区 1 仅剩 2K（不满足）；查分区 2 (50K) $\ge$ 25K。分配分区 2，占用 `150K ~ 175K`，**分区 2 剩余 25K（起始 175K）**。
  3. 作业 C (12K)：从表头查，分区 1 (2K，不满足)；查分区 2 (25K) $\ge$ 12K。分配分区 2，占用 `175K ~ 187K`，**分区 2 剩余 13K（起始 187K）**。
- **最终空闲分区链状态**：`118K (2K)` $\to$ `187K (13K)` $\to$ `240K (30K)` $\to$ `300K (15K)`。高地址大空闲区（30K）被完整保留！

##### 2. 最佳适应算法 (Best Fit, BF)
- **规则**：空闲分区链按**容量递增排列**，挑选**能满足要求的最小空闲区**切割。
- **初始排序**：分区 4 (`15K`) $\to$ 分区 1 (`20K`) $\to$ 分区 3 (`30K`) $\to$ 分区 2 (`50K`)。
- **分配追踪**：
  1. 作业 A (18K)：查容量链，15K 不够，挑选分区 1 (20K)。分配后占用 `100K ~ 118K`，**剩余 2K 外部碎片（起始 118K）**。链表重排为：`2K` $\to$ `15K` $\to$ `30K` $\to$ `50K`。
  2. 作业 B (25K)：查容量链，2K、15K 不够，挑选分区 3 (30K)。分配后占用 `240K ~ 265K`，**剩余 5K 外部碎片（起始 265K）**。链表重排为：`2K` $\to$ `5K` $\to$ `15K` $\to$ `50K`。
  3. 作业 C (12K)：查容量链，挑选满足的最小分区 4 (15K)。分配后占用 `300K ~ 312K`，**剩余 3K 外部碎片（起始 312K）**。
- **评价**：产生了 `2K`、`5K`、`3K` 等大量极其微小的外部碎片，后续几乎无法再被利用！

##### 3. 最坏适应算法 (Worst Fit, WF)
- **规则**：空闲分区链按**容量递减排列**，挑选**当前全局最大的空闲区**切割。
- **初始排序**：分区 2 (`50K`) $\to$ 分区 3 (`30K`) $\to$ 分区 1 (`20K`) $\to$ 分区 4 (`15K`)。
- **分配追踪**：
  1. 作业 A (18K)：挑选最大的分区 2 (50K)。分配占用 `150K ~ 168K`，**分区 2 剩余 32K**。链表重排为：`32K` $\to$ `30K` $\to$ `20K` $\to$ `15K`。
  2. 作业 B (25K)：挑选当前最大的分区 2 (32K)。分配占用 `168K ~ 193K`，**分区 2 剩余 7K**。链表重排为：`30K` $\to$ `20K` $\to$ `15K` $\to$ `7K`。
  3. 作业 C (12K)：挑选当前最大的分区 3 (30K)。分配占用 `240K ~ 252K`，**分区 3 剩余 18K**。
- **评价**：虽然分割后剩余空间较大（不易产生微小碎片），但过早肢解了系统中的大容量连续空间（50K 与 30K 全被切碎），若此时到来一个 35K 的大作业将无法载入。

##### 4. 邻近适应算法 (Next Fit, NF / 循环首次适应)
- **规则**：空闲链按**地址递增排列**，从**上次查找结束的位置**开始循环往下查找。
- **分配追踪**：
  1. 作业 A (18K)：从表头查，分配分区 1 (20K)，剩余 2K。指针停留在分区 1。
  2. 作业 B (25K)：从指针后继续查，分配紧邻的分区 2 (50K)，剩余 25K。指针停留在分区 2。
  3. 作业 C (12K)：从指针后继续查，分区 2 剩余 25K $\ge$ 12K，直接在分区 2 分配，剩余 13K。
- **评价**：使得碎片在内存高低地址均匀分布，但缺乏首次适应在低地址聚拢碎片、高地址保留大连续空间的天然优势。

#### 四大动态分区分配算法全景对比总结

| 算法名称 | 空闲链排序原则 | 检索与切割逻辑 | 碎片演化特征 | 408 核心考点结论 |
| :--- | :--- | :--- | :--- | :--- |
| **首次适应 (FF)** | **按物理地址递增** | 从表头开始，找第一个满足的分区 | 碎片主要集中在低地址端，**高地址完整保留大空闲区** | **综合性能最好、查找开销最小** |
| **邻近适应 (NF)** | **按物理地址递增** | 从上一次查找到的末尾接着查 | 碎片在全内存空间均匀分散，高地址大分区过早被切碎 | 性能通常逊于首次适应 |
| **最佳适应 (BF)** | **按容量大小递增** | 挑选满足容量要求的最小空闲区 | 每次切割后残留极微小碎片，形成“空闲细渣” | **最容易产生微小不可利用的外部碎片** |
| **最坏适应 (WF)** | **按容量大小递减** | 挑选全局最大的空闲区进行分割 | 残留块较大，但系统缺乏大容量连续可用分区 | 容易导致后续大作业饥饿 |

### (4) 动态分区回收时的四种邻接合并机理

当某运行进程释放其占用的内存物理区域（设回收区起始地址为 $R$，长度为 $L$）时，操作系统必须根据空闲分区链表中相邻分区的物理边界执行智能合并：

```
情形 1: 仅上邻空闲区合并            情形 2: 仅下邻空闲区合并
   ┌─────────────────┐                ┌─────────────────┐
   │ 上邻空闲区 F1   │                │   回收区 R      │
   ├─────────────────┤                ├─────────────────┤
   │    回收区 R     │                │ 下邻空闲区 F2   │
   └─────────────────┘                └─────────────────┘
 (F1 大小更新为 F1+R, 表项数不变)    (F2 基址改为 R, 大小改为 R+F2, 表项数不变)

情形 3: 上下相邻同时合并 (三合一)   情形 4: 上下均无相邻空闲区 (独立成项)
   ┌─────────────────┐                ┌─────────────────┐
   │ 上邻空闲区 F1   │                │   已分配作业    │
   ├─────────────────┤                ├─────────────────┤
   │    回收区 R     │                │    回收区 R     │
   ├─────────────────┤                ├─────────────────┤
   │ 下邻空闲区 F2   │                │   已分配作业    │
   └─────────────────┘                └─────────────────┘
 (F1 大小改为 F1+R+F2, 删 F2, 表项数-1) (为 R 新建一个独立表项, 表项数+1)
```

#### 四种合并场景状态变迁追踪表

| 邻接相对状态 | 物理地址判据 | 空闲分区表项的修改动作 | 表项总数增减 |
| :--- | :--- | :--- | :---: |
| **1. 仅有上相邻空闲区** | $\text{Start}_{\text{回收}} == \text{Start}_{F1} + \text{Size}_{F1}$ | 仅修改上邻分区 $F1$ 的容量：$\text{Size}_{F1} \leftarrow \text{Size}_{F1} + L$。$F1$ 起始基址不变。 | **不变** |
| **2. 仅有下相邻空闲区** | $\text{Start}_{\text{回收}} + L == \text{Start}_{F2}$ | 修改下邻分区 $F2$ 的起始基址与容量：$\text{Start}_{F2} \leftarrow \text{Start}_{\text{回收}}$，$\text{Size}_{F2} \leftarrow \text{Size}_{F2} + L$。 | **不变** |
| **3. 上下相邻同时存在** | 同时满足条件 1 与条件 2 | 上中下三合一：修改上邻 $F1$ 容量为 $\text{Size}_{F1} + L + \text{Size}_{F2}$；**从空闲表中彻底注销删除下邻分区 $F2$ 的表项**！ | **减 1** |
| **4. 上下均无相邻空闲区** | 无论向前还是向后都不相邻 | 回收区属于孤立块：为该回收区**单独新建一个空闲分区表项**，按地址顺序插入空闲表中。 | **加 1** |

### 1. 本学科内跨章节关联
- **关联 [基本分页与分段存储管理](02-paging-and-segmentation.md)**：
  - **共同机制**：虚拟地址向物理地址的映射转换。
  - **关键差异**：连续分配管理要求整个进程物理空间必须完全连续，导致外部碎片严重；分页存储将物理内存硬性切分为 4KB 离散页框，从根源上**彻底消除了外部碎片**，仅剩最后一个物理页的内部碎片。
- **关联 [虚拟内存与请求分页](03-virtual-memory-basics.md)**：
  - **共同机制**：内存的动态装入与换出。
  - **关键差异**：连续分配换出必须以“整个进程镜像”为单位搬移（对换 Swapping）；请求分页以“页面（Page）”为精细粒度按需调度，极大降低了 I/O 开销并支持“大作业在小内存中运行”。

### 2. 跨学科协同关联（计算机组成原理）
- **关联 [CPU 指令系统寻址方式](../../02-co/04-instruction-system/02-addressing-modes.md)**：
  - **共同机制**：基址寻址的硬件算术逻辑。
  - **关键差异**：计组中的基址寻址面向用户程序多重数据结构的基准偏移；操作系统的动态重定位将基址寄存器收归为操作系统专用的特权寄存器，成为进程物理边界隔离的硬件屏障。

## 4. 闭环决策模型与核心认知结论

### (1) 存储分配方式与碎片属性决策树

```
内存分配管理模式:
  ├─ 连续分配管理
  │    ├─ 单一连续分配 ──► 仅有【内部碎片】 (整个用户区仅运行一道作业)
  │    ├─ 固定分区分配 ──► 产生大量【内部碎片】, 【无外部碎片】 (分区预先划死)
  │    └─ 动态分区分配 ──► 产生大量【外部碎片】, 【无内部碎片】 (按需切割残留零碎空间)
  │
  └─ 离散分配管理
       ├─ 基本分页管理 ──► 仅末页存在【内部碎片】 (平均半页), 【彻底无外部碎片】
       ├─ 基本分段管理 ──► 段内连续但段间离散, 产生【外部碎片】, 【无内部碎片】
       └─ 段页式管理   ──► 段内分页, 仅末页存在【内部碎片】, 【无外部碎片】
```

### (2) 考场定性铁律
1. **动态重定位不等于分页**：只要硬件配备了“基址寄存器 + 限长寄存器”，在连续可变分区或分段系统中同样能实现完美的动态重定位。
2. **综合表现最佳的动态分区算法**：**首次适应算法（FF）** 综合性能最优秀、执行速度最快，且能在高地址有效保护大连续空间。
3. **最易产生不可利用微小碎片的算法**：**最佳适应算法（BF）**。
4. **回收表项增减铁律**：上下同时相邻合并 $\implies$ 表项数**减 1**；上下均不相邻独立成项 $\implies$ 表项数**加 1**；单侧相邻合并 $\implies$ 表项数**保持不变**。
