- **考察要点**：
  - **系统抖动（颠簸，Thrashing）的物理本质**：频繁换页导致的系统吞吐率崩溃与恶性正反馈循环。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 抖动现象的物理成因与正反馈崩溃过程

#### 抖动的严格物理定义
在请求分页虚拟存储体系中，如果分配给进程的物理页框数严重不足，导致刚被换出的页面马上又要被访问、刚换入的页面马上又被换出，**CPU 几乎将 100% 的时间耗费在等待外存磁盘 I/O 调页上，而无法执行任何有效计算**，这种系统有效吞吐量断崖式暴跌的现象称为**抖动（颠簸，Thrashing）**。

#### 辟谣：单道程序环境下会不会发生抖动？
- **高频误区**：有人认为“抖动是并发进程太多引起的，单道程序绝对不会抖动”。
- **物理真相**：**单道程序照样可能发生严重的颠簸！**
  - **物理判据**：是否发生抖动的根本物理矛盾在于：**分配给进程的物理页框数 $M$ 是否小于该进程当前运行阶段的实际工作集大小 $|W(t, \Delta)|$**。
  - **单进程实例**：假设一个大矩阵乘法程序在一个循环内部需要高频轮流访问 5 个不同的数据页面，但操作系统只给它固定分配了 3 个物理页框。在每一次内层循环中，该进程都必然经历“换出页 A 换入页 D $\to$ 紧接着换出页 B 换入页 E $\to$ 紧接着又换回页 A”，整个进程陷入每执行几条指令就缺页一次的瘫痪状态！
  - **多道程序度的推波助澜**：多道程序度过高并不是抖动的唯一根源，而是它**在全局范围内加速并诱发了所有进程物理页框被极度摊薄的雪崩机制**。

#### 多道程序度与 CPU 利用率的经典崩溃曲线与恶性正反馈

```
 CPU 利用率
    ▲
100%│                  峰值 (最佳多道程序度 N_opt)
    │                     ╭───╮
    │                   ╭─╯   ╰─╮
    │                 ╭─╯       ╰─╮
    │               ╭─╯           ╰─╮ ◄── 恶性正反馈爆发，发生颠簸 (Thrashing)
    │             ╭─╯               ╰──╮
    │           ╭─╯                    ╰──────┐
    └───────────┴─────────────────────────────┴────► 多道程序度 (并发进程数)
```

- **恶性正反馈的五步演变逻辑**：
  1. **吞吐攀升期**：多道程序度适度增加，进程发生 I/O 阻塞时 CPU 可切换到其他就绪进程，CPU 利用率稳步上升；
  2. **局部性枯竭**：并发进程数继续增加，物理内存被过度瓜分，分配给各进程的页框数跌破其局部性底线；
  3. **大面积缺页**：多个进程几乎同时高频触发缺页异常，纷纷从“运行态”转入“阻塞态”，在磁盘等待队列排队；
  4. **调度器的灾难误判（早期 OS 缺陷）**：CPU 调度器检测到 CPU 利用率骤降，误以为当前系统负载太轻、作业不足，**于是自动启动作业调度，从外存调入更多新进程到内存中运行**；
  5. **系统彻底瘫痪**：新进程的涌入进一步剥夺了剩余的页框，磁盘 I/O 队列彻底被挤爆，整机 CPU 利用率趋近于 0，有效计算完全停摆。

### (2) 丹宁工作集（Working Set）模型与数学本质

#### 历史滑动窗口的本质：用过去预测未来的局部性
为了定量衡量“一个进程当前究竟需要多少个物理页框才能平稳运行”，计算机科学家彼得·丹宁（Peter Denning）提出了**工作集（Working Set）理论**：
- **核心定义**：进程在时刻 $t$ 的工作集 $W(t, \Delta)$，是指在**向后看的过去 $\Delta$ 次内存访问（时间窗口 $[t - \Delta + 1, \, t]$）中，所访问过的全部不同页面的去重集合**。
  - $\Delta$ 称为**工作集窗口大小（Working-Set Window Size）**；
  - 集合的基数记作 $|W(t, \Delta)|$，称为**工作集大小（WSS, Working Set Size）**。
- **哲学与工程意义**：
  操作系统在物理上无法预知未来。根据**程序执行的局部性原理（Locality of Reference）**，在极短时间跨度内，程序接下来即将访问的页面集合，大概率就是刚刚访问过的页面集合。因此，**工作集大小 $|W(t, \Delta)|$ 是操作系统为该进程动态配置物理驻留集（Resident Set）的客观下限依据**！

#### 工作集滑动窗口手算追踪大题

设进程的页面访问序列如下，设定工作集窗口大小 $\Delta = 4$：
$$\dots, \, \underset{t_1}{2}, \, \underset{t_2}{6}, \, \underset{t_3}{1}, \, \underset{t_4}{5}, \, \underset{t_5}{7}, \, \underset{t_6}{7}, \, \underset{t_7}{7}, \, \underset{t_8}{5}, \, \underset{t_9}{1}, \, \underset{t_{10}}{6}, \, \underset{t_{11}}{2}, \, \underset{t_{12}}{3}, \, \underset{t_{13}}{4}, \, \underset{t_{14}}{4}, \, \dots$$

请追踪关键时间节点 $t$ 处的工作集内容与大小变化：

| 考查时刻 $t$ | 当前访问页 | 过去 $\Delta = 4$ 次访问滑窗 $[t-3, t]$ | 去重后的工作集集合 $W(t, 4)$ | 工作集大小 $|W(t, 4)|$ | 局部性状态分析与驻留集要求 |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **$t_4$** | `5` | `[2, 6, 1, 5]` | $\{1, 2, 5, 6\}$ | **4** | 处于函数初始化跳转阶段，局部性离散，需 4 个页框 |
| **$t_7$** | `7` | `[5, 7, 7, 7]` | $\{5, 7\}$ | **2** | 进入密集单循环，高度集中在页 7，仅需 2 个页框 |
| **$t_8$** | `5` | `[7, 7, 7, 5]` | $\{5, 7\}$ | **2** | 依然稳定在循环体内，需 2 个页框 |
| **$t_9$** | `1` | `[7, 7, 5, 1]` | $\{1, 5, 7\}$ | **3** | 发生局部性扩展，跳入子程序，需 3 个页框 |
| **$t_{11}$** | `2` | `[5, 1, 6, 2]` | $\{1, 2, 5, 6\}$ | **4** | 发生局部性转移（Transition），需 4 个页框防止缺页 |
| **$t_{14}$** | `4` | `[2, 3, 4, 4]` | $\{2, 3, 4\}$ | **3** | 稳定进入新代码段循环，需 3 个页框 |

- **规律总结**：
  - 当程序处于**稳定局部性阶段（In a Locality）**时，工作集大小 $|W(t, \Delta)|$ 较小且维持稳定；
  - 当程序处于**局部性转移阶段（Transition Phase）**时，旧代码与新代码交叉访问，工作集大小会出现脉冲式暴涨。

### (3) 防止与消除系统抖动的工程闭环策略

#### 1. 基于工作集的准入控制（Admission Control）
- 操作系统定期统计所有并发进程的工作集大小之和：
  $$S_{\text{total}} = \sum_{i=1}^{n} |W_i(t, \Delta)|$$
  - **安全区**（$S_{\text{total}} \le \text{系统可用页框数}$）：系统允许继续推进，甚至可以接纳新进程；
  - **危险区**（$S_{\text{total}} > \text{系统可用页框数}$）：物理页框已无法满足所有进程的基本运行集。操作系统**必须立即触发中级调度（挂起机制）**，挑选一个或多个进程强行挂起（换出到对换区），收回其占用的全部页框，充公分给剩余进程，彻底粉碎颠簸链条！

#### 2. 缺页率控制策略（PFF, Page Fault Frequency）
依据各进程实际发生的缺页频率，设置上下界水位线动态调控：

```
当前进程缺页率 (PFF)
       ▲
       │   【危险高缺页区】 ──► 为该进程动态追加分配物理页框
 阈值 U ├──────────────────────────── (若系统已无空闲页框，立即触发【挂起进程】)
       │   【稳定平衡运行区】 ──► 维持当前驻留集大小不变
 阈值 L ├────────────────────────────
       │   【页框富余区】 ──► 动态回收该进程冗余的物理页框，充入空闲池
     0 └─────────────────────────────► 时间
```

#### 3. 页面大小（Page Size）的物理折中权衡

| 比较维度 | 页面划分**较小**（如 512B ~ 1KB） | 页面划分**较大**（如 2MB ~ 1GB，大页） | 机制分水岭 |
| :--- | :--- | :--- | :--- |
| **内部碎片** | **极小**（平均仅浪费半个微小页面） | **极大**（末页内部碎片严重） | 内存空间有效利用率 |
| **页表占用体积** | **极大膨胀**（同等内存下 PTE 数量成倍暴增，耗尽系统内存） | **极小**（大幅减少多级页表级数和 PTE 数量） | 系统管理数据结构开销 |
| **TLB 覆盖率** | **覆盖内存范围狭小**（固定 64~512 项 TLB 只能覆盖几十 KB 空间，TLB 命中率低） | **覆盖内存极其广阔**（单项覆盖 2MB，大幅减少 TLB 缺失） | CPU 访存硬件性能 |
| **外存 I/O 效率** | **低下**（外存机械磁盘每次寻道需数毫秒，传输几十字节效率极低） | **极高**（连续顺序块传输，磁盘寻道时间占比大幅降低） | 磁盘与总线吞吐效率 |
| **工业标准折中** | 现代通用体系结构（x86/ARM）将标准基础页面定为 **4 KB**，兼顾内部碎片与系统管理开销；对大型数据库配备巨页（HugePage 2MB/1GB）。 | |

### (4) 澄清：父子进程 `fork` 共享页换出机制

- **错误认知**：有人误认为“如果两个进程通过 `fork` 共享只读代码页，发生置换时该页会被分别重复写到磁盘对换区两次”。
- **物理真相**：**绝无可能！**
  - 内核通过物理页描述符（`struct page`）的全局引用计数（`_refcount` / `_mapcount`）以及反向映射表（Reverse Mapping `rmap`）统一管理物理页框。
  - 当某个只读共享页面因内存紧张需要换出时：
    1. 若该页是**干净页面（Clean Page，如可执行文件代码段）**，内核直接将所有共享该页的进程页表项标记为无效，直接回收该物理页框，**0 次磁盘写 I/O**（未来需要时直接从原程序可执行文件重新读入）；
    2. 若该页是**匿名脏共享页（Dirty Anonymous Page）**，内核在对换区（Swap）仅为其**分配一份物理连续的磁盘槽位并只写入一次**，随后将所有共享该页的进程页表项统一修改为指向该相同的 Swap 槽位地址。

## 3. 本学科内跨章节关联与跨学科协同关联

### 1. 本学科内跨章节关联
- **关联 [进程状态模型与中级调度](../02-process/01-process-states.md)**：
  - **共同机制**：内存紧张时的进程调度协同。
  - **关键差异**：低级调度（CPU 调度）在就绪队列与运行态间切换，无法改变内存物理页框不足的现状；中级调度通过挂起进程并将其全部内存换出到磁盘对换区，是根治全局抖动的唯一有效大杀器。
- **关联 [页面置换算法](04-page-replacement.md)**：
  - **共同机制**：局部性利用与缺页率控制。
  - **关键差异**：页面置换算法（FIFO, LRU, Clock）仅解决“在物理页框数固定的情况下挑选哪一页淘汰”；工作集理论解决“到底至少该给进程分配多少个物理页框”的容量准入控制。

### 2. 跨学科协同关联（计算机组成原理）
- **关联 [Cache 替换算法与局部性原理](../../02-co/03-memory-hierarchy/02-cache-mapping.md)**：
  - **共同机制**：基于时间局部性与空间局部性的缓存管理。
  - **关键差异**：CPU Cache 由纯硬件状态机管理，容量极小、时延为纳秒级；操作系统工作集管理由软件通过缺页中断与时钟中断采样控制，面向 DRAM 与磁盘，时延为毫秒级。

## 4. 闭环决策模型与核心认知结论

### (1) 抖动诱因与治理闭环判定模型

```
系统发生严重性能衰退:
  ├─ 是否由于缺页率暴增导致 CPU 空转等待外存 I/O?
  │    ├─ 否 ──► 属于 CPU 密集型计算或死锁，非抖动
  │    └─ 是 ──► 【发生系统抖动 (Thrashing)】
  │
  └─ 治理手段判定:
       ├─ 盲目提高多道程序度 ──► 【绝对错误】 (加剧页框瓜分，导致雪崩)
       ├─ 单纯增加简单 FIFO/LRU 换页频次 ──► 【无效】 (无法弥补页框绝对短缺)
       └─ 正确根本手段 ──► 【降低多道程序度，触发中级调度挂起部分进程，归还页框】
```

### (2) 考场定性铁律
1. **抖动的充要物理条件**：**分配给进程的物理页框数小于其工作集大小（$M < |W(t, \Delta)|$）**。
2. **单进程也会抖动**：只要页框给得少于工作集，单道程序同样会发生恶性频繁换页。
3. **消除抖动的唯一立竿见影手段**：**降低多道程序度，挂起并换出部分进程**。
4. **工作集滑窗计算法**：从当前时刻 $t$ **严格向左倒数 $\Delta$ 个访存记录，去重后的元素个数**即为该时刻的工作集大小。
