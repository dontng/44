## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 抖动现象的物理成因与系统级恶性循环
- **现象描述**：
  在虚拟存储系统中，当系统分配给某些进程的物理页框严重不足时，页面刚被换入主存，立刻又被置换出去；刚被换出的页面，指令下一刻又要访问它，又必须重新换入。这种**频繁的页面换入换出导致 CPU 大部分时间处于等待外存 I/O 状态，而无法执行有效计算**的现象称为“抖动（颠簸）”。
- **多道程序度与 CPU 利用率的经典崩溃曲线**：

```
 CPU 利用率
    ▲
100%│                  峰值 (最佳多道程序度)
    │                     ╭───╮
    │                   ╭─╯   ╰─╮
    │                 ╭─╯       ╰─╮
    │               ╭─╯           ╰─╮ ◄── 发生颠簸 (Thrashing)
    │             ╭─╯               ╰──╮
    │           ╭─╯                    ╰──────┐
    └───────────┴─────────────────────────────┴────► 多道程序度 (并发进程数)
```

- **恶性正反馈循环的物理推手**：
  1. 初始阶段：多道程序度上升，更多进程并发，CPU 遇到 I/O 阻塞可无缝切换到其他就绪进程，**CPU 利用率攀升**；
  2. 临界过载：进程数量过多，瓜分了有限的物理页框，导致每个进程分到的页框数少于其局部性运行所需的底线；
  3. 缺页风暴爆发：进程频繁发生缺页异常，纷纷从运行态进入**阻塞态**，等待磁盘 I/O 调页；
  4. **调度器的致命误判**：操作系统的早期调度器监测到“CPU 利用率正在急剧下降”，系统以为当前系统负载过轻，便**自动调高多道程序度，调入更多新进程到内存中**；
  5. 灾难收敛：新进程进一步稀释早已干涸的物理页框，缺页率无限飙升，CPU 彻底空转等待，有效吞吐量跌至零点。

### (2) 丹宁工作集（Working Set）模型与数学本质
为了在数学上定量描述进程“在某个时刻到底至少需要占用多少个物理页框才能不发生颠簸”，计算机科学家彼得·丹宁提出了工作集理论。

- **核心定义**：
  进程在时间点 $t$ 的工作集 $W(t, \Delta)$，是指在过去的滑窗时间区间 $[t - \Delta + 1, \, t]$ 内，进程所实际访问过的**所有不同页面的集合**。
  - $\Delta$ 称为**工作集窗口大小（Working-Set Window）**，以指令访存次数或时间片步数为单位。
  - 工作集大小记作 $|W(t, \Delta)|$，代表该集合中**去重后的页面总数**。

- **跟踪求解示范**：
  设页面访问序列为：
  $$\dots, 2, 6, 1, 5, 7, 7, 7, 7, 5, 1$$
  - 若窗口大小 $\Delta = 4$：
    - 在 $t$ 时刻（刚访问完最后一个 1），往前数 4 次访问：$[7, 7, 5, 1]$；
    - 去重后的集合为：$W(t, 4) = \{1, 5, 7\}$；
    - 此时工作集大小为：$|W(t, 4)| = 3$。
  - 这意味着：操作系统必须至少给该进程分配 **3 个物理页框**，才能保证其当前不会频繁缺页。

### (3) 防止抖动的工程预防与恢复机制

#### ① 基于工作集的准入控制（Admission Control）
- **核心判定准则**：
  操作系统统计当前内存中所有并发进程的工作集大小之和：
  $$S = \sum_{i=1}^{n} |W_i(t, \Delta)|$$
  - 若 $S \le \text{系统可用物理页框总数}$：系统安全，允许保持当前多道程序度，甚至接纳新作业。
  - 若 $S > \text{系统可用物理页框总数}$：说明可用物理页框已被透支，系统濒临颠簸。操作系统调度器立即执行**进程挂起（Suspend）**，强行将某个或某些进程换出到外存磁盘交换区，彻底回收其全部页框，充公分给剩余进程，恢复系统平衡。

#### ② 缺页率策略（PFF, Page Fault Frequency）
- 依据进程的实际缺页频率动态调整分配的页框数量：
  - 设定上限阈值 $U$ 与下限阈值 $L$：
    - 若当前缺页率 $> U$：说明该进程分到的页框严重不足，操作系统为其**动态增加物理页框**；
    - 若当前缺页率 $< L$：说明该进程分到的页框过于富余（局部性已稳定），操作系统**主动回收部分物理页框**。

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 操作系统: 颠簸控制与工作集     │
                     └──────────────┬───────────────┘
                                    │ 物理页框透支时触发挂起
                                    ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 操作系统: 进程生命周期与挂起  │         │ 操作系统: 局部性原理与 Cache  │
│  - 调入对换区: 就绪挂起/阻塞挂起│ ◄────── │  - 工作集大小本质是时间局部性 │
│  - 属于中级调度 (Medium-term) │         │  - 窗口 Δ 越大, 工作集越大   │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与操作系统三级调度体系的物理贯通**：
   - 当抖动发生时，单纯依靠高级调度（作业调度）或低级调度（CPU 调度）无法救场。
   - 必须由**中级调度（Medium-Term Scheduling / 内存调度）**介入，将暂时不能运行的进程调至磁盘对换区，将其状态变更为**挂起态（Suspended Ready / Suspended Blocked）**，平抑并发度，打破恶性循环。
2. **与时间局部性在参数 $\Delta$ 上的物理权衡**：
   - 若窗口 $\Delta$ 选得过小：无法捕捉完整的循环体页面，导致计算出的工作集严重失真偏小，引发频繁缺页。
   - 若窗口 $\Delta$ 选得过大：将早已过期的历史访问也纳入工作集，导致工作集容量虚高，严重限制了系统的并发利用率。
   - 极限状态：当 $\Delta \to \infty$ 时，工作集退化为进程生命周期中访问过的所有页面全集。

## 4. 闭环决策模型与核心认知结论

### (1) 考场工作集求解闭环两步法
1. **精准定位滑窗区间**：
   从当前考查时刻 $t$ 对应的访问位置开始，**向左严格倒数 $\Delta$ 个访存引用符号**。
2. **集合去重计数**：
   将这 $\Delta$ 个引用符号放入集合中，**去除所有重复的页号**，所得集合中元素的个数即为工作集大小 $|W(t, \Delta)|$。

### (2) 抖动定性判定铁律
1. **导致系统抖动的根本原因**：**多道程序度过高（并发进程过多），导致分配给每个进程的物理页框数小于其工作集大小**。
2. **消除抖动的最直接、最有效手段**：**降低多道程序度，暂停/挂起若干进程，将其内存完全换出到对换区**。
3. **增加内存容量是否能根治抖动？** $\to$ 可以缓解或推迟抖动发生，但若无限制盲目提高多道程序度，抖动依然必然发生。
