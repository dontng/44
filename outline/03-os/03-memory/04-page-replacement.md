## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么需要页面置换？
当物理内存已无空闲页框，进程执行中再次触发缺页异常时，操作系统必须在已装入内存的页面中挑选一个“受害者页面（Victim Page）”强行淘汰，将其占用的物理页框腾出以装入新页面。
- **评判算法的核心物理标准**：挑选受害者页面的准则，能否使程序未来的**总缺页次数最少，且算法本身的硬件记录与软件遍历开销最低**。

### (2) 五大置换算法设计哲学与物理代价

```
                     ┌──────────────────────────────┐
                     │       408 核心页置换算法      │
                     └──────────────┬───────────────┘
          ┌─────────────────┬───────┴─────────┬─────────────────┐
          ▼                 ▼                 ▼                 ▼
   【最佳置换 OPT】   【先进先出 FIFO】 【最近最久未使用 LRU】 【时钟置换 CLOCK】
   面向未来(不可实现)   面向进入时间(最简单) 面向过去(开销大)     工程最优折中(软硬结合)
```

#### 1. 最佳置换算法（OPT, Optimal）
- **核心逻辑**：淘汰**未来最长时间内不再被访问**的页面。
- **物理现实**：由于 CPU 和操作系统无法预知程序未来的执行路径（分支跳转与用户输入不可预测），该算法在**工程实现上是物理不可能的**。它仅作为理论评估基准，用于衡量实际算法的优劣。

#### 2. 先进先出算法（FIFO）
- **核心逻辑**：淘汰**最早载入物理内存**的页面。
- **实现机制**：维护一个先进先出的队列，换入新页入队尾，淘汰时弹出队头。
- **致命缺陷（Belady 异常）**：**为进程分配的物理页框数增加，总缺页次数反而增加**！因为最早载入内存的页面很可能是常驻全局变量或核心循环代码，FIFO 仅凭“先来后到”盲目淘汰，破坏了局部性。

#### 3. 最近最久未使用算法（LRU, Least Recently Used）
- **核心逻辑**：淘汰**过去最长一段时间内未被访问**的页面（以过去的行为预测未来）。
- **理论性质**：属于数学证明的**堆栈型算法（Stack Algorithm）**，**严格保证绝不发生 Belady 异常**。
- **工程瓶颈**：每次哪怕极其普通的读写访存，都必须更新硬件时间戳或动态调整页面链表节点，**硬件记账时延巨大，现代 CPU 无法承受每次访存都插入如此繁重的维护指令**。

#### 4. 简单时钟置换算法（CLOCK / 二次机会算法 Second-Chance）
- **设计哲学**：不进行精确的全局时间排序，仅用 1 比特粗略区分页面是“近期用过”还是“近期闲置”。
- **硬件与软件协同**：
  - **硬件支持**：每个页表项配备 1 位**访问位（Reference / Use bit, $u$）**。当该页被读或写时，**MMU 硬件电路顺手将其置 1**（无需软件逐次维护，但硬件操作仍有成本）；
  - **软件指针巡逻**：操作系统将所有物理页框组织成一个**逻辑环形循环队列**，维护一个时钟巡逻指针（Hand）：
    1. 当需要淘汰页面时，指针自当前位置顺时针扫描；
    2. 若遇到 $u = 1$：说明该页近期被使用过，给予一次免死机会，**将其清零（$u \leftarrow 0$）**，指针前进一步；
    3. 若遇到 $u = 0$：说明该访问位自上次清零以来尚未再次置 1；初始未访问页也可能为 0，**选定其作为受害者淘汰换出**，指针前进一步指向下一位置。

#### 5. 改进型时钟置换算法（Enhanced CLOCK）
- **物理动机**：磁盘写操作比读操作慢很多。
  - 干净页（修改位 $m = 0$）：淘汰时直接释放页框，**完全无需写盘**；
  - 脏页（修改位 $m = 1$）：若修改需保留，回收前须写回相应后备存储：匿名页通常写入交换区，文件映射脏页写回文件；并非统一写 Swap。
- **双状态标记**：$(u, m) \implies (\text{访问位}, \text{修改位})$，优先级分为四档：
  - **第 1 档 $(0, 0)$**：近期未用且未修改，淘汰代价最低（首选）；
  - **第 2 档 $(0, 1)$**：近期未用但被修改过，淘汰需写盘；
  - **第 3 档 $(1, 0)$**：近期用过但未修改；
  - **第 4 档 $(1, 1)$**：近期用过且被修改过，淘汰代价最高。
- **教科书标准四轮扫描规则**：
  1. **第 1 轮**：从当前指针开始寻找第一个 $(0, 0)$。**本轮绝对不修改任何标志位**；
  2. **第 2 轮**：若第 1 轮失败，重新扫描寻找第一个 $(0, 1)$。**在此轮扫描过程中，将所有路过的页面访问位 $u$ 全部置 0（$u \leftarrow 0$）**；
  3. **第 3 轮**：若第 2 轮仍失败，重新寻找第一个 $(0, 0)$（因上一轮将 $u$ 刷为 0，原先的 $(1, 0)$ 现在变为了 $(0, 0)$）。**本轮不修改标志位**；
  4. **第 4 轮**：寻找第一个 $(0, 1)$（原先的 $(1, 1)$ 现在变为了 $(0, 1)$）。
  - *注*：至多经过 4 轮全环扫描，**必然能找到受害者页面**。

### (3) Belady 异常的数学本质与简单 CLOCK 异常反例

#### 为什么堆栈型算法绝不发生 Belady 异常？
设系统在时刻 $t$ 执行引用串 $r_1, r_2, \dots, r_t$。
- **堆栈型算法（Stack Algorithm）的形式化定义**：若一种页面置换算法满足：对于任意引用串和任意时刻 $t$，当分配 $k$ 个物理页框时常驻内存的页面集合 $M(k, t)$，**始终包含于分配 $k+1$ 个页框时的常驻页面集合 $M(k+1,t)$（未装满时允许相等）**，即：
  $$M(k, t) \subseteq M(k+1, t)$$
- **数学必然性**：由于 $k$ 框包含的页面永远被 $k+1$ 框所包含，如果当前访问的页面在 $k$ 个页框中命中（$r_t \in M(k, t-1)$），它必定在 $k+1$ 个页框中也命中！因此增加页框数**绝不可能导致原本命中的访问变成缺页**。
- **典型代表**：**LRU** 保留过去最近使用的至多 $k$ 个不同页面；**OPT** 淘汰当前驻留页中未来最晚再用者，在一致的平局处理下也满足包含性质。OPT 的驻留集合不等于无条件选取未来最近出现的 $k$ 个页面，因为它不能预先装入尚未访问的页面。

#### 简单 CLOCK 算法亦会发生 Belady 异常的严格验证
过去部分教学材料片面断言“408 考纲范围内只有 FIFO 会发生 Belady 异常”。**从算法原理与数学本质上看，简单 CLOCK 算法并不满足堆栈性质，它在特定引用串下同样会产生 Belady 异常！**

##### 严格反例参数
- **引用串序列**：`5, 2, 4, 1, 5, 2, 0, 5, 2, 3, 1, 0`（共 12 次访问）
- **简单 CLOCK 算法规范**：
  - 页框初始全为空；时钟指针 Hand 初始指向页框 0；
  - 命中时仅将对应页的 $u$ 位置 1，时钟指针 Hand 保持不动；
  - 缺页且需置换时，从 Hand 开始扫描：若 $u=1$ 则置 $u=0$ 并推进指针；若 $u=0$ 则淘汰该页，换入新页并置 $u=1$，Hand 推进到下一位置。

### (4) 重点辨析：CLOCK 算法 vs 磁盘 C-SCAN 调度

过去部分材料常将“CLOCK 算法和 C-SCAN 完全同构”一笔带过，忽视了两者在存储层次和物理特性上的重大差异：

| 比较维度 | 共同机制（Commonality） | 关键差异（Differences） | 不可直接迁移的判据 |
| :--- | :--- | :--- | :--- |
| **内存 CLOCK 置换算法** | **环形单向循环扫描**<br>均采用单向环形推进，但环形结构本身不保证相同的公平性与淘汰性质。 | **纳秒级内存操作 + 动态修改状态标志 + 遇目标立即停顿**<br>CLOCK 巡逻指针游走在 DRAM 内存页表项数组中，访问位检视与修改仅消耗几个 CPU 时钟周期，不存在任何物理机械移动开销。指针一旦找到第一个合法受害者（$u=0$），**立即停顿并就地结束本轮置换**。 | CLOCK 在巡逻扫描过程中会**主动动态改变状态（将 $1 \to 0$）**，且每次缺页只处理一个受害者即终止；绝不能迁移为磁盘那种全轨道连续批处理模型。 |
| **磁盘 C-SCAN 调度算法** | **单向循环推进**<br>磁头单向从外向内（或反向）扫描柱面，到达边缘后无服务快速飞回起点。 | **毫秒级物理机械寻道 + 不改变请求状态 + 沿途全量服务**<br>C-SCAN 控制的是笨重的物理磁头悬臂，每次移动柱面伴随真实的机械寻道时延（毫秒级）。磁头在单向移动路径上**对经过的所有排队 I/O 请求进行全量服务**，绝不在第一个请求处停顿。 | C-SCAN 飞移不修改请求本身的属性，且追求最小化机械寻道总距离；CLOCK 的“环”是纯逻辑下标循环，根本不存在物理距离概念。 |

### (6) 408 考场标准模型 vs 现代工程实现边界

```
┌────────────────────────────────────────────────────────┐
│ 408 考场标准模型                                        │
│  - 纯单链表/简单环形队列手算，单页框粒度逐步推演             │
│  - 严格按四轮扫描手算改进型 CLOCK                         │
│  - 将 FIFO 视作 Belady 异常典型代表                      │
└───────────────────────────┬────────────────────────────┘
                            │ 现实操作系统内核实现
                            ▼
┌────────────────────────────────────────────────────────┐
│ 现代工程实现边界 (Linux 内核页面回收机制)                  │
│  1. 放弃纯单指针 CLOCK，采用双链活动/非活动 LRU 链表       │
│     - Active List (活跃链表) + Inactive List (非活跃链表)│
│     - 两次访问才晋升 Active，一次未用降级 Inactive       │
│     - 页面仅从 Inactive 链表尾部回收，天然防御单次遍历攻击  │
│  2. 多代 LRU 算法 (MGLRU - Multi-Gen LRU, Linux 6.1+)   │
│     - 将页面按代际 (Generations) 划分为多个层级          │
│     - 大幅降低内存扫描过程中的 CPU 缓存抖动与锁竞争      │
│  3. 批量异步回收机制                                    │
│     - 绝不等到内存彻底耗尽才同步触发置换                  │
│     - 后台守护进程 kswapd 在内存触碰低水位时即异步批量换出│
└────────────────────────────────────────────────────────┘
```

## 3. 本学科内跨章节关联与跨学科协同关联

### 1. 本学科内跨章节关联

#### (1) 与抖动（颠簸）与工作集模型的系统边界
- **共同机制**：物理内存不足时的资源调配。
- **关键差异**：
  - 置换算法是在**物理页框固定**的前提下，决定“换谁代价更小”；
  - 当进程自身运行所必需的**工作集（Working Set）页面数大于系统分配给它的物理页框数**时，任何精妙的页面置换算法（无论是 LRU 还是 CLOCK）都彻底无能为力，进程将陷入高频缺页的系统颠簸（Thrashing）。
- **不可直接迁移的判据**：消除抖动不能靠改良置换算法，必须由操作系统调度器降低多道程序度（挂起部分进程）或动态追加物理页框。

---

### 2. 跨学科协同关联

#### (1) 计算机组成原理：Cache 替换算法与操作系统页面置换
- **共同机制**：局部性原理与冷热数据置换。
- **关键差异**：
  - **硬件纯度与时延差异**：Cache 替换完全由硬件电路在 1 个时钟周期内自动完成，因此 Cache 无法运行复杂的纯软件 CLOCK 或多轮扫描算法，通常采用纯硬件的伪 LRU（PLRU）或随机替换（Random）；
  - **操作系统页面置换**：由内核软件在微秒级（软缺页）或毫秒级（硬缺页）完成，允许运行较为复杂的状态机遍历。
- **不可直接迁移的判据**：Cache 行被替换若为脏数据只需写回主存 DRAM；操作系统页被替换若为脏数据必须写回慢速机械硬盘或 SSD 闪存块，时间惩罚高出 5 个数量级。

## 4. 闭环决策模型与核心认知结论

### (1) 改进型 CLOCK $(u, m)$ 四轮扫描法则极速判别

```
扫描指针指向当前页框，按环形顺时针推进:

第一轮: 严格匹配 (u == 0 且 m == 0)
  - 遇到符合条件的页框: 立即选为受害者，指针前移一位，终止本轮扫描！
  - 本轮扫描过程中: 绝对不修改任何页面的 u 位或 m 位！

第二轮: 若第一轮失败，扫描匹配 (u == 0 且 m == 1)
  - 遇到符合条件的页框: 选为受害者，指针前移一位，终止扫描！
  - 【核心动作】: 扫描过程中所有路过的页面，将其访问位强制置 0 (u <- 0)!

第三轮: 若第二轮仍失败，再次扫描匹配 (u == 0 且 m == 0)
  - 寻找在第二轮中被剥夺访问权 (由 (1, 0) 变为 (0, 0)) 的页面；
  - 遇到符合条件的页框: 选为受害者，指针前移一位，终止扫描。本轮不改标志位。

第四轮: 寻找 (u == 0 且 m == 1) (原先为 (1, 1) 的页面)
  - 必定命中！
```

### (2) 考场做题定性铁律
1. **Belady 异常的判断**：
   - 客观单选题标准考点：**FIFO 算法会出现 Belady 异常**，OPT 和 LRU 绝不出现；
   - 理论判断题深水区：**简单 CLOCK 算法因不是堆栈型算法，亦会发生 Belady 异常**。
2. **改进型 CLOCK 第一轮绝对不修改任何标志位**：
   - 凡是题目称“在第 1 轮扫描中将 $u$ 改为 0”者，均为对算法标准流程的违背。
