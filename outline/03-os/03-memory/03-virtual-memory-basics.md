## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 传统非虚拟内存的物理极限
- **物理困境**：
  - **一次性**：作业必须在运行前一次性全部装入内存。若作业体积大于物理内存容量，根本无法启动。
  - **驻留性**：作业一旦载入内存，将一直常驻其中，直到运行结束才释放。但事实上，一个大型程序在特定时间段内，绝大部分错误处理代码、未用函数模块和超大数据集根本不会被执行，宝贵的物理 DRAM 被极度浪费。
- **虚拟存储器的三大支柱特性**：
  1. **多次性**：无需一次性装入，仅装入当前活跃页面即可开始执行；运行时按需调入其余部分。
  2. **对换性**：不再永久驻留内存，允许将暂时不用的页面换出到外存磁盘交换区（Swap），腾出物理页框。
  3. **虚拟性**：在逻辑上向用户呈现远超实际 DRAM 物理容量的连续地址空间。其上限由计算机系统的**寻址字长（如 32 位为 4GB，64 位为 16EB）**决定，实际容量受限于内外存容量之和。

### (2) 请求分页页表项（PTE）的硬件/软件字段协议
为了支持动态按需调入与换出，请求分页的页表项必须扩充关键状态信息：

```
┌──────────────────┬────────────┬────────────┬────────────┬────────────┬──────────────────┐
│  物理页框号 PFN  │   状态位 P  │   访问位 A  │   修改位 M  │   保护位 R │     外存地址     │
└──────────────────┴────────────┴────────────┴────────────┴────────────┴──────────────────┘
```

1. **状态位（Present / Valid bit，1 位）**：
   - 核心标志：`1` 表示该页已在物理主存中；`0` 表示该页未在内存中（仅在外存磁盘上）。
   - **硬件动作**：MMU 转换地址时，一旦检查到 $P = 0$，立即向 CPU 抛出**缺页异常（Page Fault Exception）**。
2. **修改位 / 脏位（Dirty / Modified bit，1 位）**：
   - 核心标志：`1` 表示该页自载入主存后被执行过写操作；`0` 表示内容与磁盘外存镜像完全一致。
   - **优化意义**：页面置换算法将其淘汰换出时，若脏位为 0，操作系统直接丢弃该物理页框，**免去一次耗时的磁盘写 I/O**；仅当脏位为 1 时，才必须将其写回磁盘外存交换区。
3. **访问位 / 引用位（Access / Reference bit，1 位）**：
   - 记录该页近期是否被访问过，为操作系统页面置换算法（如 Clock 算法、老化算法）提供硬件统计依据。
4. **外存地址**：指出该页在磁盘交换区（Swap Area）或可执行文件映射区中的物理存储位置，供缺页中断处理程序寻址读取。

### (3) 缺页异常处理的严谨全时序（必须建立的软硬件协同图景）

```
[CPU 执行访存指令]
        │
        ▼
   MMU 查页表项 ───── (状态位 P == 1) ─────► [硬件正常翻译物理地址, 读写数据]
        │
        ▼ (状态位 P == 0: 硬件触发缺页异常)
[硬件自动动作]
  1. 压栈当前 PSW 与断点 PC (注意: PC 指向当前引发缺页的指令本身, 而非下一条!)
  2. CPU 模式由用户态切换为内核态
  3. 依据中断向量表跳转至操作系统缺页异常处理程序
        │
        ▼
[操作系统内核软件动作]
  4. 检查合法性: 访问地址是否合法越界? 若越界则向进程发送 SIGSEGV (段错误) 强制终止
  5. 寻找空闲物理页框:
     - 若有空闲页框: 直接分配
     - 若无空闲页框: 执行页面置换算法选择牺牲页 (Victim Page)
         - 检查牺牲页脏位: 若 Modified == 1, 启动磁盘写 I/O 刷盘; 若为 0, 直接作废
  6. 启动磁盘读 I/O: 将目标页从外存载入分配的物理页框中
  7. 【关键调度动作】: 由于磁盘 I/O 耗时毫秒级, 操作系统将当前进程状态置为【阻塞态 (Waiting)】
     操作系统 CPU 调度器介入, 切换至其他就绪进程执行, 保持 CPU 高效运转
        │
        ▼ (磁盘控制器完成数据传输, 产生磁盘 I/O 完成中断)
[I/O 完成中断处理]
  8. 操作系统将目标页的页表项更新: 填入分配的 PFN, 状态位置 1
  9. 将之前阻塞的进程状态移入【就绪态 (Ready)】
        │
        ▼ (调度器重新选中该进程)
[指令重新执行]
  10. 恢复上下文, 执行 iret 异常返回指令
  11. 重新执行先前引发缺页的指令 (此时页表已就绪, MMU 命中执行)
```

## 3. 本学科内跨章节系统性关联

```
                     ┌──────────────────────────────┐
                     │ 操作系统: 缺页异常处理机制   │
                     └──────────────┬───────────────┘
                                    │
        ┌───────────────────────────┴───────────────────────────┐
        ▼                                                       ▼
┌──────────────────────────────┐         ┌──────────────────────────────┐
│ 操作系统: 进程生命周期与状态  │         │ 操作系统: I/O 核心子系统与磁盘│
│  - 缺页等待 I/O: 运行态->阻塞态│         │  - 缺页处理依赖磁盘块 I/O    │
│  - I/O 完成唤醒: 阻塞态->就绪态│         │  - 交换区 (Swap) 的连续读写  │
└──────────────────────────────┘         └──────────────────────────────┘
```

1. **与中断/异常分类体系的因果锚定**：
   - 缺页中断在本质上是**内部异常（Fault, 故障）**，发生在 CPU 执行指令的过程中，由 CPU 内部电路在执行地址翻译时同步检测并抛出。
   - 区别于 Trap（陷阱）和 External Interrupt（外中断）：Fault 异常处理完成后，返回的断点 PC 必须**重新执行产生故障的原指令**，而不能跳转到下一条指令，否则当前指令的数据将彻底丢失。
2. **与进程调度和 CPU 利用率的动态关联**：
   - 发生缺页必定引发进程从**运行态变为阻塞态**，触发操作系统的进程上下文切换。若系统内缺页频率过高，CPU 将把全部时间耗费在等待磁盘 I/O 和上下文切换上，导致整体系统吞吐量归零（即抖动/颠簸）。

## 4. 闭环决策模型与核心认知结论

### (1) 物理页框分配与置换策略全景判定

| 策略组合 | 物理页框配额 | 置换候选范围 | 机制特征与工程评价 |
| :--- | :--- | :--- | :--- |
| **固定分配 + 局部置换** | 进程生命周期内分配的页框数固定不变 | 仅能在本进程已有的页框中置换 | 灵活性差，无法适应进程动态变化的内存需求，容易引发单进程局部抖动。 |
| **可变分配 + 局部置换** | 随缺页率动态微调进程的页框配额 | 仅在本进程内部选择牺牲页 | 进程间互不干扰，操作系统通过缺页率反馈（PFF）动态给高频缺页进程增发页框。 |
| **可变分配 + 全局置换** | 进程分配的页框数随运行动态波动 | 可抢占全系统所有就绪进程的页框 | 最容易实现，资源利用率高；但一个贪婪进程可能抢光其他进程的页框，极易引发连锁抖动。 |

### (2) 考场做题定性铁律
1. **只要发生缺页异常** $\to$ 当前执行进程**必定经历一次从运行态到阻塞态的切换**（因为必须等待极其漫长的磁盘 I/O）。
2. **缺页异常处理返回后** $\to$ CPU 恢复现场所执行的第一条指令**必定是引发缺页的原指令**。
3. **缺页中断是内中断还是外中断？** $\to$ **内中断（故障 Fault）**。而磁盘 I/O 搬运完成发出的信号是**外中断（硬件中断 Interrupt）**。
