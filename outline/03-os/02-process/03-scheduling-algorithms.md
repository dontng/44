## 2. 调度性能评估四大核心量化指标

设进程 $P_i$ 的**到达时刻**为 $A_i$（Arrival Time），**要求服务时间**为 $S_i$（Service / Burst Time），最终**完成时刻**为 $C_i$（Completion Time）：

```
0            Ai (到达)                  Ci (完成)
├─────────────┼────────────────────────────┤
              ◄──────── Ti (周转时间) ──────►
              ┌─────────────┬──────────────┐
              │  等待时间 Wi │ 运行时间 Si  │
              └─────────────┴──────────────┘
```

### (1) 周转时间（Turnaround Time, $T_i$）
进程从提交进入就绪队列到彻底执行完毕所经历的全部物理耗时：
$$T_i = C_i - A_i = W_i + S_i$$
- **系统平均周转时间**：
  $$\bar{T} = \frac{1}{n} \sum_{i=1}^{n} T_i$$

### (2) 带权周转时间（Weighted Turnaround Time, $W_{T,i}$）
周转时间与实际服务时间的比值，衡量作业等待的“相对委屈程度”：
$$W_{T,i} = \frac{T_i}{S_i} = \frac{W_i + S_i}{S_i} = 1 + \frac{W_i}{S_i} \ge 1$$
- **系统平均带权周转时间**：
  $$\bar{W}_T = \frac{1}{n} \sum_{i=1}^{n} W_{T,i}$$
- **物理含义**：带权周转时间必然 $\ge 1$。越接近 1，说明进程运行过程中花在等待上的比例越小，用户体验越顺畅；对于服务时间仅 1 秒的短任务，若周转时间长达 10 秒，其带权周转时间高达 10，用户体验极差。

### (3) 等待时间（Waiting Time, $W_i$）
进程处于就绪队列中等待 CPU 分配的总时间（假定为纯 CPU 密集型任务，不考虑外部 I/O 阻塞）：
$$W_i = T_i - S_i = C_i - A_i - S_i$$
- **系统平均等待时间**：
  $$\bar{W} = \frac{1}{n} \sum_{i=1}^{n} W_i$$

### (4) 响应时间（Response Time, $R_i$）
从用户提交进程到该进程**首次获得 CPU 核心开始执行指令**的时间间隔：
$$R_i = \text{首次开始执行时刻} - A_i$$
- 在交互式分时系统（如桌面操作系统）中，响应时间是衡量系统交互敏捷度的第一核心指标。

## 3. 六大经典调度算法机理与权威对比

| 算法名称 | 调度决策依据 | 抢占性 | 饥饿可能性 | 核心优势 | 致命缺陷与极端现象 |
| :--- | :--- | :---: | :---: | :--- | :--- |
| **先来先服务 (FCFS)** | 按到达就绪队列的时间先后排队 | **非抢占** | **绝无饥饿** | 算法极其简单，逻辑绝对公平 | **护航效应（Convoy Effect）**：长作业排在前面导致后到的大量短作业长时间排队，平均周转时间暴增。 |
| **短作业优先 (SJF)** | 挑选预计运行时间最短的进程先跑 | **非抢占** | **可能饥饿** | 在所有作业**同时到达**时，能取得数学上**最优的平均周转时间** | 严重偏袒短作业；长作业可能被源源不断到达的短作业无限延宕导致**饿死**；实际中难以精确预知运行时间。 |
| **短剩余时间优先 (SRTF)** | 动态挑选剩余运行时间最短的进程 | **抢占式** | **可能饥饿** | 理论上在动态到达负载下能获得**理论最低的平均等待与周转时间** | 新到达更短作业时频繁抢占引发上下文切换开销；长作业饥饿程度比 SJF 更严峻。 |
| **高响应比优先 (HRRN)** | 动态计算响应比 $R_p = 1 + \frac{W}{S}$，挑选数值最大的进程 | **非抢占** | **绝无饥饿** | 综合考虑等待时间与服务时间：短作业先跑，长作业等久了分子增大保底能跑 | 每次低级调度必须遍历就绪队列重新计算所有等待进程的响应比，系统开销较大。 |
| **时间片轮转 (RR)** | 就绪队列排队，每个进程按 FCFS 轮流执行一个固定时间片 $q$ | **抢占式** | **绝无饥饿** | 兼顾公平性与**极佳的交互响应速度**，适用于分时系统 | 时间片 $q$ 太小导致上下文切换开销过大吞噬吞吐量；时间片 $q$ 极大退化为 FCFS。 |
| **多级反馈队列 (MLFQ)** | 多队列按优先级和时间片分级，时间片耗尽降级，新任务进顶层 | **抢占式** | **可能饥饿**<br>(需老化机制防饥饿) | **现代操作系统的通用基石**：兼顾短任务极速响应、I/O 任务高优保障与长任务吞吐 | 算法参数调优复杂（队列数、各级时间片、降级与提拔周期）。 |

## 4. 全流程手算大题基准推演（Minimal Execution Trace）

### (1) 统一基准数据集
为横向精准验证 5 种算法的调度轨迹与指标差异，给定以下 4 个进程的标准到达与服务时间：

| 进程名称 | 到达时刻 ($A_i$) | 要求服务时间 ($S_i$) |
| :---: | :---: | :---: |
| $P_1$ | 0 | 7 |
| $P_2$ | 2 | 4 |
| $P_3$ | 4 | 1 |
| $P_4$ | 5 | 4 |

所有进程总执行时间：$\sum S_i = 7 + 4 + 1 + 4 = 16$ 个时间单位。

### (2) 五大算法调度甘特图与指标手算推演

#### 算法 1：先来先服务（FCFS）
- **甘特图（Gantt Chart）**：
  ```
  时刻:  0           7          11   12             16
  CPU:   |    P1     |    P2    | P3 |      P4      |
  ```
- **时序推演**：$P_1$ 于 0 时刻运行至 7；$P_2$ 于 7 时刻运行至 11；$P_3$ 于 11 时刻运行至 12；$P_4$ 于 12 时刻运行至 16。
- **指标明细**：
  - $P_1$：$C_1 = 7, T_1 = 7 - 0 = 7, W_{T,1} = \frac{7}{7} = 1.00, W_1 = 0, R_1 = 0$
  - $P_2$：$C_2 = 11, T_2 = 11 - 2 = 9, W_{T,2} = \frac{9}{4} = 2.25, W_2 = 5, R_2 = 7 - 2 = 5$
  - $P_3$：$C_3 = 12, T_3 = 12 - 4 = 8, W_{T,3} = \frac{8}{1} = \mathbf{8.00}, W_3 = 7, R_3 = 11 - 4 = 7$
  - $P_4$：$C_4 = 16, T_4 = 16 - 5 = 11, W_{T,4} = \frac{11}{4} = 2.75, W_4 = 7, R_4 = 12 - 5 = 7$
- **系统平均指标**：
  - 平均周转时间：$\bar{T} = \frac{7 + 9 + 8 + 11}{4} = \frac{35}{4} = \mathbf{8.75}$
  - 平均带权周转时间：$\bar{W}_T = \frac{1.00 + 2.25 + 8.00 + 2.75}{4} = \frac{14.00}{4} = \mathbf{3.50}$
  - 平均等待时间：$\bar{W} = \frac{0 + 5 + 7 + 7}{4} = \frac{19}{4} = \mathbf{4.75}$
  - 平均响应时间：$\bar{R} = \frac{0 + 5 + 7 + 7}{4} = \mathbf{4.75}$
- **机制剖析**：短作业 $P_3$ 只需 1 单位服务，却因长作业 $P_1$ 堵在前面硬生生等待了 7 个单位，带权周转时间飙升至 8.00，呈现典型的**护航效应**。

#### 算法 2：非抢占式短作业优先（Non-preemptive SJF）
- **甘特图（Gantt Chart）**：
  ```
  时刻:  0           7    8          12             16
  CPU:   |    P1     | P3 |    P2    |      P4      |
  ```
- **时序推演**：
  - $t = 0$：只有 $P_1$ 到达，$P_1$ 获得 CPU。因非抢占，必须执行完毕，$P_1$ 运行至 $t = 7$；
  - $t = 7$：$P_2(S=4)$、$P_3(S=1)$、$P_4(S=4)$ 均已到达。就绪队列中 $P_3$ 服务时间最短，调度 $P_3$ 运行至 $t = 8$；
  - $t = 8$：剩余 $P_2(S=4)$ 和 $P_4(S=4)$，服务时间相同，按 FCFS 先到达者优先选择 $P_2$ 运行至 $t = 12$；
  - $t = 12$：调度 $P_4$ 运行至 $t = 16$。
- **指标明细**：
  - $P_1$：$C_1 = 7, T_1 = 7, W_{T,1} = 1.00, W_1 = 0, R_1 = 0$
  - $P_3$：$C_3 = 8, T_3 = 8 - 4 = 4, W_{T,3} = \frac{4}{1} = 4.00, W_3 = 3, R_3 = 7 - 4 = 3$
  - $P_2$：$C_2 = 12, T_2 = 12 - 2 = 10, W_{T,2} = \frac{10}{4} = 2.50, W_2 = 6, R_2 = 8 - 2 = 6$
  - $P_4$：$C_4 = 16, T_4 = 16 - 5 = 11, W_{T,4} = \frac{11}{4} = 2.75, W_4 = 7, R_4 = 12 - 5 = 7$
- **系统平均指标**：
  - $\bar{T} = \frac{7 + 10 + 4 + 11}{4} = \frac{32}{4} = \mathbf{8.00}$
  - $\bar{W}_T = \frac{1.00 + 2.50 + 4.00 + 2.75}{4} = \frac{10.25}{4} \approx \mathbf{2.56}$
  - $\bar{W} = \frac{0 + 6 + 3 + 7}{4} = \mathbf{4.00}$
  - $\bar{R} = \frac{0 + 6 + 3 + 7}{4} = \mathbf{4.00}$

#### 算法 3：抢占式短剩余时间优先（SRTF / Preemptive SJF）
- **甘特图（Gantt Chart）**：
  ```
  时刻:  0     2     4    5          7             11             16
  CPU:   | P1  | P2  | P3 |    P2    |      P4      |      P1      |
  ```
- **时序与抢占推演**：
  - $t = 0$：$P_1$ 到达，剩余时间 $R_{\text{rem}}(P_1) = 7$，$P_1$ 开始运行；
  - $t = 2$：$P_2$ 到达，服务时间 $S_2 = 4$。此时 $P_1$ 剩余时间 $7 - 2 = 5$。因为 $4 < 5$，$P_2$ **强行抢占 $P_1$**，$P_2$ 投入运行；
  - $t = 4$：$P_3$ 到达，服务时间 $S_3 = 1$。此时 $P_2$ 剩余时间 $4 - 2 = 2$。因为 $1 < 2$，$P_3$ **强行抢占 $P_2$**，$P_3$ 投入运行；
  - $t = 5$：$P_3$ 运行 1 单位时间顺利完成（$C_3 = 5$）！同时 $P_4$ 于 $t = 5$ 到达（$S_4 = 4$）。
    此时就绪队列剩余情况：$P_2$（剩余 2）、$P_4$（剩余 4）、$P_1$（剩余 5）。最短剩余时间为 $P_2$，$P_2$ 恢复运行至 $t = 7$；
  - $t = 7$：$P_2$ 顺利完成（$C_2 = 7$）！就绪队列剩余：$P_4$（剩余 4）、$P_1$（剩余 5）。调度 $P_4$ 运行至 $t = 11$；
  - $t = 11$：$P_4$ 顺利完成（$C_4 = 11$）！调度最后剩下的 $P_1$ 运行其剩余的 5 个单位，于 $t = 16$ 彻底完成（$C_1 = 16$）。
- **指标明细**：
  - $P_1$：$C_1 = 16, T_1 = 16 - 0 = 16, W_{T,1} = \frac{16}{7} \approx 2.29, W_1 = 16 - 7 = 9, R_1 = 0 - 0 = 0$
  - $P_2$：$C_2 = 7, T_2 = 7 - 2 = 5, W_{T,2} = \frac{5}{4} = 1.25, W_2 = 5 - 4 = 1, R_2 = 2 - 2 = 0$
  - $P_3$：$C_3 = 5, T_3 = 5 - 4 = 1, W_{T,3} = \frac{1}{1} = \mathbf{1.00}, W_3 = 0, R_3 = 4 - 4 = 0$
  - $P_4$：$C_4 = 11, T_4 = 11 - 5 = 6, W_{T,4} = \frac{6}{4} = 1.50, W_4 = 6 - 4 = 2, R_4 = 7 - 5 = 2$
- **系统平均指标**：
  - $\bar{T} = \frac{16 + 5 + 1 + 6}{4} = \frac{28}{4} = \mathbf{7.00}$（**全算法理论最低平均周转时间！**）
  - $\bar{W}_T = \frac{2.2857 + 1.25 + 1.00 + 1.50}{4} = \frac{6.0357}{4} \approx \mathbf{1.51}$
  - $\bar{W} = \frac{9 + 1 + 0 + 2}{4} = \frac{12}{4} = \mathbf{3.00}$（**全算法理论最低平均等待时间！**）
  - $\bar{R} = \frac{0 + 0 + 0 + 2}{4} = \mathbf{0.50}$

#### 算法 4：高响应比优先（HRRN）
- **甘特图（Gantt Chart）**：
  ```
  时刻:  0           7    8          12             16
  CPU:   |    P1     | P3 |    P2    |      P4      |
  ```
- **动态决策时刻的手算响应比推演**：
  - **决策时刻 1 ($t = 0$)**：只有 $P_1$ 在场，$P_1$ 运行 [0, 7]；
  - **决策时刻 2 ($t = 7$)**：$P_1$ 完成，计算当前就绪队列所有进程的响应比：
    - $P_2$：等待时间 $W_2 = 7 - 2 = 5$，$R_{p,2} = 1 + \frac{5}{4} = 2.25$
    - $P_3$：等待时间 $W_3 = 7 - 4 = 3$，$R_{p,3} = 1 + \frac{3}{1} = \mathbf{4.00}$
    - $P_4$：等待时间 $W_4 = 7 - 5 = 2$，$R_{p,4} = 1 + \frac{2}{4} = 1.50$
    - 响应比最大者为 $P_3$（4.00），调度 $P_3$ 运行 [7, 8]；
  - **决策时刻 3 ($t = 8$)**：$P_3$ 完成，重新计算就绪进程响应比：
    - $P_2$：等待时间 $W_2 = 8 - 2 = 6$，$R_{p,2} = 1 + \frac{6}{4} = \mathbf{2.50}$
    - $P_4$：等待时间 $W_4 = 8 - 5 = 3$，$R_{p,4} = 1 + \frac{3}{4} = 1.75$
    - 响应比最大者为 $P_2$（2.50），调度 $P_2$ 运行 [8, 12]；
  - **决策时刻 4 ($t = 12$)**：只剩 $P_4$，$P_4$ 运行 [12, 16]。
- **指标结果**：本算例中各指标与非抢占 SJF 相同（$\bar{T} = 8.00, \bar{W} = 4.00$），但其核心机制是**通过等待时间权重自适应抬升响应比，从而在数学上彻底杜绝长作业无限饥饿**。

#### 算法 5：时间片轮转（RR，设时间片 $q = 2$）
- **入队规则标准约定**：在同一时刻若既有“新进程到达”又有“运行进程时间片耗尽”，**规定新到达进程先排入就绪队尾，刚耗尽时间片的进程紧随其后排在队尾**。
- **就绪队列变化全轨迹手算追踪表**：

| 时刻 $t$ | 当前占用 CPU 执行的进程 | 执行时间区间与剩余时间 | 发生事件与入队顺序处理 | 调度决策后就绪队列状态 (队头 $\to$ 队尾) |
| :---: | :---: | :---: | :--- | :--- |
| **0** | $P_1$ | 运行 [0, 2]，剩余 5 | $P_1$ 于 0 时刻到达，入队 | `[P1]` |
| **2** | $P_2$ | 运行 [2, 4]，剩余 2 | $P_2$ 到达入队；$P_1$ 时间片到期紧随其后 | `[P2, P1]` |
| **4** | $P_1$ | 运行 [4, 6]，剩余 3 | $P_3$ 到达入队；$P_2$ 时间片到期紧随其后 | `[P1, P3, P2]` |
| **5** | - | - | $P_4$ 到达，直接插入队尾 | `[P3, P2, P4]`（$P_1$ 正在 CPU 上） |
| **6** | $P_3$ | 运行 [6, 7]，**完成！** | $P_1$ 时间片到期入队；$P_3$ 只需 1 单位执行 | `[P3, P2, P4, P1]` $\to$ 调度 $P_3$ |
| **7** | $P_2$ | 运行 [7, 9]，**完成！** | $P_3$ 于 $t=7$ 顺利退出，不回队 | `[P2, P4, P1]` $\to$ 调度 $P_2$ |
| **9** | $P_4$ | 运行 [9, 11]，剩余 2 | $P_2$ 于 $t=9$ 顺利退出，不回队 | `[P4, P1]` $\to$ 调度 $P_4$ |
| **11** | $P_1$ | 运行 [11, 13]，剩余 1 | $P_4$ 时间片到期入队 | `[P1, P4]` $\to$ 调度 $P_1$ |
| **13** | $P_4$ | 运行 [13, 15]，**完成！** | $P_1$ 时间片到期入队 | `[P4, P1]` $\to$ 调度 $P_4$ |
| **15** | $P_1$ | 运行 [15, 16]，**完成！** | $P_4$ 退出；只剩 $P_1$ 运行最后 1 单位 | `[P1]` $\to$ 调度 $P_1$ |

- **甘特图（Gantt Chart）**：
  ```
  时刻:  0     2     4     6   7     9    11    13    15   16
  CPU:   | P1  | P2  | P1  | P3| P2  | P4  | P1  | P4  | P1 |
  ```
- **指标明细**：
  - $P_1$：区间 [0,2], [4,6], [11,13], [15,16] $\implies C_1 = 16, T_1 = 16, W_{T,1} \approx 2.29, W_1 = 16 - 7 = 9, R_1 = 0$
  - $P_2$：区间 [2,4], [7,9] $\implies C_2 = 9, T_2 = 9 - 2 = 7, W_{T,2} = \frac{7}{4} = 1.75, W_2 = 7 - 4 = 3, R_2 = 2 - 2 = 0$
  - $P_3$：区间 [6,7] $\implies C_3 = 7, T_3 = 7 - 4 = 3, W_{T,3} = \frac{3}{1} = 3.00, W_3 = 3 - 1 = 2, R_3 = 6 - 4 = 2$
  - $P_4$：区间 [9,11], [13,15] $\implies C_4 = 15, T_4 = 15 - 5 = 10, W_{T,4} = \frac{10}{4} = 2.50, W_4 = 10 - 4 = 6, R_4 = 9 - 5 = 4$
- **系统平均指标**：
  - $\bar{T} = \frac{16 + 7 + 3 + 10}{4} = \frac{36}{4} = \mathbf{9.00}$
  - $\bar{W}_T = \frac{2.2857 + 1.75 + 3.00 + 2.50}{4} = \frac{9.5357}{4} \approx \mathbf{2.38}$
  - $\bar{W} = \frac{9 + 3 + 2 + 6}{4} = \frac{20}{4} = \mathbf{5.00}$
  - $\bar{R} = \frac{0 + 0 + 2 + 4}{4} = \frac{6}{4} = \mathbf{1.50}$

## 5. 多级反馈队列（MLFQ）体系结构与防饥饿机制

多级反馈队列（Multi-Level Feedback Queue）是现代通用操作系统（如 Linux CFS 思想的前身、Windows 线程调度）的核心基石。

```
              【新进程到达】
                    │
                    ▼
顶层队列 Q0: ──► [ P1 ] ──► [ P2 ]  (优先级最高，时间片最小 q = 10ms)
                    │ (用完时间片未完成，强制降级)
                    ▼
次级队列 Q1: ──► [ P3 ] ──► [ P4 ]  (优先级次之，时间片翻倍 2q = 20ms)
                    │ (用完时间片未完成，强制降级)
                    ▼
底层队列 Qk: ──► [ P5 ] ──► [ P6 ]  (优先级最低，时间片最大或 FCFS 轮转)
                    ▲
                    │
           【防饥饿 Priority Boost 周期性全员提拔】
           (每隔周期 S，所有进程无条件重返 Q0 顶层队列)
```

### (1) MLFQ 核心运行法则
1. **法则 1（优先级规则）**：若 $\text{Priority}(A) > \text{Priority}(B)$，CPU 调度 $A$ 运行。
2. **法则 2（同级轮转规则）**：若 $\text{Priority}(A) == \text{Priority}(B)$，在当前队列内部按照 **时间片轮转（RR）** 调度。
3. **法则 3（新任务高优）**：所有新创建的进程首先进入最高优先级队列 $Q_0$。
4. **法则 4（降级处罚机制）**：
   - 进程在当前队列 $Q_i$ 中消耗完了分配给它的全部时间片，无论它中途是否主动放弃 CPU，它都将被**降入下一级队列 $Q_{i+1}$**。
   - 这确保了长计算密集型程序随着时间推移逐步沉入底层队列，防止其长期抢夺 CPU。
5. **法则 5（对交互型任务的优待）**：
   - 若进程在当前队列时间片耗尽之前主动发起 I/O（如等待键盘输入），说明它是交互式任务，它在被唤醒后**保持当前队列级别不变（不降级）**，使其下次唤醒依然能获得快速响应。

---

### (2) 抢占式 MLFQ 的两种考场题目变体
当一个进程正在低优先级队列 $Q_k$ 执行时，顶层队列 $Q_0$ 突然到达了一个新进程：
- **变体 A（立即强行抢占，考场主流）**：调度器立刻中断当前 $Q_k$ 中的进程，保存现场，剥夺 CPU 并分派给 $Q_0$ 的新进程。
  - **被抢占进程的处理**：被抢占的低优先级进程返回原队列 $Q_k$ 的队尾（或队头），**保留其未用完的剩余时间片**，下次调度时继续执行剩余部分，**绝不降级**（因为时间片尚未用完）。
- **变体 B（非抢占至时间片末尾）**：允许当前 $Q_k$ 进程跑完当前这一轮时间片，然后再切换至 $Q_0$。

---

### (3) MLFQ 的致命缺陷与防饥饿机制（Priority Boost / Aging）
- **长作业饥饿陷阱**：
  - 如果系统中持续不断地有大量短交互任务进入顶层队列 $Q_0$，根据法则 1，低优先级队列中的长作业将**永远无法分配到任何 CPU 时间片，发生无限期饥饿（饿死）**。
- **解法：周期性全员提拔（Priority Boost）**：
  - 系统设定一个长周期阈值 $S$（如每隔 1 秒）。
  - **每隔周期 $S$，调度器将系统内所有位于低优先级队列中的进程，不论状态，无条件统一“提拔（Boost）”回最高优先级队列 $Q_0$**，并重置它们的时间片计数器。
  - **双重收益**：
    1. **彻底根除饥饿**：长计算作业在被提拔后能够重新在顶层获得运行机会；
    2. **动态自适应行为变化**：一个原本进行密集数学计算的进程，如果代码逻辑后来转变为处理用户交互，提拔机制能让它自适应恢复高优响应性。

## 6. 常见认知反例与排错

### 反例 1：误以为“短作业优先（SJF）在任何到达条件下平均周转时间都是最优的”
> **反例辨析**：SJF 的平均周转时间最优性存在极其严格的前提——**所有作业必须在同一时刻（$t = 0$）同时到达，或者系统允许抢占（即 SRTF）**。在作业陆续动态到达且采用非抢占式 SJF 时，如果一个耗时 100 秒的超级长作业在 $t=0$ 最先到达并开始执行，后续在 $t=1$ 到达的无数个只需 0.1 秒的短作业都必须硬性等待长作业全部跑完。此时非抢占 SJF 的平均周转时间将极其恶劣，远劣于抢占式的 SRTF。

### 反例 2：误以为“高响应比优先（HRRN）算法支持抢占”
> **反例辨析**：HRRN 在经典教科书与 408 统考模型中**被严格定义为非抢占式算法**。它只在当前正在运行的进程完成或主动阻塞让出 CPU 的“调度决策时刻”，才去计算就绪队列中各个进程的响应比 $R_p = 1 + \frac{W}{S}$ 并挑选最大者投入运行。在进程运行期间，即使外界新到达了一个响应比极高的超短任务，系统也绝不打断当前正在执行的进程。

### 反例 3：误以为“时间片轮转（RR）中时间片设得越小越好”
> **反例辨析**：表面上看，时间片 $q \to 0$ 时，所有进程仿佛都在同时并行推进，响应时间趋于 0。但这是忽略了物理硬件开销的纸上谈兵！每次进程切换都需要保存/恢复寄存器、切换 CR3、遭受 TLB 失效与 Cache 污染，一次上下文切换通常耗费数微秒。若时间片设为 1 微秒，CPU 将有 80% 以上的物理时间纯粹空耗在上下文切换上，系统有用计算吞吐量将趋于崩溃。因此工程上时间片通常设定在 $10\text{ms} \sim 100\text{ms}$，使上下文切换开销占比严格低于 1%。

## 7. 本学科内与跨学科系统性关联

### 1. 本学科内跨章节关联
- [CPU 调度机制](02-cpu-scheduling.md)：
  - **共同机制**：低级调度器在时钟中断或进程状态迁移时调用算法进行决策。
  - **关键差异**：调度机制提供上下文切换的软硬件支撑和 SMP 队列框架；调度算法提供具体的数学挑选策略。
  - **不可直接迁移的判据**：调度算法假定队列查找与排序开销为 0；在真实的每核私有就绪队列中，通常使用红黑树（如 Linux CFS）实现 $O(\log n)$ 或位图实现 $O(1)$ 查找，绝不可能使用全局 $O(n)$ 线性遍历算响应比。
- [死锁处理策略](06-deadlock.md)：
  - **共同机制**：多进程对不可剥夺资源的竞争与等待。
  - **关键差异**：CPU 调度中的饥饿可以通过 Priority Boost 或 Aging 解决，进程虽然饿着但系统仍在运转；死锁是循环等待条件构成的互锁，没有任何进程能够推进，必须通过外力剥夺或回滚。
  - **不可直接迁移的判据**：优先级反转问题中，高优先级进程被低优先级进程阻塞，并非因为调度算法偏袒低优，而是因为二者争夺同一个互斥锁，必须引入优先级继承协议（PIP）解决。
- [输入/输出管理与磁盘调度](../05-io/02-disk-scheduling.md)：
  - **共同机制**：对请求队列按照某种度量（运行时间 vs 寻道距离）进行局部贪心排序。
  - **关键差异**：CPU 调度中的短作业优先（SJF）在磁盘调度中空间同构为**最短寻道时间优先（SSTF）**；
  - **不可直接迁移的判据**：SSTF 磁头在两端往返会导致边缘磁道请求严重饥饿，因而磁盘调度进化为扫描算法（SCAN / 电梯算法），而 CPU 调度由于没有物理磁臂的惯性约束，使用时间片轮转或多级反馈队列。

### 2. 跨学科协同关联
- [数据结构：树与二叉树 / 堆](../../01-ds/04-tree/02-tree-traversal.md)：
  - **共同机制**：优先级队列的高效动态维护。
  - **关键差异**：数据结构侧关注小顶堆/大顶堆在 $O(\log n)$ 时间内的插入与删除；操作系统调度算法关注在时钟中断限定的极短指令周期内完成挑选。
  - **不可直接迁移的判据**：堆结构只能高效获取极值，无法高效支持类似 RR 的 FIFO 遍历，因此现代 Linux 内核就绪队列采用红黑树按虚拟运行时间 `vruntime` 维护。
