## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么从 5 状态扩展为 7 状态？
* **物理矛盾**：经典 5 状态（创建、就绪、运行、阻塞、终止）假定所有进程体都在**物理内存**中。但当系统进程过多、物理内存耗尽时，操作系统必须将暂时不跑的进程换出到**磁盘外存对换区（Swap 区）**以腾出物理空间。
* **挂起（Suspend）的本质**：进程代码和数据被挪到磁盘外存。于是内存中的等待状态分化为外存版本：
  * **活动就绪（在内存） $\leftrightarrow$ 就绪挂起（在外存）**
  * **活动阻塞（在内存） $\leftrightarrow$ 阻塞挂起（在外存）**

### (2) 完整的 7 状态流转图

```
                      【创建态 New】
                            │
               ┌────────────┴────────────┐
               │ 内存充足                │ 内存紧张
               ▼                         ▼
        【活动就绪 Ready】 ◄───激活──── 【就绪挂起 Ready-Suspend】
           (在内存)       ───挂起───►      (在外存Swap区)
               ▲   │
   (时钟到期)  │   │ (进程调度)
               │   ▼
          【运行态 Running】
           (占有CPU)
               │   │
  (主动要资源) │   │ (exit完成 / 致命异常)
               ▼   ▼
        【活动阻塞 Blocked】            【终止态 Terminated】
           (在内存)
               ▲   │
               │   │ (内存紧缺，被中级调度换出)
               │   ▼
        【阻塞挂起 Blocked-Suspend】
           (在外存Swap区，同时在等事件)
               │
               │ (等待的I/O事件完成了)
               ▼
        【就绪挂起 Ready-Suspend】
```

### (3) 四类状态转移背后的不同推手

| 状态流转 | 触发力量 | 执行机制 | 是否为系统调用？ |
| :--- | :--- | :--- | :---: |
| **无 $\to$ 创建态** | 父进程请求开辟子任务 | 显式执行 `fork()` / `CreateProcess()` | **是（系统调用）** |
| **运行态 $\to$ 阻塞态** | 运行进程主动请求资源/等I/O | 显式执行阻塞调用，调用 **Block 原语** | **是（系统调用）** |
| **运行态 $\to$ 终止态** | 运行进程正常执行完毕 | 显式执行 `exit()` | **是（系统调用）** |
| **就绪态 $\to$ 运行态** | 内核调度程序挑选进程 | 进程调度算法（时间片轮转/优先级） | **否（内核调度）** |
| **运行态 $\to$ 就绪态** | 硬件时钟到期剥夺 CPU | 时钟外中断（Timer Interrupt） | **否（外部中断）** |
| **阻塞态 $\to$ 就绪态** | 外部设备数据就绪汇报 | I/O 完成外部硬件中断，调用 **Wakeup 原语** | **否（外部中断）** |
| **内存态 $\leftrightarrow$ 挂起态** | 物理内存紧缺，腾挪空间 | 操作系统的中级调度（Swapping 换入换出） | **否（内核管理）** |
| **运行态 $\to$ 终止态（异常）** | 程序非法操作被硬件捕获 | 硬件异常（除零、段错误） | **否（硬件异常）** |

## 4. 闭环判定模型与核心认知结论

1. **进程只能“自己把自己阻塞”**：处于运行态的进程自己发现要等资源，主动调用 Block 原语进入阻塞；外界无法强行将正常运行的进程打入阻塞态。
2. **进程绝对不能“自己把自己唤醒”**：阻塞态进程未占有 CPU，没有执行指令的能力；必须由其他协作进程或硬件 I/O 中断调用 Wakeup 原语将其唤醒至就绪态。
3. **带“挂起”二字都在外存**：挂起状态的进程体位于磁盘 Swap 区，出入挂起状态永远是**内核中级调度**的内部行为，不向应用程序开放系统调用。
