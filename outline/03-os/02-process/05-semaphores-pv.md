## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么记录型信号量彻底解决了“让权等待”？
* **整型信号量的死穴**：整型信号量是一个整型变量，`P(S)` 内部是 `while (S <= 0); S--;`。当资源没有时，进程在 `while` 里死循环忙等，违背“让权等待”。
* **记录型信号量的物理结构**：
  ```c
  typedef struct {
      int value;           // 可用资源计数器
      struct PCB *queue;   // 阻塞等待队列
  } semaphore;
  ```
* **P 操作（Wait，申请资源）的原子执行流**：
  ```c
  void P(semaphore &S) {
      S.value--;           // 先扣减一个资源额度
      if (S.value < 0) {   // 扣完后发现小于 0，说明原本没有空闲资源！
          block(S.queue);  // 进程调用 Block 原语，自己把自己挂起入队，进入阻塞态！彻底让出 CPU！
      }
  }
  ```
* **V 操作（Signal，释放资源）的原子执行流**：
  ```c
  void V(semaphore &S) {
      S.value++;           // 归还一个资源额度
      if (S.value <= 0) {  // 归还后依然 <= 0，说明阻塞队列里正有别的兄弟在苦苦排队！
          wakeup(S.queue); // 调用 Wakeup 原语，从队列里唤醒一个进程进入就绪态！
      }
  }
  ```

### (2) 408 核心数学物理守恒（信号量数值的符号意义）
* **$S.value > 0$**：表示系统中当前**空闲可用的物理资源数量**；
* **$S.value == 0$**：表示系统中资源恰好分配完毕，且**没有进程在排队等待**；
* **$S.value < 0$**：其绝对值 $|S.value|$ 严格等于**当前正阻塞在该信号量等待队列中的进程个数**！

### (3) 408 每年必考 PV 大题母模板架构

#### 模板一：前趋图关系（2020-45 大题原型）
* **规则**：前趋图中有几条有向边，就定义几个信号量。
* **口诀**：**前 V 后 P，有几条入边就连续做几个 P，有几条出边就连续做几个 V**。
* **信号量初值**：前趋信号量全部初始化为 **0**。

#### 模板二：生产者-消费者与单/多缓冲区模型（2024-46 大题原型）
* **必须设立的三个标准信号量**：
  ```c
  semaphore mutex = 1; // 缓冲区互斥访问锁（若缓冲区大小为 1 且只有一对关系，可省）
  semaphore empty = N; // 物理空位数量（初始为缓冲区容量 N）
  semaphore full = 0;  // 物理满位（已有产品）数量（初始为 0）
  ```
* **绝不能颠倒的顺序死律（防止死锁）**：
  * **先 P 同步，后 P 互斥**：
    ```c
    P(empty); // 1. 先确保有空位
    P(mutex); // 2. 再锁住缓冲区
    // 放入产品...
    V(mutex); // 3. 释放锁
    V(full);  // 4. 增加一个产品，唤醒消费者
    ```
  * **若颠倒为 `P(mutex); P(empty);`**：当缓冲区全满时，生产者先拿了互斥锁，随后卡在 `P(empty)` 睡眠；消费者想取产品却拿不到互斥锁，系统**瞬间死锁**！

## 3. 本学科内跨章节关联（网状贯通）

- $\to$ 关联 [进程状态模型](01-process-states.md)：`block()` 原语使进程从【运行态】变为【阻塞态】；`wakeup()` 原语使进程从【阻塞态】变为【就绪态】。
- $\to$ 关联 [同步与互斥基础](04-process-synchronization.md)：P/V 原语本身对 `value` 和队列的操作是临界区代码，必须通过关中断或硬件 TSL 指令实现其不可分割性。
- $\to$ 关联 [死锁处理策略](06-deadlock.md)：信号量申请顺序不当（如嵌套交叉锁）是打破死锁避免条件、引发系统死锁的最常见根源。

## 4. 闭环判定模型与核心认知结论

* **P 操作的阻塞临界线**：`S.value--` 之后，**只有严格小于 0 时才发生阻塞**（变为 0 时不阻塞，说明拿到了最后一个资源）。
* **V 操作的唤醒临界线**：`S.value++` 之后，**只要小于等于 0 就必须执行唤醒**（因为加 1 之后若是 0，说明原本是 -1，曾有一个进程在排队）。
* **大题检查清单**：
  1. 信号量定义与初值是否清晰写明；
  2. 互斥信号量 `mutex` 的 P 操作是否紧贴临界区最内层；
  3. 生产与消费的配对是否对称闭合。
