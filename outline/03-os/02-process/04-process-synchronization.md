## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须有互斥与同步？
* **物理矛盾**：并发进程共享同一个内存变量或单台打印机。若两个进程在时间片轮转或多核 CPU 上交错执行 `count++`（编译后是读寄存器、加一、写回三条指令），进程调度随时会切断中间状态，引发数据覆盖与竞争冒险（Race Condition）。
* **四大准则的物理底线**：
  1. **空闲让进**：临界区没人用时，想进的进程必须能立刻进入；
  2. **忙则等待**：临界区有人正在使用时，其他企图进入的进程必须老老实实等待；
  3. **有限等待**：等待进入的进程不能无限期挨饿，必须在有限步内获得授权；
  4. **让权等待**：当进程进不去临界区时，必须**主动交出 CPU**，绝不允许占着 CPU 空转死等（破坏此条的叫“忙等 / 自旋锁”）。

### (2) 硬件互斥机制的物理实现（408 大题与底层原理）

#### 机制一：关中断（Interrupt Disabling）
* **原理**：进临界区前执行关中断特权指令，出临界区后开中断。
* **物理逻辑**：CPU 只有响应中断时才会触发进程调度与上下文切换。关了中断，当前进程就霸占了 CPU，任何其他进程都无法打断它。
* **致命缺陷**：
  1. 关中断是**特权指令**，用户程序绝对不允许执行；
  2. **在多核（多 CPU）系统上彻底失效**！一个核关中断只能管住自己，其他核心上的并发进程依然在并行跑并修改内存！

#### 机制二：硬件原子指令 Test-and-Set（TSL 指令）
* **原理**：由 CPU 硬件电路保证的一条不可分割原子指令：
  ```c
  bool TestAndSet(bool *lock) {
      bool old = *lock;
      *lock = true; // 无论原来是什么，都直接上锁
      return old;   // 返回原来的锁状态
  }
  // 使用方式：
  while (TestAndSet(&lock)); // 若原来是 true，则死循环忙等
  // 临界区代码...
  lock = false; // 解锁
  ```
* **硬件保障**：执行 TSL 指令时，CPU 硬件在内部向内存总线发出锁定信号（锁总线），其他任何核心都无法访问该内存字，保证了“测试旧值”与“写入新值”在物理上的不可分割。
* **代价**：**违背了“让权等待”准则**！拿不到锁的进程在 `while` 循环里疯狂空转消耗 CPU，属于典型的**自旋锁（Spinlock）**。

#### 机制三：Swap 指令（交换指令 / XCHG）
* **原理**：原子交换两个内存字的内容，逻辑与 TSL 完全等价，同样通过自旋锁忙等实现。

## 4. 闭环判定模型与核心认知结论

* **自旋锁适用场景判定**：
  * **单核 CPU 系统**：绝不应使用自旋锁！因为等待者忙等占满 CPU，导致持锁者永远拿不到 CPU 来释放锁，只能白白耗尽时间片。
  * **多核 CPU 系统且临界区极短**：首选自旋锁！因为进程休眠再被唤醒涉及两次沉重的上下文切换（微秒级），自旋几纳秒能大幅节省开销。
* **四大准则违背排错**：看到代码里有 `while(turn != i);` 空循环等待，该机制**必定违背“让权等待”**。
