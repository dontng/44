## 1. 2027 考纲官方定位与考查核心
- **考察要点**：
  - 调度的多级层次体系：高级调度（作业调度）、中级调度（内存对换调度）、低级调度（进程调度）的时空尺度、触发频率与功能分工。
  - 进程调度的时机与限制条件：自旋锁/关抢占原子上下文 vs 可睡眠内核互斥锁临界区、用户临界区的可调度性辨析。
  - 进程上下文切换（Context Switch）的硬件与软件机制：`pt_regs` 用户态现场与内核态调度上下文（`thread_struct`）的分层保存、CR3 切换带来的 TLB 与 Cache 隐性开销。
  - 调度方式分类：非抢占式（非剥夺方式）与抢占式（剥夺方式）的优缺点与适用场景。
  - 现代对称多处理机（SMP）调度机制：公共就绪队列 vs 每核私有就绪队列（Per-CPU Runqueue）、处理器亲和性（软亲和与硬亲和）、负载均衡（推迁移与工作窃取 Pull Migration）及工程权衡。
  - 闲逛进程（Idle 进程）的物理特性与执行逻辑。

## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 调度的三级层次体系（各司其职的时空尺度）
操作系统在管理从外部作业提交到最终 CPU 执行的全生命周期中，设立了三个不同频度和空间尺度的调度层次：

```
                     ┌──────────────────────────────┐
                     │    外存后备作业 (磁盘)       │
                     └──────────────┬───────────────┘
                                    │ 【高级调度 (作业调度)】
                                    │ 从外存调入内存，建立 PCB
                                    ▼
       ┌─────────────────────►【活动就绪态 (内存)】◄────────────────────┐
       │ (中级调度：换入)            │                                 │
┌──────┴──────────────┐             │ 【低级调度 (进程调度)】         │
│ 就绪挂起态 (外存)   │             │ 分配 CPU 时间片                 │
│ 阻塞挂起态 (外存)   │             ▼                                 │
└──────▲──────────────┘      【运行态 (CPU)】 ─────────────────────────┘
       │                            │ (时钟中断到期 / 高优先级抢占)
       │ (中级调度：换出)           │
       └────────────────────────────┘ (内存紧缺时挂起)
```

#### 三级调度全方位权威对比表：

| 调度层次 | 调度的源头与目的队列 | 调度发生的时空尺度与频率 | 核心职责与系统目标 |
| :--- | :--- | :--- | :--- |
| **高级调度**<br>*(作业调度 / 长程调度)* | 外存后备作业队列 $\to$ 内存活动就绪队列 | **几秒至数分钟一次**<br>(频率最低) | 决定接纳多少作业入内存；为作业分配内存、初始化 PCB、建立页表，**控制多道程序并发度**。 |
| **中级调度**<br>*(内存调度 / 挂起调度)* | 内存活动队列 $\longleftrightarrow$ 外存挂起队列 (Swap) | **数百毫秒一次**<br>(频率居中) | 应对物理内存吃紧，将暂时无法运行的进程代码数据换出到磁盘对换区，**提高物理内存利用率与系统吞吐量**。 |
| **低级调度**<br>*(进程调度 / 短程调度)* | 内存活动就绪队列 $\to$ CPU 运行核心 | **几毫秒至几十毫秒一次**<br>(频率极高，每秒数十至数百次) | 按照某种调度算法从就绪队列挑选下一个占有 CPU 的进程，执行上下文切换，**实现 CPU 核心的高效分时复用**。 |

### (2) 进程调度的时机：什么时候“能调度”？什么时候“严禁调度”？

#### 1. 绝对【严禁】进行进程调度的原子上下文
在操作系统的运行过程中，以下情况绝对禁止触发进程调度或睡眠：
1. **在执行中断服务程序（ISR）的过程中**：
   - 中断服务程序运行在中断上下文中，不属于任何特定进程，没有独立的 `task_struct` 进程实体与私有上下文栈。若在 ISR 中调度睡眠，中断上下文将被永远挂起，导致中断嵌套栈崩溃与系统锁死。
2. **在持有自旋锁（Spinlock）或处于关抢占（`preempt_disable`）的内核临界区中**：
   - **底层物理逻辑**：自旋锁专为多核多线程极短临界区设计，CPU 获取锁失败时在原地紧凑循环自旋（忙等待）。
   - **死锁禁令**：如果进程在持有自旋锁期间主动调用 `schedule()` 调度让出 CPU，该进程将带着锁进入睡眠！此时若在同一个单核 CPU 上调度出另一个新进程，新进程恰好也试图申请同一把自旋锁，新进程将进入无限自旋，而持有锁的原进程永远没有机会再次被调度上 CPU 来释放锁，**直接造成单核 CPU 原地死锁**！因此持有自旋锁期间，操作系统通过自增 `preempt_count` 强制关闭内核抢占。
3. **在执行屏蔽中断的原语操作中**：关中断旨在保证微观操作的原子性，在此期间严禁被打断或切换。

---

#### 2. 可以且经常【允许】发生进程调度的场景

| 场景分类 | 具体场景与发生条件 | 是否允许发生调度 | 底层原理解析 |
| :--- | :--- | :---: | :--- |
| **用户临界区** | 进程在用户态访问由互斥锁保护的共享全局变量或共享文件 | **允许调度** | 用户临界区只保障**数据的一致性与互斥性**，并不霸占底层 CPU。时间片到期或有高优先级进程就绪时，操作系统完全可以强行剥夺 CPU。其他进程若也试图进入该用户临界区，会在互斥锁处被阻塞，绝不危害内核安全。 |
| **可睡眠内核临界区** | 进程通过系统调用进入内核态后，访问由**可睡眠互斥锁（`struct mutex` / 信号量）**保护的内核资源 | **允许调度** | 可睡眠互斥锁的设计初衷就是支持睡眠等待。申请锁失败或需等待慢速 I/O 时，内核代码主动调用 `schedule()` 让出 CPU，锁的持有者随后会通过 `wake_up()` 唤醒它。 |
| **抢占式内核态运行** | 进程处于内核态执行普通非原子系统调用逻辑（`preempt_count == 0`，未持自旋锁） | **允许抢占** | 在现代抢占式操作系统内核（如 Linux `CONFIG_PREEMPT`）中，内核态代码不再神圣不可侵犯，更高优先级的就绪进程可以直接在内核态剥夺低优先级进程的 CPU。 |

---

#### 3. 必须【触发】低级调度的客观时机
- **主动触发调度（非抢占时机）**：
  1. 当前运行进程正常执行完毕，调用 `exit()` 系统调用；
  2. 当前运行进程发生致命硬件异常（如非法指令、除以零、段错误）被强制杀死；
  3. 当前运行进程因显式系统调用（如 `read()`、`sleep()`、`P(S)`）或缺页异常主动放弃 CPU 进入阻塞态。
- **被动触发调度（抢占时机）**：
  1. 硬件定时器时钟中断到期，当前进程分配的时间片消耗殆尽；
  2. 外部中断（如网卡接收数据中断、磁盘 I/O 完成中断）唤醒了一个优先级更高的就绪进程，调度器设置 `need_resched` 标志，在中断返回前触发抢占调度。

## 3. 进程上下文切换的底层时序与开销剖析

### (1) 上下文分层保存：用户态上下文帧 vs 内核态调度上下文
一次完整的进程上下文切换绝非仅仅保存几个通用寄存器，其在操作系统底层分为两个清晰的硬件与软件分层：

```
 用户态 (Ring 3) ──► 发生中断 / 系统调用 (陷入内核)
                           │
                           ▼
 内核态 (Ring 0) ──► 1. 硬件与中断汇编桩将【用户态现场 pt_regs】压入【当前进程内核栈】:
                        (用户 PC/RIP, RSP, RFLAGS, RAX, RCX, RDX 等)
                           │
                           ▼
                     2. 内核逻辑判断需要切换进程，调用 schedule()
                           │
                           ▼
                     3. 调用底层核心函数 switch_to(prev, next):
                        - 保存 prev 的【内核态调度上下文】到 PCB (task_struct->thread)
                          (包含内核栈指针 KSP、callee-saved 寄存器 RBX/RBP/R12~R15、内核 RIP)
                        - 切换 CPU 栈指针 RSP 指向 next 进程的内核栈
                        - 切换页表基址寄存器 CR3 (加载 next 进程的一级页目录物理地址)
                        - 从 next 的内核栈中恢复其内核寄存器与被调用者保存寄存器
                           │
                           ▼
                     4. 执行 iret / sysret 返回指令:
                        - 从 next 进程内核栈弹出其【用户态现场 pt_regs】
                        - 硬件将 CPU 降级到用户态 (Ring 3)，恢复用户 PC 开始执行 next 进程
```

---

### (2) 进程切换的直接开销与隐性物理开销

| 开销类别 | 具体硬件/系统动作 | 耗时量级与物理影响 |
| :--- | :--- | :--- |
| **直接开销** | 1. 保存当前进程寄存器到内核栈与 PCB；<br>2. 运行调度算法挑选下一个进程；<br>3. 载入新进程的寄存器现场与内核栈指针；<br>4. 刷新/更新页表基址寄存器 `CR3`。 | **数微秒（$\approx 1 \sim 5\mu\text{s}$）**。<br>纯粹的 CPU 机器指令执行与内存总线访存开销。 |
| **隐性开销 1：TLB 局部/全局失效** | 写入新的 CR3 寄存器会导致 CPU 硬件 MMU 内部的 **TLB（转换后援缓冲器）表项全部或部分置为无效（Flush）**。 | 新进程刚开始运行的短时间内，每一条指令取指和数据访存都遭遇 **TLB 冷缺失（Cold Misses）**，必须频繁经历多级页表的主存遍历开销。*(注：带 PCID/ASID 特性的 CPU 可部分缓解此开销)*。 |
| **隐性开销 2：Cache 污染与冷失效** | 新进程的代码与数据与旧进程完全不同，新进程的访存将逐步替换淘汰片内 L1/L2/L3 高速缓存中的缓存行。 | 在切换后的数百个时钟周期内，新进程遭遇密集的 **Cache 冷缺失**，导致 CPU 频繁停顿（Stall）等待物理 DRAM 慢速数据交付。 |

## 4. 2027 考纲重点：现代对称多处理机（SMP）调度机制

在多核多处理器系统中，每个 CPU 核心都具有独立的计算能力，调度机制的设计面临全新的可扩展性与缓存局部性挑战。

### (1) 公共就绪队列 vs 每核私有就绪队列（Per-CPU Runqueue）

```
1. 传统公共就绪队列架构 (全局单队列):
   [ 全局就绪队列 ] ◄── 全局大自旋锁 (Spinlock)
       ▲    ▲    ▲
       │    │    │ (所有 CPU 核心每次调度都争夺同一把全局大锁)
     [CPU 0] [CPU 1] [CPU 2]

2. 现代每核私有就绪队列架构 (Per-CPU Runqueue, 无锁并行):
   [就绪队列 0]    [就绪队列 1]    [就绪队列 2]
       ▲              ▲              ▲
       │ (私有锁访问)   │ (私有锁访问)   │ (私有锁访问)
     [CPU 0]        [CPU 1]        [CPU 2]
```

- **公共就绪队列的致命瓶颈**：随着处理器核心数从 4 核增长到 64 核甚至 128 核，所有核心每次调度都必须先竞争同一把全局自旋锁。绝大部分 CPU 核心的时间将被浪费在死锁争用的自旋等待中，系统吞吐量不升反降。
- **每核私有就绪队列的优势**：每个 CPU 核心维护自己专属的就绪队列，核心只锁自己的队列，彻底消除了核间锁争用，实现了理论上的线性可扩展性。

---

### (2) 处理器亲和性（Processor Affinity）
- **软亲和性（Soft Affinity）**：
  - 调度器在为进程分配 CPU 核心时，**尽量（优先）将其调度回上次运行它的同一个 CPU 核心**。
  - **物理收益**：该核心的 L1/L2 高速缓存与 TLB 中可能依然残留着该进程的“热数据（Warm Cache）”，命中率显著高于被抛到一个全新的冷核心。
- **硬亲和性（Hard Affinity）**：
  - 操作系统向用户提供系统调用接口（如 Linux 的 `sched_setaffinity()`），显式指定某个关键进程**只能在特定的几个 CPU 核心上运行，严禁漂移到其他核心**。常用于高吞吐网络服务（网卡中断核心绑定）或高性能计算任务。

---

### (3) 负载均衡（Load Balancing）：推迁移 vs 拉迁移

当采用每核私有就绪队列后，必然面临核心间负载不均的矛盾（例如 CPU 0 的队列排了 10 个进程，而 CPU 1 的队列空空如也）。系统通过两类机制实现任务迁移：

| 负载均衡方式 | 触发主体与执行时机 | 动作机制与数据流动 |
| :--- | :--- | :--- |
| **推迁移（Push Migration）** | 内核后台周期性守护线程（如负载均衡定时器） | 定期检查所有 CPU 核心的队列长度，发现严重不均衡时，主动将超载核心上的某些就绪任务**“推（Push）”**到轻载或空闲核心的队列中。 |
| **拉迁移（Pull Migration）**<br>*(工作窃取 Work Stealing)* | 当某个 CPU 核心运行完毕所有就绪任务、即将变为空闲时 | 空闲核心主动查看邻近繁忙核心的私有就绪队列尾部，**“偷取（Steal / Pull）”**一个或多个任务挂入自己的就绪队列并立即执行。 |

> **核心工程权衡**：
> - **少迁移（保障缓存亲和性）**：进程常驻同一核心，Cache 命中率高，执行速度快，但可能导致某些核闲置而某些核超负荷；
> - **多迁移（保障负载绝对均衡）**：所有 CPU 核心充分利用，但频繁迁移导致进程在不同的核心之间反复“冷启动”，摧毁 L1/L2 Cache 局部性。
> - **现代调度器的折中解法**：优先在具有共享 L3 Cache 的同一物理 CPU 插槽（Socket / NUMA Node）内部的核心之间迁移任务；只有在全局严重失衡时才进行跨 NUMA 节点的远程迁移。

### (4) 闲逛进程（Idle 进程）
- **本质与标识**：系统启动时由内核创建的第一个内核线程（在 Linux 中称为 0 号进程 `swapper / idle`），每个 CPU 核心独占一个专属的 Idle 任务。
- **调度优先级**：**处于全局绝对最低优先级**。只有当当前核心的就绪队列没有任何可运行的普通进程时，调度器才会挑选 Idle 进程执行。
- **硬件行为**：
  - Idle 进程绝不进行复杂的算术运算，它在无限循环中执行硬件级的**低功耗等待指令**（如 x86 的 `HLT` 指令或 ARM 的 `WFI` 指令）。
  - 执行 `HLT` 指令使 CPU 核心时钟发生器降频或挂起流水线，关闭大部分门电路以显著降低功耗与发热，直到下一个硬件外部中断到来时自动唤醒 CPU 退出低功耗状态。

## 5. 条件变迁与机制变体

### 调度方式：非抢占式 vs 抢占式

| 对比维度 | 非抢占式调度（Non-preemptive / 非剥夺方式） | 抢占式调度（Preemptive / 剥夺方式） |
| :--- | :--- | :--- |
| **CPU 剥夺机制** | 一旦分配 CPU，必须运行至**主动退出、主动阻塞或发生异常**，中途绝不允许外界强行剥夺。 | 依据时钟中断或优先级规则，系统可随时**强行打断当前运行进程并剥夺 CPU**。 |
| **系统开销** | 上下文切换频率极低，调度算法开销极小。 | 上下文切换频繁，具有一定的直接与隐性切换开销。 |
| **实时响应性** | **极差**。若长作业或死循环任务霸占 CPU，后到的短任务或紧急任务将被无限延宕。 | **极佳**。高优先级紧急任务与交互式任务能够即时抢占 CPU 获得毫秒级响应。 |
| **适用场景** | 早期早期单道/多道批处理系统。 | 现代所有通用操作系统（Linux, Windows, macOS, Android, iOS）与实时操作系统（RTOS）。 |

## 6. 常见认知反例与排错

### 反例 1：误以为“处于内核态的进程绝对不能被调度或抢占”
> **反例辨析**：必须区分“原子上下文临界区”与“普通内核态系统调用”。早期 Unix 系统为了简化内核设计，确实规定只要进程处于系统调用的内核态下就绝不发生进程切换（非抢占式内核）。但**现代通用操作系统全盘引入了抢占式内核（Preemptive Kernel）**！当一个进程正在内核态执行普通非临界代码时，只要它没有持有自旋锁且没有关闭中断（`preempt_count == 0`），如果此时中断处理程序唤醒了一个实时高优先级进程，系统在中断返回时会立即触发内核态抢占，毫不犹豫地剥夺当前进程的 CPU！

### 反例 2：误以为“只要调用了 `schedule()` 调度函数，就一定会发生进程上下文切换”
> **反例辨析**：调度算法的决策与底层上下文切换是解耦的两步。当内核触发 `schedule()` 时，低级调度器遍历就绪队列进行挑选：若经过优先级或时间片权衡，调度算法挑选出来的“最优进程”**恰好依然是当前正在运行的进程本身**（例如就绪队列中没有更高优先级的其他任务），调度函数会直接跳过上下文切换阶段，直接返回继续执行当前进程。**调度决策发生不等于上下文切换必然发生**。

### 反例 3：误以为“用户态临界区与内核态临界区一样严禁进程调度”
> **反例辨析**：两者保护的目标层次截然不同。用户态临界区（如用 P/V 操作或 `pthread_mutex` 保护的全局变量）旨在保证**应用程序数据的一致性**，它并不危害操作系统内核数据结构的安全。如果持有用户互斥锁的进程在用户临界区内时间片用尽，操作系统会毫不犹豫地剥夺它的 CPU，让其他进程上台运行。其他进程如果试图进入该临界区，会在互斥锁处被置入阻塞态等待，这完全属于正常的并发控制逻辑，绝不存在内核崩溃的危险。

## 7. 本学科内与跨学科系统性关联

### 1. 本学科内跨章节关联
- [进程状态模型](01-process-states.md)：
  - **共同机制**：就绪态向运行态跃迁的驱动实体就是 CPU 低级调度器。
  - **关键差异**：状态模型关注宏观状态分类；调度机制深入微观调度触发时机与 SMP 队列设计。
  - **不可直接迁移的判据**：发生中级调度换出时，被换出的是进程的虚拟内存空间，低级调度器在内存中选择任务时必须排除处于挂起态的进程。
- [典型调度算法](03-scheduling-algorithms.md)：
  - **共同机制**：低级调度器在决策具体由谁占有 CPU 时的策略逻辑。
  - **关键差异**：调度机制提供“何时调度、如何切换”的硬件与框架基础设施；调度算法提供“挑选哪一个”的具体数学规则（FCFS, SJF, RR）。
  - **不可直接迁移的判据**：调度算法通常假定上下文切换开销为 0；但在真实的 CPU 调度机制中，时间片大小必须远大于上下文切换耗时，否则系统将被调度开销反噬。
- [进程同步与互斥基础](04-process-synchronization.md)：
  - **共同机制**：临界资源的互斥访问控制。
  - **关键差异**：同步互斥关注信号量 `value` 增减与锁的获取；调度机制关注锁机制对调度器行为的硬件约束（如持自旋锁严禁调度）。
  - **不可直接迁移的判据**：在单处理器单核环境下，自旋锁毫无意义且可能导致死锁（必须使用可睡眠锁或关中断）；自旋锁只适用于对称多处理机（SMP）多核系统。

### 2. 跨学科协同关联
- [计组：硬件级虚拟存储与地址转换](../../02-co/03-memory-hierarchy/03-virtual-memory-hardware.md)：
  - **共同机制**：进程切换时页表基址寄存器（CR3 / PDBR）的硬件重载与虚实地址映射环境切换。
  - **关键差异**：
    - **操作系统侧**：在 `switch_to` 中执行汇编特权指令更新 CR3，管理不同进程的顶级页目录物理基地址；
    - **计组侧**：硬件 MMU 捕获 CR3 的更新信号，自动触发 TLB 表项失效，并在后续指令访存中自动通过硬件状态机（Page Table Walker）遍历新页表。
  - **不可直接迁移的判据**：操作系统只负责写入新 CR3，无法干预 TLB 硬件内部的比对时序；若硬件支持 PCID/ASID，操作系统可通过打标签避免全盘清空 TLB。
- [计组：多处理器架构与硬件多线程](../../02-co/05-cpu/04-multiprocessor-and-multithreading.md)：
  - **共同机制**：多核对称多处理机（SMP）与同时多线程（SMT / 超线程）资源共享。
  - **关键差异**：
    - **计组侧**：关注物理核心之间的总线嗅探、缓存一致性协议（MESI）与 NUMA 架构访存不对称性；
    - **操作系统侧**：利用计组暴露的拓扑信息建立每核私有就绪队列，实现软硬亲和性绑定与工作窃取负载均衡。
  - **不可直接迁移的判据**：超线程在计组硬件上只是复制了寄存器架构状态（Architectural State）而共享同一个执行引擎；操作系统调度器若将两个高负载 CPU 密集型任务分派到同一物理核心的两个超线程上，其吞吐性能并不能翻倍。
