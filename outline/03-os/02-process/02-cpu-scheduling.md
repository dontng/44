## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 调度的三级层次体系（各司其职的时空尺度）

```
                     ┌──────────────────────────────┐
                     │    外存后备作业 (磁盘)       │
                     └──────────────┬───────────────┘
                                    │ 【高级调度 (作业调度)】
                                    │ 从外存调入内存，建立 PCB
                                    ▼
       ┌─────────────────────►【活动就绪态 (内存)】◄────────────────────┐
       │ (中级调度：换入)            │                                 │
┌──────┴──────────────┐             │ 【低级调度 (进程调度)】         │
│ 就绪挂起态 (外存)   │             │ 分配 CPU 时间片                 │
│ 阻塞挂起态 (外存)   │             ▼                                 │
└──────▲──────────────┘      【运行态 (CPU)】 ─────────────────────────┘
       │                            │ (时钟中断到期 / 高优先级抢占)
       │ (中级调度：换出)           │
       └────────────────────────────┘ (内存紧缺时挂起)
```

1. **高级调度（作业调度 / 长程调度）**：
   * **尺度**：几秒到几分钟一次（发生频率最低）。
   * **任务**：从外存后备队列中挑选一批作业，为它们分配内存与系统资源，**建立进程控制块（PCB）**，使其进入就绪队列。
2. **中级调度（内存对换调度 / 中程调度）**：
   * **尺度**：几百毫秒一次。
   * **任务**：当物理内存吃紧时，把暂时不跑的就绪或阻塞进程**对换（Swap）到磁盘外存**，变成**挂起状态**；待内存宽裕时再换回内存。
3. **低级调度（进程调度 / 短程调度）**：
   * **尺度**：几十毫秒一次（**发生频率极高，每秒数十至数百次**）。
   * **任务**：从内存就绪队列中按照某种策略选择一个进程，分配 CPU 运行。

### (2) 进程调度的时机：什么时候“能调度”？什么时候“绝不能调度”？

#### 1. 绝对【不能】进行进程调度与切换的紧急时刻
* **在处理中断的过程中**：中断处理是系统最底层的防御机制，嵌套乱序会导致中断栈破坏；
* **在操作系统内核程序临界区中**：内核临界区通常在操作内核全局数据结构（如进程就绪队列链表），此时必须关中断或持自旋锁，绝不能在此期间让其他进程介入修改该链表；
  * *(注：在普通“用户程序临界区”中是可以进行调度的，因为用户临界区锁住的只是共享变量，换人跑不影响内核稳定性)*；
* **在需要屏蔽中断的原语操作中**。

#### 2. 必须【触发】进程调度的时机
* 当前进程运行结束（执行 `exit()` 系统调用）；
* 当前进程发生硬件异常被强制杀死；
* 当前进程请求 I/O 被阻塞（调用 Block 原语）；
* 时间片用尽（时钟外中断触发）；
* 就绪队列中出现了优先级更高的就绪进程（在抢占式调度下）。

---

### (3) 抢占式 vs 非抢占式调度方式
* **非抢占式（非剥夺方式）**：一个进程拿到 CPU 后，除非它自己**主动退出、主动阻塞或发生致命错误**，否则任何外部事件都不能剥夺它的 CPU。实现简单，但**完全无法满足实时交互系统**（一个死循环程序能让整个系统卡死）。
* **抢占式（剥夺方式）**：操作系统可以依据时钟中断或优先级规则，**强行中断当前正在运行的进程，把 CPU 剥夺出来分配给更紧急的进程**。现代所有主流通用操作系统（Linux、Windows、macOS）全盘采用抢占式调度。

### (4) 闲逛进程（Idle 进程）
* 当就绪队列中没有任何一个可运行的进程时，CPU 该干什么？
* 操作系统会运行一个特殊的内核进程——**闲逛进程（PID 为 0）**。
* **物理特性**：
  * **优先级是全局最低的**，只要有任何一个正经进程就绪，闲逛进程立刻被抢占；
  * 它在 CPU 上执行一条低功耗等待指令（如 x86 的 `HLT` 指令），让 CPU 进入低功耗睡眠，等待下一次外中断唤醒。

## 4. 闭环判定模型与核心认知结论

* **调度频率对比**：高级调度（最慢） $\ll$ 中级调度 $\ll$ 低级调度（最快，毫秒级）。
* **内核临界区 vs 用户临界区调度判定**：
  * 用户临界区（访问普通共享文件/变量） $\implies$ **允许调度**（只保证互斥，不霸占 CPU）；
  * 内核临界区（访问就绪队列、PCB 链表等核心数据） $\implies$ **严禁调度**（必须一气呵成）。
