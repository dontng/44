## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 为什么必须硬性区分“用户态”与“内核态”？
* **物理矛盾**：物理硬件（CPU、内存、I/O 端口）只有一套，上面并发运行着多个不互信的用户程序。若允许任何程序直接执行特权指令，单点崩溃就会使全机死锁或蓝屏。
* **硬件机制**：CPU 芯片内部的程序状态字寄存器（PSW）设置专门的状态标志位（如 x86 的 CPL 环级：Ring 0 vs Ring 3）：
  * **内核态（Ring 0 / 管态 / 特权态）**：运行 OS 内核，允许执行**所有机器指令**（包含关中断、改页表基址、清空 Cache、直接操作物理端口）。
  * **用户态（Ring 3 / 目态 / 用户模式）**：运行普通应用程序，**只能执行非特权指令**（算术逻辑运算、寄存器赋值、跳转、读写自身内存）。
* **硬件截获**：在用户态下企图执行特权指令，CPU 硬件流水线立刻判定为非法指令，触发**硬件内部异常（Fault）**，强制将控制权移交内核异常处理程序处理。

### (2) 状态转换的非对称性
* **用户态 $\to$ 内核态（硬件开门）**：
  * **唯一合法通道**：必须通过**陷入指令（Trap）**、**硬件异常**或**外部中断**；
  * **硬件强制改变**：由硬件隐指令将 PSW 特权位改为内核态，自动切换到内核栈，保存断点 PC/PSW。
* **内核态 $\to$ 用户态（软件指令）**：
  * 内核完成服务后，执行**特权返回指令（如 `iret` / `sysret`）**；
  * 硬件从内核栈弹出原用户断点 PC 和 PSW，自动恢复为用户态特权级，栈指针切回用户栈。

## 4. 闭环判定模型与核心认知结论

* **陷入指令的特权级归属**：**陷入指令是非特权指令！** 用户程序在用户态执行它，执行后由硬件将 CPU 切入内核态。
* **发生时刻 vs 处理时刻**：中断或异常**可以在用户态发生**，但其处理例程**绝对在内核态执行**。
