## 2. 核心机理与物理必然性（为什么这么设计？）

### (1) 文件的逻辑结构与物理分配视图

#### 1. 文件的逻辑结构（程序员视角）
- **无结构文件（流式文件，Stream-oriented File）**：
  - 文件内部是无结构、平坦连续的**二进制字节流（Byte Stream）**。
  - **代表体系**：UNIX / Linux（“一切皆文件”哲学）。文件只负责按字节存放数据，其内部语义（ELF 格式、JSON 文本、MP4 视频）完全交由用户态应用程序自行解析，操作系统内核不做强制格式限制。
- **有结构文件（记录式文件，Record-oriented File）**：
  - 文件由一组逻辑上连续的**记录（Records）**组成，每条记录由若干数据项构成：
    - **定长记录**：每条记录长度严格相等（设为 $L$ 字节）。若要访问第 $i$ 条记录，直接利用公式 $\text{Offset} = (i - 1) \times L$ 即可在 **$O(1)$ 时间内完成随机存取**。
    - **变长记录**：每条记录长度各异，必须建立**索引表（Index File）**辅助定位，否则只能退化为从头顺序扫描 $O(n)$。
    - **索引顺序文件（Indexed Sequential File）**：将变长记录分块（如每组 100 条记录），只为每块的第一条记录建立主键索引。检索时先查索引表（确定块），再在块内微小顺序检索，大幅减少索引表体积。

#### 2. 文件保护机制（口令、加密与访问控制列表）

| 保护机制 | 物理实现机理 | 优势 | 物理短板 / 考点陷阱 |
| :--- | :--- | :--- | :--- |
| **口令保护** | 用户打开文件时提供口令，与系统内部保存的口令比对 | 开销极小，速度快 | 口令存放在系统内部（如 FCB 中），安全性差；容易被内存扫描破解 |
| **密码加密** | 采用加密算法（如 AES）将文件明文编码为密文，访问时用密钥解密 | 保密性极强，即使磁盘被盗也无法直接读取 | 加解密需大量 CPU 运算，频繁读写文件时性能开销显著 |
| **访问控制列表 (ACL)** | 为每个文件维护一张精细的访问控制矩阵，记录各用户 ID 及具体权限 | 权限控制极其精确，支持灵活授权 | 控制表占用大量存储空间，遍历列表时存在开销 |
| **UNIX 9位权限位**<br>(用户三元组) | 将用户划分为 3 类（所有者 `u`、同组用户 `g`、其他用户 `o`），每类分配读写执行（`rwx`）3 位二进制 | **仅占用 9 个比特（微小开销）**，完美契合标准目录项 | 无法针对某个具体的单个外部用户进行单独权限授予 |

> **UNIX 9 位权限手算示例**：若某文件权限字符串为 `-rwxr-xr--`：
> - 所有者（Owner）：`rwx` $\implies 111_2 = \mathbf{7}$（可读、可写、可执行）；
> - 同组人（Group）：`r-x` $\implies 101_2 = \mathbf{5}$（可读、不可写、可执行）；
> - 其他人（Others）：`r--` $\implies 100_2 = \mathbf{4}$（仅可读）；
> - 八进制权限掩码即为 **`0754`**。

### (2) 四大文件物理分配方式的严谨物理权衡

```
┌────────────────────────────────────────────────────────┐
│ 1. 连续分配: [Block 10] -> [Block 11] -> [Block 12]     │
│    - 优点: 极速顺序读写, 支持 O(1) 随机寻址            │
│    - 缺点: 严重外存外部碎片, 动态追加极其困难          │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ 2. 隐式链接分配: [Block 10|Next=25] -> [Block 25|Next=8]│
│    - 优点: 无外部碎片, 动态扩容极简                    │
│    - 缺点: 致命的 O(n) 随机访问, 磁头疯狂寻道; 容错极差 │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ 3. 显式链接分配 (FAT): 内存 FAT 表记录 Next 指针链条    │
│    - 优点: 消除磁盘寻道, 遍历转移发生在高速 RAM 中     │
│    - 缺点: 内存中依然是 O(n) 沿链解引用; 占用巨量内存  │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ 4. 混合多级索引 (UNIX inode): 直接块 + 1/2/3级间接块    │
│    - 优点: 小文件零额外 I/O, 超大文件平滑扩展至数 TB   │
│    - 缺点: 超大文件深层访问需要多级索引磁盘 I/O        │
└────────────────────────────────────────────────────────┘
```

#### 四大物理结构横向性能决策表

| 物理分配方式 | 盘块排布特征 | 顺序访问性能 | 随机存取能力 | 碎片与动态扩展性 |
| :--- | :--- | :--- | :--- | :--- |
| **连续分配** | 文件占用一组物理连续盘块 | **最高**（磁头几乎不移动，极速连续读） | **极好**（$O(1)$，$\text{Block}_k = \text{Start} + k$） | **严重外部碎片**；文件尾部写满后无法动态扩展，需全盘紧凑 |
| **隐式链接分配** | 盘块末尾存放下一块物理地址 | 较差（频繁长距离寻道） | **灾难级极差**（$O(k)$，访问第 $k$ 块必须逐一从磁盘读出前 $k-1$ 块，经历 $k$ 次机械寻道） | **无外部碎片**，动态扩展极佳；但一个盘块坏死全文件链断裂 |
| **显式链接分配**<br>(FAT 体系) | 链接指针集中存放在常驻内存的 FAT 表中 | 良好 | **良好**（常驻内存无磁盘 I/O，但**在内存中依然是 $O(k)$ 链表指针解引用**，并非数学加法） | 无外部碎片；FAT 表随磁盘容量线性暴增，消耗宝贵物理内存 |
| **索引分配**<br>(含混合索引) | 设立独立索引块登记物理块号 | 良好 | **极好**（$O(1)$，通过数组下标直接计算索引槽位） | 无外部碎片；小文件有索引块内部碎片，混合多级索引优雅化解 |

### (3) UNIX 混合多级索引（inode）架构与大题推演

#### 为什么需要混合多级索引？
现代文件系统中，**80% 以上的文件都是小于几 KB 的小文件**（如脚本、图标、文本），只有少数文件达到 GB/TB 级别（如数据库镜像、视频）。
- 若采用纯二级或三级索引：即使只存 10 字节数据，也必须先开辟 2~3 个索引块，小文件需要先进行 2~3 次磁盘寻道才能读到数据，效率极低且浪费外存。
- **UNIX inode 混合解法**：在每个文件的 inode 结构体内部，配置一个固定长度的地址指针数组（通常为 12~15 项）：
  - **直接地址项（Direct Pointers）**：直接登记数据盘块号（面向小文件，**0 次间接索引 I/O**）；
  - **一级间址项（Single Indirect）**：指向一个一级索引块，内部全部装载数据盘块号；
  - **二级间址项（Double Indirect）**：指向一个二级索引块，其下挂载多个一级索引块；
  - **三级间址项（Triple Indirect）**：指向一个三级索引块，支持超大型文件。

```
inode 内部地址指针结构:
  ├── i_block[0..11] (12 个直接项) ────────► [物理数据块 0] ... [物理数据块 11]
  ├── i_block[12] (1 个一级间接项) ────────► [一级索引块] ──► [数据块 12] ... [数据块 1035]
  ├── i_block[13] (1 个二级间接项) ────────► [二级索引块]
  │                                            ├──► [一级索引块 0] ──► [数据块 1036] ...
  │                                            └──► [一级索引块 1023] ──► ...
  └── i_block[14] (1 个三级间接项) ────────► [三级索引块] ──► [二级] ──► [一级] ──► 数据块
```

#### 手算大题推演 1：最大文件物理存储容量精算
设某文件系统磁盘物理块大小为 **$4\text{ KB} = 2^{12}\text{ B}$**，每个盘块地址指针占用 **$4\text{ B}$**。
inode 包含 **12 个直接块项、1 个一级间接项、1 个二级间接项、1 个三级间接项**。

1. **单个索引块能容纳的指针总数**：
   $$N = \frac{\text{磁盘块大小}}{\text{指针大小}} = \frac{4\text{ KB}}{4\text{ B}} = 1024 = 2^{10} \text{ 个指针}$$
2. **各级寻址容量精算**：
   - **直接寻址区（12 项）**：$12 \times 4\text{ KB} = \mathbf{48\text{ KB}}$；
   - **一级间接寻址区（1 项）**：$1 \times 1024 \times 4\text{ KB} = 4096\text{ KB} = \mathbf{4\text{ MB}}$；
   - **二级间接寻址区（1 项）**：$1 \times 1024^2 \times 4\text{ KB} = 1024 \times 4\text{ MB} = \mathbf{4\text{ GB}}$；
   - **三级间接寻址区（1 项）**：$1 \times 1024^3 \times 4\text{ KB} = 1024 \times 4\text{ GB} = \mathbf{4\text{ TB}}$。
3. **单个文件最大理论存储容量**：
   $$\text{Max Size} = 48\text{ KB} + 4\text{ MB} + 4\text{ GB} + 4\text{ TB} \approx \mathbf{4.004\text{ TB}}$$

### (4) 手算大题推演 2：给定字节偏移量定位盘块与磁盘 I/O 次数精算

#### 逻辑块号区间判定表（基于 $D = 12, N = 1024, \text{BlockSize} = 4096\text{ B}$）

| 寻址层级 | 逻辑块号覆盖区间 ($B$) | 覆盖块数 | 寻址所需磁盘 I/O 次数 (inode 已在内存，索引块未缓存) |
| :--- | :---: | :---: | :--- |
| **直接块** | $0 \sim 11$ | 12 | **1 次**（直接读物理数据块） |
| **一级间址** | $12 \sim 1035$ | $1024$ | **2 次**（读一级索引块 1 次 + 读物理数据块 1 次） |
| **二级间址** | $1036 \sim 1,049,611$ | $1024^2$ | **3 次**（读二级索引块 1 次 + 读一级索引块 1 次 + 读数据块 1 次） |
| **三级间址** | $1,049,612 \sim 1,074,791,435$ | $1024^3$ | **4 次**（读三级索引 1 次 + 读二级 1 次 + 读一级 1 次 + 读数据 1 次） |

#### 算例追踪：访问文件字节偏移量 `Offset = 5,000,000`

设某进程调用 `read()` 请求读取文件第 `5,000,000` 字节（字节偏移量为 5000000），假设文件的 inode 已读入内存，各级索引块尚未缓存至内存。

##### 步骤 1：将字节偏移量转换为逻辑块号与块内偏移
- 逻辑块号 $B$：
  $$B = \lfloor \frac{\text{Offset}}{\text{BlockSize}} \rfloor = \lfloor \frac{5,000,000}{4096} \rfloor = \mathbf{1220}$$
- 块内偏移量 $d$：
  $$d = \text{Offset} \bmod \text{BlockSize} = 5,000,000 \bmod 4096 = \mathbf{2944}$$

##### 步骤 2：区间判别
- 检查逻辑块号 $B = 1220$ 所属区间：
  - $B \ge 12$（不是直接块）；
  - $B \ge 1036$（不是一级间址）；
  - $1036 \le 1220 \le 1,049,611 \implies$ **属于二级间址寻址区间**！

##### 步骤 3：计算二级索引中的双层槽位下标
- 计算相对于二级间址起始块的相对块号 $B'$：
  $$B' = B - 1036 = 1220 - 1036 = \mathbf{184}$$
- 计算在该二级索引块内的**一级索引块槽位下标 $i_1$**：
  $$i_1 = \lfloor \frac{B'}{N} \rfloor = \lfloor \frac{184}{1024} \rfloor = \mathbf{0}$$
- 计算在对应一级索引块内的**数据盘块槽位下标 $i_2$**：
  $$i_2 = B' \bmod N = 184 \bmod 1024 = \mathbf{184}$$

##### 步骤 4：硬件访问轨迹与磁盘 I/O 次数清算
1. **第 1 次磁盘 I/O**：根据 inode 中 `i_block[13]` 保存的物理块号，从磁盘读出**二级索引块**；
2. **第 2 次磁盘 I/O**：从该二级索引块的槽位 `0` 中取得对应一级索引块的物理块号，从磁盘读出**一级索引块**；
3. **第 3 次磁盘 I/O**：从该一级索引块的槽位 `184` 中取得实际数据物理盘块号，从磁盘读出**目标数据物理块**；
4. **数据提取**：在内存中从该数据块的第 `2944` 字节处提取目标数据。
- **总磁盘 I/O 次数结算**：**3 次磁盘访问**！

## 3. 本学科内跨章节关联与跨学科协同关联

### 1. 本学科内跨章节关联

  - **共同机制**：文件名到物理实体的映射。
  - **关键差异**：目录项仅负责“文件名 $\to$ inode 编号”的瘦身绑定；inode 负责管理该文件的全部物理磁盘块分配链条。

### 2. 跨学科协同关联（计算机组成原理）
- **关联 [磁盘存储器结构与寻道调度](../../02-co/06-bus-and-io/02-io-interfaces.md)**：
  - **共同机制**：机械硬盘柱面寻道延迟的物理消弭。

## 4. 闭环决策模型与核心认知结论

### (1) 逻辑块号到寻址层级与 I/O 次数决策树

```
计算出目标逻辑块号 B:
  ├─ B < 12 ──► 【直接块寻址】 ──► 访盘 1 次 (读数据块)
  ├─ 12 <= B < 1036 ──► 【一级间接寻址】 ──► 访盘 2 次 (读一级索引块 + 读数据块)
  ├─ 1036 <= B < 1049612 ──► 【二级间接寻址】 ──► 访盘 3 次 (读二级索引 + 读一级索引 + 读数据块)
  └─ B >= 1049612 ──► 【三级间接寻址】 ──► 访盘 4 次 (逐级读 3 次索引块 + 读数据块)
```

### (2) 考场定性铁律
1. **FAT 随机访问真相**：FAT 表支持随机存取的原因是 **FAT 表常驻内存，寻链过程不发生磁盘 I/O**；但在物理内存中依然是沿着数组链表顺序跳转 $O(k)$，绝非 $O(1)$ 算术直接算出。
2. **小文件性能特权**：混合多级索引的直接地址项确保了海量小文件在 inode 在内存的前提下，**仅需 1 次磁盘 I/O 即可直达数据**。
3. **定位两级间址槽位下标公式**：先减去低级覆盖基准 $B' = B - \text{Base}$，再用整除 $\lfloor B' / N \rfloor$ 得高维槽位、用取模 $B' \bmod N$ 得低维槽位。
