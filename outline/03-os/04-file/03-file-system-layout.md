## 1. 考纲考点与核心认知

- **考纲考察要点**：
  - 文件系统在外存介质上的物理分区布局：引导块、超级块（Superblock）及其冗余备份、inode 位示图、盘块位示图、inode 表与数据区；
  - 外存空闲空间管理四大机制：空闲表法、空闲链表法、位示图法（Bitmap 转换公式推导）、成组链接法（UNIX 栈式分组的分配与回收完整微操作）；
  - 内存中的三级文件数据结构体系：进程级文件描述符表（fd table）、系统级打开文件表（`struct file`，维护独立 `f_pos` 偏移量与标志）、内存索引节点表（`struct inode`）；
  - 独立 `open()`、`dup()` 与 `fork()` 在三级打开表中的精确拓扑映射与共享/隔离语义；
  - 虚拟文件系统（VFS）的面向对象抽象与多态四大核心对象。

## 2. 核心机理与五步推演

### (1) 文件系统的外存物理切分格局

当一个物理磁盘分区被格式化为特定文件系统（如 Linux Ext2/Ext4）时，盘块被严格划分为规整的功能区间：

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬────────────────────────┐
│  引导块  │  超级块  │ 块位示图 │inode位示图│ inode表  │        数据盘块区      │
│(Boot Blk)│(Superblk)│(Blk Bmp) │(Inode Bmp│(Inode[]) │       (Data Blocks)    │
└──────────┴──────────┴──────────┴──────────┴──────────┴────────────────────────┘
```

1. **引导块（Boot Block）**：占用分区的最前段（通常为第 0 块或 1KB），负责存放引导装载程序（Bootloader）以加载操作系统内核。每个独立分区均固定保留，即使非启动分区也会留空占位。
2. **超级块（Superblock）**：**文件系统的全局元数据总枢纽**。记录分区的物理全局参数：盘块大小、总盘块数、空闲块数、总 inode 数、空闲 inode 数、挂载标志与时间戳。
   - **备份与容灾机制**：超级块是文件系统能否正常挂载的命脉。现代文件系统（如 ext2/3/4）绝不把超级块单点放在分区头部，而是在多个块组（如 Block Group 0、1、3、5、7）中保留**超级块的完整冗余备份（Backup Superblock）**。主超级块损坏时，管理员可通过 `fsck -b <块号>` 利用备份副本无损修复。
3. **位示图区（Bitmap）**：包含“盘块位图”和“inode 位图”，以极小的比特流开销追踪全盘所有物理块和 inode 结构的使用/空闲状态。
4. **inode 表（Inode Table）**：集中、连续存放全部分区文件的 inode 结构体数组。
5. **数据盘块区（Data Blocks）**：存放文件实际字节内容及目录文件的目录项。

### (2) 空闲空间管理：位示图与成组链接法

#### ① 位示图法（Bitmap）
- **机理**：用一个二进制位（1 bit）的 `0` 或 `1` 映射一个物理盘块的使用状态（如 `0` 表示空闲，`1` 表示已分配）。
- **坐标换算公式（字长 $W$ 位，行号 $i$、列号 $j$、块号 $b$ 均从 0 开始）**：
  $$\text{物理块号 } b = i \times W + j$$
  $$\text{字号（行号） } i = \lfloor b / W \rfloor, \quad \text{位号（列号） } j = b \pmod{W}$$
  *(若题目约定行号、列号或块号从 1 开始，需先将输入减 1 代入公式计算，输出再加 1 修正)*。

#### ② 成组链接法（Grouped Linked List —— UNIX 经典大容量管理）
单个磁盘块容量有限（如 1KB 只能放 256 个块号），无法用单链表高效管理数亿个空闲块。UNIX 采用**栈式分组链接**机制：

```
超级块 (内存常驻栈)
┌─────────────────────────────────┐
│ 空闲块数: N (如 100)            │
│ 空闲块号栈: [ 块100, 块99, ... 块2, 块1 ] ──► 块 1 是管理下一组的索引块
└─────────────────────────────────┘
                                      │
                                      ▼ 展开下一组
                               ┌─────────────────────────────────┐
                               │ 块 1 (磁盘物理块)               │
                               │ 空闲块数: 100                   │
                               │ 空闲块号栈: [ 块200, ... 块102, 块101 ] ──► 块 101 指向下一组
                               └─────────────────────────────────┘
```

**完整分配与回收微操作轨迹**：
1. **常规分配（栈顶还有普通块）**：
   - 检查超级块栈顶计数 $N$；若 $N > 1$，直接弹出栈顶块号分配给用户，$N \leftarrow N - 1$。
2. **跨组分配（分配到本组最后一块管理块，即 $N == 1$）**：
   - 当前栈中仅剩下“下一组的索引块”（如上图的块 1）；
   - **关键操作**：内核先将块 1 内部存储的下一组管理信息（包含下一组的块数及 100 个块号）**完整拷贝覆盖到超级块内存栈中**；
   - 随后才将物理盘块 1 本身分配给请求者（此时超级块中已无缝切换为下一组的空闲块栈，状态连贯）。
3. **常规回收（栈未满，即 $N < 100$）**：
   - 将用户归还的盘块号压入超级块栈顶，计数器 $N \leftarrow N + 1$。
4. **跨组回收（栈已满，即 $N == 100$）**：
   - 用户归还新块 $X$ 时，超级块栈已满（100 个块号）；
   - **关键操作**：内核将超级块内存栈中当前的全部 100 个块号与计数值，**整体写入刚归还的盘块 $X$ 之中**并刷入磁盘；
   - 随后将超级块栈重置：计数值 $N \leftarrow 1$，栈底唯一记录的新块号即为 $X$（新块 $X$ 正式成为衔接上一组的新管理索引块）。

### (3) 内存三级打开文件表拓扑结构（独立 `open` vs `dup` vs `fork`）

操作系统必须维护三层文件管理结构以支撑并发安全访问：
1. **进程打开文件表（fd table）**：位于各进程 PCB 内部（Linux 中的 `files_struct`）。表项索引为非负整数 `fd`，内容为指向系统打开文件表的指针。
2. **系统打开文件表（System-wide Open File Table）**：驻留于内核空间，表项为 `struct file`。核心属性包含：**当前文件读写偏移指针 `f_pos`**、文件打开访问标志 `f_flags`、该表项的引用计数 `f_count`，以及指向内存 inode 的指针。
3. **内存索引节点表（In-memory inode table）**：驻留于内核空间，表项为 `struct inode`。代表唯一的磁盘物理文件实体，维护磁盘元数据缓存、文件长度与物理块索引。

#### 三大经典并发访问场景拓扑图解

```
【场景 1: 两独立进程 (或同一进程两次) 独立调用 open()】
进程 A (fd=3) ──► [系统表项 file 1: f_pos=0] ──────┐
                                                   ├──► 【内存 inode 实体】(共享底层数据)
进程 B (fd=4) ──► [系统表项 file 2: f_pos=100] ────┘
  特点: 拥有两套独立的 f_pos 指针！进程 A 读写完全不改变进程 B 的当前读取位置。

─────────────────────────────────────────────────────────────────────────────

【场景 2: 单个进程内部执行 fd2 = dup(fd1)】
进程 A:
  fd = 3 ──┐
           ├──► [系统表项 file 1: f_pos=50, f_count=2] ──► 【内存 inode 实体】
  fd = 4 ──┘
  特点: 同一进程的两个 fd 指向同一个系统表项，共享同一个 f_pos！fd=3 读了 10 字节，
        fd=4 紧接着读取将从第 11 字节开始。

─────────────────────────────────────────────────────────────────────────────

【场景 3: 父进程打开文件后调用 fork() 创建子进程】
父进程 A (fd=3) ──┐
                  ├──► [系统表项 file 1: f_pos=0, f_count=2] ──► 【内存 inode 实体】
子进程 B (fd=3) ──┘
  特点: 子进程完全继承父进程的 fd 数组，指向相同的系统表项，共享同一个 f_pos 游标！
```

#### 并发写入的数据覆盖与乱序风险
- **顺序追加的条件**：在父子进程共享同一个系统 `file` 表项时，若两者进行的是带内核互斥保证的顺序写，或者设置了 `O_APPEND` 标志（每次写前内核自动原子将 `f_pos` 移动到文件末尾），写入的数据不会发生空间覆盖。
- **乱序与覆盖边界**：若未设置 `O_APPEND` 且应用程序自身未进行并发同步（如互斥锁），父子进程并发执行 `write()` 时可能发生执行流交错（Interleaving）；若某一方调用了 `lseek()` 改变了共享的 `f_pos`，另一方的写入位置将直接受到不可预测的偏移篡改；若使用 `pwrite()`，由于其直接指定物理偏移而不依赖 `f_pos`，则完全打破游标共享机制。

### (4) 虚拟文件系统（VFS）：多态面向对象抽象

VFS 屏蔽了不同文件系统（Ext4, FAT32, NTFS, NFS）在扇区组织、寻址协议上的物理差异，为上层统一提供 POSIX 标准 API（`open/read/write/close`）。

```
                ┌──────────────────────────────────────────────┐
                │        用户态应用程序 (read / write)          │
                └──────────────────────┬───────────────────────┘
                                       │ POSIX 系统调用接口
                ┌──────────────────────▼───────────────────────┐
                │          虚拟文件系统 (VFS 抽象层)           │
                │   Superblock  |  Inode  |  Dentry  |  File   │
                └──────┬───────────────┬───────────────┬───────┘
                       │               │               │
         ┌─────────────▼────┐    ┌─────▼──────┐   ┌────▼────────┐
         │ Ext4 具体文件系统│    │ FAT32 驱动 │   │ NFS 网络驱动│
         └──────────────────┘    └────────────┘   └─────────────┘
```

#### VFS 四大核心对象及其职能

| VFS 对象 | 对应物理/逻辑实体 | 核心维护属性 | 包含的函数操作表指针 |
| :--- | :--- | :--- | :--- |
| **超级块对象**<br>(Superblock) | 某个具体已挂载的分区 | 盘块大小、文件系统类型、脏标志 | `s_op`（如 `alloc_inode`, `write_super`, `sync_fs`） |
| **索引节点对象**<br>(Inode) | 某个具体物理文件实体 | 文件尺寸、权限、创建时间、物理块映射 | `i_op`（如 `create`, `lookup`, `mkdir`, `unlink`） |
| **目录项对象**<br>(Dentry) | 路径中的某一级分量（如 `/home`） | 目录项名称、父目录指针、子目录链表 | `d_op`（如 `d_compare`, `d_delete`, `d_release`） |
| **文件对象**<br>(File) | 进程打开文件的**动态交互会话** | **读写偏移量 `f_pos`**、打开标志 `f_flags` | `f_op`（如 `read`, `write`, `mmap`, `flush`） |

### (5) 典型反例证伪（常见认知陷阱）

1. **反例 1：“两个独立进程同时打开同一个文件时，由于文件名和 inode 相同，它们在内核中共享同一个系统打开文件表项和读写偏移量。”**
   - **反例证伪**：错误。独立调用 `open()` 会在系统打开文件表中分别创建两个独立的 `struct file` 结构体，各自拥有完全独立的 `f_pos` 指针。只有经过 `fork()` 继承或 `dup()` 复制时，才会共享同一个系统打开文件表项。
2. **反例 2：“超级块一旦损坏，整个分区数据必定永久灭失，操作系统无法恢复。”**
   - **反例证伪**：错误。现代文件系统（如 ext2/3/4）在设计时即在多个块组（Block Groups）预先留存了超级块的多份备份。通过修复工具指定备份超级块块号（如 `fsck -b 32768`），可直接用备份覆盖修复主超级块。
3. **反例 3：“成组链接法在分配最后一块管理块时，可以直接将该块交由用户使用，然后再去磁盘读取下一组。”**
   - **反例证伪**：错误。管理块内部保存着全盘下一组 100 个空闲块的唯一索引列表。必须在将该块交由用户之前，将其内部存储的全部块号预先完整读入并覆盖到超级块内存栈中，否则一旦交给用户写入，下一组空闲盘块的索引信息将彻底丢失引发全盘空间泄露。

## 3. 408 考场标准模型 vs 现代工程实现边界

| 维度 | 408 考场标准模型（学理解题口径） | 现代工程实现边界（Linux 内核实现） |
| :--- | :--- | :--- |
| **超级块单点性** | 多数教材简化描述为分区头部唯一的全局超级块 | 普遍采用**稀疏超级块（Sparse Superblock）**冗余机制，在第 0、1、3、5、7 块组分布式备份 |
| **文件描述符拓扑** | 进程表直接包含三元组或指针指向系统打开表 | Linux 内部通过 `task_struct -> files_struct -> fdtable -> fd[]` 逐级解引用到 `struct file` |
| **空闲盘块管理** | 成组链接法作为 UNIX 经典机制在大题中作为代表考查 | 现代主流文件系统（如 Ext4、XFS）不再使用传统 UNIX 成组链接法，而普遍采用**区段分配（Extent）结合多级树索引（B+ 树）**或块组位示图配合延迟分配（Delayed Allocation） |
| **VFS 缓存体系** | 侧重四大对象的静态类图与指针引用 | 工程核心是 **dcache（目录项缓存）与 page cache（页高速缓存）**，路径查找优先全走内存基数树（Radix Tree） |

## 4. 跨章节与跨学科关联

### 1. 本学科内跨章节关联
- $\to$ 关联 [目录结构与文件共享](02-directory-and-links.md)：
  - **共同机制**：硬链接与软链接的底层寻址均最终落地于 VFS inode 对象和物理 inode 表。
  - **关键差异**：目录项属于外存静态树结构；打开文件表（`file`）属于进程运行时的内存动态状态。
  - **不可直接迁移的判据**：关闭文件描述符（close）会递减系统打开文件表项引用计数 f_count（当所有打开文件对象与映射释放后，教学模型活动引用数 active_refs 归零），但不会删除磁盘目录项或改变磁盘硬链接计数 i_nlink。
- $\to$ 关联 [进程状态与控制](../02-process/01-process-states.md)：
  - **共同机制**：`fork()` 系统调用不仅复制进程上下文，还完整复制 PCB 中的文件描述符数组。
  - **关键差异**：地址空间（内存页表）在 `fork` 后采用写时复制（COW）分离；而打开文件表项（`file`）在 `fork` 后是**严格物理共享**。
  - **不可直接迁移的判据**：父进程修改私有局部变量不影响子进程，但父进程执行 `read()` 推进 `f_pos` 会直接导致子进程读取偏移量同步后移。

### 2. 跨学科协同关联
- $\to$ 关联 [计算机组成原理 / 磁盘存储介质](../../02-co/06-bus-and-io/02-io-interfaces.md)：
  - **共同机制**：文件系统逻辑块号最终必须经驱动层转换为磁盘物理 LBA 扇区地址。
  - **关键差异**：操作系统处理的逻辑块大小通常为 4KB；物理硬盘基础扇区多为 512B 或高级格式化 4KB。
  - **不可直接迁移的判据**：位示图公式计算出的“物理块号”是文件系统级别的逻辑块号，不可直接将其当成硬件磁头/柱面/扇区三元组。

## 5. 核心考点自查清单与闭环判据

1. **三级打开表共享判决口诀**：
   - 独立 `open()`：**分立 file，分立 f_pos，共享底层 inode**；
   - `dup()` 与 `fork()`：**共享 file，共享 f_pos，共享底层 inode**。
2. **位示图换算坐标基准**：
   - 严格核实字号、位号从 0 还是从 1 开始；
   - 32 位系统下：$b = i \times 32 + j$。
3. **成组链接法换组临界点**：
   - 分配到最后一块（$N=1$）必须**先将下组信息读入超级块栈，再交出物理块**；
   - 回收到满栈（$N=100$）必须**先将当前栈刷入新块，再重置超级块栈底**。
