## 2. 底层机理与物理必然性（为什么这么设计？）

### (1) 为什么必须硬性划分“用户态”与“内核态”？
* **物理矛盾**：物理硬件只有一套，但上面运行着几十个互不信任、甚至可能存在 Bug 或恶意攻击的应用程序。如果允许应用程序自由执行任何硬件指令，任何一行野指针写操作或者无休止的死循环就会瞬间摧毁整台机器。
* **硬件实现**：CPU 在程序状态字（PSW）中设立特权标志位：
  * **内核态（Ring 0 / 管态）**：运行 OS 内核代码，允许执行**所有特权指令**（改页表基址、开关中断、清空 Cache、直接操作物理 I/O 设备）。
  * **用户态（Ring 3 / 目态）**：运行普通用户程序，**只能执行非特权指令**。若在用户态企图执行特权指令，CPU 硬件流水线立刻截获并抛出非法指令异常。

### (2) 从用户态到内核态的仅有三扇大门
无论多复杂的系统，应用程序进入内核态只有且仅有以下三条路径：

```
                    ┌────────────────────────────┐
                    │      应用程序（用户态）     │
                    └──────────────┬─────────────┘
                                   │
      ┌────────────────────────────┼────────────────────────────┐
      ▼ 门1：主动打报告             ▼ 门2：执行出意外/缺硬件       ▼ 门3：外界强行打断
┌──────────────┐             ┌──────────────┐             ┌──────────────┐
│ 【系统调用】 │             │ 【硬件异常】 │             │ 【外部中断】 │
│ (Trap/访管)  │             │ (Fault/Abort)│             │ (Interrupt)  │
│ - fork()     │             │ - 除零、段错误│             │ - 时钟中断   │
│ - read/write │             │ - 缺页异常    │             │ - 磁盘读写完 │
└──────────────┘             └──────────────┘             └──────────────┘
```

### (3) 系统调用（模式切换） vs 进程切换（程序切换）的物理开销
这是 408 最核心的一对辨析：
* **模式切换（Mode Switch）**：
  * **实质**：同一个进程换特权级衣服，**不换人**！
  * **动作**：改 PSW 标志位、栈指针切到内核栈、压入断点。
  * **关键**：**CR3 页表寄存器不换，虚拟地址空间不变，TLB 和 Cache 不失效**，开销极小。
* **进程切换（Process Switch）**：
  * **实质**：操作系统剥夺当前进程 A，把 CPU 给进程 B，**彻底换人**！
  * **动作**：保存进程 A 的现场到 PCB_A，加载进程 B 的 PCB_B。
  * **致命开销**：**必须切换 CR3 页表基址寄存器**，直接导致 CPU 的快表（TLB）大面积失效，Cache 命中率暴跌，消耗数百到数千个时钟周期。

## 3. 横向跨学科与相近机制谱系

> 观察“特权隔离与状态切换”在不同软硬件层次的同构映射：

| 层次体系 | 运行实体 | 特权/保护机制 | 跨界切换的机制与代价 |
| :--- | :--- | :--- | :--- |
| **现代 CPU 体系** | 内核 vs 用户应用 | 硬件 Ring 0 ~ Ring 3 环 | `syscall` / `sysret`，换内核栈，保存断点 |
| **虚拟化系统** | VMM vs Guest OS | 根模式（Root） vs 非根模式（Non-root） | VM-Exit 与 VM-Entry，开销远大于普通模式切换 |
| **微内核架构** | 内核 vs 用户态服务进程 | 传统大内核内部调用 $\to$ IPC 消息传递 | 模块解耦带来安全，但大量模式切换导致通信性能暴跌 |

## 4. 408 核心命题陷阱与双胞胎真题对撞

### 对撞组一：广义进内核（2013-28） vs 狭义系统调用（2021-32）

| 题目年份 | 题干核心设问 | 选项考查对象 | 关键分水岭 |
| :--- | :--- | :--- | :--- |
| **2013-28** | 下列操作中，**导致从用户态转入内核态**的是？ | I. 整数除以零<br>II. `sin()` 函数调用<br>III. `read()` 系统调用 | **广义进内核**：无论主动（系统调用 `read`）还是被动出错（异常除零），只要越界进内核就算（选 I、III）。 |
| **2021-32** | 下列选项中，**通过系统调用完成**的是？ | A. 页置换<br>B. 进程调度<br>C. 创建新进程<br>D. 生成随机整数 | **狭义系统调用**：光进内核不行（页置换进内核了），必须是**应用主动显式发起的需求**才算（仅 C 是）。 |

### 对撞组二：硬件隐指令 vs 操作系统软件分工（2020-18 vs 2022-31）

* **硬件必须做（硬件隐指令，软件插不上手）**：
  1. 关中断；
  2. 保护断点（PC 和 PSW 压入内核栈）；
  3. 修改 CPU 特权级为内核态；
  4. 查中断向量表并把 PC 跳到服务入口。
* **操作系统软件做**：
  1. 保存通用寄存器；
  2. 执行具体的服务例程代码；
  3. 恢复现场并执行中断返回指令。

## 5. 真题反哺与经验投喂区（持续演进）

- **2021-32 投喂**：明确了“操作系统内部治理机制（页置换、调度）”与“用户接口（系统调用）”的边界。页置换是缺页异常触发后的内核内存治理，绝非系统调用。
- **2022-31 投喂**：死锁了硬件隐指令（保存断点 PC/PSW、切内核态）与软件服务例程的职责分界线。
- **2023-23 投喂**：微内核虽然具备极高的可靠性、扩展性与安全性，但其致命缺陷是进程间通信频繁跨越内核边界，性能较差。
- **2024-23 投喂**：中断和异常可以在用户态发生，但绝不可能在用户态处理，必定在核心态处理。发生时刻与处理时刻不可混为一谈。
- **2025-24 投喂**：VMM 与客户机操作系统绝不可能处于同一特权级，VMM 必须处于更高特权级以实现资源压制与隔离。
