## 大题1｜2021-42 · 比较计数排序与稳定性

原题定位：[src/0918.md](../../src/0918.md)，以年份题号2021-42定位。

<img src="../../bank/2021/q42.png" alt="2021-42" style="display: block; width: 46.56em; max-width: 100%; height: auto; margin: 12px 0;">

<details>
<summary>没有入口时的第一步</summary>

count记录每个元素最终位置。先分析相等时执行哪个分支，再决定两个25的相对次序是否改变。

</details>

<details>
<summary>完整解法与必要补学</summary>

（1）b最终为`[-10, 10, 11, 19, 25, 25]`。为检查稳定性，把原先两个25记为25a、25b，实际顺序为`[-10,10,11,19,25b,25a]`。

（2）内层分别执行n−1、n−2、…、1次，元素比较总数n(n−1)/2；本题n=6时为15次。时间O(n²)，辅助数组count占O(n)。

（3）原算法不稳定。当i<j且a[i]==a[j]，会进入else令count[i]++，使较早出现的相等元素排在后面。只需把比较改为：

```c
if (a[i] <= a[j]) ++count[j];
else ++count[i];
```

使相等时较晚元素的排名加1，即可保留原先次序；不同元素的大小关系不变。不能因为最后两个整数都显示25，就认为稳定性无从讨论。

</details>

<details>
<summary>重做后检查</summary>

用[2a,2b,1]手算：原算法输出[1,2b,2a]，改后输出[1,2a,2b]。两者数值均有序，但只有后者稳定。

</details>

## 大题2｜2022-42 · 在大量元素中保留最小10个

原题定位：[src/0914.md](../../src/0914.md)，以年份题号2022-42定位。

<img src="../../bank/2022/q42.png" alt="2022-42" style="display: block; width: 47.84em; max-width: 100%; height: auto; margin: 12px 0;">

<details>
<summary>没有入口时的第一步</summary>

只要最小10个，不必把十万多个数全部排序。维护候选集合时，让最容易被踢出的最大候选在根。

</details>

<details>
<summary>完整解法与必要补学</summary>

（1）取前10个数建立大根堆，堆中始终保存已经扫描部分的最小10个。逐个读后续元素x：若x不小于堆顶，丢弃；若x小于堆顶，则用x替换堆顶并向下调整。扫描完后堆内即是最小10个，不要求它们内部已经排好序，原题也明确不要求程序代码。

（2）一般保留k个时，建堆O(k)，其余每个数先和堆顶比较，只有入选时才花O(log k)调整；总时间上界O(n log k)。本题k=10固定，时间为O(n)，额外堆空间O(10)=O(1)；也可在原数组前10项建堆。随机输入时，扫描越往后，新元素入选最小10个的机会越小，因此大多数元素只需一次堆顶比较。不能为拿最小10个直接付出全排序的O(n log n)代价。

</details>

<details>
<summary>重做后检查</summary>

若改建小根堆，只能迅速拿到当前最小者，却不能在新候选到来时迅速淘汰集合内最大者；用候选[1,2,3]与新值0试一下就能看清。

</details>

## 大题1｜2015-41 · 按绝对值保留首次结点

原题定位：[src/0914.md 第03题](../src/0914.md)。以年份题号为准，避免原计划题名错位。

<img src="../bank/2015/q41.png" alt="2015-41" style="display: block; width: 45.17em; max-width: 100%; height: auto; margin: 12px 0;">

<details>
<summary>没有入口时的第一步</summary>

|data|≤n把无限查重变成0…n的直接标记。删除时前驱不能同步前移。

</details>

<details>
<summary>完整解法与必要补学</summary>

**思想及数据类型。** 设seen[0…n]初值全0。一次扫描链表；未见过的绝对值做标记并保留，见过则摘除释放。带头结点，用前驱pre维护删除位置。

```c
typedef struct Node {
    int data;
    struct Node *link;
} Node;
void unique_abs(Node *head, int n) {
    unsigned char *seen = calloc(n + 1, sizeof(*seen));
    if (!seen) return; // 实际程序需处理分配失败
    Node *pre = head, *p = head->link;
    while (p) {
        int key = p->data < 0 ? -p->data : p->data;
        if (!seen[key]) {
            seen[key] = 1;
            pre = p; p = p->link;
        } else {
            pre->link = p->link;
            free(p);
            p = pre->link;
        }
    }
    free(seen);
}
```

使用stdlib.h。题设data受n范围约束，这里按可表示的普通int范围处理。扫描m个结点O(m)，初始化n+1个标记O(n)，总时间O(m+n)，辅助空间O(n)；不能把初始化开销隐去。原例保留21、−15、−7，后续15都删。

</details>

<details>
<summary>重做后检查</summary>

用1→−1→1跟踪：保留第一个1，后两次都删除；pre必须留在第一个1处，才能处理连续重复。

</details>

## 大题2｜2019-42 · 可扩容且复用空间的队列

原题定位：[src/0914.md 第04题](../src/0914.md)。以年份题号为准，避免原计划题名错位。

<img src="../bank/2019/q42.png" alt="2019-42" style="display: block; width: 48.62em; max-width: 100%; height: auto; margin: 12px 0;">

<details>
<summary>没有入口时的第一步</summary>

题目不是固定容量数组，也不是出队就free。用循环链上的活动段和空闲段，入队时先复用空闲结点。

</details>

<details>
<summary>完整解法与必要补学</summary>

**(1)** 选链式结构；固定顺序数组满后搬移扩容无法保证每次入队O(1)。构造单循环链，使用front、rear两指针及一个保留结点。front指向当前队头之前的结点，rear指最后一个有效元素；沿rear→next到front的结点可用于后续入队。

**(2) 初始状态：** 只分配一个结点s，s→next=s，front=rear=s，逻辑上无元素。队空条件front==rear；现有存储结点已用尽的条件rear→next==front。这里“满”表示需要扩容，不表示拒绝入队。

**(3) 第一个元素x入队：** 原来rear→next==front，在rear之后新建结点p，p→next=front，rear→next=p；rear=p，rear→data=x。环为front→x→front。

**(4) 入队：** 若rear→next==front，则在rear后插入一个新结点；随后rear=rear→next，把新值放到rear。若已有空闲结点则直接使用，无需分配。出队：先判空，否则front=front→next，读出front→data；不释放这个结点，它成为新的保留结点，原保留结点进入可复用空间。

连接、赋值都为常数次，入队与出队均O(1)（按教材把单结点分配视为常数操作）。队列占用结点只增不减；不把“保留结点”误算为一个有效元素。

</details>

<details>
<summary>重做后检查</summary>

模拟入A、入B、出A、出B、再入C：最后一步应复用已有结点，而不是再次分配；每次front==rear都表示逻辑空。

</details>
