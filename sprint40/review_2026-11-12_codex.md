## 一、必须先修：Day21，2024-09，大根堆删除两次

位置：[day21.md](day21.md)，题号 2024-09。证据：[仓内原题图](../bank/2024/q09.png)，审查时已直接查看。

### 已确认问题

原题为八个元素：

```text
[28, 22, 20, 19, 8, 12, 15, 5]
```

现解析却把初始堆写成：

```text
[28, 22, 20, 5, 8, 12, 15]
```

漏掉 19，同时改变了 5 的位置。随后用“若原数组末尾为5或题给具体层序”的括注跳回原题数据，最终给出正确答案 B。正确选项不能挽救这段错误演算；从它写下的初始数组无法推出后面的结果。

### 订正依据

第一次删除：删除 28，把末尾 5 放到根，依次与较大孩子 22、19 交换：

```text
[5, 22, 20, 19, 8, 12, 15]
→ [22, 5, 20, 19, 8, 12, 15]
→ [22, 19, 20, 5, 8, 12, 15]
```

第二次删除：删除 22，把末尾 15 放到根，与较大孩子 20 交换：

```text
[15, 19, 20, 5, 8, 12]
→ [20, 19, 15, 5, 8, 12]
```

最终选 B。上述过程已用独立下滤程序复算。

### 验收要求

从原题八个数开始完整演算，每次删除元素数恰好减一；中间状态中的每个数字都有来源；移除补丁式括注。原理说明可保留，不要重写其他无关题。

## 二、必须先修：Day20，2023-43 / 44，数组列数与地址计算

位置：[day20.md](day20.md)，2023-43 及共享题干的 2023-44。证据：[第43题图](../bank/2023/q43.png)，审查时已直接查看；后续订正还需逐项对照第44题汇编图。

### 已确认问题

仓内第43题图写 `int a[24][24]`，循环却为 `i<24, j<64`。这首先是仓内题面冲突，不能仅凭这一张图断言正式真题原卷本身印刷有误。

页前勘误已声明“按 `int a[24][64]` 讲解”，但正文重新按 24 列计算，写出 2304B、1 页、72 个主存块、行跨度 96B、`a[1][0]=00422060H`、组号 3；第44题又把行偏移写成 `96*i`。同一组题混用了两套前提。

此外，正文声称：保留 24 列声明但循环到 64 列，便相当于连续写入 1536 个不同整数、跨度 6144B。这也不成立。即便仅按常见行优先地址公式机械分析，地址偏移仍为 `(24*i+j)*4`，不同循环访问会重叠，不能把循环次数当作不同元素数量。更根本地，C 数组越界涉及未定义行为，不应给它编造确定的正常执行结果。

### 按现有勘误采用 64 列时的校核值

下表是“采用 64 列解释”的条件性结果，不是对正式原卷版本的独立认证。起始地址为 `00422000H`，页大小 4KB，Cache 为 8KB、4 路、块大小 32B。

| 项目 | 结果与依据 |
|---|---|
| 数组字节数 | 24 × 64 × 4 = 6144B |
| 数组所在页数 | 页对齐起始，占 2 页 |
| 缺页次数及地址 | 按题设初始未驻留、执行期间无页面置换，首次访问两页时共 2 次；00422000H、00423000H |
| 每行跨度 | 64 × 4 = 256B = 100H |
| a[1][0] 地址 | 00422100H |
| 块内偏移位 | A4～A0，共 5 位 |
| Cache 组号位 | A10～A5，共 6 位 |
| a[1][0] 的组号 | (00422100H / 32) mod 64 = 8 |
| 数组占用主存块 | 6144 / 32 = 192 块 |

表内地址与数量已独立复算。核心判据中的符号与代入顺序也应统一：b=5、s=6，因此 s+b=6+5=11≤12，避免与后文的字段划分混淆。

### 不能只凭总容量判断 Cache 冲突

“数组小于 Cache，所以换成按列遍历仍不会置换”不能单独作为充分理由。组相联还受每组路数限制，应写出映射过程。

若采用 64 列，沿列相邻两行相差 256B，即 8 个块；24 行的组号以 8 为步长循环，涉及 8 组、每组 3 个块，没有超过 4 路。结合本题无其他数据访问冲突等前提，才能解释相关块可保留，并核对两种遍历的命中率。应同时交代采用的写缺失处理假设，避免把特定题设下的分析写成普遍定律。

### 验收要求

1. 先核对第44题的汇编行偏移，必要时查可靠原卷，明确列数依据；保留仓内题图，不擅自改图。
2. 若继续采用既有的 64 列勘误，则第43、44题所有大小、页数、地址、组号、行偏移和命中率推导均使用同一前提。
3. 删除把越界循环当作正常连续数组执行的“严谨补充”，不要并列两套互相冲突的确定答案。
4. 不能只改表面数值；按统一前提把相关小问重新复算。

## 三、必须先修：Day38，2020-47，NAT 规则过度泛化

位置：[day38.md](day38.md)，2020-47。

### 已确认问题

正文声称：“任何单级 NAT 网关仅重写 IP 头部的源端或目的端之一……”

这是错误的普遍化。同一设备可以配置源、目的地址转换，不能把本题中两台设备分别执行的操作，当作所有 NAT 网关的限制。

### 订正方向

把规则限定到本题报文方向和给定配置：H2 发出请求，经 R3 做源地址转换，再经 R2 做目的地址转换。现有逐跳地址表可在对照原图后保留；删除“任何网关都只能改一端”之类额外断言。

验收时逐跳核对源、目的地址，明确谁在哪一步改变；不需要为了反驳一句泛化而新增 NAT 专题。

## 四、表达建议：保留教学深度，减少无助于判断的包装

这是表达层面的建议，与上面的事实错误分开处理，不应优先于内容订正。

“物理不变量”“硬约束”“严格”“绝对”“荒谬至极”等词使用过密。它们容易把有条件的结论说满，也会增加零基础读者的阅读负担。“核心判据—推导—干扰项”的结构本身可以保留，不要求把整套资料改成 Codex 的文风。

订正时关注：

- 用具体操作和必要推理解释为什么，而非仅给原理命名。保留“为何推进最小值指针”“为何祖先条件会限制整棵子树”等有实际价值的内容。
- 有条件的知识写出适用前提；对错选项说明错在什么，不用贬斥性语言代替论证。
- 不机械删除所有“物理”“严格”等词，也不以缩短篇幅为目的删掉从题干走向解法的关键步骤。
- 以没有完整复习课本的读者为对象，让读者能跟着复算，并知道下次从哪个条件入手。算法题尤其不能只留下术语和完整代码，中间的设计理由仍需讲清。
