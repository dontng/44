> **核心导读**：本笔记完整收录了从 2011 年至 2025 年 408 统考数据结构开篇第一题（时间复杂度分析）的深度拆解。我们拒绝“就题论题、算完就过”的机械刷题，而是建立一套\*\*“看选项预判代码骨架”、“去噪放宽直觉”、“三行列表法破除嵌套迷糊”**以及**“洞察命题人 15 年进化套路”\*\*的降维打击体系。

## 第一章：2011 真题 —— 选项的“逆向工程”与单层倍增模型

### 【真题重现】01 · 2011-01

**1. 设** $n$ **是描述问题规模的非负整数，下面程序片段的时间复杂度是\_____\_。**

```
x = 2;
while (x < n / 2)
    x = 2 * x;

```

* **A.** $O(\log_2 n)$

* **B.** $O(n)$

* **C.** $O(n\log_2 n)$

* **D.** $O(n^2)$

### 一、 考场先手：对四个选项的“代码盲猜”与预判

在考场上扫一眼这四个经典选项（$O(\log_2 n)$、$O(n)$、$O(n\log_2 n)$、$O(n^2)$），即使先把题干代码挡住，脑子里也应当立刻浮现出四套完全不同的**代码骨架（逆向工程画像）**。这种“看到复杂度就预判代码长相”的直觉，本质上是把**步进方式（加减 vs 乘除）**和**循环嵌套层数**做了直接映射：

1. **A.** $O(\log_2 n)$ **—— “倍增”或“折半”的单层结构**

   * **预判特征**：代码里必然只有**单层循环**（或者单路递归），且循环控制变量的更新绝对不是 `x++`，而是**乘法或除法**（`x = x * 2`、`x *= k`、`n = n / 2` 或位运算 `x <<= 1`）。

   * **直觉画面**：变量像坐火箭一样以指数级逼近边界 $n$，或者问题规模 $n$ 每次被砍掉一半（如二分查找、完全二叉树沿着树高往下走）。

2. **B.** $O(n)$ **—— “一步一脚印”的线性推进**

   * **预判特征**：**单层循环**，步进方式是**常数级的加减法**（如 `x++`、`x += 2`、`n--`）。

   * **特殊变体（高频坑点）**：有时会有两层循环，但外层是倍增（`i *= 2`），内层循环次数刚好等于外层变量当前的值（`for (j = 0; j < i; j++)`）。此时总次数是等比数列求和 $1 + 2 + 4 + \dots + n/2 \approx n$，披着双层循环的皮，实则是 $O(n)$（详见 2022 真题）。

3. **C.** $O(n\log_2 n)$ **—— “线性遍历 + 倍增/折半”的嵌套组合**

   * **预判特征**：代码至少有**两层结构**（双层循环，或一层递归套一层线性扫描）。一层负责“老老实实走完 $n$ 步”（`i++`），另一层负责“翻倍跳”（`j *= 2`）。

   * **特殊变体（调和级数）**：外层 `i` 从 $1$ 到 $n$（`i++`），内层 `j` 每次加 `i`（`j += i`）。总次数为 $n/1 + n/2 + n/3 + \dots + n/n = n \ln n$，同样归入 $O(n\log_2 n)$。

4. **D.** $O(n^2)$ **—— “双层线性推进”的网格扫描**

   * **预判特征**：标准的**双层嵌套循环**，且内外两层的步进全都是**加减法**（`i++` 配 `j++`）。无论是矩形遍历（内层 `j < n`）还是三角形遍历（内层 `j < i`，即等差数列求和 $1+2+\dots+n = \frac{n(n+1)}{2}$），都跑不出这个选项。

#### 考场快速映射表

| 选项 | 核心步进算子预判 | 典型代码框架预判 | 常见伪装/干扰手法 | 
| ----- | ----- | ----- | ----- | 
| **A.** $O(\log_2 n)$ | `*`、`/`、`<<`、`>>` | 单层循环，变量倍增或折半 | 边界条件写成 `n/2`、`n-100`；底数换成 `x = 3*x` | 
| **B.** $O(n)$ | `+`、`-` | 单层线性循环；或等比求和型双层循环 | 步长写成 `x += 100`；或双指针一头一尾向中间逼近 | 
| **C.** $O(n\log_2 n)$ | 一层 `+`/`-` 套一层 `*`/`/` | 双层循环（一线性一对数）；分治递归 | 内层步进写成 `j += i`（调和级数求和） | 
| **D.** $O(n^2)$ | 两层均为 `+`、`-` | 双层嵌套线性循环 | 内层边界与外层挂钩（如 `j < i` 或 `j < 2*i`） | 

### 二、 本题秒杀印证与规范求解过程

#### 1. 秒杀印证

1. **看层数**：只有一个 `while` 循环，没有嵌套——直接砍掉需要双层结构的 **C (**$O(n\log_2 n)$**)** 和 **D (**$O(n^2)$**)**。

2. **看步进**：循环体里写的是 `x = 2 * x;`（乘 2 倍增），而不是 `x = x + 2;`——直接排除线性步进的 **B (**$O(n)$**)**，瞬间锁定 **A (**$O(\log_2 n)$**)**。

#### 2. 规范数学求解步骤

* **第一步：确定基本操作与变量变化规律**

  * **基本操作**：循环体内的赋值语句 `x = 2 * x;`。

  * **设未知数**：设该基本操作的执行次数为 $k$（$k \ge 0$）。

  * **列出变量** $x$ **随** $k$ **的演变过程**：

    * 初始状态（$k = 0$）：$x_0 = 2 = 2^1$

    * 执行第 1 次（$k = 1$）：$x_1 = 2 \times 2 = 2^2$

    * 执行第 2 次（$k = 2$）：$x_2 = 2^2 \times 2 = 2^3$

    * 执行第 3 次（$k = 3$）：$x_3 = 2^3 \times 2 = 2^4$

    * ……

    * 执行第 $k$ 次时：

      $$
      x_k = 2^{k+1}
      $$

* **第二步：建立循环终止的不等式**

  * 循环能够继续执行的充要条件是 $x < \frac{n}{2}$。

  * 因此，当循环刚好终止跳出时，必有：
    

    $$
    x_k \ge \frac{n}{2} \implies 2^{k+1} \ge \frac{n}{2}
    $$

* **第三步：求解执行次数** $k$

  * 两边同时取以 2 为底的对数（$\log_2$）：
    

    $$
    \log_2(2^{k+1}) \ge \log_2\left(\frac{n}{2}\right)
    $$

    $$
    k + 1 \ge \log_2 n - \log_2 2
    $$

    $$
    k + 1 \ge \log_2 n - 1 \implies k \ge \log_2 n - 2
    $$

  * 因此，循环体的实际执行次数 $k = \lceil \log_2 n - 2 \rceil \quad (\text{当 } n > 4 \text{ 时})$。

* **第四步：给出渐进时间复杂度**

  * 常数项 $-2$ 是低阶项，在求极限渐进量级时直接忽略，最高阶项为 $\log_2 n$。故 $T(n) = O(\log_2 n)$，**选 A**。

#### 3. 命题人陷阱辨析

循环条件里的 `n / 2` 是极其经典的视觉障眼法。对数运算具有独特性质：在真数中进行常数倍的缩放（如 $\frac{n}{2}$、$\frac{n}{10}$、甚至 $\frac{n}{100}$），通过对数法则展开后，只相当于对总次数**减去一个常数**（$\log_2 \frac{n}{2} = \log_2 n - 1$）。除以 2 只是让循环少跑了最后 1 次，根本动摇不了 $\log_2 n$ 的量级。

## 第二章：2012 真题 —— 递归视角下的骨架预判与变式推演

### 【真题重现】02 · 2012-01

**1. 求整数** $n$ **(**$n \ge 0$**) 阶乘的算法如下，其时间复杂度是\_____\_。**

```
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}

```

* **A.** $O(\log_2 n)$

* **B.** $O(n)$

* **C.** $O(n\log_2 n)$

* **D.** $O(n^2)$

### 一、 递归视角下的选项“骨架预判”

从 2011 年的“单层倍增循环”跨入 2012 年，形式从**循环迭代**跃迁到了**单路递归**。分析递归复杂度，核心公式永远只有一句话：

$$
\text{总耗时} = \text{递归树节点总数} \times \text{单次调用本身的耗时}
$$

基于这个底层逻辑，这四个选项在递归题里分别对应以下模型：

1. **A.** $O(\log_2 n)$ **—— “单路折半递归”**

   * **递推式原型**：$T(n) = T(n/2) + O(1)$

   * **代码骨架**：每次只调用**一次**自身，但参数规模砍半。

   * **典型代表**：二分查找递归版、快速幂递归版（`power(x, n/2)`）。递归树退化为一条深度为 $\log_2 n$ 的单链。

2. **B.** $O(n)$ **—— “单路线性减量递归” 或 “等比收缩的双路递归”**

   * **递推式原型 1（本题）**：$T(n) = T(n-1) + O(1)$

     * 单路递归，每次只减 1，深度为 $n$，单节点耗时 $O(1)$，总共 $n$ 层单链。

   * **递推式原型 2（进阶陷阱）**：$T(n) = 2T(n/2) + O(1)$

     * 每次裂变成两路，但非递归部分只耗 $O(1)$。树高 $\log_2 n$，但叶子节点数是 $2^{\log_2 n} = n$，总结点数为 $2n-1$。典型如二叉树的递归求节点数或完全遍历。

3. **C.** $O(n\log_2 n)$ **—— “经典分治：分两路 + 线性合并”**

   * **递推式原型**：$T(n) = 2T(n/2) + O(n)$

   * **代码骨架**：递归调用自身两次处理左右两半，并且在递归返回后（或之前），有一个与当前区间长度成正比的 `for` 循环（$O(n)$）来做合并或划分。

   * **典型代表**：归并排序（Merge Sort）、快速排序的平均情况。

4. **D.** $O(n^2)$ **—— “单路递归套循环” 或 “快排最坏退化”**

   * **递推式原型**：$T(n) = T(n-1) + O(n)$

   * **代码骨架**：每一层递归只处理 $n-1$ 的规模，但在这一层里有一个 `for (int i=0; i<n; i++)` 的循环。总代价是 $n + (n-1) + \dots + 1 = O(n^2)$。

   * **典型代表**：快速排序在数组完全有序且选第一个元素为基准时的最坏情况。

### 二、 本题秒杀逻辑

1. **看调用分支数**：`fact(n - 1)` 只有 1 次递归调用，是一条直线往下走，没有分支分叉。

2. **看单层操作耗时**：`n * ...` 和 `if (n <= 1)` 都是常数级操作，单层耗时为 $O(1)$。

3. **看递归深度**：从 $n$ 递减到 1，步长为 1，一共调用了 $n$ 次。

4. **结论**：$n \times O(1) = O(n)$，直接**选 B**。

### 三、 命题人还能怎么变？（408 递归四大进阶变式）

#### 变式 1：变时间为“空间复杂度”

* **题目陷阱**：题干把“时间复杂度”改成“**空间复杂度**”。

* **考点**：函数的调用栈（Stack Frame）。递归没有开辟显式数组，但每一次函数调用都要在内存栈上保存返回地址、参数 `n` 和局部变量。

* **推演**：本题调用栈的最大深度也是 $n$，所以空间复杂度同样是 $O(n)$。如果改写成非递归循环（迭代法），时间仍是 $O(n)$，但空间会骤降为 $O(1)$。

#### 变式 2：“伪分治”裂变 —— 指数爆炸陷阱 $O(2^n)$

* **代码变式**（斐波那契数列）：

  ```
  int fib(int n) {
      if (n <= 1) return 1;
      return fib(n - 1) + fib(n - 2);
  }
  
  ```

* **考点**：单路变双路，步长还是减常数（$-1, -2$）。此时递推式是 $T(n) = T(n-1) + T(n-2) + O(1)$。递归树变成了一棵深度为 $n$ 的满二叉树，节点数呈现几何级数暴涨，时间复杂度直接飙升到 $O(2^n)$，而空间复杂度（栈的最大深度）依然是 $O(n)$。

#### 变式 3：递归步进从“减法”换成“除法” —— 对数模型

* **代码变式**：

  ```
  void solve(int n) {
      if (n <= 1) return;
      solve(n / 2);
  }
  
  ```

* **考点**：递推式变为 $T(n) = T(n/2) + O(1)$。此时递归深度是 $\log_2 n$，复杂度瞬间从 $O(n)$ 降维到 $O(\log_2 n)$。

#### 变式 4：单层内插入耗时操作 —— 递推求和模型

* **代码变式**：

  ```
  void process(int n) {
      if (n <= 0) return;
      for (int i = 0; i < n; i++) {
          printf("hello");
      }
      process(n - 1);
  }
  
  ```

* **考点**：外表还是 $n \to n-1$，但每次进入函数都要打印 $n$ 次。递推式是 $T(n) = T(n-1) + O(n)$，算出来直接选 **D (**$O(n^2)$**)**。

## 第三章：2013 真题 —— “最坏情况”的设计哲学与头插法逆置全解

### 【真题重现】03 · 2013-01

**1. 已知两个长度分别为** $m$ **和** $n$ **的升序链表，若将它们合并为一个长度为** $m + n$ **的降序链表，则最坏情况下的时间复杂度是\_____\_。**

* **A.** $O(n)$

* **B.** $O(mn)$

* **C.** $O(\min(m, n))$

* **D.** $O(\max(m, n))$

### 一、 走向一：即便考“最坏情况”，也必须先锁定“最优解法”

2013 年这道题彻底脱离了前两年直接给代码的模式，进入了“给需求、不给代码，让你自己脑补最优算法，并在该算法下评估最坏数据”的综合考查阶段。

> **核心认知**：数据结构里的“最坏情况”，指的是\*\*“在最优算法实现的前提下，遇到最极端、最不配合的输入数据时的表现”\*\*（即 $\min_{\text{算法}} \max_{\text{数据}}$ 的博弈），绝不是让你用最笨的暴力解法去硬算！

在这道题里，题干埋了一个巨大的视觉陷阱：**“两个升序链表，合并为一个降序链表”**。

* **平庸解法的诱惑（掉坑路径）**：先按常规双指针尾插法合成为一个升序链表，然后再写个循环遍历把整个链表逆置；或者每次找最大的元素需要遍历到链表尾部。

* **洞察数据结构特性的“好解”（破局路径）**：利用单链表**头插法（Head Insertion）天然具备的“逆序”功能**！

  * 既然原链表是**升序**，我们拿两个指针 `pa` 和 `pb` 从头开始比，每次挑出**较小**的那个节点。

  * 不用尾插，直接用**头插法**塞进新链表里。

  * 越小的元素越早被挑出来，越早被头插，最后就会沉到新链表的**最底部（表尾）**；越大的元素越晚被挑出来，头插后刚好留在新链表的**最顶部（表头）**。

  * **结论**：一遍扫描 + 头插法，单次插入 $O(1)$，直接在合并的同时瞬间完成“升序变降序”。

### 二、 本题四个选项的“最坏情况”拆解与秒杀

1. **若仅看“元素比较次数”**：

   * **最好情况**：一个链表的所有元素都比另一个小（例如 $[1, 2]$ 和 $[10, 20, 30, 40]$）。只需比较 $\min(m, n)$ 次，短链表就空了（这正是 **选项 C** $O(\min(m, n))$ 设下的诱饵，它对应的是“最好情况下的比较次数”）。

   * **最坏情况**：两个链表的元素**犬牙交错、交替上升**（例如 $[1, 3, 5]$ 和 $[2, 4, 6]$），你一个我一个，一直比到两个链表几乎同时耗尽，比较次数达到最大值 $m + n - 1$ 次。

2. **若看“头插/逆置的总操作次数”（决定本题上限的铁律）**：

   * 即便一个链表提前比完了，剩下的那个链表能直接把尾巴挂过去吗？**不能！**

   * 如果题目要求合成**升序**链表，剩下的直接 `tail->next = p` 就能 $O(1)$ 挂过去；但题目要求合成**降序**链表！剩下的链表本身是升序的，你依然必须把剩下的每一个节点**逐个拆下来做头插**，才能把它们倒过来变成降序。

   * 因此，无论数据怎么分布，所有 $m + n$ 个节点都必须老老实实走一遍头插操作，总时间复杂度必然是 $O(m + n)$。

3. **选项量级换算（秒杀时刻）**：

   * 选项里没有直接写 $O(m + n)$，而是给出了 **D.** $O(\max(m, n))$。

   * 在渐进复杂度分析中，有一条黄金恒等式：
     

     $$
     \max(m, n) \le m + n \le 2\max(m, n) \implies O(m + n) = O(\max(m, n))
     $$

   * 因此，**正确答案直接锁定 D**。（注：B 选项 $O(mn)$ 是留给“拿一个链表的每个元素去另一个链表里从头遍历找插入位置”这种纯暴力错误解法的陪跑项）。

### 三、 基本功补强：彻底搞懂“头插法”与“单链表原地逆置”

#### 1. 为什么说“头插法”天然具备逆序功能？

把链表的**头结点 `L`** 想象成洗碗池旁边的**盘子底座**，把插入节点想象成**往上摞盘子**：

* **尾插法（正常排队）**：来一个新节点，就跑到队伍的**最后面**接上。先来的在最前面，后来的在最后面，顺序不变。

* **头插法（往上摞盘子）**：不管是谁来，永远**直接塞在头结点 `L` 的正后方（第一号位置）**，把原本排在第一名的节点往后挤。

假设手头依次拿到了升序排列的三个数字：`1`、`2`、`3`，用**头插法**把它们一个个塞进空链表 `L`：

1. **初始状态**：只有头结点 `L -> NULL`

2. **拿到 `1`，塞到 `L` 后面**：`L -> [1] -> NULL`

3. **拿到 `2`，强行插队到 `L` 的正后方（`1` 的前面）**：`L -> [2] -> [1] -> NULL`

4. **拿到 `3`，继续强行插队到 `L` 的正后方（`2` 的前面）**：`L -> [3] -> [2] -> [1] -> NULL`

**结论**：输入顺序是 `1 -> 2 -> 3`（升序），仅仅因为每次都往“脖子底下”（`L->next`）硬塞，出来的链表自然就变成了 `3 -> 2 -> 1`（降序）。

#### 2. 头插法的两行核心代码（绝对铁律：先连后断）

假设头结点是 `L`，现在手里攥着一个新节点 `s`（比如 `[3]`），当时的链表长这样：`L -> [2] -> [1] -> NULL`。

```
s->next = L->next;  // 第一步（先连）：让新节点 s 的右手，拉住原本的第一名（即 L->next 指向的 [2]）
L->next = s;        // 第二步（后断）：让头结点 L 的右手松开 [2]，改拉住新节点 s

```

> **为什么要“先连后断”？** 如果反过来先写 `L->next = s;`，那么 `L` 原本指向 `[2]` 的那根线就断了，由于没有别的指针记住 `[2]` 的地址，后面的 `[2] -> [1]` 整串链表就会瞬间丢失在内存里（内存泄漏）。

#### 3. 单链表原地逆置标准代码

思路：**把头结点 `L` 摘出来当成一个空盘子底座，然后把后面原来的节点 `[1] -> [2] -> [3]` 一个接一个拆下来，用头插法重新塞回 `L` 后面！**

```
// 将带头结点的单链表 L 原地逆置
void ReverseList(LinkList L) {
    LNode *p = L->next;  // p 指向原链表的第一个数据节点，准备依次拆节点
    LNode *r;            // r 是防丢指针，用来提前记住 p 后面的节点
    
    L->next = NULL;      // 核心动作：先把头结点 L 与原链表断开，变成一个空链表底座！
    
    while (p != NULL) {  // 只要还有节点没拆完，就继续
        r = p->next;     // 1. 【防丢】先把 p 身后的节点地址保存在 r 里
        
        // 2. 【头插两步曲】把 p 插到头结点 L 的正后方
        p->next = L->next; 
        L->next = p;
        
        p = r;           // 3. 【推进】p 移动到刚才保存的下一个节点，准备拆下一个
    }
}

```

#### 4. 2013 真题完整实现代码（两升序合并为一降序）

```
void MergeToDesc(LinkList La, LinkList Lb) {
    LNode *pa = La->next; // pa 扫描链表 A
    LNode *pb = Lb->next; // pb 扫描链表 B
    LNode *r;             // 防丢指针，保存下一个节点
    
    La->next = NULL;      // 把 La 的头结点清空，作为新链表的底座
    
    // 第一阶段：当两个链表都还有节点时，挑小的出来做头插
    while (pa != NULL && pb != NULL) {
        if (pa->data <= pb->data) {
            r = pa->next;       // 防丢：记住 pa 的下一个
            pa->next = La->next;// 头插第1步
            La->next = pa;      // 头插第2步
            pa = r;             // pa 往后走一步
        } else {
            r = pb->next;       // 防丢：记住 pb 的下一个
            pb->next = La->next;// 头插第1步
            La->next = pb;      // 头插第2步
            pb = r;             // pb 往后走一步
        }
    }
    
    // 第二阶段：如果 La 还有剩余（或者 Lb 还有剩余），继续挨个拆下来头插！
    while (pa != NULL) {
        r = pa->next;
        pa->next = La->next;
        La->next = pa;
        pa = r;
    }
    while (pb != NULL) {
        r = pb->next;
        pb->next = La->next;
        La->next = pb;
        pb = r;
    }
    
    free(Lb); // 释放多余的 Lb 头结点
}

```

### 四、 走向二：全局视野 —— 408 中所有的“最坏情况”是怎么设计出来的？

在数据结构全书中，命题人构造让算法跑到“最坏情况”的毒瘤测试用例，总共只有 **5 套标准模具**：

1. **模具 1：交替拉扯，拒绝提前短路（针对双指针/多路归并）**

   * **设计手法**：让不同序列的数据大小呈“拉链式”交错（如 $1, 3, 5$ 与 $2, 4, 6$）。

   * **打击目标**：有序表合并、二路归并排序的 `Merge` 过程。彻底封死“一方提前耗尽、另一方直接整体接管”的快捷通道，强迫比较指针走满 $m + n - 1$ 步。

2. **模具 2：打破平衡，强行退化为单支链（针对树形结构与分治）**

   * **设计手法**：输入完全有序（正序或逆序）的序列，或者每次故意挑选极值（最大/最小）作为划分基准。

   * **打击目标**：

     * **二叉排序树（BST）**：按 $1, 2, 3, 4, 5$ 依次插入，树直接退化成一条斜线（单链表），查找效率从 $O(\log_2 n)$ 暴跌至最坏 $O(n)$。

     * **快速排序（Quick Sort）**：初始序列有序，且枢轴（Pivot）固定选第一个元素。每次划分都是 $0$ 和 $n-1$ 两个极不对称的子区间，递归树深度从 $\log_2 n$ 退化为 $n$，时间复杂度从 $O(n\log_2 n)$ 恶化至最坏 $O(n^2)$，栈空间也恶化至 $O(n)$。

3. **模具 3：拉满失配与全表堆积（针对查找与匹配）**

   * **设计手法**：要么让人找不到（一直在边缘试探，最后一刻才失败），要么让所有人全挤在一个房间里。

   * **打击目标**：

     * **顺序查找 / 二分查找**：最坏情况就是**查找失败（元素不存在）**，或者目标元素刚好卡在最后一个位置/叶子节点上，逼你把循环跑穿。

     * **KMP / 朴素模式匹配**：主串 `0000000001`，模式串 `0001`。每次都在最后一个字符 `'1'` 处失配，让朴素匹配每次都回溯，强行拉满到 $O(mn)$。

     * **哈希表（散列表）**：所有关键字对散列函数取模后**全部同义冲突**，拉链法退化成单链表查找，开放定址法每次都要探测全表，复杂度从 $O(1)$ 跌至 $O(n)$。

4. **模具 4：全逆序对抗，触发满额交换（针对基于比较的内部排序）**

   * **设计手法**：要求升序排列时，给一个**严格降序**的数组。

   * **打击目标**：直接插入排序、冒泡排序。每一次内层循环的比较都不能提前 `break`，每一个新元素都必须一路交换/挪动到最排头，移动次数和比较次数双双达到 $\frac{n(n-1)}{2}$ 的理论极值 $O(n^2)$。

5. **模具 5：形态极端化 —— 稠密全连接 vs 单链长路径（针对图论）**

   * **设计手法**：图的复杂度由顶点数 $V$ 和边数 $E$ 共同决定，最坏情况就是把 $E$ 推向极致（完全图 $E = O(V^2)$），或者把图的直径拉到最长（退化为单链）。

## 第四章：2014 真题 —— 专治嵌套循环迷糊的“拆解与三行列表法”

### 【真题重现】04 · 2014-01

**1. 下列程序段的时间复杂度是\_____\_。**

```
count = 0;
for (k = 1; k <= n; k *= 2)
    for (j = 1; j <= n; j++)
        count++;

```

* **A.** $O(\log_2 n)$

* **B.** $O(n)$

* **C.** $O(n\log_2 n)$

* **D.** $O(n^2)$

### 一、 破除嵌套迷糊的根本法则：放弃大脑动态模拟，改用机械拆解

面对双层嵌套循环容易看懵，根本原因是试图**在大脑里把整个程序动态跑一遍**。一旦遇到变量纠缠，大脑的寄存器就不够用了。解决这个痛点的唯一办法，是改用机械化的“先拆解、后列表”破局法则。

#### 第一步：一眼定乾坤 —— 内层循环里到底有没有外层变量？

拿到任何双层循环，**第一眼先盯死内层循环的三个位置**：初值、条件、步进。看里面有没有出现外层循环的变量（比如本题外层是 `k`，就看内层有没有出现字母 `k`）。这直接把所有嵌套循环一刀劈成两大阵营：**独立型（长方形）** 和 **耦合型（三角形/梯形）**。

#### 阵营 1：独立型（内层完全不搭理外层）—— 直接用【乘法】

**2014 年这道真题，其实就是穿了马甲的“长方形”，根本不是三角形！**

1. **盯内层**：`for (j=1; j<=n; j++)`。从头到尾只有 `j` 和 `n`，**半个字母 `k` 都没有**！

2. **得结论**：说明无论外层的 `k` 怎么折腾，内层根本不关心，它每次都是雷打不动地从 $1$ 走到 $n$，固定执行 $n$ 次。

3. **单看外层**：`for (k=1; k<=n; k*=2)`。这是 2011 年练过的“乘 2 倍增”，一共执行 $\log_2 n$ 次。

4. **直接相乘**：因为内外互不干扰，就像一个长方形，长是 $n$，宽是 $\log_2 n$。
   

   $$
   \text{总次数} = \text{外层次数} \times \text{内层次数} = \log_2 n \times n = O(n\log_2 n)
   $$

   
   **直接秒选 C**，连草稿纸都不用碰。

### 二、 阵营 2：如果是“三角形”或“梯形”（耦合型），如何用“三行列表法”通杀？

如果内层条件里**出现了外层变量**（比如把本题内层的 `j<=n` 改成 **`j<=k`**），这时候内外层死死咬合在一起，不能直接相乘了。遇到这种题，**直接在草稿纸上画一个“三行列表”**，写满前 3 轮，规律自己就会跳出来！

#### 变形 1：把本题内层改为 `j <= k`（等比三角形 —— 最容易算错的坑，即 2022 真题原型）

```
for (k = 1; k <= n; k *= 2)      // 外层：每次乘 2
    for (j = 1; j <= k; j++)     // 内层：出现了 k！每次从 1 走到 k
        count++;

```

* **第 1 轮**：当 `k = 1` 时，`j` 从 $1$ 走到 $1$ $\longrightarrow$ 内层跑了 $1$ 次

* **第 2 轮**：当 `k = 2` 时，`j` 从 $1$ 走到 $2$ $\longrightarrow$ 内层跑了 $2$ 次

* **第 3 轮**：当 `k = 4` 时，`j` 从 $1$ 走到 $4$ $\longrightarrow$ 内层跑了 $4$ 次

* **第 4 轮**：当 `k = 8` 时，`j` 从 $1$ 走到 $8$ $\longrightarrow$ 内层跑了 $8$ 次

* ……

* **最后一轮**：当 `k = n` 时，`j` 从 $1$ 走到 $n$ $\longrightarrow$ 内层跑了 $n$ 次

**把右边加起来**：$\text{总次数} = 1 + 2 + 4 + 8 + \dots + n$。
这是等比数列求和！**考场偷懒结论：等比数列求和，结果永远等于“最后一项”的量级**（因为 $1+2+4+\dots+n = 2n - 1$）。所以复杂度直接变成 $O(n)$，而不是 $O(n\log_2 n)$！

#### 变形 2：标准直角三角形（等差三角形）

```
for (i = 1; i <= n; i++)         // 外层：每次加 1
    for (j = 1; j <= i; j++)     // 内层：出现了 i！每次从 1 走到 i
        count++;

```

* **第 1 轮**：当 `i = 1` 时，`j` 从 $1$ 走到 $1$ $\longrightarrow$ 内层跑了 $1$ 次

* **第 2 轮**：当 `i = 2` 时，`j` 从 $1$ 走到 $2$ $\longrightarrow$ 内层跑了 $2$ 次

* **第 3 轮**：当 `i = 3` 时，`j` 从 $1$ 走到 $3$ $\longrightarrow$ 内层跑了 $3$ 次

* ……

* **最后一轮**：当 `i = n` 时，`j` 从 $1$ 走到 $n$ $\longrightarrow$ 内层跑了 $n$ 次

**把右边加起来**：$\text{总次数} = 1 + 2 + 3 + \dots + n = \frac{n(n+1)}{2} = O(n^2)$。哪怕内层写成 `j <= 2*i`（变成 $2+4+6+\dots+2n$），或者写成 `j = i; j <= n; j++`（倒三角形：$n + (n-1) + \dots + 1$），只要列表出来是**每次加固定步长**的等差数列，面积永远是正方形的一半，量级永远是 $O(n^2)$。

#### 变形 3：加了 `if` 判断的残缺图形

```
for (i = 1; i <= n; i++)
    if (i % 2 == 1)              // 只有奇数才进内层！
        for (j = 1; j <= i; j++)
            count++;

```

* `i = 1` $\longrightarrow$ 跑 $1$ 次

* `i = 2` $\longrightarrow$ 不进内层，$0$ 次

* `i = 3` $\longrightarrow$ 跑 $3$ 次

* `i = 4` $\longrightarrow$ 不进内层，$0$ 次

* `i = 5` $\longrightarrow$ 跑 $5$ 次

加起来就是 $1 + 3 + 5 + \dots + n$，相当于把原来的三角形抽掉了一半的木条，总和大概是原来的一半（$\frac{n^2}{4}$），去掉常数系数 $\frac{1}{4}$，结果依然是 $O(n^2)$！

#### 考场防迷糊“傻瓜式”操作清单

| 步骤 | 动作 | 判断标准与结果 | 
| ----- | ----- | ----- | 
| **第 1 步** | 找内层有没有外层字母 | **没有** $\rightarrow$ 它是正方形/长方形！内外分开算，直接**相乘**（如 2014 真题：$\log_2 n \times n$）。  **有** $\rightarrow$ 它是三角形！进入第 2 步。 | 
| **第 2 步** | 在纸上写前 3 轮的次数 | 强行代入外层的前 3 个具体数字（比如 $1, 2, 3$ 或 $1, 2, 4$），数出内层分别跑了几次。 | 
| **第 3 步** | 看数字规律直接套结论 | 如果是 $1 + 2 + 3 + \dots + n$（均匀增加） $\rightarrow$ 闭眼选 $O(n^2)$。  如果是 $1 + 2 + 4 + 8 + \dots + n$（翻倍增加） $\rightarrow$ 只看最后一项，闭眼选 $O(n)$。 | 

## 第五章：2017 真题 —— 双变量纠缠的 `while` 循环与开根号模型

### 【真题重现】05 · 2017-01

**1. 下列函数的时间复杂度是\_____\_。**

```
int func(int n) {
    int i = 0, sum = 0;
    while (sum < n) sum += ++i;
    return i;
}
```

* **A.** $O(\log n)$

* **B.** $O(n^{1/2})$

* **C.** $O(n)$

* **D.** $O(n\log n)$

### 一、 为什么这道题容易让人“大脑断电”？

在之前的题目里，循环次数和判断条件是**同一个变量**（比如 `x < n/2` 且 `x = 2*x`）。而在这道 2017 年的题里，**负责计数的变量是 `i`**（每次乖乖加 1），但**负责踩刹车跳出循环的变量却是 `sum`**（`sum < n`）！两个变量职责分离，还用了 `+=` 和 `++` 叠在一起，直觉一下子就失灵了。

### 二、 专治 `while` 迷糊的“翻译 + 列表法”

遇到 `sum += ++i;` 这种缩写感到头晕时，**先在草稿纸上把它拆成大白话**：

1. `++i`：先让 `i` 自己加 1（变成 $1, 2, 3, \dots$）。

2. `sum += i`：再把新的 `i` 累加到 `sum` 肚子里面去（即 `sum = sum + i`）。

接着，拿出“三行列表法”，把前 4 轮的变量值默写出来：

* **初始状态**：`i = 0`，`sum = 0`

* **第 1 次循环**：`i` 变成 $1$，`sum` 变成 $0 + 1 = 1$

* **第 2 次循环**：`i` 变成 $2$，`sum` 变成 $1 + 2 = 3$

* **第 3 次循环**：`i` 变成 $3$，`sum` 变成 $1 + 2 + 3 = 6$

* **第 4 次循环**：`i` 变成 $4$，`sum` 变成 $1 + 2 + 3 + 4 = 10$

* ……

* **第** $k$ **次循环**：`i` 变成 $k$，`sum` 变成 $1 + 2 + 3 + \dots + k$

规律一目了然：**循环跑了** $k$ **次（也就是 `i` 的值），`sum` 就是从** $1$ **加到** $k$ **的总和！**
接下来直接套终止条件 `sum >= n`：

$$
\text{sum} = 1 + 2 + 3 + \dots + k = \frac{k(k+1)}{2} \ge n
$$


展开只看最高次项：

$$
\frac{1}{2}k^2 \approx n \implies k \approx \sqrt{2n}
$$


去掉常数系数 $\sqrt{2}$，循环次数 $k$ 的量级就是 $\sqrt{n}$，即 $O(n^{1/2})$**，稳稳选 B**！

### 三、 总结：408 单层循环的“三大金刚”模型

不管它是 `for` 还是 `while`，408 中所有单层循环的步进一共只有这 3 种套路：

| 步进套路 | 典型代码特征 | 第 $k$ 次循环后变量的值 | 令其等于 $n$ 解出次数 $k$ | 最终复杂度 | 
| ----- | ----- | ----- | ----- | ----- | 
| **1. 每次加固定常数** | `i++` 或 `i += 2` | $k$ 或 $2k$ | $k \approx n$ | $O(n)$ | 
| **2. 每次乘固定倍数** | `x *= 2` | $2^k$ | $2^k \approx n \implies k \approx \log_2 n$ | $O(\log_2 n)$ | 
| **3. 每次累加递增变量或自乘** | `sum += ++i` 或 `i*i < n` | $1+2+\dots+k = \frac{k^2}{2}$ 或 $k^2$ | $\frac{k^2}{2} \approx n \implies k \approx \sqrt{n}$ | $O(n^{1/2})$ | 

## 第六章：核心心法升华 —— 如何建立“量级抗干扰直觉（去噪放宽法）”？

> **核心痛点**：怎么在看到代码的瞬间，判断或感觉到复杂度会不会因为某些小改动而发生变化？如果改动不大，如何直接把它放宽、还原到最简单的标准模型（如纯正的 $\log n$、纯正的 $O(n^2)$）里去？

为了建立这种“去噪能力”，我们把代码里的所有改动划分为“绝对安全的瞎折腾（纸老虎，模型不变）”**和**“立刻警觉的真变异（动了筋骨，复杂度必变）”两大类：

### 一、 哪些改动是“纸老虎”？（不管怎么改，闭眼套回原模型）

#### 1. 边界和初值的“加减乘除常数” $\longrightarrow$ 统统视为没改！

* **标准件**：`while (x < n)`

* **瞎折腾**：改成 `x < n / 2`（2011真题）、`x < 100 * n`、`x < n - 999`，或者初值从 `x = 1` 改成 `x = 8`。

* **直觉判断**：在大 $O$ 的世界里，终点线往前挪一半，或者往后退十倍，对于整体增长趋势来说就是毛毛雨。遇到这种改动，**直接拿橡皮擦把常数擦掉，当成最简单的 `x < n` 来想**，模型死死锁在原处。

#### 2. 步进幅度的“换挡不换车” $\longrightarrow$ 统统视为没改！

* **同属“线性车队”（加减法内部随便改）**：

  * **标准件**：`i++`（每次加 1）

  * **瞎折腾**：改成 `i += 2`、`i += 100`。

  * **直觉判断**：只要还是用**加号或减号**配常数，步子迈得再大也是步行，**无脑归入** $O(n)$ **模型**。

* **同属“倍增车队”（乘除法内部随便改）**：

  * **标准件**：`k *= 2`（每次乘 2）

  * **瞎折腾**：改成 `k *= 3`、`k *= 10`、`k /= 2`。

  * **直觉判断**：由换底公式 $\log_3 n = \frac{\log_2 n}{\log_2 3}$ 可知，底数是 2 还是 10 只差一个常数倍。只要还是**乘号或除号**配常数，**无脑归入** $O(\log n)$ **模型**。

#### 3. 嵌套循环里，“线性层”变成三角形 $\longrightarrow$ 视为没改！

* **标准件（正方形）**：外层 `i` 从 $1$ 到 $n$（`i++`），内层 `j` 从 $1$ 到 $n$（`j++`） $\longrightarrow O(n^2)$。

* **瞎折腾（切掉一半变三角形）**：内层条件从 `j <= n` 改成了 **`j <= i`**，或者初值从 `j = 1` 改成了 **`j = i`**。

* **直觉判断**：**当外层是老老实实的 `i++`（均匀推进）时**，内层跟着外层变，仅仅相当于把正方形对角线切了一刀变成三角形。面积除以 2（$\frac{1}{2}n^2$）根本不改变平方的本质，**直接放宽回正方形模型，闭眼选** $O(n^2)$！

### 二、 哪些改动是“真变异”？（看到这 3 个信号，复杂度必变！）

1. **信号 1：运算符跨界了！（从 `+` 变成了 `*`，或者反过来）**

   * 只要某一层的步进从加减法变成了乘除法，这一层的维度立刻从 $n$ **坍缩**成 $\log n$。

2. **信号 2：判断条件里出现了“自乘”或“累加器”！**

   * 条件里的变量自己乘自己：`while (i * i < n)`（2019真题）。

   * 条件里换成了累加变量 `sum`：`while (sum < n) sum += ++i;`（2017真题）。

   * **直觉判断**：一旦看到条件不再是单纯的 `i < n`，而是带了平方或者累加和，意味着刹车的速度变成了平方级，复杂度必然从 $O(n)$ **降维成开根号** $O(n^{1/2})$。

3. **信号 3：【最隐蔽的变异】外层是倍增（`k *= 2`），内层却把上限改成了外层变量（`j <= k`）！**

   * 在 `i++` 的世界里，`j <= i` 只是把正方形切掉一半变成三角形，面积还是同量级的；**但是在 `k *= 2`（指数倍增）的世界里，绝大部分的工作量全都集中在“最后那一步”！**

   * 想象一下：第一天花 1 块钱，第二天花 2 块，第三天花 4 块……最后一天花了 $n$ 块钱。前面所有天数的钱加起来，刚好等于最后一天花的钱（$1+2+4+\dots+n/2 = n-1$）！

   * **直觉铁律**：只要看到 **“外层倍增（`k *= 2`） + 内层紧跟外层（`j <= k`）”** 的组合，外层的 $\log n$ 直接作废！整个双层循环的复杂度，**完全等于内层在“最后一轮”跑的次数（即** $O(n)$**）**！

## 第七章：2019 真题 —— 去噪放宽法的实战秒杀与“特殊选项”定律检验

### 【真题重现】06 · 2019-01

**1. 设** $n$ **是描述问题规模的非负整数，下列程序段的时间复杂度是\_____\_。**

```
x = 0;
while (n >= (x + 1) * (x + 1))
    x = x + 1;

```

* **A.** $O(\log n)$

* **B.** $O(n^{1/2})$

* **C.** $O(n)$

* **D.** $O(n^2)$

### 一、 用“去噪放宽法”瞬间还原模型

1. **看步进（引擎）**：循环体里是 `x = x + 1;`，即最标准的每次加 1（`x++`），设执行了 $k$ 次，那么 $x$ 的值就是 $k$。

2. **擦除噪音（去伪存真）**：看循环条件 `n >= (x + 1) * (x + 1)`。按照“边界和初值的加减常数统统视为纸老虎”的原则，直接拿橡皮擦把 `(x + 1)` 里的 `+ 1` 擦掉！

3. **现出原形**：擦掉噪音后，这段代码直接被放宽成了最纯粹的标准件：

   ```
   while (x * x <= n)
       x++;
   
   ```

4. **触发变异信号**：判断条件里出现了“自乘（平方）”！由 $x^2 \le n$ 两边同时开根号，直接得出执行次数 $x \le \sqrt{n}$，即 $O(n^{1/2})$，**选 B**。

### 二、 严肃辩证：选项里出现“不常见的 $O(n^{1/2})$”就一定选它吗？

在 2017 年和 2019 年，选项里混进来的特殊面孔 $O(n^{1/2})$ 确实都是正确答案。但**绝对不能把“选项罕见就无脑选”当成铁律**，而必须使用“双向锁定（对暗号）”法则：

1. **第一步（看选项，提问题）**：看到选项里有 $O(n^{1/2})$，心里立刻响起警报：“命题人放了个根号在这里，我赶紧去代码里找找，**到底有没有【平方】或者【累加】？**”

2. **第二步（看代码，对暗号）**：

   * 如果代码里**真的有** `x * x`（如 2019 年）或者 `sum += ++i`（如 2017 年） $\longrightarrow$ **暗号对上了！** 100% 确定选 $O(n^{1/2})$！

   * 如果代码里**根本没有**自乘，也没有累加器作为终止条件 $\longrightarrow$ **暗号没对上！** 这个特殊选项就是烟雾弹，立刻排除！

## 第八章：2022 真题 —— 双层循环里的“反直觉刺客”

### 【真题重现】07 · 2022-01

**01. 下列程序段的时间复杂度是（ ）。**

```
int sum = 0;
for (int i = 1; i < n; i *= 2)
    for (int j = 0; j < i; j++)
        sum++;

```

* **A.** $O(\log n)$

* **B.** $O(n)$

* **C.** $O(n\log n)$

* **D.** $O(n^2)$

### 一、 为什么说它是“反直觉刺客”？

这道题的选项回归了最经典的“老四样”：$O(\log n)$、$O(n)$、$O(n\log n)$、$O(n^2)$。命题人在 2022 年出这道题，专门就是为了抓那些“一看到两层 `for` 循环，不是选 C ($O(n\log n)$) 就是选 D ($O(n^2)$)”的考生！因为人的惯性思维很难接受“一个货真价实的双层嵌套循环，算出来居然是一次方 $O(n)$”。

如果从“答案反常识、最让人不敢选”这个角度来定义“不常见”，那在双层循环里，**B.** $O(n)$ 才是真正的刺客！

### 二、 两把手术刀 10 秒剖开本题

#### 第一把刀：直接触发“第 3 号致命变异信号”

1. **看外层**：`for (int i = 1; i < n; i *= 2)` $\longrightarrow$ 外层是坐火箭的**倍增（`i *= 2`）**。

2. **看内层**：`for (int j = 0; j < i; j++)` $\longrightarrow$ 盯住中间的条件 **`j < i`**！内层没有写 `j < n`，而是死死咬住了外层的变量 **`i`**！

3. **套用铁律**：外层倍增（`i *= 2`）+ 内层紧跟外层（`j < i`），外层的 $\log n$ 当场作废！因为前面所有轮次跑的次数加起来，都抵不过最后一轮！整个双层循环的复杂度，直接**坍缩**成最后一轮跑的次数，即 $O(n)$**（选 B）**！

#### 第二把刀：用“三行列表法”当场验算

* **第 1 轮**：当 `i = 1` 时，内层 `j` 从 $0$ 走到 $0$（`j < 1`） $\longrightarrow$ 跑了 $1$ 次

* **第 2 轮**：当 `i = 2` 时，内层 `j` 从 $0$ 走到 $1$（`j < 2`） $\longrightarrow$ 跑了 $2$ 次

* **第 3 轮**：当 `i = 4` 时，内层 `j` 从 $0$ 走到 $3$（`j < 4`） $\longrightarrow$ 跑了 $4$ 次

* **第 4 轮**：当 `i = 8` 时，内层 `j` 从 $0$ 走到 $7$（`j < 8`） $\longrightarrow$ 跑了 $8$ 次

* ……

* **最后一轮**：当 `i` 接近 $n$（设为 $\frac{n}{2}$）时，内层跑了 $\frac{n}{2}$ 次

**把右边一列加起来**：

$$
\text{sum} = 1 + 2 + 4 + 8 + \dots + \frac{n}{2} = n - 1 = O(n)
$$


稳稳落在 **B.** $O(n)$！

### 三、 把 2014 真题 和 2022 真题 焊死在一起对比

这两道题是 408 历史上最经典的一对“双胞胎”，只差了一个字母，答案天差地别：

| 真题年份 | 外层循环 | 内层循环 | 关键区别（内层上限） | 几何形状与计算 | 最终答案 | 
| ----- | ----- | ----- | ----- | ----- | ----- | 
| **2014-01** | `k *= 2` | `j <= n` | 上限是固定的 **`n`**（独立） | **长方形**：宽 $\log n \times$ 长 $n$ | **C.** $O(n\log n)$ | 
| **2022-01** | `i *= 2` | `j < i` | 上限是外层的 **`i`**（耦合） | **指数阶梯**：$1+2+4+\dots \approx n$ | **B.** $O(n)$ | 
| *(假想对比)* | `i++` | `j < i` | 外层改成了 **`i++`** | **直角三角形**：$1+2+3+\dots+n \approx \frac{n^2}{2}$ | **D.** $O(n^2)$ | 

## 第九章：2023 真题 —— 线性表文字游戏与四大“夺命避坑指南”

### 【真题重现】08 · 2023-01

**01. 下列对顺序存储的有序表（长度为** $n$**）实现给定操作的算法中，平均时间复杂度为** $O(1)$ **的是（ ）。**

* **A.** 查找包含指定值元素的算法

* **B.** 插入包含指定值元素的算法

* **C.** 删除第 $i$（$1 \le i \le n$）个元素的算法

* **D.** 获取第 $i$（$1 \le i \le n$）个元素的算法

### 一、 题干里的“障眼法”与四选项真实底牌

命题人在题干里塞进了一个极其阴险的定语组合：**“顺序存储” + “有序表”**。

* **A. 查找包含指定值元素的算法** $\longrightarrow$ $O(\log_2 n)$（若顺序查找则是 $O(n)$）

  * 因为它是“顺序存储 + 有序”，满足随机访问和单调性，最优解法是**折半查找（二分查找）**。

* **B. 插入包含指定值元素的算法** $\longrightarrow$ $O(n)$（**本题头号大坑！**）

  * **常见错觉**：“既然是有序表，我用二分查找找到插入位置不就 $O(\log_2 n)$ 吗？”

  * **避坑铁律**：在顺序表里插入一个元素，分成“找位置”**和**“挪屁股（移动元素）”两步。二分查找确实能把“找位置”压缩到 $O(\log_2 n)$，但为了腾出空位，后面的元素依然要挨个往后搬，平均要移动 $\frac{n}{2}$ 个元素！所以总复杂度是 $O(\log_2 n) + O(n) = O(n)$。**二分查找救不了顺序表的插入和删除！**

* **C. 删除第** $i$ **个元素的算法** $\longrightarrow$ $O(n)$

  * 定位第 $i$ 个元素虽然只要 $O(1)$，但删掉它之后，后面的 $n-i$ 个元素要集体往前补位，平均移动 $\frac{n-1}{2}$ 次，依然是 $O(n)$。

* **D. 获取第** $i$ **个元素的算法** $\longrightarrow$ $O(1)$**（正确答案）**

  * 数组的看家本领“随机存取（Random Access）”，不管有没有序，直接通过下标地址公式 `base + (i-1)*sizeof(ElemType)` 一步到位，**选 D**。

### 二、 延伸避险：这道题没考出来、但随时会背刺你的 4 个“夺命判断”

#### 避坑 1：把“顺序存储”改成“链式存储” —— 二分查找当场报废！

* **夺命追问**：“对长度为 $n$ 的**有序单链表**，查找包含指定值元素的最快平均时间复杂度是多少？”

* **真相**：**单链表绝对不能用二分查找！** 因为二分查找要求在 $O(1)$ 时间内直接跳到中间节点 `mid`，而链表没有下标，找中间节点必须从头指针一步步走过去。在有序单链表里查找，哪怕排得再整齐，也只能从头顺序扫描，时间复杂度死死锁在 $O(n)$！

#### 避坑 2：链表里的“真假 $O(1)$” —— 到底给的是“序号 $i$”还是“指针 $p$”？

* 如果把本题题干改成“单链表”，那么 **D（获取第** $i$ **个元素）和 C（删除第** $i$ **个元素）全都是** $O(n)$，因为都得先从头数到第 $i$ 个位置。

* **但是！如果题目这么问**：“在单链表中，给定指向某节点的**指针** $p$（非尾节点），删除 $p$ 所指节点（或在 $p$ 前插入一个节点）的最快时间复杂度是多少？”

* **真相（“偷天换日法”）**：其实是 $O(1)$！不用从头遍历找前驱 `pre`，只要把 $p$ 的后继节点 `q = p->next` 的数据域直接复制（覆盖）到 $p$ 肚子里（`p->data = q->data`），然后把后继节点 `q` 删掉（`p->next = q->next; free(q);`），耗时仅仅是常数级 $O(1)$！

#### 避坑 3：“平均” vs “最好” vs “最坏” —— 换个定语，C 也能变成 $O(1)$！

* 本题问的是“平均时间复杂度”**。如果改成**“最好时间复杂度”**，再看选项 **C（删除第**** $i$ ****个元素）**：当** $i = n$**（刚好删除顺序表的**最后一个元素）时，后面没有任何元素需要往前挪，此时 C 的最好时间复杂度也是 $O(1)$！

* 同理，B 选项在最好情况下（指定值恰好比原表所有元素都大，直接插在表尾，且从表尾开始比较），比较 1 次、移动 0 次，最好复杂度也能达到 $O(1)$！看清题干问的是“最好”、“最坏”还是“平均”，是保命的第一步。

#### 避坑 4：“按值操作” vs “按位操作” —— 拆解动作的“木桶效应”

在任何线性表里，判断复杂度永远遵循“两步拆解法（定位 + 施工）”**，总复杂度取决于**慢的那一步：

$$
\text{总时间} = \max(\text{定位时间}, \text{修改结构/移动元素时间})
$$

| 操作类型 | 顺序无序表 | **顺序有序表（本题）** | 链式无序表（单链表） | **链式有序表（有序单链表）** | 
| ----- | ----- | ----- | ----- | ----- | 
| **获取第** $i$ **个元素（按位查）** | $O(1)$ | $O(1)$**（本题选 D）** | $O(n)$（需遍历定位） | $O(n)$（需遍历定位） | 
| **查找指定值** $x$**（按值查）** | $O(n)$ | $O(\log_2 n)$**（二分查找）** | $O(n)$ | $O(n)$**（不能二分！）** | 
| **插入指定值** $x$**（保持性质）** | $O(1)$（直接插表尾） | $O(n)$（找 $O(\log n)$ + **挪** $O(n)$） | $O(1)$（直接头插） | $O(n)$（**找位置** $O(n)$ + 插 $O(1)$） | 
| **删除第** $i$ **个元素（按位删）** | $O(n)$（定 $O(1)$ + **挪** $O(n)$） | $O(n)$（定 $O(1)$ + **挪** $O(n)$） | $O(n)$（**定** $O(n)$ + 删 $O(1)$） | $O(n)$（**定** $O(n)$ + 删 $O(1)$） | 

## 第十章：2025 真题 —— 看似朴素的“终极缝合怪”与未来预测

### 【真题重现】09 · 2025-01

**1. 下列程序段的时间复杂度是\_____\_。**

```
int count = 0, i, j;
for (i = 1; i * i <= n; i++)
    for (j = 1; j <= i; j++)
        count++;

```

*(注：原卷印刷中内层写为 `j=<i`，系 `j<=i` 的排版笔误)*

* **A.** $O(\log n)$

* **B.** $O(n)$

* **C.** $O(n\log n)$

* **D.** $O(n^2)$

### 一、 为什么说它是“披着朴素外衣的缝合怪”？

2025 年这道题表面上眉清目秀，实际上它把 **2019 年的“开根号模型”（`i*i <= n`）** 和 **经典的“等差直角三角形模型”（`j <= i`）** 强行缝合在了一起！

* 考场上无数人第一眼看到两层 `for` 循环，且步进全都是 `i++` 和 `j++`，肌肉记忆直接选了 **D (**$O(n^2)$**)**；

* 还有一部分人看到了 `i*i <= n`，慌忙去找 $O(n^{1/2})$ 却发现选项里根本没有！

* 实际上，这道题的正确答案依然是那个“双层循环里的反直觉刺客”——**选 B (**$O(n)$**)**！

### 二、 两把快刀斩乱麻

#### 第一把刀：用“放宽直觉（几何面积法）”秒杀

只要外层是 `i++`，内层是 `j <= i`，它就是一个**标准直角三角形**！

* **普通直角三角形**：如果外层是 `i <= n`，底是 $n$，高也是 $n$，面积就是 $\frac{1}{2} \times n \times n = O(n^2)$。

* **2025 年这把缩骨伞**：外层的终止条件是 **`i * i <= n`**！这意味着外层的 `i` 根本走不到 $n$，它走到 $\sqrt{n}$ 的时候就撞墙停下了！

* 也就是说，这是一个**底边长为** $\sqrt{n}$**、高也为** $\sqrt{n}$ **的迷你直角三角形**！
  

  $$
  \text{面积} = \frac{1}{2} \times \text{底} \times \text{高} = \frac{1}{2} \times \sqrt{n} \times \sqrt{n} = \frac{1}{2}n
  $$

* **负负得正（开根号遇上平方，刚好抵消）**！去掉常数 $\frac{1}{2}$，直接锁定 **B.** $O(n)$！

#### 第二把刀：用“三行列表法”硬核验算

* **第 1 轮**：当 `i = 1` 时，内层 `j` 从 $1$ 走到 $1$ $\longrightarrow$ 跑了 $1$ 次

* **第 2 轮**：当 `i = 2` 时，内层 `j` 从 $1$ 走到 $2$ $\longrightarrow$ 跑了 $2$ 次

* **第 3 轮**：当 `i = 3` 时，内层 `j` 从 $1$ 走到 $3$ $\longrightarrow$ 跑了 $3$ 次

* ……

* **最后一轮**：当 $i^2 \approx n$，即 **`i =`** $\sqrt{n}$ 时停止，此时内层 `j` 从 $1$ 走到 $\sqrt{n}$ $\longrightarrow$ 跑了 $\sqrt{n}$ 次。

**把右边一列加起来**（套用等差数列求和公式）：

$$
\text{总次数} = 1 + 2 + 3 + \dots + \sqrt{n} = \frac{\sqrt{n}(\sqrt{n} + 1)}{2} = \frac{1}{2}n + \frac{1}{2}\sqrt{n}
$$


只保留最高阶项 $n$，答案板上钉钉就是 **B.** $O(n)$！

### 三、 终极全景复盘：2011 — 2025 命题人的“三代进化心路历程”

1. **第一代（2011 - 2014）：单点直球期**

   * 考倍增就是纯倍增（2011），考递归就是纯单链（2012），考双层循环就是互不干扰的长方形（2014）。只要认识基本语法就能拿分。

2. **第二代（2017 - 2019）：引入“平方/开根号”新武器**

   * 命题人觉得大家把 $O(\log n)$ 背熟了，于是造出了“累加器（`sum += ++i`）”（2017）和“显式自乘（`(x+1)*(x+1)`）”（2019），把答案引向了 $O(n^{1/2})$。

3. **第三代（2022 - 2025）：反直觉“降维合成期”（最阴险的阶段！）**

   * 命题人发现考生学会了“看外表猜答案”（看到一层循环带平方就找 $\sqrt{n}$，看到两层循环就无脑选 $O(n\log n)$ 或 $O(n^2)$）。

   * 于是，**2022 年**和**2025 年**不约而同地玩起了“双层循环坍缩成 $O(n)$”的把戏！

     * **2022 年**用 **“对数轮次（**$\log n$**）** $\times$ **指数累加（**$2^k$**）”**，指数和对数互为逆运算，一抵消，坍缩成了 $O(n)$！

     * **2025 年**用 **“根号轮次（**$\sqrt{n}$**）** $\times$ **线性累加（平方和）”**，开根号和平方互为逆运算，一抵消，又坍缩成了 $O(n)$！

### 四、 预判未来（2026 / 2027）：命题人还能怎么“缝合”？

顺着 2022 和 2025 年“两层组合”的设计美学，未来考场上极可能出现以下 2 个变种：

#### 变种预测 1：2025 真题的“独立长方形版”

如果把 2025 年的内层 `j <= i` 改回独立的 **`j <= n`**：

```
for (i = 1; i * i <= n; i++)     // 外层跑 √n 轮
    for (j = 1; j <= n; j++)     // 内层每轮固定跑 n 次
        count++;

```

* **秒杀**：内外独立直接相乘，$\sqrt{n} \times n = O(n^{3/2})$（或写作 $O(n\sqrt{n})$）。

#### 变种预测 2：调和级数伪装者（最经典的未考模型）

```
for (i = 1; i <= n; i++)         // 外层 1 到 n
    for (j = 1; j <= n; j += i)  // 注意步进：每次加 i ！
        count++;

```

* **秒杀**：用三行列表法：

  * `i = 1` 时，`j` 每次加 1，跑 $\frac{n}{1}$ 次；

  * `i = 2` 时，`j` 每次加 2，跑 $\frac{n}{2}$ 次；

  * `i = 3` 时，`j` 每次加 3，跑 $\frac{n}{3}$ 次……

  * 加起来是 $n\left(1 + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{n}\right) = O(n\log n)$！看着全是加号，结果居然带 $\log n$！
