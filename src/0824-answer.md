## 01｜2010-23：接口＝应用能直接调用的入口

<img src="../bank/2010/q23.png" alt="2010-23" width="412" style="display:block; width:25.75em; max-width:100%; height:auto;">

**新增**：区分“应用的入口”与“内核内部/硬件机制”。**起手**：逐项问“应用用它向内核要服务吗”。→ **A**

| 选项 | 题面依据 |
| --- | --- |
| A 系统调用 | 应用经 trap 请求内核服务的入口，正是题问的“提供给应用程序的接口” ✓ |
| B 中断 | 由外设或异常引起的控制转移，应用不“调用”它 |
| C 库函数 | 运行在用户态的库代码；其中读文件类函数内部才发系统调用，库函数本身不是 OS 内核提供的接口 |
| D 原语 | 内核内部不可被打断的操作序列（如进程控制原语），是内核的实现手段，不是应用的入口 |

<a id="q02"></a>
## 02｜2012-23：发生时 CPU 在哪个态，与处理时在哪个态分开

<img src="../bank/2012/q23.png" alt="2012-23" width="423" style="display:block; width:26.44em; max-width:100%; height:auto;">

**新增**：题问“可能在用户态发生”，只看事件出现那一刻。**起手**：每项写“发生那刻 CPU 在跑谁”。→ **C**

- 系统调用：用户程序自己执行 trap 指令，发生在用户态。
- 外部中断：事件由外设产生（0823-01），用户程序运行时可以到来。
- 缺页：用户指令访问不在内存的页，翻译时发现（0816-04），那刻仍是用户指令。
- 进程切换：保存旧进程现场、选下一个、恢复新现场，是调度程序（内核代码）的动作，不能由用户态执行。

四项的处理程序随后都进内核；若问“处理在哪个态”，则前三项也在内核，题面问的不是这个。

## 03｜2013-25：命令发出前，设备相关参数由驱动算好

<img src="../bank/2013/q25.png" alt="2013-25" style="display:block; width:33.62em; max-width:none; height:auto;">

沿用 0823-05 的“发起向下、完成向上”，题给链条逐段标一句：

```
用户程序          提出读写（只知道文件/逻辑位置）
系统调用处理程序  进内核，分派到设备管理
设备驱动程序      逻辑位置 → 柱面号/磁头号/扇区号，向控制器发命令   ← 新增
中断处理程序      I/O 完成后才运行，收尾
```

**新增**：柱面/磁头/扇区是具体磁盘的参数，必须在发命令前由懂该设备的驱动算出。→ **C**。A 不了解设备；B 只分派；D 在完成之后才运行，赶不上给命令提供参数。

## 04｜2013-28：用户态进内核只有三个入口

<img src="../bank/2013/q28.png" alt="2013-28" width="445" style="display:block; width:27.81em; max-width:100%; height:auto;">

**新增**：进内核的入口＝异常（本指令出错）、系统调用（trap）、中断（外部）。**起手**：逐项问“它是否触发这三者之一”。

| 项 | 判断 |
| --- | --- |
| I 整数除以零 | 本条指令产生的内部异常，进内核 ✓ |
| II sin() 函数调用 | 一次普通函数调用加算术，没有 trap，也没有题给的异常，留在用户态 |
| III read 系统调用 | trap，进内核 ✓ |

→ **B**。信号：“函数调用”本身不进内核，看有没有 trap 或异常。

<a id="q05"></a>
## 05｜2014-25：特权指令＝用户随便执行就会伤到全机

<img src="../bank/2014/q25.png" alt="2014-25" width="443" style="display:block; width:27.69em; max-width:100%; height:auto;">

**新增**：判据“这条指令一旦任何程序都能执行，会不会影响其他程序或整个系统”。

- 跳转、压栈：只改自己的 PC 和栈，普通。
- trap：就是用户态进内核的入口（04），必须允许用户执行。
- **关中断**：用户程序关中断后再死循环，时钟中断进不来，OS 失去控制 → 特权，用户态不能执行。→ **D**

## 06｜2015-23：需要保存的“现场”，是服务程序会改写的程序状态

<img src="../bank/2015/q23.png" alt="2015-23" width="369" style="display:block; width:23.06em; max-width:100%; height:auto;">

**新增**：现场＝被打断程序之后还要用、而服务程序又会改写的状态。沿用 0823-02/07：硬件响应时先存断点。

| 选项 | 依据 |
| --- | --- |
| A PC | 响应时硬件已存断点，不是 OS 存 |
| B 通用寄存器 | 服务程序也要用 GPR，不先存就毁了原程序 → OS 在服务程序里存 ✓ |
| C 块表（TLB） | 访存加速结构，丢了只是重新装入，不影响程序正确性，不属于要保存的程序状态 |
| D Cache | 同上，对程序透明 |

→ **B**。

## 07｜2015-24：“不可能”题——只需为每个排除项找一个合法触发

<img src="../bank/2015/q24.png" alt="2015-24" style="display:block; width:32.76em; max-width:none; height:auto;">

**新增**：用 04 的三个入口，给 A、B、D 各写一个合法触发；剩下找不到的就是答案。题问“可能”，所以不必每次都触发。

```
A DIV R0,R1   R1=0 时除零异常（题未限定 R1≠0）
B INT n       软中断指令，本身就是 trap 类入口
D MOV R0,addr 访问 addr 可能缺页或越界访存
C NOT R0      只在寄存器内取非：无除法、无 trap、无内存访问，找不到触发 → 选 C
```

## 08｜2016-23：批处理不交互；单道/多道是另一维度

<img src="../bank/2016/q23.png" alt="2016-23" width="429" style="display:block; width:26.81em; max-width:100%; height:auto;">

**新增**：批处理＝作业提交后成批运行，用户不在线干预；与之相对的交互属分时系统（课本分类）。

- I 多用户直接交互：与批处理的“成批、不干预”相反 ✗。
- II 分为单道与多道 ✓。
- III 多道时，作业 A 等 I/O，CPU 转去算作业 B；I/O 完成靠中断通知（0823-05）✓。

→ **A**。B 漏 III；C、D 含 I。

## 09｜2017-24：系统调用四步按因果排序

<img src="../bank/2017/q24.png" alt="2017-24" style="display:block; width:30.47em; max-width:none; height:auto;">

**起手**：写一次 `read(fd, buf, n)` 的前后。**新增**：约束只有两条——服务程序是内核代码，必须先进内核（04）；参数要在 trap 前放好，内核入口按约定取。

```
③ 传递参数      用户程序里，放进约定的寄存器/栈
② 执行 trap     进内核
④ 服务程序      内核态
① 返回用户态
```

→ **C**。A：返回在服务之前；B：服务在传参之前；D：服务在 trap 之前，那时还在用户态，没有权限执行。

## 10｜2018-29：一次时钟中断，三个计数同时动

<img src="../bank/2018/q29.png" alt="2018-29" style="display:block; width:29.38em; max-width:none; height:auto;">

**起手**：写“来一个时钟中断，每个量怎么变”。时间片＝一个进程每次连续占用 CPU 的最长时长。

| 量 | 变化 |
| --- | --- |
| I 内核时钟变量 | +1 个滴答 |
| II 当前进程占用 CPU 时间 | +1 个滴答 |
| III 当前进程时间片剩余 | −1 个滴答，减到 0 才触发调度 |

三个都由时钟中断服务程序更新，**D**。III 是递减，同样是“更新”。

## 15｜2021-32：判据——应用主动请求的才是系统调用

<img src="../bank/2021/q32.png" alt="2021-32" style="display:block; width:29.78em; max-width:none; height:auto;">

**新增**：看“为什么进内核”，而不是“最后谁干活”。

| 选项 | 进内核的原因 |
| --- | --- |
| A 页置换 | 缺页异常触发（0816-04），内核自己选页 |
| B 进程调度 | 内核在时间片用完或阻塞时自行决定（10），应用不提“请调度” |
| C 创建新进程 | 应用主动请求（如 fork）→ **系统调用** ✓ |
| D 生成随机整数 | 常规由库函数在用户态计算，不需内核权限 |

D 的读法：若某实现从内核取随机源，则会用系统调用，题取常规读法。

## 16｜2022-24：启动期必须先建好中断入口映射

## 19｜2023-21：设备发请求；结束不是设备发的

<img src="../bank/2023/q21.png" alt="2023-21" width="325" style="display:block; width:20.31em; max-width:100%; height:auto;">

题问**错误**。

| 项 | 判断 |
| --- | --- |
| A 异常 | 在指令执行中检测（除零在运算时，缺页在访存时）✓ |
| B 中断请求 | 在一条指令执行完时检测（0823-17）✓ |
| C 开中断后检测到请求就响应 | 题面把“开中断”作为允许前提，取字面读，不另加屏蔽、NMI 等条件（0823-21），不判错 |
| D 设备经控制器发中断**结束**信号 | 设备发的是中断**请求**；处理结束由服务程序执行中断返回体现，不是设备给 CPU 的信号 ✗ |

→ **D**。

## 22｜2023-26：什么时候“完成”才是回到用户态

<img src="../bank/2023/q26.png" alt="2023-26" style="display:block; width:32.12em; max-width:none; height:auto;">

**起手**：画每项完成时 CPU 所在位置。

- 阻塞进程、唤醒进程、执行 CPU 调度：都是内核函数，完成时仍在内核里；之后运行哪个进程、它上次停在哪段代码，题面没给。例如调度选中的进程，之前可能正停在系统调用内部（阻塞过），则仍在内核态 —— 所以不能断言回用户态。
- **执行系统调用**：服务例程完成后，返回指令回到调用者的用户程序（09 的 ①）→ 内核态转为用户态。→ **D**

## 24｜2025-23：换进程换私有状态，不换系统共用结构

<img src="../bank/2025/q23.png" alt="2025-23" style="display:block; width:30.94em; max-width:none; height:auto;">

**新增**：逐个问“这个寄存器的内容属于某个进程，还是属于整个系统”。题问“不需要更新”。

| 选项 | 判断 |
| --- | --- |
| A 通用寄存器 | 属进程，旧值存起来、装入新值（06）需要换 |
| B 页表基址 | 每个进程有自己的地址空间，同一虚地址对应不同物理页，需要换 |
| C 程序寄存器 | 图上写作“程序寄存器”，按程序计数器理解：要跳到新进程的指令，需要换 |
| D 内核中断向量表基址 | 全系统共用一份内核表（16、21），换进程后入口不变，不需要换 ✓ |

→ **D**。C 的读法：题面没有写成“程序计数器”，若指别的程序状态，同样属进程私有，结论不变。
