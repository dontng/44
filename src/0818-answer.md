## 01｜2009-17：RISC 取向，控制器多用硬连线

<img src="../bank/2009/q17.png" alt="2009-17 原题" width="336" style="display:block; width:21.00em; max-width:100%; height:auto;">

**新增**：控制器产生控制信号的两种做法，及 RISC 取向落在哪一种。**起手**：每项写“说指令集还是控制器”。**答案：A**（题问错误项）

```
硬连线：译码结果经门电路直接输出控制信号     快，改动要改电路
微程序：每条机器指令对应控制存储器里一段微指令，
        逐条取出，每条给一组控制信号            灵活，多一次取微指令
```

指令少而规整，译码逻辑小，硬连线可行；A 说“普遍”采用微程序，方向相反。

| 项 | 说法 | 判断 |
|---|---|---|
| B | 大多数指令一个周期完成 | RISC 的教材特征（操作数多在寄存器）；“大多数”不是“全部” |
| C | 通用寄存器相对 CISC 多 | RISC 的教材特征 |
| D | 指令数、寻址方式、格式种类少 | RISC 的教材特征 |

B、C、D 题面各自就是特征描述，与 RISC 取向一致；只有 A 落在控制器上且方向反。

## 02｜2010-18：汇编程序员“可见”＝指令能指名或语义依赖

<img src="../bank/2010/q18.png" alt="2010-18 原题" width="365" style="display:block; width:22.81em; max-width:100%; height:auto;">

**新增**：可见的判据。**起手**：对每个寄存器问“哪条汇编指令能写它或读它”。**答案：B（PC）**

沿用 0817-01：`PC:2000H→2001H→2002H`，相对转移以取完后的 PC 为基准，转移指令直接改 PC。

| 项 | 有无汇编指令指名/依赖 |
|---|---|
| A MAR、C MDR | 访存时存地址/数据的内部寄存器，指令字段里没有它们的编号 |
| D IR | 存放当前指令供译码，无指令操作数能指名 |
| B PC | 转移、相对寻址的语义依赖它 |

> “可见”不要求有 `MOV PC,…`：转移指令改 PC 已使其可见。

## 03｜2011-18：流水线要每条指令分段一致

<img src="../bank/2011/q18.png" alt="2011-18 原题" width="448" style="display:block; width:28.00em; max-width:100%; height:auto;">

**新增**：流水线把指令切成段（如取指 IF、译码 ID、执行 EX、访存 MEM、写回 WB），每段占一个时钟，**周期由最慢段定**，所以各指令的段数、段时长越一致越好。**起手**：画 5 段，逐项问哪一段会不齐。**答案：D**

```
     c1  c2  c3  c4  c5  c6
I1   IF  ID  EX  MEM WB
I2       IF  ID  EX  MEM WB
```

| 项 | 不满足时哪里不齐 | 满足后 |
|---|---|---|
| I 格式规整、长度一致 | 变长：译码前不知道本条多长，下一条起点推迟 | IF 段固定取一条 |
| II 按边界对齐 | 数据跨两个存储字要两次访存，MEM 段变长 | MEM 一次完成 |
| III 仅 Load/Store 访存 | 算术指令也带访存，段内要“算地址＋取数＋运算”，各指令段数不一 | 其余指令 MEM 空过，每条同样 5 段 |

三项都有利，故不能选缺一项的 A、B、C。“有利”不是“必需”，也不保证无冒险。

## 04｜2015-12：硬件直接执行的是 ISA 位串

<img src="../bank/2015/q12.png" alt="2015-12 原题" width="387" style="display:block; width:24.19em; max-width:100%; height:auto;">

**新增**：取指单元从存储器拿到的只能是机器指令编码（0817 的各字段拼成的位串）。**起手**：问“送到取指单元的是什么”。**答案：A（仅 I）**

| 项 | 取到的是 | 判断 |
|---|---|---|
| I 机器语言程序 | 位串，可译码执行 | 成立 |
| II 汇编语言程序 | 助记符、标号文本，须由汇编器编成位串 | 题问“硬件能直接执行”，文本不行 |
| III 硬件描述语言程序 | 描述电路结构，经综合才成电路，不是 CPU 逐条取的指令 | 不成立 |

汇编助记符常与机器指令一一对应，但标号要换成地址、字段要编码，这步在执行之前。

## 05｜2016-12：翻译工具按输入输出区分

<img src="../bank/2016/q12.png" alt="2016-12 原题" width="450" style="display:block; width:28.13em; max-width:100%; height:auto;">

**新增**：四个工具各自的输入输出。**起手**：写出下表，再看题面“高级语言源程序→目标代码文件”。**答案：C（编译程序）**

| 工具 | 输入 | 输出 |
|---|---|---|
| 编译程序 | 高级语言源程序 | 汇编码或机器级目标代码 |
| 汇编程序 | 汇编语言程序 | 目标代码文件 |
| 链接程序 | 多个目标模块、库 | 可执行文件 |

## 06｜2018-12：二进制的三条理由（无新台阶）

<img src="../bank/2018/q12.png" alt="2018-12 原题" style="display:block; width:29.65em; max-width:none; height:auto;">

无新台阶；三项各属不同层面，逐条核实。**起手**：写 0/1 加法表。**答案：D（I、II、III）**

```
a b | a+b 的和位  进位        和位＝a⊕b，进位＝a∧b
0 0 |  0          0          全加器：和＝a⊕b⊕c，进位＝ab+c(a⊕b)
0 1 |  1          0          （已验证 8 种输入全对）
1 0 |  1          0
1 1 |  0          1
```

- I 规则简单：加、乘表各只有 4 项。
- II 两个稳态：高/低电平对应 0/1，易区分（题面“制造两个稳态的物理器件较容易”）。
- III 门电路做算术：上面几个门即构成加法。

三项分别对应规则、器件、电路，A、B、C 各漏掉一项，都与上面的核实不符。

## 07｜2019-12：存储程序四条，哪一条说“都”

<img src="../bank/2019/q12.png" alt="2019-12 原题" width="433" style="display:block; width:27.06em; max-width:100%; height:auto;">

**新增**：冯·诺依曼“存储程序”：程序功能靠 CPU 执行指令；指令与数据同为二进制；执行前存入存储器；按地址访问。**起手**：对 C 里的“都”找一条反例。**答案：C**（题问错误项）

反例必须是合法指令：任何 ISA 都有从存储器取数的指令，其操作数在 M[EA]，指令里只有形式地址（0817-04），所以数据不是“都在指令中”。

| 项 | 判断 |
|---|---|
| A | 与存储程序一致 |
| B | 存储里二者都是二进制，区别在使用方式：取指用作指令，访存取数用作数据 |
| D | 与“预先存放”一致 |

## 08｜2020-12：机器字长＝一次处理的数据宽度

<img src="../bank/2020/q12.png" alt="2020-12 原题" style="display:block; width:29.22em; max-width:none; height:auto;">

**新增**：机器字长指 CPU 一次处理的整数数据宽度，由 ALU 和通用寄存器体现。**起手**：每个部件问“放/算的是什么”。**答案：B（仅 I、III）**

| 项 | 放/算的 | 能否不等于字长（合法反例） |
|---|---|---|
| I ALU | 整数运算宽度 | 按字长的定义同宽 |
| III 通用寄存器 | 整数数据 | 同宽 |
| II 指令寄存器 | 一条指令 | 64 位机上 32 位定长指令（RV64），指令长≠字长 |
| IV 浮点寄存器 | 浮点数 | 32 位机带双精度浮点，寄存器 64 位 |

题问“一定”，II、IV 各有一个合法反例就不选。

## 09｜2021-17：用 02 的判据再判四个寄存器（无新台阶）

<img src="../bank/2021/q17.png" alt="2021-17 原题" style="display:block; width:36.77em; max-width:none; height:auto;">

无新台阶。**起手**：对四项各问“有无指令指名或语义依赖”。**答案：D（仅 III、IV）**

| 项 | 依据 |
|---|---|
| I 指令寄存器 | 同 02，无指令能指名 |
| II 微指令寄存器 | 微程序控制器内部放当前微指令（01）；硬连线 CPU 根本没有，ISA 不涉及 |

## 10｜2022-18：ISA 与实现的判据

<img src="../bank/2022/q18.png" alt="2022-18 原题" style="display:block; width:26.21em; max-width:none; height:auto;">

**新增**：ISA 是程序/编译器依赖的契约；判据：换掉它，已编译的程序要不要重编、结果变不变。**起手**：逐项问这句。**答案：B（仅 I、III）**

| 项 | 换掉后 | 归属 |
|---|---|---|
| I 指令字格式和类型 | 已有机器码无法译码，须重编 | ISA |
| III 通用寄存器个数和位数 | 指令里寄存器字段位数随个数变（0817-05），程序可用资源变 | ISA |
| II CPU 时钟周期 | 同一程序更快或更慢，结果不变 | 实现 |
| IV 加法器进位方式 | 行波进位与超前进位给出同样的和与 CF，只是延迟和面积不同 | 实现 |

> IV 不是 CF：进位标志是 ADD 的结果语义，属 ISA；“进位方式”指电路怎样传递进位。

## 12｜2024-13：四种“指令”各由谁处理

<img src="../bank/2024/q13.png" alt="2024-13 原题" width="436" style="display:block; width:27.25em; max-width:100%; height:auto;">

**新增**：伪指令按题面定义，是“把汇编程序里实现特定功能的指令序列定义成一条”，由汇编器展开，不进入目标程序的指令集。**起手**：逐项问“谁来处理”。**答案：B（仅 II、III）**

| 项 | 谁处理 | 判断 |
|---|---|---|
| I 伪指令 | 汇编器展开成若干条真指令 | CPU 看不到 |
| II 微指令 | 微程序控制器从控制存储器取出并执行（01） | CPU 内部执行 |
| III 机器指令 | 取指译码执行 | 直接执行 |
| IV 汇编指令 | 助记符文本（04） | 须先汇编 |

> 读法：题面没限定控制器类型。把微程序控制器内部执行的微指令算作“CPU 执行”，才得 II、III（B）；若只算程序可写的指令，答案是“仅 III”，四个选项里没有，故按 B 读。硬连线 CPU 没有微指令，这是题面的含糊处。
