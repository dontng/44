<a id="q01"></a>
## 01｜2009-22：外部中断先找 CPU 之外的事件源

![2009-22 原题](../bank/2009/q22.png)

键盘输入由外设到达，能请求 CPU 在适当指令边界响应**外部中断，选 A**。除数为零、浮点下溢、访存缺页都是当前指令执行过程中发现的内部异常或陷入，不因外设主动发信号而来。第一笔先问事件从哪发生，比只背“中断”“异常”名称更稳。

<details open><summary>缺页为什么不算外设中断</summary>

缺页可能需要随后访问磁盘，但最初发现它的是 CPU/MMU 翻译正在执行的指令地址，属于同步的内部异常；外设完成磁盘 I/O 后再通知 CPU 可产生**另一个**外部中断。把触发点与后续处理用到的设备分开，才不会看到“磁盘”就把缺页分类错。
</details>

<a id="q02"></a>
## 02｜2010-21：单级中断把硬件入口和程序主体排顺序

![2010-21 原题](../bank/2010/q21.png)

单级中断进来先**关中断 III**，防止处理现场时再次嵌套；再**保存断点 IV**，随后**处理中断事件 V**；结束时**恢复现场 VI**，**中断返回 VII**。给定选项对应 **C**。开中断 II 不属于这条单级处理中必须提前插入的步骤；保护通用现场 I 可在服务程序内部进行，但选项的关键骨架是硬件入口与返回。

<details open><summary>断点与通用现场不必是同一个动作</summary>

断点保存下次恢复执行的 PC 等必要控制状态，通常由中断响应硬件先完成；通用寄存器的保存依赖处理程序需要使用哪些寄存器，可由软件完成。题只提供四个序列，先排掉“还没保护现场就开中断”和“处理后才保存断点”，再看 C 的顺序。
</details>

<a id="q03"></a>
## 03｜2011-21：屏蔽字按处理优先级，不按 L 编号

![2011-21 原题](../bank/2011/q21.png)

题给响应优先级从高到低 `L4→L0→L2→L1→L3`。正在处理 L1 时，允许前三个更高优先级打断，故对应屏蔽位 `M4=0,M0=0,M2=0`；屏蔽自身 L1 与低级 L3，`M1=1,M3=1`。按题目要求的 `M4M3M2M1M0` 顺序写成 **`01010`，选 D**。不要把下标顺序错当优先级顺序。

<details open><summary>五个位置逐位核验</summary>

| 位 | M4 | M3 | M2 | M1 | M0 |
| --- | --- | --- | --- | --- | --- |
| 优先级相对 L1 | 高 | 低 | 高 | 本级 | 高 |
| 屏蔽？ | 0 | 1 | 0 | 1 | 0 |

题说 `Mi=1` 表示屏蔽。若把 1 当允许，会得到相反字串；先把该定义抄在纸上，再按高低填值。
</details>

<a id="q04"></a>
## 04｜2011-22：轮询花的周期要除以每秒总周期

![2011-22 原题](../bank/2011/q22.png)

每次查询至少用 500 周期，每秒至少查 200 次，设备 A 至少占 `500×200=100000` CPU 周期/秒。50MHz 每秒有 50,000,000 周期，占比 `100000/50000000=0.002=0.20%`，**选 C**。先写“周期/次 × 次/秒”，再除“周期/秒”，单位自动约掉。

<details open><summary>轮询频率与程序执行时间为何同时出现</summary>

为保证数据不丢，CPU 必须每秒投入最少 200 次查询，哪怕设备尚未需要 CPU 做实际数据处理，也付出读状态的开销。若查询程序再复杂或查得更频繁，占比只会更大，所以题问“至少”。把 0.002 换百分数需乘 100，得到 0.2%，不是 0.002%。
</details>

<a id="q05"></a>
## 05｜2011-26：发起磁盘请求与完成通知是两次方向相反的交接

![2011-26 原题](../bank/2011/q26.png)

用户程序提出磁盘 I/O，先进入**系统调用处理程序**，再由**设备驱动程序**设置控制器、发起具体设备操作；磁盘完成后以中断通知 CPU，进入**中断处理程序**，顺序 **用户→系统调用→驱动→中断，选 B**。不能让用户代码直接先执行内核驱动，也不能在设备启动前先处理“完成中断”。

<details open><summary>两个方向从同一条时间线区分</summary>

向设备发请求：用户态陷入内核的系统调用，内核检查参数、找驱动，驱动下命令；从设备回来：设备完成并发中断，内核处理完成状态，再唤醒/返回相应进程。题里的四个程序名字分别占这几个位置，先画“发起→运行→完成”就能裁决。
</details>

<a id="q06"></a>
## 06｜2012-21：命令字、状态字、类型号都是总线数据载荷

![2012-21 原题](../bank/2012/q21.png)

I/O 总线的数据线可以传接口命令字、读回的状态字以及中断类型号这些**数值**，故 I、II、III 都成立，**选 D**。承接 0822-04：握手/应答**信号**是控制线上的时序信息，不能因“命令字”也叫命令就把编码后的数值误当同一种控制线电平。

<details open><summary>值与信号的分界</summary>

CPU 要写一个具体的 I/O 命令码，数据线承载码值，控制线同时表明这是写操作；读状态字时数据线返回状态位组合，控制线表明读取时刻；中断类型号也是一个可传递的数值。线的分类由其承载内容的角色决定，不靠中文里是否出现“命令/中断”。
</details>

<a id="q07"></a>
## 07｜2012-22：隐指令做必需入口，不替服务程序保存所有寄存器

![2012-22 原题](../bank/2012/q22.png)

中断响应硬件的隐指令在入口要关中断 I、保存断点，并取中断服务程序入口地址送入 PC III。**保存通用寄存器内容 II**属于服务程序按需保护现场的工作，不由该隐指令一概完成。所以 **仅 I、III，选 B**。与 02 的顺序题合在一起看：先有可靠入口，再由软件处理详细现场。

<details open><summary>为何不能因“保护现场”四个字全选</summary>

返回地址/状态必须及时保护，否则无法回原程序；但通用寄存器有许多，哪几个会被服务程序改写取决于程序约定与具体处理代码。若把全部 GPR 无条件压入隐指令，题里 II 的软件/硬件责任就被抹平。先区分**断点**与**一般寄存器现场**。
</details>

<a id="q08"></a>
## 08｜2013-19：外设与控制器的接口，选 USB

![2013-19 原题](../bank/2013/q19.png)

题目问“设备和设备控制器（I/O 接口）之间”互连。USB 可连接外设与主机侧控制器，**选 B**。PCI、AGP、PCI Express 在这组比较中更多处于主机内部部件/控制器与系统互连的一侧；先画“CPU/内存—控制器—外设”三段，再看题指定的是哪一段。

<details open><summary>为何 PCIe 也可能接外设却不是本题裁决</summary>

现实中很多设备控制器本身通过 PCIe 接到主机，但题问设备**与其控制器之间**的外设接口，典型 USB 在控制器外侧。只背“PCIe 可连接设备”而不找控制器在链路哪端，容易把内外两层接口混在一起。
</details>

<a id="q09"></a>
## 09｜2013-22：中断要 CPU 时间，DMA 主要要总线使用权

![2013-22 原题](../bank/2013/q22.png)

中断 I/O 请求 CPU 执行服务程序；DMA 搬运数据时请求总线使用权，A 对。中断在指令边界响应，DMA 在当前总线事务完成后争用总线；数据通过中断服务程序/硬件 DMA 控制器搬运，B、C 为本题常用模型。D 用“中断适用于**所有**外设、DMA **仅**适用于快速外设”做绝对限制，未由机制推出，故 **错误选 D**。

<details open><summary>“适合大量高速数据”不是“只能”</summary>

DMA 设置有启动成本，连续大块、高速设备通常更能摊薄成本，所以常说适合高速设备；但慢设备如需减少 CPU 逐字搬运，也可设计 DMA，关键在控制器、事务量和收益。中断方式也不应把所有设备的控制需求不加判断地一概归入。抓 D 的“所有/仅”并要求机制证据。
</details>

<a id="q10"></a>
## 10｜2014-21：统一编址的 I/O 端口可以用访存指令

![2014-21 原题](../bank/2014/q21.png)

状态端口和控制端口可以共用寄存器；CPU 可访问的接口寄存器称 I/O 端口。独立编址时，I/O 端口和主存可有相同数字地址，由不同地址空间区分；**统一编址**则把 I/O 端口映进主存地址空间，CPU 可用访存指令读写它，D 的“不能”错误，**选 D**。

<details open><summary>两种编址的最便宜区分</summary>

独立编址：有独立 I/O 地址空间和专用 I/O 指令，数值相同的地址在不同空间可各指一处。统一编址：端口占用主存地址空间中的一段，普通 load/store 等访存动作可访问。题干的“统一”提示的是指令路径相通，不是禁止访存。
</details>

<a id="q11"></a>
## 11｜2014-22：每 400ns 一次请求，占用 100ns

![2014-22 原题](../bank/2014/q22.png)

每 400ns 来一个中断请求，每次 CPU 响应并处理用 100ns；持续工作时占比最少 `100/400=25%`，**选 B**。允许最大响应延迟 50ns 是必须及时开始响应的约束，不是每次处理要额外再加 50ns，也不能以它替代实际 100ns 处理成本。

<details open><summary>与 04 的轮询成本比较</summary>

04 每次定时查询都花 500 周期，不管设备有无新数据；本题请求到来才花中断处理时间。若处理 100ns 长于请求间隔 400ns，持续处理会积压；这里 100<400，可用每一段 400ns 内的处理份额直接计算。最多延迟 50ns 只约束调度及时性，不改变平均处理量。
</details>

<a id="q12"></a>
## 12｜2015-21：打印控制器端口不必接收主存地址

![2015-21 原题](../bank/2015/q21.png)

中断 I/O 打印时，CPU 可把打印字符写到接口数据端口、读设备状态、下控制命令；这三类都与端口交换。**主存地址**不需要作为打印端口的交换内容，**选 B**。DMA 控制器才要知道从/往哪一片主存搬数据，别把它的地址参数挪到逐字中断打印流程。

<details open><summary>先问这份信息由谁使用</summary>

打印字符供打印机消费；状态位让 CPU 判定设备是否就绪；控制命令使接口启动/复位等。主存地址是 CPU/内存系统定位内存的值，普通端口传输时 CPU 自己先从内存取到字符，再把字符写端口，接口不必知道字符原来放哪。
</details>

<a id="q13"></a>
## 13｜2015-22：不是每种内部异常都返回原指令续做

![2015-22 原题](../bank/2015/q22.png)

内部异常与当前指令相关、由内部逻辑检测，可在指令执行过程中响应，A/B/C 正确。D 断言**处理后都回到发生异常的指令继续**错误：故障 fault 如缺页可重试原指令，陷阱 trap 如系统调用通常从下一条继续，终止 abort 可能无法恢复，**选 D**。第一笔看题干列出的三种类别，本身就提示返回位置不能统一。

<details open><summary>三类异常的最小区别</summary>

故障在指令完成前发现，处理后若条件已修复可重试；陷阱常在特定指令执行后把控制交给系统，返回时继续后续流程；终止意味着严重问题不能正常重试。具体架构细节可能不同，考试上足以用一个反例推翻 D 的“都”。
</details>

<a id="q14"></a>
## 14｜2016-22：缺页是内部异常，DMA 完成是外部中断

![2016-22 原题](../bank/2016/q22.png)

题目已把执行中内部特殊事件叫异常，把外部请求叫中断。访存缺页由当前指令地址翻译发现，是**异常**；除零、存储保护错也是异常；DMA 传送结束由设备/控制器通知 CPU，是外部**中断**。A 说“缺页属于中断”错误，**选 A**。承接 01，发生后用磁盘处理不改变最初检测来源。

<details open><summary>同一 I/O 任务可能连续触发两类事件</summary>

进程访问缺页，CPU/MMU 先触发异常；内核调页时发起磁盘 I/O；磁盘完成又触发设备中断。不能因时间链上后来有设备中断，就倒推前面的缺页也是外部中断。分类按**事件产生点**，不是按最终由哪个设备帮忙。
</details>

<a id="q15"></a>
## 15｜2017-21：I/O 指令在寄存器与接口端口间传数据

![2017-21 原题](../bank/2017/q21.png)

CPU 执行 I/O 指令时，典型数据路径是**通用寄存器 ↔ I/O 接口内的端口**，**选 D**。外设与端口之间的传输发生在接口的设备侧；CPU 指令并不直接穿过接口去操作设备物理引脚。两个 I/O 端口之间也不是普通 I/O 指令的默认数据传输路径。

<details open><summary>画三段防混</summary>

`CPU 寄存器 ↔ I/O 端口 ↔ 外部设备`。题问的是“**I/O 指令实现**的数据传送”，对应左半段；设备控制器根据协议再与设备交换，是右半段。某些体系结构也可经内存映射执行 load/store，但处理器可见的接口端口仍是左侧的交接对象。
</details>

<a id="q16"></a>
## 16｜2017-22：多重中断允许高优先级打断处理中断

![2017-22 原题](../bank/2017/q22.png)

外部中断在指令结束边界响应，与正在执行的那条指令通常无关，CPU 采样请求线发现它。B 说“**中断处理期间 CPU 处于关中断状态**”一概而论，和**多重中断系统**不符：保存好必要现场后可重新开中断，让更高优先级请求嵌套，故 **错误选 B**。初入中断短暂关中断与整个处理期间永远关中断不是同一句话。

<details open><summary>把 02、03 的两步连起来</summary>

02 的入口先关中断，防止现场尚未保护就嵌套；03 的屏蔽字允许更高优先级、屏蔽本级及低级。保护完成后可依屏蔽字开放特定中断，于是高优先级服务程序能打断当前服务程序。多重中断的“多”就体现在这条时间线上。
</details>

<a id="q17"></a>
## 17｜2018-22：只有允许响应，CPU 才能接外设请求

![2018-22 原题](../bank/2018/q22.png)

中断控制器按优先级仲裁，不按请求到达先后简单 FIFO；隐指令保存断点等控制状态，GPR 由服务程序按需保护；外部中断通常待当前指令结束再响应。CPU 必须处于**中断允许状态**才能响应外设中断，**选 C**。这不是说请求在关中断时物理上不出现，而是 CPU 暂不转入服务。

<details open><summary>请求、响应、处理是三个时刻</summary>

设备可以先提出请求；CPU 在允许且达到可响应边界时取该请求并完成隐指令；服务程序之后处理具体事件。D 用“立即暂停当前指令”跳过边界，B 把硬件断点保存和软件通用寄存器保护混为一体。先给动词定位时刻，选项就易分开。
</details>

<a id="q18"></a>
## 18｜2019-21：中断 CPU 占用按每秒缓冲次数算

![2019-21 原题](../bank/2019/q21.png)

接口数据缓冲 32 位=4B，每秒 50kB 数据需要最多 `50,000/4=12,500` 次中断；一次含响应、处理用 1000 周期，合计 `12.5×10⁶` 周期/秒。1GHz 每秒 `10⁹` 周期，占比 `12.5M/1000M=1.25%`，**选 A**。题问“最多”，按每份缓冲都触发一次中断估算。

<details open><summary>为何不能把 50kB 直接乘 1000</summary>

中断开销按**次数**计，接口一次可缓冲 4B，要先把字节率除以每次数据量。若只按 50kB/s 当 50,000 次中断，会高估四倍。`kB` 取 1000 还是 1024，对本题选项的近似结论无影响。
</details>

<a id="q19"></a>
## 19｜2019-22：DMA 四步各有不同执行者

![2019-22 原题](../bank/2019/q22.png)

驱动程序先给 DMA 控制器设置主存地址、方向、数量等参数（I）；传送前 DMA 控制器请求总线使用权（II）；搬运中它直接控制总线读写（III）；结束后发中断，CPU 的中断服务程序做收尾（IV）。四项均正确，**选 D**。DMA 的“CPU 不逐字搬”不等于 CPU 从头到尾完全不参与。

<details open><summary>把“软件设置”和“硬件搬运”切开</summary>

启动阶段由内核/驱动准备，数据阶段由 DMA 硬件从设备接口与主存间搬运，完成阶段再由中断处理程序确认状态并通知等待者。若把 II 的总线请求归给 CPU，会误认数据阶段仍由 CPU 执行普通 load/store；若把 IV 删除，又会漏掉完成通知。
</details>

<a id="q20"></a>
## 20｜2020-20：定时器与网包到达是外部请求

![2020-20 原题](../bank/2020/q20.png)

I 访存缺页由当前执行指令触发内部异常；II 定时器到时和 III 网络数据包到达均由处理器外的设备/控制器请求服务，是**外部中断**。故仅 II、III，**选 C**。这一题把 01 的键盘、14 的 DMA 完成再扩成时钟和网络两种设备来源。

<details open><summary>定时器通常在芯片里，为什么仍叫外部中断</summary>

“外部”按相对于**当前指令执行逻辑**分类，定时器到期并非这条指令算出的同步结果；即使计时硬件集成在同一芯片内，也由独立计时源异步提出请求。缺页则与正在翻译的访存指令一一对应，处理后通常要重试该指令。
</details>

## 11—20 收束

同样的 CPU 时间占比，轮询按定期查询次数算，中断按实际数据缓冲/请求次数算。中断入口先硬件保住最小控制现场，软件再保存所需寄存器；多重中断可在安全时重新允许高优先级。DMA 把每份数据的搬运交给硬件，但启动与结束仍有驱动和中断参与。

<a id="q21"></a>
## 21｜2020-21：可屏蔽请求出现，不等于 CPU 立刻响应

![2020-21 原题](../bank/2020/q21.png)

NMI 不受一般中断允许位屏蔽，优先级高于可屏蔽中断；可屏蔽请求还能受屏蔽字影响。B 却说一旦可屏蔽请求信号有效，CPU“**立即响应**”，漏掉中断允许、优先级以及当前指令结束边界，故 **错误选 B**。抓“请求”与“响应”之间仍有条件和时刻。

<details open><summary>三道题共享的时间线</summary>

设备提出请求，可暂时保持/等待；CPU 在可响应边界采样，若中断允许且未屏蔽，再由优先级逻辑决定是否转服务程序。NMI 可越过通常的总开关，但也不意味着在一条指令中间随意破坏精确执行点。17 的“只有允许才响应”对应可屏蔽请求，不能不加限定套到 NMI。
</details>

<a id="q22"></a>
## 22｜2020-22：周期挪用只在某个总线周期让 CPU

![2020-22 原题](../bank/2020/q22.png)

512B 数据块，接口缓冲一次 32 位=4B，DMA 每准备好 4B 就争取一次总线；在 DMA 获得总线的**那一周期**，CPU 不能同时用它访问主存。C 扩成“**整个数据块传送过程中 CPU 都不能访问主存**”错误，周期挪用让 CPU 在其他空闲总线周期继续工作，**选 C**。结束仍发 DMA 完成中断。

<details open><summary>周期挪用与整块独占的区别</summary>

512B 分成 `512/4=128` 份，每份到来时 DMA 请求一个可用的总线周期，间隙总线可回给 CPU。若真整块期间独占，便把“每准备好 32 位发一次请求”与“周期挪用”这两个条件浪费了。DMA 优先取得已请求的总线周期，并非从开始到结束永久拥有总线。
</details>

<a id="q23"></a>
## 23｜2021-20：可编程中断控制器管理请求，不是设备 I/O 端口

![2021-20 原题](../bank/2021/q20.png)

磁盘驱动器、打印机适配器、网络控制器都在设备与主机之间完成数据/控制转换，可作 I/O 接口。可编程中断控制器主要负责**汇集、屏蔽与仲裁中断请求**，并非某个 I/O 设备的数据接口，故 **选 D**。不要因为它也连接 CPU、可能有可编程寄存器，就把所有控制器都归入设备接口。

<details open><summary>控制器“控制谁”是裁决点</summary>

网络控制器收发网络数据帧，磁盘/打印接口面对具体数据设备；中断控制器处理的是来自各种设备的请求线和优先级，让 CPU 知道应响应哪个来源。它服务于中断机制整体，而不提供某种外设的数据传送路径。
</details>

<a id="q24"></a>
## 24｜2021-21：修好缺页后，原访存指令还没有完成

![2021-21 原题](../bank/2021/q21.png)

题先给异常在当前指令执行中检测、外部中断在执行后检测。缺页在访存指令完成前发生，处理程序把缺页调入主存后，**必须重启这条访存指令，选 B**。系统调用 trap 一般按返回约定走下一条，DMA 完成与缺纸是外部通知，不要求把当前指令倒回重做。

<details open><summary>“返回哪一条”用已完成工作判</summary>

若 CPU 已完成一条指令，再响应异步设备中断，返回应接着做后续指令；若当前指令因缺页连目标数据都尚未读到，就不能假装完成。0816-04 已讲这一故障恢复，本题要求把它与系统调用及外部中断并排裁决。
</details>

<a id="q25"></a>
## 25｜2021-22：中断响应不要求先退出内核态

![2021-22 原题](../bank/2021/q22.png)

A 说“**仅在用户态**，CPU 才能检测和响应中断”，错误：内核态执行期间若中断允许、达到边界且优先级符合条件，同样可响应外设请求，**选 A**。用户态/内核态是程序权限，开/关中断与屏蔽是另一个维度；不能把“内核代码”自动等于“永不受中断打断”。

<details open><summary>两维状态交叉检查</summary>

内核态可以临时关中断保护关键区，也可以开中断允许更高优先级嵌套；用户态也可能在某些关键时刻因硬件状态暂不响应。题问多重中断，若内核服务程序绝不能响应中断，就无法形成高级请求打断当前服务程序的嵌套。先查中断允许和屏蔽，再看权限状态的作用。
</details>

<a id="q26"></a>
## 26｜2022-21：中断处理要赶在下一份数据覆盖缓冲前

![2022-21 原题](../bank/2022/q21.png)

字符型键盘、针式打印机常适合中断 I/O；数据由 CPU 执行中断服务程序搬运；设备工作时 CPU 可调度其他进程。C 声称“外设准备数据的时间应**小于**中断处理时间”是倒置的：若外设比 CPU 处理还快，新数据可能不断到来并覆盖/挤满缓冲，故 **错误选 C**。

<details open><summary>比较的是生产间隔和消费时间</summary>

单缓冲且无其他吸收机制时，设备两份数据之间的准备间隔应足够长，让 CPU 响应并处理前一份；较慢字符设备正适合这条路径。若是 SSD/网卡等高速连续数据，逐份中断使 CPU 负担过高，DMA 与缓冲批量处理更合理。不能把“时间越短越高效”不分对象套到设备准备时间。
</details>

<a id="q27"></a>
## 27｜2023-22：DMA 数据阶段不跑“CPU 的 DMA 传送程序”

![2023-22 原题](../bank/2023/q22.png)

查询由 CPU 跑查询程序，普通中断 I/O 由 CPU 跑服务程序，高速 SSD/网络适合 DMA。C 说 DMA 方式由 CPU 执行“DMA 传送程序”来逐份完成 I/O，违背 DMA 的关键：**驱动设好参数后，控制器硬件搬运数据**，故 **错误选 C**。CPU 可在传送完成时再处理一个中断。

<details open><summary>先后参与不等于全程搬运</summary>

启动：CPU/驱动配置地址、长度、方向；中间：DMA 控制器争总线，从设备接口到主存（或反向）搬块；结束：中断通知 CPU 收尾。若把中间改成 CPU 逐字执行程序，已退回程序查询/中断搬运的模式，DMA 的意义就消失了。
</details>

<a id="q28"></a>
## 28｜2024-21：屏蔽字改嵌套优先级，不改硬件响应优先级

![2024-21 原题](../bank/2024/q21.png)

题问错误。响应阶段的优先级由中断控制器/硬件仲裁决定；处理期间，软件可保存 GPR、设置新的屏蔽字，决定哪些级别允许**嵌套打断当前服务**；单重方式处理时保持关中断。A 把屏蔽字说成“确定**中断响应的优先级**”，混淆响应优先级与处理时的屏蔽/嵌套优先级，**选 A**。

<details open><summary>用 03 的 L1 屏蔽字检验</summary>

L1 处理程序设置 `01010` 让 L4、L0、L2 可嵌套，屏蔽 L1、L3；这没有把原来硬件认定的请求响应次序 `L4→L0→L2→L1→L3` 重新接线。屏蔽影响的是“此时哪些请求可以进入处理”，不等于改变请求线的固有仲裁排序。
</details>

<a id="q29"></a>
## 29｜2024-22：DMA 控制的数据通路跨设备接口与主存

![2024-22 原题](../bank/2024/q22.png)

题指定 DMA 控制器负责 I/O，数据并不先进入 CPU 通用寄存器。实际搬运路径在**设备接口和主存之间，选 C**。DMA 控制器提供地址、计数、方向及总线控制，数据可经总线在两端交换；“控制器在场”不意味着它把数据停在 CPU 与 DMA 控制器之间。

<details open><summary>画出路径而不是只记“绕过 CPU”</summary>

`设备 ↔ 设备接口 ↔ 总线 ↔ 主存`，DMA 控制器在这条路径上决定读/写时机、地址及长度；CPU 主要在开始设参与结束响应。D 的“设备接口与 DMA 控制器之间”只截取控制关系或局部连接，不是题问的整条数据传输通路。
</details>

<a id="q30"></a>
## 30｜2025-21：批量高速设备更能摊薄 DMA 启动成本

![2025-21 原题](../bank/2025/q21.png)

网卡与固态硬盘可连续传较大量数据，适合 DMA 批量搬运，**II、III，选 B**。键盘与针式打印机通常逐字符、低速，可由中断 I/O 满足；为了几个字节就配置 DMA，启动/结束成本不划算。这里问“适合”，不是断言慢设备物理上绝不能接 DMA，与 09 的“仅适用于”错误不矛盾。

<details open><summary>用收益而非设备名字记忆</summary>

若传一块数据，CPU 逐字搬需持续指令和中断；DMA 先付配置成本，再由硬件搬整个块，块越大/越快越划算。低速偶发字符只让 CPU 在准备好时响应一次即可。选择网卡、SSD 是它们的典型负载形态，真实系统仍取决于控制器能力与具体工作量。
</details>

<a id="q31"></a>
## 31｜2025-22：DMA 完成通知是外部中断请求

![2025-22 原题](../bank/2025/q22.png)

DMA 传输完成由控制器主动向 CPU 报告，属于**外部中断请求，选 A**。总线事务结束只是数据传输阶段的一个时序边界，不必每次都让 CPU 进中断；页故障处理结束是内部异常的恢复过程；断点指令执行会引起内部陷阱。按**谁发起给 CPU 的请求**裁决，别只见“结束”二字就归一类。

<details open><summary>把 19 的第四步补上</summary>

驱动设参、DMA 硬件争总线并搬运，整个数据块完成后才由控制器发中断，让 CPU 做收尾、唤醒等待者。若 128 次周期挪用每次都算 CPU 中断，就重新产生大量处理开销，违背 DMA 批量化目的。
</details>

## 0823 收束｜三条路径分清执行者

轮询：CPU 按计划查状态、逐份搬；中断 I/O：设备就绪通知，CPU 执行服务程序搬；DMA：CPU 设参，DMA 控制器占用若干总线周期搬数据，完成后通知 CPU。异常则由当前指令执行发现，需按 fault/trap/abort 判断返回位置。考场只需先写“请求者、搬运者、完成通知”三项，再选最短计算或排错路径；教学完成不等于限时独立熟练。
