## 01｜栈和队列只差“取出哪一个”

<img src="../bank/2009/q01.png" alt="2009-01 原题" width="504" style="display:block; width:31.50em; max-width:100%; height:auto;">

> **新增**：存放的数据结构按**取出顺序**区分：队列取最早放入的，栈取最近放入的
> **起手**：写 `A入 → B入`，再问先取出谁　→　**答案 B**

题干两句话各给一个条件：

- “依次写入”：主机按产生顺序放入。
- “依次取出”：打印机按这个顺序取走，先写入的先打印。

```text
放入：A, B, C          取出：A, B, C      先进先出 → 队列
若取最近放入的：       取出：C, B, A      后进先出 → 栈
```

打印次序必须和任务到达次序相同，所以选 **B**。树、图靠分支或连线表示关系，题面没有这类关系。

“速度不匹配”只说明为什么要缓冲，不决定结构。看到“缓冲”就选栈，是把暂存当成了顺序要求。

## 02｜最小容量：同一时刻栈里最多留几个

<img src="../bank/2009/q02.png" alt="2009-02 原题" width="502" style="display:block; width:31.38em; max-width:100%; height:auto;">

> **沿用**：01 的“取出顺序”
> **新增**：栈的 push / pop；容量要不小于**任一时刻的栈内元素数**
> **起手**：把出队序列翻成 push/pop 逐步写栈　→　**答案 C**

出栈的元素立刻进队，队列照原样保存，所以**出栈顺序就是 `b,d,c,f,e,a,g`**。队列不用再模拟。

输入固定为 `a,b,c,…`。要出的目标不在栈顶，就继续压入，直到压到它：

```text
目标 b：压 a,b       [a,b]    高 2   弹 b → [a]
目标 d：压 c,d       [a,c,d]  高 3   弹 d → [a,c]
目标 c：             弹 c → [a]
目标 f：压 e,f       [a,e,f]  高 3   弹 f → [a,e]
目标 e：             弹 e → [a]
目标 a：             弹 a → []
目标 g：压 g，弹 g
```

整个过程最高是 3，所以容量 3 够用。

**为什么 2 不行**：`b` 弹出后 `a` 要留到最后才出；`c` 要晚于 `d` 弹出，却比 `d` 先到，所以压 `d` 时 `a,c,d` 同时在栈里。下界 3 与上面的构造相等，才能说“最小是 3”。

| 选项 | 判断 |
|---|---|
| A 1、B 2 | 低于下界 3 |
| **C** 3 | 下界 = 构造 |
| D 4 | 够用，但不是最小 |

## 03｜给出的序列行不行：每次目标不在栈顶就压入

<img src="../bank/2010/q01.png" alt="2010-01 原题" width="493" style="display:block; width:30.81em; max-width:100%; height:auto;">

> **沿用**：02 的目标驱动写栈
> **新增**：题目额外限制“连续 Pop 不超过 2 次”，所以要数**两次压入之间弹了几个**
> **起手**：对每个候选逐个目标写栈　→　**答案 D**

规则：下一个目标在栈顶就弹；不在，就压入后续输入直到它。目标在栈顶时没有别的选择，压别的只会把它盖住，所以**连续弹几个是被序列决定的**。

```text
A dcebfa  压abcd 弹d c | 压e 弹e b | 压f 弹f a     最长连弹 2 ✓
B cbdaef  压abc  弹c b | 压d 弹d a | 压e 弹e | 压f 弹f   2 ✓
C bcaefd  压ab 弹b | 压c 弹c a | 压de 弹e | 压f 弹f d     2 ✓
D afedcb  压a 弹a | 压bcdef 弹 f e d c b                  连弹 5 ✗
```

D 在 `f` 之后，`e,d,c,b` 都已在栈里，依次紧挨着弹出，找不到可以插入压入的位置。所以“不可能得到的”是 **D**。

> 只看序列“像不像栈序列”会漏掉这一条。本题的信号是：连续几个目标都已在栈内且依次是栈顶，就是一次长连弹。

## 04｜两端都能入队：结果是“先降后升”的形状

<img src="../bank/2010/q02.png" alt="2010-02 原题" width="493" style="display:block; width:30.81em; max-width:100%; height:auto;">

> **新增**：新元素只能放在当前序列的左端或右端；这决定最终序列的形状
> **起手**：把 `a..e` 记成 1..5，一步步在纸上放　→　**答案 C**

先放 1（`a`）。以后每来一个，放左端或右端：

```text
1                   a
2 放左     21        b a
3 放右     213       b a c
4 放左     4213      d b a c
5 放右     42135     d b a c e
```

最终序列里：放在左边的元素，越晚来越靠左；放在右边的，越晚来越靠右；`a` 在中间。所以把序号写出来，是**先递减到 1，再递增**。出队端在哪一头都一样，反过来读仍是这个形状。

| 选项 | 序号 | 形状 |
|---|---|---|
| A `bacde` | 2 1 3 4 5 | ✓ |
| B `dbace` | 4 2 1 3 5 | ✓（上面的例子） |
| **C** `dbcae` | 4 2 3 1 5 | ✗ 先降到 2，又升到 3，再降到 1 |
| D `ecbad` | 5 3 2 1 4 | ✓ |

C 里的 `c` 在 `b` 与 `a` 之间，而 `c` 是 `b` 之后才来的，只能放两端，进不去中间。选 **C**。

## 05｜`d` 先出：旧栈被锁死，`e` 只能插进缝隙

<img src="../bank/2011/q02.png" alt="2011-02 原题" width="535" style="display:block; width:33.44em; max-width:100%; height:auto;">

> **沿用**：02/03 的目标驱动写栈
> **新增**：首个输出固定后，栈里剩下的先后被锁死；还没到的元素按位置计数
> **起手**：写 `d` 弹出时栈里是什么，哪个元素没来　→　**答案 B**

首个弹出的是 `d`，说明 `a,b,c,d` 已压入，**`e` 还没压**（压了就盖住 `d`）。`d` 弹出后：

```text
栈（底→顶）：a b c      未到：e
```

`c,b,a` 的出栈次序已锁死。`e` 只能在某个时刻压入并立刻弹出，位置是 `c,b,a` 前后与之间的缝隙：

```text
_ c _ b _ a _        四个空位 → 4 种
e c b a   c e b a   c b e a   c b a e
```

`e` 压在栈顶后不立刻弹，就必须在 `c` 之前弹出，仍是上面的某一种。选 **B，4**。

数成 3 或 5，是把三个元素之间的缝隙数错了：三个元素有 4 个缝隙（前、中间两个、后）。

## 06｜循环队列初值：由“非空时的指向”倒推

<img src="../bank/2011/q03.png" alt="2011-03 原题" width="536" style="display:block; width:33.50em; max-width:100%; height:auto;">

> **沿用**：0801-02 的“先读指针指元素还是指空位”
> **新增**：入队是“先把 `rear` 推进一格，再写入”；用首次入队之后的状态倒推初值
> **起手**：写第一个元素入队后 `front`、`rear` 的值　→　**答案 B**

题给：非空时 `front` 指队头元素，`rear` 指**队尾元素**；第一个元素写在 `A[0]`。

```text
首个元素入队后：front = 0，rear = 0     （只有一个元素，头尾同一格）
入队动作：rear 先加 1（取模 n），再写入
所以入队前：rear = n−1，front 不动，仍为 0
```

初值 `(0, n−1)`，选 **B**。

| 选项 | 问题 |
|---|---|
| A `0,0` | `rear` 先加 1 就写到 `A[1]` |
| C `n−1,0` | `front` 应指首元素 `A[0]`，不是 `n−1` |
| D `n−1,n−1` | 同 C，`front` 不对 |

这和 0801-02 的 `end2` 指**尾后空位**不同。题目换了指向，推出的初值就不同，不要套另一题的公式。

## 07｜中缀转后缀：栈里放“还不能确定的运算符”

<img src="../bank/2012/q02.png" alt="2012-02 原题" width="437" style="display:block; width:27.31em; max-width:100%; height:auto;">

> **沿用**：02 的“栈最高时有几个”
> **新增**：扫描规则——决定哪些符号弹出、哪些留下
> **起手**：按规则逐个符号写栈　→　**答案 A**

题目已给后缀结果，那不是要数的东西。要数的是转换过程中栈的**峰值**。扫描规则：

- 操作数：直接输出，不进栈。
- `(`：压入。
- 运算符：把栈顶**优先级不低于它**的运算符先弹出（顶是 `(` 就停），再压入它。`*`、`/` 高于 `+`、`-`。
- `)`：弹出直到 `(`，把这个 `(` 丢掉。

扫描 `a+b-a*((c+d)/e-f)+g`，栈自底向顶：

```text
+          [+]
-          弹 +，[-]
*          [-,*]
(  (       [-,*,(,(]
+          [-,*,(,(,+]       ← 5 个，峰值
)          弹 +、(，[-,*,(]
/          顶是 (，[-,*,(,/]      4
-          弹 /，[-,*,(,-]       4
)          弹 -、(，[-,*]
+          弹 *、-，[+]
```

峰值 5，选 **A**。

B 7 是全部运算符个数，D 11 是运算符加括号的总数，都等于假设没有任何符号被弹出。C 8 也没有任何一刻达到。

## 08｜`p₂=3`：用构造法数 `p₃` 能取几个值

<img src="../bank/2013/q02.png" alt="2013-02 原题" width="539" style="display:block; width:33.69em; max-width:100%; height:auto;">

> **沿用**：05 的“已入栈的锁死，未到的插缝”
> **新增**：求“可能取值”时，逐个值给出构造，并说明哪个值一定不行
> **起手**：先问 `3` 弹出前，栈里已经有什么　→　**答案 C**

`p₂=3`，说明 `3` 已入栈，所以 `1,2` 也已压入。`p₁` 有三种情形：

| `p₁` | 操作 | 弹出 3 之后栈里 | `p₃` 可以是 |
|---|---|---|---|
| 1 | 压 1 弹 1，压 2、3，弹 3 | `2` | 2，或继续压 `4…k` 弹 `k` |
| 2 | 压 1、2 弹 2，压 3 弹 3 | `1` | 1，或 `k≥4` |
| 4 | 压 1、2、3、4，弹 4、弹 3 | `1,2`（顶 2） | 2，或 `k≥5` |

汇总：`p₃` 可取 `1`、`2`、`4,5,…,n`。`3` 已用过，不可能再取。其余每个值上面都有构造，所以共 `2 + (n−3) = n−1` 个，选 **C**。

核对：`n=3` 时 `p₃` 只能是 1 或 2，共 2 个 = `n−1`；`n=4` 时是 1、2、4，共 3 个。

若只考虑 `p₁` 是 1 或 2，会漏掉 `p₁=4`，但 `p₃` 的取值集合不变。B `n−2` 比上面能构造出的取值少一个；A `n−3` 少两个；本题 `n≥3` 已给定，D“无法确定”不成立。

## 09｜扫到 `f` 就停：看那一刻的栈

<img src="../bank/2014/q02.png" alt="2014-02 原题" width="515" style="display:block; width:32.19em; max-width:100%; height:auto;">

> **沿用**：07 的扫描规则
> **新增**：题目问的是扫描到某个符号的**那一刻**，不是整个转换结束
> **起手**：用 07 的规则，扫到 `f` 就停　→　**答案 B**

`a/b+(c*d-e*f)/g`，栈自底向顶：

```text
/         [/]
+         弹 /，[+]
(         [+,(]
*         [+,(,*]
-         弹 *，顶是 (，[+,(,-]
*         [+,(,-,*]
f         读到 f：停
```

此刻栈内依次是 `+ ( - *`，选 **B**。后面的 `)`、`/g` 还没读到，不能提前处理。

| 选项 | 违反的规则 |
|---|---|
| A `+ ( * −` | `-` 来时 `*` 优先级更高，必须先弹 |
| C `/ + ( * − *` | `+` 到来时旧 `/` 已弹出 |
| D `/ + − *` | 少了 `(`，且 `/` 已弹出 |

题目说“依次”，按栈底到栈顶读，与上面的写法一致。

## 10｜旧题复现：先读约定

<img src="../bank/2014/q03.png" alt="2014-03 原题" width="524" style="display:block; width:32.75em; max-width:100%; height:auto;">

> **沿用**：与 [0801-02](0801-answer.md#q02) 是同一道原题；06 的“先读指针指向”
> **起手**：遮住旧答案，写 `end1`、`end2` 各指什么　→　**答案 A**

先写题干约定：`end1` 指**队头元素**，`end2` 指**队尾后一个空位**，最多容纳 `M−1` 个。再推公式：

```text
空：end1 == end2
满：end2 再前进一步就碰到队头：end1 == (end2+1) mod M
```

选 **A**。这次要检验的是：不翻旧答案，能否从约定写出两个式子。和 06 对照：06 里 `rear` 指元素，所以首次入队前 `rear` 在 `n−1`；本题 `end2` 指空位，空队列时和 `end1` 同格。两题的指向不同，公式不能互相套用。

## 11｜调用也进栈：先调用的在栈底

<img src="../bank/2015/q01.png" alt="2015-01 原题" width="525" style="display:block; width:32.81em; max-width:100%; height:auto;">

> **沿用**：0731-02 的调用链
> **新增**：函数调用时，要记住“还没做完的调用”，这些记录放在栈里：被调用时压入，返回时弹出
> **起手**：写 `main → S(1) → S(0)`　→　**答案 A**

```text
main()         调用 S(1)，等它的返回值         ← 还没结束，留在栈里
 S(1)          n=1，要 S(0)+1，等 S(0)         ← 还没结束
  S(0)         n≤0，返回 0                     ← 栈顶，最先返回
```

栈底到栈顶是 `main()→S(1)→S(0)`，选 **A**。返回的次序是 `S(0)`、`S(1)`、`main()`，与入栈次序相反。

B 把返回次序当成了入栈次序；C 的 `S(0)` 在 `S(1)` 下面，意味着没调用 `S(1)` 就有了 `S(0)`，不可能。题目问的是栈里保存的信息，不需要算 `S(1)` 的值。

## 12｜同轨先进先出：进入序里的递减项不能同轨

<img src="../bank/2016/q03.png" alt="2016-03 原题" width="550" style="display:block; width:34.38em; max-width:100%; height:auto;">

> **沿用**：01 的“先进先出”，02 的“下界要有构造配合”
> **新增**：每条轨道就是一个队列；要先出小号，同一轨道上进入的车必须**依次增大**
> **起手**：写进入序 `8 4 2 5 3 9 1 6 7`，找互相不能同轨的几辆　→　**答案 C**

行进方向都是从左到右，同一轨道上先进入的先驶出。目标是 `1…9` 依次驶出，所以同一轨道里，先进入的编号必须更小。若 `8` 先于 `4` 进入同一轨道，`8` 就先出，不满足。

**下界**：`8,4,2,1` 在进入序里依次出现，且递减，两两不能同轨，至少需要 4 条。

**构造**：每辆车放到末尾编号比它小的轨道，找不到就开新轨道：

```text
8 → 轨1[8]      4 → 轨2[4]      2 → 轨3[2]
5 → 轨2[4,5]    3 → 轨3[2,3]    9 → 轨1[8,9]
1 → 轨4[1]      6 → 轨2[4,5,6]  7 → 轨2[4,5,6,7]
```

四条轨道内部都递增，出口按 `1,(2,3),(4,5,6,7),(8,9)` 依次取即可。下界与构造都是 4，选 **C**。

A 2、B 3 低于下界；D 5 可行，但不是最少。

## 13｜四句话：“必须”“唯一”“两端”各找一个反例

<img src="../bank/2017/q02.png" alt="2017-02 原题" width="475" style="display:block; width:29.69em; max-width:100%; height:auto;">

> **沿用**：03、04 的栈与两端入队
> **新增**：带“必须”“只要……就”“允许”的绝对说法，用最小反例判断
> **起手**：对 III 用输入 `1,2` 试两种操作　→　**答案 C**

| 命题 | 判断 | 依据 |
|---|---|---|
| I 非递归重写**必须**用栈 | ✗ | 求 `1+…+n` 的递归可改成一个循环加累加变量，不用栈 |
| II 函数调用用栈保存必要信息 | ✓ | 见 11：未结束的调用记录在栈里 |
| III 入栈次序定了，出栈次序就定 | ✗ | 输入 `1,2`：`push1 pop1 push2 pop2` 得 `1,2`；`push1 push2 pop2 pop1` 得 `2,1` |
| IV 栈**允许**在两端操作 | ✗ | 栈只在栈顶一端入、出；两端入队是 04 的队列限制，不是栈 |

错误的是 I、III、IV，选 **C**。

I 不能说成“递归都能不用栈”：一般的树遍历要显式用栈保存待处理的结点。题里的“必须”只需要一个反例就能推翻。

## 14｜两个栈做算式：先弹出的是右操作数

<img src="../bank/2018/q01.png" alt="2018-01 原题" width="521" style="display:block; width:32.56em; max-width:100%; height:auto;">

> **沿用**：每执行一步就更新草图
> **新增**：`a` 先弹、`b` 后弹，算的是 `b op a`，不是 `a op b`
> **起手**：每轮写 `a、b、op` 和 S₁ 的新状态　→　**答案 B**

S₁ 自底向顶 `5,8,3,2`；S₂ 自顶向底 `+,-,*`。

| 轮 | `a`（先弹） | `b` | `op` | 算 `b op a` | S₁ 之后（底→顶） |
|---:|---:|---:|:---:|---|---|
| 1 | 2 | 3 | `+` | 3+2 = 5 | 5, 8, 5 |
| 2 | 5 | 8 | `-` | 8−5 = 3 | 5, 3 |
| 3 | 3 | 5 | `*` | 5×3 = 15 | 15 |

选 **B**。

如果第 2 轮读成 `a−b = 5−8 = −3`，第 3 轮就是 `5×(−3) = −15`，得到 A。减法对顺序敏感，加法、乘法不敏感，所以第 1、3 轮读反不影响结果，第 2 轮读反就错。C、D 与按题意逐轮算得到的 15 不符。

## 15｜队列 + 栈：谁压在谁上面决定能不能取

<img src="../bank/2018/q02.png" alt="2018-02 原题" width="528" style="display:block; width:33.00em; max-width:100%; height:auto;">

> **沿用**：03 的目标驱动写栈
> **新增**：输入来自队列，次序固定为 1…6；三种操作是“直接输出”“压入栈”“弹栈输出”
> **起手**：对每个候选，逐个目标判断：是队头就直出，否则要先把队头暂存进栈　→　**答案 C**

队列里的元素只能按 `1,2,3,…` 出队；想先输出靠后的数，就得把前面的数压进栈暂存。栈里后压的先弹。

| 选项 | 操作 | 结果 |
|---|---|---|
| A `1,2,5,6,4,3` | 直出 1、2；压 3、4；直出 5、6；弹 4、3 | ✓ |
| B `2,3,4,5,6,1` | 压 1；直出 2…6；弹 1 | ✓ |
| **C** `3,4,5,6,1,2` | 要先输出 3，1、2 必须先压入；栈 `[1,2]` 顶是 2；3—6 直出后，弹出的第一个是 2 | ✗ 要 `1,2`，只能得 `2,1` |
| D `6,5,4,3,2,1` | 压 1…5；直出 6；依次弹 5…1 | ✓ |

C 不行的原因是具体的：**2 压在 1 上面**，要先取 1，就必须越过 2，栈做不到。选 **C**。

## 16｜按给定的 Push/Pop 序列执行

<img src="../bank/2020/q02.png" alt="2020-02 原题" width="527" style="display:block; width:32.94em; max-width:100%; height:auto;">

> **沿用**：02 的逐步写栈；这次操作序列由题给，不用自己找
> **起手**：八步各写一行栈　→　**答案 D**

步  操作   栈（底→顶）   输出

## 17｜一端只入、另一端可入可出

<img src="../bank/2021/q02.png" alt="2021-02 原题" width="525" style="display:block; width:32.81em; max-width:100%; height:auto;">

> **沿用**：04 的“放在两端”；这次出队也只在右端
> **新增**：出队只能从**右端**取，所以先取到的必须在右端
> **起手**：先出 4，写出 1、2、3、4 的位置　→　**答案 D**

左端只能放入新元素；右端既能放入，又能取出。入队序列 1…5。逐个检验候选，读出右端取出的次序：

| 选项 | 一种可行的放法（从左到右的队列，右端取出） | 结论 |
|---|---|---|
| A `5,4,3,1,2` | 全入后队列为 `2 1 3 4 5` | ✓ |
| B `5,3,1,2,4` | 全入后队列为 `4 2 1 3 5` | ✓ |
| C `4,2,1,3,5` | 放 1；2 右、3 左 → `3 1 2`；4 右 → `3 1 2 4`；取 4、2、1、3；再入 5 取 5 | ✓ |
| **D** `4,1,3,2,5` | 见下 | ✗ |

D：要先取 4，取走后右端必须是 1，所以 2、3 在 1 的**左边**。两个都从左端放入，顺序是 `3 2 1 4`。取 4、1 之后，右端是 2，下一个要取 3，却被 2 挡住。若把 3 放在 1 右边，取 4 之后右端就是 3，不是 1。无论怎样放，`4,1,3,2` 都不成立。选 **D**。

这和普通队列不同：普通队列不能让后来的 5 先出，这里右端可以入，所以 A、B 的 5 先出可行。排除时要找“两个元素的先后被锁死”，不能只凭“队列先进先出”。

## 18｜同一入栈序列：出栈序列有多种，也可判定

<img src="../bank/2022/q02.png" alt="2022-02 原题" width="467" style="display:block; width:29.19em; max-width:100%; height:auto;">

> **沿用**：13 的最小反例；03 的目标驱动写栈
> **新增**：区分“可能得到多种出栈序列”和“能否判断某个序列是不是出栈序列”
> **起手**：取 `in=1,2`，写两种操作　→　**答案 D**

```text
in = 1,2：push1 pop1 push2 pop2 → out = 1,2   （与 in 相同）
          push1 push2 pop2 pop1 → out = 2,1   （in 的倒序）
```

| 选项 | 判断 |
|---|---|

## 19｜后缀表达式：从最里面往外，一块一块拼

<img src="../bank/2024/q02.png" alt="2024-02 原题" width="295" style="display:block; width:18.44em; max-width:100%; height:auto;">

> **沿用**：07 的优先级（同级从左到右）
> **新增**：后缀的规则是运算符写在它的两个操作数**之后**；按运算的先后，由里向外拼
> **起手**：先写 `z−u` 的后缀　→　**答案 A**

`x+y*(z−u)/v` 的运算顺序：括号先算；`*`、`/` 同级，从左到右，所以先 `y*(z−u)`，再 `/v`；最后 `x+`。

```text
z−u            →  zu−
y*(z−u)        →  y zu− *      = yzu−*
…/v            →  yzu−* v /    = yzu−*v/
x+…            →  x yzu−*v/ +  = xyzu−*v/+
```

选 **A**。

| 选项 | 问题 |
|---|---|
| B `xyzu−v/*+` | 先算 `(z−u)/v` 再乘 `y`，同级本应先乘后除 |
| C `+x / * y−zuv` | 运算符在前，是前缀形式（恰好是原式的前缀） |
| D `+x* y /−zuv` | 前缀形式，且运算顺序也不对 |

## 20｜括号匹配：容量够不够看栈高的峰值

<img src="../bank/2025/q02.png" alt="2025-02 原题" width="486" style="display:block; width:30.38em; max-width:100%; height:auto;">

> **沿用**：07 的 `(` 入栈、`)` 配对弹出；09 的“某一刻的栈”
> **新增**：容量是否够，只看同时未闭合的括号最多有几个
> **起手**：逐个括号写栈高，字母和运算符跳过　→　**答案 D**

算法 A 遇到左括号压栈，遇到右括号与栈顶配对。栈容量 3，所以**第 4 个同时未闭合的左括号**就放不下。

```text
D  [a−(b+[c*(d+e)−f]+g+h)
   [   ( [  (          栈高 1, 2, 3, 4   ← 第 4 个左括号放不下
```

D 不能处理，选 **D**。

A、B、C 的峰值只到 3：

```text
A  (a+[b+(c+d))…      ( [ ( 高 3；) 配 ( 后高 2；再来 ) 遇到 [，类型不符
B  [(a*(b+c)/(d-e)…   [ ( ( 高 3；) 后高 2；又 ( 高 3；) 后高 2；] 遇到 (，类型不符
C  (a*[b−(c−d)*e/(f+g))…   ( [ ( 高 3；) 后 2；( 又 3；) 后 2；再来 ) 遇到 [，类型不符
```

这三个字符串自己括号并不匹配，算法会在遇到不匹配时报告并停下，没有超过容量。题问的是“不能处理”，所以按**容量是否被超**来判：若把“不匹配”也算成不能处理，四项都不能处理，题目没有唯一答案。
