## 01｜2009-23：并发的对象不一定都争同一处理器

![2009-23 原题](../bank/2009/q23.png)

题限定**单处理机**。两个进程不能在同一时刻都占这个 CPU，I 的进程与进程只能交替并发，不能物理并行。CPU 执行指令时设备可自主工作 II；通道可控制 I/O 与 CPU 并行 III；不同设备也可相互并行 IV。**II、III、IV，选 D**。第一笔写出每对对象是否都必须占唯一 CPU。

<details><summary>把“并发”与“并行”分到同一时间刻度</summary>

单核上的两个进程可在一段时间内交替推进，是并发；题问的并行指同一时刻。处理器、通道、设备是不同执行资源，因此它们的动作可重叠；不要因“单处理机”三个字否定一切并行。
</details>

<a id="q02"></a>
## 02｜2009-24：响应比同时计等待和服务

![2009-24 原题](../bank/2009/q24.png)

题问综合考虑等待时间与执行时间。高响应比优先按 `响应比=(等待时间+要求服务时间)/要求服务时间=1+等待/服务` 排序，**选 D**。服务短者在等待相同情况下比值高；长作业等久后比值也升高。第一笔看候选算法的比较量里是否**同时**出现两个时间。

<details><summary>分母为何放服务时间</summary>

若直接比等待+服务，长作业可能天然大；除以服务时间让等待相对本身服务长度产生作用。例：短作业服务 2、等 2，比值 2；长作业服务 10、等 2，比值 1.2；长者再等 10，比值也变 2。此处例子只用于理解，不必每题另造数值。
</details>

<a id="q03"></a>
## 03｜2010-24：新进程从“新的执行主体”识别

![2010-24 原题](../bank/2010/q24.png)

登录成功使系统为用户建立执行环境，启动一个程序也要创建相应进程，I、III 对。设备分配把已有进程所需资源交给它，**并不必然**创建新进程，II 不选。**仅 I、III，选 C**。第一笔问结果是“多了一个可被调度的主体”，还是“已有主体多了一份资源”。

<details><summary>与 0824 的系统调用相接</summary>

用户可通过系统服务创建进程，内核再给它分配 PCB、地址空间等资源；分配设备本身是资源管理动作，不与创建新 PCB 画等号。
</details>

<a id="q04"></a>
## 04｜2010-26：用尽时间片意味着已经得到过机会

![2010-26 原题](../bank/2010/q26.png)

在多级反馈队列的常见规则中，进程用完整个时间片仍未结束，说明它已连续占用本级给的 CPU 份额，可降至较低优先级队列，**选 A**。刚完成 I/O 的进程进入就绪队列常希望较快响应；长期在就绪队列等待则不宜再降；被选中运行也不是惩罚条件。第一笔找“它是否**消耗了 CPU 配额**”。

<details><summary>此题暗含的调度规则边界</summary>

优先级动态调整依赖具体算法；题问合理时机，耗尽时间片是一个直接可观察信号。不能把“发生一次状态变化”都当作降低优先级理由。
</details>

<a id="q05"></a>
## 05｜2011-23：短任务优先也要给长期等候者上涨机会

![2011-23 原题](../bank/2011/q23.png)

沿用 02 的响应比 `1+等待/服务`：服务时间短者起初容易领先，但等待时间不断增加会提高长期未执行任务的比值，避免它永久排不到，**高响应比优先，选 B**。先来先服务和时间片轮转不会按短任务先选；非抢占短任务优先只看短，不随等待产生这项补偿。第一笔要求同时满足“短任务偏好”和“等待越久优先级越升”。

<details><summary>为什么等久后仍可能赶上</summary>

对固定服务时长 `S>0`，等待 `W` 增大时 `1+W/S` 单调上升。它不是许诺每个作业立刻上 CPU，而是避免固定“总有更短者先来”造成的长期饥饿。
</details>

<a id="q06"></a>
## 06｜2011-24：用户态也能运行提供交互的普通程序

![2011-24 原题](../bank/2011/q24.png)

命令解释程序读取并解析用户输入，可作为普通用户进程执行，**选 A**。缺页处理、进程调度、时钟中断处理都需要内核管理异常、上下文和计时，B/C/D 在内核态。第一笔问代码有没有直接处理受保护的 CPU 状态，而非名字里是否含“系统”。

<details><summary>命令解释器要访问文件怎么办</summary>

它自己可在用户态解析命令，需要文件或启动程序时再发系统调用跨边界。代码可能请求内核服务，不等于自身始终是内核处理程序。
</details>

<a id="q07"></a>
## 07｜2011-25：共享进程资源，独立保存线程运行位置

![2011-25 原题](../bank/2011/q25.png)

同一进程的线程共享代码段、打开文件和全局变量；每个线程有自己的执行栈与栈指针，才能暂停 A、运行 B、再恢复 A，**选 D**。第一笔问这个量是“进程共同拥有的资源”还是“恢复某一线程独立执行点所必需”。

<details><summary>为何共享代码不共享栈指针</summary>

多个线程可执行同一函数机器码，但各自调用深度、局部变量和返回地址不同，必须以各自栈指针找到自己的栈顶。共享“代码”并不意味着共享“当前执行位置”。
</details>

<a id="q08"></a>
## 08｜2012-25：虚拟存储要让逻辑连续与物理分散脱钩

![2012-25 原题](../bank/2012/q25.png)

虚拟存储按需调入、换出页面或段，让程序的逻辑空间不必连续占满物理内存；它要依靠**非连续分配**的页式/段式等机制，**选 B**。A 的“只能连续”反向；虚拟容量还受虚拟地址位数和可用外存等限制，C 的“只受外存”与 D 的“只受内存”都太绝对。第一笔分别审“实现结构”和“容量上限”，不要被相似措辞带走。

<details><summary>本题为何插在进程生命线</summary>

进程切换时每个进程的虚拟地址空间各自映射；后题会问页表基址随进程切换。这里先知道“同一个逻辑地址未必对应连续物理内存”，不必重新上一整章存储管理。
</details>

<a id="q09"></a>
## 09｜2013-27：画两条可重叠的时间线，不把耗时全相加

![2013-27 原题](../bank/2013/q27.png)

两块输入各从外设到系统缓冲需 100，缓冲到用户工作区需 5，分析需 90。第一块读至 `t=100`，复制到 `105`，分析到 `195`；与此同时第二块可从 `t=100` 读至 `200`，随后复制到 `205`，分析到 **`295`，选 B**。第一笔写每项动作占用 CPU、缓冲和设备中的哪个资源，才知道哪些能重叠。

<details><summary>为什么不是 390 或 200</summary>

完全串行是 `2×(100+5+90)=390`，漏掉第二次复制与分析会错误得到约 200。最短排程中第二块设备读与第一块 CPU 分析重叠，但第二块还须等自己读完并复制才能分析；用每条任务的完成时刻取最大值，末尾是 295。
</details>

<a id="q10"></a>
## 10｜2014-23：饥饿问的是“永远轮不到”，不是平均等多久

![2014-23 原题](../bank/2014/q23.png)

时间片轮转让就绪队列中的每个进程轮流取得有限 CPU 片，只要每次服务和队列推进，进程不会被**永久**跳过，**选 A**。静态优先级可让低优先级长期被新高优先级压住；短作业优先无论抢占与否都可能不断偏向新来的短任务。第一笔问调度规则会不会给已排队者一个确定的轮到机会。

<details><summary>“无饥饿”不等于考场响应时间一定短</summary>

进程数多或时间片大小不合适，轮转仍可能等待较长；它保证公平轮到，和 02、05 的平均等待、短任务偏好是不同指标。
</details>
