## 01｜2009-23：并发的对象不一定都争同一处理器

![2009-23 原题](../bank/2009/q23.png)

题限定**单处理机**。两个进程不能在同一时刻都占这个 CPU，I 的进程与进程只能交替并发，不能物理并行。CPU 执行指令时设备可自主工作 II；通道可控制 I/O 与 CPU 并行 III；不同设备也可相互并行 IV。**II、III、IV，选 D**。第一笔写出每对对象是否都必须占唯一 CPU。

<details open><summary>把“并发”与“并行”分到同一时间刻度</summary>

单核上的两个进程可在一段时间内交替推进，是并发；题问的并行指同一时刻。处理器、通道、设备是不同执行资源，因此它们的动作可重叠；不要因“单处理机”三个字否定一切并行。
</details>

<a id="q02"></a>
## 02｜2009-24：响应比同时计等待和服务

![2009-24 原题](../bank/2009/q24.png)

题问综合考虑等待时间与执行时间。高响应比优先按 `响应比=(等待时间+要求服务时间)/要求服务时间=1+等待/服务` 排序，**选 D**。服务短者在等待相同情况下比值高；长作业等久后比值也升高。第一笔看候选算法的比较量里是否**同时**出现两个时间。

<details open><summary>分母为何放服务时间</summary>

若直接比等待+服务，长作业可能天然大；除以服务时间让等待相对本身服务长度产生作用。例：短作业服务 2、等 2，比值 2；长作业服务 10、等 2，比值 1.2；长者再等 10，比值也变 2。此处例子只用于理解，不必每题另造数值。
</details>

<a id="q03"></a>
## 03｜2010-24：新进程从“新的执行主体”识别

![2010-24 原题](../bank/2010/q24.png)

登录成功使系统为用户建立执行环境，启动一个程序也要创建相应进程，I、III 对。设备分配把已有进程所需资源交给它，**并不必然**创建新进程，II 不选。**仅 I、III，选 C**。第一笔问结果是“多了一个可被调度的主体”，还是“已有主体多了一份资源”。

<details open><summary>与 0824 的系统调用相接</summary>

用户可通过系统服务创建进程，内核再给它分配 PCB、地址空间等资源；分配设备本身是资源管理动作，不与创建新 PCB 画等号。
</details>

<a id="q04"></a>
## 04｜2010-26：用尽时间片意味着已经得到过机会

![2010-26 原题](../bank/2010/q26.png)

在多级反馈队列的常见规则中，进程用完整个时间片仍未结束，说明它已连续占用本级给的 CPU 份额，可降至较低优先级队列，**选 A**。刚完成 I/O 的进程进入就绪队列常希望较快响应；长期在就绪队列等待则不宜再降；被选中运行也不是惩罚条件。第一笔找“它是否**消耗了 CPU 配额**”。

<details open><summary>此题暗含的调度规则边界</summary>

优先级动态调整依赖具体算法；题问合理时机，耗尽时间片是一个直接可观察信号。不能把“发生一次状态变化”都当作降低优先级理由。
</details>

<a id="q05"></a>
## 05｜2011-23：短任务优先也要给长期等候者上涨机会

![2011-23 原题](../bank/2011/q23.png)

沿用 02 的响应比 `1+等待/服务`：服务时间短者起初容易领先，但等待时间不断增加会提高长期未执行任务的比值，避免它永久排不到，**高响应比优先，选 B**。先来先服务和时间片轮转不会按短任务先选；非抢占短任务优先只看短，不随等待产生这项补偿。第一笔要求同时满足“短任务偏好”和“等待越久优先级越升”。

<details open><summary>为什么等久后仍可能赶上</summary>

对固定服务时长 `S>0`，等待 `W` 增大时 `1+W/S` 单调上升。它不是许诺每个作业立刻上 CPU，而是避免固定“总有更短者先来”造成的长期饥饿。
</details>

<a id="q06"></a>
## 06｜2011-24：用户态也能运行提供交互的普通程序

![2011-24 原题](../bank/2011/q24.png)

命令解释程序读取并解析用户输入，可作为普通用户进程执行，**选 A**。缺页处理、进程调度、时钟中断处理都需要内核管理异常、上下文和计时，B/C/D 在内核态。第一笔问代码有没有直接处理受保护的 CPU 状态，而非名字里是否含“系统”。

<details open><summary>命令解释器要访问文件怎么办</summary>

它自己可在用户态解析命令，需要文件或启动程序时再发系统调用跨边界。代码可能请求内核服务，不等于自身始终是内核处理程序。
</details>

<a id="q07"></a>
## 07｜2011-25：共享进程资源，独立保存线程运行位置

![2011-25 原题](../bank/2011/q25.png)

同一进程的线程共享代码段、打开文件和全局变量；每个线程有自己的执行栈与栈指针，才能暂停 A、运行 B、再恢复 A，**选 D**。第一笔问这个量是“进程共同拥有的资源”还是“恢复某一线程独立执行点所必需”。

<details open><summary>为何共享代码不共享栈指针</summary>

多个线程可执行同一函数机器码，但各自调用深度、局部变量和返回地址不同，必须以各自栈指针找到自己的栈顶。共享“代码”并不意味着共享“当前执行位置”。
</details>

<a id="q08"></a>
## 08｜2012-25：虚拟存储要让逻辑连续与物理分散脱钩

![2012-25 原题](../bank/2012/q25.png)

虚拟存储按需调入、换出页面或段，让程序的逻辑空间不必连续占满物理内存；它要依靠**非连续分配**的页式/段式等机制，**选 B**。A 的“只能连续”反向；虚拟容量还受虚拟地址位数和可用外存等限制，C 的“只受外存”与 D 的“只受内存”都太绝对。第一笔分别审“实现结构”和“容量上限”，不要被相似措辞带走。

<details open><summary>本题为何插在进程生命线</summary>

进程切换时每个进程的虚拟地址空间各自映射；后题会问页表基址随进程切换。这里先知道“同一个逻辑地址未必对应连续物理内存”，不必重新上一整章存储管理。
</details>

<a id="q09"></a>
## 09｜2013-27：画两条可重叠的时间线，不把耗时全相加

![2013-27 原题](../bank/2013/q27.png)

两块输入各从外设到系统缓冲需 100，缓冲到用户工作区需 5，分析需 90。题设系统缓冲区和用户工作区**均为单缓冲**：第一块读至 `t=100`，复制到 `105` 后才释放系统缓冲；分析在 `105—195` 进行。第二块只能从 `t=105` 开始读，至 `205` 完成，再于 `205—210` 复制、`210—300` 分析。最短时间 **300，选 C**。第一笔写每项动作占用哪个缓冲，尤其不能让第二次读入覆盖还在复制的第一块。

<details open><summary>为什么不是 390 或 200</summary>

完全串行是 `2×(100+5+90)=390`，漏掉第二次复制与分析会错误得到约 200。B 的 295 把第二次读入提前到 t=100，漏掉第一块复制占用系统单缓冲的 5 个时间单位。可重叠的是第二块读入与第一块分析；第一块读入与复制之间，以及同一系统缓冲上的复制与下一次读入之间，仍必须串行。最短总时间为 `2×(100+5)+90=300`。
</details>

<a id="q10"></a>
## 10｜2014-23：饥饿问的是“永远轮不到”，不是平均等多久

![2014-23 原题](../bank/2014/q23.png)

时间片轮转让就绪队列中的每个进程轮流取得有限 CPU 片，只要每次服务和队列推进，进程不会被**永久**跳过，**选 A**。静态优先级可让低优先级长期被新高优先级压住；短作业优先无论抢占与否都可能不断偏向新来的短任务。第一笔问调度规则会不会给已排队者一个确定的轮到机会。

<details open><summary>“无饥饿”不等于考场响应时间一定短</summary>

进程数多或时间片大小不合适，轮转仍可能等待较长；它保证公平轮到，和 02、05 的平均等待、短任务偏好是不同指标。
</details>

## 11｜2015-25：运行变就绪，与运行变阻塞只差一个等待原因

![2015-25 原题](../bank/2015/q25.png)

P(wait) 若资源不足、内存申请失败或启动 I/O 后需等设备，进程可能因等待条件转**阻塞**。高优先级进程到来抢占当前运行者，当前者仍可运行，只是暂时拿不到 CPU，转**就绪**，**选 D**。第一笔问进程接下来缺的是“可运行条件”还是“CPU 使用权”。

<details open><summary>时间片耗尽也同理</summary>

用尽时间片只说明 CPU 份额要让给别人，不会凭空变成等待 I/O 或信号量；它也回就绪队列。后题的“阻塞/就绪”可沿这一个判断区分。
</details>

<a id="q12"></a>
## 12｜2017-23：先在调度时刻划掉尚未到达者

![2017-23 原题](../bank/2017/q23.png)

`t=2` 已到达的是 J1(到 0、运行 3)、J2(到 1、运行 3)、J3(到 1、运行 2)；J4 要到 `t=3`，不能抢先进入候选集合。FCFS 按到达最早选 **J1**，短作业优先按运行时间最短选 **J3**，**选 D**。第一笔先圈“当前就绪集合”，再套算法。

<details open><summary>为何不能被 J4 的 1 迷惑</summary>

若先比较四个运行时间，J4 最短，会误选未到达作业；调度算法只在已进入系统且就绪者中选择。题特意把开始时刻放 t=2，正为考这个约束。
</details>

<a id="q13"></a>
## 13｜2017-27：时间片用完还可运行，不能写成阻塞

![2017-27 原题](../bank/2017/q27.png)

题问**错误**。时间片越短，切换通常越频繁，A 对；时钟中断更新剩余片长 C 对；选择片长要考虑响应、开销、进程数量等 D 对。B 把片用完后的状态写成**阻塞**，其实进程仍具备运行条件，应从执行态转**就绪态**，**选 B**。第一笔只看它是否在等外部条件；没有就不能叫阻塞。

<details open><summary>与 11 的同一动作</summary>

抢占与片用完都只是失去 CPU，仍在就绪队列；P(wait) 等不到资源或未完成 I/O 才阻塞。用一条状态原因线解两题，后续不重背状态图。
</details>

<a id="q14"></a>
## 14｜2018-23：多任务不等于多 CPU

![2018-23 原题](../bank/2018/q23.png)

多任务系统中各任务可交替并发；CPU 和设备还可并行，I 对。任务共享文件、内存、设备时需互斥与保护，II 对。单 CPU 也可通过切换运行多任务，III“需要多 CPU”错，**仅 I、II，选 C**。第一笔沿 01 的资源图分开“多任务轮换”和“多核同刻执行”。

<details open><summary>I 中两个词的读法</summary>

多任务 OS 既支持进程在时间上并发推进，也允许不同硬件资源上的工作并行。不能因单核上两个进程不同时执行就否认整个系统的并行特性。
</details>

<a id="q15"></a>
## 15｜2018-24：周转时间含本题开始前已经等过的时间

![2018-24 原题](../bank/2018/q24.png)

优先权值越大越先运行，顺序 **P2(30)→P3(20)→P1(10)**。每次调度/切换耗 1 μs，从 T 算：P2 完成 `1+24=25`，P3 完成 `25+1+36=62`，P1 完成 `62+1+12=75`。但表中已等待 15、18、30 μs，所以三个周转时间为 `15+25=40`、`18+62=80`、`30+75=105`，平均 **75 μs，选 D**。第一笔把表头“等待时间”抄到周转式里。

<details open><summary>三个容易丢的 1 μs</summary>

一共调度三个进程，第一次从 T 开始也有一次调度/切换开销；每次接力再各有一次。若只数两次得到完成 24、60、72，平均会偏小；若漏掉既有等待时间，得到的是从 T 后的平均完成时刻，不是周转。
</details>

<a id="q16"></a>
## 16｜2018-25：把一次加一拆成读、改、写，再数可行序列

![2018-25 原题](../bank/2018/q25.png)

每线程必须保持内部 `读 x→寄存器加 1→写回 x` 顺序。最终 `x=2` 的关键：第二个线程读取到第一个线程**已经写回的 1**，才能写出 2；这要求某线程三条先完整执行，再执行另一线程的三条。只有 `111222` 与 `222111` 两种，**选 B（2）**。第一笔盯“第二次读到的 x 是 0 还是 1”，不用一口气枚举全部交错。

<details open><summary>为什么中间插入一步也不行</summary>

若线程 2 在线程 1 写回前读，它拿到 0，局部加后只能写 1；若线程 1 在那个间隙加一但还没写，线程 2 也仍读到 0。要最后写出 2，先前的一次写 1 必须完成，而各线程的写就是第三条，所以整个先行线程已结束。指令交错会造成丢失更新。
</details>

<a id="q17"></a>
## 17｜2019-23：用户级线程的控制信息由谁维护

![2019-23 原题](../bank/2019/q23.png)

内核级线程由 OS 调度 A 对；用户级线程切换不必每次陷入内核，通常效率较高 C 对；即使 OS 不提供内核线程，用户线程库仍可实现用户级线程 D 对。B 称 **OS 为每个用户级线程建立线程控制块**，这些线程的控制与调度通常由用户空间线程库管理，内核未必逐一认识，**选 B**。第一笔问“操作系统是否看得见这个线程”。

<details open><summary>与 07 的两个维度</summary>

07 问同进程线程共享哪些资源；本题问线程由哪一层调度。共享地址空间不决定 OS 一定为其逐个建内核控制块，不能从“都是线程”推同一调度层。
</details>

<a id="q18"></a>
## 18｜2019-27：先遵守高队列优先，再算低队列等待

![2019-27 原题](../bank/2019/q27.png)

两进程初入 Q1，片长 10 ms。P1 先跑 `0—10` 后剩 20 转 Q2；P2 在 Q1 跑 `10—20` 后剩 10 转 Q2。Q1 空，Q2 按短进程优先：P2 跑 `20—30` 完成，P1 跑 `30—50` 完成。P1 等待 `50−30=20`，P2 等待 `30−20=10`，平均 **15 ms，选 C**。第一笔先写 Q1 的两个片，而非一看到 P2 短就让它先跑。

<details open><summary>等待时间与周转时间核对</summary>

均在 0 到达，P1 周转 50，服务 30，等待 20；P2 周转 30，服务 20，等待 10。也可逐段数：P1 等 10—30，P2 等 0—10；两个办法得同样结果。
</details>

<a id="q19"></a>
## 19｜2020-26：设计多级反馈必须定义四类规则

![2020-26 原题](../bank/2020/q26.png)

队列**数量 I** 决定有几级，级间**优先级 II** 决定先服务谁，队列内部**算法 III** 决定同级轮到谁，**迁移条件 IV** 决定何时降级或调整。四项都是设计参数，**选 D**。第一笔把它们对应 18 的具体 Q1/Q2：几队、谁优先、各队怎么排、用完一片去哪里。

<details open><summary>只答“有多个队列”为什么不够</summary>

若没规定迁移，一个长作业可能一直占高级队列；没规定队列间优先级，不知道 Q2 是否要等 Q1 空；没规定内部算法，无法确定 P1、P2 的顺序。四个维度合起来才是可运行的规则。
</details>

<a id="q20"></a>
## 20｜2020-29：父子进程不同于同进程的两个线程

![2020-29 原题](../bank/2020/q29.png)

题问**错误**。父子进程可并发/在多核上并行，有各自 PCB；进程间对同一临界资源必须遵守互斥。B 却说父子进程**共享虚拟地址空间**，创建子进程可复制或写时复制映射，但逻辑上各有自己的虚拟地址空间，**选 B**。第一笔把 07 的“同进程线程共享地址空间”与“父子是两个进程”对照。

<details open><summary>写时复制为何不使 B 成立</summary>

父子开始时可映射到相同物理页以省复制，某方写入时再复制物理页；这是物理页的暂时共享和映射优化，不是一个共同的虚拟地址空间。修改父进程的一般变量不会无条件改变子进程的对应变量。
</details>

状态题先问是否还具备运行条件；调度题先圈当前就绪集合，再排队，最后把既有等待和切换开销加回；线程题分“共享资源”和“独立执行现场”。16 的六步只需抓第二次读取前必须有第一次写回，考场不枚举二十种。教学覆盖不代表本人熟练。

<a id="q21"></a>
## 21｜2021-24：创建进程先有记录，再有可运行状态

![2021-24 原题](../bank/2021/q24.png)

OS 创建新进程必须申请空白**PCB（进程控制块）**并初始化其中的标识、状态、资源等信息，I、II 对。刚创建后通常先进入就绪等候，并不必须立刻成为**执行态**，III 错，**选 B**。第一笔区分“创建一个可被调度的主体”与“马上取得 CPU”。

<details open><summary>与 03 的创建原因接上</summary>

登录或启动程序使 OS 新建执行主体，PCB 是内核记录它并安排调度的凭据；能进入就绪队列不等于该时刻抢到处理器。即使最终会运行，也不能把将来状态写成创建时的必要步骤。
</details>

<a id="q22"></a>
## 22｜2021-25：时间片轮转需能记、能计时、能排队

![2021-25 原题](../bank/2021/q25.png)

实现时间片轮转要用 PCB I 记进程及其状态，用时钟中断处理程序 II 在片到时接管，用进程就绪队列 III 安排下一位，**仅 I、II、III，选 C**。阻塞队列 IV 对等待 I/O 的进程有用，但不是**分时系统实现轮转调度本身**的必需结构。第一笔把 13 的“片尽→就绪”逐步落实为数据结构与触发器。

<details open><summary>“系统可能有”与“本算法需要”</summary>

真实分时 OS 可有阻塞队列来管理 I/O；此题问使轮转机制成立所需的东西。就绪队列能放被换下的进程，时钟能发出换人的信号，PCB 保存上下文；阻塞队列不能替代这三者。
</details>

<a id="q23"></a>
## 23｜2021-27：四种不同原因都可能重新选进程

![2021-27 原题](../bank/2021/q27.png)

中断处理结束可能发现有更合适的就绪者 I；当前进程阻塞 II 或执行结束 III 后不能继续占 CPU；时间片用完 IV 也要轮换。四者都**可能**引起进程调度，**选 D**。第一笔问“现在是否要决定接下来由谁运行”，而不是四项是否一律属于相同状态转换。

<details open><summary>“可能”保留条件</summary>

某次中断返回原进程可能最合适，就不一定切换；阻塞/结束/片尽则通常必须找接替者。题目只需证明每类事件存在触发调度的场景，不能把可能误读为必然每次切换。
</details>

<a id="q24"></a>
## 24｜2022-23：多道程序的收益不是无限单调上升

![2022-23 原题](../bank/2022/q23.png)

多道程序让不同进程在等待与计算之间交替并发，需要管理共享资源；这些是 A、C 的合理叙述。它不**必须**有虚拟存储，可在更早/简单的存储管理上运行，B 也对。D 说“进程数越多，CPU 利用率越高”是无上限单调判断；内存与调度成本增加、频繁换页可降低有效运行，**选 D**。第一笔对“越多越高”试一个资源不足反例。

<details open><summary>何时增加并发度真有收益</summary>

进程很少而常等 I/O 时，增加作业能让 CPU 在等待空档做别的工作；达到内存、设备等瓶颈后，额外进程的竞争和切换开销会吃掉收益。这是一个带条件的经验趋势，不是无限递增定律。
</details>

<a id="q25"></a>
## 25｜2022-25：抢占式优先级数“上 CPU 的段数”

![2022-25 原题](../bank/2022/q25.png)

优先值小者更高。`t=0` P0 开始；`t=10` P2(10) 到达，抢占 P0(15)；`t=15` P3(6) 抢占 P2；P3 到 `25` 结束，P2 到 `40` 结束；P0 再运行，结束后 P1(20) 最后执行。CPU 段依次 **P0→P2→P3→P2→P0→P1**，共 **6 次进程调度，选 C**。第一笔在 0、10、15 三个到达时刻先找“新者是否更优先”。

<details open><summary>为何 P1 到达 t=10 没有立刻运行</summary>

P1 的优先值 20 比当时 P0 的 15 更低，且比同时到达的 P2 的 10 更低；它只入就绪队列。后续 P3、P2 结束后，P0 仍比 P1 优先。不要把“到达一次”直接数成“调度一次”；只有 CPU 实际开始执行新的一段才计数。
</details>

<a id="q26"></a>
## 26｜2022-28：读文件和请求设备可能等，片尽不等资源

![2022-28 原题](../bank/2022/q28.png)

读文件 I 若需磁盘完成可阻塞；申请外设 III 若设备不可用可等待；执行 `wait()` IV 若信号量资源不足可阻塞。时间片用尽 II 仍具备运行条件，仅从执行态转就绪。**I、III、IV，选 D**。第一笔用 11、13 的判据：当前还缺什么外部条件？

<details open><summary>“可能”不要求每次读文件都阻塞</summary>

文件数据若已经缓存，读操作可能很快完成；设备可立即分配、信号量也可能有余量。题问可能导致阻塞，三者各有需要等待的情形；片尽只是 CPU 被轮换。
</details>

<a id="q27"></a>
## 27｜2023-27：主动让 CPU 但不等条件，状态仍就绪

![2023-27 原题](../bank/2023/q27.png)

键盘输入、缺页异常和资源不足的 `wait()` 都可能需要等输入、调页或信号量条件，导致阻塞。**主动让出 CPU** 没有产生资源等待，该线程仍可运行，转就绪，**选 C**。第一笔问“让出后立刻重新选中它，是否还有外部障碍？”没有就属于就绪。

<details open><summary>注意 wait() 与 yield 的区别</summary>

`wait()` 若拿不到信号量资源才阻塞；主动 `yield` 只是把 CPU 机会交给调度器。二者都离开执行态，但一个缺资源、一个只缺 CPU。题用“可能”而非“必然”，因此 wait 仍是阻塞候选。
</details>

<a id="q28"></a>
## 28｜2023-29：抢占时间线算完成，再减各自到达

![2023-29 原题](../bank/2023/q29.png)

优先值大者更高：P1 在 `0—20` 跑 20；P2 到达抢占，在 `20—30` 跑 10；P3 到达再抢占，`30—43` 完成；P2 `43—75` 完成剩余 32；P1 `75—115` 完成剩余 40。周转分别 `115−0=115`、`75−20=55`、`43−30=13`，平均 `(115+55+13)/3=61 ms`，**选 B**。第一笔画到达时刻与已用 CPU，而不是拿服务时间直接排序。

<details open><summary>两次抢占后的剩余量</summary>

P1 原需 60，在 20 时剩 40；P2 原需 42，在 30 时剩 32。P3 完成后，P2 优先值 10 仍高于 P1 的 1，所以先补 P2。若误让 P1 先跑，会同时改变 P1、P2 的完成时刻。
</details>

<a id="q29"></a>
## 29｜2024-24：终止本进程不等于必然杀掉子进程

![2024-24 原题](../bank/2024/q24.png)

OS 终止进程要回收其设备、内存及 PCB 等本进程资源，B/C/D 是一般收尾。子进程是另一个执行主体，可能由系统接管或按 OS 规则处理，**不一定必须终止子进程，选 A**。第一笔划出“这个进程拥有的资源”与“另一个进程是否也终止”两类结果。

<details open><summary>与 20 的父子独立性</summary>

父子各有 PCB 和地址空间；父终止不自动等于子终止。具体 OS 的孤儿收养与父子生命周期规则可以不同，题句的“**不一定**”只需否定必然性。
</details>

<a id="q30"></a>
## 30｜2025-25：单链表的队首快，按优先级插入要找位置

![2025-25 原题](../bank/2025/q25.png)

单链表按优先级有序，高优先级在头。取队首进程直接读头指针并更新为下一结点，`O(1)`；新进程要维持顺序，最坏需从头比较至插入位置，`O(n)`，**选 C（插入 O(n)，选出 O(1)）**。第一笔把一次插入拆为“找位置 + 改指针”，不能只数改指针的常数次。

<details open><summary>与 0731 的复杂度计数接上</summary>

若已经给了插入位置，改几条链确是常数；题只给新进程的优先级，没有位置，必须比较现有结点。选出过程的队首已按优先级排好，不需要再次扫描 n 个进程。复杂度算完整操作而非最后一步。
</details>

## 30 题收束：保底与加速

拿起不了笔时先问三件事：**谁正在执行？它是缺 CPU 还是缺资源？当前候选集合里谁优先？** 数值题画到达、抢占、完成三类时刻，再算等待 `周转−服务`；错项先排掉“未到达可被选”“片尽就阻塞”“到达就算调度”“共享物理页等于共享地址空间”。这能保住至少一条排错线。
