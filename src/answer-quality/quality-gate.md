# Answer｜互动教学质量门槛

> 本规则从0731九道题的实际讲解和多次纠偏中形成。它约束后续 `src/MMDD-answer.md` 的教学质量，不规定统一排版，也不要求每题写成相同长度。

## 1. 当前教学任务

用户已经开始直接做真题，没有时间先完整翻书或听课。因此不能假定相关章节已经学过，也不能把“零基础”理解成重新讲一本教材。每道题都要完成一件更实际的事：让用户即使起初没有思路，也知道第一步看什么、第二步怎样推进，并逐步形成可以迁移到下一题的考场反应。

目标是408达到105+，所以解释是否优秀，不看概念覆盖得多不多，而看它能否提高以下能力：读出题干的有效条件、找到可执行的第一步、排除有诱惑力的错误路线、处理相邻变式，并在后续题目中减少重新教学的成本。

## 2. 一道题应当怎样展开

### 先按正常读题顺序走

不要先宣布答案，再从答案倒推一条必然正确的路线。应当按照一个初学者看到题目的顺序处理：每读到一个条件，就说明它现在提供了什么、尚且不能推出什么，以及下一步最便宜的动作是什么。

如果题干依次出现“升序”“合并成降序”“最坏情况”，就依次处理：已有顺序能提供什么便利；输出方向是否迫使重新排序；最坏情况要求哪些数据都被处理。不能把三个词揉成一句标准结论。

### 给出能够真正迈出的第一步

“分析复杂度”“观察代码”“根据定义判断”都不算第一步。合格的第一步必须能直接写在草稿上，例如：

```text
把 i 的前三个实际取值写出来。
把递归调用展开到基例。
先确认题目问的是数值还是执行次数。
把一次操作拆成定位和后续移动。
```

没有思路时，先让用户动起来，再从这个动作中生长出方法。

### 正确路线与排错能力同时建立

不能只说明为什么正确答案成立。对于有诱惑力的错误方向，要讲清三件事：它为什么看起来合理；它偷偷使用了什么不成立的前提；下次看到什么信号可以及时停下。

例如不能只说“不是 `n log n`，而是 `n`”。应当指出：把“外层有 `log n` 轮”和“内层最大达到 `n`”直接相乘，相当于假设每一轮内层都执行 `n` 次；但实际各轮是 `1，2，4，……`，所以必须求和。

### 每题只增加必要的 i+1

后面的题可以调用前面已经讲过的动作，并在此基础上增加一个新判断。没有参与当前题理解和选项裁决的概念，不提前加入。

不得突然使用尚未解释的术语，例如在只需要理解有序合并的阶段强行引入某种插入法。若一个术语确实不可避免，必须在首次使用时直接说明它做了什么以及为何此处需要它。

## 3. 如何对待用户的错误与分歧

首次作答只能证明选择结果，不能证明当时的心理过程。不得写“你当时一定是因为……”或根据某个旧选项虚构思路。可以说“这道题存在一条容易走进去的路线”，然后客观还原它，并交给当前对话判断它是否命中了真实问题。

用户提出的新疑问优先级高于预先准备的讲稿。它通常说明上一步解释虽然能推出答案，却没有补上真正缺失的中间层。此时应直接回答疑问所在的关系，不复述整题，也不把它重新包装成一套更大的理论。

不能用“不是A而是B”代替纠错。真正的纠错必须解释：A是怎样被联想到的、哪一个条件使A失效、今后用什么判断把A挡住。否则只是塞入新答案，没有增加能力。

## 4. 深度与表达边界

“不拘泥于题目”是要求提炼可迁移的思考动作，不是把单题扩成整章理论；“生动”是让推理过程有推进、有转折、能看见陷阱，不是添加与题目无关的比喻和故事。

优先直接讲对象之间的真实关系。比喻只有在它能减少理解步骤时才使用；若还需要额外解释比喻本身，就删掉。不要用“工作量”“拉链”等替代词遮住代码实际发生的动作。

Markdown只用于提升理解：代码块展示实际执行过程，公式承载数量关系，表格用于并列比较。不得用大量标题、单句成段和重复总结制造一种看似完整的讲义。

篇幅由真实卡点决定。不能因为追求全面而把九题重新讲几遍，也不能在被要求收束时只剩几条口号。判断标准是：关键的中间推理和主要陷阱是否保留，重复答案和装饰性内容是否删除。

## 5. 复杂度题的专用动作

复杂度题首先确认“在数谁”。通常是在数整段算法中某个基本操作随输入规模增加而执行多少次；变量最终的数值不必等于运行时间。

随后按以下顺序处理：

```text
1. 输入规模是什么？
2. 哪个动作被反复执行？
3. 控制变量实际经过哪些值？
4. 每个值对应多少次基本动作？
5. 各轮应当相乘还是相加？
6. 最紧的增长阶是什么？
```

必须区分程序变量与轮数。若 `i*=2`，第 `k` 轮的 `i` 是 `2^(k-1)`，不是 `k`。只有内层每轮成本固定时，才能直接用“轮数 × 每轮成本”；内层依赖外层变量时，应写出逐轮工作量并求和。

用户询问“这种复杂度是怎么设计出来的”时，说明代码能力层面的因果：停止边界决定最终走到哪里，更新方式决定经过哪些值，循环主体决定每轮做多少工作。也要说明真实算法通常从任务所需操作出发，复杂度由操作组织方式产生，不是为了凑一个 `O(n)` 而随意拼循环。

复杂度选择题默认寻找最紧的量级。应明确区分：`log² n = o(n)` 表示增长严格慢于 `n`；它也属于宽泛的 `O(n)`，但自身的准确量级是 `Θ(log² n)`。

## 6. 0731现场形成的固定约束

| 教学曾经偏到哪里 | 后续固定怎样处理 |
| --- | --- |
| 围着题目逐行翻译，像检查用户是否看懂代码 | 从题干出发教第一步，同时提炼邻近题仍能使用的判断 |
| 只证明正确答案，没有建立排除能力 | 还原错误选项成立所需的条件，指出本题缺少哪一条件 |
| 过度形式化，堆理论和文字 | 只讲能参与当前判断的关系，并及时回到题目 |
| 为了“生动”强加比喻和例子 | 优先展示变量、边界、数据和操作的真实变化 |
| 擅自猜测用户当时为何选某项 | 只描述客观可能的陷阱，不把陷阱归因给用户 |
| 提前引入头插法等未出现的知识 | 遵守 i+1，只补当前题不可缺少的一层 |
| 忘记说明到底在算谁的复杂度 | 先确定输入规模与被计数的基本动作 |
| 见两层循环就相乘 | 先检查内层是否随外层变化，必要时列项求和 |
| 只会算现成代码，没解释代码为什么这样写 | 增加“任务—边界—更新—每轮动作—总量”的实现视角 |
| 收官时重新讲完整套题，或缩成几句空话 | 保存完整答案档案；现场收官只提炼能力变化和关键坑 |

## 7. 从教学现场整理 Answer 的步骤

原始对话不能直接倾倒进仓库，也不能只抽取最终答案。整理时按以下顺序处理：

1. 按题号收集原讲解、用户追问、纠偏和最后澄清，避免遗漏后续才补齐的关键关系。
2. 删除寒暄、重复道歉、无效比喻、来回确认和已经被推翻的讲法，但保留“为什么被推翻”。
3. 将有效内容恢复成一条从题干到答案的连续教学路线；不能留下只有看过聊天才能理解的残句。
4. 把具体分歧转写为旁边题也能使用的判断，但不把单题扩写成整章教材。
5. 独立复核题目、答案、代码执行过程和渐进结论，不能因为现场最终达成一致就跳过正确性检查。
6. Answer 服务快速学习与复习；教学上下文单独保存，供后续回答校准，不把质量管理内容混入复习正文。

## 8. 每题交付前的检查

回答前快速检查：

- 一个完全没学过该点的人，是否知道第一笔该写什么？
- 是否在不知道答案的顺序下仍能走到结论？
- 是否解释了主要错误路线为什么有诱惑力、又在哪里失效？
- 是否误把旧作答当成了用户心理证据？
- 是否引入了当前题用不到的新术语、新理论或比喻？
- 是否回答了用户刚刚提出的真实疑问，而不是继续原讲稿？
- 最后留下的判断能否在下一道相近题中直接调用？

若其中任何一项不满足，应改写对应部分，而不是在答案末尾追加一段补丁。
