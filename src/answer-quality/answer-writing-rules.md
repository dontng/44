# Answer 写作与审核规则｜以题代学

> 把用户对 `src/MMDD-answer.md` 的要求落成可执行、可检查的规则。写作者与审核者共用：审核者的产出是**改好的 answer**，不是评语。与 [quality-gate.md](quality-gate.md)、[learning-system.md](learning-system.md) 一致；与用户当下的明确指令冲突时，以指令为准。

## 0. 目的与读者

读者：四战考研，408 目标 105+；认识代码（`while`、递归、指针不必从头解释），但没有时间看书听课。

`MMDD-answer.md` 针对同名的题单 `src/MMDD.md` 逐题解析。它只做一件事：**读者靠这道题补上做对它所必需的知识，并带走换壳变式能直接动手的做法。** 判断标准：合上它以后，是否少看了一节书、同类题能否自己下手。

它同时服务两种用法，缺一不可：**一遍过**（读得动）和**复盘**（隔几天回来，十秒内找到本题的起手、关键机制、陷阱）。

## 1. i+1 链：本规则的主线

- **i 是读者当前已具备的能力，1 是解决本题所需的新知识。** 每题只跨一个台阶；做完后 i 增加 1。
- 第 1 题用起点能力解；第 2 题用「起点 + 第 1 题」解；第 n 题用前 n−1 题累积的能力解。**严禁使用尚未在前面讲过的知识**。若某个术语或机制必须出现，它就是本题的那个“1”，必须首次出现时讲清它实际怎样运作。
- 每题先明确（用一两句，不必成栏目）：
  - 本题直接调用前面哪几题的什么能力（带回链，如“沿用 01 的写前几项”，不重抄）；
  - 本题新增的那一个台阶是什么；
  - 这一个台阶只含必需的那一层，当前题用不到的一律不提前讲。
- 审核时按顺序检查：在读到第 n 题时，是否使用了第 n 之后才讲的东西？是否有一个台阶被拆成两三个同时新增？是否有前面已讲的能力被重新教了一遍？
- 日期之间同理：新的日期继承前面日期已讲过的内容，查 [learning-ledger.md](learning-ledger.md) 确认哪些已成为可调用能力，不得凭空假设。

## 2. 动笔与审核前

1. **读 `src/MMDD.md`**：它是题单，题目以图片嵌在其中（图片文件存放在 `bank/`，那只是素材库，不是读题入口）。打开图片逐字读题干和全部选项；结果表里的“答案”列用于核对，不替代独立解题。
2. **独立解一遍**，得到自己的答案和每个选项的裁决，再与题单核对。不一致时先复查图和计算。
3. 找出本题的**承重机制**（即 i+1 的那个“1”）：读者若没学过这一块，哪条知识缺失会卡死？
4. 只读与本题和 i+1 链相关的文件，不为“审核”通读质量文档或无关日期。

## 3. 内容要求（不是栏目，不得做成每题相同的小标题或句式）

- **能落到草稿纸的第一步**：写出前几项、展开前两层递归、算出一个具体地址、画出指针改动前后。“观察”“分析”“由定义可得”不算。
- **按读题顺序推进**：读到哪个条件，就说它给了什么、没给什么，再走下一步；不先亮答案再倒推。
- **补机制，不只给结论**：新台阶要讲到读者能预测下一步实际发生什么（变量取值、指针指向、内存位置、比较次数）；公式要有来源。
- **选项逐个裁决**：每个选项成立需要什么前提、题面哪条证据使它不成立；诱惑性强的错误路线要拆开：为什么看起来合理、偷用了什么前提、看到什么信号该停。不得编造排除理由。
- **考场直觉**：严谨推导太重时（夹逼、取整讨论），给出一眼看量级或结论的做法，二者不得冲突；严谨部分只留承重一句。
- **变式边界**：改动哪个条件会改变结论；变式必须真能击穿一种假懂，不是换数字。

## 4. 文件头（跳转链接与正文之间）

顺序：跳转链接 → 大写文件名标题 → **本篇速览** → 正文。速览是导航与复盘入口，不是正文，也不是 GPT 自己觉得重要的总结。固定只放这几样，且必须能在 30 秒内扫完：

1. **进入本篇时已有 / 读完新增**：各一行（始终可见），对应 i 与 i+n。“已有”必须能在 ledger 或前一篇里找到出处；“新增”按题序列出各题的台阶。
2. **速览表，放进 `<details>` 折叠**（所有 answer 统一）：`题号（链到锚点）| 新增台阶 | 起手 | 最易错 → 先看什么`，每题一行。起手必须是可执行的动作；“最易错”写成“诱人的错误 → 该看的信号”。**不放答案，也不放用户的历史作答**——答案在各题正文开头，作答记录在 `data/` 与题单的结果表里，不在 answer 中重复。
3. **跨题反复出现的信号**：折叠区内表格下方，一行一个，注明对应题号。

不放：对上一篇的回顾性总结、重复正文的答案推导、流程说明、“这不是速记表”之类的自述。若本篇与上一篇有真实的承接，只在“已有”里点名所调用的旧台阶。

## 5. 版式：用 Markdown 把重点“排出来”，不堆文字


目标：打开一题，视线能直接落在**起手、关键步骤、答案、陷阱**上，其余内容在需要时才读。

1. **答案与结论前置**：每题开头（题图之后）先给一小块“起手 + 答案”，让复盘者不读正文也能拿到要点；正文是对它的展开。
2. **一个段落只讲一件事**，不超过约 4 行。出现“首先/其次/另外”串起的长段，拆开。
3. **并列内容用表格**：多选项裁决、多种写法对比、多轮取值，一律表格，不写成连续长句。典型：选项 | 成立需要什么 | 题面证据 | 结论。
4. **推进过程用代码块或编号列表**：变量取值、调用展开、指针变化、逐轮执行，用等宽块逐行写出，不用文字描述。
5. **加粗只用于一处要点**：每题加粗限于答案、新台阶的定义、陷阱的信号词；一段里加粗不超过两处，不得整句加粗。
6. **公式单独成行**，只写承重的几行；推导细节折叠。
7. **折叠区**（`<details>`）放：严谨证明、取整细节、题外拓展、旧台阶回看。不得把必要机制折叠到读者无法继续的地步（见 [learning-system.md](learning-system.md)：必要知识不能伪装成可跳过的拓展）。
8. **用 `> ` 引用块或 `>[!WARNING]` 之类标出陷阱**，一题最多一两处，避免“处处是重点”。
9. 每题的**标题要带出这一题的新台阶**，复盘者只扫标题就能想起来。
10. 禁止：整页同一种段落堆叠；每题固定“小标题+同样句式的收尾”；大量单句成段；重复总结。

## 6. 表达

- 每题的写法由这道题决定：有的三行草稿加一个陷阱，有的拆五个选项，有的是一段机制说明。禁止所有题共用同一结构与收尾。
- 不写“本题考查……”“这是一道经典题”；不写寒暄、鼓励、道歉；不根据旧作答推测读者当时怎么想。
- 比喻只在能减少理解步骤时使用；若比喻本身还要解释，就删。
- 篇幅由卡点决定：保留关键中间推理和主要陷阱，删重复答案和装饰；既不扩成教材章节，也不缩成口号。

## 7. 审核者怎么做

审核 = **读题、做题、对照 answer、直接改好**。

1. 按第 2 节读 `MMDD.md` 并独立解题。
2. 逐题检查：
   - 题干读错、漏读？答案、裁决、计算、渐进阶是否都对？
   - i+1：是否用了后面才讲的知识？新台阶是否讲到可预测下一步？是否一个题塞了多个台阶？
   - 第一步是否可执行？错误路线是否真实拆解？
   - 版式：重点是否一眼可见？有没有长段堆叠、该用表格没用、该用代码块没用？复盘能否十秒找到起手和陷阱？
   - 是否沿用了模板化结构和收尾？
3. **发现就改文件**，改完复算一遍。不输出“到位的点/冗余的点/总评/审核结论”，不复述 answer 本身。
4. 向用户汇报只写：改了哪里、为什么改、哪些地方因条件含糊没把握、需要用户拍板的事。没有改动的题不表扬。
5. 一次一篇：处理完并核对后再进下一篇。

## 8. 交付前自检

- [ ] 我读了 `MMDD.md` 里的原题图，并独立解出答案？
- [ ] 本题只用了前面已讲的能力，且只新增了一个台阶？
- [ ] 认识代码、没学过这一块的人，读完能写出第一步？
- [ ] 新台阶讲到可预测下一步？
- [ ] 每个选项有依据，最诱人的错误路线被拆开？
- [ ] 文件头有速览表且起手可执行；每题开头有“起手+答案”，重点一眼可见，没有长段堆叠？
- [ ] 并列内容用了表格，推进过程用了代码块？
- [ ] 这一题的写法由题目决定，不是照搬上一题？
- [ ] 公式、数值、结论逐项复算过？

任何一项不满足，改对应部分，不在末尾追加补丁。
