## 01｜2011-43：8 位截断之后再解读 signed

![2011-43 原题](../bank/2011/q43.png)

**（1）寄存器。** `x=134=86H`，`y=246=F6H`；`m=x` 和 `n=y` 赋给8位 signed `int` 后，在题设补码机器模型中位型未变，但解释为 `m=−122`、`n=−10`。无符号 `z1=x−y=−112 mod256=90H`，`z2=x+y=380 mod256=7CH`。所以 **R1=86H、R5=90H、R6=7CH**。

**（2）m 与 k1。** `m=86H`（按 signed 值−122）；`k1=m−n=−122−(−10)=−112=90H`。题要“用十六进制”，两个位型分别 **86H、90H**。

**（3）一套加法器。** 减法经 `A+(~B)+1`，有符号和无符号共用8位 ALU，差别是结果/标志怎样解释：无符号借位/进位看 CF；signed 范围看 OF。

**（4）OF。** 加法同号相加却得到异号；减法异号相减却得到与被减数异号。`k1=−112` 在 `−128..127` 内，**不溢出**；`k2=m+n=−132` 超出，8位回绕为 `7CH`，**溢出**。`z1,z2` 是 unsigned 模256 运算，不用 signed OF 裁判它们。

<details open><summary>先保存位，再读数值</summary>`F6H` 当 unsigned 是246、当 signed 是−10；`86H` 当 unsigned 是134、当 signed 是−122。不能把 `m=x` 直接说成数学整数134再做 signed 运算。本题按题设8位补码机器的截断模型说明；标准 C 对不可表示的 unsigned→signed 转换允许实现定义处理。</details>

## 02｜2017-43：整数上界与 float 精度是两道关

![2017-43 原题](../bank/2017/q43.png)

**（1）n=0 的循环。** `n` 为 unsigned，`n−1` 得 `FFFFFFFFH`；`i` 从0递增后回绕，`i<=FFFFFFFFH` 永真，故死循环。若 `i,n` 都为 signed int，`0−1=−1`，第一次 `i=0<=−1` 为假，循环不执行并返回1，即 `f(0)`。

**（2）n=23。** 数学值 `2^24−1=00FFFFFFH`，32位 int 可精确存；float 单精度可精确表示24位有效二进制数，因此 f1 与 f2 返回的 int 都为 **00FFFFFFH**。

**（3）n=24。** f1 的整数 `2^25−1=33554431`；float 在此量级相邻可表示数间距为2，逐次运算后舍入到 **33554432.0**。f2 返回值发生差异是**精度舍入**，不是浮点溢出；返回 int 时得到33554432。

**（4）n=31 与 int 最大可行 n。** `2^32−1` 的低32位为 `FFFFFFFFH`，按题设机器回绕解释为−1。signed int 可表示的最大该形数是 `2^31−1`，即 **n=30**；再大即越界。严格 C 语义下有符号溢出未定义，不能把机器回绕当成可移植 C 保证。

**（5）f2(127)。** `7F800000H` 是 IEEE754 **正无穷大**；到 `n=127` 时理论值临近 `2^128`，舍入/溢出到正无穷。保持有限不溢出的最大 **n=126**；完全精确无舍入的最大 **n=23**。还要防 `n=0` 的 unsigned 循环问题，这三个上界都是在 n>0 正常执行的前提下谈数值。

<details open><summary>三个“坏掉”分别在哪一步</summary>循环边界 `n−1` 的类型决定能否结束；整数结果超过有符号范围决定 f1 是否还能表示；float 即使没溢出，也可能因24位有效精度先丢掉尾部的1。不要把精度损失叫成无穷大，也不要以 f2(127) 推出 f2(24) 已溢出。</details>

## 03｜2019-45：递归调用、相对位移与乘法溢出

![2019-45 原题](../bank/2019/q45.png)

**（1）调用。** 求 f(10) 的 f1 调用实例共有 **10** 次（10 到1）；其中源码第16行的递归 `call f1` 执行 **9** 次。第16行 `call` 是递归调用指令。

**（2）跳转。** 第12行 `jle` 是条件转移（`n<=1` 走基例）；第20行 `jmp` 是无条件转移，执行到此处一定改变控制流；第16行 `call` 也必跳到被调用函数并保存返回位置。

**（3）下一地址与编码。** 第16行地址 `00401025H`，5字节长，下一条 **0040102AH**（第17行）。目标 `00401000H`，位移为 `00401000−0040102A=−2AH=FFFFFFD6H`。机器码 `E8 D6 FF FF FF`；偏移量在低地址先存 `D6`，所以是**小端**。

**（4）13! 不同。** `13!=6227020800` 超32位有符号范围；低32位 `7328CC00H`，按题设回绕解释为 **1932053504**。要返回正确值，递归函数及乘积的计算/返回类型都改为足够宽的整数，如 `long long f1(int n){ return n>1 ? (long long)n*f1(n-1) : 1LL; }`。仅把最后的接收变量变宽，前面的32位乘法已经失真。

**（5）OF 与异常。** signed `imul` 的64位数学乘积若不能由低32位作符号扩展恢复，高32位便不等于低32位符号位的全0/全1扩展，**OF=1**。要在该条件转异常处理，可在 `imul` 后用 **`jo`**（溢出则跳）。

<details open><summary>“调用次数”与“call 执行次数”分账</summary>最外层调用 f1(10) 也是一次函数调用，但它不是函数体第16行执行出的；只要把 10,9,...,1 写下来，就能分别数出10个栈帧与9次自调用。位移一律从当前指令**末尾**算，不是从 opcode 地址算。</details>

## 04｜2021-43：格式字段各自约束什么

![2021-43 原题](../bank/2021/q43.png)

**（1）宽度与容量。** 字长16位，ALU 操作数宽 **16位**；20位字节地址可寻址 `2^20 B=1MB`；指令寄存器 IR 为 **16位**；MAR需 **20位** 承载地址，MDR按8位数据总线为 **8位**。指令本身16位，取指可分两次经8位总线，不能因此把 MDR 误写成16位。

**（2）操作与寄存器。** R型 `op1` 4位，可定义 **16种**；I/J型6位主操作码，`000000` 留给 R，合计最多 **63种**；寄存器字段2位可编码 **4个**通用寄存器。

**（3）解码与运算。** `01B2H=000000 01 10 11 0010`：R型 `rs=1,rt=2,rd=3,op1=0010`，故 **R3←R1−R2**。`R1=B052H`、`R2=0008H` 时结果 **B04AH**，在 signed16范围内；`01B3H` 的 op1=0011 是**乘法**：`B052H` 按 signed16 是 −20398，乘 8 得 −163184，超出 −32768..32767；低16位结果为 **8290H，溢出**。初始 R3 的 `0020H` 被覆盖。判断 OF 看 signed 输入与结果的符号关系，而不是见最高位为1就报溢出。

**（4）I型访存偏移。** 若 imm 为有符号偏移，应先**符号扩展**再与基址相加；零扩展会把负偏移错误解释为大正数。

**（5）无条件跳转。** **J型**带 `target`，把形式地址写到 PC 低10位；它就是题中无条件转移的格式。I型也可编码条件转移，但不能在没有额外约束时直接把 I 型的所有指令说成无条件跳转。

<details open><summary>位宽不要互相借</summary>MAR 对应地址线20位；MDR对应数据线8位；ALU与通用寄存器对应字长16位。题面分别给这些值是为了让你判断它们属于不同路径，不是让一个“机器字长”统管全部字段。</details>

## 05｜2023-44：按机器码长度走，才能正确取下一条

![2023-44 原题](../bank/2023/q44.png)

**（1）第20条地址。** 第19条起址 `004010AEH`，机器码 `C7 84 82 00 20 42 00 0A 00 00 00` 共 **11字节**，所以下一条（第20条）为 **004010B9H**。逐个按图中的实际字节数计，不凭汇编语句长短猜。若肉眼计数，分组为 `C7`(1)+`84`(1)+`82`(1)+`00 20 42 00`(4)+`0A 00 00 00`(4)=11。

**（2）跳转。** 第2条 `EB 09` 是短相对位移，下一地址 `0040107BH`，加 `09H` 得 **00401084H**；第7条 `7D 32` 同为短相对位移，下一地址 `0040108AH`，加 `32H` 得 **004010BCH**。相对量的基点是各自下一条指令。

**（3）有效地址。** `mov [ecx+edx*4+00422000H],0AH` 是**带比例的基址/变址加位移**内存寻址；`ecx` 保存行号 i 对应的字节偏移 `i×64×4`，`edx` 保存列号 j，首址为 `00422000H`。位移字节 `00 20 42 00` 对应00422000H、立即数 `0A 00 00 00` 对应10，均按**小端**排。

**（4）首次执行第19条。** 其指令位于已执行过前面同一代码页 `00401000H`，所以**取指本身**不因首次执行该条而缺页；首次写 `a[0][0]` 可能引发**数据页**缺页，二者要分开。第19条全11字节从 `...0AE` 到 `...0B8`，未跨4KB代码页边界。

<details open><summary>只记住一个动作</summary>先把机器码划成 opcode、寻址字节、位移、立即数四段，再求“起址+总字节数”；位移跳转再以这个**下一地址**为起点。数组下标由行长64和元素4字节翻译为字节地址。</details>

## 06｜2024-44：小端字节还原元素，页号用地址高位

![2024-44 原题](../bank/2024/q44.png)

此题的 `slli` 编码依赖[2024-43 给出的指令格式](../bank/2024/q43.png)，不能只看本题裁图凭常见 MIPS/RISC-V 格式猜。

**（1）寄存器。** `slli r4,r2,2` 把 i 左移两位生成字节偏移，`add r4,r3,r4` 因此 R3 为 **数组 a 首址**、R2 为 **i**；`lw` 读 a[i]，`add r1,r1,r5` 因此 R1 为 **sum**。

**（2）按地址取数。** 首址 `0013DFF0H`，i=5，元素地址 `+5×4=0013E004H`；该处四字节 `DC EC FF FF` 按小端还原为 **FFFFECDCH**。初始 sum `00001332H`，相加后低32位 **0000000EH**。4KB页号为地址右移12位，`0013E004H` 的页号 **0013EH**；此次至少需要 a[0] 到 a[5] 六个 int，从 `...DFF0` 起的前四个占该页末16B，后两个落下一页，因此数组 a **至少跨2页**。题未给完整数组长度，不能推出实际最多跨几页。

**（3）编码/改 short。** 原题43给的位段依次 `000000 | shamt(2) | rs1(2) | 010 | rd(4) | 0010011`，合成 **00212213H**。若 a 的元素变 short，占2B，计算 `a[i]` 字节偏移应左移**1位**，汇编变 `slli r4,r2,1`；其余操作是否改为 short 访存还需与题设完整程序配套，本小问只问这条移位形式。

<details open><summary>为何至少两页</summary>数组不是从页首开始，而从 `...DFF0` 距页末16B；四个4B元素正好填满第一页，a[4]、a[5] 已进入下一页。题只给本次 i=5，没有给数组总长度，切勿借用另一道题的数组规模。</details>

## 07｜2025-44：补码除法的数据通路与异常

![2025-44 原题](../bank/2025/q44.png)

**原图需先核对的冲突。** 文字说 `x` 在 **R2**、数组首址在 **R3**；`idiv R1,R3` 这行的旁注却写 `{R0,R1}/R2`。按字面 R3 是数组地址，无法得到题目要求的 x 除数。本题以下依**文字与旁注共同指向的 R2=x**解释，不把 R3 地址当作 x。

**（1）初始寄存器。** `d[i]=87654321H` 最高位1，作为 signed32 是负数；`scov` 将其符号扩展到 `{R0,R1}`，故除法器初始余数寄存器 **R=FFFFFFFFH**、商/被除数低部 **Q=87654321H**，除数寄存器 **Y=000000FFH**。控制逻辑里的 **Cn** 是迭代计数器；每一位除法由 ALU 作加或减（配合移位与符号判定），而非普通一次算出商。

**（2）异常。** 两类典型输入：**x=00000000H** 时除0，d 可取任意值如 `00000001H`；**d=80000000H、x=FFFFFFFFH** 时最小负数除−1，数学商 `2^31` 不可装入 signed32。CPU 检测后保存异常现场（断点 PC/状态及原因），切换到内核/异常态并跳到异常向量，由处理程序决定终止、报告或恢复。除法器不应把溢出的商悄悄写回当作正常结果。

<details open><summary>从符号扩展理解 R 与 Q</summary>32位负数扩成64位，左半部补32个1，右半部保留原位型；除数 `0xFF` 在题目给的 `x=0xff` 是正的255，不能误当8位 signed 的−1。R/Q/Y 的初始化是进入迭代**之前**的机器状态，不是最终商和余数。</details>
