## 01｜2009-16：相对转移从取完指令后的 PC 起算

<img src="../bank/2009/q16.png" alt="2009-16 原题" width="505" style="display:block; width:31.56em; max-width:100%; height:auto;">

**新增**：相对寻址的目标＝PC＋位移，其中 PC 是取指结束后的值。**起手**：写 PC 随取指的变化。**答案：C（2008H）**

```
取操作码   PC: 2000H → 2001H
取位移量   PC: 2001H → 2002H     （指令共 2 字节，取完）
目标 = 2002H + 06H = 2008H
```

A 2006H＝2000H＋6，位移加在首址上，与“取指时 PC 自动加 1”不符；B 2007H＝2001H＋6，只计 1 字节，指令有 2 字节；D 2009H＝2003H＋6，取指只加到 2002H。

读法：题图未写位移量单位；按字节得 2008H，按字（2 字节）为 200EH，不在选项中，故取字节。

## 02｜2011-16：偏移寻址都是“寄存器＋D”，间接是“取内容”

<img src="../bank/2011/q16.png" alt="2011-16 原题" width="533" style="display:block; width:33.31em; max-width:100%; height:auto;">

**新增**：把寻址方式翻译成有效地址 EA 的公式。**起手**：对每个选项写 EA。**答案：A（间接寻址）**

| 选项 | EA | 寄存器＋D？ |
|---|---|---|

## 03｜2011-17：无新台阶（同 0813-02）

<img src="../bank/2011/q17.png" alt="2011-17 原题" width="534" style="display:block; width:33.38em; max-width:100%; height:auto;">

与 [0813-02](0813-answer.md#q02) 同题，仅调用旧结论：无符号 a>b ⇔ 减法无借位且结果非零，即 CF＝0 且 ZF＝0，即 `¬(CF+ZF)=1`。**答案：C**。这里按“减法的 CF＝借位”读。

用 8 位代入各选项（`a−b`），亮出一个 a、b 使其与 `a>b` 不符：

| 选项 | 反例 | 标志 | 式子值 | 实际 |
|---|---|---|---|---|
| A `CF+OF=1` | a＝01H, b＝02H | CF＝1 | 1（转移） | a<b，不该转 |
| B `¬SF+ZF=1` | a＝10H, b＝F0H | SF＝0, ZF＝0 | 1（转移） | a<b，不该转 |
| D `¬(CF+SF)=1` | a＝05H, b＝05H | CF＝0, SF＝0 | 1（转移） | a＝b，不该转 |
| C | 以上三例均为 0；a＝FFH, b＝01H 得 1 | | | 吻合 |

## 04｜2013-17：先算 EA，再按 EA 取操作数

<img src="../bank/2013/q17.png" alt="2013-17 原题" width="538" style="display:block; width:33.63em; max-width:100%; height:auto;">

**新增**：EA 是地址，操作数是 EA 处的内容，是两步。**起手**：写两行。**答案：D（4000H）**

```
EA     = R + D   = 1000H + 2000H = 3000H      （沿用 02 的偏移公式）
操作数 = M[3000H] = 4000H
```

A 1000H 是 R 的内容、B 2000H 是 D（或 M[1000H]，未被访问），都只是 EA 的加数；C 3000H 是 EA，题问“访问到的操作数”。

M[1000H]、M[2000H] 都不在路径 `R+D→M[EA]` 上。

## 05｜2014-17：定长指令的位移字段＝总长减去其他字段

<img src="../bank/2014/q17.png" alt="2014-17 原题" width="524" style="display:block; width:32.75em; max-width:100%; height:auto;">

**新增**：按题干把每个字段列出来逐项扣位。**起手**：写 `32−8−4−4`。**答案：A**

```
总长 32 位
操作码（含寻址方式位）          8   题面直接给
源操作数：寄存器直接寻址 → 寄存器号     4   16 个寄存器 → 2⁴
目的操作数：基址寻址 → 基址寄存器号     4   “可使用任一通用寄存器”
偏移量  32−8−4−4 = 16
```

源与目的各是一个操作数，各需自己的寄存器字段，所以扣两次 4。16 位补码范围按 [0812-21](0812-answer.md#q21)：`−2¹⁵ … 2¹⁵−1 = −32768 … +32767`。

B、D 的正端比负端大 1，补码做不到；C 是 17 位补码范围，字段只有 16 位；D 两处都不符。

## 06｜2016-17：括号＝取内容，嵌套＝执行次序

<img src="../bank/2016/q17.png" alt="2016-17 原题" width="541" style="display:block; width:33.81em; max-width:100%; height:auto;">

**新增**：选项里的 `( )` 读作“……的内容”，最内层先做。**起手**：取具体值代入。**答案：C**

题给 I 是寄存器**编号**，D 是形式地址，所以 `(I)` 才是该寄存器里的值。取 I＝2，R2＝1000H，D＝20H，M[1020H]＝3000H：

```
先变址   (I)+D   = 1000H + 20H = 1020H
后间址   ((I)+D) = M[1020H]    = 3000H   → 这个内容就是 EA
```

A `I+D`：I 是编号，不是值（代入得 2＋20H）；B `(I)+D`：到 1020H 为止，缺后间址那次取内容；D `((I))+D`：先取 M[1000H] 再加 D，次序是先间址后变址，与题面相反。

信号：D 在括号最内层 ⇒ 先加 D；在最外层 ⇒ 最后才加。

## 07｜2017-15：每轮要变的量，放在寄存器里

<img src="../bank/2017/q15.png" alt="2017-15 原题" width="448" style="display:block; width:28.00em; max-width:100%; height:auto;">

**新增**：访问数组时，EA 要在**同一条指令**的反复执行中变化。**起手**：对每个选项问“循环第 1、2 轮 EA 变吗”。**答案：D**

| 选项 | EA | 循环中 | 与题面 |
|---|---|---|---|
| A 相对 | PC＋D | 循环反复执行同一条指令，PC 值相同 ⇒ EA 不变 | 访问不到下一个元素 |
| B 寄存器寻址 | 操作数就在寄存器里（[13](#q13) 细讲） | 没有访存 | 数组在内存里，按下标走不了 |
| C 直接 | D | D 写在指令里，每轮相同 | 同上，只能访问一个元素 |
| D 变址 | R＋D | 把 D 取为首址、R 取为下标，每轮改 R | 符合 |

信号：题面“按下标顺序”＝每轮要变的量，放变址寄存器（公式同基址，见 [02](#q02)）。

## 08｜2017-16：扩展操作码——短操作码留空位，长操作码补编码

<img src="../bank/2017/q16.png" alt="2017-16 原题" width="515" style="display:block; width:32.19em; max-width:100%; height:auto;">

**新增**：定长指令里，不同格式的操作码长度不同，短前缀没用完的码值可以向下扩展。**起手**：设指令长 L，列两种格式的操作码位数。**答案：A（24 位）**

```
三地址：操作码 L−18 位，需 ≥29 条
二地址：操作码 L−12 位，需 107 条 —— 比三地址多 6 位
```

L＝24：三地址操作码 6 位，共 64 个码值，用掉 29，剩 35 个。把剩下的某个 6 位码值当作“这是二地址指令”的前缀，再接 6 位，每个前缀可编 64 条；35×64＝2240 ≥ 107，足够。

| 选项 | 说明 |
|---|---|
| A 24 | 如上，可行；且是各选项中最小的 |
| B 26 | 把 29＋107＝136 条放进同一个操作码空间，需 8 位，8＋18＝26；题面写的是两种格式，不必共用 |
| C 28、D 32 | 比 A 长，可行但不是“至少” |

下界：L＝22 时三地址操作码 4 位，16 个码值 <29，不行；L＝23 位数上可行（3×64＝192 ≥ 107），但指令按字节编址应为整字节，故 24；24 也是最小选项。

## 10｜2019-15：无新台阶（同 0812-17）

<img src="../bank/2019/q15.png" alt="2019-15 原题" width="501" style="display:block; width:31.31em; max-width:100%; height:auto;">

与 [0812-17](0812-answer.md#q17) 同题，调用 [04](#q04) 的 EA 与 [05](#q05) 的补码。**起手**：把 `FF12H` 当 16 位补码化成十进制。**答案：D（EFFF FF15H）**

```
D = FF12H = −(10000H−FF12H) = −EEH = −238
EA = F0000000H − EEH = EFFFFF12H        ← 操作数首字节（地址最小的字节）
大端：12 34 FF 00 依次放在 EA, EA+1, EA+2, EA+3
LSB = 00H 在 EA+3 = EFFFFF15H
```

A、B（F000FF12H、F000FF15H）是 FF12H 零扩展相加，与“补码表示”不符；C 是 EA，大端中 EA 放最高字节，LSB 在 EA＋3。

## 11｜2020-16：条数定操作码位数，同一字段由寻址方式解释

<img src="../bank/2020/q16.png" alt="2020-16 原题" width="588" style="display:block; width:36.75em; max-width:100%; height:auto;">

**新增**：从指令条数反推操作码位数。**起手**：算 2ⁿ ≥ 48。**答案：A（0～255）**

```
操作码  2⁵=32 <48 ≤ 2⁶=64 → 6 位
方式码  4 种方式 → 2 位
地址字段 16−6−2 = 8 位
```

题问“直接寻址”：字段本身就是地址，没有负地址，按无符号 `0 … 2⁸−1`。

B 0～1023 是 10 位无符号＝16−6，没扣题面“4 种寻址方式”的 2 位；C −128～127 位数对，但是字段按补码位移解释（相对寻址）的范围，直接寻址按地址；D 10 位补码，位数与解释都不符。

## 12｜2022-19：扩展操作码两层，逐层“剩余前缀×64”

<img src="../bank/2022/q19.png" alt="2022-19 原题" width="479" style="display:block; width:29.94em; max-width:100%; height:auto;">

**新增**：在 [08](#q08) 的一层扩展上再扩一层。**起手**：自上而下列每层的剩余码值。**答案：D（128）**

16 位、地址码 6 位：

```
二地址：操作码 16−12 = 4 位 → 16 个码值，用 12，剩 4
一地址：操作码 4+6 = 10 位 → 4×64 = 256 个码值，用 254，剩 2
零地址：操作码 10+6 = 16 位 → 2×64 = 128 条
```

“最多”：每层只占用必需的码值，不浪费，剩下的才能全部往下扩展，所以 128 是最大值。

B 2 是一地址层剩下的码值数，它们还能各自加 6 位；C 64 是只剩 1 个码值时的结果，而剩 2 个；A 0 与剩 2 个可扩展码值矛盾。

## 13｜2023-17：寄存器里的值当数还是当地址，看寻址方式

<img src="../bank/2023/q17.png" alt="2023-17 原题" width="548" style="display:block; width:34.25em; max-width:100%; height:auto;">

**新增**：地址码是寄存器号时，有“寄存器直接”和“寄存器间接”两条路。**起手**：设 R3＝1000H，走两遍。**答案：A**

```
寄存器直接：操作数 = R3          = 1000H
寄存器间接：EA = R3 = 1000H，操作数 = M[1000H]   （沿用 04 的“EA 再查内存”）
```

两种方式里编号都是 3、寄存器内容都是 1000H，差别只有指令里的寻址方式（[06](#q06) 图中的 M 字段）。

B 编码方式（补码、BCD 等）定位串的数值意义，不定它是不是地址；C、D：两条路径中编号、内容都相同，区分不了。
