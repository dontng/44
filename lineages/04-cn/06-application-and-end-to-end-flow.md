## 一、域名系统（DNS）

### 1. 层次架构、查询方式与资源记录

DNS 采用树形分布式结构，避免单台中心服务器单点故障和拥塞，包含四类服务器：
- **根域名服务器**（全球 13 个逻辑组，靠任播部署镜像）：知道所有顶级域名服务器的地址；
- **顶级域名服务器（TLD）**：管理 `.com`、`.cn` 等顶级域，知道对应权限服务器的地址；
- **权限（权威）域名服务器**：保存具体组织域名到 IP 的最终映射；
- **本地域名服务器（Local DNS）**：不属于 DNS 层次树内部，由运营商或校园网提供，充当主机的代理跑腿角色。

**两种查询方式**：
- 主机 $\to$ 本地域名服务器：**递归查询**（主机托付给本地 DNS，坐等最终 IP）；
- 本地域名服务器 $\to$ 外网各级服务器：**迭代查询**（根服务器和顶级服务器只告诉你下一跳该问谁，绝不替全球用户做递归，否则会瞬间扛不住）。

**传输层选择**：
- 日常解析默认用 **UDP 53 端口**（无连接，1 RTT 拿结果）；
- 两种情况切用 **TCP 53 端口**：① 响应超过 512 字节被截断（首部 `TC = 1`），客户端改用 TCP 重查（现代 EDNS0 可将 UDP 载荷扩展到 4096B）；② 主从域名服务器之间做**区域传送**同步整个数据库。

**五种核心资源记录（RR）**：
- **`A`**：域名 $\to$ IPv4 地址；**`AAAA`**：域名 $\to$ IPv6 地址；
- **`NS`**：子域 $\to$ 权限域名服务器主机名（父域返回 `NS` 时必须附带该服务器的 `A` 记录，即**粘合记录 Glue Record**，防止查服务器 IP 陷入死循环）；
- **`CNAME`**：别名 $\to$ 规范主机名（CDN 常用）；
- **`MX`**：邮件域 $\to$ 邮件服务器主机名（拿到后再查它的 `A` 记录）。

> **真题推演 1（2020-40：DNS 缓存命中 vs 未命中的总耗时）**
> 主机 H 与本地 DNS 在同一局域网（局域网时延忽略），访问外网任意服务器 $\text{RTT} = 10\text{ ms}$。求访问 `www.abc.com` 纯文本首页的最短和最长耗时。
> - **HTTP 阶段固定耗时**：TCP 三次握手 1 RTT（10ms）+ 发 HTTP GET 并收网页 1 RTT（10ms）= **20ms**（最容易漏算 TCP 握手的 10ms）。
> - **最短时间（本地 DNS 缓存命中）**：DNS 外网耗时 0，总计 $0 + 20 = \mathbf{20\text{ ms}}$。
> - **最长时间（缓存全空）**：本地 DNS 依次迭代问根、`.com` 顶级、`abc.com` 权限三台服务器，花 3 RTT（30ms），加上 HTTP 的 20ms，总计 **$50\text{ ms}$**。

## 二、超文本传输协议（HTTP）与版本演进

### 1. 报文格式、方法、状态码与 Cookie

HTTP 是纯文本行协议，请求报文和响应报文都用**空行 `\r\n`** 分隔首部与实体主体。
- **常用方法**：`GET`（查资源，安全、幂等）、`POST`（提交数据/建资源，不安全、不幂等）、`HEAD`（只回首部不回实体，安全、幂等）、`PUT`（上传替换，不安全、幂等）、`DELETE`（删除，不安全、幂等）。
- **高频状态码**：
  - `200 OK`（成功）、`206 Partial Content`（范围请求/断点续传）；
  - `301`（永久重定向）、`302`（临时重定向）、`304 Not Modified`（协商缓存命中，直接用本地副本）；
  - `400`（请求语法错）、`401`（未认证）、`403`（拒绝访问）、`404`（资源不存在）；
  - `500`（服务器内部错）、`502`（网关收到无效响应）、`504`（网关超时）。
- **无状态与 Cookie/Session**：TCP 在传输层是有状态的，但 HTTP 在应用层是**无状态**的。为了记住用户登录状态、购物车和个性化偏好，服务器通过 `Set-Cookie` 把标识发给浏览器，浏览器后续请求自动带上 `Cookie`，服务器再查对应 Session。
  - **2026-40 避坑**：Cookie 的典型用途是会话管理、个性化推荐、购物车，但**不能缩短 Web 对象的响应时间**（缩短响应时间靠的是浏览器缓存、代理缓存或 CDN，带 Cookie 反而让请求首部变长）。

### 2. 非持久连接 vs 持久连接（RTT 计算）

设网页包含 1 个主 HTML 和 $N$ 个内嵌图片/对象，忽略发送时延：
- **HTTP/1.0 非持久连接（串行）**：每个对象单独建 TCP 连接、传完即关，每个对象花 2 RTT（1 握手 + 1 请求），共 **$2(N + 1)\text{ RTT}$**。
  - 例如 **2024-40**：1 个页面 + 7 个小图像（共 8 个对象），非持久且不支持并行连接，总共需要 $8 \times 2 = \mathbf{16\text{ RTT}}$。
- **HTTP/1.1 持久连接（非流水线）**：只建 1 次 TCP 连接，对象一个接一个请求，共 **$1 + 1 + N = (N + 2)\text{ RTT}$**。
- **HTTP/1.1 持久连接（流水线）**：建 1 次 TCP 连接，拿到 HTML 后一口气把 $N$ 个对象请求并发发出去，共 **$3\text{ RTT}$**（但存在应用层队头阻塞）。

> **真题推演 2（2022-40：HTTP/1.1 持久连接与 TCP 慢开始联动）**
> 主机 H 用 HTTP/1.1 持久连接访问服务器 S，$\text{RTT} = 10\text{ ms}$，HTML 占 1 MSS，内嵌 1 幅 3 MSS 的图像，不考虑发送时延。求全部收完的最短时间。
> - **第 1 RTT（0~10ms）**：TCP 握手建连，服务端初始 `cwnd = 1 MSS`。
> - **第 2 RTT（10~20ms）**：H 请求 HTML，S 发 1 MSS HTML，H 确认后 S 的 `cwnd` 慢开始翻倍为 **2 MSS**。
> - **第 3 RTT（20~30ms）**：H 请求 3 MSS 图像，但此时 S 的 `cwnd` 只有 2 MSS，**这一轮只能先发 2 MSS**！H 收到并确认后，S 的 `cwnd` 涨到 4 MSS。
> - **第 4 RTT（30~40ms）**：S 发完最后 1 MSS 图像。
> - 总计 4 RTT = **$40\text{ ms}$**（如果忽略 TCP 慢开始窗口限制，就会误算成 30ms）。

### 3. HTTP/1.1 $\to$ HTTP/2 $\to$ HTTP/3 演进

- **HTTP/1.1**：基于 TCP，文本格式，单连接串行处理，有应用层队头阻塞。
- **HTTP/2**：仍基于 TCP，引入**二进制分帧**、单连接内多 Stream **多路复用**、**HPACK 首部压缩**（静态表 + 动态表 + 哈夫曼编码）。消除了应用层队头阻塞，但底层还是同一条 TCP 连接，一旦丢包仍会触发 **TCP 传输层队头阻塞**。
- **HTTP/3**：底层改用基于 **UDP 的 QUIC 协议**，不同 Stream 独立确认重传，**消除了跨 Stream 的传输层队头阻塞**；合并传输与 TLS 1.3 握手（初次 1-RTT，会话恢复支持 0-RTT）；用连接 ID 标识连接，手机在 Wi-Fi 和 5G 间切换不断线。

## 三、FTP 与电子邮件系统

### 1. FTP（文件传输协议）的双连接与主/被动模式

FTP 把控制命令和文件数据拆成两条独立的 TCP 连接（**带外控制**），避免传大文件时取消命令被堵死：
- **控制连接（TCP 21）**：**持续连接**，整个登录会话期间保持打开，传输登录、目录切换等命令；
- **数据连接（主动模式 TCP 20 / 被动模式随机临时端口）**：**非持续连接**，每次传一个文件或拉取目录列表时临时建立，传完立即关闭。因此**传 $n$ 个独立文件共建立 $1 + n$ 条 TCP 连接**。

两种数据连接建立模式：
- **主动模式（PORT）**：客户端发 `PORT` 报自己的端口，**服务器用 20 端口主动连客户端**。缺点：客户端在 NAT 或防火墙后面时，外部主动连入常被拦截。
- **被动模式（PASV）**：客户端发 `PASV`，服务器开一个随机端口告诉客户端，**客户端主动连服务器**，天然穿透客户端防火墙和 NAT。

### 2. 电子邮件系统（SMTP / MIME / POP3 / IMAP）

用户电脑不会 24 小时开机，因此邮件通过常在线的邮件服务器中转寄存，采用**“推 + 拉”**模型：
- **发送端 UA $\to$ 发送方邮件服务器 $\to$ 接收方邮件服务器**：全程用 **SMTP（TCP 25，推协议 Push）**。发件服务器连收件服务器前，需先查 DNS 的 **`MX` 记录**。
- **接收方邮件服务器 $\to$ 收件人 UA**：用 **POP3（TCP 110）** 或 **IMAP（TCP 143，拉协议 Pull）**。
  - **2025-40 考点**：POP3 只负责用户代理从邮件服务器**读取邮件**，绝不用于发信或服务器间中继；且在同一个 TCP 连接里可以连续发送多次 `RETR` 命令收取多封邮件。

**MIME 与 Base64**：SMTP 原生只支持 7 位 ASCII 文本，发中文、图片、PDF 附件需靠 **MIME** 扩展（不取代 SMTP）。MIME 常用 **Base64 编码**：每 **3 个 8 位字节（24 bit）** 拆成 **4 个 6 位组**映射成可打印 ASCII 字符，体积膨胀率为 **$\frac{4}{3} \approx 133.3\%$**（末尾不足 3 字节时，剩 2 字节补 1 个 `=`，剩 1 字节补 2 个 `=`）。

**POP3 与 IMAP 的区别**：
- **POP3**：离线式存取，分认证、事务、更新三阶段；`RETR` 下载后邮件不会立刻消失，只有发 `DELE` 标记并在最后发 `QUIT` 正常退出时服务器才真正删除。不支持多设备状态同步，也不支持服务器端文件夹。
- **IMAP**：在线式集中存储，邮件长期留在服务器上，**多设备实时同步已读/删除/分类状态**，支持创建服务器端文件夹和先下摘要、按需下载大附件。

## 四、跨网段通信全流程综合（DNS + ARP + 交换机 + NAT）

把全书协议串成一条真实时间线，看两道经典的 408 全栈大题：

### 案例 1：浏览器输入 URL 到发出 HTTP 请求（2021-47）

局域网内主机 H1（端口 4）、静默主机 H2（端口 3）、本地域名服务器（端口 1）、默认网关路由器 R（端口 2）全连在同一台初始转发表为空的交换机 S 上。H1 在浏览器输入 `www.abc.com`：

1. **先走 DNS 解析**：应用层协议是 **DNS**，逐层向下封装为 **`DNS → UDP → IP → 以太网帧`**（注意 ARP 是独立协议，不在 DNS 的封装链里）。
2. **第 1 次 ARP 与交换机自学习**：H1 不知道本地 DNS 的 MAC，发 **ARP 请求广播帧**（目的 MAC 全 F）。S 从端口 4 收到，学到 `(H1 的 MAC, 端口 4)`，并向端口 1、2、3 泛洪——**H2 收到第 1 个广播帧**。本地 DNS 从端口 1 单播回 ARP 应答，S 学到 `(DNS 的 MAC, 端口 1)`。随后 H1 与 DNS 单播交互拿到 `www.abc.com` 的公网 IP（单播精准转发，H2 收不到）。
3. **第 2 次 ARP 与交换机自学习**：H1 发现目标 IP 不在本子网，要交给默认网关 R，但不知道 R 的 MAC，再发 **ARP 请求广播帧**（目的 MAC 全 F）。S 向端口 1、2、3 泛洪——**H2 收到第 2 个广播帧**。R 从端口 2 单播回 ARP 应答，S 学到 `(R 的 MAC, 端口 2)`。
4. **TCP 握手与 HTTP 请求**：H1 经 R 向公网服务器发起 TCP 三次握手（帧的目的 MAC 填 R 的 MAC，目的 IP 填 Web 服务器 IP）并发送 HTTP GET，全程单播转发，H2 收不到。
5. **结果核对**：
   - 交换机 S 的转发表里**只有 H1（口 4）、本地 DNS（口 1）、路由器 R（口 2）三项**，绝没有从未发过帧的 H2；
   - H2 收到的帧至少 **2 个**，都是 **ARP 请求广播帧**，目的 MAC 均为 **`FF-FF-FF-FF-FF-FF`**。

### 案例 2：两个重叠私网经公网跨 NAT 访问（2020-47）

右侧私网主机 H2（`192.168.1.2`）经 NAT 路由器 R3（公网口 `203.10.2.6`）、公网路由器 R1、NAT 路由器 R2（公网口 `203.10.2.2`）访问左侧私网的 Web 服务器（私网 IP 碰巧也是 `192.168.1.2`）：

- **必须做的配置**：
  1. 在 **R2** 上配**静态 NAT 端口映射（DNAT）**：将 `203.10.2.2:80` 映射到内网服务器 `192.168.1.2:80`；
  2. 在 **R3** 上配**动态 NAT / NAPT（SNAT）**：把右侧内网出站报文的源 IP 转换为 `203.10.2.6`；
  3. 主机/服务器配好各自默认网关，R2、R3 配好指向 R1 的默认路由。
- **IP 数据报沿途的源/目的 IP 变化**：

| 报文所处位置 | 源 IP | 目的 IP | 说明 |
| :--- | :---: | :---: | :--- |
| H2 刚发出（右侧私网） | `192.168.1.2` | `203.10.2.2` | 目的 IP 必须填 R2 公网地址，绝不能填 `192.168.1.2`（否则会发给自己） |
| 经 R3 转发后（公网） | **`203.10.2.6`** | `203.10.2.2` | R3 做 **SNAT**，改源 IP 为自己公网口，目的 IP 不变 |
| 经 R2 转发后（左侧私网） | `203.10.2.6` | **`192.168.1.2`** | R2 做 **DNAT**，查静态映射表改目的 IP 为内网服务器，源 IP 不变 |
