# 数据链路层：组帧、差错控制与滑动窗口可靠传输

> 返回：[全科知识脉络总览](../README.md)

把「组帧与透明传输」「差错控制（汉明码与 CRC）」「滑动窗口协议（停等、GBN、SR）」放在同一条脉络里，是因为它们按顺序解决了点对点链路上的三个核心问题：先把物理层送来的连续 0/1 比特流切成一帧一帧，再检查这帧在传输中有没有出错，最后如果帧丢了或坏了，用确认、重传和滑动窗口把相邻结点之间的数据既不丢不乱、又高效率地传过去。

---

## 一、数据链路层定位与组帧（透明传输）

### 1. 相邻结点间的流量控制

在分层体系中，**数据链路层负责两个相邻结点之间的流量控制与差错控制**（2022-33 专门区分了这一点），防止发送方发得太快淹没相邻接收方的帧缓存；而跨越多跳网络的端到端流量控制属于传输层（TCP），物理层只管传比特流，不做流量控制。

### 2. 四种组帧方法与透明传输

物理层传过来的是没有边界的连续比特流，数据链路层必须给网络层的 IP 分组加上帧头、帧尾，标出每一帧的起止位置（**组帧**）。同时还要保证**透明传输**：哪怕数据载荷里碰巧出现了和帧边界一模一样的比特串，接收端也不能把它误判为帧结束。

| 组帧方法 | 定界与透明传输做法 | 特点与缺陷 |
| :--- | :--- | :--- |
| **字符计数法** | 帧首部第 1 个字段写明本帧总字符数（含计数字段本身） | 只要计数字段错 1 位，接收端就彻底找不准后续所有帧的边界，已基本淘汰 |
| **字符填充法** | 用特殊控制字符定界（如 `SOH`/`EOT`）；数据中出现控制字符或转义符 `ESC` 时，在前面插入 `ESC`；接收端收到 `ESC` 后删掉它并还原后面的字符 | 面向字节/字符，依赖字符编码 |
| **零比特填充法** | 用固定标志 `01111110`（`0x7E`，中间连续 6 个 1）定界；发送端在数据里**每遇到连续 5 个 `1`，立刻在后面插 1 个 `0`**；接收端**每遇到连续 5 个 `1` 且后跟 `0`，就把这个 `0` 删掉** | 面向比特，与数据内容无关，硬件移位实现快；HDLC 和同步 PPP 采用 |
| **违规编码法** | 用物理层编码里正常数据不会出现的非法波形做边界（如曼彻斯特编码中全高或全低无跳变） | 零比特开销，但依赖底层物理编码（传统局域网使用） |

### 3. 两种典型点对点协议：PPP 与 HDLC

考纲常把广域网点对点协议 **PPP** 和 **HDLC** 拿来对比：
- **PPP（点对点协议）**：
  - **面向字节**；异步链路用字符填充（`0x7D` 转义 `0x7E`），同步链路用零比特填充。
  - 由三部分组成：IP 数据报封装方法、**LCP（链路控制协议**，建链、协商参数、PAP/CHAP 认证）、**NCP（网络控制协议**，如 IPCP 协商分配 IP）。
  - **只检错、不纠错、不可靠**：有 CRC 校验，出错直接丢弃；**没有帧序号、没有确认 ACK、没有重传、没有流量控制**（把可靠性留给上层 TCP）。
- **HDLC（高级数据链路控制）**：
  - **面向比特**，统一采用零比特填充法；包含信息帧（I 帧）、监督帧（S 帧）、无编号帧（U 帧）。
  - **提供可靠传输**：有帧编号、确认、重传和滑动窗口流量控制。

## 二、差错控制：汉明距离、CRC 与海明码

### 1. 最小汉明距离与检错、纠错能力

两个等长码字对应位不同的个数叫**汉明距离**（即两码字按位异或后 `1` 的个数）。一个码集中任意两个合法码字汉明距离的最小值，称为**最小汉明距离 $d_{\min}$**。它直接决定编码的检错和纠错上限：
- **检出不超过 $e$ 位错**：$d_{\min} \ge e + 1$，即 $e = d_{\min} - 1$；
- **纠正不超过 $t$ 位错**：$d_{\min} \ge 2t + 1$，即 $t = \lfloor (d_{\min} - 1) / 2 \rfloor$；
- **同时检 $e$ 位错并纠 $t$ 位错（$e > t$）**：$d_{\min} \ge e + t + 1$。

> **真题推演 1（2025-34 最小汉明距离求检错与纠错能力）**
> 给定 4 个 8 位码字：`1001 1010`、`0101 1100`、`1111 0000`、`0000 1111`。
> - 两两算异或里 `1` 的个数：前 5 对的距离都是 4，最后一对（`1111 0000` 与 `0000 1111`）的距离是 8。
> - 因此最小汉明距离 $d_{\min} = 4$。
> - 检错能力 $e = 4 - 1 = \mathbf{3}$ 位；纠错能力 $t = \lfloor (4 - 1) / 2 \rfloor = \mathbf{1}$ 位（如果错 2 位，出错码字到两个合法码字的距离可能都是 2，接收端没法唯一判断原码字是谁，所以不能纠 2 位错）。

### 2. 循环冗余校验（CRC）

CRC 是数据链路层最常用的检错码（以太网帧尾 FCS 就是 32 位 CRC），核心运算是**模 2 除法**（按位异或，不进位也不借位）：
1. 双方约定生成多项式 $G(X)$，设最高次幂为 $r$，对应 $r+1$ 位二进制除数；
2. 发送端在原始数据 $M$ 后面补 $r$ 个 `0`，用除数做模 2 除法，上商规则是“当前被除数最高位为 1 商 1、为 0 商 0”，得到 $r$ 位余数 $R$（即帧检验序列 **FCS**）；
3. 把余数 $R$ 拼到 $M$ 末尾发出（$T = M\cdot 2^r \oplus R$）；
4. 接收端用同一个除数对收到的整串比特做模 2 除法：**余数为全 0 则认为未出错并接受；余数非 0 则直接丢弃**。

> **真题推演 2（2023-37 接收端 CRC 校验）**
> 已知生成多项式对应除数 $G = 10011$（$r = 4$），接收端收到以 `10111` 开头的 9 位比特串，哪一种末尾 4 位能通过校验？
> - 先用前 5 位和除数异或：$10111 \oplus 10011 = 00100$；
> - 剩下高位为 `100`，拼上末尾 4 位得到 7 位序列 `100xxxx`；
> - 要使余数为 `0000`，`100xxxx` 必须刚好被 `10011` 整除，把除数左对齐 2 位就是 `1001100`，所以 `xxxx` 必须是 **`1100`**，即完整码串 `101111100` 无错。

**CRC 的两个必考辨析**：
- **CRC 会漏检吗？会。** 若传输中叠加的差错图样 $E(X)$ 恰好是生成多项式 $G(X)$ 的非零倍式（$E(X) \bmod G(X) = 0$，例如 $G=1011$ 时恰好翻转了对应的 3 位），接收端算出的余数依然是 0，就会漏检。不过在实际链路中漏检概率极低。
- **无差错接受 $\ne$ 可靠传输**：CRC 只能保证“交给网络层的帧基本没比特错”，出错的帧被链路层直接丢掉了。如果不配合确认和重传，丢掉的帧就永远没了；只有加上确认和重传，才叫“发送什么就准确收到什么”的可靠传输。

### 3. 海明码（纠正 1 位错）

海明码能检测并纠正 1 位错（$d_{\min} = 3$）。设数据位 $k$ 位、校验位 $r$ 位，总长 $n = k + r$，校验位要能表示“无错”和“$k+r$ 个位置中哪一位错”共 $k+r+1$ 种状态，因此必须满足海明不等式：
$$2^r \ge k + r + 1$$

**手算示例（4 位数据 $D_4 D_3 D_2 D_1 = 1010$，偶校验）**：
1. $k = 4$ 代入 $2^r \ge 5 + r$，得 $r = 3$（校验位 $P_1, P_2, P_3$），总长 7 位。
2. 校验位固定放在编号为 $2^{i-1}$（即第 1、2、4 位）的位置，数据位依次填入第 3、5、6、7 位：
   - $H_7(D_4)=1,\; H_6(D_3)=0,\; H_5(D_2)=1,\; H_4(P_3),\; H_3(D_1)=0,\; H_2(P_2),\; H_1(P_1)$。
3. 按位号的二进制分解列偶校验方程（异或和为 0）：
   - $P_1$ 管最低位为 1 的位（1, 3, 5, 7）：$P_1 \oplus 0 \oplus 1 \oplus 1 = 0 \implies P_1 = 0$；
   - $P_2$ 管次低位为 1 的位（2, 3, 6, 7）：$P_2 \oplus 0 \oplus 0 \oplus 1 = 0 \implies P_2 = 1$；
   - $P_3$ 管最高位为 1 的位（4, 5, 6, 7）：$P_3 \oplus 1 \oplus 0 \oplus 1 = 0 \implies P_3 = 0$。
   - 发出海明码：$H_7\sim H_1 = \mathbf{1010010}$。
4. **纠错**：若第 5 位翻转为 0（收到 `1000010`），接收端重算三组偶校验得到指错字：
   - $S_1 = 0\oplus 0\oplus 0\oplus 1 = 1$，$S_2 = 1\oplus 0\oplus 0\oplus 1 = 0$，$S_3 = 0\oplus 0\oplus 0\oplus 1 = 1$；
   - $S_3 S_2 S_1 = 101_2 = 5$，直接锁定第 5 位出错，将其取反即可恢复。
   - 注意标准海明码只能纠 1 位错；如果同时错 2 位，指错字会指错位置导致“越纠越错”。若要“纠 1 位、检 2 位”，需额外加 1 位全局奇偶校验位（使 $d_{\min}=4$）。

## 三、滑动窗口协议与信道利用率精算

### 1. 三种可靠传输协议的机制对比

为了不丢失、不重复、不失序，数据链路层引入确认（ACK）、超时重传和滑动窗口。三种协议的区别集中在一张表里：

| 协议 | 发送窗口 $W_T$ | 接收窗口 $W_R$ | $n$ 位序号下的窗口上限 | 确认方式 | 乱序到达帧 | 超时重传动作 |
| :--- | :---: | :---: | :--- | :--- | :--- | :--- |
| **停止-等待（SW）** | $1$ | $1$ | $W_T = 1, W_R = 1$（只需 1 位序号） | 逐帧确认 | 丢弃 | 只重传当前帧 |
| **后退 N 帧（GBN）** | $> 1$ | 固定为 $1$ | $1 < W_T \le 2^n - 1$ | **累计确认** | **直接丢弃**（无缓存），重发上次已收帧的 ACK | **回退重传**自超时帧起的所有已发未确认帧 |
| **选择重传（SR）** | $> 1$ | $> 1$ | $W_T + W_R \le 2^n$（对称时 $W_T = W_R \le 2^{n-1}$） | **逐帧独立确认** | **缓存下来**，等缺帧补齐后一并按序上交 | **只重传超时那 1 帧** |

**为什么窗口大小要受序号位数 $n$ 限制？**
- **GBN 为什么不能取 $2^n$**：设 $n=3$（序号 0~7），如果 $W_T = 8$，发送方一口气发出 0~7 号帧，接收方全收到后期待新一轮的 0 号帧；万一反向 ACK 全丢，发送方超时重发旧的 0 号帧，接收方分不清它是“新一轮的 0 号”还是“旧的重传 0 号”，就会重复收下旧数据。所以必须留至少 1 个空闲序号，$W_T \le 2^n - 1 = 7$。
- **SR 为什么要求 $W_T + W_R \le 2^n$**：因为接收窗口也会往前滑。发送方超时重发的最老未确认帧，不能落进接收方已经滑动过去的新窗口里，否则同样会新旧混淆。对称情况下（$W_T = W_R$）各分一半，最大只能取 $2^{n-1}$。

> **真题推演 3（2024-37 选择重传 SR 窗口滑动与重传）**
> 甲乙采用 3 位序号的 SR 协议，最大窗口 $W_T = W_R = 2^{3-1} = 4$。甲连续发出 F0、F1、F2、F3（发送窗口 `[0, 1, 2, 3]` 满），其中 F1 丢失。
> - **$t_1$ 时刻**：甲收到 $\text{ACK}_0$。因为 F0 是窗口左沿，窗口向前滑动 1 格变为 `[1, 2, 3, 4]`，甲立刻发出新帧 **F4**。
> - **随后**：甲收到 $\text{ACK}_2$，只能把 F2 标记为已确认，由于左沿 F1 没确认，窗口不动。
> - **$t_2$ 时刻**：F1 定时器超时。SR 是独立重传，甲只重发丢失的 **F1**（不会像 GBN 那样把 F2、F3 也跟着重发）。

> **真题推演 4（2023-35 相同序号位数下三种协议的最大利用率比较）**
> 序号均占 3 位，比较停等（$U_1$）、GBN（$U_2$）、SR（$U_3$，设 $W_T=W_R$）在无差错时的最大信道利用率。
> - 很多人凭直觉以为“SR 更高级所以利用率最高”，结果选错！
> - 无差错时最大利用率只看**最大发送窗口能开多大**：停等 $W_1 = 1$，SR 为了防重叠窗口被对半切，$W_3 = 2^{3-1} = 4$，而 GBN 发送窗口可以开到 $W_2 = 2^3 - 1 = 7$。
> - 因为 $W_1 < W_3 < W_2$，所以在相同链路上三者最大信道利用率满足 **$U_1 \le U_3 \le U_2$**（若都能跑满 100% 则取等号）。

### 2. 信道利用率与发送窗口计算

设数据帧发送时延 $T_f = L/R$，往返传播时延 $\text{RTT} = 2\tau$，确认帧发送时延 $T_{\text{ack}}$。从开始发第 1 帧到收到第 1 帧的 ACK，一个完整发送周期耗时为：
$$T_{\text{cycle}} = T_f + \text{RTT} + T_{\text{ack}}$$

如果发送窗口为 $W$，一个周期内发送端实际在发数据的时间是 $W \cdot T_f$，信道利用率**绝不能超过 100%**：
$$U = \min\left(1,\; \frac{W \cdot T_f}{T_f + \text{RTT} + T_{\text{ack}}}\right)$$
有效吞吐率 $= U \times R$。要让信道跑满 100%，所需最小窗口为 $W_{\min} = \left\lceil \frac{T_f + \text{RTT} + T_{\text{ack}}}{T_f} \right\rceil$。

> **真题推演 5（2020-36 不可忽略 ACK 发送时延的停等协议）**
> 停等协议，链路速率 $10\text{ kbps}$，单向传播时延 $\tau = 200\text{ ms}$，数据帧长 $1000\text{ B}$，**确认帧也长 $1000\text{ B}$**。
> - 数据帧发送时延 $T_f = \frac{1000 \times 8}{10000} = 0.8\text{ s}$；
> - 确认帧发送时延 $T_{\text{ack}} = \frac{1000 \times 8}{10000} = 0.8\text{ s}$（题干给了长度，绝对不能忽略！）；
> - 往返传播时延 $2\tau = 0.4\text{ s}$；
> - 周期总耗时 $= 0.8 + 0.4 + 0.8 = 2.0\text{ s}$，信道利用率 $= \frac{0.8}{2.0} = \mathbf{40\%}$。如果漏算 $T_{\text{ack}}$ 就会掉进 $0.8 / 1.2 = 66.7\%$ 的陷阱。

> **真题推演 6（2025-47 第 2 问：卫星链路 GBN 窗口与序号位数反推）**
> 卫星信道速率 $200\text{ kbps}$，单向传播时延 $\tau = 0.24\text{ s}$，帧长 $1500\text{ B}$，忽略 ACK 发送时延，要求信道利用率不低于 80%。
> - 单帧发送时延 $T_f = \frac{1500 \times 8}{200 \times 10^3} = 0.06\text{ s}$；
> - 一个周期 $T_{\text{cycle}} = 0.06 + 2 \times 0.24 = 0.54\text{ s}$；
> - 由 $\frac{W \times 0.06}{0.54} \ge 0.8$ 得 $W \ge 7.2$，取整至少 **$W = 8$**；
> - 采用 GBN 协议，由 $2^n - 1 \ge 8 \implies 2^n \ge 9$，因此帧序号至少需要 **$n = 4$ 位**。
