程序静静躺在磁盘上只是一堆指令，加载到内存跑起来才叫“进程”。为了在有限的 CPU 核心上同时服务几十上百个任务，操作系统先给每个任务建档案（PCB）并管好它的生命周期状态，再把“占资源”和“跑代码”拆开引入更轻量的线程、补齐进程间通信（IPC）通道，最后靠调度机制和调度算法决定下一毫秒到底把 CPU 交给谁。把这四块按“实体 $\to$ 状态 $\to$ 轻量化与通信 $\to$ 调度决策”的顺序串起来，整章逻辑一气呵成。

## 一、进程、PCB 与状态流转

### 1. 进程与 PCB
- **进程是资源分配的基本单位**，每个进程拥有**独立的虚拟地址空间**（独立的页表和页表基址）。哪怕是用 `fork()` 创建出来的父子进程，虽然底层可能用写时复制暂时共享只读物理页框，但在逻辑上和页表上依然是**各自独立的虚拟地址空间**，绝不是“共享虚拟地址空间”（`2020-29`）。
- **PCB（进程控制块）** 是进程存在的唯一标志，存放在**内核空间**，通常按状态用链表（如就绪队列、阻塞队列）或索引表组织。里面记着四类信息：
  1. 标识符：`PID`、`PPID`、`UID`；
  2. 处理器状态（上下文）：通用寄存器、`PC`、`PSW`、栈指针；
  3. 调度与状态信息：当前状态、优先级、剩余时间片；
  4. 资源清单：页表基址、打开文件描述符表等。
- **进程的创建与终止**：
  - 创建原语：`申请空白 PCB` $\to$ `分配资源` $\to$ `初始化 PCB` $\to$ `插入就绪队列`。新进程创建后只能进入**就绪态**，绝不会直接设为执行态（`2021-24`）。
  - 终止原语：必须回收该进程占用的内存、外设和 PCB；但父进程终止时，**不一定连带终止其子进程**（`2024-24`），在 Unix/Linux 中孤儿进程会被 `init`/`systemd` 收养继续运行。
  - 原语（创建、撤销、阻塞、唤醒）要求执行不可分割，单核下通常靠**关中断 / 开中断**保证原子性。

### 2. 五状态模型与七状态（挂起）模型

进程在内存中的基本生命周期是五状态：**创建态 $\to$ 就绪态 $\leftrightarrow$ 运行态 $\to$ 终止态**，以及 **运行态 $\to$ 阻塞态 $\to$ 就绪态**。

区分**运行态 $\to$ 就绪态**和**运行态 $\to$ 阻塞态**只需要问一个问题：**它有没有在等某个外部事件或资源？**
- **运行态 $\to$ 阻塞态**（等不到东西，给了 CPU 也没法往下走）：读文件/读键盘等阻塞 I/O、申请已被占用的外设、执行信号量 `wait()`（`P` 操作）资源不足、访存发生**缺页异常**需要从磁盘调页（`2022-28`）。注意：缺页异常是硬件内中断，不是系统调用，同样会让进程阻塞。
- **运行态 $\to$ 就绪态**（自身条件全齐，只是让出了 CPU）：**时间片用完**、被更高优先级进程抢占、或者线程**主动出让 CPU**（如 `yield`，`2023-27`）。
- **阻塞态 $\to$ 就绪态**：进程阻塞后已经交出 CPU，**绝不可能自己唤醒自己**，只能由外部 I/O 中断或其他运行中的进程执行唤醒原语（如 `V` 操作）把它移回就绪队列。

当物理内存紧张时，操作系统通过**中级调度（对换）**把暂时不运行的进程换出到磁盘对换区（Swap），这就从五状态扩展出**七状态**（把就绪和阻塞各分成“活动”和“挂起”两种）：
- **阻塞 vs 挂起**：阻塞态的进程仍在**内存**里等事件；挂起态的进程被换出到了**外存磁盘**。两者都不能被低级调度直接分派 CPU。
- **高频易错点**：处于**阻塞挂起态**的进程，如果它等待的 I/O 事件完成了，中断处理程序会**直接在外存把它唤醒为就绪挂起态**，不需要先换入内存再唤醒；等以后内存宽裕了，中级调度再把它从就绪挂起换入内存变为活动就绪态。

## 二、线程与进程间通信（IPC）

### 1. 为什么引入线程？共享什么、私有什么？
进程切换不仅要保存寄存器，还要更换页表基址寄存器（`CR3`），常常带来 TLB 失效和 Cache 冷缺失，开销很大。引入**线程**后，把“资源分配”和“CPU 调度”拆开：**进程管资源，线程管调度**。同进程内的线程切换**不需要切换页表**，轻量得多。

| 归属 | 具体内容 | 容易踩的坑 |
| :--- | :--- | :--- |
| **同进程所有线程共享** | 虚拟地址空间（**代码段、全局/静态数据段、堆 Heap**）、打开文件描述符表、信号处理动作、工作目录与 UID/GID | 堆内存（`malloc` 出来的空间）是同进程线程共享的（`2026-25`）；因为共享页表，如果线程 A 拿到线程 B 栈上局部变量的指针，硬件上也能直接读写 |
| **每个线程私有** | 线程 ID（`TID`）、**程序计数器 `PC`、通用寄存器、独立的用户栈、独立的内核栈（对内核级线程而言）**、线程状态、信号屏蔽字 | 内核级线程绝不能共用同一个内核栈，否则同时陷入内核时会把彼此的调用帧踩烂（`2026-25`） |

### 2. 线程的三种实现模型
- **用户级线程（ULT，多对一 $N:1$）**：完全由用户态线程库创建和管理，内核根本不知道它们的存在（`2026-25`）。
  - *优点*：切换全程在用户态完成，0 次模式切换，极快。
  - *缺点*：① 只要有一个线程发起阻塞系统调用，内核就会把**整个进程**阻塞，其他就绪线程全跟着停摆；② **无法利用多核并行**，内核每次只给这个进程分 1 个核心。
- **内核级线程（KLT，一对一 $1:1$）**：内核为每个线程建控制块并直接调度。
  - *优点*：一个线程阻塞不影响同进程其他线程；能真正跑在多个 CPU 核心上并行。
  - *缺点*：切换要陷入内核态，开销比 ULT 大。
- **多对多模型（$M:N$，$M$ 个用户线程映射到 $N$ 个内核线程）**：折中方案，但调度库和内核配合复杂。注意：**不存在“多个内核线程映射到同一个用户线程”的倒置模型**（`2026-25`）。

### 3. 进程间通信（IPC）与信号
因为进程间虚拟地址空间互相隔离，跨进程传数据必须靠内核提供的 IPC 通道：

1. **共享存储（Shared Memory）**：内核把**同一个物理页框**分别映射到进程 A 和进程 B 的页表里。建好映射后双方直接读写内存，**不经过内核搬运数据，速度最快**；但内核不管并发冲突，用户必须自己配合信号量或互斥锁做同步。
2. **消息传递（Message Passing）**：数据打包成带边界的消息，通过内核缓冲区拷贝传递。分为**直接通信**（显式指明对方进程名 `send(P, msg)`）和**间接通信**（通过内核的信箱/消息队列中转，自带互斥和阻塞同步）。
3. **管道通信（Pipe）**：
   - **本质**：内核在**内存**中开辟的一块固定大小的循环字节流缓冲区，**不是磁盘文件**，断电或关闭后数据即消失。
   - **半双工**：只能单向流动（`fd[1]` 写、`fd[0]` 读）；要双向通信必须建**两根管道**。
   - **自带同步**：写满时写进程阻塞，读空时读进程阻塞，数据读走即消费。
   - **端关闭边界**：写端全关后，读端先把剩余数据读完，再读就返回 `0`（EOF）；读端全关后，写端再写会收到 **`SIGPIPE` 信号**（默认终止进程）。
   - **匿名管道 vs 命名管道（FIFO）**：匿名管道靠 `fork()` 继承文件描述符，只用于有亲缘关系的进程；命名管道在目录树里有个路径名和 inode，无亲缘关系的进程也能打开，但数据依然只在内存里流转、不落盘。
4. **信号（Signal）**：用于异步事件通知（如终端中断、子进程退出、`SIGPIPE`），不是传数据的队列。
   - 信号的三种处置：默认、忽略、捕获（运行用户注册的信号处理函数，在用户态执行）。`SIGKILL` 和 `SIGSTOP` 不能捕获、忽略或屏蔽。
   - **屏蔽（Mask）不等于忽略**：屏蔽只是暂时推迟递达；Linux 标准信号在屏蔽期间多次产生通常会合并成 1 次待处理状态，解除屏蔽后不会保证执行多次。信号处置全进程共享，但屏蔽字按线程私有维护。

## 三、CPU 调度机制：何时调度、怎么切换、多核怎么排

### 1. 三级调度
- **高级调度（作业调度）**：外存后备作业 $\to$ 内存就绪队列，频率最低，决定多道程序度。
- **中级调度（内存调度）**：内存 $\leftrightarrow$ 外存对换区（挂起与激活），缓解内存紧张。
- **低级调度（进程调度）**：内存就绪队列 $\to$ CPU，频率最高（几毫秒到几十毫秒一次），现代 OS 必不可少。

注意多道程序度与 CPU 利用率的关系：**绝不是进程越多 CPU 利用率越高**（`2022-23`）。并发进程太少时 CPU 容易空等 I/O；但进程多到物理内存装不下每个进程的工作集时，系统会疯狂缺页换页（抖动/颠簸），CPU 利用率反而暴跌。

### 2. 调度的时机与禁止调度的场景
- **必须/可能触发调度的常见时机**（`2021-27`）：① 当前进程正常或异常终止；② 当前进程因 I/O、缺页或 `wait()` 主动阻塞；③ 时钟中断发现时间片用完；④ 外部 I/O 中断唤醒了更高优先级的进程（中断返回前触发抢占）。
- **严禁调度的场景**：① 执行中断服务程序（ISR）期间；② 执行关中断原语期间；③ 持有内核**自旋锁**（关抢占）期间（如果带着自旋锁去睡觉，同核上另一个进程来抢这把锁就会原地死等，直接死锁）。
- **允许调度的场景**：进程在**用户态临界区**（如拿着用户互斥锁）或在内核态持有可睡眠互斥锁时，完全允许被剥夺 CPU——其他进程进不去该临界区只需阻塞等待，不会搞崩内核。
- **容易忽略的细节**：调用调度程序选出来的最优进程，如果恰好还是当前正在跑的进程，就**不会发生上下文切换**。

### 3. 上下文切换开销与数据结构
- 进程切换分为**直接开销**（保存/恢复寄存器和内核栈、运行调度算法、修改 `CR3`）和**隐性开销**（修改 `CR3` 导致 TLB 失效和 Cache 冷缺失）。
- **时间片轮转（RR）的最小依赖构件**（`2021-25`）：只需要 **时钟中断处理程序**（扣减时间片）、**PCB**（存上下文）、**就绪队列**（排队）。**阻塞队列**不是 RR 算法本身必需的（就算全是纯计算任务，RR 也能照常跑）。
- **就绪队列的链表复杂度**（`2025-25`）：如果用**单链表**按优先级从高到低存就绪进程（高优先级在队头），选出最高优先级进程只需摘队头，耗时 **$O(1)$**；但插入新进程时单链表不能二分，必须顺着链表找位置，耗时 **$O(n)$**。

### 4. 多核 SMP 调度与闲逛进程
- **公共就绪队列 vs 每核私有队列**：多核下如果共用一个全局队列，所有核心每次调度都要抢同一把大锁，严重拖慢扩展性；现代系统采用**每核私有就绪队列（Per-CPU Runqueue）**。
- **处理器亲和性**：尽量让进程留在上次跑过的核心上，复用该核的 L1/L2 Cache 和 TLB（软亲和性由调度器尽量保证；硬亲和性由系统调用强制绑定）。
- **负载均衡**：私有队列容易冷热不均，靠**推迁移**（后台定时把忙核任务推给闲核）和**拉迁移 / 工作窃取**（闲核主动从忙核队尾偷任务）平衡；迁移太勤会破坏缓存亲和性，需要在两者间折中。
- **闲逛进程（Idle，0 号进程）**：优先级全局最低，只有就绪队列完全为空时才运行，循环执行低功耗停机等待指令（如 x86 `HLT`）省电，直到下一个外中断把 CPU 唤醒。

## 四、典型调度算法与真题手算推演

### 1. 四个核心性能指标
设进程 $P_i$ 的到达时刻为 $A_i$、服务时间为 $S_i$、完成时刻为 $C_i$：
- **周转时间**：$T_i = C_i - A_i$（从到达至彻底完成的总时间）
- **带权周转时间**：$W_{T,i} = T_i / S_i \ge 1$（反映短作业“多委屈”）
- **等待时间**：$W_i = T_i - S_i$（纯计算任务在就绪队列里干等的总时间）
- **响应时间**：$R_i = \text{首次上 CPU 时刻} - A_i$

### 2. 六大经典算法速览

| 算法 | 决策规则 | 抢占性 | 会不会饥饿 | 核心特点 |
| :--- | :--- | :---: | :---: | :--- |
| **FCFS（先来先服务）** | 按到达顺序 | 非抢占 | 不会 | 简单公平，但长作业堵前面会引发**护航效应**，拖垮短作业带权周转时间 |
| **SJF（短作业优先）** | 选服务时间最短的 | 非抢占 | **会** | 所有作业**同时到达**时平均周转时间最优；长作业可能饿死 |
| **SRTF（短剩余时间优先）** | 选剩余时间最短的 | 抢占 | **会** | 动态到达下理论平均周转时间最低，但抢占切换多、长作业更易饥饿 |
| **HRRN（高响应比优先）** | 选 $R_p = 1 + \frac{W}{S}$ 最大的 | 非抢占 | 不会 | 兼顾短作业（$S$ 小）和久等的长作业（$W$ 大），每次调度要重算全队响应比 |
| **RR（时间片轮转）** | 队头轮流跑一个时间片 $q$ | 抢占 | 不会 | 响应快、适合分时交互；$q$ 太小切换开销吞噬 CPU，$q$ 太大退化为 FCFS |
| **优先级调度** | 选优先级最高的 | 可抢占/非抢占 | 低优**会** | 静态优先级易饥饿，可用**老化（随等待时间提高优先级）**缓解 |

- **多级反馈队列（MLFQ）**：现代通用调度器的核心原型。设计它必须确定四个要素（`2020-26`）：**① 就绪队列数量；② 各队列的优先级；③ 各队列内部的调度算法（如高优队列时间片短、低优队列时间片长）；④ 进程在队列间的升降级迁移规则**（新进程进顶层队列，用完时间片未完成就降一级，主动发起 I/O 保持原级不降；为防止低层长作业饥饿，每隔一定周期把所有进程统一提拔回顶层）。

### 3. 真题手算案例 1：抢占式优先级调度的“调度次数”怎么数？（结合 2022-25）

设单核采用**抢占式优先级调度**，规定**优先数越小，优先级越高**。4 个进程如下：
- $P_0$：0ms 到达，需 100ms，优先数 15
- $P_1$：10ms 到达，需 60ms，优先数 20
- $P_2$：10ms 到达，需 20ms，优先数 10
- $P_3$：15ms 到达，需 10ms，优先数 6

问整个过程共发生几次进程调度？（记住：每当 CPU 分派给一个新进程或重新切回一个被中断的进程，才算 1 次调度。）
1. **0ms**：只有 $P_0$，**第 1 次调度**分派 $P_0$。
2. **10ms**：$P_1$(20)、$P_2$(10) 到达。$P_2$ 优先级高于 $P_0$(15)，抢占！$P_0$ 剩 90ms 回就绪队列。**第 2 次调度**分派 $P_2$。
3. **15ms**：$P_3$(6) 到达，高于 $P_2$(10)，抢占！$P_2$ 已跑 5ms，剩 15ms 回就绪队列。**第 3 次调度**分派 $P_3$。
4. **25ms**：$P_3$ 跑完 10ms 退出。就绪队列里 $P_2$(10) 最高，**第 4 次调度**切回 $P_2$。
5. **40ms**：$P_2$ 跑完剩余 15ms 退出。就绪队列里 $P_0$(15) 高于 $P_1$(20)，**第 5 次调度**切回 $P_0$。
6. **130ms**：$P_0$ 跑完剩余 90ms 退出。只剩 $P_1$，**第 6 次调度**分派 $P_1$，跑至 190ms 全部结束。

一共 **6 次**调度（千万别数成 4 次——被抢占后重新切回来也要算调度）。

### 4. 真题手算案例 2：抢占式优先级调度的“平均周转时间”（结合 2023-29）

同样是抢占式优先级调度，但这一题规定**优先数越大，优先级越高**（考场审题第一件事就是圈出优先数大小方向！）。3 个进程如下：
- $P_1$：0ms 到达，需 60ms，优先数 1
- $P_2$：20ms 到达，需 42ms，优先数 10
- $P_3$：30ms 到达，需 13ms，优先数 100

顺着时间轴推：
1. **0 ~ 20ms**：$P_1$ 运行 20ms，剩 40ms。
2. **20 ~ 30ms**：$P_2$(10) 抢占 $P_1$(1)，运行 10ms，剩 32ms。
3. **30 ~ 43ms**：$P_3$(100) 抢占 $P_2$(10)，运行 13ms 后于 **43ms 完成**。
4. **43 ~ 75ms**：切回 $P_2$ 跑完剩余 32ms，于 **75ms 完成**。
5. **75 ~ 115ms**：切回 $P_1$ 跑完剩余 40ms，于 **115ms 完成**。

最后别忘了**周转时间 = 完成时刻 − 到达时刻**：
- $T_1 = 115 - 0 = 115\text{ ms}$
- $T_2 = 75 - 20 = 55\text{ ms}$
- $T_3 = 43 - 30 = 13\text{ ms}$
- 平均周转时间 $= (115 + 55 + 13) / 3 = 183 / 3 = \mathbf{61\text{ ms}}$。

### 5. 真题手算案例 3：时钟中断驱动的动态优先级 + 时间片调度（结合 2026-45）

除了“新进程一到立刻抢占”，还有一种更贴近真实内核的考法：**只在每 10ms 一次的时钟中断时检查抢占**（`2026-45`）。规则：时间片 50ms，优先数越大优先级越高，同优先级 FIFO；**因时间片用完重入就绪队列时，若优先级大于 0 则减 1，已经为 0 时保持 0；因被更高优先级抢占重入就绪队列时优先级不变**；两种情况重入队列都重置时间片为 50ms。4 个进程：`P1`(10ms到, 需95ms, 优先3)、`P2`(10ms到, 需20ms, 优先4)、`P3`(12ms到, 需40ms, 优先2)、`P4`(14ms到, 需60ms, 优先5)。
1. **时钟中断次数**：总 CPU 时间 $95+20+40+60 = 215\text{ ms}$，从 10ms 跑到 225ms，每 10ms 触发一次（10, 20, …, 220ms），共 **22 次**。
2. **调度过程（共 7 次）**：
   - `10ms`（第 1 次）：`P2`(4) 优先于 `P1`(3) 先跑。`12ms` `P3` 到、`14ms` `P4`(5) 到，但未到时钟中断，不抢占；
   - `20ms`（第 2 次）：时钟中断触发，`P4`(5) 抢占 `P2`(4，剩 10ms，被抢占优先级保持 4 回队)，**`P4` 首次运行在 20ms**；
   - `70ms`（第 3 次）：`P4` 跑满 50ms（剩 10ms），时间片用完优先级降为 4 回队；队里 `P2`(4, 20ms入队) 早于 `P4`(4, 70ms入队)，按 FIFO 跑 `P2`；
   - `80ms`（第 4 次）：`P2` 跑完，跑 `P4`(4)；`90ms`（第 5 次）：`P4` 跑完，跑 `P1`(3)，**`P1` 首次运行在 90ms**；
   - `140ms`（第 6 次）：`P1` 跑满 50ms（剩 45ms），降为 2 回队；`P3`(2, 12ms到) 早于 `P1`，按 FIFO 跑 `P3`，**`P3` 首次运行在 140ms**；
   - `180ms`（第 7 次）：`P3` 跑完，切回 `P1` 跑至 225ms 结束。
3. **参数变化影响**：时间片从 50ms 改大到 100ms，能覆盖 `P4`(60ms) 和 `P1`(95ms) 的总需求，调度顺序简化为 **`P2 → P4 → P2 → P1 → P3`**，**调度次数从 7 次减少到 5 次**；时钟中断间隔从 10ms 缩成 1ms，中断处理频率翻 10 倍，**系统开销增加**。
