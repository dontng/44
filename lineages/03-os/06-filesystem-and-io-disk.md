用户程序写下一句 `read(fd, buf, 4096)`，背后走完了一整条从逻辑文件到物理盘片的链条：先通过目录树、打开文件表和 inode 算出数据落在哪几个逻辑盘块，再穿过虚拟文件系统（VFS）、设备独立性软件、设备驱动和中断处理程序，最后由磁盘控制器按寻道调度算法（或 SSD 的闪存翻译层）把字节读进内存。把文件系统和设备 I/O 放进同一条脉络，就能把“文件名怎么变成磁盘扇区读写”彻底打通。

## 一、文件物理结构与 UNIX 混合多级索引（inode）

### 1. 逻辑结构、文件保护与四种物理分配方式
- **逻辑结构**：UNIX/Linux 采用**无结构流式文件**（平坦字节流，内部格式由应用自己解释）；数据库等场景也有定长/变长**有结构记录式文件**。
- **文件保护**：口令保护（开销小但安全性差）、加密保护（最安全但加解密耗 CPU）、访问控制列表 ACL（最精细但占空间大）、UNIX **9 位权限位**（所有者/同组/其他各 3 位 `rwx`，例如 `-rwxr-xr--` 对应八进制 `0754`）。
- **四种物理分配方式**：
  1. **连续分配**：顺序读最快、支持 $O(1)$ 随机访问，但有严重外部碎片、文件长度很难动态扩展。
  2. **隐式链接分配**：每块末尾存下一块指针，无外部碎片、易扩展，但只能顺序访问（随机访问极慢），断一块后面全丢。
  3. **显式链接分配（FAT）**：把链指针集中放进常驻内存的 **FAT 表**，寻链不读盘；同时 FAT 表覆盖全卷所有簇，表项为 0 就表示空闲簇，所以 **FAT 表既管文件链接又直接反映空闲空间分布**（`2025-31`）。缺点是磁盘越大 FAT 表越占内存。
  4. **索引分配**：每个文件建索引表登记物理块号，**同时支持文件长度动态可变与高效随机访问**（`2020-24`）。

### 2. UNIX 混合多级索引（inode）＋ 两道真题手算

实际系统里小文件占绝大多数，大文件占少数。UNIX inode 在结构体里放若干**直接地址项**（小文件 0 次间接索引，直接 1 次读盘拿数据），再配**一级、二级、三级间接地址项**按需向大容量平滑扩展。

**真题手算 1：目录项、硬链接、打开读盘次数与 6 MB 文件寻址层级（结合 2022-45）**
设磁盘块大小 4 KB，盘块地址占 4 B，每个索引块可存 $4\text{ KB} / 4\text{ B} = 1024$ 个块号；inode 含 10 个直接项、1 个一级间接项、1 个二级间接项、1 个三级间接项。
1. **目录项内容**：目录 `stu` 下有子目录 `course`（inode 2）和文件 `doc`（inode 10），UNIX 目录项只存 `(文件名, inode 号)`，即 `("course", 2)` 和 `("doc", 10)`。
2. **硬链接共享盘块**：如果 `course1` 和 `doc` 的 inode 号都是 10，它们互为硬链接，共享同一个 inode 和数据块（若 `course1` 占 30 号块，`doc` 占的也是 30 号块）。
3. **打开并读取 `course1` 要读几个磁盘块？**：即使题目说“父目录 `course` 已在内存”，在内存查目录项只拿到整数 `10`，**并不包含 inode 10 结构体本身**！所以必须先读 **1 次盘**把 inode 10 所在的磁盘块读入内存，再根据里面的直接项读 **1 次盘**把数据块 30 读入内存，共 **2 个磁盘块**。
4. **`course2` 增长到 6 MB 要用哪几级间接项？**：
   - 所需数据块数 $= 6\text{ MB} / 4\text{ KB} = 6144 / 4 = 1536$ 块；
   - 10 个直接项 + 1 个一级间接项最多覆盖 $10 + 1024 = 1034$ 块；
   - 因为 $1536 > 1034$，溢出部分（$1536 - 1034 = 502$ 块）落入二级间接项（最多覆盖 $1024^2$ 块）。因为索引是自低向高依次填满的，所以**一级间接项和二级间接项都要使用**（别漏掉一级间接项）。

**真题手算 2：inode 盘块号定位、跨界偏移访盘与非空目录递归删除（结合 2026-46）**
设磁盘块 4 KB，单个 inode 占 128 B，inode 表从 100 号盘块开始连续存放、共占 4096 块，每个 inode 含 5 个直接项和 1 个一级间接项（块地址 4 B）。
1. **求 inode 1000（从 0 编号）所在的物理盘块号**：每块放 $4096 / 128 = 32$ 个 inode；相对块偏移 $= \lfloor 1000 / 32 \rfloor = 31$；物理盘块号 $= 100 + 31 = \mathbf{131}$。
2. **访问文件字节偏移 21460，inode 已在内存，最多访盘几次？**：
   - 逻辑块号 $= \lfloor 21460 / 4096 \rfloor = 5$（块内偏移 980）。
   - **极易错点**：5 个直接项覆盖的是逻辑块 **0、1、2、3、4**，逻辑块 **5** 刚好溢出进入一级间接项！最坏情况一级索引块没缓存，需先读一级索引块（1 次）再读数据块（1 次），最多访问 **2 个盘块**。
3. **系统最多能创建多少个文件？**：每个文件（含目录）独占 1 个 inode，上限 $= 4096 \times 32 = \mathbf{131072}$ 个。
4. **删除包含 30 KB 子文件 `file` 的目录 `dir1` 要改哪些元数据？**（自底向上清理）：
   - 释放 `file` 占用的盘块：$\lceil 30\text{ KB} / 4\text{ KB} \rceil = 8$ 个数据块 + **1 个一级间接索引块**（别漏算索引块！）共 9 块，在**盘块位图**中将这 9 位清 0；在**inode 位图**中将 `file` 的 inode 位清 0；
   - 释放 `dir1` 自身：清空其目录项，将 `dir1` 占用的数据块在盘块位图清 0、其 inode 在 inode 位图清 0；
   - 更新父目录 `dir`：删掉指向 `dir1` 的目录项，并更新父目录 inode 的大小、修改时间和链接计数。

## 二、目录、硬软链接、文件系统布局与 VFS

### 1. 目录项瘦身与文件操作辨析
- 把大 FCB 拆成**目录项 `(文件名, inode 号)`** 和 **inode（存权限、大小、时间、盘块指针）**，一个磁盘块能塞进更多目录项，大幅减少查目录时的读盘次数。
- **高频选择题辨析**：
  - 创建新文件时，**访问权限写入 inode，绝不写入目录项**（`2025-29`）；
  - 系统最大文件总数受限于 inode 号位数（如目录项里 inode 号占 4 B 即 32 位，则最多 $2^{32}$ 个文件，与文件名长度无关，`2020-31`）；
  - 只有 `open(路径名)` 需要查找目录树；后续 `read(fd)`、`write(fd)`、`close(fd)` 直接拿整数 `fd` 查打开文件表，**不再查目录**（`2024-29`）。

### 2. 硬链接 vs 软链接（符号链接）与空间回收
| 对比维度 | 硬链接 | 软链接（符号链接 / 快捷方式） |
| :--- | :--- | :--- |
| **inode** | 与源文件**共享同一个 inode** | 独立的新文件，有**独立 inode**，内容存目标路径字符串 |
| **删源文件后** | 仅 `i_nlink--`，通过其他硬链接照常读写 | 软链接文件仍在，但变成失效断链，打不开原文件（`2021-30`） |
| **跨文件系统 / 链目录** | **不支持**（各分区 inode 编号独立；禁止普通用户硬链目录防环路） | **都支持**（基于文本路径解析；相对路径以软链接所在目录为基准） |

- **磁盘空间何时真正释放？** 必须同时满足**磁盘硬链接数 `i_nlink == 0`** 且 **内存中已无进程打开或映射该文件**。如果进程 A 正打开着文件，别人把文件名 `rm` 掉了，进程 A 仍能正常读写，直到进程 A `close()` 后磁盘块才真正回收。
- **`close()` vs `delete()`（`2023-31`）**：最后一个打开该文件的进程执行 `close()` 时，只释放**内存中的活动 inode**，绝不会删除磁盘目录项、减少硬链接数或释放磁盘数据块。

### 3. 外存分区布局、开机引导与空闲空间管理
一个分区格式化后依次包含：**引导块 $\to$ 超级块（记总块数、空闲块数等全局参数，现代系统多处冗余备份）$\to$ 盘块位示图 & inode 位示图 $\to$ inode 表 $\to$ 数据块区**。

- **开机引导与制作启动盘顺序（结合 2021-46、2025-32）**：
  - 开机执行顺序：**ROM 中的引导程序（BIOS/UEFI） $\to$ 磁盘引导程序（MBR） $\to$ 分区引导程序（PBR） $\to$ 操作系统初始化程序**。
  - 新硬盘制作启动盘顺序：**磁盘物理格式化（低级格式化，划分物理磁道和扇区） $\to$ 磁盘分区（建分区表） $\to$ 逻辑格式化（高级格式化，确定逻辑块/簇大小、建文件系统和根目录，HDD 与 SSD 逻辑格式化共同完成这一步） $\to$ 安装操作系统**。
- **空闲空间管理**：
  - **位示图法**：1 bit 对应 1 个物理块（字长 $W$ 时，块号 $b = i \times W + j$）。**位图占用空间大小只由磁盘总容量决定，完全固定不变**，不受碎片多少影响（`2024-26`）。
  - **成组链接法（UNIX）**：超级块里放当前组的空闲块号栈（如最多 100 块），栈底那一块记录下一组 100 个空闲块号。**两个必考临界动作**：① 分配到本组最后 1 块（$N=1$）时，必须**先把该块里的下一组块号读进超级块栈，再把该块分给用户**；② 回收块时若超级块栈已满（$N=100$），必须**先把当前栈的 100 个块号写进刚归还的块 $X$，再把超级块重置为 $N=1$ 且只记录 $X$**。

### 4. 三级打开文件表与虚拟文件系统（VFS）
- **三级打开表**：进程打开文件表（`fd` 表）$\to$ 系统打开文件表（存**读写偏移指针 `f_pos`**、打开标志、引用计数）$\to$ 内存 inode 表（文件属性与盘块指针）。
  - **两进程各自独立 `open()`**（`2020-23`）：各自拥有独立的读写偏移量，但共享文件属性信息；某进程 `close()` 只是把引用计数减 1，只要还有其他进程打开就不能删系统表项。
  - **`dup()` 或 `fork()` 继承**：指向**同一个系统打开文件表项**，共享同一个读写偏移量 `f_pos`。
- **虚拟文件系统（VFS）**：向上提供统一 POSIX 接口，向下适配 Ext4、FAT32、NTFS、NFS 等异构/网络文件系统，核心对象为超级块、inode、目录项（dentry）和文件对象（file）。注意：**VFS 是一层软件抽象，不会显著提高文件访问速度**（`2025-28`）。

## 三、I/O 控制方式、软件层次、缓冲与 SPOOLing

### 1. 四大 I/O 控制方式与设备分类
- **演进**：程序直接控制（轮询，CPU 忙等）$\to$ 中断驱动（按字/字节中断，用于键盘等低速**字符设备**）$\to$ DMA（按连续数据块中断，用于磁盘等高速**块设备**）$\to$ 通道控制（执行通道程序，进一步解放 CPU）。
- **块设备 vs 字符设备（`2026-31`）**：块设备以块为单位、可寻址、支持随机存取（常用 DMA）；字符设备以字节流为单位、不可寻址、只能顺序存取（常用中断驱动）。两者都可以通过统一的系统调用接口访问，但**不必采用相同的 I/O 控制方式**。

### 2. I/O 软件四层与高频考题定位
从上到下四层：
1. **用户层 I/O 软件（用户态）**：库函数（`printf`/`scanf`）、SPOOLing 守护进程。
2. **设备独立性软件（内核态）**：核心目标是**应用程序只用逻辑设备名，更换物理设备时不需要修改应用程序代码**（`2020-30`）。负责维护逻辑设备表（LUT）、设备保护、缓冲管理、以及按 **SDT $\to$ DCT $\to$ COCT $\to$ CHCT** 顺序分配设备（分配时需综合考虑：设备固有属性、分配安全性/防死锁、设备独立性、设备当前分配状态，`2023-32`）。
3. **设备驱动程序（宏内核在内核态，微内核在用户态）**：唯一直接和设备控制器寄存器打交道的软件，负责设备初始化、发读写命令、启动设备。注意：**驱动程序必须强依赖于具体的 I/O 控制方式**（轮询、中断、DMA 写法完全不同，`2022-32`）。
4. **中断处理程序（内核态）**：响应外设中断，把数据从**设备接口数据寄存器读出，放入操作系统的内核缓冲区**（`2024-31`、`2026-32`），然后唤醒等待该 I/O 的阻塞进程（绝不会把当前碰巧被打断的无辜进程改成阻塞态）。

### 3. 单缓冲 / 双缓冲耗时公式与 SPOOLing
设外设输入一块耗时 $T$，缓冲区搬到用户区耗时 $M$，CPU 处理一块耗时 $C$：
- **单缓冲**：单块稳态周期 $= \max(C, T) + M$；连续处理 $n$ 块总耗时为 $n(T + M) + C$（当 $T \ge C$）或 $T + n(M + C)$（当 $T < C$）。
- **双缓冲**：单块稳态周期 $= \max(T, M + C)$；连续处理 $n$ 块总耗时为 $nT + M + C$（当 $T \ge M + C$）或 $T + n(M + C)$（当 $T < M + C$）。
- **SPOOLing（假脱机技术）**：把慢速独占设备（如打印机）虚拟成多进程共享设备。核心构件是开辟在**磁盘（外存）**上的**输入井 / 输出井**（绝不是在内存里！内存里只有短暂中转的输入/输出缓冲区），再配后台守护进程缓输出。

## 四、磁盘物理结构、时延计算、磁头调度与 SSD

### 1. 磁盘编址、存取时间与 DMA 请求（结合 2022-44）
- 磁盘物理地址按 **`(柱面号, 磁头号, 扇区号)`** 排布：把柱面号放最高位，因为切换磁头是电子开关（极快），移动磁头换柱面是机械运动（最慢），读完一整个柱面所有盘面再移动一次机械臂，能大幅减少寻道。
- 扇区交替编号与错位命名：防止控制器刚处理完上一扇区，下一逻辑扇区就已经转过去了导致多等一整圈。
- **平均存取时间公式**：$T_{\text{access}} = T_{\text{seek}}(\text{平均寻道}) + T_{\text{rot}}(\text{平均旋转延迟 = 半圈}) + T_{\text{trans}}(\text{传输时间})$。

**真题手算（`2022-44`）**：某磁盘有 4 个双面盘片、每面 20000 磁道、每道 500 扇区（每扇区 512 B），转速 7200 RPM，平均寻道时间 5 ms，控制器缓冲区 64 位，周期挪用 DMA。
1. **扇区地址三字段最少位数**：
   - 磁头号：$4 \times 2 = 8$ 个盘面 $\to \lceil \log_2 8 \rceil = \mathbf{3\text{ 位}}$；
   - 柱面号：20000 个磁道，$2^{14}=16384 < 20000 \le 32768=2^{15} \to \mathbf{15\text{ 位}}$；
   - 扇区号：500 个扇区，$2^8=256 < 500 \le 512=2^9 \to \mathbf{9\text{ 位}}$。
2. **单扇区平均访问时间**：
   - 转速 $7200 / 60 = 120\text{ 转/秒}$，转一圈耗时 $1000 / 120 \approx 8.333\text{ ms}$；
   - 平均旋转延迟（半圈）$= 8.333 / 2 \approx 4.167\text{ ms}$；
   - 单扇区传输时间（$1/500$ 圈）$= 8.333 / 500 \approx 0.0167\text{ ms}$；
   - 合计 $= 5 + 4.167 + 0.0167 \approx \mathbf{9.18\text{ ms}}$。
3. **DMA 总线请求次数与仲裁**：
   - 每扇区 512 B，缓冲区 $64\text{ bit} = 8\text{ B}$，需请求总线 $512 / 8 = \mathbf{64\text{ 次}}$；
   - DMA 与 CPU 同时申请总线时，**DMA 优先获得总线**：因为磁盘高速旋转，缓冲区数据不及时搬走会被新数据覆盖导致丢失；而 CPU 稍等一个周期只会慢一点，不会丢数据。

### 2. 磁头调度算法与真题手算
- **FCFS**：按到达顺序，无饥饿但寻道距离长。
- **SSTF（最短寻道时间优先）**：每次挑离当前磁头最近的请求，可能来回折返，**唯一会导致饥饿**。
  - *真题案例（`2021-26`）*：当前在 184，请求 `{184, 182, 187, 176, 199}`。顺序为 `184 → 182 → 187 → 176 → 199`，总位移 $= 0 + 2 + 5 + 11 + 23 = \mathbf{41}$。
- **SCAN（电梯算法）vs LOOK**：单向扫描服务，SCAN **必须走到物理边界**（如 0 或 399）才掉头；LOOK 走到**该方向最后一个请求**就掉头。
- **C-SCAN（循环扫描）vs C-LOOK**：只朝一个方向服务，到头后空程快速跳回另一端再同向服务（C-SCAN 走两端物理边界，C-LOOK 走两端最远请求）。
  - *真题案例（`2024-32`）*：磁道范围 0~399，完成 200 号磁道请求后**向磁道号减小的方向移动**，待服务请求 `{300, 120, 110, 0, 160, 210, 399}`，采用 **C-SCAN**：
    1. 向小号方向依次服务 `200 → 160 → 120 → 110 → 0`：位移 $200 - 0 = 200$；
    2. 到达 0 号后空程跳回另一端 399 号磁道：位移 $399 - 0 = 399$；
    3. 继续向小号方向依次服务 `399 → 300 → 210`：位移 $399 - 210 = 189$；
    4. 总移动磁道数 $= 200 + 399 + 189 = \mathbf{788}$。

### 3. 固态硬盘（SSD）核心特点
- 基于闪存颗粒，无机械臂，**寻道时间为 0**。
- **读写以页（Page）为单位，擦除以块（Block）为单位**（一个块包含几十到几百页）。
- **不能原位覆盖，必须异地更新**：修改某页时，闪存翻译层（FTL）把新数据写到另一个空白页，把旧页标为无效并更新逻辑地址到物理地址的映射表。
- **垃圾回收（GC）与写放大**：空闲块不足时，选无效页最多的块，把里面的有效页搬到新块，再整块擦除；有效页搬迁造成实际写入量大于主机请求写入量（写放大）。
- **磨损均衡**：闪存块擦写寿命有限。**动态磨损均衡**写新数据时优先挑擦写次数少的空闲块；**静态磨损均衡**更彻底，会主动把长期不动的**冷数据**搬到擦写次数高的块里，腾出擦写次数少的新块给热数据用。
