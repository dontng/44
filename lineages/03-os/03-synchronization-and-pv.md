> 脉络编号：`os-03` · 返回 [全科知识脉络总览](../README.md)

多个进程并发跑起来后，只要它们碰到了同一块共享内存、同一个缓冲区或同一台外设，指令一交错就可能把数据写花，或者把先后顺序搞乱。这一条脉络先讲清楚并发不出乱子的底层条件和软件/硬件/管程几种互斥思路，再重点把 408 几乎年年考大题的信号量与 PV 操作建模方法一次讲透。

## 一、并发为什么会出错？互斥、同步与四大准则

### 1. 竞态条件与 Bernstein 条件
哪怕是高级语言里一句简单的 `count++`，编译成机器指令也是三步：读内存到寄存器 $\to$ 寄存器加 1 $\to$ 写回内存。如果两个线程同时做 `count++`，线程 1 刚算完还没写回就被切走，线程 2 算完写回 1，线程 1 回来再把自己的 1 写回去，一次加法就丢了。

两个并发进程 $P_1, P_2$ 什么情况下能放心并行、结果一定可再现？经典的 **Bernstein 条件**（`2026-27`）给出了充要条件（设 $R_i$ 为读变量集，$W_i$ 为写变量集）：
1. $R_1 \cap W_2 = \emptyset$（$P_1$ 读的变量，$P_2$ 不能写）；
2. $W_1 \cap R_2 = \emptyset$（$P_1$ 写的变量，$P_2$ 不能读）；
3. $W_1 \cap W_2 = \emptyset$（两者不能同时写同一个变量）。

注意：**不需要满足 $R_1 \cap R_2 = \emptyset$**——多个进程同时读同一个变量完全安全，不会互相破坏。

### 2. 临界区、互斥与同步
- **临界资源**：一次只允许一个进程使用的共享资源（比如 `2024-46` 里只能放一个数据分组的共享缓冲区 B）。
- **临界区**：进程中访问临界资源的那段代码。
- **互斥**：排他访问，“我在用的时候你别进”（如两个进程都往缓冲区 B 写数据）。
- **同步**：有先后顺序约束，“你干完这步我才能干下一步”（如必须先往空缓冲区写入数据，另一个进程才能读）。

### 3. 临界区互斥的四大准则
1. **空闲让进**：临界区没人时，想进的进程要能立刻进去；
2. **忙则等待**：临界区有人时，其他想进的进程必须等在外面；
3. **有限等待**：不能让某个进程无限期等下去（防止饥饿）；
4. **让权等待**：进不去的时候，应当主动释放 CPU 进入阻塞态，不要占着 CPU 原地空转。

**高频考点**（`2020-32`）：前三条是所有互斥机制**必须满足**的硬条件，但**“让权等待”不是所有互斥机制都必须满足的**——像 Peterson 算法和硬件自旋锁都是在 `while` 里忙等，虽然没让权，但依然是合法的互斥机制。

## 二、软件互斥、硬件原子指令与管程

### 1. 四种软件互斥方法对比
为了用纯软件实现两个进程 $P_0, P_1$ 的互斥，教材按由浅入深讲了四种方案：
- **单标志法**（`while (turn != i); ... turn = j;`）：满足忙则等待，但**违背空闲让进**（必须你一次我一次严格交替，对方不想进时你也不能连进两次）。
- **双标志先检查法**（`while (flag[j]); flag[i] = true;`）：检查和置标志不是原子的，可能两人都看见对方为 `false` 然后一起冲进临界区，**违背忙则等待**。
- **双标志后检查法**（`flag[i] = true; while (flag[j]);`）：两人同时举旗后互相死等，**违背空闲让进和有限等待**（活锁）。
- **Peterson 算法**（先举旗表达意愿，再把 `turn` 谦让给对方）：
  ```c
  flag[i] = true;
  turn = j;
  while (flag[j] && turn == j); // 忙等
  // 临界区
  flag[i] = false;
  ```
  - **结论**：完美满足**空闲让进、忙则等待、有限等待**，唯一不满足的是**让权等待**。为什么一定互斥？因为 `turn` 同一时刻只能是 0 或 1，后写 `turn` 的那一方一定卡在 `while` 里，不可能两人同时跳出循环。

### 2. 硬件互斥：关中断与原子指令（TSL / Swap / CAS）
1. **关中断**：在单核 CPU 上，进临界区前关中断、出临界区后开中断，时钟中断进不来就不会发生进程切换，代码自然原子。
   - **真题案例（结合 2021-45）**：用关中断实现整型信号量的 `wait(S)` 时，**绝对不能**在关中断状态下直接写 `while (S <= 0);`——一旦 `S <= 0`，CPU 关着中断原地死循环，时钟中断和调度全被屏蔽，别的进程永远没机会上 CPU 执行 `signal(S)`，整机直接死锁。单核下的正确改法是在循环里临时放开：`while (S <= 0) { 开中断; 关中断; }`，给调度器留出切换窗口。
   - 同样要注意：**用户程序不能使用开/关中断指令实现互斥**，因为它们是特权指令，用户态执行会触发异常；而且一旦用户程序关了中断不打开，操作系统就彻底失去对 CPU 的控制。
2. **硬件原子指令：`TestAndSet`（TSL）、`Swap`（XCHG）和 `CAS`**：
   - CPU 提供单条不可分割的读-改-写指令（现代多核下通过缓存一致性协议锁住对应 Cache 行，跨 Cache 行时才锁总线）。
   - **真题案例（结合 2023-45）**：用硬件 `swap key, lock` 实现自旋锁（`lock = TRUE` 表示上锁，`FALSE` 表示空闲）：
     ```c
     bool key = TRUE;
     while (key == TRUE)    // 必须用 while，绝不能用 if！
         swap key, lock;    // 硬件原子指令，不能用普通软件函数 newSwap() 代替
     // 临界区
     lock = FALSE;          // 退出区必须开锁，不能写成 lock = TRUE
     ```
     - 如果把 `while` 错写成 `if`，`lock` 为 `TRUE` 时只交换一次后 `key` 仍为 `TRUE`，但程序会直接越过 `if` 冲进临界区，互斥失效。
     - **不能用软件函数 `newSwap()` 代替硬件 `swap` 指令**：软件函数由多条机器指令组成，执行中途可能发生线程切换，导致两个线程同时换出 `FALSE` 一起进入临界区。
   - **自旋锁的适用边界**：不满足让权等待。在**多核系统且临界区极短**时非常高效（省去了上下文切换开销）；但在单核或临界区很长时会导致空转浪费 CPU 甚至死锁。

### 3. 管程（Monitor）与条件变量
把共享数据和操作它的一组过程封装成一个模块，**同一时刻只允许一个进程在管程内执行**（互斥由编译器保证）。管程内部用**条件变量** `condition x` 做同步：
- `x.wait()`：条件不满足时，**无条件阻塞**调用者并**自动释放管程互斥锁**；
- `x.signal()`：唤醒一个等在 `x` 上的进程；如果当前没人等，**这个信号直接丢失（不会像信号量那样把计数值加 1）**。
- **条件变量 vs 信号量**：信号量有整型计数值，能记住历史上的 `V` 操作；条件变量**没有计数值**。
- **为什么现代系统（Mesa 语义，如 POSIX pthread、Java）必须用 `while (!cond) x.wait();` 而不是 `if`**：唤醒后被唤醒者不会立刻抢到管程锁，期间可能有别的进程插队把条件再次破坏，所以醒来后必须重新用 `while` 检查条件。

## 三、信号量机制与 PV 操作建模

### 1. 记录型信号量与数值含义
为了克服整型信号量忙等的缺点，记录型信号量由一个整数 `value` 和一个阻塞队列 `queue` 组成：
```c
void wait(semaphore &S) {   // 即 P(S)
    S.value--;
    if (S.value < 0) block(S.queue);   // 资源不够，主动阻塞，实现让权等待
}

void signal(semaphore &S) { // 即 V(S)
    S.value++;
    if (S.value <= 0) wakeup(S.queue); // 队列里还有人在等，唤醒一个进入就绪队列
}
```
**信号量数值的含义（高频选择题，`2026-26`）**：
- $S > 0$：当前还剩 $S$ 个可用资源，阻塞队列为空；
- $S = 0$：资源刚好用完，没人排队；
- $S < 0$：资源已用完，且 **$|S|$ 等于当前正在阻塞队列里排队的进程数**。
- *例子（`2026-26`）*：信号量初值设为 5，用来控制某临界区最多允许 5 个进程并发进入。若当前 $S = -2$，说明 5 个名额已全被占满（正在临界区里执行的进程数 $m = 5$），外面还有 $|-2| = 2$ 个进程在阻塞队列里排队（$n = 2$）。

### 2. PV 建模的四类经典套路

写 PV 大题时，先按下面三条铁律定好信号量初值：
- **互斥信号量**（一次只进一个）：初值设为 **1**；
- **资源容量信号量**（最多放 $N$ 个空位或有 $N$ 个资源）：初值设为 **$N$**；
- **先后同步信号量**（前趋事件“你做完我再做”）：初值一律设为 **0**。

#### 套路 1：前趋图同步（结合 2020-45、2022-46）
- 有向边 $X \to Y$（$Y$ 必须在 $X$ 之后执行）：设初值为 0 的信号量 `s_xy = 0`，在 $X$ 后面写 `V(s_xy)`，在 $Y$ 前面写 `P(s_xy)`。
- **减少多余信号量的关键（`2022-46`）**：如果操作 $A, E, F$ 在线程 $T_1$ 里顺序执行，$B, C, D$ 在线程 $T_2$ 里顺序执行，依赖关系为 $A \to C, B \to C, C \to D, C \to E, E \to F$。因为**同一线程内部靠代码书写顺序天然有序**（$B \to C$、$C \to D$、$E \to F$ 都不用管），真正跨线程的依赖只有两条：$A \to C$ 和 $C \to E$，所以**只需要 2 个初值为 0 的信号量** `aDone` 和 `cDone`：
  - $T_1$：`A(); V(aDone); P(cDone); E(); F();`
  - $T_2$：`B(); P(aDone); C(); V(cDone); D();`

#### 套路 2：生产者-消费者与多级流水线（结合 2024-46、2025-45）
标准有界缓冲区（容量 $N$）：`empty = N`，`full = 0`，`mutex = 1`。
- 生产者：`P(empty); P(mutex); 放数据; V(mutex); V(full);`
- 消费者：`P(full); P(mutex); 取数据; V(mutex); V(empty);`
- **绝对不能颠倒两个 `P` 的顺序**：必须**先 `P` 同步信号量（`empty`/`full`），再 `P` 互斥锁（`mutex`）**。如果先 `P(mutex)` 再 `P(empty)`，当缓冲区满时生产者会**抱着互斥锁去睡觉**，消费者进来卡死在 `P(mutex)` 上，双方永久死锁。
- **单容量极简情形（`2024-46`）**：缓冲区容量为 1 且初始为空，如果 $P_1$ 只写一次、$P_2$ 只读一次，因为不需要循环归还空位，只需 **1 个同步信号量 `full = 0`** 即可（$P_1$ 写完 `V(full)`，$P_2$ 先 `P(full)` 再读）；如果缓冲区初始非空，$P_1$ 和 $P_2$ 都要修改它，则只需 **1 个互斥信号量 `mutex = 1`**。

**真题完整推演：三人植树流水线（结合 2025-45）**
- 场景：甲挖树坑，乙放树苗并填土，丙浇水。规则：① 树坑数量小于 3 时甲才能挖坑；② 只有 1 把铁锹（甲挖坑、乙填土都要用）；③ 只有 1 个水桶（仅丙浇水用）。要求信号量尽可能少。
- 拆解：
  1. 空坑容量限制（最多 3 个未填土的坑）：`semaphore empty = 3;`
  2. 甲 $\to$ 乙前趋（已挖好的坑数）：`semaphore holes = 0;`
  3. 乙 $\to$ 丙前趋（已填好土待浇水的树苗数）：`semaphore trees = 0;`
  4. 铁锹（甲乙共享互斥）：`semaphore shovel = 1;`
  5. 水桶（只有丙一人用，没有竞争，**不设信号量**）。
- 代码（注意先 `P` 同步再 `P` 铁锹互斥锁，且乙放树苗不占铁锹，填土前才拿铁锹）：
  ```c
  void 甲() {
      while (1) {
          P(empty);  P(shovel);  挖树坑();  V(shovel);  V(holes);
      }
  }
  void 乙() {
      while (1) {
          P(holes);  放树苗();  P(shovel);  填土();  V(shovel);  V(empty);  V(trees);
      }
  }
  void 丙() {
      while (1) {
          P(trees);  浇水();
      }
  }
  ```

#### 套路 3：读者-写者问题
允许多个读者同时读，但写者必须独占（写时不能有其他读者或写者）。
- **读者优先**：用 `count = 0` 记录当前读者数，`mutex = 1` 保护 `count`，`rw = 1` 做读写锁。第一个读者进来时 `if (count == 0) P(rw);`，最后一个读者离开时 `if (count == 0) V(rw);`。缺点是读者源源不断时会导致**写者饥饿**。
- **读写公平（防写者饥饿）**：在读者和写者最外层再套一个排队闸机 `semaphore w = 1;`。写者一到就先 `P(w)` 再 `P(rw)`，把后续新来的读者挡在 `w` 外面，等手头正在读的读者退完就能立刻写，写完再 `V(rw); V(w);`；读者在进门改 `count` 前后加上 `P(w)` 和 `V(w)` 即可。

#### 套路 4：哲学家进餐问题
5 人围坐，每人需左右两根筷子 `chopstick[5] = {1,1,1,1,1}`。如果所有人都先拿左筷再拿右筷，可能同时每人手里抓 1 根左筷，全员死锁。三种经典解法：
1. **限制人数**：设 `room = 4`，最多允许 4 人同时上桌拿筷子（抽屉原理保证至少 1 人能拿齐两根）；
2. **奇偶非对称**：奇数号先左后右，偶数号先右后左（打破循环等待）；
3. **原子拿双筷**：用 `mutex = 1` 把“拿左筷 + 拿右筷”包起来，拿齐两根再 `V(mutex)`。
