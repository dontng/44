# 系统总线仲裁与带宽、I/O 接口编址、中断隐指令与 DMA

> 返回 [全科知识脉络总览](../README.md)

CPU 和内存算得再快，数据也得从外设进来、送回外设出去。这条脉络沿着数据进出主机的真实路线展开：**系统总线**是大家公用的马路（要算带宽、管谁先上路、怎么对表）；**I/O 接口**是外设连上总线的收费站（靠端口编址让 CPU 能读写）；**程序查询 $\to$ 程序中断 $\to$ DMA** 则是 CPU 和外设打交道的三代演进，核心目标是一步步把 CPU 从繁琐的数据搬运里解放出来。2020–2026 年间，总线带宽计算、中断响应与屏蔽字、DMA 周期挪用几乎每年必出 2～3 道选择题。

## 一、系统总线：分类、带宽、仲裁与定时

### 1. 总线的“分时共享”与三类总线
如果每两个部件之间都单独拉线，主板根本布不下。总线用一组公共导线把各部件连起来，特点是**分时共享**：
- **共享**：挂在总线上的多个设备都可以同时收听总线上的信号；
- **分时**：同一时刻**只允许一个设备往总线上发送（驱动）电平**，否则会短路冲突。
- **三类总线**：**数据总线**（双向，位数决定一次传多少位）、**地址总线**（单向，主设备发出，位数决定最大寻址空间）、**控制总线**（单根单向，整体有进有出）。
- **易错细节**：写操作时主设备驱动数据总线；但**读操作的数据传输阶段，是由被选中的从设备驱动数据总线**把数据送回主设备，并不是只有主设备才能驱动数据总线。

### 2. 总线带宽计算与真题常见陷阱
- **理论峰值带宽**：
  $$B_{\text{peak}} = \text{每秒传输次数} \times \frac{\text{数据总线宽度（位）}}{8}$$
  如果时钟频率是 $f$，单倍数据率（SDR）每周期传 1 次；双倍数据率（DDR，上下沿都传）每周期传 2 次；全双工双向同时传再乘 2。
- **真题案例 1（2020-19，QPI 总线）**：时钟频率 $2.4\text{ GHz}$，每周期传 2 次（$4.8\text{ GT/s}$），单向有效数据位宽 16 位（2B），双向全双工同时传，则总带宽 $= 4.8\text{ G} \times 2\text{ B} \times 2 = 19.2\text{ GB/s}$。
- **真题案例 2（2025-20，MT/s 陷阱）**：题干说总线每周期传 4 次，接着给“工作频率 1333 MHz（实际单位是 MT/s，表示每秒传送 1333M 次）”，数据宽 64 位（8B）。因为 **1333 MT/s 本身已经是折算过“每周期 4 次”之后的每秒传送次数**，绝不能再乘 4！直接算 $1333\text{ M} \times 8\text{ B} \approx \mathbf{10.66\text{ GB/s}}$。
- **有效带宽 vs 突发传输（2023-20、2024-20）**：
  - **非突发传送（2023-20）**：每读一个字都要重走一遍“发地址 + 主存准备 + 传数据”。比如 32 位总线（4B）、100 MHz（周期 10 ns），首字等待 2 周期，则每读 1 个字花 $1 + 2 + 1 = 4$ 周期，读 4 个字（16B）花 16 周期（160 ns），有效带宽仅 $16\text{ B} / 160\text{ ns} = 100\text{ MB/s}$；
  - **突发传输（Burst）**：只发 1 次首地址，等 2 周期后连续 4 个周期吐出 4 个字，总耗时仅 $1 + 2 + 4 = 7$ 周期（70 ns），有效带宽跃升到 $16\text{ B} / 70\text{ ns} \approx 228.6\text{ MB/s}$，非常契合 Cache 行填充。

### 3. 集中式总线仲裁的三种方式
当 CPU 和多个 DMA 控制器同时抢总线，中央仲裁器有三种裁决方式：

| 仲裁方式 | 控制线数（$n$ 台设备） | 优先级特点 | 故障敏感度 |
| :--- | :---: | :--- | :--- |
| **链式查询** | **3 根**（BR、BG、BS，与 $n$ 无关） | 固定，离仲裁器越近优先级越高 | **最怕单点故障**（中间断了下游全瘫痪） |
| **计数器定时查询** | **$2 + \lceil \log_2 n \rceil$ 根** | 可调（从 0 计数固定优先；从上次继续计数循环公平） | 中等，但计数轮询有延迟 |
| **独立请求** | **$2n + 1$ 根** | 最灵活，内部排队器可动态编程，响应最快 | 最好，但线太多、硬件开销大 |

### 4. 总线定时（通信）的四种方式
- **同步定时**：统一公共时钟，控制简单速度快，但必须迁就最慢的设备。
- **异步定时（2021-19）**：无统一时钟，靠“请求”和“回答”握手联络，适合速度差异大的设备（每次握手传送的数据量等于数据总线宽度）。按因果严谨程度分三种：
  - **不互锁**：发完请求/回答延时自动撤销，最快但不可靠；
  - **半互锁**：主设备收到回答才撤请求，但从设备延时自动撤回答；
  - **全互锁**：主等回答才撤请求，从等请求撤销才撤回答，最可靠也最慢。
- **半同步定时**：保留统一时钟，增加一条 `WAIT#` 等待线，慢设备没准备好就拉低 `WAIT#` 让主设备插入整周期等待。
- **分离式通信**：把读事务拆成两半——主设备发完地址和读命令就**立刻释放总线**；等从设备把数据准备好，再自己申请总线把数据送回来。彻底消除了等待慢设备时的总线空转。

## 二、I/O 接口与端口编址

CPU 不能直接连外设，因为外设太慢、电平协议五花八门，必须经过**I/O 接口（适配器/控制器）**做缓冲和转换。注意区分外设和接口（**2021-20**）：磁盘驱动器、键盘按键、显示器面板是**外设**；磁盘控制器、显卡、网卡、中断控制器是**I/O 接口**。

- **I/O 端口**：指 I/O 接口芯片内部能被 CPU 直接寻址读写的寄存器，分为**数据端口**（双向缓冲数据）、**控制端口**（CPU 写命令启动/配置设备）、**状态端口**（CPU 读设备是忙、就绪还是出错）。高位地址线译码产生芯片片选信号 $\overline{\text{CS}}$，低位地址线选通芯片内部具体哪一个端口。
- **两种编址方式对比**：
  - **统一编址（存储器映射 I/O，MMIO）**：端口和主存共用同一个物理地址空间。优点是**不需要专门 I/O 指令**，直接用 `MOV`/`LDR`/`STR` 等访存指令就能操作，寻址方式灵活；缺点是占用物理地址编码空间，且必须禁用 Cache、C 代码里用 `volatile` 防编译器把状态轮询优化成死循环。ARM、RISC-V 和现代 PCIe 主流用这种。
  - **独立编址（端口映射 I/O，PMIO）**：端口拥有独立于主存的地址空间（如 x86 的 64KB 端口空间），靠控制线 $M/\overline{\text{IO}}$（或独立的 $\overline{\text{IOR}}/\overline{\text{IOW}}$）区分访存还是访 I/O，即使地址编号相同也不会混淆。优点是不占主存地址空间；缺点是必须专门配 `IN`/`OUT` 指令，寻址方式单一。

## 三、三种 I/O 传送方式：程序查询、中断与 DMA

### 1. 程序查询方式（轮询）
CPU 发启动命令后，反复读状态端口检查 `READY` 位，没好就一直死循环“忙等”，好了再从数据端口读走 1 个字节。硬件最简单，但 CPU 算力全耗在空转上。

### 2. 程序中断方式
外设准备数据时 CPU 照常干活；数据放进接口缓冲寄存器后，外设发中断请求，CPU 停下手头工作去把数据搬进内存。

#### ① 外部中断 vs 内部异常（2020-20、2021-21、2025-22、2026-21）
- **外部中断（外中断）**：来自 CPU 外部硬件引脚（INTR/NMI），与当前执行的指令无关。包括时钟中断、键盘/网卡/磁盘 I/O 中断、**DMA 传送结束中断（2025-22）**。
- **内部异常（内中断）**：CPU 执行当前指令时内部出错或主动陷入，包括：
  - **故障（Fault）**：可修复的错误（如缺页异常、除零、溢出），修复后返回**重新执行触发故障的那条指令**（**2021-21**）；
  - **陷阱（Trap）**：有意安排的陷入（如系统调用 `syscall`/`int 0x80`、断点调试），这是用户态程序合法请求内核服务的入口（**2026-21**），返回后执行**下一条指令**；
  - **终止（Abort）**：不可恢复的严重硬件错误，直接终止进程。

#### ② 中断响应条件、中断隐指令与中断服务程序
CPU 响应可屏蔽外部中断（INTR）必须同时满足三个条件（**2020-21**）：① 有中断请求且未被屏蔽；② CPU 处于**开中断状态**（`IF=1`）；③ 到达**当前指令执行周期的末尾**。注意：CPU 处于**内核态**时只要开着中断，一样可以响应更高优先级的中断（**2021-22**）。

一旦响应，CPU 先由硬件自动执行**中断隐指令**（它不是指令集里的机器指令，不在主存里，而是硬件微操作序列，**2026-22**），完成三步不可分割的动作：
1. **关中断**（`IF=0`，保护保存断点过程不被打断）；
2. **保存断点**（硬件自动把 **PC 和 PSW** 压入内核栈）；
3. **引出中断服务程序**（按中断向量号查向量表，把 ISR 入口地址装入 PC）。

接下来转入软件写的中断服务程序（ISR）：**保存通用寄存器现场 $\to$（多重中断时）设新屏蔽字并开中断 $\to$ 执行设备服务 $\to$ 关中断 $\to$ 恢复旧屏蔽字与通用寄存器现场 $\to$ 执行中断返回指令 `IRET`**（`IRET` 会从栈里同时弹出 PC 和原 PSW，原子恢复 `IF` 位，避免先开中断再返回留下的竞态缝隙）。

#### ③ 多重中断与屏蔽字（2024-21）
- **响应优先级**：由**硬件排队器**决定，裁决“多个中断同时到达时先响应谁”，软件改不了。
- **处理优先级**：由软件设置的**中断屏蔽字**决定，裁决“正在服务谁时允许被谁打断嵌套”。
- **屏蔽字写法（3 条规矩）**：`1` 表示屏蔽，`0` 表示允许打断。
  1. 任何中断源对**自己**必须填 `1`（对角线全 1，防止自己打断自己）；
  2. 对处理优先级**低于或等于**自己的全填 `1`，**高于**自己的全填 `0`；
  3. 某一行里的 **`1` 越多，处理优先级越高**。
  例如响应优先级 $A>B>C>D$，若希望处理优先级为 $D>A>C>B$，则按 $[A,B,C,D]$ 排列的屏蔽字为：$D$ 是 `1111`（4 个 1），$A$ 是 `1110`（3 个 1），$C$ 是 `0110`（2 个 1），$B$ 是 `0100`（1 个 1）。

#### ④ 中断方式的吞吐上限（2022-21）
每准备 1 个字节/字就中断一次，为了不丢数据，**外设产生相邻两个数据的时间间隔，必须大于等于 CPU 执行一次中断处理的时间**。遇到几十 MB/s 的硬盘或千兆网卡，CPU 光响应中断就爆表了（比如 $40\text{ MB/s}$ 按每 4B 中断一次就是每秒 $10^7$ 次中断，每次花 500 周期需要 $5\times 10^9$ 周期/秒，直接把 500 MHz 的 CPU 压垮到 1000% 负荷）。

### 3. DMA（直接内存访问）方式
高速块设备（如硬盘、SSD、以太网卡，**2025-21**）必须用 **DMA**。它在外设接口和主存之间建一条**绕过 CPU 寄存器的数据通路**（**2023-22、2024-22**），数据成块直接在“外设 $\leftrightarrow$ DMA 控制器 $\leftrightarrow$ 主存”间传送。

- **DMA 控制器（DMAC）里的四个寄存器**：主存地址寄存器（MAR，每传一字自动加减）、字计数器（WC，计满归零发结束中断）、控制/状态寄存器（CR）、数据缓冲寄存器（BR）。
- **DMA 传送三阶段**：
  1. **预处理**：CPU 往 DMAC 写入主存起始地址、传输字数、传送方向并启动设备，然后 CPU 干别的去；
  2. **数据传送**：完全由 DMAC 接管总线自动搬运，**不需要 CPU 执行指令**；
  3. **后处理**：整块传完后，DMAC 向 CPU 发**一次外部中断（块结束中断）**，CPU 检查状态做收尾。
  回到上面 $40\text{ MB/s}$ 磁盘的例子：改用 4KB 块 DMA 后，每秒只需约 9766 次块结束中断，每次收尾 1000 周期，CPU 占用率从 1000% 骤降到 **不到 2%**！
- **DMA 使用总线的三种方式**：
  1. **停止 CPU 访问主存**：整块传完前 CPU 不能碰主存；
  2. **周期挪用（Cycle Stealing，最常考，2020-22）**：DMAC 缓冲器凑满 1 个字就向总线申请借用 **1 个主存存取周期**写进主存，写完立刻还总线。注意：挪用的是**主存周期**不是 CPU 时钟周期——如果此时 CPU 在做寄存器运算或命中了片内 Cache，CPU **0 停顿**，与 DMA 完全并行；只有 CPU 恰好也要访主存时，才让给优先级更高的 DMA 等 1 个主存周期。
  3. **DMA 与 CPU 交替访存**：把一个周期切成两半，前半归 CPU、后半归 DMA，不用总线仲裁，但硬件复杂。

### 4. 中断方式 vs DMA 方式核心对比
| 对比维度 | 程序中断方式 | DMA 方式 |
| :--- | :--- | :--- |
| **数据通路** | 外设 $\to$ 接口 $\to$ **CPU 寄存器** $\to$ 主存 | 外设 $\to$ DMAC $\to$ 主存（**绕过 CPU**） |
| **传送单位** | 单字节或单字 | 连续数据块（如 512B / 4KB） |
| **CPU 响应时机** | **一条指令执行结束**时响应中断 | **一个总线存取周期结束**即可响应 DMA 请求 |
| **仲裁优先级** | 低于 DMA 请求 | **高于**中断请求和普通 CPU 访存（防止高速外设数据溢出丢失） |
| **适用设备** | 键盘、鼠标、串口等慢速字符设备 | 磁盘、SSD、网卡等高速块设备 |
