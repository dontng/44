# 指令流水线冒险与旁路、多处理器架构与硬件多线程

> 返回 [全科知识脉络总览](../README.md)

当一条指令的顺序执行已经压榨到极限，硬件提升算力就走上了两条“并行”路线：一条是在单核内部把指令拆成多段重叠着跑（**指令流水线**），另一条是堆多个核心或者在一个核心里同时跑多个线程（**多处理器与硬件多线程**）。把这两块合在一起看，你就能顺着“单核流水线卡在哪 $\to$ 怎么靠旁路和分支预测救 $\to$ 实在救不了（比如 Cache 缺失等 200 周期）就靠硬件多线程和多核来填满算力”的自然逻辑，一次全部打通。

---

## 一、经典五段流水线与性能指标

经典 RISC 五段式流水线把一条指令拆成 5 个阶段，相邻两段之间用**流水段寄存器**（`IF/ID`、`ID/EX`、`EX/MEM`、`MEM/WB`）隔开：
1. **IF（取指）**：按 PC 从指令 Cache 取指令，更新 PC；
2. **ID（译码/读寄存器）**：指令译码产生控制信号，同时从通用寄存器堆读出源操作数；
3. **EX（执行）**：ALU 做算术逻辑运算，或计算 Load/Store 的访存有效地址；
4. **MEM（访存）**：Load 读数据 Cache，Store 写数据 Cache（运算指令在此段空过）；
5. **WB（写回）**：把运算结果或 Load 读回的数据写进目标寄存器。

**流水线时钟周期由最慢的那一段决定**：$\Delta t = \max(\text{各段耗时}) + \text{锁存器延迟}$。流水线**没有缩短单条指令的执行时间**（反而因为加了锁存器略微变长），它提升的是**吞吐率**。

设 $k$ 段流水线执行 $n$ 条指令，期间共插入 $N_{\text{stall}}$ 个停顿周期（气泡），时钟周期为 $\Delta t$：
- **总耗时**：$T_{\text{pipe}} = (k + n - 1 + N_{\text{stall}})\Delta t$；
- **吞吐率**：$\text{TP} = \frac{n}{T_{\text{pipe}}}$，无停顿且 $n \to \infty$ 时最大吞吐率为 $\frac{1}{\Delta t}$；
- **加速比**：$S = \frac{n \cdot k}{k + n - 1 + N_{\text{stall}}}$（极限逼近 $k$）；
- **效率**：$E = \frac{S}{k} = \frac{n}{k + n - 1 + N_{\text{stall}}}$。

## 二、流水线三大冒险（冲突）与化解

### 1. 结构冒险（资源冲突）
两条指令在同一周期抢同一个硬件部件。最典型的例子：第 1 条指令在 **MEM 段**访问主存数据，第 4 条指令同时在 **IF 段**访问主存取指令。如果指令和数据共用一个主存端口，就会撞车。
- **解法**：片内采用**哈佛结构**（L1 指令 Cache 和 L1 数据 Cache 物理分离）；如果没分离，就只能暂停后一条指令 1 个周期。

### 2. 数据冒险（数据相关）——408 最高频考法
先分清两个词：**数据相关**是代码里两条指令读写同一个寄存器带来的先后逻辑关系；只有进到流水线里重叠执行、可能读到旧值时，才变成**数据冒险**。

三类数据相关在**按序五段流水线**里的表现完全不同：
- **写后读（RAW，真相关）**：前一条写 `R1`，后一条读 `R1`。**按序五段流水线里只可能发生 RAW 冒险**！
- **读后写（WAR，反相关）**：前一条读 `R1`，后一条写 `R1`。因为读在 ID（第 2 段）、写在 WB（第 5 段），前一条早就读完了，按序流水线**绝不会发生 WAR 冒险**。
- **写后写（WAW，输出相关）**：两条先后写 `R1`。因为按顺序进入 WB，前一条先写、后一条后写，按序流水线**绝不会发生 WAW 冒险**。
*(WAR 和 WAW 只有在**乱序执行**或不同运算部件周期数不等的流水线里才会出问题，现代 CPU 用**寄存器重命名**彻底消除它们。)*

遇到 RAW 冒险，怎么算停顿（气泡）周期数？分“无转发”和“有旁路转发”两种情况：

#### 情况 A：没有旁路转发（纯靠等前一条写回寄存器）
- **408 默认前提：寄存器堆支持“前半周期写（WB）、后半周期读（ID）”**：
  前一条指令 $I_1$ 在第 5 周期（C5）前半周期写回寄存器，后继指令最早在 C5 后半周期就能读到新值：
  - **紧邻指令 $I_2$**（原定 C3 读）：必须在 ID 停顿 **2 个周期**（推到 C5 读）；
  - **隔 1 条指令 $I_3$**（原定 C4 读）：必须在 ID 停顿 **1 个周期**（推到 C5 读）；
  - **隔 2 条指令 $I_4$**（原定 C5 读）：**0 停顿**。
- **防坑提醒**：如果题目明确写“寄存器堆**不支持**同周期先写后读”，读就得推到 C6，上面三种停顿数全部加 1（变成 3、2、1 个周期）。

#### 情况 B：有旁路转发（Forwarding / Bypassing）——真题核心（2023-19、2024-19）
其实 ALU 算完的结果在 **EX 段末尾**就出来了，不用傻等 WB 写回寄存器；硬件直接从 `EX/MEM` 和 `MEM/WB` 流水段寄存器拉根线连回 ALU 输入端，就能把结果直接送给下一条指令用：
- **ALU 指令后面紧跟依赖它的指令（ALU-ALU）**：直接从 `EX/MEM` 转发到下一条指令的 EX 输入端，**0 停顿**！
- **Load 指令后面紧跟依赖它的指令（Load-Use 冒险，2023-19、2024-19）**：
  ```
  I1: LW   R1, 0(R2)    ; IF | ID | EX | MEM(末尾才读出R1!) | WB
  I2: ADD  R3, R1, R4   ;      IF | ID | [stall]            | EX(此时转发拿到R1) | MEM | WB
  ```
  `LW` 要到 **MEM 段末尾**（C4 末）才能从数据 Cache 拿到 `R1`，而紧邻的 `ADD` 在 C4 开头（EX 段）就要用 `R1`，时间倒流不了！所以 **即使有完整的旁路转发，紧邻的 Load-Use 冒险也必须强制插入 1 个停顿周期**，然后走 `MEM/WB -> EX` 转发通道。
  *(注：编译器可以通过把后面一条不相关的独立指令挪到 `LW` 和 `ADD` 中间，把这 1 个停顿周期填掉。)*

### 3. 控制冒险（分支冲突）
条件分支指令（如 `beq`、`bne`）要算完比较结果才知道下一条该不该跳。在结果出来前，流水线已经顺着往后取了 1～3 条指令；如果预测错了，就必须把误取进来的指令全部清空作废（冲刷 Flush），白白浪费周期。
- **缓解手段**：静态预测（如总预测不跳，或向后跳的循环预测跳）、动态分支预测（用分支历史表 BHT、2 位饱和计数器记录最近跳转历史）、尽早把分支判断从 EX 前移到 ID 段。

## 三、多处理器架构：Flynn 分类、UMA/NUMA 与 Cache 一致性

### 1. Flynn 分类法（按指令流和数据流数量分）
- **SISD（单指令流单数据流）**：传统单核 CPU。**高频陷阱：单核超标量流水线（每周期发射多条指令）依然属于 SISD！** 因为它只有一个程序计数器（PC），指令来自同一条串行指令流，属于指令级并行，不是多指令流。
- **SIMD（单指令流多数据流）**：一个控制器同时向多个 ALU 广播同一条指令，对一组向量/数组的不同元素做相同运算（数据级并行）。典型代表：向量处理器、CPU 的 SSE/AVX 指令、**GPU**。
- **MISD（多指令流单数据流）**：实用通用机中几乎没有，仅用于航天容错冗余表决。
- **MIMD（多指令流多数据流）**：多个独立核心、多个 PC，各自跑各自的程序、处理各自的数据（线程/进程级并行）。典型代表：**多核处理器、对称多处理机（SMP）、集群**。

### 2. 共享内存多处理器：UMA vs NUMA
- **UMA（统一存储访问，经典共享总线 SMP）**：所有核心通过共享总线访问同一块主存，**任意核心访问任意主存地址的延迟完全相同**。缺点是核心一多，共享总线很快堵死，扩展性差。
- **NUMA（非统一存储访问）**：把多核分成多个节点（Node），每个节点自带本地主存，节点间用高速互连相连。虽然全局仍统一编址，但核心**访问本地主存很快、跨节点访问远端主存明显更慢**。

### 3. 多核私有 Cache 一致性与伪共享
多核里每个核有自己的私有 L1/L2 Cache。如果核 0 和核 1 都缓存了主存地址 `X=0`，核 0 在自己 Cache 里把 `X` 改成 `100`（写回法还没刷主存），核 1 再读自己 Cache 就会读到过时的 `0`。
- **硬件解法（MESI 监听协议）**：每个 Cache 行标记四种状态——**M（已修改，独有且脏）、E（独占，独有且干净）、S（共享，多核都有且干净）、I（无效）**。核 0 要写一个处于 `S` 状态的块时，先在总线上广播“使无效”消息，核 1 监听到后立刻把自己那一行标为 `I`，核 0 再升级为 `M` 写入。
- **伪共享（False Sharing）**：Cache 一致性以整个 **Cache 行（如 64B）** 为单位。如果两个互不相干的变量 `a` 和 `b` 刚好挨着放在同一条 64B Cache 行里，核 0 只改 `a`、核 1 只改 `b`，硬件也会不停地让对方整行失效，导致 Cache 行在两核间来回颠簸、性能大跌。解决办法是给并发变量之间加填充字节，让它们分到不同的 Cache 行里。

## 四、硬件多线程（超线程）

如果单核遇到 L3 Cache 缺失去读 DRAM，一等就是两三百个时钟周期，流水线里的 ALU 全闲着。软件线程切换要进操作系统内核保存现场，花几千周期，救不了这种短停顿。**硬件多线程（2022-22）**直接在**同一个物理核心内部**做分工：
- **每个硬件线程独立复制一份（架构状态）**：各自的 **PC、通用寄存器堆、状态标志寄存器（PSW）**——在操作系统眼里，有几套架构状态就有几个“逻辑 CPU”；
- **多个线程共享一套（执行部件与缓存）**：共享 **ALU、FPU、指令译码器、L1/L2 Cache、TLB**。

按切换和发射方式分为三种：
1. **细粒度多线程**：**每个时钟周期轮流切线程**，每周期只发射当前选中线程的指令。能遮掩短停顿，但拖慢了单个线程的执行速度。
2. **粗粒度多线程**：一直跑同一个线程，**只有遇到长延迟阻塞（如 Cache 缺失）才切**。不影响单线程顺畅运行，但切换时要排空流水线，损失几个周期。
3. **同时多线程（SMT，如 Intel 超线程）**：在超标量多发射处理器上，**同一个时钟周期内同时把多个线程的指令混在一起发射**到不同的空闲执行单元里。既填补了长延迟的空闲周期，又填满了单周期内用不完的发射槽位。注意：因为共享执行单元和 Cache，开启超线程并不是把算力翻倍，通常只提升 20%～30%。
