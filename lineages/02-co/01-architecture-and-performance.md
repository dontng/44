# 计算机硬件层次、程序执行层级与 CPI/MIPS 性能方程

> 返回 [全科知识脉络总览](../README.md)

学计算机组成原理，一上来容易被一堆零散名词绕晕：冯·诺依曼结构、编译汇编链接、ISA、微架构、机器字长、CPI、MIPS……其实它们串在一起只回答两件事：**第一，一行 C 代码是怎么一层层翻译下来，最后在硬件里跑起来的；第二，同一段程序跑在不同硬件上，怎么用数字客观衡量谁更快。** 把“层次划分”和“性能方程”放进同一条脉络，就能先建立整门课的坐标系，后面学运算器、Cache、流水线时，所有优化手段都会自然落回到这套时间方程里。

## 一、冯·诺依曼结构与“存储程序”

早期计算机（比如 ENIAC）换一个计算任务就得人工重新拔插导线。冯·诺依曼结构解决这个问题的核心思想只有一句话——**存储程序**：把**指令**和**数据**都编码成二进制数，不加区分地放进同一个主存储器里，由 CPU 里的程序计数器（PC）自动一条一条取出来执行。

它定下了计算机的五大部件：**运算器、控制器、存储器、输入设备、输出设备**。早期机器以运算器为中心（输入输出都要绕道运算器），现代教材里的经典模型则演进为**以存储器为中心**，减少运算器被 I/O 占用的瓶颈。

因为指令和数据在主存里都是 0 和 1，没有任何额外标签，**CPU 怎么区分读出来的是指令还是数据？**
- **408 经典模型（按执行阶段区分）**：在**取指周期**，CPU 按 PC 里的地址从主存读出来的内容，会被当成**指令**送进指令寄存器（IR）；在**执行周期**，CPU 按指令算出的有效地址从主存读出来的内容，会被当成**数据**送进通用寄存器或运算器（ALU）。
- **现代 CPU 的实际做法（按通路和 Cache 区分）**：在流水线 CPU 里，一条指令正在取指（IF），另一条指令可能同时在访存（MEM）。如果指令和数据共用一套接口，就会互相抢路（结构冒险）。所以现代 CPU 采用了一种折中方案：**芯片内部用哈佛结构**（L1 Cache 拆成独立的指令 Cache 和数据 Cache，取指和访存各走各的路），**芯片外部仍用冯·诺依曼结构**（L2/L3 Cache 和主存依然指令与数据混存、统一编址）。

## 二、从 C 代码到机器执行：翻译过程与软硬件层次

一段 C 语言源程序（比如 `hello.c`）并不是直接扔给 CPU 就能跑的，它必须经过四个步骤（对应真题 **2022-20** 的工具链顺序）：

1. **预处理（`hello.c` $\to$ `hello.i`）**：展开 `#include` 头文件、替换 `#define` 宏、处理条件编译、删掉注释。输出**仍然是 C 语言文本文件**。
2. **编译（`hello.i` $\to$ `hello.s`）**：做词法/语法/语义分析和优化，把 C 代码翻译成**汇编语言文本文件**。
3. **汇编（`hello.s` $\to$ `hello.o`）**：把汇编助记符一一翻译成二进制机器指令，生成**可重定位目标文件**（二进制文件，里面已经有 `.text` 代码段和 `.data` 数据段，但调用外部函数或全局变量的地址还没最终填死）。
4. **链接（多个 `.o` + 库文件 $\to$ 可执行文件）**：把多个目标文件和库文件合并，做**符号解析**和**重定位**，算出最终的虚拟地址，生成可直接加载运行的二进制可执行文件。

把视野拉到整个计算机系统，从上到下分为**应用软件层 $\to$ 系统软件层（操作系统、编译器） $\to$ 指令集体系结构（ISA）层 $\to$ 微架构（计算机组成）层 $\to$ 物理实现层（晶体管、芯片封装）**。408 选择题几乎年年考其中两条最关键的边界：

### 1. ISA（指令集体系结构）与微架构（计算机组成）的边界
判断一个东西属于 ISA 还是微架构，只要问一句：**“改了它，原来编译好的二进制可执行文件还能不能直接跑？”**（对应 **2022-18、2025-16、2026-16**）
- **属于 ISA（软件可见的接口规范）**：指令格式、操作码与指令功能、寻址方式、数据类型和大小端、通用寄存器的个数和位数、主存编址方式、中断和异常机制、I/O 指令等。编译器和汇编程序员必须知道这些，才能生成正确的机器码。
- **属于微架构（底层硬件实现）**：有没有流水线、流水线分几级、有没有 Cache 和分支预测器、ALU 用串行进位还是超前进位、控制器用硬布线还是微程序、总线的具体位数等。同一套 x86 指令集，二十年前的 CPU 和今天的 CPU 内部电路天差地别，但老程序照样能跑，说明这些都是微架构细节。
- **逻辑设计与物理实现（2026-12）**：流水线、数据通路属于逻辑设计/微架构层；而芯片用几纳米工艺、封装引脚怎么排、供电散热怎么做，属于更底层的物理实现层。

### 2. 哪些指令能被 CPU 硬件直接执行？哪些寄存器对汇编程序员可见？
- **CPU 硬件直接执行的层级（2024-13）**：只有**机器指令**（进入 IR 由硬件译码执行）和**微指令**（在微程序控制器里从控制存储器读出直接控制电路）。高级语言语句和汇编指令都必须先翻译成机器指令，CPU 看不懂文本。
- **汇编程序员可见的寄存器（2021-17）**：只要指令集里存在指令能直接或间接读写它，就对汇编程序员可见。
  - **可见**：通用寄存器、程序计数器 PC、堆栈指针 SP、基址/变址寄存器、程序状态字 PSW（标志寄存器）。
  - **不可见（内部透明）**：指令寄存器 IR、主存地址寄存器 MAR、主存数据寄存器 MDR、单总线 CPU 里的暂存器 Y 和 Z。这些完全由硬件自动调度，汇编代码里写不出它们的名字。

## 三、四大“字长与宽度”不要混为一谈

教材和真题里经常同时出现四个带“字长”或“宽度”的词，各自对应不同的硬件部件：

| 概念 | 对应的硬件部件 | 说人话的含义 |
| :--- | :--- | :--- |
| **机器字长** | ALU 和通用寄存器（**2020-12**） | CPU 一次能直接处理的定点整数位数（比如 32 位、64 位 CPU），通常等于通用寄存器位数和内部数据通路宽度。 |
| **存储字长** | 主存单元与 MDR | 主存按字读写时，一个存储单元包含的二进制位数。现代机器主存通常按字节（8 位）编址，但一次读写可以并行传输 32 位或 64 位。 |
| **指令字长** | 指令寄存器 IR | 一条机器指令占多少位。可以是定长的（如 RISC 统一 32 位），也可以是变长的（如 x86 的 1～15 字节），不一定等于机器字长。 |
| **数据总线宽度** | CPU 外部数据总线的根数 | CPU 与主存/外设之间**一次总线传输**能并行送多少位。它可能小于存储字长——比如存储字长 16 位、数据总线 8 位，读一个字就需要分两次传送。 |

## 四、性能指标与 CPU 执行时间方程

评判一台机器跑程序快不快，最容易踩坑的地方是混淆**CPU 执行时间**和**响应时间**，以及迷信主频或 MIPS。

### 1. 响应时间、CPU 时间与吞吐率
- **响应时间（执行时间 / 墙钟时间）**：从按下回车运行程序，到屏幕输出结果一共过了多久。它既包含 CPU 算的时间，也包含等硬盘、等网络、等操作系统把 CPU 分给别的进程的时间。
- **CPU 执行时间（$T_{\text{CPU}}$）**：纯粹花在 CPU 芯片上执行这个程序指令的时间（分用户 CPU 时间和系统 CPU 时间），**不含 I/O 等待和其他进程占用的时间**。
- **吞吐率**：单位时间内系统总共能完成多少个任务。升级 CPU 主频能同时改善响应时间和吞吐率；加多核通常主要提升吞吐率。

### 2. 核心公式：CPU 执行时间方程
$$T_{\text{CPU}} = \text{指令条数 (IC)} \times \text{每条指令平均时钟周期数 (CPI)} \times \text{时钟周期 } T_{\text{clk}} = \frac{\text{IC} \times \text{CPI}}{\text{主频 } f}$$

把这三项拆开看，就能看清整个计算机组成原理的优化脉络：
- **指令条数 IC**：由算法、编译器和指令集（ISA）决定。
- **平均 CPI**：由微架构（流水线、分支预测、Cache 命中率）和指令集共同决定。如果程序包含多种指令，**加权平均 CPI** 等于各类指令占比乘以各自 CPI 再求和：$\text{CPI} = \sum (p_i \times \text{CPI}_i)$。
- **时钟周期 $T_{\text{clk}} = 1/f$**：由芯片工艺和最慢那一段组合逻辑的延迟决定。

**真题算例（2022-12、2023-12 思路）**：
假设某程序总指令数 $\text{IC} = 10^6$ 条，其中 ALU 指令占 50%（CPI=1）、访存指令占 30%（CPI=2）、分支指令占 20%（CPI=3），CPU 主频 $f = 2\text{ GHz}$：
1. 加权平均 $\text{CPI} = 0.5 \times 1 + 0.3 \times 2 + 0.2 \times 3 = 1.7$；
2. 总时钟周期数 $= 10^6 \times 1.7 = 1.7 \times 10^6$ 周期；
3. CPU 执行时间 $T_{\text{CPU}} = \frac{1.7 \times 10^6}{2 \times 10^9\text{ Hz}} = 0.85\text{ ms}$。

如果把 Cache 缺失也算进来（对应 **2025-18**），每条指令实际消耗的周期就是“理想基础 CPI + 访存停顿周期”：
$$\text{CPI}_{\text{实际}} = \text{CPI}_{\text{基础}} + \text{每条指令平均访存次数} \times \text{Cache 缺失率} \times \text{缺失损失周期}$$
其中取指每条指令必发生 1 次，数据访存只在 Load/Store 指令上发生，所以分开写就是：
$$\text{CPI}_{\text{实际}} = \text{CPI}_{\text{基础}} + \big(\text{I-Cache 缺失率} \times 1 + \text{D-Cache 缺失率} \times \text{访存指令占比}\big) \times \text{缺失损失}$$

顺带一提，流水线也不是切得越深越好：把流水线从 5 级切到 20 级，每级电路变简单，主频 $f$ 确实能提上去；但数据冒险和分支预测失败时清空流水线的代价也会成倍涨上去，把综合 CPI 拖高，一旦超过临界点，总时间 $T_{\text{CPU}}$ 反而变长。

### 3. MIPS、GIPS、FLOPS 与 MIPS 陷阱
- **MIPS**（每秒百万条指令）与 **GIPS**（每秒十亿条指令，**2023-12**）：
  $$\text{MIPS} = \frac{\text{IC}}{T_{\text{CPU}} \times 10^6} = \frac{f}{\text{CPI} \times 10^6}, \qquad \text{GIPS} = \frac{f}{\text{CPI} \times 10^9}$$
- **FLOPS**（每秒浮点运算次数，**2021-12**）：按 $10^3$ 递增——
  $\text{KFLOPS}(10^3) \to \text{MFLOPS}(10^6) \to \text{GFLOPS}(10^9) \to \text{TFLOPS}(10^{12}) \to \text{PFLOPS}(10^{15}) \to \text{EFLOPS}(10^{18})$。注意算力速率一律用十进制 $10^3$ 换算，而内存容量用二进制 $2^{10}$ 换算，别混了。
- **为什么不能光看 MIPS 比快慢？**
  接上面那个 $2\text{ GHz}$ 的例子：优化前 $\text{IC}_1 = 10^6$、$\text{CPI}_1 = 1.7$，算得 $\text{MIPS}_1 \approx 1176.5$，$T_1 = 0.85\text{ ms}$。现在换个更好的编译器，把很多简单指令合并优化掉，指令数降到 $\text{IC}_2 = 6 \times 10^5$，但剩下的访存和分支占比变高，平均 $\text{CPI}_2$ 升到 $2.5$。此时 $\text{MIPS}_2 = 2000 / 2.5 = 800$（看着暴跌了），但实际耗时 $T_2 = \frac{6 \times 10^5 \times 2.5}{2 \times 10^9} = 0.75\text{ ms}$，反而跑得更快！所以不同指令集、甚至同一台机器换了编译器，MIPS 都没有可比性；真正靠谱的只有针对具体基准程序的执行时间（比如 SPEC 基准测试）。
