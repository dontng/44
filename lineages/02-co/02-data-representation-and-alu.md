# 定点数补码与标志位、ALU、IEEE 754 浮点与 C 机器级表示

> 返回 [全科知识脉络总览](../README.md)

内存和寄存器里存的永远只是一串 0 和 1，同一串 32 位比特，既可以是带符号整数，也可以是无符号数、浮点数，甚至是一条机器指令（**2020-13**）。这条脉络把“数据怎么编码、电路怎么算、编译器怎么把 C 代码摆进内存和栈帧”串成一条完整的线：先看定点数和 ALU 加减乘除，再看 IEEE 754 浮点数，最后落到大小端、结构体对齐、汇编控制流与函数栈帧——这正是 408 计组大题（如 2021-43、2023-44、2024-44、2025-44、2026-43）最常考的综合主战场。

## 一、定点数编码、移位与类型转换

### 1. 为什么整数都用补码？
原码和反码都有两个毛病：一是 $+0$ 和 $-0$ 有两种编码，判零麻烦；二是异号相加得先比绝对值再做减法。补码利用 $n$ 位寄存器的模 $2^n$ 特性，把减法直接变成加法：$A - B = A + [-B]_{\text{补}} \pmod{2^n}$，而且 0 只有唯一的 `000...0`。

$n$ 位编码的表示范围和规律（以 8 位为例）：
- **无符号数**：$0 \sim 2^n - 1$（8 位为 $0 \sim 255$），所有位都是数值位。
- **原码 / 反码**：$-(2^{n-1}-1) \sim +(2^{n-1}-1)$（8 位为 $-127 \sim +127$），有两个 0。
- **补码**：$-2^{n-1} \sim +(2^{n-1}-1)$（8 位为 $-128 \sim +127$；32 位为 $-2^{31} \sim 2^{31}-1$，**2022-13**）。负数端多出一个最小负数 $-2^{n-1}$，它的编码是 `1000...0`（最高位为 1，其余全 0），原本是原码的 $-0$，补码把它给了最小负数。
- **移码**：把补码的**符号位取反**就得到标准移码（偏置值 $2^{n-1}$）。移码最大的好处是**机器码越大、真值越大**，方便硬件直接比较大小，所以用来表示浮点数的阶码（注意 IEEE 754 的阶码偏置值不是 $2^{n-1}$，而是 $2^{n-1}-1$）。

**手算补码的两个快捷技巧**：
- **已知真值求 $n$ 位补码**：负数补码 $= 2^n + X$。比如真题 **2023-13** 求 16 位 `short` 型 $-8190$ 的补码：$-8190 = -8192 + 2 = -2^{13} + 2$，用 $65536 - 8190 = 57346 = \text{E002H}$（或者把 $8190 = \text{1FFEH}$ 按位取反加 1，立得 `E002H`）。
- **比较两个补码的大小（2021-13）**：先看最高位，0 一定大于 1；同为负数时，十六进制数值越接近 `FFFFH`（即 $-1$），真值越大。比如 `7FFCH`（正数）$>$ `FFFCH`（$-4$）$>$ `8000H`（$-32768$）。

### 2. 逻辑移位与算术移位
- **逻辑移位（针对无符号数）**：左移低位补 0，右移高位补 0。
- **算术移位（针对带符号数）**：
  - 正数无论原/反/补，左右移都补 0；
  - 负数**补码**：**左移低位补 0**（移出位与新符号位不同则溢出），**右移高位补 1**（保持负号不变，相当于向负无穷取整除以 2）。
- **易错点（2026-13）**：移位会丢掉移出去的比特，**不可逆**！把一个数先算术右移 3 位再算术左移 2 位，**绝不等于**算术右移 1 位，因为右移时丢掉的低 3 位在左移时会被补成 0。

### 3. 扩展、截断与 C 语言隐式转换
- **短转长**：无符号数做**零扩展**（高位全补 0）；带符号数做**符号扩展**（高位全复制原符号位，正补 0 负补 1）。
- **长转短（截断）**：直接砍掉高位，原样保留低位。比如 **2024-12**：32 位 `int` 值 `32777 = 0000 8009H`，截断成 16 位 `short` 后剩 `8009H`（最高位为 1，变成负数 $-32759$）；再符号扩展回 32 位就是 `FFFF 8009H`。
- **同字长有/无符号互转**：底层的 0/1 位串一动不动，只改变解释方式。C 语言里 32 位 `int` 与 `unsigned int` 混合运算或比较时，会把 `int` 隐式转成 `unsigned int`，所以 `-1 > 0U` 为真（`-1` 的 `FFFFFFFFH` 被解释成 $2^{32}-1$）。
- **既变字长又变符号（2025-12）**：C 语言的顺序是**先扩展字长（按原类型决定符号扩展还是零扩展），再改变符号解释**。比如 16 位 `short si = -32767`（`8001H`）转 32 位 `unsigned int`：先按 `short` 符号扩展成 32 位 `FFFF 8001H`，再按无符号数解释，得到 $2^{32} - 32767$。

## 二、ALU、超前进位与标志位，以及定点乘除法

### 1. 串行进位与超前进位（CLA）
一位全加器（FA）计算本位和 $S_i = A_i \oplus B_i \oplus C_{i-1}$，向高位进位 $C_i = A_i B_i + (A_i \oplus B_i)C_{i-1}$。如果把 $n$ 个全加器串在一起（行波进位），高位必须等低位一级一级传进位，延迟跟位数 $n$ 成正比。

为了提速，定义两个只依赖本位输入的信号：
- **进位产生项** $G_i = A_i B_i$（本位自己就产生进位）；
- **进位传递项** $P_i = A_i \oplus B_i$（或者 $A_i + B_i$，低位有进位就往上传）。

于是 $C_1 = G_1 + P_1 C_0$，$C_2 = G_2 + P_2 G_1 + P_2 P_1 C_0$……每一位的进位都能直接由 $C_0$ 和各位 $G_i, P_i$ 算出来，理论上只需 2 级门延迟。但位数一多，单个逻辑门的输入端（扇入）太多做不出来，所以实际工程里把 16 位分成 4 组，每组 4 位用组内先行进位，组间再加一级先行进位发生器（两级 CLA）。

### 2. 加减统一通路与四个标志位（ZF、SF、CF、OF）
硬件用同一套加法器做加减法：$A - B = A + (\sim B) + 1$。用控制信号 $\text{Sub}$ 区分：加法时 $\text{Sub}=0$，减法时 $\text{Sub}=1$（把 $B$ 按位取反，同时最低位进位输入 $C_0 = 1$）。

每次运算结束，ALU 硬件都会**同时**算出四个标志位（硬件不知道你在算有符号数还是无符号数，**CF 和 OF 绝不互斥**）：
- **ZF（零标志）**：结果全 0 时为 1。
- **SF（符号标志）**：直接等于结果的最高位 $F_{n-1}$。
- **CF（无符号进位/借位标志）**：$\text{CF} = C_{\text{out}} \oplus \text{Sub}$。加法看有没有向最高位外进位；减法看有没有借位（无符号 $A < B$ 时 $\text{CF}=1$）。
- **OF（有符号溢出标志）**：$\text{OF} = C_n \oplus C_{n-1}$（最高位进位与次高位进位异或）。更直观的判断法：加法时**同号相加结果变号**就溢出；减法时**正减负得负、或负减正得正**就溢出（**2022-43、2025-14**）。

**真题案例（2024-43）**：32 位加法 $A = \text{8765 4321H}$，$B = \text{9876 5432H}$：
- 逐位相加得 33 位结果 `1 1FDB 9753H`，截断低 32 位输出 $F = \text{1FDB 9753H}$；
- 最高位产生了进位 $C_{\text{out}} = 1$，加法 $\text{Sub}=0$，所以 **$\text{CF} = 1$**（按无符号数看溢出了）；
- $A$ 和 $B$ 最高位都是 1（都是负数），结果 $F$ 最高位是 0（正数），两负相加得正，所以 **$\text{OF} = 1$**（按有符号数看也溢出了）！
- 反过来再看 **2023-16**：32 位减法 `10 - (-20) = 30`，有符号结果 30 没超范围，所以 $\text{OF} = 0$；但按无符号数看，`0000 000AH` 减去 `FFFF FFEC H` 明显不够减要借位，所以 $\text{CF} = 1$。

### 3. 定点乘法与除法
- **乘法的三种实现与快慢对比（2020-43、2024-15）**：
  1. 软件模拟（没有乘法指令，用循环移位 + 加法实现）：最慢，每轮都要取指、译码、分支；
  2. 复用 ALU 和移位器的迭代乘法指令（如原码一位乘、补码 Booth 一位乘）：居中，硬件自动循环 $n$ 步；
  3. 阵列乘法器（全组合逻辑加法树）：最快，单周期或极少周期直接出结果。
- **Booth 补码一位乘法规则**：部分积寄存器 ACC 用双符号位初值 0，乘数寄存器 MQ 末尾加 1 位附加位 $y_{n+1}=0$。每步看最低两位 $(y_n, y_{n+1})$：
  - `00` 或 `11`：部分积加 0；
  - `01`：部分积加 $[x]_{\text{补}}$；
  - `10`：部分积加 $[-x]_{\text{补}}$。
  然后 ACC、MQ、附加位联合**算术右移 1 位**（$n$ 位数值位的小数乘法做 $n$ 次移位、第 $n+1$ 步用原乘数符号位和附加位做最后一次加减但不移位）。
- **乘法溢出判定（2020-43）**：两个 $n$ 位数相乘会先得到 $2n$ 位完整乘积，截断成 $n$ 位返回时：
  - **无符号乘法**：只要高 $n$ 位**不全为 0**，就溢出；
  - **带符号乘法**：只要高 $n$ 位**不全等于低 $n$ 位的最高位（符号位）**，就溢出。
  例如 $n=32$ 时，$(2^{31}-1) \times 2 = \text{00000000 FFFFFFFEH}$，截断低 32 位是 `FFFFFFFEH`：高 32 位全 0，所以无符号乘法不溢出；但低 32 位最高位是 1 而高 32 位是 0，带符号乘法溢出（截断后变成了 $-2$）。
- **定点除法（原码加减交替法与 2025-44 补码除法器）**：
  - 恢复余数法在试减得到负余数时，还要再加回去恢复再左移；**加减交替法（不恢复余数法）**利用恒等式 $2(R_i + |Y|) - |Y| = 2R_i + |Y|$，余数为负时直接商 0、左移 1 位、下一步改做**加**除数；余数为正时商 1、左移 1 位、下一步改做**减**除数。$n$ 位小数除法共 $n+1$ 次加减、$n$ 次左移，若最终余数为负再加一次除数恢复。
  - **真题案例（2025-44）**：32 位带符号整数除法 `d[i] / x`，先把 32 位被除数 `d[i] = 0x87654321`（负数）经 `scov` **符号扩展**成 64 位放进寄存器对 `{R, Q}`，所以高 32 位 $R = \text{0xFFFFFFFF}$、低 32 位 $Q = \text{0x87654321}$，除数 $x = \text{0xFF}$ 放进 $Y = \text{0x000000FF}$。循环计数器在控制逻辑里，ALU 执行加、减两种运算。
  - **32 位带符号整数除法异常的唯二条件（2025-44）**：① 除数 $x = 0$（`0x00000000`）；② 商溢出——只有唯一一种情况：**最小负数除以 $-1$**，即被除数 `0x80000000`（$-2^{31}$）、除数 `0xFFFFFFFF`（$-1$），数学商 $+2^{31}$ 超出了 32 位补码上限 $2^{31}-1$。

## 三、浮点数与 IEEE 754 标准

定点数表示不了极小或极大的数，浮点数把数拆成符号 $S$、阶码 $e$ 和尾数 $f$，写成 $V = (-1)^S \times M \times 2^E$。

### 1. 单精度（float）与双精度（double）格式
- **单精度 `float`（32 位）**：1 位符号 $S$ + 8 位阶码 $e$（偏置值 **127**）+ 23 位尾数小数 $f$（有效精度 24 位，约 7 位十进制有效数字）。
- **双精度 `double`（64 位）**：1 位符号 $S$ + 11 位阶码 $e$（偏置值 **1023**）+ 52 位尾数小数 $f$（有效精度 53 位，约 15～16 位十进制有效数字）。

根据阶码 $e$ 和尾数 $f$ 的取值，IEEE 754 分成 5 种情况（以单精度为例）：

| 阶码 $e$ | 尾数 $f$ | 数值类型 | 真值公式 |
| :---: | :---: | :--- | :--- |
| $1 \sim 254$ | 任意 | **规格化数** | $(-1)^S \times (1.f) \times 2^{e - 127}$（隐含前导 1，指数范围 $-126 \sim +127$） |
| 全 0（0） | 全 0 | **$\pm 0$** | $(-1)^S \times 0$ |
| 全 0（0） | 非 0 | **非规格化数（2023-14）** | $(-1)^S \times (\mathbf{0.}f) \times 2^{-126}$（**隐含位是 0，指数固定是 $1-127=-126$**，用于渐进下溢） |
| 全 1（255） | 全 0 | **$\pm \infty$** | 上溢或非零除以 0 |
| 全 1（255） | 非 0 | **NaN（非数）** | `0.0/0.0`、负数开方等非法运算 |

**两个真题手算示例**：
- **十进制转 IEEE 754（2022-14）**：把 $-0.4375$ 转成 `float`。
  $-0.4375 = -7/16 = -0.0111_2 = -1.11_2 \times 2^{-2}$。
  $S = 1$；阶码 $e = -2 + 127 = 125 = 0111\ 1101_2$；尾数 $f = 1100\dots 0$。
  拼起来：`1 01111101 110000...0` = **`BEE0 0000H`**。
- **IEEE 754 转十进制（2025-13）**：把 `4730 0000H` 转成真值。
  展开二进制：`0 10001110 011000...0`。
  $S = 0$；阶码 $e = 10001110_2 = 142 \implies E = 142 - 127 = 15$；尾数 $1.011_2 = 1 + 1/4 + 1/8 = 1.375$。
  真值 $= 1.375 \times 2^{15} = 1.375 \times 32768 = 45056$。

### 2. 精度丢失、舍入与类型转换
- **十进制小数何时能精确表示（2021-14）**：化成最简分数后，分母的质因数**只能有 2**。像 $1.2 = 6/5$ 分母含 5，二进制是无限循环小数，绝不可能被 IEEE 754 精确表示。
- **整数与浮点互转（2024-14）**：
  - `int`（31 位有效位）转 `double`（53 位有效尾数）：**一定无损**；
  - `float` 转 `double`：**一定无损**；
  - `int` 转 `float`（24 位有效尾数）：**不会溢出**（`float` 范围大得多），但**可能丢精度**。注意特例：32 位最小负数 $-2^{31} = -1.0 \times 2^{31}$，尾数全 0，`float`（`CF00 0000H`）可以**完全精确**表示它；而最大正数 $2^{31}-1$ 有 31 个连续的 1，转 `float` 会被舍入成 $+2^{31}$。
  - `double` 转 `float`：既可能丢精度，也可能溢出成 $\pm \infty$；`float/double` 转 `int`：直接向零截断小数部分，超范围则溢出。
- **默认舍入方式（2026-14）**：IEEE 754 默认采用**就近舍入到偶数（Round to Nearest, Ties to Even）**。硬件在尾数末尾留了保护位、舍入位和粘滞位：被舍弃部分严格大于一半就进位；严格小于一半就舍去；正好等于一半时，看保留结果的最低位，让它变成偶数（末位为 0）。

### 3. 浮点数加减运算五步
1. **对阶（小阶向大阶看齐）**：把阶码小的那个数的尾数右移 $|\Delta E|$ 位，阶码加 $|\Delta E|$。绝不能大阶向小阶看齐，否则大数尾数左移会直接把最高有效位挤丢。
2. **尾数加减**：对阶后的有效尾数（带隐藏位 1）直接做定点加减。
3. **规格化**：
   - 尾数相加产生进位（如变成 `10.xxx`）$\implies$ **右规**：尾数右移 1 位，阶码加 1；
   - 尾数相减高位抵消（如变成 `0.001xxx`）$\implies$ **左规**：尾数左移 $k$ 位直到最高有效位为 1，阶码减 $k$。
4. **舍入**：对阶右移或右规时移出的低位按就近偶舍入处理；如果舍入导致尾数又进位，还需再右规一次。
5. **溢出判定**：**只看阶码，不看尾数**！阶码超过最大允许值（单精度 $>254$）叫上溢（变 $\pm\infty$ 或异常）；小于最小允许值（$<1$）叫下溢（变非规格化数或机器零）。注意浮点加法因为对阶舍入，**不满足结合律**。

## 四、大小端、边界对齐与 C 语言机器级表示

### 1. 大端与小端字节序
内存按字节编址，一个 4 字节整数 `0x12345678` 存放在 `0x1000 ~ 0x1003` 时：
- **大端模式**：高字节放低地址（`0x1000` 放 `12`，`0x1003` 放 `78`），符合人眼阅读顺序，网络字节序统一用大端。
- **小端模式（x86、RISC-V 默认）**：低字节放低地址（`0x1000` 放 `78`，`0x1003` 放 `12`）。

两个必须记住的边界：① 大小端**只管字节顺序，不管单个字节内部的 8 个比特顺序**；② 大小端**不改变数组元素的先后顺序**，数组元素地址永远递增，只影响每个元素内部那几个字节怎么摆。在 **2024-44** 里，小端机器从 `0013 E004H` 连续读出 4 个字节 `DC, EC, FF, FF`，从高地址往低地址拼起来就是 `FFFF ECDCH`。

### 2. 数据边界对齐与结构体大小
总线一次读 4 字节或 8 字节，如果一个 `int` 跨了 4 字节边界，CPU 就得访存两次再拼接。所以编译器默认按**自然边界对齐**（**2020-14、2025-15**）：
1. **成员对齐**：每个成员的起始偏移量必须是它自身大小（对齐模数）的整数倍，不够就补空白填充字节（Padding）；
2. **整体对齐**：结构体总大小必须是内部**最大基本成员**大小的整数倍，不够就在末尾补填充，这样结构体数组里的下一个元素才不会歪掉。

例如 `struct A { char c1; int i; char c2; }`：`c1` 在 `0`，补 3 字节，`i` 在 `4~7`，`c2` 在 `8`，末尾补 3 字节凑 4 的倍数，总大小 **12 字节**；如果把字段重排成 `{ int i; char c1; char c2; }`，总大小立刻缩成 **8 字节**。

### 3. 控制结构与过程调用（函数栈帧）
- **条件分支**：`cmp` 指令做无写回减法更新标志位（注意 AT&T 语法 `cmp a, b` 算 `b - a`，Intel 语法 `cmp a, b` 算 `a - b`），随后 `je/jne`（看 ZF）、有符号 `jg/jl`（看 SF 与 OF）、无符号 `ja/jb`（看 CF 与 ZF）决定是否跳转。`switch-case` 分支多且连续时，编译器会建一张**跳转表**实现 $O(1)$ 间接跳转。
- **循环结构**：编译优化后常把 `while`/`for` 翻译成“前置条件检查 + 底部反向跳转的 `do-while`”形式，每次循环只跳一次。
- **x86-32 函数栈帧布局**（栈从高地址向低地址增长）：
  1. 主调函数先把实参从右向左压栈，再执行 `call`（把返回地址压栈，同时修改 PC 跳进子函数）；
  2. 子函数入口（序言）：`push ebp`（保存旧帧指针）$\to$ `mov ebp, esp`（确立新帧基址）$\to$ `sub esp, N`（给局部变量腾空间）；
  3. 此时相对 `ebp` 的偏移规律固定：**`[ebp]` 是旧 `ebp`，`[ebp+4]` 是返回地址，`[ebp+8]`、`[ebp+12]` 是第 1、2 个形参，`[ebp-4]`、`[ebp-8]` 是局部变量**；
  4. 返回时（结语）：返回值放 `eax`，执行 `leave`（等价于 `mov esp, ebp` + `pop ebp`），再执行 `ret`（弹出返回地址装回 PC）。
  5. 寄存器保存约定：`eax/ecx/edx` 是**调用者保存**（主调函数用前自己压栈），`ebx/esi/edi/ebp` 是**被调用者保存**（子函数若要改动必须先压栈、返回前弹回）。现代 x86-64 / RISC-V 会优先用寄存器传参（比如 RISC-V 用 `a0~a7`，返回地址放 `ra` 寄存器）。

**真题串联（2026-43）**：把 C 语句 `y = (x << 4) - 5;`（`x` 在 `[R15+0]`，`y` 在 `[R15+2]`）翻译成 16 位机器指令时，正好把整条脉络串起来：先用基址偏移 0 把 `x` 加载到 `R0`，再用 `sll` 左移 4 位，再用 `addi` 加上 $-5$ 的 8 位补码 `1111 1011`（`FBH`），最后存回 `[R15+2]`。
