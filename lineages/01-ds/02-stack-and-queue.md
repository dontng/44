# 受限线性容器：栈、队列、循环队列与双端队列

> 脉络编号：`ds-02` · 返回 [全科知识脉络总览](../README.md)

栈、队列和双端队列本质上都还是线性表，只是给插入和删除加了“门禁”：栈只准在同一端进出（后进先出，LIFO），队列只准一端进、另一端出（先进先出，FIFO），双端队列则是把两端都放开再按需锁掉其中一个口。把它们放在一条脉络里，刚好可以对比不同出入规则怎么决定合法序列、怎么解决数组假溢出、以及怎么撑起括号匹配和表达式求值这些经典应用。

---

## 一、栈（Stack）：后进先出与存储实现

栈只允许在**栈顶（`top`）**做入栈（`Push`）和出栈（`Pop`），栈底封死。

### 1. 顺序栈、链栈与共享栈

- **顺序栈**：用数组 `data[MaxSize]` 实现。408 最常用的约定是 **`top` 指向当前栈顶元素**，初始化 `top = -1`：
  - 栈空：`top == -1`；栈满：`top == MaxSize - 1`；
  - 入栈：先 `top++` 再存 `data[top] = x`；出栈：先取 `x = data[top]` 再 `top--`。
  - （偶尔题目也会约定 `top` 指向下一个空位，初始化 `top = 0`，此时栈满是 `top == MaxSize`，审题看清初始值即可。）
- **链栈**：用单链表实现，通常把**链表头**当作栈顶（不带头结点时 `Push` 就是头插、`Pop` 就是删表头，都是 $O(1)$）。在 408 理论题里认为链栈不会上溢（除非系统内存耗尽）。
- **共享栈**：两个顺序栈共用一个长度为 `MaxSize` 的数组，栈 0 从下标 0 往上长（初始 `top0 = -1`），栈 1 从下标 `MaxSize - 1` 往下长（初始 `top1 = MaxSize`）。
  - 栈 0 空：`top0 == -1`；栈 1 空：`top1 == MaxSize`；
  - **共享栈满的条件**：**`top0 + 1 == top1`**（两个栈顶迎面贴在一起）。

### 2. 栈的模拟与括号匹配

做具体入栈/出栈序列模拟题时，**题目给了几步就只做几步，千万别自作主张把最后留在栈里的元素也弹出来**。例如真题 `2020-02` 依次执行 `Push(a), Push(b), Pop, Push(c), Pop, Push(d), Push(e), Pop`，弹出的依次是 `b, c, e`，结束后 `a, d` 仍留在栈里，所以输出序列就是 `b, c, e`，不是 `b, c, e, d, a`。

在**括号匹配**里，遇到左括号压栈、遇到右括号就弹出栈顶检查是不是配对。这里常考的一个细节是：**校验一串表达式所需栈的最小容量，取决于未闭合左括号的最大同时嵌套深度，跟表达式总长度或括号总数无关**。例如真题 `2025-02` 问容量为 3 的栈哪个表达式无法完成匹配：看 `a * [b + (c * [x + (d + e)])]`，依次读到 `[`、`(`、`[` 时栈里已有 3 个左括号（已满），紧接着又遇到 `(d + e)` 的左括号 `(`，嵌套深度达到 4，发生栈上溢；而其它选项虽然括号总数不少，但里面的括号及时闭合弹出了，栈深从未超过 3。

## 二、合法出栈序列与卡特兰数

给定入栈顺序 $1, 2, \dots, n$，在入栈过程中可以随时出栈，能得到哪些输出序列？

### 1. 两个极端与“312 禁形”判断法

- **全顺与全逆都合法**（真题 `2022-02`）：每进一个立刻弹出，输出就是原序 `1, 2, ..., n`；全部压进去再一口气弹出，输出就是完全逆序 `n, ..., 2, 1`。
- **判断一个序列合不合法**：不用每次都从头模拟，记住一条充要规律——**在已经出栈的元素 $P_i$ 后面，所有比 $P_i$ 小的元素必须按从大到小的顺序出栈**。换句话说，只要存在下标 $i < j < k$ 且数值满足 **$P_i > P_k > P_j$（“大—小—中”，即 312 模式）**，这个序列就**绝对不合法**。
  - 原因很直观：$P_i$ 能先出栈，说明比它小的 $P_j$ 和 $P_k$ 早就都在栈里了；入栈是递增的，所以更大的 $P_k$ 一定压在更小的 $P_j$ 上面，出栈时必须先出 $P_k$ 再出 $P_j$，绝不可能先出 $P_j$ 再出 $P_k$。
  - 例如真题 `2026-42` 给序列 `2, 3, 1, 6, 4, 7, 5, 9, 8`：看 `6, 4, 5`（$6 > 5 > 4$），6 出栈时 4 和 5 都已经在栈里且 5 压在 4 上面，不可能跳过 5 先出 4，立刻判为非法；而 `2, 3, 1, 5, 6, 7, 4, 9, 8` 没有任何“大—小—中”，可以合法生成。

### 2. 卡特兰数与递推计数

$n$ 个**互不相同**的元素按固定顺序入栈，且**栈容量足够大（$\ge n$）**时，所有合法出栈序列的总数等于第 $n$ 个**卡特兰数**：
$$C_n = \frac{1}{n+1} \binom{2n}{n} = \frac{(2n)!}{(n+1)!\,n!}$$
前 5 项直接记住很省时间：**$C_1 = 1,\; C_2 = 2,\; C_3 = 5,\; C_4 = 14,\; C_5 = 42$**。如果题目限制了栈容量 $k < n$，有些需要压超过 $k$ 个元素的出栈序列就做不出来，总数会严格小于 $C_n$。

真题 `2026-42` 还顺着卡特兰数的推导考了分类计数：
- $n=4$ 时以 2 开头的出栈序列有几种？先 `Push(1), Push(2), Pop(2)`，此时栈里压着 1、外面还有 3 和 4 待入栈，相当于 3 个元素的出栈排列问题，共 $C_3 = 5$ 种（`2,1,3,4`、`2,1,4,3`、`2,3,1,4`、`2,3,4,1`、`2,4,3,1`）。
- 推广到 $n = k$，设规模为 $k-1$ 的合法出栈序列数为 $M$：如果第一个出栈的是 1，只能 `Push(1), Pop(1)`，剩下 $2 \sim k$ 这 $k-1$ 个元素在空栈上做完全一样的问题，所以以 1 开头的序列数正好是 **$M$**。

## 三、表达式转换与求值：用栈去掉括号

人习惯看中缀表达式（运算符在中间，比如 `a + b * c`），但需要靠括号和优先级决定先算谁；计算机更喜欢**后缀表达式（逆波兰式）**，运算符写在两个操作数后面，从左往右扫一遍就能直接算，不需要括号。

### 1. 中缀转后缀（用运算符栈）

从左往右扫描中缀表达式，记住两条核心现象：**操作数的相对顺序永远不变**，运算符按优先级进出栈：
1. **遇到操作数**：直接输出。
2. **遇到 `(`**：直接压栈。压进栈后，把 `(` 当成栈里优先级最低的符号，任何普通运算符都弹不动它。
3. **遇到 `)`**：不断弹栈并输出，直到把配对的 `(` 弹出来为止（这对括号直接丢弃，不输出）。
4. **遇到普通运算符（`+ - * /`）**：只要栈顶运算符的优先级 **$\ge$** 当前运算符（注意：**同级也要弹**，因为加减乘除都是左结合），就把栈顶弹出来输出，直到栈空、遇到 `(`、或栈顶优先级严格更低，再把当前运算符压栈。
5. **扫描结束后**：**把栈里剩下的运算符全部依次弹出输出**（千万别漏这一步）。

拿真题 `2024-02` 的 $x + y \times (z - u) / v$ 走一遍：
- 扫 `x` 输出 `x`；扫 `+` 压栈 `[+]`；扫 `y` 输出 `xy`；扫 `*` 比 `+` 高，压栈 `[+, *]`；
- 扫 `(` 压栈 `[+, *, (]`；扫 `z` 输出 `xyz`；扫 `-` 压栈 `[+, *, (, -]`；扫 `u` 输出 `xyzu`；
- 扫 `)` 弹出 `-` 并丢掉 `(`，输出 `xyzu-`，栈剩 `[+, *]`；
- 扫 `/`：栈顶 `*` 与 `/` 同级，先弹出 `*` 输出 `xyzu-*`，新栈顶 `+` 低于 `/`，停止弹栈并压入 `/`，栈变为 `[+, /]`；
- 扫 `v` 输出 `xyzu-*v`；
- 表达式结束，把栈里剩下的 `/` 和 `+` 依次弹出，最终得到 **`xyzu-*v/+`**。

### 2. 后缀表达式求值（用操作数栈）

从左往右扫后缀表达式：遇到操作数就压栈；遇到运算符就连续弹出两个数算完再压回去。
唯一的易错点在于**减法 `-` 和除法 `/`** 这种不满足交换律的运算：**先弹出来的是右操作数 $b$，后弹出来的是左操作数 $a$，算的是 $a - b$ 或 $a / b$**，千万别算反。

比如计算 `15 7 1 1 + - / 3 *`：
- 依次压入 `15, 7, 1, 1`；
- 遇 `+`：弹 `1, 1`，算 $1+1=2$ 压栈 $\to$ `[15, 7, 2]`；
- 遇 `-`：先弹 $b=2$，再弹 $a=7$，算 $7-2=5$ 压栈 $\to$ `[15, 5]`；
- 遇 `/`：先弹 $b=5$，再弹 $a=15$，算 $15/5=3$ 压栈 $\to$ `[3]`；
- 压入 `3`，遇 `*` 算 $3 \times 3 = 9$，最终结果是 **9**。

## 四、队列与循环队列：消除假溢出

队列只允许在**队尾（`rear`）入队**、在**队头（`front`）出队**，遵循先进先出（FIFO）。

### 1. 假溢出与循环队列

如果用普通一维数组实现顺序队列，入队 `rear++`、出队 `front++`，过一会儿 `rear` 走到数组尽头报“队满”，但前面出队腾出来的格子明明还空着，这就叫**假溢出**。

解决办法是把数组首尾相连做成**循环队列**，用取模运算让指针绕回开头：
- 入队：`rear = (rear + 1) % MaxSize`
- 出队：`front = (front + 1) % MaxSize`

### 2. 判空与判满的三种办法

绕成环之后，队空和队满时都是 `front == rear`，分不清了。408 教材给出三种区分办法（默认 `front` 指队头元素、`rear` 指队尾元素的**下一个空位**，初始 `front = rear = 0`）：

| 方案 | 队空条件 | 队满条件 | 队列当前元素个数 |
| :--- | :--- | :--- | :--- |
| **① 牺牲一个存储单元**（最常考） | `front == rear` | `(rear + 1) % M == front` | `(rear - front + M) % M` |
| **② 增设 `size` 计数器** | `size == 0` | `size == M` | `size` |
| **③ 增设 `tag` 标志位**（入置 1 出置 0） | `front == rear && tag == 0` | `front == rear && tag == 1` | 相等时按 `tag` 为 `0` 或 `M`，否则取模 |

**注意一种指针变体**：如果题目明确说明 `rear` 指向的是**当前队尾元素本身**（而不是下一个空位），那么初始空队是 `front = 0, rear = M - 1`；入队时要先 `rear = (rear + 1) % M` 再赋值；用牺牲一个单元法时，队满条件变成 `(rear + 2) % M == front`。

### 3. 链式队列的边界

带头结点的链式队列里，`front` 指向头结点，`rear` 指向最后一个数据结点。出队时取 `p = front->next; front->next = p->next;` 后，**必须加一句 `if (rear == p) rear = front;`** 再 `free(p)`——这和前面单链表删唯一结点的坑完全一样，防止队列删空后 `rear` 变成悬空指针。

## 五、双端队列：输入受限与输出受限

双端队列（Deque）左右两端原本都能进能出。考试专考两种“砍掉一个口”的变体：
- **输入受限双端队列**：只能从一端进，但两端都能出。
- **输出受限双端队列**：两端都能进，但只能从一端出。

判断一个输出序列能不能得到，直接动手在纸上画个横条模拟两端最稳妥。看下面这两个经典的互补例子（输入顺序 `1, 2, 3, 4`）：

1. **序列 `4, 1, 3, 2`**（真题 `2021-02` 考的正是这个序列在输出受限下的不可达性）：
   - **输入受限（只从左进，左右皆可出）——可达**：`1, 2, 3, 4` 依次从左端进队，队内为左 `[4, 3, 2, 1]` 右。接着左端出 `4`、右端出 `1`、左端出 `3`、左端出 `2`，全部搞定。
   - **输出受限（左右皆可进，只从右出）——不可达**：`4` 先出、紧接着 `1` 出，说明 `4` 走后 `1` 必须在最右端；那么 `1, 2, 3` 进队时 `2, 3` 只能从左端塞到 `1` 的左边，队内从左到右排成 `[3, 2, 1]`，接着 `4` 从右端进并立刻右出，再右出 `1`。此时队列剩 `[3, 2]`，露在最右端的是 `2`，接下来只能出 `2`，绝不可能越过 `2` 先出 `3`！
2. **序列 `4, 2, 1, 3`**：
   - **输入受限（只从左进，左右皆可出）——不可达**：要让 `4` 第一个出，`1, 2, 3, 4` 必须全进队，排成左 `[4, 3, 2, 1]` 右。`4` 从左端出去后，两端露着的是 `3` 和 `1`，`2` 夹在中间，根本出不来。
   - **输出受限（左右皆可进，只从左出）——可达**：`1` 进 $\to$ `2` 从左进 `[2, 1]` $\to$ `3` 从右进 `[2, 1, 3]` $\to$ `4` 从左进 `[4, 2, 1, 3]`，然后从左端依次出队就是 `4, 2, 1, 3`。
