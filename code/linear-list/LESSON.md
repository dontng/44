# 单链表：先看见每句代码改变了什么

这页直接给出状态、关键代码和变化原因，可以不运行，也不必先读完整程序。先认出“结点、地址、连接”三样东西，再看增删改查怎样组合它们。完整实现和运行入口放在后面，需要时再打开。

## 1. 会认：定义里的 data、next、L 分别是什么？

先想清楚要存什么。一个元素是 10，除了存这个数，还需要记住“下一个元素在哪里”；单链表结点因此包含两个字段：data 存值，next 存后继地址。地址的作用是找到对象，读代码时通常无需知道它具体是哪个数字。

```c
typedef struct LNode {
    int data;             // 当前元素的值。
    struct LNode *next;    // 下一个结点的地址；没有后继时为 NULL。
} LNode, *LinkList;
```

`struct LNode` 定义这种结点的形状；末尾把结点类型简称为 `LNode`，把“指向这种结点的指针类型”简称为 `LinkList`。所以 `LinkList L` 与 `LNode *L` 一样，L 只存地址。next 声明中写 `struct LNode`，是因为末尾的简称当时还没有定义完；不用为此另外记一种结构。

有了类型，再创建具体对象：

```c
LNode a = {10, NULL};  // 创建结点 a：data=10，next=NULL。
LNode head = {0, &a};  // 创建头结点：next 保存 a 的地址。
LinkList L = &head;   // L 保存头结点的地址。
```

`{...}` 按字段顺序填入值；`&a` 表示“a 的地址”。头结点是为统一操作而放在开头的辅助结点，它的 data 不算表中元素，所以这条表只有一个元素 10。这里的 0 只是填充值，换成别的数也不增加元素。

| 看到的表达式 | 沿着哪里找 | 结果 |
|---|---|---|
| `L` | 不继续访问，直接取变量内容 | head 的地址 |
| `L->next` | 找到 head，再读 next | a 的地址 |
| `L->next->data` | 从 head 找到 a，再读 data | 10 |
| `L->next->next` | 从 head 找到 a，再读 next | NULL |

`->` 用于通过地址访问字段；对象本身访问字段用 `.`，因此这里 `L->next` 和 `head.next` 指的是同一处。读长表达式时就从左往右走，不要把几个箭头当作一个需要记忆的词。

**最小验证：**保持 head 存在，只把 `head.next` 改为 NULL，表就空了。L 仍指向 head，因此“空表”是 `L->next == NULL`；`L == NULL` 连头结点都没有指向。实际定义见 [linked_list.h](linked_list.h)，其中 `ElemType` 只是给 int 另起的元素类型名。

## 2. 会读：p 往后走，链表为什么没有少一个元素？

现在表中有 `[10, 30]`，对应结点 a、b；头结点接 a，a 接 b，p 也指向 a。先只看一句：

```c
p = p->next;
```

右边先从 a 取出 b 的地址，左边再把这个地址存进 p。**等号左边是 p，因此改变的是 p 这个变量。**a 里面的 next 没有被赋值，头结点也没有被改。

| 观察对象 | 执行前 | 执行后 |
|---|---|---|
| p 指向谁 | a（10） | b（30） |
| 头结点的 next | a | a |
| a 的 next | b | b |
| 从表头能读到什么 | `[10, 30]` | `[10, 30]` |

这就是遍历的感觉：换一个观察位置，原来的结点仍在那里。查找、计数、打印都复用这个动作，只是在每个位置做不同的事。

再把 p 指回头结点，观察另一句：

```c
p->next = p->next->next;
```

右边沿头结点找到 a，再取出 a 的后继 b；左边是“头结点里的 next 字段”，于是头结点改为直接接 b。**最小验证：**p 没移动，但从表头只能读到 `[30]`。认代码时先找等号左边：改 p 是移动观察位置，改 next 是改连接，改 data 是改元素值。

## 3. 会感受：插入的顺序为什么不能随便换？

初始仍是 `[10, 30]`。pre 指向 10，新结点 s 存 20；目标是让 pre 接 s，再让 s 接原来的 30。先不管怎样申请内存，只看接线的两句：

```c
s->next = pre->next;  // s 先记住原后继30在哪里。
pre->next = s;        // pre 再改为连接s。
```

| 时刻 | pre 的 next | s 的 next | 从 pre 出发能读到 |
|---|---|---|---|
| 开始 | 30的结点 | NULL | `[10, 30]` |
| 第一句后 | 30的结点 | 30的结点 | `[10, 30]`，s尚未接入 |
| 第二句后 | s | 30的结点 | `[10, 20, 30]` |

第一句只是在新结点里准备连接，第二句才把它接入原表。以后需要重写时，先列出目标的两条连接，再问“哪一个旧地址会被覆盖”，顺序就有依据。

**最小反例：交换两句。**先做 `pre->next = s`，pre 里原来保存的后继地址就被覆盖了；再做 `s->next = pre->next`，读到的已是 s，于是 s 指向自身。两行语句分别都合法，组合起来却不满足插入需求，这就是要验证的逻辑。

<details>
<summary>换个条件：插在末尾，还需要换两句代码吗？</summary>

不需要。原后继是 NULL 时，第一句让 s 的 next 为 NULL，第二句仍让前驱接 s，新结点自然成为链尾。空表在头结点后插入也符合这一关系；不同的是怎样找到前驱。

</details>

## 4. 会迁移：删除也是修改同一条连接

表为 `[10, 30]`，pre 指向头结点，q 指向要删的 10。目标是让头结点直接接到 30。

```c
LNode *q = pre->next;  // 保存待删结点的地址。
pre->next = q->next;   // 前驱改接目标的后继。
```

| 观察对象 | 修改前 | 修改后 |
|---|---|---|
| 头结点的 next | 10的结点 | 30的结点 |
| q 指向谁 | 10的结点 | 仍是10的结点 |
| 从表头能读到什么 | `[10, 30]` | `[30]` |

**最小验证：**被摘下的结点仍然存在，q 仍能找到它，所以“从链表中移除”与“释放其内存”是两个动作。完整实现里，结点来自 malloc，接线后还需 free；读取 q 的数据和后继必须发生在 free 之前。最小实验用局部变量建结点，不需要、也不能对它们调用 free。

<details>
<summary>换个条件：只剩一个元素时，再删除会怎样？</summary>

目标的后继是 NULL，同一句 `pre->next = q->next` 就让头结点的 next 变成 NULL，得到空表。头结点让首元结点也有前驱，首位和末位因此可以使用同一套接线；空表没有待删元素，则需要在接线之前拒绝操作。

</details>

## 完整代码在哪？按你当前的问题进入

现在可以打开 [使用示例 demo.c](demo.c)，看同一条表的创建、增删改查和清空；每步旁边有结果。想知道某一步怎样实现，再打开 [linked_list.c](linked_list.c)，不必从头通读。

| 想找的能力 | 对应代码 | 读的时候抓住什么 |
|---|---|---|
| 定义、创建、判空 | 头文件、`list_create`、`list_empty` | 谁存值、谁存地址、空表的连接 |
| 按位取值、按值找位、遍历、计数 | `list_get`、`list_find`、`list_print`、`list_length` | p怎样走，每到一处做什么 |
| 修改元素 | `list_update` | 找到目标，只改data |
| 插入 | `list_insert` | 找前驱、准备新结点、两句接线 |
| 删除 | `list_delete` | 找前驱、保留目标信息、接线、释放 |
| 清空与销毁 | `list_clear`、`list_destroy` | 释放前保存后继；是否保留头结点 |

这些函数共用 `node_at` 定位：从头结点走 pos 步；寻找第 pos 个元素的前驱，就走 pos-1 步。按位序插删最坏为 O(n)，主要花在寻找前驱上，已知前驱后的接线是 O(1)。

<details>
<summary>读到 &value、*out 或 malloc 时，再看这里</summary>

`list_get(L, 2, &value)` 把调用者变量 value 的地址传给参数 out，函数内部通过 `*out` 给那个变量赋值；函数返回的 true/false 另行说明操作是否成功。这样 value 为 0 或负数也不会与失败混淆。

`malloc(sizeof *s)` 按一个结点的大小申请内存，成功时返回地址，失败时返回 NULL。`s` 是指针，`*s` 表示它指向的对象，`sizeof *s` 取该对象类型的大小；这里的 sizeof 不会读取一个结点。`free(s)` 结束那块内存的使用，此后不能再通过旧地址读写。先理解连接如何变化，再回看这些生命周期处理。

</details>
